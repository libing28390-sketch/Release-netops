# 容器错误日志与 CPU 采样

在 Linux 部署主机的仓库根目录执行，需要有 Docker 读取权限。脚本只读取运行状态，不安装软件、不重启容器、不读取容器环境变量。

## 全容器日志

```bash
bash scripts/collect_container_errors.sh 2h 20000
```

收集每个容器的原始日志、带上下文的错误匹配、状态、OOM/退出/重启记录、资源限制、日志轮转配置及即时资源统计。输出目录名称会在结束时打印。

第二个参数是每容器日志行数上限；需要全部保留日志时使用 `all`。实际时间覆盖受 Docker 轮转和行数上限影响。MatchingLines 是关键字命中的行数，跨服务可能记录同一个失败，不能直接相加作为独立事故数量。事件缓存有限，当前 OOM=false 不证明历史上从未发生 OOM。

## 应用 CPU

```bash
bash scripts/capture_netops_cpu.sh nexora-netops 300
```

时长范围 10–300 秒。输出连续容器 stats、进程/线程 CPU，并生成压缩包。宿主机已安装 py-spy 时另收集 Python 函数栈；未安装时会写明缺少函数采样。当前采样不展开 native 栈，asyncio/uvloop 入口下的 C 层计算与等待仍需进一步定位。函数栈频率不能直接当作 CPU 时间比例，线程池等待栈也不是 CPU 热点。

输出文件默认仅当前用户可读写。应用原始日志可能自带敏感业务信息，分享前请检查。与旧版做 CPU 对比时，保持采样时长、设备规模、采集周期与页面负载接近，并记录实际部署版本。

这两个脚本及本说明保留在 Linux 发布目录中，更新源码或发行包后可以使用相同命令。
