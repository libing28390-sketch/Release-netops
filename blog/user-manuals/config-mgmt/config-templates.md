# Nexora NetOps 配置模板中心用户使用手册

> 适用页面：`/config/templates`  
> 功能模块：配置管理 → 配置模板  
> 适用版本：Nexora NetOps 0.1.1 及后续兼容版本

## 1. 功能概述

配置模板中心用于把网络设备的 CLI 配置整理成可重复使用、可校验、可追踪的模板。模板不直接等同于一次设备变更：它首先负责保存命令结构和参数定义，然后通过参数方案生成预览，经过语法、参数、厂商平台和风险检查后，才可以交给自动化任务或变更流程继续处理。

模板中心支持以下工作：

- 查看系统内置模板和用户自定义模板；
- 按厂商、平台、场景、来源、状态和关键字快速查找；
- 创建、编辑、复制和归档自定义模板；
- 使用 Jinja2 参数变量生成不同设备的命令；
- 自动识别模板变量并生成字段、类型、默认值和示例值；
- 保存参数方案，重复用于预览或后续任务；
- 查看命令预览、模板源码、参数 JSON、校验结果和版本差异；
- 导入、导出模板，便于跨环境迁移；
- 记录渲染历史、审核状态、版本信息和质量评分。

模板中心使用 PostgreSQL 中的模板数据和版本数据作为正式数据源。浏览器中的输入草稿仅用于临时恢复，不能代替点击保存，也不能代替后续的变更审批。

## 2. 进入页面与页面布局

登录后从左侧导航进入“配置管理 → 配置模板”，或直接访问 `/config/templates`。页面采用三栏布局：

1. 左栏是模板库。这里可以搜索模板、选择厂商和平台、筛选场景、来源、状态，并查看模板卡片。
2. 中栏是参数区。选中模板后，这里显示参数方案、字段分组、输入框、必填标识、示例值和字段校验信息。
3. 右栏是结果区。这里显示命令预览、模板源码、参数 JSON、校验结果和版本差异，并提供复制、下载、全屏等操作。

顶部的“导入模板”和“新建模板”用于管理模板；模板详情区域中的“复制为自定义”用于将内置模板复制成可修改的副本。系统内置模板通常是只读的，不能直接编辑或删除，必须先复制为自定义模板。

## 3. 模板与参数方案的区别

模板是命令本身，例如：

```jinja2
vlan {{ vlan_id | default(100) }}
 description {{ vlan_name | default("USERS") }}
```

参数方案是这份模板的一组具体输入，例如：

```json
{
  "vlan_id": 100,
  "vlan_name": "生产业务"
}
```

同一个模板可以保存多个参数方案，例如“生产区 VLAN”“测试区 VLAN”和“分支办公 VLAN”。修改参数方案不会修改模板源码；修改模板源码也不会自动替换已有参数方案。模板版本变化后，旧参数方案可能出现字段缺失或兼容性提示，需要重新检查。

## 4. 创建自定义模板

### 4.1 打开创建窗口

点击页面右上角“新建模板”。创建窗口中填写模板基本信息、命令源码、回滚源码、示例 JSON 和可选的字段定义。建议先确定厂商和平台，再编写命令，因为同一个业务动作在 Cisco IOS、Huawei VRP、H3C Comware、Juniper Junos 等平台上的语法并不相同。

### 4.2 基本信息

主要字段如下：

| 字段 | 填写说明 |
|---|---|
| 模板名称 | 建议使用“厂商/平台 + 场景 + 动作”的格式，例如“华为 VRP VLANIF 网关”。 |
| 厂商 | 选择 Cisco、Huawei、H3C、Juniper、Arista、Ruijie、ZTE、Maipu、DPtech 或自定义厂商。 |
| 平台 | 必须选择与厂商匹配的平台，例如 Huawei VRP、H3C Comware V7、Cisco IOS XE。 |
| 场景 | 用于分类和筛选，例如 switching、routing、security、management 或 interface。 |
| 软件版本 | 填写适用版本范围，例如“VRP 8.x”或“Comware V7”。不确定时不要填写虚假的精确版本。 |
| 模板说明 | 说明模板用途、适用对象和不适用场景。 |
| 使用说明 | 写清前置条件、输入参数含义和执行前检查。 |
| 风险说明 | 说明可能中断业务、影响路由、覆盖已有配置或需要维护窗口的情况。 |

厂商和平台必须关联。系统会拒绝不匹配的组合，避免把 Cisco 命令误用于华为设备，或把 H3C Comware V7 模板误用于不兼容的平台。

### 4.3 编写模板源码

模板源码使用 Jinja2 变量。变量名必须使用小写蛇形命名，例如 `vlan_id`、`interface_name`、`gateway_ip`。推荐为可选参数提供安全默认值，为生产关键参数保留必填校验。

推荐示例：

```jinja2
vlan {{ vlan_id | default(100) }}
 description {{ vlan_name | default("USERS") }}
quit
interface Vlanif{{ vlan_id | default(100) }}
 ip address {{ gateway_ip | default("192.0.2.1") }} {{ netmask | default("255.255.255.0") }}
 description {{ interface_description | default("USER_GATEWAY") }}
```

注意以下规则：

- 不要把设备命令写进变量值，例如变量 `interface_name` 只填写 `GigabitEthernet0/0/1`，不要填写 `interface GigabitEthernet0/0/1`。
- 不要把命令分隔符、换行、管道符、反引号或脚本片段放入普通变量。
- IP 地址、子网掩码、VLAN ID、接口名、ASN 等变量应使用语义明确的名称，系统会按名称推断类型并校验。
- Cisco、Arista、锐捷等设备通常使用 VLAN `name`；Huawei、H3C 常使用 VLAN `description`。不要为了统一字段名而统一 CLI 语法。
- 涉及密码、密钥、Community 或 Secret 的字段应标记为敏感参数，示例值不得填写真实生产凭据。

### 4.4 编写回滚源码

回滚源码用于生成撤销或恢复命令，不是说明文字。建议每个可能改变设备状态的模板都填写回滚内容。例如：

```jinja2
undo vlan {{ vlan_id | default(100) }}
```

Cisco、Juniper、Huawei、H3C 等厂商的回滚命令不同，必须按目标平台编写。回滚不应盲目删除整段业务配置；如果模板只是修改接口描述，应只回滚该描述，避免误删已有配置。

### 4.5 示例 JSON

示例 JSON 必须是对象，不能是数组、字符串或带注释的 JSON。示例值用于初始化参数面板、生成预览和校验模板是否能够完整渲染。例如：

```json
{
  "vlan_id": 100,
  "vlan_name": "PRODUCTION",
  "gateway_ip": "192.0.2.1",
  "netmask": "24",
  "interface_description": "PRODUCTION_GATEWAY"
}
```

系统支持根据模板字段自动识别示例值；如果示例 JSON 中包含模板没有使用的字段，这些多余字段会被忽略。子网掩码字段支持 `24` 和 `255.255.255.0`，系统会根据模板和厂商平台转换为正确格式。

### 4.6 字段定义

字段定义是可选的。即使不手工填写，系统也会从源码中的 `{{ ... }}` 自动生成字段。手工填写字段时可以设置：

- 字段名：必须与源码变量名完全一致；
- 显示名称：面向用户的名称，例如“VLAN ID”“网关地址”；
- 类型：文本、整数、IPv4、子网掩码、VLAN ID、接口或敏感值；
- 是否必填：生产配置建议把 VLAN ID、接口名、网关地址等关键字段设为必填；
- 示例值：用于预览和参数方案初始值；
- 字段说明：填写格式、范围和注意事项。

只在源码实际使用变量后再增加字段定义。保存时系统会删除与源码无关的字段，防止参数面板出现“看起来可以填写但实际不会生效”的假字段。

点击保存后，系统会检查厂商与平台、Jinja2 语法、变量格式、回滚内容和示例值。校验失败时不会创建模板，应先按错误信息修复。

## 5. 使用模板生成配置

### 5.1 选择模板

在左栏使用关键字搜索模板名称、说明、厂商、平台或命令内容。可以组合厂商、平台、场景、来源和状态筛选。选择模板后，中栏显示该模板的参数字段，右栏加载当前版本。

切换模板时，系统会重新加载模板自己的字段、示例值、参数方案和渲染结果，不应继续沿用上一模板的缓存参数。若页面仍显示旧字段，先点击刷新；若仍未恢复，记录模板名称和页面错误信息后交给管理员检查。

### 5.2 填写参数

字段旁的星号表示必填。参数来源通常会显示为“用户填写”“模板默认值”“示例值”“参数方案”或“系统计算”。生产执行前，应将关键字段从示例值改为实际值，并检查预览中的每一行命令。

常见参数说明：

- `vlan_id`：1 至 4094 的 VLAN 编号；
- `vlan_name`：VLAN 名称或厂商对应的 VLAN 描述；
- `interface_name`：设备实际接口名；
- `interface_description`：接口业务描述；
- `gateway_ip`：三层接口地址；
- `netmask` 或 `network_mask`：点分十进制掩码或 CIDR 前缀长度；
- `wildcard_mask`：Cisco ACL/OSPF 等场景使用的通配符掩码；
- `local_as`、`peer_as`：BGP AS 号；
- `allowed_vlans`：允许通过的 VLAN 列表。

### 5.3 参数方案

在参数区选择“未使用参数方案”下拉框旁的输入框，输入方案名称后点击保存。例如可以保存“WH-DC-02 生产 VLAN”。参数方案只保存参数值，不保存密码明文；敏感值在重新加载时可能显示为脱敏占位符，需要重新输入。

使用已有方案时，系统会根据当前模板版本和必填字段检查兼容性。如果模板升级后增加了新字段，界面会提示仍需补充的必填参数。补齐后再保存为新方案，避免覆盖仍被其他任务使用的旧方案。

### 5.4 渲染与预览

点击“立即渲染”或等待参数输入自动预览。右栏的“命令预览”用于查看最终命令；“模板源码”用于查看 Jinja2 原始内容；“参数 JSON”用于核对实际提交值；“校验结果”显示语法、参数、风险和警告；“版本差异”用于比较两个模板版本。

渲染结果中应重点检查：

1. 模板变量是否全部替换，没有残留 `{{ ... }}`；
2. IP 地址、掩码、VLAN ID、接口名是否属于目标设备实际范围；
3. 命令缩进、进入和退出配置模式的顺序是否正确；
4. 厂商命令是否与平台匹配；
5. 是否产生高风险命令，如删除 VLAN、清除接口地址、覆盖认证或修改默认路由；
6. 回滚预览是否能撤销本次配置。

预览成功不等于设备已经执行。真正执行仍需经过自动化任务、变更单、审批、维护窗口和设备侧结果确认。

## 6. 复制模板

模板卡片或详情区域提供“复制为自定义”操作。复制适用于以下场景：

- 需要基于系统内置模板增加本地字段；
- 需要调整默认值、说明或回滚命令；
- 需要为不同型号或平台建立受控变体；
- 需要在不影响官方模板的情况下进行试验。

复制后会生成一个新的自定义草稿，保留源码、回滚源码、字段、示例值、版本和兼容性信息。新副本可以直接编辑；原模板保持只读。复制后应立即修改名称和说明，避免用户误把副本当成官方模板使用。

## 7. 修改自定义模板

在自定义模板卡片上点击编辑，或进入详情后点击编辑。修改窗口可以修改基本信息、厂商平台、源码、回滚源码、示例 JSON 和字段定义。保存时系统会重新解析变量并同步字段，不再保留源码中已删除的旧字段。

修改建议按以下顺序进行：

1. 先复制或导出当前模板，保留修改前备份；
2. 修改模板说明和风险说明，写清变更原因；
3. 修改源码和回滚源码；
4. 更新示例 JSON，使所有必填字段都有有效示例；
5. 重新点击渲染，查看命令预览和校验结果；
6. 检查版本差异，确认没有意外删除命令；
7. 在测试设备或低风险设备上验证后，再提交审核或发布。

内置官方模板不可直接修改。若编辑按钮不可用，请先复制为自定义模板。模板处于审核、发布或归档状态时，是否允许修改取决于当前用户角色和权限；不要通过修改 URL 绕过权限控制。

## 8. 删除、归档与恢复

模板中心的“删除”对自定义模板实际执行的是归档，而不是物理删除。归档后模板从默认模板库隐藏，避免历史参数方案、渲染记录和审计记录失去关联。归档前确认没有自动化作业、变更单或其他用户依赖该模板。

系统内置模板不能删除。若不希望使用内置模板，可以取消收藏、调整筛选条件，或复制成自定义版本后使用。删除自定义模板时需要确认弹窗；确认后应刷新列表，确认该模板已从默认视图消失。

归档属于受控变更，管理员可通过数据库、审计日志或管理接口核对归档记录。不要直接删除 PostgreSQL 中的模板行，否则可能导致版本、参数方案、渲染历史和审计链路断裂。

## 9. 导入与导出

详情区域的下载操作可以导出完整 JSON 模板包，通常包括模板基本信息、当前版本、源码、回滚源码、字段定义、示例值、兼容性和校验摘要。导入时系统会校验源码是否存在、校验和是否匹配、厂商平台是否有效，并按自定义草稿处理。

推荐流程：

1. 在源环境打开模板详情并导出 JSON；
2. 保留原始导出文件，不要用普通文本编辑器破坏 JSON 编码；
3. 在目标环境使用“导入模板”；
4. 导入后检查厂商、平台、字段、示例值和版本；
5. 用目标环境真实平台重新渲染；
6. 通过测试后，再提交审核或交给自动化任务。

导出文件不应包含真实密码、设备密钥或 SNMP Community。导入失败时重点检查 JSON 格式、版本结构、校验和、厂商平台名称和模板源码编码。

## 10. 审核、版本和质量管理

模板状态通常包括草稿、审核中、已发布和已归档。建议由模板作者负责创建和测试，由具备审核权限的运维人员负责审批，管理员负责高风险模板和官方模板管理。

模板版本应保持可追溯。每次改变命令结构、字段含义、默认值、回滚方式或适用平台，都应形成新版本或至少留下明确的变更说明。发布前比较版本差异，确认新增、删除和修改的命令行。

质量评分可用于发现模板缺陷，但不能替代人工审核。一个质量较高的模板至少应具备：明确的厂商和平台、完整的说明、可渲染的源码、有效的示例值、字段格式校验、回滚源码和风险说明。

## 11. 常见问题

### 11.1 保存时提示厂商和平台不匹配

检查平台下拉框是否属于当前厂商。例如 H3C 应选择 Comware 平台，Huawei 应选择 VRP 或 USG，Cisco 应区分 IOS、IOS XE、NX-OS、IOS XR 和 ASA。不要用“自定义平台”掩盖真实平台错误。

### 11.2 参数面板没有显示我写的字段

检查源码是否使用标准 Jinja2 变量格式，例如 `{{ vlan_id }}`。字段定义只会保留源码实际使用的变量；如果变量写在普通注释、错误的括号或字符串拼接中，系统不会把它当成可填写字段。保存后重新打开模板，确认字段是否生成。

### 11.3 预览中仍有变量未替换

检查变量名是否拼写一致、必填字段是否为空、示例 JSON 是否为对象，以及变量是否位于条件分支中。对于条件变量，建议使用 `default` 或在参数方案中补齐值。

### 11.4 掩码格式错误

确认模板字段被识别为子网掩码，而不是普通文本。Cisco、Huawei、H3C 等平台可使用 `24` 或 `255.255.255.0` 输入，系统会按目标语法转换；通配符掩码不能当作普通子网掩码使用。

### 11.5 为什么内置模板不能编辑或删除

内置模板属于系统维护内容，直接修改会影响其他用户和后续升级。请使用“复制为自定义”，在副本中修改并通过审核。

### 11.6 修改后页面仍显示旧参数

先确认保存请求成功，再刷新模板列表和详情。模板详情、参数方案和渲染结果属于不同数据，旧参数方案不会自动覆盖新模板字段。若仍异常，应记录模板 ID、版本、浏览器时间和错误提示，交由管理员检查后端日志及 PostgreSQL 中的版本记录。

### 11.7 预览成功是否可以直接下发设备

不能。预览只代表模板在当前输入下能够生成命令，并不代表设备连通、权限足够、命令适用于真实型号或变更已获批准。生产操作仍需经过设备范围确认、变更审批、执行任务、结果核验和回滚准备。

## 12. 推荐操作清单

创建模板前：确认厂商、平台、型号范围、官方语法和回滚方式。  
保存模板后：确认源码、字段、示例 JSON、风险说明和校验结果。  
执行前：使用真实设备参数渲染，检查每一行命令和回滚命令。  
发布前：在测试设备验证，比较版本差异，完成审核和变更记录。  
归档前：确认没有定时任务、自动化作业或未完成变更依赖该模板。  
跨环境使用：导出后保护文件，导入后重新验证厂商平台和设备型号。
