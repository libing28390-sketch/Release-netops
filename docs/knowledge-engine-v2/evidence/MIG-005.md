# MIG-005 Evidence

- Task ID: MIG-005
- 原始要求：为旧 Metadata 建立可信、需验证、不可用三个等级。
- 最终状态：PASS（三级规则、分类 manifest 与 PostgreSQL 只读审计完成）。

## 目标

对 legacy `ai_document.metadata_json`、typed semantic columns、parse status/error、生命周期和排除标记建立 deterministic 的 `trusted`、`needs_validation`、`unusable` 三级分类。分类只产生 hash/count/动作，不改写旧行，不提前创建 V2 投影。

## 三级规则

- `trusted`：JSON object、parse status 已验证、全部 required fields、类型/枚举合法、无 UNKNOWN、无 server-owned/security 字段、active 且未排除、source trust allowlist 内。
- `needs_validation`：可解析但缺字段、UNKNOWN、类型/枚举不兼容、parse status 缺失、生命周期未证明等，可人工 reconciliation 后再迁移。
- `unusable`：JSON 非 object/非法、parse error、Secret 或 instruction-like value、server-owned key、超限；必须 quarantine/exclude。

## PostgreSQL 真实快照结果

- 156 行 metadata_json 都是 JSON object 并产生 metadata hash。
- 154 行 parse status 为 `parsed`，但 legacy `rag_priority` 为 `P0` 字符串而非 V2 规定的 0–100 integer，因此保守标记需验证。
- 2 行 metadata parse status 为 `missing`、required fields 不完整、official_only 缺失，同样标记需验证。
- 未发现 unusable 行：没有 JSON malformed、server-owned key、Secret/instruction-like value 或 metadata parse error。

这不是把数据强行标记为可信；它准确反映当前 legacy Metadata 与 V2 类型契约之间的差距，后续需在 MIG-006/007 前完成 normalization/review。

## 数据库影响

只执行 PostgreSQL `BEGIN READ ONLY`，无 INSERT、UPDATE、DELETE、DDL 或 typed projection 写入；SQLite 未作为验收证据。

## 安全影响

Manifest entry 只有 legacy IDs、tenant hash、metadata hash、grade、parse status、原因码和动作；raw metadata、原文、ACL、Secret、DSN 和异常原文均不输出。server-owned/security 命中直接 unusable。

## 回滚方式

无生产变更。可废弃本地 confidence manifest；保留原 `metadata_json` 和 V1 typed projection，禁用新 adapter 即可恢复。

## 已知限制

此分类不代替 MIG-006 的官方厂商/产品/版本核验，也不代替 MIG-007 的重新 Parse/Chunk/Embed/Index。`needs_validation` 行在 reconciliation 完成前禁止进入 V2 active retrieval。
