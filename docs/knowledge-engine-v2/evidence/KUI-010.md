## KUI-010

目标：官方来源导入与企业文件上传使用不同表单和校验。

修改文件：src/api/ai.ts；src/pages/ai/Knowledge/KnowledgeManagementTab.tsx；docs/knowledge-engine-v2/architecture/KUI-001-018-KNOWLEDGE-ADMIN-CONTRACT.yaml。

实现内容：知识管理页提供独立的“导入官方 URL”和“上传企业 SOP”入口。官方表单要求 HTTPS URL、Vendor、Product Family、版本范围和已审核条款，调用 `/api/knowledge-v2/ingestion/official-url`；企业表单要求文件、标题、负责人、部门，限制 20 MB，调用 multipart `/api/knowledge-v2/ingestion/enterprise-sop`，分类展示为服务端固定的 INTERNAL。两者不共享错误 Metadata。

执行命令：`npm.cmd run lint`；`npm.cmd run build`；`py_compile`；`pytest backend/tests/catalog/test_ing002_official_url_import.py backend/tests/catalog/test_ing005_enterprise_sop_import.py backend/tests/ai/test_kui_001_008_knowledge_admin.py -q -p no:cacheprovider`。

测试结果：21 passed；前端 TypeScript lint/build 通过；后端 Python 编译通过。既有官方 URL 与企业 SOP API 合同、权限、校验和幂等测试保持通过。

数据库影响：无新增 DDL；复用 Source Registry、Ingestion Job 和 tenant-scoped import service。

安全影响：官方 URL 交给 Source Registry / safe outbound 边界；企业文件在服务端 20 MB 限制和 INTERNAL 强制分类下处理；浏览器只展示安全的任务结果。

回滚方式：回退新增入口与 API wrapper，不删除已提交的 ingestion job/source 记录。

已知限制：导入任务的进度、取消和重试由后续 API/OBS 管理界面任务实现。

最终结论：PASS
