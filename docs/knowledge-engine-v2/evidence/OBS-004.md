- 原始要求: `建立请求 ID 贯穿前端、API、RAG、Gateway 和 Provider。`
- 目标: 让一次前端请求在 API、知识检索 Trace、AI Security/LLM Gateway、重试/Fallback 和 Provider 出站请求中保持同一 bounded request_id，并可从响应/SSE 反查。

- 实现内容:
  - API 边界使用 `resolve_request_id` 校验 `X-Request-ID`，拒绝控制字符、超长和非法字符，缺失/非法值生成 server-owned ID，并在成功/错误响应回写。
  - 前端 `apiRequest` 和 Assistant SSE 请求自动生成 `web_*` ID；调用者显式提供的 ID 保留；SSE HTTP 错误包含 request ID。
  - Assistant non-stream/stream、RAG retrieval trace、V1 chat 和 versioned SSE event envelope 均携带同一 ID。
  - LLM Gateway 的 chat、stream、retry、fallback 复用 explicit/context ID；Provider adapter 仅通过 `X-Request-ID` 出站 header 传递，不写入模型 body。
  - Retrieval Trace 在 tenant-scoped bounded projection 中保留 request_id，未改变 raw query hash-only 和现有 redaction contract。
