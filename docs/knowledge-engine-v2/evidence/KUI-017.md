### 实现内容

- 知识检索自动登记有界 Trace；管理员 API 提供 tenant-scoped 列表和详情，状态支持 hit/no_match/not_run。
- 读模型最多保留 200 条，Query 只保存 SHA-256，Actor 只保存短哈希；请求实体、候选计数、解析歧义、平台候选和引用 metadata 摘要按 allowlist 投影。
- 默认排除 Query 正文、Chunk 正文、SQL、URL、文档/Chunk ID、用户名和凭据；跨租户详情统一 404。
- Knowledge Management 增加 Retrieval Trace / 追踪视图，支持状态筛选、刷新、列表、详情、阶段计数、引用摘要、空态/失败态和窄屏布局。
- 暂不增加 DB-012 持久化表；后续 MIG 任务负责 durable trace history，当前进程模型不改变 V1 或生产数据。

### 数据库影响

无新增 DDL、无生产表写入。PostgreSQL 探针只验证运行环境；Trace 当前保存在进程内固定上限队列，清理随进程生命周期发生。SQLite 不参与 KUI-017 接受门禁。

### 安全、权限与审计

- API 使用 `knowledge_source.read`，服务端绑定用户租户；Trace 写入沿用检索调用的 tenant/user 上下文。
- 对查询、引用和实体字段执行 allowlist + 长度限制；不存储原始 Query、响应、Chunk 或 URL。
- 失败只返回安全消息；管理员不能通过 trace_id 读取其他租户记录。

### 回滚方式

回退 Trace store、assistant 登记钩子、API 路由、前端面板和契约即可；无迁移、无持久化数据删除、无 V1 表改动。

### 已知限制

Trace 为当前进程内 read model，服务重启后历史消失；DB-012 durable retrieval/rag/citation tables 在后续 MIG/REL 任务中落地。现阶段只展示摘要，不提供原文诊断。
