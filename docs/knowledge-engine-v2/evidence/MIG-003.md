- Task ID: MIG-003

## 目标

为每个 tenant-scoped legacy `ai_document` 建立稳定的旧 ID→V2 Document/V2 Document Version 映射，并生成可复核、可重跑、无原文的迁移 Manifest。映射只作为 MIG-004 dry-run 的输入，不代表目标数据已经创建。

## 实现内容

1. 旧身份键固定为 `(ai_document.tenant_id, ai_document.id)`；语义 `document_id` 同时保留用于审计。
2. V2 document/version ID 使用固定 namespace 的 UUID5 生成，不依赖随机数或当前数据库状态；相同输入重跑得到相同映射。
3. Manifest entry 记录旧 ID、旧语义 ID、tenant hash、V2 IDs、准入分类、source registry 解析状态、声明 hash 和动作；不复制原文、normalized 内容、metadata、ACL 或 Secret。
4. PostgreSQL 只读事务读取 legacy rows 和 Source Registry keys；发现 unresolved source 时 fail-closed，不虚构 registry ID。
5. Manifest digest 排除 `generated_at` 和自身 digest，保证重跑可比较；重复 legacy key 或 deterministic V2 collision 直接失败。

## 数据库影响

只执行 PostgreSQL `BEGIN READ ONLY`；无 INSERT、UPDATE、DELETE、DDL、sequence 或目标 V2 row 创建。Manifest/report 是本地 review artifact，MIG-004 前不会驱动生产写入；SQLite 未作为验收证据。

## 安全影响

Manifest 只含 hash、ID 映射、分类和动作；原文、normalized 内容、metadata、ACL、DSN、Secret 和异常原文不落盘。tenant 本身只以 SHA-256 表示；legacy ID 仅因迁移 join 必需而保留。
