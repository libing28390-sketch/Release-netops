- Task ID: MIG-007

## 目标与阻断

MIG-007 只能消费 MIG-006 通过官方来源、唯一目录实体和版本 scope 复核的文档。重建顺序固定为 Parse → Normalize → Classify → Chunk → Embed → Index → Validate → Commit → Completed；未验证文档不能因为“看起来像 Huawei/VRP”而进入 Provider 或写入 Chunk/Index。

## 安全、数据库与回滚

- 只执行 PostgreSQL `BEGIN READ ONLY`；没有 job/document/chunk/embedding/index 写入，也没有外部 Provider/官方站点请求。
- 计划只保留 hash/计数/阶段，不保存正文、来源 URL、凭据、ACL、DSN 或异常原文；租户身份以 hash 形式存在。
- 解除阻断后仍必须使用现有 `KnowledgeReindexService` 的事务替换、维度校验、Compare-and-Set 和失败原子性；本 gate 不绕过这些边界。
- 回滚：停止 rebuild worker，继续读取 V1 projection；所有旧文档和旧 Chunk 保持不变。

## 解除条件

1. MIG-006 对至少一条文档产出 `verified`，且 source registry/version 与目录实体为同租户 active/valid；
2. 重新运行 MIG-007 gate 产生非零 eligible 集合；
3. 通过 Provider 维度、Chunk 原子替换、并发编辑和失败回滚的 PostgreSQL 探针后，才允许 apply。

## 最终结论

BLOCKED：安全重建门禁已落地并通过 PG 只读测试，但现场没有可合法重建的 verified 文档；未执行任何 Parse/Chunk/Embed/Index 生产副作用。该阻断不影响继续执行不依赖重建的 MIG-008 一致性核对。
