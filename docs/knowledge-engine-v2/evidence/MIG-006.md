## 目标

## 判定规则

- `verified`：同租户的 active/valid 官方来源证据、唯一 reviewed catalog 匹配、版本 scope 和平台绑定均成立，才允许进入后续迁移。
- `needs_validation`：上传/手工来源未绑定 source registry、官方证据缺失、catalog snapshot 不可用、UNKNOWN 或候选不唯一；必须复核或重新取证。
- `unusable`：明确的厂商/产品/OS/版本冲突、非法 metadata 或安全字段；必须 quarantine/exclude。
- prefix/trigram 只能生成候选，不能直接提升为 verified；正文内容永远不是实体权威。

## 数据库、安全与回滚

- 数据库：只执行 `BEGIN READ ONLY`，查询 `ai_document`、`kb_source_registry` 和信息架构；无 INSERT、UPDATE、DELETE 或 DDL。SQLite 未作为验收证据。
- 安全：严格 tenant hash；不输出 raw metadata/body、来源 URL、凭据、ACL、DSN 或异常详情；禁止驱动选择和设备写操作。
- 回滚：删除本地 report/manifest 并关闭 MIG-006 迁移 wave；原始 V1 metadata、typed projection 和 source 文本保持不变。

## 已知限制

当前 catalog contract 仍是审计冻结/无生产表状态，且 legacy 文档尚未绑定官方 source registry/version；因此本任务完成的是“重新验证门禁和可审计结果”，不是把文档强行迁移为已验证。后续必须先完成 source evidence/catalog snapshot，再让 MIG-007 对通过复核的文档重新 Parse、Chunk、Embed、Index。
