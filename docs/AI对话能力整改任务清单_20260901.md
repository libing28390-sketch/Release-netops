# Nexora AI 对话能力整改任务清单

> 文档日期：2026-09-01  
> 文档状态：最终整改总清单  
> 正式范围：P0、P1  
> 技术预研：P2（Instructor 隔离验证，不直接进入生产调用链）

## 1. 整改目标

- 提高网络运维意图识别、实体提取和知识检索的稳定性。
- 在信息不足时主动澄清，减少猜测、误路由和答非所问。
- 统一 DeepSeek、OpenAI Compatible、Qwen、Ollama 等模型的内部返回结构。
- 确保设备命令、配置变更等高风险操作必须经过权限、风险和确认校验。
- 保证所有外部 LLM 请求继续经过 Nexora AI Gateway、Security Vault、审计、限流和熔断链路。
- 建立可量化、可回归的 AI 对话与 RAG 质量评测体系。

## 2. 不可突破的架构与安全边界

- [x] 所有 LLM 请求必须经过 `backend/ai/gateway/`，禁止业务代码直接创建外部 Provider 客户端。
- [x] Provider Adapter 只负责传输，接收经过 Security Vault 处理后的消息。
- [x] 密码、Enable Secret、SNMP Community、私钥和用户 Token 不得以明文进入外部模型请求或日志。
- [x] Provider、租户和用户并发限制必须继续生效。
- [x] 结构化校验重试必须纳入预算、审计、限流和熔断统计。
- [x] 外部文档和多模态 URL 必须经过项目统一的安全出站 HTTP 服务，不允许第三方库自行抓取。
- [x] 高风险意图在低置信度、参数缺失或未确认时不得执行。
- [x] 知识检索必须执行租户、角色和知识范围权限过滤。

## 3. P0：意图识别基础整改

### AI-INT-001：建立统一意图结果模型

- [x] 定义 `IntentDecision` Pydantic 模型。
- [x] 定义严格的 `IntentType` 枚举。
- [x] 定义 `RiskLevel` 枚举。
- [x] 统一实体、过滤条件、缺失字段、澄清问题和确认状态。

验收标准：

- 所有意图结果均能由 Pydantic 完整校验。
- LLM 无法返回系统未定义的意图或风险等级。
- `confidence` 必须位于 `0.0` 至 `1.0`。

### AI-INT-002：改造意图解析流程

- [x] 保留确定性规则优先策略。
- [x] 仅在确定性规则无法判断时调用 LLM。
- [x] 替换手工 Markdown Fence 清理和裸 `json.loads()` 逻辑。
- [x] LLM 返回结果统一转换为 `IntentDecision`。
- [x] 为 Prompt 增加版本标识。

验收标准：

- 明确的资产、知识和通用请求不产生不必要的 LLM 调用。
- 非法 JSON、缺失字段和错误枚举不会流入后续业务逻辑。
- 日志能够追踪意图 Prompt 版本和解析路径。

### AI-INT-003：结构校验纠正

- [x] 首次结构校验失败时，生成最小化校验反馈。
- [x] 纠正请求仍通过 `llm_gateway.chat()` 发出。
- [x] 每次意图识别最多进行一次结构纠正。
- [x] 记录失败类型、纠正次数、Token 和延迟。

验收标准：

- 不产生无限重试或重试放大。
- Provider 网络重试与结构纠正重试能够分别统计。
- 纠正后的消息不会修改调用方原始消息对象。

### AI-INT-004：安全降级

- [x] 删除“所有异常静默降级为 `general_qa`”的行为。
- [x] 只读普通问答允许安全降级。
- [x] 执行类、配置类和高风险请求必须返回澄清或拒绝状态。
- [x] 对用户返回可理解的失败原因，对日志保留技术错误码。

验收标准：

- 高风险请求不会因解析异常进入普通执行流程。
- Provider 不可用、格式错误和权限不足具有不同错误提示。

## 4. P0：安全调用链整改

### AI-SEC-001：Security Vault 零泄漏

- [x] 为意图识别和结构纠正补充合成敏感凭据测试。
- [x] 验证 Prompt、Provider 请求、审计日志和错误日志均已脱敏。
- [x] 禁止在结构校验错误中回显完整敏感输入。

验收标准：

- 合成密码、Token、Community 和私钥外发数量为零。
- 安全测试通过率为 100%。

### AI-SEC-002：网关韧性与预算

- [x] 验证 Provider 429 的重试和故障转移。
- [x] 验证连接超时、读取超时和不可达 Endpoint。
- [x] 验证熔断阈值、冷却时间和恢复状态。
- [x] 验证 Provider、租户和用户并发限制。
- [x] 为结构纠正设置调用次数和 Token 上限。

验收标准：

- 上游故障不会导致无限等待或无限调用。
- 每次纠正和备用模型调用都计入审计与预算。

## 5. P1：主动澄清与多轮对话

### AI-DLG-001：缺失参数识别

- [x] 支持设备、接口、时间范围、协议、指标和动作等缺失字段。
- [x] 生成单一、明确、可回答的澄清问题。
- [x] 避免一次提出多个相互无关的问题。

验收标准：

- “检查交换机接口”不会直接猜测设备和接口。
- 澄清结果可以直接补充到当前意图状态。

### AI-DLG-002：多轮会话槽位

- [x] 保存当前任务的已识别实体和缺失字段。
- [x] 支持后续消息补充参数。
- [x] 支持用户否定或覆盖已识别条件。
- [x] 增加任务完成、取消和会话过期机制。
- [x] 避免旧任务上下文污染新任务。

验收标准：

- “不是核心交换机，是汇聚交换机”能够覆盖旧设备范围。
- 会话过期后不会继续使用旧设备、接口或时间范围。

### AI-DLG-003：前端澄清交互

- [x] 展示 AI 当前识别的设备、接口、协议和时间范围。
- [x] 提供候选设备、接口和时间范围快捷选择。
- [x] 允许用户直接修改错误实体。
- [x] 显示“等待补充信息”状态。

验收标准：

- 用户不需要重复输入完整设备名称和上下文。
- 修改条件后，后端收到的是更新后的结构化状态。

## 6. P1：知识库对话与 RAG 整改

### AI-RAG-001：建立知识查询计划

- [x] 定义 `KnowledgeQueryPlan` Pydantic 模型。
- [x] 统一厂商、产品族、系列、协议、文档类型和关键词字段。
- [x] 区分官方知识、企业知识和全部知识范围。
- [x] 将目录选择、对话实体和全文条件合并为一个查询计划。

验收标准：

- 对话查询与知识管理页面使用一致的过滤语义。
- 所有过滤条件都经过字段白名单和权限校验。

### AI-RAG-002：元数据标准化

- [x] 统一 Huawei/华为、H3C/华三、Cisco/思科等名称。
- [x] 审计现有 `UNKNOWN` 厂商、产品族和系列；未发现可由可信来源安全推断的记录，不做猜测性回填。
- [x] 无法推断的数据进入明确的“待治理”范围，并自动排除 RAG，保留在管理列表供补充分类。
- [x] 新文档入库时执行元数据标准化和合法性校验。

验收标准：

- 同一厂商不会因中英文或大小写产生多个 Facet。
- `UNKNOWN` 不会无解释地作为普通产品分类展示。

### AI-RAG-003：混合检索与引用

- [x] 合并目录路径、元数据、全文和向量检索。
- [x] 校验 pgvector 维度与当前 Embedding Contract 一致。
- [x] 保留 pg_trgm 降级检索路径。
- [x] 回答返回文档、章节、厂商、系列和来源信息。
- [x] 无命中时提供精确条件、放宽/切换范围提示和官方资料补充建议；补充任务可在知识库管理页审核后采集。

验收标准：

- 目标文档 Top-5 召回率达到约定基线。
- 回答中的关键事实可以追溯到具体文档切片。
- Provider 或 Embedding 服务异常时有可验证的降级行为。

## 7. P1：工具调用与运维执行安全

### AI-TOOL-001：建立工具调用计划

- [x] 定义 `ToolCallPlan` Pydantic 模型。
- [x] 校验工具名称、设备、参数、动作、风险和确认状态。
- [x] 建立工具及参数白名单。
- [x] 校验厂商、平台和命令兼容性。

验收标准：

- 非法工具和未知参数不会进入执行层。
- 华为、H3C、Cisco 命令不会发送到不兼容设备。

### AI-TOOL-002：高风险保护

- [x] 识别 shutdown、reload、删除配置和批量变更等高风险动作。
- [x] 执行前验证权限、设备状态、影响范围和关联变更单。
- [x] 支持 Dry Run，展示设备、命令和预计影响。
- [x] 使用一次性确认令牌；参数变化后必须重新确认。
- [x] 保存用户输入、模型决策、最终参数和执行结果。

验收标准：

- 未确认的高风险操作执行数量为零。
- 低置信度或参数缺失时不会调用执行工具。
- 审计记录能够还原完整决策链路。

- [x] 在隔离测试模块中验证 Instructor 边界；当前环境未安装 Instructor，不引入生产依赖。
- [ ] 对比内部 Pydantic 方案与 Instructor 的代码量、成功率、延迟和 Token 消耗。
- [x] 通过本地 Fake Gateway 验证未来适配器只能继续使用 Nexora Gateway。
- [x] 隔离测试确认适配器不持有 Provider API Key、Endpoint 或远程 URL。
- [x] 隔离测试未启用任何远程图片、音频或 PDF URL 抓取能力。
- [ ] 固定经过安全评审的版本范围，不跟随主分支或未发布版本。
- [ ] 继续补充真实适配器的消息不可变性、重试预算和错误日志脱敏验证。

正式引入条件：

- 至少多个生产场景需要重复的结构化输出、校验和纠正能力。
- 适配方案不会绕过 Security Vault、审计、限流、预算、熔断和故障转移。
- 依赖升级、镜像体积、启动时间和安全扫描结果可接受。
- 与内部轻量方案相比具有明确、可量化的收益。
