# Nexora v1.0.9

> 发布内容更新日期：2026-10-09

## 2026-10-09 补充交付

### LibreNMS SNMP 硬件与无线采集

- 扩展已纳入 `backend/vendor/librenms` 的厂商 MIB 与规则适配，由 Python 采集适配器执行；补充 Comware 等厂商的硬件和无线指标路径，并支持 SNMPv3 设备认证。
- 改进硬件指标导出中的重复规则校验复用，降低设备传感器较多时的采集处理开销。

### PostgreSQL 性能看板

- 新增 Grafana PostgreSQL 性能看板，并通过 `pg_stat_statements` 与受限权限的 postgres_exporter 采集语句统计。
- 看板展示按 Query ID 排名的 Top SQL、调用速率、执行耗时、平均单次耗时、返回行数和数据库级共享缓存命中率；不采集或展示 SQL 正文。
- Docker 更新流程会重建 PostgreSQL 容器但保留数据卷，并配置 `pg_stat_statements` 与监控账号；无需为此清空数据库数据。

## 2026-10-05 补充交付

### 首页设备统计与数据库兼容

- 首页设备总量改用完整摘要接口，不再受资产列表默认 200 行分页影响；避免首页为统计总量反复加载和处理完整设备明细。
- 修正旧数据库环境中的设备版本字段兼容，并补充数据库迁移，减少设备识别流程因版本列缺失而报错。

### Grafana V2 统一展示

- 12 个 Grafana Dashboard 对齐 NOC V2 颜色与状态语义，规范接口错误/丢弃、无线状态、利用率和 No Data 展示；修正状态字段着色和业务链接字段匹配。

### VictoriaMetrics 存储保护

- 默认监控数据保留期调整为 30 天；VictoriaMetrics 在所在文件系统剩余空间低于 10 GiB 时停止写入，vmagent Remote Write 临时数据上限为 1 GB。
- 这项磁盘保护作用于 VictoriaMetrics，不代表 SeaweedFS/S3 bucket 容量监控或写入限额；S3 数据仍使用 Docker 数据目录所在文件系统的可用空间。

## 本次更新（v1.0.9）

### 告警站点与列表显示

- 告警中心、告警历史及导出使用 CMDB 站点目录中的站点名称，保留主机名与管理 IP；100% 缩放下增加合理列宽和横向滚动，避免站点、等级、状态与责任人文字挤成竖列。

### IPAM 与 CMDB 一致性

- 库存列表与差异核对按租户、VRF 和地址匹配，保留跨 VRF 同 IP 的独立人工记录。
- 周期前缀发现遵守设备的自动投影禁用策略；部分采集、离线与未采集设备不会使其前缀被误判失效。
- 终端站点使用 CMDB 合法站点归属，无匹配时显示未分配站点，避免把交换机名称当作站点。
- 旧终端发现缓存仍以 IP 为唯一键，本次未改变其跨 VRF 存储模型。

### LLDP 完整性与采集预算

- 修正远端 chassis ID 与 subtype 的 OID 映射，并正确保留二进制 MAC；拓扑 LLDP 单表 walk 预算为 30 秒、最多 10000 行，支持设备配置的 SNMP 端口。
- 超时、失败或截断保留明确的不完整状态，避免把部分结果当作完整结果老化已有观测；通过现有 CLI 路径兜底。

### 重复错误与监控开销

- 修正 MIB 激活状态整数与布尔值的错误比较，减少重复符号解析和不满足条件的规则探测。
- 自动 OID 发现失败按 120/240/480/900 秒退避，无硬件类别结果等待 900 秒再试，普通指标轮询继续执行。
- m0262 扩宽接口计数与聚合存储，避免大计数插入溢出；原始采样和持久化基线在同一事务提交，提交成功后才更新内存基线。
- 修正空接口拓扑边重复主键问题，保留已有链路标识并检查租户与事实一致性。
- 提供 `scripts/collect_container_errors.sh` 和 `scripts/capture_netops_cpu.sh` 及使用说明，便于收集容器错误和 CPU 证据。线上 CPU 降幅仍需部署后对照采样；本次不改变 SNMP exporter 的设备认证或超时配置。

### 拓扑发现与资产名称

- LLDP 优先使用 SNMP；本轮 SNMP 失败或数据不完整时，再串行使用现有 CLI 命令和解析模板兜底，正常的空邻居结果不触发 CLI。
- 拓扑仅展示当前纳管资产，一台设备保留一个图标；采集异常保留设备图标并标记状态，未关联的邻居仅用于诊断。
- 本次发现使用当前观测生成链路，移除旧观测对本轮结果的干扰；双侧 LLDP 证据显示实线，单侧证据显示虚线。
- 补充 SNMP 聚合口与成员口采集，保留物理成员链路和聚合口信息。
- 资产导入必须填写主机名；成功读取 SNMP sysName 后同步回填 CMDB 和关联设备，无法同步时保留现有名称并提示检查配置。
- 关联资产的设备名称统一从 CMDB 获取；CLI 邻居按当前资产主机名准确、唯一关联，名称未匹配的结果仅用于诊断。
- 简化拓扑发现进度与异常提示，集中提示检查 SNMP Community、CLI 解析模板及资产主机名。

### 平台绑定与启动缓存

- 明确设备首次平台绑定与后续修改权限；管理员通过受控重绑定路径修改平台，普通用户获得明确的权限提示。
- 对 LibreNMS MIB 与规则引导增加缓存和变更检查，避免内容未变化时每次启动重新扫描导入。

### 监控平台与 Grafana

- 修正 Grafana、vmagent 与 Nginx 子路径间的内部采集路径，避免 Grafana `/metrics` 请求被重定向到公网 HTTPS 地址后抓取失败。
- 修正 Docker cAdvisor 采集配置与容器指标看板，覆盖容器 CPU、内存工作集、磁盘读取/写入速率；补充容器无数据时的排查线索。
- 统一多个 Grafana 看板的运行时间展示，并改进监控平台健康看板中的组件状态与采集目标说明。
- 新增专线中心，可登记线路、A/Z端点、合同带宽和计量范围，并查看接口历史、探针绑定和 SLA 覆盖。
- 逐线路探针记录目标、用途、执行器、配置版本和路径证据；只有匹配当前执行上下文的可复核路径证据参与可信可用率计算，缺证或不支持时显示数据不足。
- 共享物理接口保留端口总流量参考，但抑制线路利用率和容量告警，避免把整口流量归因给单条专线。
- 新增专线端点、合同历史、探针质量和 SLA 迁移；旧 WAN 接口补齐线路租户/资源范围校验。

### 告警处置与通知

- 告警运营看板将 `retrying` 计入失败尝试，统计 24 小时告警成功率；有指标但没有已完成尝试时显示“暂无已完成投递”，指标源缺失时显示“数据暂不可用”。
- 告警等级使用中文显示，相关通知指标名称统一为“告警成功率”。

### 定时作业安全审批

- 敏感审批可按审批人可用能力选择 MFA 动态码、邮箱验证码或飞书验证码，不再限定只能通过飞书授权。

### S3 对象存储

- Docker 新安装默认启用内置 SeaweedFS S3，为配置备份与 PAM 录像提供对象存储；本地已有文件不会自动迁移，切换前需按迁移流程处理。

升级后请确认 Compose 已按新版本重新创建 cAdvisor、vmagent、Grafana 与 Nginx 容器；旧容器日志中关于 Docker overlay layer 的错误不会因只替换看板文件而消失。

## 发布定位

v1.0.9 起，Nexora 服务端的发布形态收敛为 **Linux / Ubuntu / Docker**。v1.0.8 是最后一个提供 Windows 原生桌面服务端发行包的版本；v1.0.9 不再构建或发布 Windows 桌面安装包、桌面启动器或 Windows 服务端发布分支。Windows 操作员工作站 Agent 仍作为独立附件发布，用于从 Windows 浏览器访问 Linux 服务端并拉起本机浏览器/终端。

Windows 网络设备的资产管理、SNMP 采集、SSH/WinRM 远程管理能力继续保留。这里的变化只针对 Nexora 平台自身的部署与发行形态。

## v1.0.9 已有基线功能

- 移除 Windows 桌面启动器、原生安装包、Windows 专用打包资源及 Windows 发布流水线。
- 发布工作流只生成 Linux / Ubuntu / Docker 归档，并将本说明作为 GitHub Release 正文。
- 前端 Terminal Agent 配置入口按浏览器所在工作站提供 Windows Agent 或 Linux/Ubuntu 安装方式。
- Windows 工作站 Agent 独立构建并挂载到同一版本 Release，不代表恢复 Windows 服务端部署支持。
- 配置备份与 PAM 录像接入统一对象存储接口，支持本地存储和 S3 兼容存储配置。
- SNMP 同步主机名时同步更新资产管理中的主机名，资产管理数据继续作为初始数据源。
- Docker 构建过程保留阶段日志，便于查看构建进度和失败原因。
- 增加 SNMP Walk 诊断与公共/厂商 MIB 查询，解析结果突出展示设备、系统和 LLDP 邻居等关键信息。
- 高级 OID 浏览器显示资产模板中的完整厂商目录，并通过 LibreNMS 规则、sysObjectID 和 sysDescr 自动识别受管设备厂商；登记信息与探测结果冲突时明确提示。
- LLDP 诊断补齐本地接口名映射，可结合 LLDP 本地端口表和 IF-MIB `ifName` 将邻居端口索引解析为接口名称。
- 修正网络接口指标的序列身份与 Grafana 面板聚合，减少重复接口曲线并完善 Linux/Windows 主机监控视图。
- Docker 新安装默认启用内置 SeaweedFS S3 并生成安装专用凭据；现有本地录像和配置备份不会自动迁移。
- Grafana 通过同源认证代理复用 Nexora 登录会话，匿名访问保持关闭；专用认证网络使用 Docker IPAM 动态分配，并由 Nginx 统一剥离外部 `/grafana/` 前缀。
- Docker 前端镜像只安装构建所需依赖，避免与 Promptfoo 相关的原生 SQLite 开发依赖影响离线或受限环境构建。

### v1.0.9 监控与告警基线

- 告警规则支持租户范围隔离、从 CMDB 确认执行设备、资产范围匹配，以及按通知组投递 Webhook/邮件告警；历史通知方式按当前支持的渠道兼容归一化。
- 告警详情和事件时间线查询按设备租户范围过滤，确保跨租户事件不会出现在详情中。
- 修复在线设备返回 SNMP CPU/内存指标时告警采集循环引用缺失设备名、导致本轮处理提前中断的问题。
- 邮件告警支持管理多条 SMTP 通道，并按已启用通道选择收件目标。宿主机 CPU、内存和磁盘阈值用于平台健康状态计算，不作为告警投递渠道。
- 新增平台健康、告警运营和出向探测质量看板；出向探测补充 ICMP 丢包与抖动数据，并显示明确的速率单位和接口别名。
- Prometheus 可抓取聚合后的平台、告警和出向探测指标，为 Grafana 提供看板数据。
- 新增 PostgreSQL 迁移以支持租户告警规则、出向探测质量字段和旧告警通知数据归一化。升级前请备份数据库。

## 升级提示

- 本次含 m0262—m0267 数据库迁移；启动会自动应用待执行迁移。升级前备份数据库并评估遥测表大小，ALTER TYPE 可能锁表和重写数据，建议安排维护窗口。应用回滚可保留扩宽列，数据库降级会拒绝超出旧 INTEGER 范围的值。
- Windows 原生服务端部署请继续使用 v1.0.8；Linux/Docker 新部署和升级使用 v1.0.9。
- Windows 用户访问 v1.0.9 的 Linux 服务端时，安装同一版本 Release 中的 Windows Workstation Agent。
- 从 v1.0.8 或更早版本迁移到 v1.0.9 前，请先备份数据库、`data/` 及现有配置备份/PAM 录像数据。
- Docker 新安装默认使用内置 SeaweedFS S3；总可用空间由 Docker 数据目录所在磁盘决定，当前没有前端 bucket 容量配额。
- 更新现有 `.env` 时保留原有存储后端；切换到 S3 不会自动迁移本地录像和配置备份，需按单独迁移流程处理。
