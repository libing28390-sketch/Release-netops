## 1. 完成摘要

已完成 42 轮线上实时浏览器 Copilot 测试中发现的 4 项边界缺陷修复与回归验证：

1. **IPAM 与 PAM 子串冲突修复（P0）**：将 `ipam_prefix` 路由置前，并将 PAM 英文匹配改为词边界正则 `(?<![a-z])pam(?![a-z])`，`"IPAM 网段利用率怎么样"` 不再误命中 `pam_sessions`。
2. **因果/风险/对比分析直通大模型升级（P0）**：扩展 `_REASONING_ESCALATION_MARKERS`（新增 `结合上面 / 结合上述 / 潜在风险 / 风险分析 / 风险评估 / 对比 / 比较 / 哪台更 / 哪个更 / 更需要关注 / 分析下 / 分析一下`），命中时确定性返回 `intent="troubleshooting"` + `reasoning_escalation=True`，直接跳过外部 `intent_parser`（省去 600+ Token 的额外分类调用，同时避免被误判为 `asset_analysis` 吐出全网设备表），并携带 `recent_local_facts` 与 `active_device` 交由大模型综合分析。
3. **全局查询清空粘滞单设备焦点（P1）**：`entity_context.py` 将无单设备代词的复数列表问法（`有哪些 / 列表 / 待审批`）判定为 `scope_mode="global"`，同时移除裸词 `"变更工单"` 的省略主语继承；`assistant.py` 在 `scope_mode == "global"` 时显式清除 `entity_context_json` 中的 `active_device`。
4. **危险命令只读拒绝守卫无条件优先（P1）**：`assistant.py` 中 `_explicit_device_execution_request` 不再因上一轮残留的 `pending_clarification` 被跳过，确保 `"帮我在这台设备上执行 undo ospf 1 并保存"` 始终直接返回 0-Token 只读拦截回复。
