# 计划作业审批快照对齐走查

## 完成摘要

- 查明执行器会把当前数据库行重建为执行快照，并与审批时保存的摘要比对；不一致时在执行前拒绝。
- 修复新建作业的摘要口径：巡检项按真实执行的逗号/换行拆分规则规范化；创建时基于拟持久化行生成执行快照，并与已批准清单核对。
- 摘要不匹配时在消费审批令牌前返回 409，要求重新申请审批；既有作业摘要不会被自动重写，执行端校验没有放宽。
- 历史页对已知摘要不一致原因仅显示“权限校验未通过，作业未执行”，不附加原因、步骤或跳转按钮；提示弹窗进一步收窄并按内容自适应高度。正常执行详情仍保留原布局，其他权限拒绝仍保留原提示。

## 根因证据与边界

- 代码路径证实：创建授权摘要曾直接从规范化请求清单生成；执行时则从数据库字段反向生成快照。巡检项经 `check_items` 列表写入逗号分隔的 `commands`，执行端再按逗号/换行拆回列表，存在有损往返。
- 当前没有用户截图对应的 job ID、现场数据库行或 scheduler 日志。不能证明该条记录实际含有触发该往返差异的输入；也不能排除作业在审批后确实被编辑。
- 对旧的摘要失效作业，安全的恢复方式是检查内容后重新审批；本次不对数据库做回填或重签。
