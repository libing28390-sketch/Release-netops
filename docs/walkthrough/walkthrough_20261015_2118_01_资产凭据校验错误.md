# 资产凭据校验错误修复记录

## 结果
- 资产新增/编辑请求返回 HTTP 400/422 且 API 使用结构化 `error.message` 时，资产页面现在展示后端的校验原因。
- 提示继续对当前表单中的密码值脱敏；如果后端给出 Request ID，也会附在提示中，便于查日志。
- 增加回归测试，验证结构化校验原因可见且合成密码不会出现在页面错误提示里。

## 根因
- 后端稳定错误响应把校验原因放在 `error.message`。
- HTTP 客户端把结构化 `payload.error` 放入 `ApiError.detail`；资产页此前只接受字符串 `detail`，所以退回“保存校验失败，请检查填写内容”。
- 当前服务日志只记录 422 状态和请求 ID，没有保留原始响应正文；无法从现有日志还原刚才那次具体字段校验原因。
