# 资产录入必填标识执行记录

## 完成摘要
新增资产窗口给资产编号、管理 IP 添加红色 `*`、原生 required 与 aria-required 标识，并说明主机名、整机 SN、型号选填。新录入缺少资产编号/管理 IP 或管理 IP 格式错误时不能提交；批量导入预检执行同样规则并报告行号。历史资产编辑不增加必填阻断。实际下载的 API 模板和静态模板同步更新标识，保留原有生命周期等业务必填项。

## SNMP 采集核查
`backend/services/snmp_service.py` 的通用 `_snmp_walk` 默认上限为 200，达到上限标记 truncated。资产型号识别 `snmp_entity_model_service.py` 已显式对型号、实体类型、父实体三列传入 2000 行上限；按实体索引关联，不按行位置拼接。达到 2000、标记截断、超时或异常时拒绝不完整表，不将部分记录当作可信整机型号。本轮未修改 SNMP 生产逻辑。

导入识别 `snmp_import_identification_service.py` 当前读取 sysObjectID/sysDescr/sysName 和实体型号；没有读取/回填 entPhysicalSerialNum。页面与模板将 SN 标为选填，不承诺当前自动采集。真实设备超过 2000 行或三秒内不能完成 WALK 时仍可能无法取得型号，不能将本轮结果解释为无限行数支持。

## 用户追加的拓扑耗时只读核查
本轮未修改拓扑采集逻辑。手动 `/api/topology/discover` 默认设备并发为 6，按固定切片 gather，20 台为 6/6/6/2，存在每批最慢设备阻塞下一批的等待。每台先并行读取 10 个 LLDP/接口相关 OID，业务调用传 `max_rows=None`，每个 walk 30 秒，使用普通 GETNEXT walk；单进程 SNMP gate 默认 30，且 gate 排队发生在 walk 的30秒超时之外。LLDP后依次等待聚合 inventory、本机名确认、本机 IP 身份以及 observation 入库；聚合中多个表串行读取，失败时可另行触发 SSH CLI 聚合采集，即使 LLDP 自身已成功。

每设备尝试默认外层超时 300 秒，最多 2 次，仅 `ssh_unreachable` 被列为可重试。run 内每台不做全局图重建；开始清理后及全批完成时会重建。周期调度路径并非固定6台分批，不能混用两种路径的完成语义。以上为源码证据，没有远端运行配置或分阶段实测，不能把默认值当成用户现场配置，也不能断定主要耗时来自哪一阶段。优先建议滑动并发队列、评估 LLDP GETBULK、复用同次接口表并补充分阶段耗时；均尚未实施。
