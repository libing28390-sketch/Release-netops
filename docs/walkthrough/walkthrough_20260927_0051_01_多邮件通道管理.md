# 多邮件通道与收件人管理

## 完成摘要

将 `/management/notifications` 从单份 SMTP 配置改为多通道管理：管理员可以新增、编辑、删除、停用/启用和快捷测试每个通道。新增、编辑继续使用三步配置向导；服务商选择支持国内邮箱、国际邮箱和开源/自建类别及独立品牌标记。收件目标可同时包含系统用户组和多个系统用户。

告警邮件现在按已启用 SMTP 通道拆分为独立 outbox 投递任务，失败重试互不影响。组目标按 `users.group_name` 在发送时动态解析同租户、active 用户，收件地址去重；旧 `primary` 与个人通知偏好保持兼容。

## 关键实现说明

- m0256 增加通道显示名和 JSON 收件人目标，保留旧凭据与配置；迁移可重复执行。
- SMTP profile API 覆盖列表、收件人目录、创建、更新、启停、删除、连接测试和测试邮件；密码密文不回传。
- 收件人目录与保存校验按当前租户和 active 用户过滤；组按自由文本 `group_name` 动态解析，不保存静态邮箱快照。
- email outbox 为每个启用 profile 建立独立 delivery key；旧未拆分记录不重复展开，workspace 通知仍固定使用 `primary`。
- 管理列表使用公共 `DataTable` / `DataTableFrame`，提供测试、启停、编辑、删除行操作、权限/空态和测试反馈；旧单通道死组件已移除。
- 供应商卡片使用区分式品牌标记，“国内邮箱”替代旧分类，移除 Microsoft 365 世纪互联独立卡片。

## 风险与回滚

- 系统用户组目前是 `users.group_name` 自由文本，没有独立组 ID；用户组改名后需在 SMTP 通道中更新目标。
- 启用多条通道会为各自配置投递邮件，按所选目标向多个收件人发送。
- 若回滚代码，保留新增数据库列与配置数据；迁移 downgrade 有意不删除数据。恢复上一版代码后，旧单通道 API 和 `primary` 仍可工作。
