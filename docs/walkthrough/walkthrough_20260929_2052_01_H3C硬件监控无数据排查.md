# H3C 硬件监控无数据排查

## 完成摘要

确认 F1090-9 的 SNMP 硬件探测确实有数据：线上诊断页显示 176 个传感器、200 条测量；设备清单状态为在线、健康、SSH。Grafana 中 `network_snmp` 对该设备的 `up` 为 1，硬件库存 scrape `up` 也为 1，但 Explore 中该设备没有 `nexora_hw_sensor_info` 或 `nexora_hw_capability_status` 序列。

诊断 UI 调用 `/api/platform-registry/snmp-hardware-discovery-test`。该接口直接执行 `discover_device_oid_config()` 并返回读数，不调用 `persist_discovery()`；Grafana `/hardware-metrics` 只读取已持久化的传感器库存。后台轮询原先仅依据通用发现快照的 6 小时有效期决定是否重新发现，不会检查硬件能力记录是否缺失。

后续线上只读 SQL 直接确认了触发条件：F1090-9 的设备与 `snmp_device_discoveries` 快照的 vendor/platform/model/version 完全一致，快照年龄为 1 小时 47 分钟；`snmp_hardware_discovery_runs`、`snmp_hardware_capabilities`、`snmp_hardware_sensors` 对该设备均无记录。因此后台 freshness gate 将该身份发现视为新鲜，没有启动硬件发现和持久化。厂商汇总同时确认 Cisco 有 6 台设备、30 条可导出且质量为 good 的传感器，H3C 为 0，排除全厂商共同无数据。

已在后台增加硬件能力库存检查：身份快照仍新鲜时，如果能力行不存在或发现版本过旧，也触发发现并经现有 `persist_discovery()` 路径写入。没有按 H3C 隐藏数据，也没有添加 H3C 专用 SNMP 规则。
