# 自动化脚本、巡检指标与结果可读性修正

## 完成摘要与证据边界

完成31条内置脚本、94项巡检指标、脚本列表分页、NSOT采集目录和巡检结果详情页的源码修正。此前浏览器盘点记录的NSOT目录为259条重复的“模板×平台版本”组合；现在按模板展示，共7条模板行，选择平台 profile 后再查看该 profile 的命令。当前没有部署本次代码，因此运行站点页面和真实设备执行效果仍未验证。

用户此前说明 Nexora 与 LibreNMS 在同一 Docker 宿主机，停掉 `prom/snmp-exporter` 后离线告警恢复。这个时间相关性不能单独证明根因。Prometheus SNMP Exporter 的数据路径是 Prometheus 经 HTTP 请求 exporter，再由 exporter 通过 SNMP 访问设备；LibreNMS 的默认可用性检测包含 fping/ICMP。两套采集的轮询负载、目标重叠和宿主机资源竞争都可能构成解释，但需要离线告警源、LibreNMS poll log、SNMP exporter scrape 记录和容器资源数据才能判定。参考：[SNMP Exporter 架构](https://github.com/prometheus/snmp_exporter/blob/main/examples/sample-configs/README.md)、[LibreNMS 快速 Ping 检测](https://docs.librenms.org/Extensions/Fast-Ping-Check/)、[LibreNMS ICMP 配置](https://docs.librenms.org/Support/Configuration/)。

仓库当前 `monitoring/snmp-exporter/snmp.yml` 是 `modules: {}` 的安全回退配置；Compose 将 `nexora-monitoring-artifacts` 持久卷只读挂载到 exporter，启动时读取卷中的运行配置。因此仓库文件不能代表故障现场卷内配置。历史诊断包 `artifacts/collector_error_correlation_20261002.md` 记录了两台 H3C (`10.254.0.5`、`10.254.0.6`) 的 496 次配对失败，全部为 `request timeout (after 2 retries)`；IF-MIB 周期约30秒，system 周期约900秒，日志中没有成功采样。该次快照 exporter CPU 为1.11%、vmagent为0.27%，不足以支持“exporter CPU 饱和直接导致设备离线”；同时它不能证明是用户此次告警中的设备或同一时间段。现场根因仍需把 LibreNMS poll/fping 结果、exporter 实际 target/module/interval、同分钟容器资源和告警状态对齐。

## 修改内容

### 脚本与分页

- 审校全部31条内置脚本：24条 Linux Shell、7条网络 CLI 命令集。Linux 单项与集成脚本在缺少数据、命令或权限时输出 `NA`，避免把采集失败伪装为正常的0；修正计数器增量、单位口径、依赖工具和状态输出。网络脚本每条命令均来自相应平台的本地只读命令目录，去掉统一覆盖所有型号的巡检承诺。
- `std_linux_integrated` 的输出键与单项检查键保持一致；服务器巡检按 `check_key` 读取综合输出，缺失指标不再错误地回退为数值0。
- 脚本列表翻页时取消过期请求、清空旧页行并显示加载/错误状态；移除旧行的布局退出动画，避免翻页重影。

### 巡检指标

- 94项默认指标补齐显式单位、解析类型、期望状态和比较方向，并贯通 PostgreSQL schema、初始化种子、API schema、CRUD 与服务端执行消费者。
- SNMP 风扇/电源从 LibreNMS 新鲜、活动的 `component_state` 硬件传感器读取；状态码为 `0=正常、1=警告、2=故障、3=未知/未采集`。缺测/unknown 不报成功，也不计为严重故障。
- Linux NTP 同步与最近重启改为状态型指标，明确期望值，不再把布尔状态套入百分比/计数阈值。
- 阈值比较方向支持 `above` 和 `below`，并允许有限负数阈值。Cisco Syslog 检查使用 running-config 计数，0个日志主机低于阈值1时告警。
- 固定通用 BGP 占位指标 `net_bgp` 默认停用，避免把未知平台/无邻居样本解释成设备故障；平台专用邻居指标保留。
- ICMP/TCP 指标复用已有 ping/SSH 探测结果评价阈值，避免重复探测；巡检指标新增/修改时保存 `script_id`、阈值、解析类型、期望值、单位和阈值方向。
- Cisco SNMP community 仅在内存中解析，结果只存 `safe`/`unsafe`；缺少匹配行按未采集/解析失败处理。持久化的原始命令输出由脱敏器遮蔽。
- 指标页统计使用服务端跨页 facets；vendor filter 使用原始 vendor code，名称仅用于展示；category facet 匹配大小写不敏感。94项统计包含“其他采集方式”，不再因当前页或类别大小写显示错误。

PostgreSQL migrations：`m0289_inspection_item_unit`、`m0290_inspection_threshold_direction`、`m0291_disable_generic_bgp_inspection_item`。运行与测试路径保持 PostgreSQL-only，没有使用 SQLite。

### NSOT 与巡检结果输出

- NSOT 目录改为每个采集模板展示一行，条件和备注不再按平台重复；profile 命令在选择具体 profile 后查询。页面说明 profile 存在不等于模板已验证适配该型号。
- 巡检详情默认展示总体结论、去重后的严重/警告数、优先异常与建议及最多4项核心指标。指标使用中文名称和单位；风扇/电源等状态以正常、告警、故障、未采集展示，并按异常优先排序。未知与未采集分开显示；Ping/SSH 失败统一去重计数，页面设备徽标与摘要使用同一健康结论。
- 完整指标分析、快照、合规内容和原始命令保留在默认折叠的“技术详情”中。Excel 首表列任务时间与设备状态计数，并为每台告警/异常设备列一条优先问题和建议；PDF 首页/首部呈现相同状态总览，异常设备摘要增加建议列。详细工作表和原始命令仍可追溯，JSON 继续保留完整机器可读字段。
