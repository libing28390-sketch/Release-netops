# 资产编辑必填标识与堆叠SN

## 完成摘要
编辑窗口中的资产编号和管理IP继续带红色必填星号；序列号字段可以编辑并保存。SNMP身份同步按H3C已验证的固定索引GET 1、2、3，并读取同索引实体名称、描述、型号；不执行ENTITY-MIB WALK。堆叠实体分别持久化，列表显示成员数量，编辑窗口和只读资产详情按实体显示各自SN，不把两个SN拼到同一个标量字段。未知成员名称显示实体索引和“成员归属待确认”。

## 根因与修改
- `src/pages/AssetManagement/components/AssetModal.tsx`：SN Field原先设置 `disabled={isEditMode}`。编辑时移除此禁用，显示说明；资产编号和管理IP仍只读且仍标必填。
- `backend/api/assets.py`：SN原列在创建后immutable allowlist中，因此仅开启input无法持久化。现允许单独修改SN、更新linked device及source=`operator`；资产编号、主机名、管理IP、厂商、型号等原不可变字段保持规则。
- `backend/database/migrations/m0303_asset_serials_allow_duplicates.py`：HCL多台设备复用相同SN，故移除历史SN全局唯一索引；资产编号、主机名和管理IP唯一约束保留。机箱成员仍按资产+实体索引存储。
- `backend/services/snmp_import_identification_service.py`：在既有身份识别核心之后，以独立步骤对H3C采集机箱SN，不让SN采集失败回滚已有vendor/model/hostname识别。确认已禁用SNMP、身份冲突或无关联设备时跳过。
- `backend/services/asset_chassis_serial_service.py` + migration 302：固定GET 1/2/3，解析OctetString，拒绝含NUL的数据库文本；读取异常与NoSuch实例分别处理。保留手填标量SN；完整单实体且字段为空时自动填充，堆叠时各成员独立保存；不完整采集不清除旧成员，空快照使用持久watermark拦截过期并发结果。
- `backend/api/assets.py`：资产列表/详情向有权限的caller投影成员数组；批量SNMP反馈包括成员同步结果。
- `src/components/AssetChassisMembers.tsx`：只读展现名称、索引、SN、型号和描述；未知名称明确待确认。`AssetReadonlyDetail.tsx`与AssetManagement编辑modal复用该组件。
- `public/templates/asset_import_template.xlsx`、`backend/api/assets.py`动态模板和`src/pages/AssetManagement/index.tsx`回退说明同步为H3C可自动读SN，堆叠成员分别保存，其他厂商手工填写。

## HCL证据与SN为空的排查结论
用户在HCL及`192.168.56.14`设备上运行OID `.1.3.6.1.2.1.47.1.1.1.1.11.2`返回非空SN，并确认模拟器设备会复用相同SN。这证明HCL SN可读，同时说明SN不能当作不同设备之间的全局唯一键。它不证明应用服务器使用相同profile、SNMP版本、端口和访问策略，也不表示此前入库的历史资产已完成新采集。部署/加载新代码后，已有资产需在资产管理执行一次手动SNMP同步；结果会显示SN同步状态。收到具体`serial_sync`状态和安全脱敏的应用日志后，可进一步定位失败发生在采集、权限/版本配置还是写库环节。

## 剩余边界
H3C以外厂商不调用该固定索引逻辑。设备只在名称/描述未标出IRF成员时按实体索引显示，不能从SN推算成员号或主备。H3C以外厂商SN仍可手工录入。应用服务器配置可能与HCL模拟器不同，手工同步反馈将提供具体状态。改动未部署；新迁移302需应用启动后生效。
