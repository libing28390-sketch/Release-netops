# 告警规则租户范围与通知组优化

## 完成内容

- 告警规则和规则历史增加租户隔离；m0257 为既有租户复制历史网络规则，保留默认租户原 ID 和行为。宿主机规则仍只属于 `tenant-default`。
- 新增当前租户的活动用户组目录与 `notification_group_names` 持久化。网络告警根据告警设备 tenant 和规则组过滤活动用户；SMTP profile 收件目标继续与规则组取交集。
- 通知投递遇到无活动组成员或格式错误时不会扩大到全体用户；无收件成员的 outbox 投递不会重试。规则组不会附加到直接全局 webhook payload。
- 规则运行时缓存改为按 tenant 分开，设备离线和维护窗口重开按 `ping_unreachable` 读取正确租户的规则；规则控制 severity、通知策略和通知组。没有匹配的已启用规则时保留告警事件，但不发送规则通知。
- 新建规则只允许已接入执行器的指标；历史 `srv_*` 规则标记为不可执行，API 批量启用也会拒绝重新启用它们。`host_*` 仅默认租户可配置，固定全局范围、workspace 渠道且不允许通知组；迁移同步归一化旧宿主机规则及其历史快照。
- 宿主机阈值按 warn/critical 分级选取最新启用规则，避免只加载前两条时遗漏某一级，或混用级别阈值。
- 精简告警规则主表单，按范围类型解释匹配字段；OID/采集信息和高级阈值行为收起，展示通知组选项加载/空/错误状态，并说明 SMTP profile 收件目标的交集关系。

## 运行边界

- PostgreSQL 集成测试使用仓库的隔离数据库 fixture；没有将迁移应用到用户的运行数据库。
- 告警规则组限制适用于用户级 webhook、workspace 通知和邮件收件用户。直接配置的 `global_webhook` 是系统级目标，不属于用户组收件范围。
- `host_*` 仍由 `/api/health` 独立评估；它使用默认租户的全局 workspace 规则和用户个人通知偏好。
- 迁移为每个已存在的租户复制网络规则，运行应用时由现有 migration runner 执行。
