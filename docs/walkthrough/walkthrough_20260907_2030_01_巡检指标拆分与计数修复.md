# Linux 巡检指标拆分、TCP 重传率与指标计数执行记录

## 完成摘要

已处理巡检指标管理页和 Linux 主机巡检的三类问题：

- 指标分类/采集方式计数改为服务端 facet，全量统计不再受当前分页影响；首次打开页面即可显示“服务器/主机”的真实数量。
- 内置 Linux Server 指标改为按指标绑定独立 Shell 脚本执行；`std_linux_integrated` 保留为旧配置回退，`insp_linux_full` 继续供遥测使用。
- TCP 重传率改为一秒采样窗口内的 `RetransSegs` 增量 / `OutSegs` 增量，并补齐 `tcp_retrans_pct` 输出键，同时保留 `tcp_retrans` 兼容别名。

## 根因

### 指标计数

`/api/inspections/items/all` 开启分页后只返回当前页 20 条记录，原前端直接从 `items` 计算分类数量。因此第一页刚好是网络设备指标时，服务器分类会显示为 0；点击服务器分类后重新请求服务器页，数量才看起来正确。

### Linux 指标脚本

默认 Server 指标过去全部绑定 `std_linux_integrated`，而巡检执行器又优先执行 `insp_linux_full`，造成“页面显示的脚本”和“实际执行的脚本”不一致。部分指标没有对应的单指标脚本。

### TCP 重传率

旧综合脚本只输出 `tcp_retrans`，但内置指标的 `check_key` 是 `tcp_retrans_pct`，所以显式指标无法从综合输出关联到值；同时旧公式使用系统启动以来累计计数，不能代表当前采样窗口。

## 修改文件

- `backend/services/inspection_service.py`
  - 分页列表增加分类和采集方式 facet 查询，保留既有 `items`、`total`、分页字段。
  - 对有 `script_id` 的 Linux 指标按脚本 ID 去重执行；无绑定脚本的旧自定义配置继续使用综合脚本回退。
- `backend/database/seed.py`
  - 为缺失的 Linux 指标补充独立标准脚本。
  - 将 22 个内置 Server 指标绑定到对应脚本。
  - 修正 TCP 重传率的字段读取、采样窗口和兼容输出。
- `src/pages/InspectionItemsTab.tsx`
  - 使用后端 facet 渲染分类和采集方式数量，避免从当前页推断全量数量。
- `backend/tests/vendor_audit/test_linux_inspection_contract.py`
  - 覆盖 facet 查询过滤边界、内置脚本绑定唯一性和 TCP 输出契约。

## 生效方式

这些修改需要进入后端镜像。部署时重建并重启后端容器，应用启动时会通过现有 seed/upsert 逻辑更新脚本和内置指标绑定；不需要新增数据库迁移。重启后刷新指标管理页，第一页即可看到全量分类计数。

单指标执行会增加 SSH 脚本调用次数；相同 `script_id` 在一次巡检内会去重，只执行一次。TCP 重传率在采样窗口没有新增出站报文时返回 0，避免除零。
