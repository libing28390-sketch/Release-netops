# 配置备份统计口径与对象存储说明走查

## 完成摘要
- 新备份批次建账前排除服务器资产及无法识别为网络设备的非候选对象；明确关联到 network_device 资产、可识别网络平台，或有匹配已发布备份动作的网络设备进入统计。网络设备里不支持备份命令的项仍显示为跳过并参与该网络批次统计。
- 批次列表、详情、分页设备列表和 Site 汇总按照当前资产关联过滤 server/host/physical_server；历史批次中服务器不会再拉低网络设备成功率。
- `/configs/backup-stats` 的今日台账、快照趋势、总快照数、存储大小、设备统计和最近备份统一排除 server/host/physical_server，避免旧服务器账本污染成功率和备份指标。
- `/config/backup` 用通俗标签说明存储连接检查和 READY、PENDING、ERROR、LEGACY、spool 五类计数。明确说明计数包含配置备份及 PAM 录屏；S3 检查只验证 Bucket 列表访问，不会逐对象验证上传/下载；S3 兼容表示采用 S3 接口，并不意味着服务商一定为 AWS。
- 已审查内置厂商运行配置/启动配置命令，命令列表汇报给用户。其他厂商使用已发布且厂商/平台匹配的配置档命令，不在代码中硬编码统一命令。

## 关键实现说明
- `run_scheduled_backup` 使用 `is_network_device_for_config_backup`、明确关联的 `network_device` 资产及可备份候选判定共同筛选账本目标。此函数也由手动触发路径调用。新账本不再把服务器记录为 skipped。
- 历史列表、批次详情、设备分页、Site 汇总和今日统计通过 `physical_assets.asset_type` 排除 `server`、`host`、`physical_server`。如果批次账本存在但资产已删除，资产类型不可恢复，该行按默认网络设备处理。历史统计也会随当前资产分类变更而变化。
- S3 状态徽标区分连接检查失败、上传失败、上传待处理和连接检查通过；卡片解释 S3 Bucket、本地旧路径和暂存副本。spool 行数会和 PENDING/ERROR 等生命周期状态重叠，不表示单独另一批文件。

## 剩余风险/后续建议
- 历史账本没有保存当时的 `asset_type` 快照，因此历史报表使用设备当前关联资产类型；设备资产关系被删除或后来改分类时，历史批次统计可能随之变化。
- 已发布配置档支持的非内置厂商命令取决于数据库里当时已发布的 action 内容，需在对应厂商的配置档内核对。
