# 资产导入、编辑与删除提速 walkthrough

## 结果

- 导入请求运行期间，资产列表按约 1.2 秒间隔静默刷新，已写入的行可逐步显示；请求完成后再刷新最终列表和汇总。
- 批量删除改为一次 API 调用、一个数据库连接和一次提交；单项权限和失败隔离继续保留。删除关联数据常用的查询键增加了索引。
- 新建和导入将 SNMP、管理端口、WinRM 与 SSH 配置并入资产 INSERT，减少每条资产后续重复 UPDATE。
- 编辑请求只携带相对打开表单时真正发生变化的字段。资产类型、资产编号、序列号、厂商、型号、主机名、管理 IP 和设备高度在编辑页只读，后端也拒绝变更；不会改动导入时的 SNMP 主机名识别逻辑。
- 状态、生命周期、站点、机柜、安装起始 U 位、部门、备注、网络接入信息及凭据等仍可修改。机箱设备高度 `u_height` 与机柜内安装 U 位是两个不同字段：前者固定，后者可随迁移调整。
- 状态单字段编辑不再发送标签、Web 配置和未变身份字段；不会重复执行身份重复查询、凭据预解析、站点解析、机柜同步或设备资料同步，也不会为未变的机柜/U 位调用位置校验接口。状态变化仍会触发监控目标同步和资产汇总刷新。
- 未引入 Redis。

## 影响范围

- `src/pages/AssetManagement/index.tsx`：导入进行时增量刷新；编辑差异请求；保存后静默刷新和按需刷新汇总。
- `src/pages/AssetManagement/components/AssetModal.tsx`：创建后固定字段只读提示与控件；迁移字段维持可编辑。
- `backend/api/assets.py`：合并资产写入；编辑字段差异处理、不可变档案校验、条件关联同步和批量删除。
- `backend/database/schema.py`、`backend/database/migrations/m0282_asset_delete_lookup_indexes.py`：删除关联查询索引。
- `backend/services/tag_service.py`、`backend/services/pam_web_service.py`：标签和 Web 配置未变化时避免重建。

## 性能预期与边界

- 删除路径减少请求、连接和逐行事务开销；关联表索引避免大表逐资产扫描。
- 新增/导入路径减少资产主表写入次数。SNMP/设备创建本身仍会耗时，增量刷新改善可见性，不保证整批 SNMP 采集完成时间缩短。
- 普通编辑只处理变更字段；状态编辑仍有必要的异步监控同步与汇总读取，位置变更仍要同步机柜关系。
- 没有对当前 Windows 数据库做基准测量，因此不对端到端耗时下降比例作承诺；列表读取路径也没有通过本轮删除索引得到同等级的专项优化。

- 本轮没有新增或运行自动化测试。
