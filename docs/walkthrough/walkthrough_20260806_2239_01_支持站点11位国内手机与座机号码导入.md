# 支持 CMDB 站点导入/新建使用国内 11 位手机与座机号码 - 执行结果与验证报告

## 1. 完成摘要
已修复在 `/cmdb/sites` 批量导入或新建站点时，输入 `13111111111` 等国内 11 位标准手机号或 `010-88888888` 等带区号座机号被后端校验拦截报错的问题。系统现已全面支持国内手机号、座机号及国际 E.164 格式号码的导入与创建。

## 2. 实际修改文件
- [schemas.py](file:///d:/netops/netsops-main/backend/schemas/schemas.py)
  - 在 `SiteCreate.validate_contact_phone` 中移除了强制国际区号的要求 (`international_required=True` -> `international_required=False`)。
  - 放宽 `SiteCreate.validate_phone_for_country` 后置校验正则为 `r'^(?:\+86|0)?1[3-9]\d{9}$|^0\d{2,3}-?\d{7,8}$|^\+[1-9]\d{6,14}$'`，全面兼容 11 位国内手机号（如 `13111111111`）、带区号座机（如 `010-88888888`）以及国际格式（如 `+8613111111111`）。
- [test_cmdb_sites_import_export.py](file:///d:/netops/netsops-main/backend/tests/configuration/test_cmdb_sites_import_export.py)
  - 新增 `test_site_import_supports_domestic_chinese_phone_numbers` 回归测试用例。

## 3. 关键实现说明
- 此前 Pydantic `SiteCreate` 模型在校验 `contact_phone` 时误设置了 `international_required=True`，导致即使在前端 UI 提示“支持 11 位手机号”且示例为 `13800000000` 的情况下，后端 API 请求仍报 HTTP 422 校验失败。
- 修正后，`SiteCreate` 校验规则与前端 UI 提示以及 `SiteUpdate` 的校验逻辑完全一致，既防范非法乱码，又天然贴合国内用户的输入习惯。
