# 修复链路聚合识别与拓扑采集说明走查与验证报告

## 1. 任务背景与核心解决问题
针对用户反馈的几大关键问题：
1. **接口描述导致线路重复 / 散线未聚合**：S6850-3 与 S6850-4 之间原本配置了 `Route-Aggregation34`（包含 `GE1/0/1 ~ 4`），但界面渲染出 4 条平行的散线以及因接口描述（如 `TO-S6850-4-GE1/0/1`）解析产生的紫色叠加线。
2. **刷新发现执行大量复杂 CLI 导致耗时且复杂**：拓扑发现阶段原先无条件连接 SSH，并调用 `collect_protocol_evidence` 执行了 6 类复杂的 CLI 查询（OSPF、ISIS、BGP、路由表、接口描述、STP），造成大量 CLI 刷屏与链路冗余。
3. **聚合口标签双重堆叠**：S6850-1 与 S6850-2 之间的 `Bridge-Aggregation12` 在连线中央垂直重叠渲染了两个一模一样的 `BAGG12 · 4×10G` 标签。
4. **流水线状态栏虚假警告**：流水线卡片显示“未匹配证据: 19”，且文案仍标注为单一旧版的“只读采集 LLDP”。

---

## 2. 根因分析与实施措施

### 2.1 端口 ID 优先，杜绝接口描述覆盖真实接口
- **根因**：`backend/services/snmp_service.py` 的 `collect_snmp_lldp_neighbors` 中，判断若描述中含有 `ge/gi/te` 等字符就错误地将 `remote_port` 设置为接口描述（`TO-S6850-4-GE1/0/1`），弃用了真实的 `lldpRemPortId`（`GigabitEthernet1/0/1`）。导致聚合匹配字典找不到对应端口，4 端口的聚合折叠中断。
- **修复**：在 [snmp_service.py](file:///d:/netops/netsops-main/backend/services/snmp_service.py) 中优化逻辑：只要 `lldpRemPortId` 是合法的端口名称（非空、非纯数字/MAC），一律优先采用端口 ID；仅在纯 MAC 且非 `TO-` 描述前缀时才回退至描述。

### 2.2 彻底精简拓扑发现，去除复杂 CLI 协议推导
- **根因**：`backend/services/topology_service.py` 在 `discover_device_neighbors` 初始就无条件 `__enter__` 打开 SSH 会话，并在发现流程中执行 `collect_protocol_evidence`（依次下发 OSPF、ISIS、BGP、路由表、接口描述、STP 等 6 条 CLI 命令），不仅拖慢发现速度，还将接口描述（`TO-S6850-3-GE1/0/1`）保存为协议连线插入画布。
- **修复**：
  1. 移除 `discover_device_neighbors` 中的无条件 SSH 会话建立，完全改为“SNMP 免密优先探测；仅在 SNMP 无邻居时才按需回退单条 LLDP CLI”。
  2. 移除拓扑发现中的 `collect_protocol_evidence`，不再执行 OSPF/ISIS/BGP/路由表/接口描述/STP 等复杂推导。
  3. 在 `_sync_aggregation_inventory` 中增加前置判定：若设备在数据库中已存在 LAG 记录，则直接复用，不重复发起 SSH CLI 查询。
  4. 在 `build_graph_payload` 中排除 `interface_description` 协议记录，并将历史残留标记为 stale，彻底消除紫色重复连线。

### 2.3 聚合链路标签居中去重
- **根因**：`src/components/TopologyGraph.tsx` 中将聚合两端标签均计算在连线中点（各偏移 13px），当两端名称相同时（如均为 `BAGG12 · 4×10G`），重叠显示为两个双胞胎徽标。
- **修复**：在 [TopologyGraph.tsx](file:///d:/netops/netsops-main/src/components/TopologyGraph.tsx) 中增加判断，当 `isRealAggregationLink` 且两端标签相同时，隐藏 target 侧标签，并将 source 侧标签精确置于连线物理中心（偏移为 0），呈现为单个清晰居中徽标。

### 2.4 流水线状态统计与文案优化
- **根因**：`get_topology_generation_status` 在统计 `unmatched_observations` 时没有过滤 `is_active = 1`，将已失效历史数据计算在内。
- **修复**：
  1. 在 [topology_service.py](file:///d:/netops/netsops-main/backend/services/topology_service.py) 中增加 `WHERE COALESCE(o.is_active, 1) = 1 AND COALESCE(o.status, 'active') <> 'stale'`，未匹配证据数归零。
  2. 在 [TopologyPage.tsx](file:///d:/netops/netsops-main/src/pages/TopologyPage.tsx) 中更新流水线标签为 `SNMP · LLDP`，步骤优化为 `只读采集 xDP/LLDP (SNMP优先)`、`合并双向证据与链路聚合`，并更新运行机制说明。
