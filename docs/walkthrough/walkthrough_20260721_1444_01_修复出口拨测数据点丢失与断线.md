# 修复出口拨测数据点丢失与断线 验证报告

本报告记录了对互联网出口拨测历史趋势图的数据分桶校准与验证结果。

## 完成摘要

1. **确定数据未丢失**：经查询数据库 `outbound_probe_results` 和 `outbound_probe_runs`，发现在过去一小时内，后台检测任务均正常触发并生成了共 65 个完整探测明细，数据库内无断点。
2. **分析根因**：原前端分桶逻辑使用严格的 `[t, t + step)` 步长分桶，由于网络执行的时延漂移（例如探测时间为 14:02:04 和 14:03:06），导致特定 1 分钟区间包含 2 个样本，而下一个分钟区间完全没有样本。没有样本的区间被前端填充 `latency: null, result: null`。由于图表禁用了 `connectNulls`，导致呈现大量虚假的连线断裂。
3. **分桶对齐优化**：
   - 引入 **最近邻分桶窗格**，将时间轴的起点与终点自动规范化对齐至分钟整点边界；
   - 使用 `[t - step/2, t + step/2)` 将每个历史探针点归纳至距离其最近的整点；
   - 彻底消除了因执行时间几秒的微调偏移导致的假性空分桶，同时如果系统发生真实的长周期探测缺失（如停机），依然会展示真实的数据断点，完全符合业务预期。
