# 设备采集模板实施结果

## 完成摘要

- NSOT 单设备策略支持按角色默认、基础监控、二层交换机、三层/网关、防火墙、无线和自定义模板选择。
- 模板与旧 `collection_policy_json` 兼容，显式设备 collector override 优先于模板；切换模板清除旧单项覆盖，恢复默认清空模板/覆盖。
- 角色展示名映射到策略使用的规范值，例如 Core Switch、Access Switch、Wireless AC、Load Balancer。
- NSOT 全量同步现在执行有效采集策略；ARP、RIB、动态协议、接口/VLAN 和 Prefix 投影均按模板/覆盖筛选。实时用户发起的 IP 定位继续保留必要的按需查询路径。
- NSOT 定时作业现在先解析其保存的设备范围，再将同一在线设备 ID 集合传入 ARP、MAC/终端、RIB/BGP/路由邻居、拓扑、接口状态和 Prefix 阶段；无匹配目标时标记 `skipped`，不会退化为全量执行。
- Automation 复合范围若 JSON 无效、不是对象、没有任何条件或含未知维度，均按空目标处理；表单会提示并阻止未选条件的复合任务，避免坏配置扩大到全网。
- scoped 终端更新不会把范围外 endpoint 标为 inactive 或抢占其 IP 所有权；scoped BGP 运行不会全表删除其他设备的快照。
- Automation 已新增批量采集模板入口：站点/角色/设备类型/平台交集筛选，服务端预览命中总量、最多 10 台样例和已有覆盖数；确认后原子套用预设模板或恢复角色默认。选项/候选范围会叠加 `asset:view` / `asset:update` 的 tenant/site 授权；tenant-less Administrator 保留全局操作。目标、权限、旧策略、操作类型或模板变化会使预览快照失效并返回 409。
- NSOT 的单设备策略弹窗现为 IP 查找器，不再先加载所有设备：输入一个 IPv4/IPv6 管理地址后查看策略；批量套用与 Cron 周期都继续留在 Automation。IPv6 查询也核验规范化地址，因此压缩/展开形式的重复 IP 会提示冲突。旧的按设备 ID 读取/写入策略 API 也已加入租户和站点范围约束，不能绕过查找接口读取或修改范围外策略。
- 精确 IP 查询用到的 `devices.ip_address` 普通 B-tree 索引已加入 PostgreSQL migration `m0230_devices_ip_lookup_index`，并同步 fresh-install baseline；索引非唯一，不会改变历史数据或禁止重复 IP。
- 批量操作继续写现有 `devices.collection_policy_json`，不新增 schema/迁移；应用/恢复会清空设备级 collector overrides。成功后可把同一筛选条件带到 NSOT Cron 创建表单；周期由“一个设备范围 + 一个 Cron + 一个统一 NSOT 任务”组成，不为每台设备/指标创建作业。
- 批量策略变更会写审计事件，包含操作、筛选范围、操作者和影响数，不记录预览快照 token。

## 剩余风险 / 后续建议

- 批量套用是一次性写入当前匹配设备；未来新增到相同筛选条件的设备不会自动继承，需要再次执行批量套用。NSOT Cron 在运行时动态选择当前在线范围，但不改写设备模板。
- 实时用户触发的 IP 定位是显式查询路径，部分必要的 ARP/LLDP 查询仍允许即时执行；模板控制后台/NSOT 定时采集，不是禁止所有用户即时查询。
- ARP cache / endpoint 以 IP 为全局键，跨站点 IP 重叠仍有既存歧义；scoped endpoint 路径已避免覆盖范围外现有 owner，但后续宜以网段/VRF 维度进一步确认缓存隔离语义。
- 拓扑链接仍由所有已持久化 LLDP observation 重建为全局派生图；scoped 作业只限制设备连接与采集目标，不改变这一全局派生步骤。
- VLAN 投影也会从当前数据库中的全局接口/ARP/MAC 事实重算；ARP 过期键清理是全局 TTL 维护，且 `arp_cache` 以 IP 为键，跨站点同 IP 的 scoped 刷新有共享缓存覆盖风险。此类派生/全局缓存语义不等于范围外设备被重新登录采集，但不能承诺严格的全局写入隔离。
- ARP collector 有并发安全批次上限；大范围任务可能在一次运行中只轮到部分候选设备，后续周期会继续轮转。若业务要求每次 Cron 都覆盖整个目标集，需要单独评估连接限流与批次吞吐。
- v1 暂不分别配置 ARP、LLDP 等指标的独立 Cron；若以后需要，应先评估任务重叠、设备登录并发和多作业重复采集。
- scoped BGP 采集采用按 ID upsert 并保留未返回路径，避免局部/失败采集造成快照清空；撤销路径的清理仍依赖后续成功的全量刷新。
- 模板仅表示允许采集；设备实际平台不支持、凭据缺失或连接失败时仍需由采集结果报告具体状态。模板切换不删除历史事实。
