# 告警规则通知渠道与邮件投递审计执行记录

## 完成摘要

已严格按实施计划完成告警规则通知方式和邮件投递审计链路。规则可以选择跟随个人设置、飞书、邮件或飞书+邮件；邮件通过 PostgreSQL outbox 异步投递；SMTP 配置使用加密凭据；投递尝试和失败会关联到原告警，并在告警详情、告警历史和活动审计中可见。告警 active/resolved 生命周期不受通知成功或失败影响。

## 关键实现

### 规则级通知方式

- `alert_rules.notification_channels_json` 使用 JSONB 保存渠道数组，旧规则自动默认为 `workspace`。
- 允许渠道包括 `workspace`、`feishu`、`dingtalk`、`wechat`、`email` 和 `global_webhook`。
- `workspace` 与显式渠道互斥，避免“跟随个人设置”与邮件/飞书选择叠加导致重复通知。
- 规则页面提供个人设置、飞书和邮件选项，并在规则列表展示通知方式。

### SMTP 邮件通道

- 新增 `notification_smtp_configs`，保存 SMTP 主机、端口、SSL/STARTTLS、用户名、发件人、超时和速率限制。
- SMTP 密码通过现有 credential encryption 加密保存，API 和界面只返回是否已配置，不返回密码。
- `/api/alerts/notification-channels` 提供通道状态和脱敏 SMTP 配置。
- `/api/alerts/notification-channels/email` 提供管理员保存接口。
- `/api/alerts/notification-channels/email/test` 提供显式测试邮件接口；测试邮件不进入告警 outbox 和告警历史。
- 个人设置增加邮件告警开关、触发通知开关和恢复通知开关，收件地址使用用户资料中的邮箱。

### Outbox 与失败审计

- outbox 新增 `alert_id`、租户、事件类型和目标标识，并支持 `feishu`、`dingtalk`、`wechat`、`email` 等渠道。
- 新增 `alert_delivery_attempts` 记录每次 sending、retrying、succeeded、failed 或 skipped 尝试。
- 投递入队写入 `NOTIFICATION_QUEUED`。
- 投递成功写入 `NOTIFICATION_SENT`。
- 可重试失败写入 `NOTIFICATION_RETRYING`。
- 重试耗尽或不可重试错误写入 `NOTIFICATION_FAILED`。
- 未配置 SMTP、没有收件人、邮箱无效或渠道未配置写入 `NOTIFICATION_SKIPPED`。
- 错误只保存稳定脱敏错误码，例如 `smtp_config_missing`、`smtp_auth_failed`、`smtp_tls_failed`、`smtp_timeout`、`smtp_recipient_rejected`；不保存原始密码、完整邮箱列表或 SMTP 原始响应。
- 触发和恢复使用独立 delivery key；邮件失败不会关闭告警。
- 投递尝试和已结束 outbox 记录沿用告警一年的保留周期，重试中的记录不会被清理。
- 维护窗口结束后的重新打开通知也重新解析规则渠道，并使用 `reopened` 事件类型和独立 delivery key。

### 告警台与历史

- 告警详情展示各渠道最新投递状态、尝试次数和错误码。
- 告警历史增加通知状态列、通知状态过滤器和导出字段。
- 告警活动审计直接读取投递失败事件，因此即使告警仍然 active，也能明确看到邮件发送失败。
- 新增 `/api/alerts/{alert_id}/deliveries`，返回投递尝试明细和按渠道汇总。

### 规则历史修复

- 发现旧 `alert_rule_history.settings_id` 外键指向兼容表，无法保存真实规则 ID。
- 新增 `rule_id` 字段和外键迁移，规则创建/更新历史现在能正确关联 `alert_rules.id`，旧字段保留兼容。

## 剩余风险与后续建议

- Docker 环境需要用测试 SMTP 服务验证真实 TLS、认证失败、超时、临时 4xx 和恢复重试。
- 当前速率限制为单进程内存窗口；多实例部署时应进一步改为 PostgreSQL/Redis 共享限流。
- 暂未实现邮件 bounce/DSN 自动解析、短信和复杂通知编排。
- `git diff --check` 仅剩已生成 `dist/index.html` 的 CRLF trailing whitespace 提示，不影响源码、迁移或构建结果。
