# SN 行为与边界

1. 动态读取 ENTITY-MIB 的实体类型、父实体和序列号，按实体索引关联；不再假设 1/2/3 或最多三个成员。索引支持 PostgreSQL integer 正数范围。
2. 只有类型明确为 chassis、关系完整且无循环/嵌套冲突、SN 有效时，才能确认机框成员；多个机框即使 SN 相同，也按不同实体索引分别保存。完整快照中只有一个不同 SN 值时，将共同值写入资产主 SN。板卡或 module SN 不晋升整机 SN。
3. H3C 新旧 frames 表仅按唯一 SN 或明确的机框名称证据佐证，冲突时保留不确定状态，不把私有编号当作 ENTITY 索引。没有加入新的私有型号回退配置。
4. Huawei 明确 S 系型号+成员编号的多个 module 保留候选，包含不同型号成员；不能从候选自动构造整机或成员 SN。未确认的 module 成员映射仍作为候选处理。
5. 使用前后 sysUpTime 与 entLastChange 检测明显重启或实体变化；对象不支持时不能宣称原子快照。已检测变化的快照不确认 SN。
6. 单设备最多 3 个并发操作，列上限 2000 行、总预算 60 秒；超限、超时、取消、部分读取不视为完整快照。取消时清理子任务。
7. 仅完整且无候选/失败的可信快照允许替换旧成员集合，并给单机框填充/更新自动来源标量 SN；堆叠保存独立成员，不随意指定主 SN。部分失败不删除旧成员、不覆盖旧标量；人工 SN 保留。
8. 新自动来源为 snmp_entity_discovery，旧 snmp_entity_fixed_get 仍识别为历史自动来源；不改变跨资产允许重复 SN 的既有 m0303 规则。
