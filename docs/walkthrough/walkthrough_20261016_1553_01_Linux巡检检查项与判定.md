## 关键实现

- CPU 利用率与每核负载分开计算；CPU 利用率和 I/O 等待改用 `/proc/stat` 短窗口增量，避免依赖 `top` 文本格式或使用开机累计 I/O 等待值。
- OOM 与 SSH 认证日志按最近 24 小时过滤；SSH 来源可以用 `NEXORA_SSH_IGNORE_IPS` 配置可信地址。
- 文件系统按本地文件系统类型检查，保留 Inode `-` 值保护并过滤预期的 Snap 只读挂载；空间/ Inode 输出只列高使用率项。
- TCP 的 `CLOSE_WAIT`、`TIME_WAIT` 和重传率分别输出状态；总连接数由服务端继续应用巡检项中配置的阈值。`ss` 不可用时改读 `/proc/net/tcp*`，两种来源都不可读则显示未采集。
- I/O 使用同一次 `iostat` 采样解析当前物理磁盘读写延迟，不再重复调用并输出整张原始表。
- SSH 是必需服务；Cron 和 Docker 按可选项呈现。失败的非关键 systemd 单元只作信息展示。
- 新增 DNS 名称解析与时延、NTP 同步与偏差、IPv4/IPv6 默认网关可达性、系统及进程文件句柄使用率检查。DNS 使用 `getent` 的系统解析路径，默认不探测公共域名；配置 `NEXORA_DNS_PROBE_NAME` 后才执行三次、每次最多等待 2 秒的查询。
- 网关只把 Ping 成功或邻居状态 `REACHABLE` 作为可达证据；无 `via` 的点到点路由不作为网关可达成功。进程 FD 扫描统计可读和权限/读取失败的 PID，有扫描缺口时明确显示未采集状态。
- SSH 日志在最近 24 小时无可读样本时显示未采集，不会用“没有失败行”假定审计成功。
- 指标保留 `--- METRICS ---`、既有 `tcp_retrans` 别名，并为 `disk_io_await` 提供兼容值；CPU、磁盘、NTP、TCP、服务和 FD 指标分别提供状态。`NA` 哨兵与显式 `ERROR`/`WARNING` 同时出现时保留异常状态。
- 综合脚本状态与数据库巡检项阈值共同判定，取更严重状态；服务层会将数据库阈值新产生的告警加入巡检结果。
- 数据库初始化流程已对系统脚本按 ID upsert，更新脚本源不需要新增数据库迁移；本任务未部署或重启服务。

## 剩余风险与后续建议

- DNS 默认状态是未采集；需在执行环境设置 `NEXORA_DNS_PROBE_NAME` 指向内网业务域名。`getent` 经过 NSS，结果可能由 `/etc/hosts` 或本地缓存提供，不等于直连指定 DNS 服务器的探测。
- 默认路由不是所有服务器都必须存在；确实要求默认路由的主机需设置 `NEXORA_REQUIRE_DEFAULT_GATEWAY=1`。
- DNS、NTP、CPU、磁盘、TCP 和句柄脚本阈值可通过脚本顶部对应的 `NEXORA_*` 环境变量覆盖；选中的巡检项数据库阈值也会生效，两个判定结果取更严重者。
- `std_linux_*` 单项脚本保持原样；本次改动针对综合脚本及其 `METRICS` 解析路径。
- 当前调度器仍可能把输出中的 `[ERROR]` 健康发现归类为作业执行失败；本任务没有改变作业状态语义。
- 浏览器只读排查确认 `*/57 * * * *` 会命中每小时第 0 和第 57 分钟；列表把作业级 `last_run_at` 复制到未来的 cron 执行项并误显示“已执行”。本任务没有修改作业或其列表状态逻辑。
