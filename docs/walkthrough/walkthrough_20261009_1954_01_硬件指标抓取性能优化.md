# 硬件指标抓取性能优化 Walkthrough

## 完成摘要

为 `/hardware-metrics` 增加单次抓取范围的 provenance trust 结果复用。重复来源的传感器不再重复执行同一来源证明校验；每条传感器仍单独处理新鲜度并进入指标渲染，不可信或 provenance 冲突数据继续拒绝导出。接口日志现在包含 `source_validation_ms`、`trust_cache_hits` 和 `trust_cache_misses`。

## 关键实现

- 新增 `hardware_sensor_trust_cache_key()`，仅用来源校验实际消费的 provenance 字段构成稳定、可哈希身份；包含顶层与嵌套 source/metadata/rule_version 冲突，不包含传感器读数和身份标签。
- `_collect_hardware()` 对每个不同 provenance 执行原有 `is_trusted_hardware_sensor()`，并在当前 scrape 中缓存真假结果。缓存不跨请求，因此上游快照或文件变化会在下一抓取重新验证。
- 新增测试证明两个同源 CPU 传感器仅验证一次但都输出，提交不一致或旧自定义 source 仍分别被判断并拒绝。
