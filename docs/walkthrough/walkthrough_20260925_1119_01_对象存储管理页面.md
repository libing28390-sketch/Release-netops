# 对象存储管理页面 Walkthrough

## 完成摘要

收敛存储设置的日常操作：管理员只需要管理 S3 配置并选择一个全局默认。配置备份和 PAM 录像共用此默认配置，系统自动使用 `config/`、`pam/` 两个固定 key 前缀区分用途；管理页面不再显示“用途路由”页签或按用途重复设置的来源、Bucket、前缀、测试和保存操作。

## 用户可见变化

- 管理员在 **平台管理 → 对象存储**（`/management/storage`）查看配置列表、新增/编辑/删除配置并测试连接。新增、编辑沿用参考图的居中弹窗布局。
- 配置备份与 PAM 录像共用当前全局默认存储。Docker 部署默认使用 `.env` 中的本地 SeaweedFS；如需改接另一套 S3，创建配置并设为全局默认即可。Access Key 与 Secret 可继续从部署环境读取，无需普通用途页面逐项配置。
- 新写入分别使用固定前缀：`config/YYYY/MM/<snapshot-id>.cfg.enc`、`pam/YYYY/MM/<session-id>.<format>`。更改全局默认只影响后续新对象；既有对象继续按记录的 provider、Bucket 和完整 key 读取。
- 新建/编辑弹窗不显示 Region、Path-style、TLS；兼容默认值在后端处理。数据库 profile 凭据使用 `CREDENTIAL_ENCRYPTION_KEY` 加密，API 不返回 Secret 明文。
- SeaweedFS 会按 `S3_BUCKET` 创建默认 Bucket；外部 S3 的 Bucket 需事先创建并授予相应权限。被既有对象引用的配置不可删除或修改连接参数。

## 关键实现

- 新增迁移 `m0251_storage_single_default`：把已有用途绑定中的 provider mode 统一为 `default`，清空用途级 profile 与 Bucket 覆盖，保留 `config`、`pam` 前缀。之后两类新写入均从全局默认 profile 解析，未配置数据库默认 profile 时回退到部署环境 `.env`。
- 配置备份和 PAM 录像写入仍通过 `build_storage_service(purpose=...)` 使用既有后端存储抽象；已有对象元数据与上传重试仍固定到首次使用的 provider、Bucket 和 object key。
- 后端通用用途绑定及 API 继续保留，为将来的业务扩展提供基础；普通用户设置页面不要求理解或维护这些绑定。
