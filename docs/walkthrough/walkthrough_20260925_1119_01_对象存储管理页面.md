# 对象存储管理页面 Walkthrough

## 用户可见变化

- 管理员可在 **平台管理 → 对象存储**（`/management/storage`）打开“存储设置”页。主视图采用“对象存储 / 用途路由”页签和配置表格；新增、编辑通过右侧抽屉完成，字段按“基本设置 / S3 / 其他设置”分组，布局参考用户提供的第二张图。
- 对象存储表格列出名称、Endpoint、Bucket/Region、脱敏凭据、默认状态和更新时间；环境变量配置不能编辑或删除，连接测试、编辑和删除均保留在每行操作区。
- 配置备份和 PAM 录像的 provider、Bucket 覆盖和 key 前缀放在独立“用途路由”页签，避免挤占配置列表。当前没有独立命令存储后端或 API，所以界面不添加空壳的“命令存储”配置页签。
- 新建/编辑抽屉包含名称、S3 类型、Bucket、Region、Access Key ID、Secret、Endpoint、默认选项、Path-style/TLS 和备注；编辑时空凭据保持已存值，修改连接参数后需要输入凭据才能测试草稿。
- Access Key 与 Secret 以 `CREDENTIAL_ENCRYPTION_KEY` 加密保存；API 不返回 Secret 明文。S3 Bucket 需先在 SeaweedFS/S3 服务中创建，并授予所选凭据访问权限。
- 配置备份与 PAM 录像分别有一条用途路由，可选择当前默认、环境变量或指定 profile，设置可选 Bucket 覆盖与完整 object key 前缀。迁移初始值为 `config_backup → default/config`、`pam_recording → default/pam`。
- 可以在保存前测试用途草稿。测试按选定来源、Bucket 覆盖与 profile 执行 health check，不会保存或上传业务对象；S3 `/` 只是 object key 虚拟前缀，无需创建目录。
- 示例完整 key：`config/YYYY/MM/<snapshot-id>.cfg.enc`、`pam/YYYY/MM/<session-id>.<format>`。若自定义前缀为 `archive/netops`，则示例为 `archive/netops/YYYY/MM/...`。
- 新写入对象记录 provider ID（环境变量配置时为 `NULL`）、实际 Bucket 和完整 object key。用途路由/全局默认修改仅影响后续写入；失败 spool 重试和已有对象的读取/删除使用首次写入时记录的 provider 与完整 key。仍被对象或用途路由引用的 profile 不可删除。
- `/api/storage/status` 继续保留原字段，现按配置备份用途返回实际生效的 provider、Endpoint、Bucket 和健康状态，供配置备份界面显示。

## 扩展边界

用途路由使用通用 purpose 模型与 API（`GET /api/storage/usages`、`PUT /api/storage/usages/{purpose}`、`POST /api/storage/usages/{purpose}/test`），不为每种业务新增一个 S3 Endpoint。加入新业务时注册用途并让业务 writer 使用 `build_storage_service(purpose=...)`，即可复用 profile、bucket override、key prefix 与失败重试语义。

知识库当前将 `original_content`、`normalized_content` 与检索 chunks 存在 PostgreSQL；当前 UI 不提供知识库用途，也不会自动将其迁到 S3。将来若归档知识源原始文件，还需为文档版本/来源记录 provider ID、Bucket、object key、hash/size/content type，并接入读取、删除、租户授权、保留策略与旧数据迁移；检索所需文本、chunks 与向量按知识库当前模型继续管理。
