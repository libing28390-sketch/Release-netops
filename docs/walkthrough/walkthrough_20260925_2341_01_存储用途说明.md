# 存储用途说明

## 完成摘要

对象存储管理页现在说明业务数据与默认 Bucket 前缀的对应关系，帮助管理员确认配置备份和 PAM 会话录像会写入哪里，并明确知识库目前未使用这项对象存储配置。创建/编辑时固定显示 S3，并提示 Endpoint 应填写 S3 API 地址；S3 缺失 Bucket 不再被误判为缺失对象，配置快照查看/下载也不再把存储故障伪装成空内容。

## 关键实现说明

- 增加中英文“存储用途”说明：全局默认 Bucket 下，配置备份使用 `config/` 前缀，PAM 会话录像使用 `pam/` 前缀。
- 创建和编辑弹窗将固定类型 `S3` 显示为静态文本，去掉不可操作的下拉框。
- Endpoint 字段新增中英文提示，说明 Bucket 和 `config/`、`pam/` 用途目录不属于 Endpoint；服务商要求路径前缀时仍可按其文档填写。
- S3 `NoSuchBucket` 错误现在作为存储服务错误向上报告；`NoSuchKey` 仍报告为对象不存在，避免 PAM 将整桶丢失提示成单条录像 404。
- 配置快照对象读取失败时记录 Bucket 错误码/HTTP 状态等安全摘要，避免存储错误在日志中完全不可见。
- 配置快照内容/下载接口使用严格读取：对象确实不存在时返回 404，桶缺失或存储不可用时返回 503。内部分析调用保留原有空内容兼容行为。
- 复核 `docker-compose.yml`：netops 的 `NO_PROXY`/`no_proxy` 已含 `seaweedfs` 和 `nexora-seaweedfs`，容器内访问默认 SeaweedFS 地址会绕过继承的 HTTP 代理。
- 说明知识库文件当前没有路由到此对象存储；Bucket 需先在 S3 服务中创建，本页只保存连接配置。
- 说明 `Environment` 配置来自 `.env`，仅在数据库没有全局默认配置时用作回退。
- 未修改存储配置、Bucket 内容或业务存储路由。

## 剩余风险与后续建议

- 若后续知识库也接入对象存储，应同步更新这里的用途与前缀说明。
- 当前连接测试只验证 S3 API 可访问及 Bucket 列表可读，不验证对象上传、下载和删除；UI 已明确标注这个边界。
- 后端仍允许 endpoint 带路径，因为部分 S3 兼容服务可能要求反代路径前缀；前端提示不要把 Bucket 或 `config/`、`pam/` 业务目录当作路径附加。`/conf` 是否有效取决于服务商配置，SeaweedFS 根服务地址不应加它。
