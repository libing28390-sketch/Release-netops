# 前端生产构建进度提示走查记录

## 完成摘要

用户截图中的 Docker BuildKit `frontend-build` 步骤仍在计时，Vite 只停留在 `transforming...`。根因是项目直接运行 `vite build`，Vite 默认不会在模块转换阶段持续显示百分比；模块转换完成后才输出总模块数，所以界面看起来像卡住。

已增加两层可见进度：独立 Node 父进程每 10 秒输出构建存活和耗时；Vite build-only 插件每处理 250 个模块报告计数。Dockerfile 与 `npm run build` 统一走包装器。开发服务器行为不变，也没有新增依赖。

同步发布检查时发现，`.github/workflows/release.yml` 会从 `scripts/` 显式保留允许公开的脚本；原清单没有新包装器，会导致公有树缺文件。现已把它纳入发布输入校验、公有树保留清单和清理后的必需路径校验。公有仓库由 `release.yml` 同步，没有直接推送公有仓库。

## 关键实现说明

- 包装器独立启动 Vite 子进程并继承 stdout/stderr，每 10 秒报告仍在构建及已用时间；子进程退出后清理 timer，并把退出码传回 npm/Docker。
- Vite 进度插件只用于 build，转换 250 个模块输出一次计数，并报告转换阶段完成；计数表示已处理模块数，不伪装成百分比。
- `Dockerfile` 的前端阶段执行 `npm run build`，与开发机/CI 的生产构建使用相同包装器。
- 发布工作流在源输入校验、公有树清理保留清单及净化后必需路径校验中都包含 `scripts/build-frontend.mjs`。
