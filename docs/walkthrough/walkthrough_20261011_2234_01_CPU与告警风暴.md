# CPU 与告警风暴调查结果

对应计划：[plan_20261011_2234_01_CPU与告警风暴.md](../plans/plan_20261011_2234_01_CPU与告警风暴.md)

## 完成摘要

定位到本地开发环境的多重负载来源：Tailwind 原先将整个仓库作为扫描源；Vite 还会发现 `dist-*` 中额外 HTML 入口；Uvicorn 开发自动重载监听整个仓库；设备状态抖动因 `asset_id` 也被当成采集目标候选，导致频繁编译完整 SNMP 目标并逐设备记录“缺少凭据”。Docker 运行时不启动 Vite，不过原构建上下文会带入历史构建目录，构建阶段 Tailwind 也会扫描过多候选。

在 8.7 秒空闲采样中，Vite CPU 为 0%，整机平均 CPU 16%。该整机样本也包含 VMware、Codex、后端等进程；这证明本轮采样时 NetOps 没有维持此前的 100% CPU，但并非严格的单变量 A/B 测试。

## 实际修改

- `.dockerignore`：忽略根目录 `dist-*` 与 `.codex-*`，历史验证输出不再进入 Docker 构建上下文。
- `vite.config.ts`：将依赖优化入口固定到 `index.html`，避免默认 HTML glob 将 4 个 `dist-*` 页面作为入口；Vite watcher 忽略 `dist-*` 与 `.codex-*`。
- `src/index.css`：Tailwind 扫描根限定到 `src`。旧扫描清单为 15,070 个路径，其中 22 个历史目录占 7,777 个；新清单为 590 个源文件。旧路径的 stat 合计约 1.86 GB，其中 JS/JSON/SVG/CSS 等文本候选约 588 MB；这不能证明 GLB 二进制内容被 Tailwind 读取。
- `backend/main.py`：Uvicorn 本地开发重载范围由仓库根改为 `backend/`。当前正在运行的 Uvicorn 父进程仍使用启动时配置；下次完整重启后生效。
- `backend/services/background_monitor_service.py`：状态改变后的采集目标同步只对 SNMP 字段或服务器类型相关的设备触发；移除通用 SSH credential 和 `asset_id` 作为候选条件。当前 221 台均有关联资产，但仅 15 台有 SNMP 凭据，且没有发现资产表中存在而设备行遗漏的 SNMP 绑定。五分钟定时同步保留。
- 同一服务：SNMP 凭据未配置时不再创建 `SNMP Unreachable`，启动时把旧的此类活动告警静默置为已恢复，历史记录继续保留。
- `backend/tests/monitoring/test_background_monitor_snmp_alerts.py`：添加真实服务函数的 mock 边界测试，覆盖缺凭据、配置凭据失败、历史误报去重恢复以及目标同步筛选。

## 历史日志证据

- 用户附件包含 1,004 行，其中 455 条逐设备“未配置 SNMP 凭据”warning。当前工作树中的聚合日志修改已于 21:51 写入；本地日志最后一条逐设备 warning 是 21:40:18，合计 12,952 条。之后使用每次编译一条聚合 warning。
- 20:38 记录了 36 次设备状态变化和 9 次 CollectorAutoSync；20:07 记录 8 次同步，并有约 1,446 条逐设备 warning。与 221 个全命中的 `asset_id` 候选相符，表明状态变化曾放大全量采集目标重编译。
- 当前数据库未恢复的缺凭据 SNMP 告警为 0 条；当前设备全为 online，未恢复的设备离线告警为 0 条。
- 设备离线判断仍由单次失败探测立即切换：SNMP 未配置时按 ICMP 2 秒、管理 TCP 2 秒顺序兜底；Windows A-Loop 并发为 2，完成全批才 sleep 15 秒。探测间歇失败会形成 offline/online 翻转。该状态机风险尚未调整，因为只增大告警 FOR 时间而不在每个采样周期推进状态机可能令告警永远停在 PENDING。

## 未执行验证与剩余风险

- 当前机器未安装 Docker CLI，Compose 配置解析和镜像构建未验证；Docker 的生产运行时不会运行 Vite，镜像重建后才会包含后端告警和同步修改。
- 没有在旧全仓扫描配置上重新启动 Vite制造对照负载，避免重新引发数 GB 内存和高 CPU；当前 CPU 降幅不是严格 A/B 结论。
- 后端运行实例尚未完整重启，Uvicorn watcher 的 `backend/` 范围仍待实际服务下次完整启动确认。
- 离线/恢复告警的采样滞回需独立设计：让状态探测每次样本推进告警机，并把设备展示状态与告警进入条件解耦；本轮不修改实时网络告警规则。

回滚方式：恢复上述 Vite、CSS、Docker 忽略和后端开发启动配置的改动；SNMP 误报状态恢复仅保留历史事件，无需数据库回滚。
