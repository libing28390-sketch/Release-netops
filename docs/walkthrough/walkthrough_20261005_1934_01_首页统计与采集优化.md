# 首页统计与采集优化完成记录

## 完成摘要

首页设备总数和在线率改为读取全量数据库聚合，不再受无分页列表 200 条上限影响。首页停止请求设备明细，设备资产分页页也停止额外的共享全量列表请求。SNMP exporter 配置在运行时 YAML 输出边界规范化数字枚举键，避免 reload 因字符串键被读成整数键失败。

## 关键实现

- 新增 `GET /api/devices/summary?asset_type=network_device`，单次数据库聚合返回总数、在线/离线/待处理/未知状态数和平台分布；按设备 ID 去重。非管理员按自身租户过滤，管理员可看全部租户。该接口不执行设备 profile、标签和健康状态逐条标注。
- 首页通过汇总接口初次加载并每 30 秒刷新，避免并发重叠请求，卸载时取消请求和清理定时器；请求失败时保留最近一次成功结果。平台缺失值显示为本地化“未知”。
- App 在 dashboard 和 inventory/devices 子页的初次加载、路由切换及轮询中跳过共享设备明细请求；分页子页仍使用自身分页接口。
- SNMP exporter 编译配置在 `include_unit=False` 的 runtime 路径中，将 metric、index、lookup 里的 `enum_values` 数字键转为整数；非数字键、冲突键和非字符串枚举名会明确报错。保存到业务记录的 JSON 形态不变。

## 日志原因与剩余问题

- 附件日志中 `/api/devices` 共 196 次，平均约 3.91 秒、P95 约 15.04 秒、最长约 27.9 秒；主页每 15 秒拉取一次明细，慢响应可能与下一轮重叠。新首页统计接口绕开明细标注链，停止首页这类重型轮询。
- SNMP exporter 的枚举配置解析错误源于 YAML 中数字枚举键被输出成字符串，触发 reload HTTP 500；配置编译边界已修正。
- 附件经筛选后有 6,477 行；SNMP exporter 记录约 1,429 次超时/取消（67 个目标）、511 次无效 OID（19 个目标）、55 次连接拒绝（2 个目标）。vmagent 对其中失败也有对应记录，所以按两层日志合并观察会看到重叠；这些是周期采集失败被反复报告，不是同一请求意外执行了数千次。它们仍是实际设备或 OID 故障信号，本次没有隐藏或改写。
- APScheduler 有 193 次单实例任务跳过（locator runs 102、locator invalidations 45、health snapshot 40、alert delivery 6），表示上一轮超时或未结束。PostgreSQL 日志另有 4 次 `column "version" does not exist`、一次主机名唯一约束冲突和一次前缀重复；这些记录的触发路径尚未确认，需分别排查。
- 首页统计口径是 `devices` 表中网络设备，不含没有关联设备记录的物理资产；资产导入流程会为网络设备创建关联设备记录。资产管理卡片同时统计服务器，因此资产页总量与首页网络设备总量可能本来就不同。
