# 手动新增设备复用导入补全流程执行记录

> 完成时间：2026-10-13（Asia/Shanghai）

## 完成摘要

手动新增网络设备现在在数据库提交后通过 FastAPI 后台任务调用与表格导入相同的 LibreNMS 纳管和 SNMP 身份识别服务，最后同步监控采集目标。两阶段相互隔离：纳管失败不会阻断 SNMP 识别，识别失败也不会撤销已保存的资产；API 响应新增 `enrichment_pending` 字段提示后台补全已排队。服务器等非网络资产继续沿用原有监控目标同步流程。

身份识别使用创建时已解析的 SNMP Profile/Community 状态和用户录入的厂商、平台、型号作为声明值，与导入流程使用相同的服务契约。后台任务始终在资产事务提交后运行，不在 HTTP 请求处理期间探测设备。

## 剩余风险与后续建议

这项修改让手动新增补上与导入相同的网络设备纳管和身份识别步骤，但硬件监控数据仍取决于设备在线、SNMP Profile/Community 可用、硬件传感器受采集器支持且采集任务成功。若部署后某设备仍缺少硬件面板数据，下一步应检查设备在线状态、SNMP 凭据解析和硬件传感器发现结果。回滚时移除手动新增路由的后台任务注册及对应辅助函数，可恢复原有新增后仅同步采集目标的行为。
