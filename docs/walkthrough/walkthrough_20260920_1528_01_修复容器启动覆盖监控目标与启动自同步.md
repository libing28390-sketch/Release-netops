# 修复容器启动覆盖监控目标与启动自同步走查记录

## 1. 验证摘要
- 排查定位了 `linux_targets.yml` 为空列表 `[]` 的根本原因：`scripts/sync-frontend-dist.sh` 在容器重启时无条件执行 `cp -f`，将镜像中预置的空文件覆盖了已编译的目标文件。
- 修复了 `scripts/sync-frontend-dist.sh`：只有在 target 文件不存在时才初始化复制，绝不覆盖已有 targets。
- 在 `backend/main.py` 的启动流程中加入即时异步同步 `trigger_async_monitoring_sync(delay_seconds=3.0)`，确保容器启动后 3 秒内自动从数据库读取全部已纳管服务器并生成 target 规则，无需等待 5 分钟定时器。
- 本地自动化测试 `test_domestic_and_wireless_monitoring.py` 验证通过（`5 passed in 45.20s`）。
