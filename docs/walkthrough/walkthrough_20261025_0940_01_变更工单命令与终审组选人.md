# 变更工单命令与终审组选人走查

## 完成摘要

- 手工执行命令和回退命令现在都可逐条添加、删除；接口继续使用原 `commands: string[]` 与 `rollback_plan: string`，回退命令以换行保存，旧多行内容可继续编辑。
- 命令区标题改为“机器命令”，输入项改为“添加执行命令”，删除原先重复的“命令/下发内容”标签。
- 变更控制表默认展开并标记必填。正式提交前校验实施人、协同审核人、变更前检查、人工实施步骤、变更后验证、业务验证；草稿仍可不完整保存。后端在创建、更新和状态迁移至初审时均校验控制表，不受原功能开关绕过。
- 用户管理新增独立的“工单职责”选择与列表标记，和“管理员/普通用户”基础角色分开。普通用户无法配置初审或终审；初审/终审候选只显示管理员且具备对应职责组的用户，不再回退到所有管理员。
- 后端只允许管理员被指定为初审/终审，也在初审处理时校验管理员身份；原有职责组和指定审批人校验保留。相关英文拒绝原因增加中文提示。

## 原因核实

- 前端之前在终审组无候选时回退显示所有管理员，后端仍要求被选用户 `role == Administrator` 且 `change_groups_json` 包含 `final_approver`，因此页面曾显示后端必然拒绝的候选人。
- 本机用户管理页当前显示 Alice 的基础角色为“管理员”，但“工单职责”为“未配置”；编辑表单中“终审组”与“初审组”均未勾选。这解释了所报错误：管理员基础角色本身不等于终审职责。
- 仅检查了 Alice 的设置，没有保存或改变任何用户权限。将 Alice 加入终审组会增加审批权限，需在执行前取得明确确认。
