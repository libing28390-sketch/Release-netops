# 资产与机柜联动及物理空间校验验证报告

针对用户指出的“在资产管理录入设备时未进行机柜U位冲突校验，且机柜管理页面无法同步展示资产设备”的设计缺陷，我们已经完成了代码重构、冲突校验与数据全同步的建设。

## 变更文件与联动机制说明

### 1. 资产与机柜联动逻辑实现
* **目标文件**：[assets.py](file:///e:/data/netsops/backend/api/assets.py)
* **变更点**：
  * 新增了后台通用同步服务 `_sync_rack_device_from_asset(conn, asset_id, obj)`，自动提取并计算所绑定的 `rack` 机柜名、计划上架位置 `planned_start_u` 和高度 `u_height`。
  * **在创建和更新资产时**：若检测到合规的机柜和U位参数，自动将该设备注册进 `rack_devices` 表，同时自动检测冲突；若移除了机柜或U位设置，则执行自动下架动作从 `rack_devices` 移除该条目。
  * **在删除资产时**：级联清除 `rack_devices` 中对该资产的一切上架记录。
  * **在批量导入资产时**：以安全容错的方式进行联动同步，遇到冲突时单独记录警告日志，保证不阻塞总体的资产录入工作。
  * **U位物理重叠强校验**：任何资产的新增与改动在触发 U位上架时，均会执行机柜容量限制检查和区间交叉排他碰撞校验（`_check_u_constraints`）。一经发生重叠，立刻回滚资产事务，并向前台返回标准的 `400` 错误信息。
