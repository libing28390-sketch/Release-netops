# 山石配置备份命令实施记录

## 完成摘要

已为 Hillstone / 山石 StoneOS 增加配置备份默认命令，并对齐单设备备份、批量与定时备份的命令选择及 Netmiko 平台映射。

- 当前运行配置：`show configuration running`
- 下次启动配置：`show configuration startup`

## 实际修改文件

- `backend/services/platform_registry_service.py`：后端命令目录，`PLATFORM_ACTION_COMMANDS["hillstone_stoneos"]`。
- `backend/services/config_backup_command_service.py`：识别 Hillstone、StoneOS、山石别名，供备份命令选择和网络设备分类使用。
- `backend/services/config_vendor_platform_service.py`：将“山石”规范化为 `Hillstone`。
- `backend/api/assets.py`：在资产写入和平台纠正路径将 Hillstone / StoneOS / 山石规范到 `hillstone_stoneos`，不再静默落到 Cisco。
- `backend/core/platform_utils.py`：规范化 Hillstone vendor/platform，冲突平台修正为 `hillstone_stoneos`。
- `backend/drivers/netmiko_driver.py`、`backend/engine/drivers/netmiko_driver.py`：显式将 Hillstone 平台传给 Netmiko，避免旧驱动回退 Cisco。
- `src/utils/configBackupCommands.ts`：前端单设备备份默认命令镜像及别名。
- `backend/tests/configuration/test_startup_config_backup.py`：更新 Hillstone 内置备份命令覆盖预期。
- `backend/tests/vendor_audit/test_hillstone_support.py`：覆盖资产平台与配置厂商服务的 Hillstone / StoneOS 别名。

## 关键实现

后端批量/定时备份从 `backend/services/platform_registry_service.py` 的 `PLATFORM_ACTION_COMMANDS` 读取命令；`backend/services/config_backup_command_service.py` 按 vendor/platform 解析到 `hillstone_stoneos`。单设备备份前端使用 `src/utils/configBackupCommands.ts` 的对应镜像，所以两条路径使用相同命令。

驱动映射显式保留 Netmiko 的 `hillstone_stoneos` device type。当前安装的 Netmiko dispatcher 已确认注册该类型；没有为 StoneOS 使用 Cisco device type。

## 剩余风险

命令由用户明确提供，但尚未在目标设备及具体 StoneOS 版本上执行。若设备提示命令不支持，应按该设备版本核实 CLI 后再调整映射。
