## 完成内容

- 登录期间首次读取并每 30 秒刷新汇总；登出、切换账号时清空旧值并取消旧请求。请求失败时保留上次成功值，首次加载失败显示不可用状态，不再用设备列表长度伪装全局总数。
- 资产管理每次成功刷新 summary 后更新共享总数，覆盖页面初次加载以及现有保存、删除、批量删除、导入和手动刷新路径。
- 运营总览显示共享资产总数；操作工作台新增“资产管理设备”统计，同时保留按当前筛选条件统计的“当前节点”。
- 为总数计算、store 请求竞争和资产保存刷新补充前端测试。
- `/access/workspace` 使用 `mode=light` 显式分页读取完整设备集，修复后端默认最多返回 200 条导致的截断；分页期间总数变化、缺页或响应记录数/ID 不一致时拒绝覆盖上次完整列表并显示可重试错误。
- `/automation/quick-ops` 使用 `mode=light` 完整分页读取 `asset_type=network_device`，避免被后端无分页请求的 200 条安全上限截断；同时防御性排除未关联资产台账但仍被标记为服务器平台/角色的旧记录。快捷操作的名称、IP、平台、状态、站点、角色等字段都由轻量响应提供。
- `/monitor/topology` 使用网络设备 `mode=topology` 完整分页读取，绕开相同的 200 条上限；后端只投影拓扑需要的设备字段并补充 `interface_data`，不加载配置历史。网络设备类型在请求层限定，旧的服务器设备记录再做一次防御过滤；拓扑图不会把服务器作为可见节点。
- `/monitor/overview` 的在线数和比例在 summary 成功时改用同一汇总中的在线数与网络设备+服务器总数；汇总状态尚不可用时，分子和分母一起回退到本地设备列表，避免混合统计口径。
- 拓扑接口增加 `mode=topology` 有界投影，保留接口状态/遥测供拓扑链路详情使用，同时不读取设备完整配置历史；后端回归覆盖该投影的接口数据与历史字段行为。

## 数据口径说明

资产管理和运营总览统计网络设备与服务器；快捷操作和网络拓扑只选择网络设备。拓扑汇总显示 200 台网络设备而资产台账显示 221 项时，两者可能存在 21 台服务器的预期口径差异，不代表数据漏读。没有关联到可操作 `devices` 记录的物理资产仍会计入台账总数，但不会因此出现在工作台设备列表。本次没有修改数据库关联或执行数据回填。

资产 API 的新建和导入路径会为网络设备/服务器创建关联 `devices` 记录；旧资产更新时，如果找不到关联设备，当前同步逻辑会跳过，不会自动补建。旧接口的 200 行上限意味着还不能判断台账与真实设备行数是否相等；本地分页代码部署后，工作台会显示设备 API 的真实总数。若仍小于台账总数，再按权限范围和关联关系做只读核对，本次不自动生成连接凭据或可操作设备。

本地修改尚未提交或部署，所以生产页中的在线分母仍显示旧的 200；本次也未对生产数据做修改。
