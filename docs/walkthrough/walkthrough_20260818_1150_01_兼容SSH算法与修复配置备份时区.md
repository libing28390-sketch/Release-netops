# 走查与验证报告：兼容全量 SSH 算法与修复 Docker 时区/配置备份时间

## 1. 任务完成摘要

本次任务针对用户反馈的两大问题完成了全链路修复与兼容适配：
1. **老旧网络设备 Web 终端 SSH 算法全量兼容**：解决了在 Web 终端 (`/access/workspace`) 登录老旧网络设备时报错 `✗ ssh_connection_failed: No matching MAC algorithm found` 的问题。将 AsyncSSH 与 Paramiko 底层支持的全部 MAC 算法（包括 `hmac-md5`, `hmac-sha1`, `hmac-sha1-96`, `hmac-md5-96` 等）、KEX 算法（如 `diffie-hellman-group1-sha1`, `diffie-hellman-group14-sha1` 等）、Cipher 算法（如 CBC、3DES、Blowfish、Arcfour 等）和 HostKey 算法（如 `ssh-dss`, `ssh-rsa`）完整纳入动态协商序列，且保证现代强安全算法优先，彻底杜绝算法不匹配导致的中断。
2. **Docker 时区与配置备份时间解析一致性修复**：
   - **Docker 容器环境**：`Dockerfile` 基础镜像基于 `python:3.10-slim`，补充安装了系统包 `tzdata`，并在 `Dockerfile`、`docker-compose.yml` 及 `.env.example` 中默认注入 `TZ=Asia/Shanghai` 环境变量。
   - **后端 ISO 时间戳规范化**：将 `backend/api/configs.py` 和 `backend/services/config_backup_policy_service.py` 中原先生成的无时区信息的 naive datetime（如 `datetime.now().isoformat()`）统一替换为标准 UTC ISO 格式（`datetime.now(timezone.utc).isoformat()` 或 `_utc_now_iso()`）。
   - **前端时区解析向前兼容**：在 `src/pages/ConfigBackupTab.tsx` 和 `src/pages/ConfigDiffViewTab.tsx` 中增加 `parseIsoDate` 工具函数，对历史缺少时区后缀的 UTC ISO 字符串智能识别，确保历史与新建备份记录在浏览器端均能准确按照本地时区展示。

3. **NetmikoDriver SSH 连接与协商超时放宽至 60 秒**：
   - 将 `backend/drivers/ssh_compat.py` 中的 `conn_timeout` 默认值由 `20` 秒提升至 `60` 秒；
   - 将 `backend/drivers/netmiko_driver.py` 与 `backend/engine/drivers/netmiko_driver.py` 中的默认 `timeout` 由 `10` 秒放宽至 `60` 秒，`blocking_timeout` 由 `10` 秒调整为 `30` 秒，`session_timeout` 放宽至 `120` 秒；
   - 将 `backend/api/configs.py` 调度配置备份的默认执行超时由 `30` 秒放宽至 `60` 秒。
