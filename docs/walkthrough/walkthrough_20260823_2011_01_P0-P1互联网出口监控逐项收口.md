## 本轮实现范围

### P0

- 修正 WAN 列表服务端汇总、无数据 NULL 语义和 24 小时趋势数据源/降采样。
- 活动告警唯一性覆盖 `firing` 与 `acknowledged`；恢复后可生成新 episode。
- SNMP 采集明确区分成功、部分、超时、认证失败、设备不可达和接口不存在；失败不覆盖上次有效速率，也不累计接口 Down。
- 记录 HC64/32 位计数器来源、质量和设备重启/回绕/异常间隔标志。
- 新增配置只读采集测试 API；保存前要求当前站点/设备/接口/ifIndex 测试通过。
- 手动采集增加并发互斥、操作者冷却和稳定错误码。
- 前端补齐趋势错误/重试、分页汇总、事件筛选、告警联动定位和卡片/表格视图。

### P1

- 新增 `m0162_wan_alert_ack_uniqueness` 和 `m0163_wan_error_discard_rates`；后者补齐原始错误/丢弃计数器、每秒速率及 rollup 平均速率字段。
- PostgreSQL 月分区创建使用事务级 advisory lock；5m/1h/daily 聚合支持 P95、峰值、高负载时长、错误/丢弃速率和 UPSERT。
- 保留清理记录、维护窗口时区/周期、维护抑制、ACK/关闭审计、线路组约束和报告幂等导出。
- 链路列表支持站点、运营商、状态、关键字、角色和线路组组合筛选；前端增加对应筛选控件。

## 真实 PostgreSQL 验证（2026-08-23）

- 连接本地 PostgreSQL 18.4（数据库 `netops`），迁移前待执行 `162、163`；执行后 `APPLIED 2`、`AFTER_PENDING ()`、安全升级门禁通过。
- `m0162` 的活动告警唯一索引已核对为 `(link_id, metric) WHERE status IN ('firing','acknowledged')`；`m0163` 的原始错误/丢弃计数器、每秒速率和 5m/1h/daily 平均速率列均已存在。
- 分区父表已存在滚动分区 `202607`～`202611`；实际数据量为原始 1 分钟样本 `5579` 行、1 小时聚合 `164` 行、1 条链路。
- `ensure_wan_partitions_once()` 返回 `created=5`；`rollup_wan_samples_once()` 返回 5m `1293` buckets/`5580` samples、1h `165` buckets、daily `19` buckets；`apply_wan_retention_once()` 返回各层删除 `0`、`raw_partitions=0`，并成功写入保留运行审计。
- 同一调度锁的两个并发尝试结果为 `[True, False]`，证明跨实例锁只有一个获胜者；分区 DDL 自身使用事务级 PostgreSQL advisory lock。
- 30 次真实服务调用测得：30 天趋势 `p95=7.974 ms`（最大 `10.118 ms`），当前总览 `p95=2.185 ms`（最大 `2.559 ms`）。这满足当前数据量的时间门禁，但不替代生产规模压测。

## 发现并修复的运行态问题

- PostgreSQL 的 `wan_retention_policies.updated_at` 会以 `datetime` 返回；保留任务原先直接 `json.dumps(policy)` 会失败。已改为 `json.dumps(policy, default=str)`，并在真实 PostgreSQL 上重新执行保留任务验证成功。
