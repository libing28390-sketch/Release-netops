## 根因与实现

原 workflow 在清理私有/开发文件后直接执行 `git add .`，但只排除了 `blog/`、备份、日志等路径，没有排除根目录的 `handoff.md`。因为私有源仓库通过 `.gitignore` 的 `!handoff.md` 规则继续跟踪它，公开树重建时会自然被暂存并推送。

本次使用两层保护：

1. 清理层：在 Ubuntu 和 Windows 发布树生成前显式执行 `rm -f handoff.md`。
2. 门禁层：在两个 job 的 forbidden-path 检查中显式加入 `handoff.md`，即使未来清理规则被误删，`git add .` 后也会让发布 job 失败，而不是继续上传。

没有修改 `.gitignore`，因为 `handoff.md` 仍然需要在私有源仓库中保存和追踪。
