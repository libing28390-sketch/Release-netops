# 调度锁与数据库时区修复走查

## 完成摘要

- 新增 PostgreSQL migration `m0229_scheduler_lock_timestamptz`：把 `scheduler_locks.locked_at` / `expires_at` 转成 `TIMESTAMPTZ`，把 legacy owner token 从 `locked_at` 安全迁入独立 `owner_token`；支持幂等重复运行和协调式回滚。
- `docker-compose.yml` 显式以 `${TZ:-Asia/Shanghai}` 设置 PostgreSQL session 与 log 时区；原有 `TZ` 默认不变，不删除/重建数据库数据卷。
- 核心同步/异步调度器、动态任务、Reindex 和 Import 租约均改为 expiry-aware 原子 upsert；任务结束后 owner-fenced 释放，长任务有 heartbeat，重复竞争不会再因预期的唯一键冲突写 PG ERROR。
- 同时纳入此前已请求的默认管理员租户修复 m0228，避免这次 Docker Release 后仍遗留资产导入 403。

## 关键实现与安全边界

- 原子 upsert 仅在现有 lease 已过期时接管；owner_token 对 heartbeat / release 做 fencing，旧 worker 不能续租或删除新 worker 的行。
- 旧 Reindex/Import 锁把 token 放在 `locked_at`；migration 识别并保留这些 token，绝不直接把 token cast 成日期。旧 scheduler 的 UTC ISO 时间按显式 offset 转换，绝对 instant 不变。
- PostgreSQL `TIMESTAMPTZ` 在内部保存时间点；PostgreSQL `TimeZone=Asia/Shanghai` 负责 SQL 读取显示为上海本地时间。[PostgreSQL 日期时间类型文档](https://www.postgresql.org/docs/17/datatype-datetime.html) · [TimeZone 参数文档](https://www.postgresql.org/docs/17/runtime-config-client.html)
- migration m0229 只变更 `scheduler_locks`；之前的 m0228 只回填默认 `admin`。其他空租户账号不会被自动塞进默认租户。
