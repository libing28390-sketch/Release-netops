# 3. 告警管理产品使用手册 (Alerts)

告警管理模块是网络平稳运转的“哨兵”，负责汇聚各类硬件异常、接口抖动、配置异常等告警，并提供丰富的生命周期处置能力。

![告警管理](file:///e:/data/netsops/docs/images/alerts_desk.png)

## 1. 核心功能概述

告警管理包含以下子菜单：
1. **告警工作台 (Alert Desk)**：活动告警看板，支持告警确认、重置与忽略等交互。
2. **历史告警 (Alert History)**：存储所有已解决或已归档告警，提供大范围时间轴的统计分析。
3. **告警维护期 (Maintenance Windows)**：用于设备割接或网络升级时，静默特定站点的告警，防止告警风暴灌满邮箱/企业微信。
4. **告警规则配置 (Alert Rules)**：定制触发阈值，如“CPU > 90% 持续 5 分钟则发送紧急告警”。

---

## 2. 详细操作步骤

### 2.1 告警响应与状态处置
1. 进入 **告警管理 -> 告警工作台** 看板。
2. 页面中会根据严重程度（Critical、High、Medium、Low）使用不同颜色的色块展示异常指标。
3. 交互流程：
   * **确认 (Acknowledge)**：点击设备告警右侧的“确认”按钮，这会向团队宣告“该告警已有专人跟进”，告警状态变更为已确认，暂停超时自动升级。
   * **忽略/重置 (Dismiss/Reset)**：排除故障后，可手动或让系统在监控指标恢复正常时自动将告警清零。

### 2.2 割接与静默窗口设置
在日常运维中，对设备进行升级时通常会产生大量虚报的 Up/Down 告警。
* 进入 **告警管理 -> 静默与维护** 页面。
* 选定指定站点（如 `金桥数据中心`）或特定设备，设定维护时间段（如 `2026-07-10 15:00 ~ 18:00`）。
* 在此时间段内，告警引擎接收到该源的告警会“拦截不发”，仅做后台记录。
* 数据校验与触发规则的后端接口可参考 [alerts.py](file:///e:/data/netsops/backend/api/alerts.py) 模块。
