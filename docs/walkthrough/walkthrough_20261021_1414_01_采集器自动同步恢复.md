# 采集器自动同步恢复验证

## 完成摘要

修复自动同步仅凭数据库 APPLIED 跳过发布的问题。源产物损坏会自动重新编译，current/runtime 损坏会自动重新发布，exporter 重载失败会保留待重载状态并在下一次同步重试。正常配置保持幂等，不因 SNMP 设备超时反复发布。

- 主 Agent：backend/api/monitoring_v1.py、backend/services/collector_sync_service.py、backend/main.py、backend/tests/monitoring/test_collector_auto_sync_recovery.py、本计划/报告及 docs/fixes/fix_20261021_collector_auto_sync_runtime_recovery.md。
- Luna backend_worker：backend/services/collector_artifact_service.py、backend/tests/monitoring/test_collector_artifact_service.py。
- 未修改用户已有前端变更，未提交或推送。

## 关键行为

1. compile 内容不变时，先校验源产物完整性、版本、collector 和 checksum；缺失/损坏则生成新版本。
2. already_applied 还需 current/runtime 完整且版本/checksum 一致，以及 current_version.json 为对应版本 APPLIED。
3. publish 先写 RELOAD_PENDING，exporter reload 成功后原子确认 APPLIED。重载失败返回 503 SNMP_EXPORTER_RELOAD_PENDING，旧数据库 APPLIED 也不会让后续同步跳过重试。
4. 无产物路径的发布返回 409，不能虚报应用成功。
5. 自动同步汇总支持 SUCCESS、PARTIAL_FAILURE、FAILED，启动日志按实际结果输出；日志区分 published 和 unchanged/runtime verified。
6. 同版本重试、未确认版本、损坏 current、缺失 marker 都不能覆盖真正的 previous。仅完整 current 与匹配的 APPLIED/ROLLED_BACK marker 可晋升 LKG。
