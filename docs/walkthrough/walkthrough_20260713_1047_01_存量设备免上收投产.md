# 存量设备免上收投产 Walkthrough

## 完成摘要

- 资产投产支持“标准上收投产”和“存量设备免上收投产”两条路径。
- 免上收设备可进入已投产，但保持未托管，不执行密码修改。
- 免上收要求普通账号凭据可用、设备已完成连通验证，并填写至少 5 个字符的原因。

## 关键实现说明

- 标准模式仍在口令轮换与回连成功后写入 `production` 和 `is_managed=1`。
- 免上收模式写入 `lifecycle_status=production`、`is_managed=0`、`rotation_status=exempt`。
- 物理资产记录 `credential_governance_mode=legacy_exempt`、豁免原因和时间。
- 前端投产确认层提供两个独立按钮，免上收按钮只有原因满足长度要求时才启用。

## 剩余风险与建议

- 后续高权限操作应统一检查 `is_managed=1`，免上收设备只开放普通账号只读任务。
- 建议在资产列表增加“已投产·未托管”标识，避免只看投产状态产生误解。
# 用户验收补充：设备来源与新增状态约束

- 新增 `asset_origin=new|legacy`，录入界面明确展示“新设备/存量设备”。
- 新增资产的投产状态控件被锁定为待投产，并显示说明文案。
- 后端忽略新增请求中的 `production`，无条件以 `staging` 保存，防止绕过前端。
- 免上收投产增加后端来源校验，只有 `asset_origin=legacy` 才允许执行。
- 迁移 `m0007_asset_origin.py` 将升级前已有资产回填为 `legacy`，新安装和新录入默认 `new`。
- 定向测试更新为 `6 passed`，完整后端测试更新为 `368 passed, 1 warning`。
- 当前 PostgreSQL 已应用迁移版本 7，`physical_assets.asset_origin` 字段验证存在，健康检查返回 HTTP 200。
