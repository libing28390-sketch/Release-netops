# 执行记录：资产主机名与 CLI 邻居关联

## 完成摘要

按用户确认的规则收敛：SNMP 是 LLDP 主采集方式，完整成功或正常空邻居结果不调用 CLI；SNMP 失败、不完整或数据不可用时才串行进入 CLI 兜底。CLI 使用当前 CMDB 资产 hostname 做精确且唯一的邻居关联，不要求设备先通过另一轮 hostname 在线校验。未匹配邻居保留诊断，不增加画布设备图标。

复用工作区已有的资产导入 SNMP sysName 同步：读取成功时在同一事务中更新 CMDB 和关联设备记录；失败保留现有名称，导入页面明确提示检查 SNMP Community 并核对 CMDB 与实际设备名称。没有修改当前 CLI 命令或 TextFSM 模板。

补齐设备名称来源缺口：设备列表、轻量列表、搜索、排序、连接目标和拓扑标签优先读取 CMDB；已关联资产的设备编辑名称只读，后端编辑也以 CMDB 名称修正设备镜像，名称统一在资产管理维护。

## 关键实现说明

1. CLI-only observation 来源标记贯穿写入、当前 run 重匹配及诊断投影。只使用当前 physical_assets.hostname，大小写无关精确匹配且候选唯一；不读取旧设备名、sys_name、资产编号、旧观测别名，也不按 CLI 上报 IP/序列号猜测目标。既有 parser 的规范化保持原样。
2. CLI-only 未匹配记录禁止借用其他 observation 学到的别名。CMDB 改名后重新关联会清除旧绑定；已有 managed canvas 投影将诊断临时节点和链接排除。回归确认诊断节点不改变纳管设备的图标数量。
3. 拓扑标签即便面对旧 CMDB IP 占位值，也以当前 CMDB 值为准，不改用另一份过期设备名。旧资产需由导入同步或人工在 CMDB 补齐实际名称。
4. /devices 对关联资产使用统一名称进行返回、搜索和排序。设备编辑在写设备镜像前锁定资产行，遵循资产先于设备的锁顺序，避免并发 SNMP/CMDB 改名被旧读取结果覆盖。
5. 拓扑发现进度仅保留百分比和汇总；移除重复的逐台异常 chip 和长说明。异常卡片默认只显示数量、一句排查建议及可展开详情。CLI 名称未匹配有明确原因。
6. 导入失败信息保留现有逐台详情，默认只提示主机名未自动同步、保留现有名称，不新增验证状态或复杂诊断面板。

## 剩余风险与回滚

- 自动同步失败时不能证明导入名称等于设备实际名称；由简短提示引导用户在 CMDB 核对。CLI 名称不能唯一匹配时不生成当前正式链路。
- 无关联资产的遗留设备仍兼容读取设备自身名称；本次不批量迁移或清理旧资产，也未改旧 /devices/import 路径。当前资产导入会创建 CMDB 关联。
- 旧链路读接口支持单独读取 stale 记录；本次验证旧名称不会继续生成活跃链路，当前画布继续沿用隐藏陈旧链路的筛选。
- 回滚仅恢复本次 hostname 读取/编辑、CLI 身份约束和提示改动，保留用户已有平台绑定、SNMP 聚合及其他工作区改动。无数据库迁移、提交或部署。
