# 华三 Comware V3 平台支持交付说明

## 交付结果

系统新增了 `h3c_comware_v3` 这一 H3C Comware V3 系统 Platform Profile。无论是新部署，还是已有 Docker/PostgreSQL 数据库升级，平台管理、资产录入/导入、设备平台绑定、巡检/自动化命令和 TextFSM 模板选择都会识别该版本。

| 边界 | V3 的最终配置 | 说明 |
| --- | --- | --- |
| Profile code | `h3c_comware_v3` | 平台管理和绑定使用的具体版本身份 |
| 厂商 | `H3C` | 与既有华三平台保持同一厂商边界 |
| 连接驱动 | `hp_comware` | Netmiko/Scrapli 兼容层认可的 Comware 传输标识 |
| 解析家族 | `h3c_comware` | 对外持久化的公共 H3C 解析家族 |
| 命令目录 | 复用 V5 兼容命令 | V3 使用 `display bgp peer` 等旧式命令，不误用 V7/V9 的地址族命令 |
| TextFSM | V3 → V5 → 公共家族 | 没有真实 V3 夹具前，明确使用已验证的 V5 模板回退，不伪造 V3 模板文件 |

## 实现范围

- 后端平台注册表增加 V3 Profile、目录元数据和 V5 兼容动作快照；Comware 版本 `3.x` 的库存识别会选择 V3 Profile。
- Netmiko、engine Netmiko、Scrapli、巡检、拓扑、发现、运行数据和 H3C 标准化链路都补充 V3 到 `hp_comware` / `h3c_comware` 的一致映射。
- TextFSM 平台目录、模板候选、命令建议、自动化快捷查询和 AI 平台别名支持 V3；V3 建议只允许 V5 或公共模板作为回退，不会泄漏 V7/V9 专属模板。
- 前端平台设置、资产管理、设备表单/详情、巡检项、脚本管理、密码轮换、监控、治理和自动化页面提供 V3 显示或选择入口。
- 新增 PostgreSQL 幂等迁移 `m0212_h3c_comware_v3_platform`：补齐系统 Profile、发布版本、动作和 V5 兼容模板版本绑定。长模板编码使用稳定哈希后缀，避免超过 64 字符时截断冲突。

## Docker 升级后的效果

重新构建并启动应用后，迁移会自动应用。可在容器中确认：

```bash
docker compose exec db psql -U postgres -d netops -c "SELECT platform_code, name_zh, connection_driver, parser_platform FROM platform_profiles WHERE platform_code = 'h3c_comware_v3';"
```

预期会得到一条 `H3C Comware V3` 系统 Profile，`connection_driver` 为 `hp_comware`，`parser_platform` 为 `h3c_comware`。若设备已绑定此 Profile，其公共设备平台仍是 `h3c_comware`，这是为了保持同厂商设备的资源范围、运行数据和解析边界一致。

## 后续边界

当拿到真实 H3C Comware V3 的 CLI 输出时，应补充可追溯来源的夹具和专属 `h3c_comware_v3_*.textfsm` 模板；随后可把当前 V5 兼容回退替换为经测试的 V3 专属语法。当前版本不会假设 V3 与 V7/V9 的输出兼容。
