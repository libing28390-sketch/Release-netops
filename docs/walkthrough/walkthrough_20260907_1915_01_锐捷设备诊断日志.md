## 针对 192.168.96.101 的日志判读

该设备当前解析上下文应表现为：`platform=ruijie_rgos`、Profile/parser platform 为 `ruijie_rgos_v12`、Netmiko `device_type=ruijie_os`。重点检索 `[netops-cli]`：

1. 若先出现 `event=connect_start ... secret_configured=False ruijie_session_auto_enable=True`，随后出现 `event=connect_failed ... Failed to enter enable mode`，说明失败发生在会话准备阶段，`show lldp neighbors` 尚未发送。
2. 若出现 `event=command_start`，则命令已经进入发送边界；查看 `contains_double_quote` 和 `command=` 可判断是否把双引号作为命令字面量传给设备。
3. 若随后出现 `event=command_cli_error`，`error_line` 是设备真实返回的 CLI 错误；这和 Python/Netmiko 的连接错误是两条不同链路。
4. 若命令成功但解析异常，查看 `event=parser_start`/`event=parser_result` 中的 `parser_platform`、`template`、`template_source`、`parse_status` 和 `record_count`。

注意：日志中的 `command=%r` 会为展示添加 Python 字符串边界；是否真的含有字面量双引号，以 `contains_double_quote=True/False` 为准。
