# S3 对象路径展示与新文件明文存储

## 完成摘要

- “对象存储”菜单下拆分为“存储配置”和“文件浏览”两个子菜单；`/management/storage/files` 默认以可展开目录树浏览对象，并可复制完整 `s3://bucket/key` 路径。
- 原 `/management/storage` 继续用于管理 S3 存储配置，不再混放文件浏览器。
- 修正模块侧栏的叶子路由匹配：只有显式设置 `activeMatch` 的菜单按前缀匹配；进入文件浏览时只高亮“文件浏览”，不再同时高亮“存储配置”。
- 后端通过 S3 `ListObjectsV2` 获取实际 Bucket 内容；接口只允许管理员访问，不生成预签名或匿名下载链接。
- 新写入 S3 的配置快照仅 gzip 压缩，使用 `.cfg.gz` key；本地存储的配置快照仍沿用应用层加密。PAM 录像继续以原始字节保存。
- 历史加密配置对象保持原样，读取时仍兼容解密。S3 Access Key 与 Secret 仍使用 AES-256-GCM 加密保存在数据库。

## 关键实现

- 新增 `GET /api/storage/objects`，支持 provider、前缀、continuation token 和受限 page size；响应只包含对象 key、`s3://` URI、大小、修改时间、Endpoint 与 Bucket。
- 文件浏览页按目录惰性读取，每页最多 100 个对象；复制的 `s3://` URI 需要 Endpoint 和有权限的 S3 客户端，页面不会提供免认证访问链接。
- “对象存储”父菜单包含“存储配置”和“文件浏览”；文件浏览路由独立显示页面标题，默认展示 Bucket 根目录树。
- 新 S3 配置快照存为 gzip 明文；旧的 `ENCRYPTED:` 内容继续走 Fernet 解密。针对本地存储的加密和 S3 凭据加密未改变。
- Nexora 上传请求没有启用 S3 服务端加密参数；对象静态加密取决于 SeaweedFS、云 S3 或底层存储的外部配置。

## 剩余风险与后续建议

- 历史 `.cfg.enc` 对象仍依赖原来的 `CREDENTIAL_ENCRYPTION_KEY`；本次没有改写历史对象。
- 新 `.cfg.gz` 对象未加密但仍经过 gzip 压缩。S3 服务或底层磁盘可能另行启用了静态加密，Nexora 不会覆盖该设置。
- `s3://` 路径不是浏览器免认证链接；Endpoint 必须从访问端可达，下载客户端仍需 S3 授权。
