# S3 配置快照目录与在线文件查看

## 完成摘要

- 新配置快照以 UTF-8 纯文本 `.cfg` 写入 S3，按日期和厂商组成目录层级；默认完整 key 为 `config/YYYY/MM/DD/{vendor}/{hostname}_{HHMMSS}_{trigger}_{snapshot-id}.cfg`。启动配置保留 `_startup` 标记，配置用途自定义 key prefix 仍由存储绑定应用。
- S3 上传失败时，spool 使用与新 `.cfg` 对象相同的明文格式；重试使用记录的目标对象 key。新路径的分段会替换路径分隔符/危险字符，支持中文厂商名。
- 文件浏览页为 `.cfg`、历史 `.cfg.gz` 和 `.cfg.enc` 增加在线预览、下载为 `.cfg` 的操作；集成时改成类似 VS Code 的左侧资源树与右侧文件列表，保留懒加载、分页、面包屑与路径复制。
- 新增管理员专用对象内容 API。它规范化 object key、仅处理 `.cfg` 系列文件，兼容 gzip/Fernet 历史数据，返回纯文本或安全附件名；读取错误不暴露供应商原始响应。
- 本地快照加密、S3 凭据加密、PAM 录像路径和历史对象内容均未更改。用户确认只整理新快照，未迁移现有快照。

## 关键实现说明

- `object_key_for_snapshot()` 返回相对 key，由存储用途的 key prefix 追加根目录，避免默认路径重复出现 `config/config/`。
- 手动快照、定时 running/startup 快照、上传失败记录和失败重试都传递 vendor、hostname 和 trigger；本地后端仍使用 Fernet 编码及 `.cfg.enc` 扩展名。
- `GET /api/storage/objects/content` 要求 Administrator 身份。对象读取按选择的 S3 profile 执行；扩展名限制兼容默认和自定义 key prefix。
- 历史 `.cfg.gz` 会解压，历史 `.cfg.enc` 会沿用现有 Fernet 解密，页面统一展示和下载为配置文本。

## 剩余风险与后续建议

- 历史 `.cfg.gz`、`.cfg.enc` 对象仍保留旧路径；目录树会同时显示历史旧结构和新日期/厂商结构，这是用户选择保留历史位置的结果。
- 新 S3 配置对象不做应用层加密或压缩；静态加密取决于 SeaweedFS / S3 服务或底层存储配置。
- 文件内容读取由后端将对象载入内存后解码，面向常规网络设备配置快照；当前未做大对象流式预览。
