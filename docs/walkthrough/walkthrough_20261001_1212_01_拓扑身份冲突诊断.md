## 关键实现

- 匹配规则将 LLDP 管理 IP 作为首选身份；如果它没有命中 CMDB，就直接返回未匹配及 `reported_management_ip_not_found_in_cmdb`，名称或序列号不能把邻居猜测性合并到 CMDB 设备。
- 没有上报 LLDP IP 时，仍允许现有的序列号/主机名匹配。
- 未匹配投影按报告 IP 区分不同的伪节点，并返回匹配原因，避免不同地址因相同名称或机箱标识而混为一个身份。

## 本轮增补：链路证据状态（2026-10-01）

### 状态判定

- `bidirectional_confirmed`：链路两端都有完整的当前 LLDP 快照，并且对端存在反向邻居观测。
- `single_sided_evidence`：只有一侧提供了邻居观测，或者另一端采集失败、未完成或未纳管。它说明证据来自一侧，不表示物理链路只能单向通信。
- `neighbor_mismatch`：链路两端的 LLDP 快照都完整，但其中一端没有反向发现该邻居。
- `stale`：链路已超过现有证据 TTL。
- 其他类型链路仍可标记 `unknown` / `not_applicable`，不套用 LLDP 双向语义。

后端在拓扑链路响应中提供证据状态、观察方向、协议来源和两端采集快照摘要。画布线型只有两种：双向证据为实线，未达到双向确认的证据为统一虚线；不再按邻居不一致、过期、链路类型或聚合状态引入额外虚线样式或逐边标记。线条不带方向箭头，链路协议和采集快照通过点击链路查看。

## 最新修正：本轮接口 IP 归属与最终统一匹配

### 根因与证据

- 旧发现 `dd9c97ea-c442-4a66-8a19-4ddd3d55ccaf` 有 34 条 LLDP 观测，26 条因 `management_ip_not_found` 无对端；剩余 8 条是 S6850-3/4 四个成员端口的双向观测，合并后只有一个 LAG。
- 只读查询设备自身 IP-MIB 证明 `10.254.100.5` 属于管理地址 `10.254.0.2` 的设备、`10.254.13.2` 属于 `10.254.0.3`、`10.254.100.2` 属于 F1090-9。资产接口 IP/IPAM 库为空，原匹配器没有这些事实。
- “18 个邻居”是按报告地址归组后的诊断条目，不能解释为 18 台设备未纳管。

### 实现与边界

- 通过 SNMP IP-MIB `ipAdEntAddr` 与 `ipAddressIfIndex` 读取本机 IPv4/IPv6；SNMP 本轮失败/无可用完整表时，经现有只读 `get_ip_interfaces` / 多厂商接口采集器走普通操作权限 CLI。
- SNMP 使用已解析凭据，禁止默认 community；表读取错误或达到 2048 行上限时不采信截断结果。CLI 仅接受明确的本机 IP 字段，排除网关、邻居、peer/destination 等远端地址。协议失败不会中断已有 LLDP 结果。
- 本机归属记录在既有采集状态 metadata，包含当前 run 与代次；无 LLDP 邻居的设备同样可提供本机地址。地址库只加入同租户、同 run、当前 generation 的设备自身事实。
- 所有设备完成后重新匹配本轮观测，然后归并端口/聚合成员；归属确认后仍保留报告名和资产名称，不改 CMDB 主机名或管理地址。重复 IP（包括接口地址与另一资产管理地址碰撞）保持歧义，不按名字强行连边。
- 重匹配锁定代次，更新每台采集匹配计数与 run-device 计数；从 PostgreSQL 强制刷新相同代次的 Redis 快照，避免之前发布的空 neighbor_id 被继续复用。
- 前端只修正文案：“邻居身份待确认”“上报 IP 尚未确认归属，可能是设备接口地址”。采集异常和设备离线不混用；画布说明为每台纳管设备一个图标、双向实线/单向虚线。
