## 当前判断

Grafana 采集链路上已确认一个持续慢点：NetOps 的 `/hardware-metrics` 由 `platform_hardware_inventory` 每60秒抓取一次。采样结束时的最新30分钟内，30次请求均返回200，中位耗时1.71秒，p95为4.10秒，最大5.58秒；日志中认证阶段为0ms，绝大部分时间在 handler 内。

生产库有5296条活动硬件传感器记录，总表约5322行、24 MiB。该 handler 读取所有活动传感器及 JSONB 元数据，按设备分组，逐设备将数据解码并渲染为 Prometheus 文本，再读取硬件能力记录。查询计划为传感器全表扫描后排序；它返回约99.5%的传感器表记录，因此现有设备前缀索引不适合替代全表扫描。当前可确认的是这个 exporter 处理路径慢；它可能影响监控数据刷新并消耗 NetOps 处理资源，但尚未证明它是所有页面卡顿的唯一原因。

同期也观察到成功的 NetOps API 请求偶发1–2秒；最新30分钟有17条成功请求超过1秒，`/api/config-templates` 最慢约3.96秒。这些请求耗时主要在 handler，而不是鉴权。一次多 API 同时变慢的窗口里，PG 活动采样的查询年龄约3ms，没有锁等待。

### 对用户卡顿问题的判断
