# 定时巡检结果与执行人展示

## 完成摘要

- 调度器现在加密保存每台设备的巡检阶段输出，明文兼容列只保留 `{}`；标准错误也会并入保存结果，异常分支同样保存加密详情。
- 旧调度记录在用户通过执行详情权限检查后会按现有密钥策略加密回填，并清除明文输出；密钥不可用或输出格式无效时继续拒绝返回明文。
- 历史 API 返回开始时间、结束时间、总耗时和任务创建人。执行历史列表只显示任务摘要、单一状态和时间信息；设备数、成功/失败数等详情留在点击后的详情中。
- 执行历史列表与巡检详情中的健康评分已移除。Linux 巡检忽略预期的 squashfs 只读挂载，并跳过非数字磁盘使用率，避免 `df` 返回 `-` 时触发整数比较告警。
- 定时任务的内部来源仍由 `scenario_id` 标识；新执行记录同时保存任务创建人，旧执行记录优先从关联定时任务解析创建人。

## 关键实现

- 调度器使用 `protect_output` 写入 `phases_encrypted` 和保留期限，`phases_json` 不再保存原始输出。
- 详情接口只在资源授权通过后迁移旧明文结果；迁移完成后重新读取密文记录，再走既有输出解密和审计流程。
- 执行历史 API 对巡检、Playbook 和配置备份分别使用其实际完成时间，并统一计算耗时。正在执行的任务以当前时间估算耗时；等待、审批和排队状态不计为执行耗时。
- 历史任务归属优先取 `scheduled_jobs.created_by`；新建的计划执行行也直接记录创建人，避免任务删除后丢失用户归属。
- Linux 巡检仍将真实 `[ERROR]` 健康告警标记为失败；本次没有把健康异常伪装成执行成功。
