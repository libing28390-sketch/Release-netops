# 稳定 SSH 兼容算法回归：执行与验证

## 完成摘要

已修正发布 Actions 暴露的 OpenSSH 版本依赖测试问题。SSH 生产代码和算法策略未改；新增测试通过 mock 能力验证 DSA 在支持的客户端中被加入，在不支持的客户端中被过滤。

## 实际修改文件

`backend/tests/pam/test_ssh_compat_algorithms.py`、本次 `docs/plans/`、`docs/walkthrough/` 和 `docs/fixes/` 记录。

## 关键实现说明

将 legacy 算法“策略声明”与 system OpenSSH “本机可用算法”分别验证。不会要求不同版本的 runner 安装 DSA 实现。

## 验证命令与结果

- `pytest --confcutdir=backend/tests/pam -q backend/tests/pam/test_ssh_compat_algorithms.py`（test-only 环境变量，禁用 Pydantic dotenv 加载）：23 passed。
- 初次直接 pytest 加载 `backend/tests/conftest.py`，由于本机专用 PostgreSQL 凭据不可用而在 autouse DB fixture 阶段失败；通过 `--confcutdir` 隔离纯 SSH 单测后完成针对性验证。
- `git diff --check`：通过。
- 原 Actions 失败证据：3759 passed、2 skipped，唯一失败为该环境依赖断言。
- 本次修复提交的完整 Release Actions 将在推送后复验。

## 未执行验证及原因

完整后端 pytest、前端检查/构建及公开发布同步由新提交的 GitHub Actions 运行；未连接真实设备。

## 剩余风险与后续建议

算法源列表仍保留 DSA 兼容候选，实际 OpenSSH 只会使用其本机实现的算法；Paramiko 等 transport 遵循各自库的实现能力。
