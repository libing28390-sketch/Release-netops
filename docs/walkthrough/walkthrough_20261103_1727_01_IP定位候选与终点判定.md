# IP定位SNMP优先与终点判定

## 完成摘要
旧定位入口仍按CLI核心角色起点运行，与发现终端的SNMP证据链断开。实机失败记录显示先查AC_21、S6850-2、S6850_1、AC_20、S6850-5的路由；在S6850-5找到ARP后，又因access角色默认禁用MAC查询，生成错误的无FDB能力结论。

已接入SNMP端点优先入口，普通定位先使用有效唯一证据；证据不足或实时刷新时，优先调用现有SNMP事实采集。已知目标ARP来源时仅刷新相关授权设备；没有来源时限制在授权及数量预算内。SNMP仍不足时保留有界CLI追踪。

## 实际文件
- backend/services/ip_locator_endpoint_evidence.py：Luna负责的新增授权证据解析器及候选来源读取。
- backend/services/ip_locator_trace_service.py：主Agent接入、SNMP结果/兼容字段、旧缓存版本失效。
- backend/services/ip_locator_task_service.py：保存定位任务结果时重新读取并比对SNMP依赖，发生变化降级。
- backend/services/ip_locator_service.py：定向MAC查询和完整快照不再把角色默认值当成能力；明确禁用策略继续生效。
- src/utils/ipLocator.ts：SNMP定位结果类型显示为已定位到接入端口。
- backend/tests/ip_locator/test_endpoint_evidence.py、test_snmp_entry.py、test_trace_service.py，backend/tests/vendor_audit/test_ip_locator_arp_contract.py：证据边界、入口、事务保存和CLI回归。
- docs/modules/ipam-group/发现终端采集与排查指南.md：补充定位入口规则。

## 关键边界
按目标IP精确读取ARP，授权、租户和站点过滤在证据关联前执行，最终交换机也必须在授权集合。SNMP当前采集代次与原始FDB相符，并复用现有access端口证明规则。IP多MAC、多VLAN、多站点、多端口或有未能定位的有效分支均不直接判唯一。未知VRF只允许同设备物理接入口证明，不虚构完整三层路径。原始数据、工单均未删除。

FDB原表MAC为紧凑形式，投影为冒号形式；新增读取统一规范MAC并限定设备与目标MAC，避免整台FDB传回后过滤。

## 剩余边界与回滚
低频FDB采集不能保证已老化条目存在；缺失、冲突或未授权证据不会强行返回接入端口。SNMP不足保留CLI兜底，并未承诺所有场景都完全不使用CLI。不做远端部署、提交或推送。
回退本轮新增SNMP入口及其依赖判定即可恢复原追踪方式；源数据不需删除或迁移。
