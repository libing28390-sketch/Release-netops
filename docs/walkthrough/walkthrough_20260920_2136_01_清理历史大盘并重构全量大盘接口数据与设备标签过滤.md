## 3. 关键实现说明

### 3.1 废除 DEV_JOIN，改用原生标签选择器
原本的 PromQL 设计采用时序外乘：
`DEV_JOIN = "* on(instance) group_left(sysName) (last_over_time(sysName{sysName=~\"$device\"}[1d]) * 0 + 1)"`
在真实环境中，Cisco 等大量网络设备在 VictoriaMetrics 中根本没有 `sysName` 指标（仅有 5 个 H3C 设备有该指标）。一旦与空向量相乘，左侧所有接口时序直接被清空！
现在统一使用原生选择器：
`sel = 'site_name=~"$site",vendor=~"$vendor",role=~"$role",hostname=~"$device"'`
所有时序原生带有 `hostname` 标签，匹配效率极高，完全零丢时序风险！

### 3.2 设备变量枚举对齐全网真实维度
原本设备变量仅查询 `sysName`，导致 Cisco 设备无法被查出。
现已更正为：
`label_values({__name__=~"ifOperStatus|up",job=~"network_snmp|.*snmp.*",site_name=~"$site",vendor=~"$vendor",role=~"$role"}, hostname)`
全网 14 台设备均可正常枚举与单选/多选过滤。

### 3.3 安全的接口名称关联（IF_JOIN）
```promql
* on(instance, ifIndex) group_left(ifName) ((ifName * 0 + 1) or on(instance, ifIndex) (ifOperStatus * 0 + 1))
```
即使某个接口或设备未单独上报 `ifName` 时序，也会被 `ifOperStatus` 保底保留，绝不发生接口时序被误乘丢弃的现象。
