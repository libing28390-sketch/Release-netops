# 网页加载性能审查实施记录

## 完成摘要

根据用户提供的性能建议，完成已能由代码证据定位的前端首屏、跨路由请求、监控概览、拓扑概览、Grafana 默认时间范围和 Nginx 普通 API 连接改进；同时按用户授权审查并准备提交当前工作区内的代码改动。未把 SQL 索引或 Redis 缓存作为未经测量的默认答案。

实际浏览器性能基线（HAR、Performance trace、React Profiler、API P95）未采集，因此交付报告只引用可重现的构建依赖体积，不声称页面加载时间或 P95 达标。

## 关键实现

- 登录动画、资产/自动化导入导出、拓扑 PNG 导出在使用时加载；移除把 3D vendor 依赖拉入入口 preload 的手工分包规则。
- shared lookups 按路由消费者与登录身份复用结果；避免无关管理页请求；Dashboard 高频状态只在 Dashboard 读取。
- 监控 overview 的接口遥测批次上限 250，并按访问范围合并同一在途计算；health/resource GET 读取调度样本，不由读取请求触发采样写入。
- 默认全站拓扑先显示站点/links 概览；进入站点或选择非物理关系视图后再取设备级图。
- Grafana 初始时间范围遵循 dashboard 默认值；普通 `/api/` Nginx 代理清空 `Connection` 头以允许 upstream keepalive。
- 用户明确要求纳入工作区其余代码改动；提交前筛选代码、测试、迁移与本轮归档文件，并排除内部协作材料、运行日志和构建诊断目录。
