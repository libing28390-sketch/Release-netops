# 旧 SSH 算法配置持久化完成记录

## 完成摘要

- 新增 PostgreSQL migration 215，将 `ssh_algorithm_profile` 持久化到 `physical_assets` 与 `devices`，默认 `auto` 并设置合法值 CHECK 约束。
- 资产/设备创建、更新、导入、反向关联和双向同步均保留规范化后的 profile；未知值安全回退为 `auto`。
- 设备列表、资产列表/详情、设备连接测试和 PAM 审计/AsyncSSH 会话均读取持久化 profile。
- 前端资产管理支持四种 profile 的编辑、复制、Excel 导入/导出和详情展示；`legacy_break_glass` 必须勾选高风险确认。
- 设备连接池 key 纳入 profile，profile 切换不会复用旧传输会话。

## 关键实现说明

1. migration 先添加列、归一化历史值，再设置默认值、NOT NULL 和 CHECK；未知历史值统一写为 `auto`，downgrade 保留新增列。
2. `AssetCreate`/`AssetUpdate` 与设备 CRUD 使用共享 `normalize_ssh_algorithm_profile`，避免 vendor/platform 分支复制算法规则。
3. 资产是 CMDB canonical source；资产保存后 profile 同步到 linked device，直接设备更新也会同步回资产。
4. PAM session 审计记录 profile，break-glass 使用可追溯；前端只展示策略名和风险说明，不展示凭据。

## 剩余风险/后续建议

- `legacy_break_glass` 仍可能启用已淘汰算法，只应在隔离管理网络、明确授权和审计条件下使用。
- 设备升级到 SHA-2 KEX、RSA-SHA2/Ed25519、AEAD 和 SHA-2 MAC 后，应把 profile 回切到 `modern` 或 `auto`。
