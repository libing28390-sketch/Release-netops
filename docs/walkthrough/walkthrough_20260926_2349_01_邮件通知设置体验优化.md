# 邮件通知设置体验优化完成记录

## 完成摘要

参考用户提供的邮件服务商资料，将 `/management/notifications` 改为三步配置向导，并在 SMTP 后端补充独立的连接测试。预设覆盖国内主流邮箱、国际邮箱、Mailpit、Mailcow、Postfix/Exim 和自定义服务；界面明确区分隐式 SSL/TLS、STARTTLS 与无加密。用户确认收到测试邮件后才可开启新的正式邮件告警配置。

子 Agent 对 SMTP 传输模式、认证行为、Mailpit 默认配置和 OAuth2 所需改造范围作了独立只读复核。结论与实现一致：现有后端支持 SSL、STARTTLS、无加密及可选用户名/密码认证；OAuth2 需要单独的认证模型和 token 流程，本次不扩展。

## 关键实现

- 三步流程为选择服务与连接方式、填写账号凭据与发件人、测试连接和投递并启用告警。
- 个人中心资料示例姓名改为“韩梅梅”，邮箱示例同步改为 `han.meimei@example.com`；姓名、手机号、邮箱三个占位提示调深，改善浅色和深色主题下的可读性。
- 主内容区最大宽度扩展为 1536px，减少宽屏下主体卡片过窄、左右留白过多的问题，并保留较小屏幕的内边距。
- 服务商选择从原生长下拉改为搜索框、国内/国际/开源自建分类和响应式信息卡；卡片显示主机名、端口、加密方式与分类，选中项高亮，搜索支持名称和 SMTP 主机。
- 预置 QQ、腾讯企业邮箱、网易 163/126/yeah.net、新浪、139、189、阿里企业邮箱、Gmail/Workspace、Outlook.com、Microsoft 365（含世纪互联）、iCloud、Yahoo、Zoho、Mailpit、Mailcow、Postfix/Exim/OpenSMTPD 和自定义 SMTP。Mailpit 提示同时标明 SMTP 1025 与 Web UI 8025。
- 已保存配置可在同一向导重新编辑并保存；页面提供删除配置操作，确认后清除 SMTP 密码和各项配置并关闭邮件告警。后端保留一条空的租户覆盖记录，防止删除租户配置后意外重新启用共享默认 SMTP。
- 服务商预设可以继续编辑；主机变化时清空当前页面账号凭据和发件地址，防止把原服务商密码误用于新服务商。切换到无认证 SMTP 并保存时，后端可按请求清理旧的加密密码。
- `ssl` 使用直接 TLS 连接，`starttls` 使用 SMTP EHLO 后升级 TLS，`none` 仅供受控测试网络。密码认证仅在填写 SMTP 用户名时进行。
- 新增管理员接口 `POST /api/alerts/notification-channels/email/test-connection`，检查连接、TLS 和已配置凭据，不发送邮件。
- 新增管理员接口 `DELETE /api/alerts/notification-channels/email`，清空 SMTP 配置和凭据，并返回空配置状态。
- 测试邮件使用独立主题和正文，不伪装成告警，也不新建告警历史；测试可在正式邮件告警关闭时执行。修改后执行测试会先保存设置。
- SMTP 发送的连接超时和 socket 发送超时分别使用配置值。
- Google 和 Microsoft 服务的提示明确说明当前只支持用户名/密码 SMTP AUTH，不支持 OAuth2 / Modern Auth。Outlook.com 账号可能无法通过认证；Microsoft 365 还受租户和邮箱 SMTP AUTH 策略影响。

## 未验证项与剩余风险

- 未实现 OAuth2 / Modern Auth；需要这类认证的账号可能连接成功但无法完成登录。SMTP AUTH 还可能被服务商或 Microsoft 365 租户策略关闭。
- Mailpit 预设要求部署环境中已有 Mailpit 服务且 Nexora 可以访问其 SMTP 端口；Mailpit 默认接收邮件供测试查看，不向真实收件人投递。
- SMTP 返回接受邮件只代表服务器接受本次请求，不能保证收件箱最终投递；启用新配置前需要人工确认测试收件。
