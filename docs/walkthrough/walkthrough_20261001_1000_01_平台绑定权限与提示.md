# 平台绑定权限与 SNMP 拓扑降级走查

## 完成摘要

修复了普通设备编辑绕过平台解绑权限的后端入口，并将前端已有绑定的修改/解绑限制为管理员专用操作。拓扑发现现在能把错误 SNMP 端口与 SNMP MIB walk 失败隔离出来，继续尝试 SSH/CLI LLDP；部分 SNMP 数据不会被误当成完整快照写入。

## 关键实现

- `backend/api/devices.py`：普通设备更新不能替换或清除已有 `platform_profile_id`，返回带 `PLATFORM_BINDING_LOCKED` 的 409。首次绑定、相同 Profile 的幂等保存和未绑定 legacy 设备仍按原行为工作；已有绑定的替换/解绑继续走管理员专用接口。
- `src/components/BatchPlatformBindingModal.tsx`、`src/components/DeviceDetailModal.tsx`、`src/components/DeviceFormModal.tsx` 及调用处：使用当前真实角色控制现有绑定编辑；角色缺失时不授予管理员能力。通用设备编辑将已有绑定设为只读。结构化冲突提示被转换为可读文案。
- `backend/services/topology_service.py`：校验 SNMP 端口。坏端口通过隔离副本完成凭据解析，不会阻断 SSH 凭据，也不会被默认成 161 发起请求；错误时尝试 CLI fallback。SNMP 与 CLI 都不可用时错误信息会同时保留两边原因，错误码可区分无效端口和 SNMP MIB 采集失败。
- `backend/services/snmp_service.py`：区分已完成但无邻居与 MIB walk 失败。任一 MIB walk 失败时抛出不含凭据的安全错误，让拓扑层转 CLI；避免把不完整的邻居结果当成完整快照。
- 发现失败仍经现有失败快照栅栏处理，不替换该设备此前有效的邻居记录；其他成功设备仍可参与拓扑 run 的部分成功结果。

本轮没有新增或运行拓扑 pytest，也没有连接用户另一台机器或真实设备做 SNMP/SSH 验证；因此无法确认该环境的具体故障字段或网络原因。若 SNMP 配置错误且设备没有可用的普通 SSH 凭据，系统无法凭空取得新的邻居数据，会将该设备标记为失败并保留上次有效拓扑。要刷新当前拓扑，需修复 SNMP 端口/community/访问策略，或提供可用的只读 SSH 凭据。没有执行提交、推送或部署。
