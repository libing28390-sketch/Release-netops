# 旧 SSH 算法跨厂商兼容完成记录

## 完成摘要

- 新增集中式、与厂商无关的 SSH 算法 profile：`auto`、`modern`、`legacy_compat`、`legacy_break_glass`。
- `auto` 保持现代算法优先，并兼容附件设备所需的 group14/gex SHA-1、`ssh-rsa`、AES-CBC、HMAC-SHA1。
- group1、`ssh-dss`、MD5、RC4、DES、Blowfish、3DES 等高风险算法不再作为默认 Paramiko 能力，仅在显式 `legacy_break_glass` profile 下启用；system OpenSSH 会先过滤本机实际支持的算法。
- 统一覆盖 Netmiko、Scrapli system/Paramiko、直接 Paramiko、AsyncSSH、资产深度验证、设备连接测试、巡检、拓扑、调度、IP 定位和 PAM 路径。
- 连接池 key 纳入 SSH profile，避免 profile 变化后复用旧算法会话。

## 关键实现

1. 共享策略生成 Paramiko `disabled_algorithms`，默认阻止高风险算法但保留附件设备的安全旧算法。
2. Netmiko 不再全局设置 `disable_sha2_fix=True`，避免现代 RSA-SHA2 设备被无意降级。
3. Scrapli Windows Paramiko 和非 Windows system transport 均复用共享策略；system transport 使用 `+` 追加旧算法并保留现代优先级，且通过 `ssh -Q` 过滤本机不支持的算法。
4. OpenSSH 8.2 与新版本的公钥选项通过 `ssh -G` 选择 `PubkeyAcceptedKeyTypes`/`PubkeyAcceptedAlgorithms`。
5. vendor/platform/device_type/命令映射保持原有契约，算法策略不包含厂商分支。

## 剩余风险与建议

- `legacy_break_glass` 会恢复高风险旧算法，只应在隔离管理网、明确授权和审计条件下使用。
- 未新增持久化 profile 字段；若需要在设备长期纳管中为单台设备固定 break-glass 档案，后续应增加 PostgreSQL migration、设备/资产字段和前端受控配置。
- 仍建议升级设备 SSH 服务，最终移除 SHA-1、CBC 和 `ssh-rsa` 兼容依赖。
