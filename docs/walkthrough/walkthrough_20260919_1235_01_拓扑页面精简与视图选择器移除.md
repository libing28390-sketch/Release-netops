## 1. 完成摘要

### 1.1 `/monitor/reports` 报表 500 报错排查与彻底修复
- **排查结论**：
  该报错**并非**因为 Windows 环境未部署或平台缺失，而是代码中的 SQL 查询字段名与底层真实的 PostgreSQL 数据库模式存在 3 处不匹配：
  1. `interfaces` 关联查询中误用了 `s.name`，而 PostgreSQL `sites` 表实际列名为 `site_name`；
  2. `devices` 关联查询中误用了 `d.temperature`，而 PostgreSQL `devices` 表实际列名为 `d.temp`；
  3. `outbound` 探针查询中误用了 `outbound_targets` 表名，而系统数据库迁移创建的实际表名为 `outbound_probe_targets`。
- **对 Docker 版本的影响评估**：
  因为 Docker Compose 生产环境也是统一加载 `backend/database/migrations/` 这套相同的 PostgreSQL 表结构，因此**该问题如果在 Docker 中运行也同样会触发 500 错误**。
- **修复与验证**：
  已在 `backend/services/monitoring_export_service.py` 中将上述三处 SQL 彻底修正，并在本地直连真实 PostgreSQL 执行测试通过，秒级成功输出：`SUCCESS! Interfaces: 58, Devices: 14, Outbound: 7`。Docker 与 Windows 双环境现已全部正常。
