## 关键实现说明

- `inspect` 阶段解析 `DATABASE_URL`，并通过 PostgreSQL `current_database()` 与 `current_user` 校验真实连接目标。
- 明确拒绝重置 `postgres`、`template0`、`template1` 系统数据库。
- PostgreSQL 重置前自动定位 `pg_dump`，使用 custom format 写入 `data/backups/database-reset/`；密码只通过 `PGPASSWORD` 环境变量传递。
- 备份退出码、文件存在性和非零大小全部通过后，才允许执行 `DROP SCHEMA public CASCADE`。
- 并发连接终止条件使用实际数据库名参数，不再写死 `netops`。
- schema 重建后调用现有 `init_db()`，并验证 `users`、`devices`、`credentials`、`schema_migrations` 及默认管理员 bcrypt 密码。
- 桌面端执行前展示数据库类型、地址和库名，要求用户完整输入数据库名后才能继续。
- 成功后显示备份路径和重建表数量，并自动重新启动后端服务。
- 历史重置函数已改名并显式禁用，不再由界面按钮调用。

## 剩余风险与后续建议

- `pg_dump` 主版本高于目标 PostgreSQL 服务端通常可用，但正式部署建议安装与服务端主版本一致的客户端工具。
- 首次真实使用前建议先在独立临时数据库完整演练备份、重置和 `pg_restore`。
- 数据库恢复出厂不会清理磁盘附件和录像；如需要完整卸载，应设计独立且范围明确的文件清理流程。
