# MIG-001 迁移策略 walkthrough

MIG-001 只确定策略，不执行生产迁移。现有 V1 数据必须先被读取、计数、做 hash/租户/权限清单，再按四类数据的可信度分波次处理。

| 数据层 | 当前可信度 | 策略 | 激活前硬门槛 |
| --- | --- | --- | --- |
| Document | C | 保留原始字节/hash，追加不可变 Document Version | source hash、tenant、ACL、provenance 全部可证明 |
| Metadata | B | 解析、规范化、hash、冲突隔离 | active 行必填字段 100%，未知/冲突不进入检索 |
| Chunk | B | 从可信 Document Version 重建新 generation | 0 孤儿/重复/环，结构保真通过，失败 generation 不可检索 |
| Embedding | C | 固定模型/维度/contract 后重算，不复制旧 JSON/TEXT 向量 | 维度/contract 100% 匹配，shadow 召回/延迟无回归 |

本轮 PostgreSQL 只读 catalog 显示：V1 `ai_document` 156 行、`ai_document_chunk` 474 行；V2 文档身份/版本表已存在但为空；canonical chunk/embedding 目标表尚未创建。该结果支持“先策略、后迁移”的判断，不能被解释为已完成迁移。

回滚始终保留 V1：禁用 V2 typed/shadow read，恢复 V1 adapter 或上一 READY generation，保留 quarantine、原始内容、hash 和审计证据。
