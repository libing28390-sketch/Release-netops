# 容器指标启动顺序完成记录

## 根因

整机启动时 Compose 只等待 `docker-socket-proxy` 容器进入运行态，没有等待它代理的 Docker API 已可用。cAdvisor 首次请求 `/info` 超时后，Docker 容器发现 factory 初始化失败且没有自行重试。cAdvisor 的 `/metrics` 仍能响应，因此 vmagent 的 scrape target 看起来在线，但 VictoriaMetrics 只有主机级序列，Grafana 容器图表没有数据。重启 cAdvisor 会重新初始化 Docker factory，所以之前单独重启采集端后数据恢复。

## 实际修改

- `docker-compose.yml`：给 `docker-socket-proxy` 增加 `/info` 健康检查，并让 cAdvisor 等待 `service_healthy` 后再启动。
- 健康检查使用 `wget -Y off`，绕开容器环境继承的 HTTP 代理配置，避免本地 Docker API 探测被发往外部代理。
- `backend/tests/monitoring/test_monitoring_v1_deployment_contract.py`：新增 Compose 契约检查，锁定健康检查命令、超时/重试参数和依赖条件。
