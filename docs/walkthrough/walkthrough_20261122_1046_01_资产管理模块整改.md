## 一、完成摘要

已完成资产管理模块（`/assets/dashboard`、`/assets/devices`、`/assets/servers`、`/cmdb/assets` 及对应后端接口）的全部 9 项整改，涵盖 **6 项功能/安全/死代码缺陷修复** 与 **3 项首屏加载与接口性能优化**：

1. **[P1 安全/越权] CMDB 资产树与列表权限范围过滤与凭据脱敏**：`GET /api/cmdb/assets/tree`、`GET /api/cmdb/assets` 已接入 `_asset_scope_clauses` 并统一走 `_sanitize_asset_item`（修复原手写脱敏遗漏 `snmp_community` 等敏感列的问题）；`GET /api/assets/tree` 补齐缺失的 `device_role` 查询列。
2. **[P1 多厂商适配] 消除合法子平台静默回退**：补齐 `backend/api/assets.py` 与 `backend/core/platform_utils.py` 对 `cisco_iosxr`、`cisco_asa`、`huawei_smartax`、`huawei_usg`、`juniper_srx` 及主流安全/网络厂商平台的识别规则，并统一 Cisco 默认平台为 `cisco_ios`。
3. **[P2 服务器管理] 站点字段统一与服务端状态计数/筛选**：`InventoryServersTab` 全面切换至规范 `site_id` / `site_name` / `site_code`（对接 `/api/cmdb/sites`），通过 `GET /api/assets?include_status_counts=true` 返回服务端全量状态分布计数，快捷状态卡直接驱动服务端 `status` 过滤与分页重置，同步移除无法触发的死删除弹窗。
4. **[P2 网络设备] 生命周期、标签与快捷状态卡服务端分页**：`GET /api/devices` 新增 `lifecycle_status`、`tag_ids`、`quick_filter` 查询参数（在 `quick_filter` 之前计算 `status_counts` 与 `health_counts`，保持顶部 KPI 稳定），`inventoryStore` 与 `InventoryDevicesTab` 去除当前页客户端二次过滤，彻底修复分页空页问题。
5. **[P3 表单与死代码] 复制表单状态污染与死代码清理**：修复 `openCopy` 误复制 `snmp_community_set: true` 且未规范化 `platform` 的问题；清理 `AssetManagement/index.tsx` 中不可达的 XTerm 弹窗与 `TerminalAccessModal`，以及 `CmdbAssetManagementTab.tsx` 中隐藏的旧分页 DOM。
6. **[P2 首屏加载性能] 体积瘦身与懒加载**：从 `AssetManagementTab` 首屏彻底移除 `xterm`（284.45 kB）与静态 `xlsx`/`importUtils`（443.60 kB，改为导入与兜底模板下载时按需 `import()`），并将 `AssetModal`（80.01 kB）与 `AssetImportValidationModal` 改为 `React.lazy` 弹窗打开时按需加载。
7. **[P2 首屏接口性能] 消除重复/冗余请求与搜索防抖**：在 `inventoryStore` 新增 `hydrateAssetsSummary`，`AssetManagement` 首屏不再重复请求 `/api/assets/summary`；移除首屏无用的 `/api/racks` 请求（改为 Excel 导入校验时按需拉取）；为 4 个资产列表页的搜索框统一增加 250ms 防抖。
8. **[P2 后端汇总性能] 单次聚合查询**：将 `GET /api/assets/summary` 中 4 次串行全表 `COUNT(*)` 合并为单条 `SUM(CASE WHEN ... THEN 1 ELSE 0 END)` 聚合 SQL。
