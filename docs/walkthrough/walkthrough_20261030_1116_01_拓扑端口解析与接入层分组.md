# 拓扑端口解析与接入层分组

## 完成摘要

修复了 LLDP `Port ID` 二进制值被当作接口名写库的问题；角色分层布局会把密集层拆成最多六台的子行，并按已发现的最近上联层级排列；节点主机名完整显示，按相邻间距换行，背景框和标签避让按新行高度扩展。

## 关键实现

- `backend/services/snmp_service.py` 同时读取 `lldpRemPortIdSubtype`（OID `.6`）、原始 `lldpRemPortId`（OID `.7`）和原始 OCTET STRING 字节。 subtype 2/3/4/6 不作为远端接口名；MAC、网络地址和线路标识只保留可读的十六进制证据，优先使用有效端口描述。没有可用描述时邻居关系保留、端口留空，避免 NUL 写入或伪造端口。
- `backend/services/topology_service.py` 将 subtype 和可安全存储的 Port ID 证据放入观察 payload。
- `src/utils/topologyRoleLayout.ts` 将每个角色层分为最多六台的行；密集子行依据 LLDP 物理上联设备分组，双上联节点平衡到最近上层分组，未连接节点排在后面。完整布局保留所有设备。
- `src/components/TopologyGraph.tsx` 以完整名称替代省略文本，按可用宽度换行；同步扩展名称底板、角色文字位置及标签碰撞区域，因此画布缩放、平移和 SVG/PNG 导出仍读取相同名称文本。

## 剩余边界

- 当 subtype 是 MAC、网络地址或线路标识且没有可用端口描述时，拓扑仍会保留邻居观察，但没有远端接口名可用于确认接口级链路。
- 多行分组作用于层级自动布局。其余布局模式保留原有排列方式；名称仍会完整换行显示。
- 未对远端 SNMP 数据再次采集；修复基于用户给出的 `.6` subtype 与 `.7` 原始 OCTET STRING 证据。
