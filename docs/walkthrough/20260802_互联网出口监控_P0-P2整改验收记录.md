## 3. 外部验收阻断

目标地址 `http://192.168.96.1:5400/monitor/outbound` 在本次及上一轮验收时均无法连接；对应 API 地址也无法连接。应用内浏览器连接初始化再次返回“系统找不到指定的路径”，因此无法取得真实页面截图、登录态、实时采集数据或浏览器交互证据。

另外，完整串行 `pytest -q backend/tests` 在 10 分钟门限内仍未完成；此前一次串行运行暴露的 19 个上传测试事件循环隔离问题已修复，并单独复验为 19 passed。拆分执行的全部顶层测试文件及领域目录均通过，当前证据是“分批全量通过，但串行总耗时超过门禁”，不能将串行命令标记为通过。

## 4. 目标环境恢复后的验收项

1. 打开监控页面，确认概览、可用性、链路、告警、分析、运维六个视图可访问。
2. 创建/编辑链路，验证站点、设备、接口级联过滤，以及非法跨站点/伪造 ifIndex 被拒绝。
3. 对真实 SNMP 设备执行手工测试，确认成功、超时、认证失败、空响应不会被写成 0 流量。
4. 观察 70/85/95 告警的触发、恢复、重复触发、确认、关闭及审计记录。
5. 验证维护窗口抑制、主备/负载均衡链路组、探针绑定、关联事件和容量建议。
6. 运行一次汇总/保留/关联定时任务，并检查 PostgreSQL 分区与汇总查询耗时。
7. 目标环境恢复后重新完成串行测试和浏览器验收，记录最终耗时和结果；通过后再将三份清单状态改为 `accepted`。
