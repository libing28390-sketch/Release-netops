# IP 地址清单完整性与展示

## 根因与数据证据

- `/api/ipam/addresses` 原先只合并 `ip_addresses` 手工记录及活动 `network_endpoints`，不读取 M0299 的成功代次 CMDB 接口快照。
- 只读聚合审计（当时数据库快照）：WH-DC-01 有 15 个 IPAM 前缀、0 条手工 IP 地址记录；原 IPAM API 返回两条虚拟前缀网关、0 条自动发现 IP。成功 CMDB 快照当时有 9 台设备/426 条接口观察，33 条带前缀长度的接口 IP，聚合为 19 个报告 CIDR；审计时这些地址都没有落入 WH-DC-01 的 15 个 IPAM 前缀。
- 因此“15 个网段”和“2 条地址”本来是前缀目录数与地址行数的不同口径；没有地址行的其他前缀不会自动生成地址。接口快照原先未投影到 IPAM，导致可用的接口 IP 也没有出现。
- CMDB 接口观察缺少 VRF；接口 IP 只能显示为接口采集来源及设备报告的网络范围，不能安全地关联到某个已有 VRF 前缀，也不能自动创建 IPAM prefix。

## 修改

- `backend/services/ipam_service.py`：IPAM只读列表新增当前成功代次 CMDB 接口 IP 观察；展示站点、设备、接口、采集时间、设备报告 CIDR 与 source。明确分类未匹配/待 VRF 确认；支持搜索设备报告 CIDR；不修改共享 `interfaces`、`ip_inventory` 或 monitoring endpoint。
- `src/pages/IPVlan/IPAddressTab.tsx`、`src/pages/IPVlan/ipAddressTablePresentation.ts`：分开显示已纳管网段与设备报告网络、接口采集来源、匹配状态和真实采集时间；站点/前缀/IP 固定可见，其余列横向滚动；说明栏始终展示“网段数”和“地址行数”是不同统计，并显示接口观察数、设备报告 CIDR、匹配/未匹配/待 VRF 确认数。旧后端未返回接口统计字段时也显示明确状态，不再把对照说明整块隐藏。手工行不以创建时间冒充发现时间，无采集时间的网关显示“未采集”。

## 数据边界与剩余事项

没有批量创建/修改 IPAM 网段；报告 CIDR需依据地址规划另行纳管。快照不含 VRF，现有前缀没有被猜测式绑定。未修改监控代码或解析模板。修改尚未提交/推送。需要让浏览器实际连接的开发后端加载当前工作区版本后，才能完成接口快照行的现场验收；不应通过结束无法确认归属的监听进程来强制重启。
