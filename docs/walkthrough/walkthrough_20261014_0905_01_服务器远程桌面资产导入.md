# 服务器远程桌面资产导入 Walkthrough

## 完成摘要

资产导入模板现在提供可选的“远程桌面”工作表，可按资产编号或主机名为新导入资产填写 RDP、VNC 配置。表头沿用其他工作表的“资产编号”“主机名”，并提供与服务器示例资产对应的 RDP/VNC 示例行。导入前应按实际情况替换或删除示例行。远程桌面导入沿用资产凭据，不在该表重复填写凭据 ID。

资产表已有普通/管理员凭据。导入远程桌面配置时，这些资产凭据作为 RDP/VNC 的默认凭据，因此远程桌面工作表不重复列出凭据 ID。若 RDP 或 VNC 需要使用不同账号，可在导入后打开资产的远程桌面配置单独绑定。

RDP 证书 SHA-256 指纹是可选的 RDP 服务器证书固定值，不是操作系统硬件指纹或机器唯一 ID。它要求 64 位十六进制字符串；必须填写实际服务器证书的指纹。VNC 不使用域、安全模式和证书指纹，因此这些列在 VNC 示例中留空。

“远程桌面”表将资产编号、主机名和协议标为必填项；说明明确资产编号与主机名至少填写一项即可。填写说明及参数参考增加 RDP 域、四种安全模式、真实证书指纹格式和剪贴板双向复制粘贴的说明及示例。

- `backend/api/assets.py`：扩展资产导入请求，在该资产行的事务中复用现有远程桌面 profile 保存服务，并只记录非敏感审计摘要。

## 关键实现说明

- RDP 和 VNC 分行填写，同一资产最多各配置一行；未填写端口时使用 RDP 3389、VNC 5900。
- 远程桌面导入继承资产普通/管理员凭据；如需某个 RDP/VNC 配置使用不同凭据，导入后在资产远程桌面配置中单独绑定。
- RDP 安全模式留空时使用 NLA；剪贴板共享默认关闭；配置名称可留空并使用协议默认名称。
- 配置行无法关联到本次工作簿中的资产、协议重复或字段无效时，前端会提示行号。资产工作表里的凭据引用无效时，后端回滚对应资产行。
- 按既有规则，重复资产会跳过而不会更新。远程桌面配置仅随新资产导入，不会借重复导入修改已有资产。

## 剩余风险与后续建议

- 导入前需确保资产工作表引用的凭据库 ID 有效，且凭据类型和账号角色适用于目标登录；不匹配时该资产行不会导入。
- 本次只修改代码和模板，没有部署到线上。服务器需要采用包含这些改动的版本后，下载的新模板才会出现远程桌面工作表。
