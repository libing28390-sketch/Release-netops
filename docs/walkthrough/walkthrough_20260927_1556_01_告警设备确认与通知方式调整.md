# 告警设备确认与通知方式调整

## 变更摘要

- CMDB 搜索命中结果放入独立、受限高度的确认窗口，以较小字号展示设备名、管理 IP 和资产信息。
- 搜索结果勾选只更新窗口内的暂存选择。点击“确认选择”后才写入规则；“取消”丢弃窗口内的改动。
- 告警主表单只显示已确认机器数量及“查看或调整”入口，不再堆叠大量 IP。已确认设备可以在同一弹窗中查看和调整。
- 搜索命中超过窗口展示上限时，提示缩小范围并禁用确认，避免误把前 50 台当成完整结果。
- 移除用户可见的“系统投递”渠道标签。网络规则中的旧 `workspace` 数据兼容为当前可配置的 Webhook/邮件；`m0259` 只归一化非宿主机规则及其历史快照。
- 审核后确认，宿主机 CPU、内存、磁盘规则只参与平台健康状态计算，并不进入告警通知投递链路。宿主机表单改为明确说明这一点，列表显示“仅用于健康状态”；数据库中的内部兼容值保留，不暴露成用户可配置渠道。

## 关键文件

- `src/pages/AlertRulesTab.tsx`：CMDB 搜索确认弹窗、紧凑的主表单摘要，以及宿主机健康状态说明。
- `src/pages/alertManagementShared.ts`、`src/pages/alertManagementShared.test.ts`：前端通知渠道归一化及对应测试。
- `backend/services/alert_rule_service.py`：网络规则通知渠道和通知组约束；保留宿主机阈值规则语义。
- `backend/services/background_monitor_service.py`：保留内部旧渠道兼容处理。
- `backend/database/migrations/m0259_normalize_alert_rule_notifications.py`：只归一化非宿主机规则及历史记录。
- `backend/tests/monitoring/test_alert_rule_notification_channels_migration.py`、`test_alert_rule_notification_groups.py`、`test_host_alert_rule_runtime.py`：渠道迁移、通知组和宿主机阈值回归。
- 对应计划：`docs/plans/plan_20260927_1556_01_告警设备确认与通知方式调整.md`。

## 行为边界

页面当前不会把宿主机阈值规则当成通知规则。若要为宿主机健康事件发送邮件或 Webhook，需要另行接通健康事件评估和 outbox 投递后再开放配置。
