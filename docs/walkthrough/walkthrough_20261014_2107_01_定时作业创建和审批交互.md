# 定时作业创建和审批交互走查

## 完成摘要
- 定时作业编辑/创建收敛为“任务与目标”“调度与审批”两步，限定内容宽度；第二步展示小型目标设备预览、调度配置、审批和最终创建。
- IP 查询结果不再默认勾选；查询只显示候选项，用户明确勾选后才加入范围。输入提示同步说明需要手动选择。
- 新增只读 cron 预览接口，使用 APScheduler 实际时区和 `CronTrigger` 计算最多 10 个未来运行时间；预览有加载、无效表达式、错误、空结果和重试状态，接口暂不可用不会阻止有效表单提交。
- 停用/启用和删除审批验证码输入满 6 位后自动验证；验证中显示状态并用请求状态/ref 阻止重复验证，失败后允许修改验证码重试。停用/删除仍保留验证通过后的最终操作确认。
- 邮箱审批验证码使用专用简洁模板，主题固定为“Nexora 安全审批验证码”，正文只含审批事项、申请人、验证码、有效期、验证次数和安全提示，不再呈现告警表格、manifest、hash 或自由说明。
- 按用户要求放宽周期作业限制：可选择命令执行、自动化脚本以及配置变更模式，不再由 API 全局返回“暂不支持计划执行”。

## 关键实现说明
- cron 预览的计算时区直接取动态 APScheduler 实例，避免与实际计划任务的默认时区脱节；重复取下一个时间点时推进微秒，避免重复返回同一时间。
- cron 预览只影响展示，不作为表单提交的硬性依赖；API 请求被取消时不覆盖新表达式产生的结果。
- 邮件函数不再接收 alert 对象；邮件正文对动态字段做 HTML 转义并去除换行，OTP 不写入日志。
- 验证请求通过 `verifying` 状态和 in-flight ref 保护；输入变更后可重试，验证成功后仍需用户明确确认停用或删除。
- 创建/更新 API 不再拦截 `command`、`script_run` 和 `is_config`；前端为命令与脚本分别提供输入方式。命令只能选择直接命令或已发布脚本其中一种，脚本作业必须使用一个已发布脚本，配置变更原因纳入 OTP 审批清单。
- 调度器放开后仍以 `authorization_manifest_hash` 作为执行授权：每次运行重验创建者、租户、计划作业权限、配置内容和目标设备权限；管理凭据授权每次重新检查。已发布脚本的内容摘要不匹配、脚本撤销或审批内容变化都会拒绝执行。
- `is_config` 对网络设备继续选择配置模式；Linux 主机执行普通 Shell 命令，不会错误进入网络设备的 config 模式。

## 剩余风险与建议
- 运行中的应用尚未加载本轮构建；部署/重启服务后，需在浏览器确认命令、脚本和配置变更表单。旧表单状态在刷新后会丢失，且验证码可能过期；如果作业内容或范围变化，应重新申请审批。
- 绑定平台 Profile 的网络设备仍由调度器要求使用其 `platform action_code`，以保留该平台解析器策略；用户截图中的 Linux 主机不受此条件影响。
- cron 时间使用服务器 APScheduler 本地时区计算，浏览器以本地时区格式显示；跨时区部署场景应在 UI 同时标注时区。
