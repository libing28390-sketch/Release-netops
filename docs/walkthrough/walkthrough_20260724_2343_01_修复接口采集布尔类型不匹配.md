# Walkthrough / 验证报告: 修复接口采集布尔类型不匹配

## 完成摘要

修复了在 PostgreSQL 核心关系数据库环境下，手工或调度执行接口采集时，向 `interfaces` 表保存/更新记录时因为对 `is_l3` (boolean) 字段传入整型数字 `1`/`0` 导致 PostgreSQL 抛出 `DatatypeMismatch: 字段 "is_l3" 的类型为 boolean, 但表达式的类型为 integer` 异常而崩溃的 Bug。

## 实际修改文件

* [backend/services/interface_collection_service.py](file:///d:/netops/netsops-main/backend/services/interface_collection_service.py)
* [backend/services/scheduler_service.py](file:///d:/netops/netsops-main/backend/services/scheduler_service.py)

## 关键实现说明

1. **接口采集修改**：将 `backend/services/interface_collection_service.py` 内部 `UPDATE` 和 `INSERT` 语句中对 `is_l3` 列硬编码的整型 `1` 替换成了标准 SQL 布尔型字面量 `TRUE`。
2. **调度服务同步修改**：将 `backend/services/scheduler_service.py` 在拼接物理接口 values 时，对 `is_l3` 的三元表达式返回值从整型 `1`/`0` 更改为了 Python 的布尔对象 `True`/`False`。
3. **兼容性**：修改后的代码采用标准的 `TRUE`/`FALSE` 逻辑和 Python 原生 `bool` 类型，在 PostgreSQL 和单元测试使用的 SQLite 环境下均完全兼容。
