# 无线 AP 纳管离线统计修复走查

## 完成摘要

修正了 AP 下线时总数随在线状态行消失而减少、离线数仍为 0 的统计缺陷。所有完整 AP 清单采集共用已知身份保留逻辑；H3C 额外使用其 MIB 的明确连接状态。看板现将总数称为“纳管 AP”，并将“明确断连”和“完整清单中未上报”分别作为可识别状态。

## 关键实现

- H3C adapter 按 APID/序列号生成稳定 AP 身份，读取 `hh3cDot11APConnectionType`。`notAvailable(3)` 映射为 `disconnected`；只有 `run` 且连接类型为 master/slave 才映射为 `online`；过渡状态和未知枚举保持独立语义。
- H3C 组合状态使用 `snapshot_only`，避免单 OID 周期轮询覆盖由连接类型和运行状态共同得出的结果。断连后运行 AP 表若不再提供名称/型号，会保留之前成功采集的展示值。
- 完整 AP 清单中缺失的既有 `component_state` 身份不再被立即禁用，而是保留为 `not_present`，导出状态标签 `not_reported` 并刷新完整清单的观测时间。不完整、partial、failed 快照不会修改 AP 状态。这个通用生命周期规则适用于所有完整的 wireless AP 采集来源。
- Grafana 总数基于仍启用的 AP 状态身份；在线查询识别 `associated/run/online`；离线查询识别厂商明确断连和 `not_reported`。未上报在 AP 明细里单独显示，不把它描述成设备直接返回的明确断连。

## 剩余风险与后续建议

- 对未提供明确断连 OID 的厂商，完整清单缺行会显示为 `not_reported` 并计入离线统计；仅凭 SNMP 缺行不能区分 AP 离线与 AP 已从控制器删除。后续应增加控制器配置清单删除确认或人工核销流程。
- 部署新看板和后端后，建议在维护窗口再次对一台 AP 做断连验证，确认目标 AC 固件在断连时返回 `notAvailable`，或 AP 行从完整清单消失后呈现 `not_reported`，并验证恢复后复归在线。
- 回滚路径是恢复本走查列出的后端、看板源和展示配置文件，并重新生成无线看板 JSON；不涉及数据库 schema 或设备配置。
