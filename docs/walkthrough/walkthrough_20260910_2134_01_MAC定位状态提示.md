# MAC 定位状态提示 — 完成记录

## 完成摘要

已修复 IP 定位 MAC 表结果语义不清的问题。定位服务现在保留原有 list 返回兼容性，同时附带结构化 `mac_lookup` 状态；IP 定位主页面和复用面板会根据状态显示 MAC 表命中、未开启、设备不支持、查询失败或已查询未命中。ARP-only 仍作为设备不支持/查询不可用时的安全降级路径。

## 关键实现说明

- MAC 查询结果通过 list-compatible 的 `_MacQueryRecords` 携带状态，不破坏既有直接比较、索引和遍历调用方。
- 状态覆盖 `not_attempted`、`disabled`、`unsupported`、`query_failed`、`not_found`、`found`；命令和平台注册动作均做相应归因，响应不携带凭据或原始异常敏感内容。
- 注册动作或全表采集遇到模板未产出结构化记录时，会复用已保留的原始 MAC 表输出做保守解析，避免“设备有记录但模板为空”被误判为未命中。
- 多跳追踪保留先前命中的 MAC 证据，并在 `last_status`/`mac_lookup_attempts` 中记录后续下游查询状态，避免上游已命中时被后续未命中覆盖。
- ARP-only 位置说明根据状态生成，不再把策略关闭或设备不支持误写为“MAC 表中未发现”。
- `PATH_TRACED` 终端卡片不再展示冗长的路径推理备注；必要的 ARP-only、链路未完成和查询状态提示仍保留。
- 用户卡片将内部 `PATH_TRACED` 映射为“已定位到接入端口”（英文：`Access port located`），其他位置类型也通过共享标签映射展示。
- “实时刷新”按钮在已有普通 MAC 结果时可用，不再只依赖 ARP 缓存命中；前端共享状态文案抽到 `src/utils/macLookup.ts`。

## 剩余风险/后续建议

- `mac_table` 事实库仍由后台终端采集任务写入；单次交互定位的 MAC 命中是实时证据，不会自动替代全量快照。若要在 NSOT MAC 表中看到记录，仍需为支持该能力的设备开启 `endpoint_location` 并执行同步。
- 真实设备的动态 MAC 可能在查询间老化或迁移；状态会明确显示“已查询未命中”，不会伪装成设备不支持。
