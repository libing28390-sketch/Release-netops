## 关键实现

- AP 离线数按设备标签匹配 `总 AP 数 - 在线 AP 数`，并将结果限制为不小于 0；缺少任一侧数据时 PromQL 不产出离线数。
- 02/03 面板说明只保留读数含义和必要口径，不展示实现细节。生成器改动后审阅了完整输出；只有 Device 与 Wireless 两份 dashboard JSON 发生内容变化。
- 设备列偏好版本升至 v2，默认 13 个核心列；平台代码、适配版本、绑定来源、版本一致性诊断列不再出现在主表和导出中。
- 机柜名称优先使用资产模型的 `racks.name`，兼容旧名称字段；测试覆盖名称与内部机柜标识不一致的场景。
- Luna 子 Agent 参与复核无线指标来源和离线计算语义；主 Agent 整合看板、设备列表、测试及交付记录。

## 剩余风险与后续建议

- 若设备仍无总 AP 指标，离线 AP 会保持无数据，这是为避免将在线 AP 数冒充离线数；需在后续采集适配中补齐可信总量来源。
- 旧的全列偏好会因列偏好版本升级而重置到默认核心列；用户仍可使用支持的可选列设置。
- 用户部署新版本后，可在 03 检查在线 AP=2、总量缺失时离线 AP 留空，并查看 02/03 的精简提示。
