# 平台凭据、投产说明与资产保存错误处理

## 完成摘要

- 凭据中心的新建表单不再显示 Cisco 专用 Enable 密码；已有凭据仅在所有绑定设备均为 Cisco 平台时显示该字段。
- Web 管理入口改为紧凑启用栏和独立配置弹窗，取消弹窗会恢复打开前的草稿。
- 资产状态未完成凭据上手时，尝试投产会展示明确阻断说明，并可保存当前表单、保持原“待投产”状态。投产操作通过后，分别说明口令上收会更换设备普通/特权口令，免上收会保留原口令并记录豁免、设备不纳入 Nexora 托管。
- 凭据尚未验证时，阻断弹窗也会展示口令上收和免上收两种路径及禁用原因；免上收明确说明仅适用于存量资产、仍需连通性验证，不能绕过后端门禁。
- 根因：稳定错误响应同时包含 `error` 契约和根级 `detail`，通用 API 客户端此前优先把整个 `error` 对象当作详情，资产页又只认字符串，所以具体服务端原因被通用提示遮住。
- 修复后前端优先显示具体服务端 `detail`，解析 `details.errors` 字段校验数组；密码值继续脱敏。没有具体原因时显示状态码和请求编号，不再统一落到“保存校验失败”。
- Linux 综合巡检脚本在 `df -iP` 对不支持 inode 统计的文件系统返回 `-` 时跳过整数比较；有效百分比仍按阈值判定。

- `backend/api/assets.py`：资产列表、详情提供 `onboarding_status`；保留投产服务端前置门禁。

- `backend/database/seed.py`：跳过非数字 inode 百分比。

- `src/api/http.ts`、`src/api/http.test.ts`：响应同时含通用错误摘要和具体 detail 时保留具体原因。
- `src/pages/CmdbManagementTab.tsx`：按绑定平台控制 Enable 密码字段。
- `src/pages/AssetManagement/types.ts`：同步 `onboarding_status` 类型。
- `src/pages/AssetManagement/index.tsx`、`src/pages/AssetManagement/index.test.tsx`：安全格式化和脱敏保存错误；未完成上手时提供保留待投产的保存路径。
- `src/pages/AssetManagement/components/AssetModal.tsx`：Web 入口配置弹窗及清楚区分凭据保存、口令上收和免上收投产。
