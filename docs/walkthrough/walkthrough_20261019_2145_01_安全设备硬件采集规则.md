# 安全设备硬件采集规则走查

## 完成摘要

基于 LibreNMS 固定提交 `6c26b4fe4a40f7b392c19c36a44257212736e38c`，新增 20 个安全设备 OS detection/discovery profile，覆盖 9 个资产安全厂商；新增 43 个 MIB 及传递依赖。bundle 现在包含 156 个 profile、298 个规则 YAML、2,403 条 MIB 清单记录。当前已纳入规则没有缺失的 MIB import 依赖。

FortiGate 有一个可选描述模板引用上游未提供的 `InetAddress_FORTINET-FORTIGATE-MIB`；它只影响显示标签，没有采集 OID 依赖。Palo Alto `panos` 保留两条依赖型号/版本身份的 partial 诊断。没有把任何猜测的厂商 OID 放进 bundle。

## 实际修改文件

- `backend/vendor/librenms/resources/definitions/os_detection/`、`os_discovery/`：20 个上游 profile。
- `backend/vendor/librenms/mibs/`：43 个安全设备 MIB 与标准依赖。
- `backend/vendor/librenms/source-manifest.json`、`README.md`、`docs/architecture/SNMP采集全流程与代码索引.md`。
- `backend/services/librenms_mib_service.py`、`backend/services/mib_repository_service.py`、`backend/api/devices.py`：安全资产厂商的 MIB scope 归一化和同步范围。
- `backend/tests/snmp/test_librenms_bundle_manifest.py`：安全规则、模块引用、MIB imports、哈希与 scope 回归。
- 根目录 `handoff.md` 更新本地缺口及官方来源研究；按项目约定不加入公开提交。

## 覆盖边界

没有固定 LibreNMS OS profile 的资产厂商：Sangfor、Venustech、NSFOCUS、Topsec、Qi An Xin。WatchGuard Fireware 有识别规则但没有可解析硬件定义。Barracuda NG Firewall、Load Balancer、WAF 与 Sophos UTM 也没有可解析的硬件定义。Barracuda Email Security profile 只有一个通用 count sensor；不能把它描述为完整健康采集。

官方文档补查发现：

- Sangfor NGAF 说明可从设备 SNMP 页面下载产品 MIB；该文件随设备/产品版本提供。[Sangfor NGAF SNMP 文档](https://support.thailand.sangfor.com/hc/th/articles/14011519045273-Monitor-NGAF-%E0%B8%9C-%E0%B8%B2%E0%B8%99-SNMP)
- WatchGuard Fireware 列出企业 MIB，并说明随 Fireware OS 安装到管理电脑。[WatchGuard MIB 概览](https://www.watchguard.com/help/docs/help-center/en-US/content/en-us/Fireware/basicadmin/snmp_about_mibs_c.html)、[企业 MIB 字段](https://www.watchguard.com/help/docs/help-center/en-US/Content/en-US/Fireware/basicadmin/snmp_mibs_details_c.html)
- NSFOCUS WAF/ADS 文档说明从设备页面下载产品 MIB；公开文档没有提供可固定版本的独立 MIB 包。[NSFOCUS WAF SNMP](https://nsfocusglobal.com/introduction-to-nsfocus-waf-snmp/)、[NSFOCUS ADS 用户指南](https://nsfocusglobal.com/wp-content/uploads/2022/02/NSFOCUS-ADS-V4.5R90F03-User-Guide.pdf)
- Barracuda WAF 和 Load Balancer 文档提供设备 MIB 下载方式与部分 OID；CloudGen Firewall 公布 PHION-MIB 硬件传感器字段。[WAF OID 文档](https://documentation.campus.barracuda.com/wiki/spaces/BWAFv76/pages/2724374/SNMP%2BGET%2BCommands)、[Load Balancer MIB](https://documentation.campus.barracuda.com/wiki/spaces/BLBv42/pages/3637596/How%2Bto%2BConfigure%2BSNMP%2BMonitoring%2Bon%2Bthe%2BBarracuda%2BLoad%2BBalancer)、[CloudGen PHION-MIB 字段](https://documentation.campus.barracuda.com/wiki/display/CGFv90/PHION-MIB%2BField%2BDescriptions)
- Sophos UTM 文档列出其支持的标准 MIB；Astaro MIB 页面用途是通知 trap，而非产品硬件 discovery。[Sophos UTM SNMP 文档](https://docs.sophos.com/nsg/sophos-utm/utm/9.721/help/en-us/Content/utm/utmAdminGuide/MgmtSNMP.htm)
- Topsec 官方防火墙资料确认 SNMPv1/v2/v3 支持，但本次公开检索未找到可下载 MIB 或硬件 OID 表。[Topsec 防火墙资料](https://www.topsec.com.cn/uploads/2022-01-18/0e5c988b-b02d-4a36-8460-04451ea9cdb61642487890475.pdf)
- Qi An Xin 部分产品页说明支持 SNMP，但未找到与目标安全设备型号对应的公开 MIB/OID 文档。[奇安信产品文档入口](https://www.qianxin.com/support/product)
- 本次公开网页检索未找到 Venustech 安全设备可下载的官方 MIB/OID 文档。

这些厂商资料不是 LibreNMS OS discovery YAML。没有把它们冒充成已实现规则；如后续要加 Nexora 专有采集器，需取得匹配固件版本的 MIB 原件，明确产品身份字段，并为非 LibreNMS 来源建立独立的版本与 SHA-256 来源校验。
