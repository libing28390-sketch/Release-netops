# 设备版本识别与批量绑定一致性 Walkthrough

## 完成摘要

本次修复将“设备实际软件版本”和“平台命令/解析适配版本”明确分开：设备的 `version` 继续保存 `show version`/SNMP 采集到的真实软件版本，平台 Profile 的版本只表示命令与 TextFSM 适配代际。批量绑定在已知两者主版本冲突时默认被前端和后端拦截；管理员勾选明确覆盖后才允许手动使用不一致的 Profile，风险提示仍会保留。已有错误绑定不会被后台静默改写，也可以选择“修改绑定”改成与设备实际版本匹配的 Profile。

## 关键行为

- 批量绑定弹窗将目标字段标为“命令/解析适配版本”，并说明它不等同于设备当前软件版本。
- 设备列表、展开行和详情页现在并列显示“设备软件版本（SNMP/采集）”与“命令/解析适配”。例如设备实测 `7.1.064 (V7)`、绑定 `华三 Comware V5 (V5)` 时，两者都会保留且会标记“版本不一致”；绑定信息通过设备的具体 Profile 元数据返回，不再把 Profile 版本伪装成设备软件版本。没有显式绑定的历史设备也会显示“默认命令/解析适配”（依据平台族和实测主版本推导），不会再出现只有手工修改过的设备才有适配信息的情况。
- 已知的 H3C、锐捷、迈普主版本不一致时，前端显示冲突并默认禁用提交；管理员明确确认后发送 `allow_version_mismatch`，后端只允许 Administrator 覆盖，否则仍返回稳定错误码 `PLATFORM_VERSION_MISMATCH`（HTTP 409）。
- 批量校验先完整检查所有设备，再执行更新，版本冲突不会产生部分绑定。
- 已有错误绑定可以手动修正：选择“修改绑定”，选同厂商且版本匹配的 Profile（例如设备 `7.1.064` 选择 Comware V7），确认管理员操作后保存；如确实需要 V7→V5，则勾选管理员覆盖确认后保存。解除或覆盖已有绑定仍遵守原有 Administrator 权限与确认流程。
