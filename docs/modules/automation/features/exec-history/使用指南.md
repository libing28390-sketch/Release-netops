# 执行历史使用指南

## 进入页面

1. 使用有权访问该功能的账号登录 Nexora。
2. 在侧栏展开“自动化”。
3. 点击“执行历史”，浏览器应进入 `/automation/history`。
4. 若页面提示无权限，应由管理员核对角色和资源范围，不要通过前端绕过。

## 日常操作

1. 先查看页面顶部的范围、状态、来源和更新时间。
2. 使用搜索或筛选缩小对象范围；清除筛选后应恢复完整列表。
3. 打开目标对象详情，核对标识、所属范围和证据。
4. 执行写操作前再次确认目标、影响范围和回退条件。
5. 操作完成后查看结果、失败原因与审计记录；不要只依据按钮提示判断成功。

## 本功能特别注意

以 PostgreSQL 持久化数据为事实源，页面明确展示加载、空数据、未知、失败和成功状态，并保留来源与更新时间。

## 异常与空数据处理

- 加载中：等待请求结束，不重复触发高风险操作。
- 无数据：确认筛选范围与数据接入是否正确；无数据不等于健康。
- 未知：根据页面提示补充配置、权限或采集证据。
- 请求失败：记录页面错误与时间，检查 API、网络和 PostgreSQL 连接。
- 状态冲突：优先刷新实时证据；冲突消除前不执行确定性修复。

## 验收清单

- [ ] 侧栏入口和 URL 正确。
- [ ] 页面无横向溢出或遮挡，常用分辨率可操作。
- [ ] 搜索、筛选、分页或空状态符合业务规模。
- [ ] 正常、异常、未知、未配置和无数据没有混用。
- [ ] 写操作反馈可追踪，高风险操作有保护。
- [ ] 数据来自真实 API；没有固定演示结果。
- [ ] 相关持久化使用 PostgreSQL。
