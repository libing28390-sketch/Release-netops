# 监控存储保留与磁盘保护

VictoriaMetrics 保存 Grafana 查询的历史指标，vmagent 负责采集和短期重试缓存。当前参数与默认值为：

| 配置 | 默认值 | 含义 |
|---|---|---|
| `VM_RETENTION_PERIOD` | `30d` | 指标保留 30 天，过期数据通过后台清理回收 |
| `VM_MIN_FREE_DISK_SPACE_BYTES` | `10737418240` | 首次启动时的回退值；管理员可在“监控 → 采集器”中调整 `/storage` 剩余空间保护阈值 |
| `VMAGENT_MAX_DISK_USAGE` | `1GB` | 每个 remote-write 地址的磁盘重试缓存上限 |

剩余空间保护仅约束 VictoriaMetrics 的新指标写入；已有数据仍可查询。其他容器和宿主机仍可写入同一磁盘，vmagent 也会继续缓存到配置上限。因此这不是整台主机的硬性磁盘配额。缓存满后最旧的待发送数据会丢弃，保护期间可能产生数据缺口。

## 前端调整和立即应用

在“监控 → 采集器”页面，管理员可以调整 VictoriaMetrics 的最小剩余空间阈值。保存并确认后，宿主机 helper 先备份 `.env`，只同步 `VM_MIN_FREE_DISK_SPACE_BYTES`，再提交共享运行时配置；两处同步成功后，容器内的 supervisor 向 VictoriaMetrics 进程发送 SIGTERM，等待它优雅退出后再退出，由 Docker 的 `restart: unless-stopped` 策略重启整个 VictoriaMetrics 容器。新容器从持久化运行配置卷读取新阈值。应用期间指标写入会短暂中断，原有 `/storage` 数据卷不会删除。

页面会同时显示设定值、当前生效值、主机 `.env` 同步状态、容器状态和最近容器重启时间。若 `.env` 同步失败，运行阈值不会提交；若 VictoriaMetrics 没有成功启动，状态会显示错误代码。该控制适用于 Linux/systemd 下的标准 Docker Compose 部署。

部署脚本在 Linux/systemd 主机安装一个无网络访问的 systemd path/service helper；页面通过共享运行时卷提交受限请求，helper 只允许更新 `VM_MIN_FREE_DISK_SPACE_BYTES`。NetOps Web 容器不挂载主 `.env`，也不获得 Docker socket。每次 `.env` 实际变更前，helper 在部署目录创建权限为 `0600` 的 `.env.backup.vm-threshold.*` 备份，并以原子替换保留其他参数、文件权限及 LF/CRLF 行尾。页面保存值仍保存在 `nexora-vm-runtime` 卷中并由 VictoriaMetrics supervisor 使用；该值与 `.env` 同步，并在普通容器重启或升级后保留。不要用 `.env.example` 覆盖现有凭据。

首次安装或手动使用 Docker Compose 的主机，需要在部署目录运行 `sudo bash scripts/monitoring/install_vm_storage_env_sync.sh`。没有安装同步 helper 时，页面显示未就绪并禁止提交阈值，避免运行值与 `.env` 分离。

## 容量预算

设备数无法直接换算成 GB：接口数量、指标数量、采集间隔、标签变化和压缩效果都影响容量。先在目标设备规模下运行 24–72 小时，按同一时间点的 `du -sk /storage` 差值测量日增量，再预算保留期，并为索引、后台合并、清理延迟和其他业务卷留下空间。30 天保留不代表第 30 天立即回收到固定大小，减少保留期也不会立刻释放全部旧数据。

例如实际日增量 1GB 时，30 天基础数据量约 30GB；90 天约 90GB，均尚未计入余量。官方建议存储文件系统至少保留 20% 空闲空间。当前 97.4GiB 文件系统仅剩 23.2GiB 时，应结合其他业务占用评估扩容，而不是把全部剩余空间都分给指标。

## 回滚与数据影响

磁盘保护阈值可在页面中改回旧值，保存确认后会再次立即重启 VictoriaMetrics 容器。保留期和 vmagent 队列上限仍由 `.env` 配置；修改它们后需执行 `docker compose up -d --no-deps victoriametrics vmagent` 才会生效。已因保留期清理的数据、已因队列满丢弃的样本不会因回滚恢复；有长期保留要求时应先备份或迁移存储。
