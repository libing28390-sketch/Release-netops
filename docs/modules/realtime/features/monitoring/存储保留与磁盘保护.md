# 监控存储保留与磁盘保护

VictoriaMetrics 保存 Grafana 查询的历史指标，vmagent 负责采集和短期重试缓存。默认部署值为：

| 配置 | 默认值 | 含义 |
|---|---|---|
| `VM_RETENTION_PERIOD` | `30d` | 指标保留 30 天，过期数据通过后台清理回收 |
| `VM_MIN_FREE_DISK_SPACE_BYTES` | `10737418240` | `/storage` 所在文件系统剩余不足 10GiB 时停止接收新指标 |
| `VMAGENT_MAX_DISK_USAGE` | `1GB` | 每个 remote-write 地址的磁盘重试缓存上限 |

剩余空间保护仅约束 VictoriaMetrics 的新指标写入；已有数据仍可查询。其他容器和宿主机仍可写入同一磁盘，vmagent 也会继续缓存到配置上限。因此这不是整台主机的硬性磁盘配额。缓存满后最旧的待发送数据会丢弃，保护期间可能产生数据缺口。

## 已部署服务器更新

修改仓库默认值不会覆盖已有 `.env` 中的值；若已有 `VM_RETENTION_PERIOD=90d`，必须更新服务器 `.env`。不要用 `.env.example` 覆盖现有凭据。

在服务器仓库更新到包含本次修改的版本后，执行下列命令。脚本只替换三个配置键，保留其余值，兼容原来的 LF/CRLF，创建带时间戳的备份：

```bash
cd /data/nexora-automation
python3 - <<'PY'
from datetime import datetime
from pathlib import Path

path = Path('.env')
content = path.read_bytes().decode('utf-8')
backup = path.with_name('.env.backup-' + datetime.now().strftime('%Y%m%d-%H%M%S-%f'))
backup.touch(mode=0o600, exist_ok=False)
backup.write_bytes(path.read_bytes())
updates = {
    'VM_RETENTION_PERIOD': '30d',
    'VM_MIN_FREE_DISK_SPACE_BYTES': '10737418240',
    'VMAGENT_MAX_DISK_USAGE': '1GB',
}
lines = []
seen = set()
for line in content.splitlines():
    key = line.split('=', 1)[0].strip()
    if key in updates:
        if key not in seen:
            lines.append(key + '=' + updates[key])
            seen.add(key)
    else:
        lines.append(line)
lines.extend(key + '=' + value for key, value in updates.items() if key not in seen)
path.write_bytes(('\n'.join(lines) + '\n').encode('utf-8'))
PY
docker compose config --quiet
docker compose up -d --no-deps victoriametrics vmagent
```

该操作重建两个监控容器并复用原有数据卷。使用 `up` 应用启动参数；仅执行 `restart` 不会更新参数。若 shell 或额外 Compose env-file 已设置同名变量，也需同步更新，因为它们可能覆盖 `.env`。

## 确认运行参数与空间

```bash
docker inspect nexora-victoriametrics --format '{{json .Config.Cmd}}'
docker inspect nexora-vmagent --format '{{json .Config.Cmd}}'
docker exec nexora-victoriametrics df -h /storage
docker exec nexora-victoriametrics du -sk /storage
docker exec nexora-victoriametrics sh -c "wget -Y off -qO- http://127.0.0.1:8428/metrics | grep -E '^vm_(storage_is_read_only|free_disk_space_bytes)'"
```

预期出现 `-retentionPeriod=30d`、`-storage.minFreeDiskSpaceBytes=10737418240`、`-remoteWrite.maxDiskUsagePerURL=1GB`。`vm_storage_is_read_only` 为 1 表示存储已进入保护状态；释放空间后会重新检查并恢复写入。

## 容量预算

设备数无法直接换算成 GB：接口数量、指标数量、采集间隔、标签变化和压缩效果都影响容量。先在目标设备规模下运行 24–72 小时，按同一时间点的 `du -sk /storage` 差值测量日增量，再预算保留期，并为索引、后台合并、清理延迟和其他业务卷留下空间。30 天保留不代表第 30 天立即回收到固定大小，减少保留期也不会立刻释放全部旧数据。

例如实际日增量 1GB 时，30 天基础数据量约 30GB；90 天约 90GB，均尚未计入余量。官方建议存储文件系统至少保留 20% 空闲空间。当前 97.4GiB 文件系统仅剩 23.2GiB 时，应结合其他业务占用评估扩容，而不是把全部剩余空间都分给指标。

## 回滚与数据影响

可把三个配置值改回原值，再执行 `docker compose up -d --no-deps victoriametrics vmagent`。已因 30 天策略清除的历史数据、已因队列满丢弃的样本不会因回滚恢复；有长期保留要求时应先备份或迁移存储。
