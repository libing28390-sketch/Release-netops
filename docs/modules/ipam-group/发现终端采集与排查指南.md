# 全局 ARP 采集与终端识别（SNMP）

## 同设备端口定位

ARP的VRF未确认时，仍可使用同一设备、站点、VLAN和MAC的二层证据显示物理端口：ARP/FDB观测相差不超过5分钟，SNMP接口属性当前成功代次明确包含该access端口，access VLAN相同，并且端口候选唯一。上联和聚合口排除；此结果不确认VRF、不自动登记地址。页面没有原始VRF值时留空。

桥端口映射多于PVID条目时，仅输出有完整PVID及VLAN成员关系的端口属性，不因其他非VLAN端口没有PVID而拒绝全部结果。当前代次没有提供的端口不能复用旧属性来完成上述匹配。

## 先分清两件事

1. **采集原始 ARP**：供 IP 定位使用，应覆盖所有 SNMP 可采到 ARP/邻居表的网络设备，不只采网关。
2. **识别终端**：从 ARP 记录中排除网关、设备接口、虚拟网关等基础设施地址，再结合 VLAN 和 MAC 转发表判断终端及接入端口。

ARP 记录不能直接等同于终端。页面默认展示的数量也不是全网 IP 总数。

## 设备采集范围

| 数据 | 应采设备 | 默认不采设备 |
|---|---|---|
| ARP：IP、MAC | 所有 SNMP ARP 表可用且属于管理范围的设备，包括路由器、三层交换机、防火墙和确实支持 ARP 表的接入设备 | SNMP 不支持 ARP 表的纯二层设备；采集状态标记为不支持，不当作 0 条记录 |
| MAC FDB：MAC、VLAN、端口 | 管理范围内 SNMP FDB 可用的交换设备；上级交换机的记录也可用于分析路径 | 不提供桥接/FDB 表的设备；最终端口定位需确认是终端侧接入口 |

**ARP 采集不能只按“网关设备”筛选，也不能只靠 `core`、`access` 等角色猜测。** 应维护 SNMP 能力和采集状态清单。设备角色只能帮助初选。

SNMP 不支持、凭据缺失或读取失败时，明确显示不支持/失败，不要静默排除。ARP/FDB 的采集范围依据各自能力独立确定，不按角色硬性排除。

全局 ARP/FDB 周期任务只用 SNMP。SNMP 不支持或失败时保存状态并保留上次完整快照，不回退 CLI。

## 从 ARP 中识别终端

- 按站点、VRF、IPAM 网段和 VLAN 解释 ARP 记录。
- 将已登记的网关 IP、设备/接口 IP、VRRP/HSRP 虚拟 MAC、网络/广播地址等标为基础设施。
- 其余记录作为终端候选。只有站点、VLAN、MAC 和时间窗口匹配、VRF 范围可解释，且拓扑/端口类型能够确认唯一终端侧接入口时，才补充接入交换机和端口；其余显示“未定位”。FDB 中的上联或聚合端口不能直接当作终端物理端口。
- 保留原始 ARP 观测供 IP 定位；终端页只做分类和筛选，不要在采集阶段把非网关 ARP 丢掉。
- 原始 ARP/FDB 保留来源、批次、时间和完整性，并设置历史保留期限。采集失败不更新终端的最近发现时间，不删除历史观测，也不判断为离线。

## 采集周期：当前与建议

2026-11-03 本机代码修改前的运行状态：

| 当前任务 | 实际情况 |
|---|---|
| ARP 后台周期任务 | 配置为每 10 分钟一次；近期观测批次约为北京时间 11:15、11:25、11:35、11:45、11:55 |
| ARP 每日作业 | 数据库还启用了每天 02:00 的 `arp-daily-sweep`，尚无执行记录；存在额外自动采集入口 |
| FDB | 采集函数存在，但没有注册周期任务；30 分钟只是未接入调度的常量，不能据此认为已经在跑 |
| IPAM 投影 | 每分钟读取已有数据库记录，不访问设备 |

代码和 `.env` 现已调整为一个 ARP+FDB 联合作业，每 60 分钟运行一次；migration `m0307` 会停用每日 ARP 作业。ARP 与 FDB 的“近期”判定窗口同步为两轮加 2 分钟抖动（当前默认 122 分钟），避免源表已经按小时采集、IPAM 却仍按旧周期判断为过期。当前已运行进程和数据库尚未重启/应用迁移，因此要等服务重启后才会按新周期运行。

联合作业先采 ARP、再采 FDB，每类最多 2 台并发；设备失败使用退避，不重叠堆积。另有两个显式手动入口：`/ip-locator/arp-sweep` 会立即扫一轮 ARP；`/ip-locator/nsot-sweep` 会手动触发 ARP、FDB 和其他网络事实同步。因此自动任务不是“每天只跑一次”，但手动点击会额外触发采集。IP 定位单 IP 查询仍是另一条按需路径。IPAM 投影每分钟只读数据库，不访问设备。

低频采集无法保证发现所有短时终端。H3C S6850 Release 66xx 文档给出的动态 FDB 默认老化时间是 300 秒，实际设备配置可能不同。因此每小时甚至每日采样，都可能漏掉两轮之间出现后又老化的记录；页面必须展示最近观测时间。要提高短时终端覆盖率，应补充 DHCP 绑定或事件数据，而不是承诺仅靠低频 ARP/FDB 得到完整实时清单。[H3C S6850 MAC 地址表命令参考](https://www.h3c.com/en/Support/Resource_Center/EN/Home/Switches/00-Public/Reference_Guides/Command_References/H3C_S6805_S6825_S6850_S9850_CR-66xx/03/202204/1588650_294551_0.htm)

## S6850-5 / 172.16.5.10

- 已知 S6850-5 本机看到 `172.16.5.10 → 8e47-5760-0706`，VLAN 7、GE1/0/2；但平台尚未通过 SNMP 采到它。
- 这份 CLI 输出不能证明 SNMP ARP 表支持或凭据可用；需要单独做 SNMP 能力检查。
- 当前自动 ARP 选择依赖设备角色和 SVI 证据，S6850-5 是 `access` 且没有 SVI 证据，所以被排除。若 SNMP 能读取它的 ARP 表，应把它列入全局 ARP 采集清单；不能因为角色是 `access` 就跳过。
- MAC FDB 则应从 S6850-5 采，用于确认该 MAC 的接入端口。
- IPAM 中 `172.16.5.0/24` 在两个站点都有记录。S6850-5 所在的 WH-DC-01 记录没有 VLAN 和网关；另一个站点的 `172.16.5.1` 不能直接套用。需补齐 WH-DC-01 的 VLAN/网关信息。

## 当前需要补齐的系统逻辑

1. 用 SNMP 探测并记录每台设备的 ARP/FDB 支持状态，ARP 清单覆盖所有支持设备，不限于网关。
2. ARP 周期任务按这份清单采集；对不支持或失败设备显示原因。
3. MAC FDB 按 SNMP 能力清单采集；上级交换机记录保留作路径证据，最终定位要求唯一终端侧接入口。
4. 终端页在全量 ARP 观测上分类，默认过滤基础设施和非业务范围。

改动前，ARP 自动选择依赖 L3 角色/SVI，FDB 没有周期任务。新代码按在线纳管设备尝试 SNMP ARP/FDB；不支持/失败写入 `device_collection_status`，并保留旧快照。S6850-5 将在新作业启动后首次接受 SNMP 检查；CLI 看到 ARP 记录还不能证明它的 SNMP MIB 和凭据可用。

## IP 定位页面

- 普通“定位”：优先读取有效、唯一的 SNMP ARP + FDB + 接入口证据，不从全部核心设备开始查路由。
- “实时刷新”：有目标 ARP 来源时，只刷新相关授权设备的 SNMP 数据；尚无来源时，在授权范围和设备数量预算内采集。
- SNMP 证据不足才进入原有定向路径追踪。设备的 core/access 角色不等于 MAC 表支持能力；明确禁用策略仍生效。
- 未知 VRF 的同设备物理端口证明只用于显示接入位置，不宣称已确认 VRF 或完整三层路径。
- 后台任务保存结果时重新核对源证据；证据变化则不再发布为完整定位结果。
