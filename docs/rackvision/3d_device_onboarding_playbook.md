# RackVision 3D 设备新增经验手册

这份手册记录当前 S6800 真机化打磨中验证过的做法。新增厂商或型号时，先遵守
[NEXORA_3D_ASSET_SPEC_V1.md](./NEXORA_3D_ASSET_SPEC_V1.md) 的资产契约，再按本清单联调。

## 1. 先固定“数据真相”，再做视觉

- 机柜位置来自 `/api/racks/{rack_id}/layout`，不要从 3D 模型或截图反推 U 位。
- 线路只渲染 `get_current_links` 返回的已验证物理链路；LLDP/CDP、发现来源、LAG 成员和运行状态随链路保留。
- 聚合链路必须展开成物理成员后再画线。逻辑 `Bridge-Aggregation` / `Route-Aggregation` 本身不是一个需要插线的端口。
- 没有链路证据时显示“无已验证链路”，不要用示例线冒充真实拓扑；如果确实需要演示线，必须显式标记为 preview。
- 端口灯只根据已验证链路点亮。没有活动/流量遥测时不要伪造闪烁速度，最多用稳定的 link 灯和弱副灯表达“已连接”。
- SFP/SFP+ 光模块只在链路端点被证实时插入：模块壳体、拉环、前端 receptacle 和介质色由 `fiber/copper/dac` 决定；空 cage 保持开放，不把整排端口预填成模块。
- 配线架是独立的被动 1U 设备，不等同于理线槽：只有 `/api/racks/{rack_id}/layout` 中存在
  `device_role=patch_panel` 的安装记录时才渲染。当前 CAT6 24 口资产优先使用
  `generic_patch_panel_cat6_24p.glb`，GLB 不可用时由 `PatchPanelFaceplate` 绘制 24 个开放式 RJ45
  插口；不凭空注入配线架，也不为被动端口伪造状态灯或链路。

## 1.1 机柜用途模板

机柜不应被强制套成“服务器 + 交换机 + UPS”的综合柜。前端的
`rackProfiles.ts` 提供可复用的用途分类：

- 网络设备柜：核心、汇聚、接入、DC Leaf/Spine、高密度交换机；
- 服务器柜、存储柜、安全设备柜、综合网络柜、综合布线柜；
- UPS/电源柜、传输/光通信柜。

分类只用于说明机柜用途和推荐布局，不覆盖 CMDB 的设备身份或 U 位。当前 JG-02
由交换机/防火墙占比自动识别为“网络设备柜 · 高密度交换机”，因此“几乎全是交换机”是
有效场景；只有实际安装了配线架、服务器或 UPS，布局中才会出现对应设备。

## 2. GLB 资产必须可被程序识别

Blender 导出前固定以下约定：1 Blender unit = 1 m，`1U = 0.04445 m`，坐标为
`X=左右、Y=前后、Z=上下`，设备正面为 `+Y`。导出后检查 transforms 已应用，scale 为
`1/1/1`，并记录真实宽度、深度、高度。

端口不要只建成一个实心盒。一个可读的端口组件至少包含：

1. 外层金属笼体/四边框；
2. 后退的黑色 cavity（腔体）；
3. 腔体内的触点、lane 或 latch；
4. A/B 端口灯；
5. 端口编号和 connection anchor。

每个端口对象的 `extras` 至少写入：

```json
{
  "component_type": "port_cage|port_cavity|port_contact|port_led|port_label",
  "port_index": 49,
  "port_media_type": "qsfp28",
  "connection_face": "front",
  "connection_anchor": "PORT_ANCHOR_FRONT_049"
}
```

材质名应保持稳定（例如 `MAT_PORT_CAGE`、`MAT_SOCKET_BLACK`、`MAT_CONTACT_GOLD`、
`MAT_LED_PORT`、`MAT_LABEL`），这样前端可以在不重导整套模型的情况下做独立灯效和材质修正。

## 3. 端口坐标与线路必须共用同一套映射

- 线路端点使用 `getPortPhysicalCoordinates()`，不能按设备中心、端口数量平均分布。
- 每一种设备都要把端口编号、物理 x/y 偏移、介质类型写成可测试的映射。
- S6800 的 49–54 是右侧两组三口 QSFP28；`QSFP1..6` 这类紧凑别名要明确映射到 49–54，不能把 1..6 当成左侧业务口。
- 至少测试首/中/尾三个高速口（例如 49、53、54），确认线路落在不同 cage；同时测试一个普通 GE/SFP 口。
- 对双排 SFP 设备要验证端口编号顺序（当前 S6800 GLB 为 01–08 下排、09–16 上排），线路和模块必须复用同一行偏移。
- 设备名称、厂商、型号和 asset key 的识别要集中在 helper 中，避免某个页面能识别、另一个页面退回通用布局。

## 4. 线路的审美与遮挡规则

线路要遵循“端口短引 + 面板外下走 + 机柜侧边汇线”的结构：

- 第一段从真实端口出发，只做短距离应力释放；
- 端点的 z 深度要落在模块 receptacle 面，而不是 cage 内部；用深色 boot 和细色应力释放段表达“已插入”，不要用大面积发光方块遮住插口；
- 双芯 SFP 光纤应把两根细纤芯分别对准两个 LC 孔，再合并到主线；铜缆/DAC 端点保持单 boot，不能用同一套形状冒充光纤。
- 公共水平段放在 `centerY - height/2 - clearance` 以下，不能穿过当前或下一台设备的面板；汇线槽应贴着 19 英寸安装轨内侧（当前实现约 `x=±2.35`），避免跑到柜体外侧，同时让其他设备的线路在正面视图可见；
- 同一个端点的多根线使用确定性的 lane offset 扇出，不能全部叠在一个 x/y；
- 线径随全景/特写调节，颜色按介质和状态区分（光纤本色蓝、铜缆本色黄、down 红色），hover 时只突出当前线；
- 端口组件的深度排序要在横向线段之前，未连接的端口必须仍能看到黑色腔体和边框；已连接端口只允许对应的短引或插头遮住自己。
- 配线架端口应保持两排（或资产定义的实际排布）独立可读，端口线缆从插口短引进入本层理线槽；理线槽的黑色挡板不能替代配线架面板。
- 若机柜顶盖/状态条与最高两台设备的 U 位有几何重叠，顶盖材质应关闭 `depthWrite`（只对这些结构件克隆材质），保留外观但不遮挡设备面板和端点。

## 5. 指示灯状态语义

- PWR：设备在线时稳定绿色；离线熄灭。
- SYS：正常绿色心跳；warning 仍保持绿色，告警由 ALM 表达；critical 使用明显红色脉冲。
- ALM：正常熄灭，warning 琥珀色闪烁，critical 红色闪烁。
- 链路端口：只有实际链路端点点亮绿色；副灯降低亮度，除非后端明确提供活动遥测。

状态灯应同时适配 GLB 原生灯和 procedural fallback，不能只在某一套渲染路径生效。

## 6. 每新增一个设备的验收顺序

1. **资产检查**：GLB 节点、材质、metadata、尺寸、正反面和端口数量。
2. **纯映射测试**：端口编号到 3D 坐标、别名归一化、首中尾端口不重合。
3. **前端测试**：`npm run test:frontend -- src/pages/RackManagement/Rack3D`、`npm run lint`、`npm run build`。
4. **浏览器检查**：正面、背面、45°、设备特写；分别查看按需线路和全线；确认 QSFP/SFP/RJ45 的腔体、灯、编号和线缆没有互相遮挡。
5. **拓扑回归**：用真实 LLDP/CDP 结果检查普通物理链路、LAG 多成员、down/degraded 状态及无链路场景。
6. **性能检查**：重复设备优先复用 GLB；动画只更新灯材质和必要粒子，避免每帧重建 TubeGeometry。

遇到视觉问题时，先判断是“数据/坐标错误”还是“层次/材质错误”：前者修正 topology normalization
和坐标映射，后者修正资产组件或前端 overlay，避免用线路偏移掩盖端口数据错误。
