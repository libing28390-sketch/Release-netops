# IPAM 网段创建与分配简化实施计划

## 任务目标

降低从接口生成网段的列表噪声，说明并简化网段创建、IP 分配和地址池流程；修正新增网段弹窗的闪屏与拥挤布局，同时保留现有 IPAM 数据和 API 能力。

## 本轮执行结果

- 已完成接口候选分页和状态筛选；UI 默认查看待创建项，支持逐页显式选择，也支持确认后一次生成全部待创建项。空 `candidate_ids` 不再隐式表示全量操作。
- 保留按精确 CIDR + 租户/站点/VRF 分组，不合并相邻网段。普通接口采集发现网段；手动生成流程还会补登记接口 IP。
- 新增网段表单以 CIDR 为起点；名称是可选别名，网关 IP 与网关设备关联分别解释；IP 规划器按需展开，高级作用域与状态字段默认收起。接口关联 ID 不再接受接口名称文本，新建留空，编辑保留原 ID。
- IP 分配将设备/MAC/角色/状态等次要字段折叠；地址池表单隐藏不需要的租户选择并从所属网段继承租户。列表已加载后，保存或刷新会保留当前行，失败的首次加载仍可正确显示加载状态。
- 本轮只做源码静态审查和 `git diff --check`；未运行测试、构建、浏览器或部署。

## 现状与问题

- 自动发现与手动生成是两条不同流程：接口采集会按精确 CIDR 和租户、站点、VRF 自动发现网段；手动生成还会登记接口 IP。相邻网段不能为减少条目而擅自汇总。
- 手动候选预览返回全部候选及完整接口明细，前端一次挂载大量行，数据量大时像报表且难以使用。
- `candidate_ids` 为空时后端会将其解释为生成全部候选，UI 虽然禁用了空选择，但 API 契约有误操作风险。
- 新增网段弹窗一次展示过多字段，CIDR 输入过程中推荐区域动态出现会导致内容位移；进场动画也会放大“闪屏”感。
- 网段名称是便于识别的可选别名；网关 IP 和网关设备是两个不同概念。当前网关接口输入框提示填写接口名，但字段后端按接口 ID 查询，需要核实契约。
- IP 分配与地址池表单包含可折叠的次要属性；矩阵快捷分配可以进一步缩成主要字段优先。

## 影响范围

- 网段创建/编辑、接口生成弹窗、IP 地址分配、地址池创建页面。
- 不涉及数据库迁移、真实设备配置、部署或已有 IPAM 数据删除。

## 实施步骤

1. 完成只读调用链检查，确认自动发现、手动生成、网关接口字段以及各表单保存契约。
2. 保留按精确 CIDR + 作用域分组，不自动合并相邻网段；让候选预览先呈现待处理摘要和精简条目，避免一次渲染所有接口详情。
3. 将批量生成限制为显式选中的候选，空选择请求返回可读错误；在 UI 提供明确的一键处理待生成项入口和必要的数量确认。
4. 重排新增网段表单：核心字段优先，作用域、网关关联及说明等次要字段按需展开；稳定推荐区域高度并减少弹窗进场/内容插入造成的跳动。保留现有可选数据字段。
5. 精简矩阵快捷分配和地址池的默认表单，仅保留核心输入；次要字段折叠并继续提交兼容的默认值。
6. 完成代码差异审查、静态格式/契约核对，并记录未执行的验证项。

## 验证计划

- 不运行测试或构建，除非用户明确要求验证；进行静态调用方与请求/响应契约审查。
- 检查 `git diff --check`，查看所有变更，确认没有触碰无关用户文件。
- 重点核查空候选拒绝、显式候选生成、CIDR 作用域分组不变、表单可展开回看全部字段、后台刷新不清空当前列表。

## 风险与回滚思路

- 现有调用方可能依赖空候选表示全量；修改前需检索全部调用点，确保 UI 始终提交显式 ID。
- 表单默认值变化可能影响旧数据编辑；高级字段需保持可见/可编辑，并沿用后端默认与校验规则。
- 候选精简不能丢失生成所需数据；生成仍应从服务端重新加载并校验完整候选。
- 候选分页响应有上限，但服务端为计算全局计数仍会扫描并归并完整接口集合；“生成全部待创建”目前是同步请求和单事务，特别大的批次仍可能受 API/代理超时影响。需要根据实际设备规模评估是否改为持久化后台任务并显示进度。
- 如出现契约回归，可回滚本任务对应的前端/API 改动；不需要数据库恢复，且此前已有工作区修改必须保留。

- 所有执行者需检查并保留共享工作区中的已有改动，不覆盖或撤销他人工作。
