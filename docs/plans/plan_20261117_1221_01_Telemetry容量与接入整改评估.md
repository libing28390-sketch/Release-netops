# Telemetry 容量与接入整改评估计划

- 目标：形成可执行整改建议书，明确独立采集器边界、64 MiB 限制作用域、数量/吞吐/存储模型和验收门槛。
- 现状：Compose 使用 vmagent/VM v1.103.0；抓取上限 67108864 字节；存在用户未提交业务改动。用户要求不使用任何 skills。
- 范围：只读审计代码与部署配置、官方版本源码；离线合成载荷测量；不访问设备、不访问生产数据库、不部署、不修改业务配置。
- 拟修改文件：本计划、对应 walkthrough、容量整改建议书及必要离线测量附件（均位于 docs/）。
- 步骤：核对现有资源与运行能力；核对协议各层大小限制；建立设备/接口/指标/频率模型；实测合成 Prometheus 载荷；形成整改项、建议准入上限和压测验收条件。
- 分工：主 Agent 负责本地配置、容量模型、文档和集成；limits_audit 子 Agent 只读核实官方 v1.103.0 大小限制，不写文件、不创建下级 Agent。
- 验证：离线脚本重新计算样本数、响应字节数、64 MiB 阈值和存储/队列预算；核对文档与配置行号。没有运行环境时不把模型当成生产实测上限。
- 风险与回滚：模型中的每样本字节、设备支持和生产余量均需现场测量；不作配置变更，无业务回滚。保留现有用户文件。
- 范围补充：用户追问资产导入是否接入Telemetry；只读核查当前资产API和前端导入工具，补充整改书中的资产新增/编辑/导入/已有资产绑定范围及验收，仍不实施业务代码。
- 完整性复核：用户要求检查其它遗漏，补充首发协议/数据模型/API契约、证书权限、可靠发布、资产生命周期、数据与告警时间语义、采集器owner、并发配额、消费页面及安装升级回退等12项实施契约；记录现有collector产物与CMDB同步复用边界。
