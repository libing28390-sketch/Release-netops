## 已确认差异与实现边界
- 对照 bundle 固定的 LibreNMS 提交 `6c26b4fe4a40f7b392c19c36a44257212736e38c`：CPU 非零、内存 module/正使用率是上游发现限制；保留零读数与非 module 内存属于有实体/容量证据的兼容增强。
- 内存容量缺失时，上游 `Mempool::fillUsage` / `Number::fillMissingRatio` 仍保留比例，而本地适配器丢弃整行。修正为独立读取使用率，实际容量可用时优先 64 位 `.32`、回退 `.10`，不伪造字节容量。
- 上游 `includes/discovery/sensors/temperature/comware.inc.php` 的机框 `.12`/阈值 `.13` 逻辑不在 YAML 中，本地缺少对应适配。补齐 module/sensor 筛选及 65535 不支持值。
- Grafana 查询的是库存 `nexora_hw_*`，不是 exporter 原始 `hh3cEntityExt*`。不修改看板查询或 Compose；诊断使用生产 poll plan 的只读模式，分别显示实时值和已持久化后台样本。
- 发现版本升级到 v5，并修正历史分类版本混存时重复触发升级发现的问题；常规六小时重发现 TTL 保留。
