# CMDB 页面缩放与网络设备接口采集

## 目标

修复 CMDB 各页面在视口/浏览器缩放变化时的布局伸缩与溢出问题，并让人工“采集接口”任务只面向在线网络设备。

## 现状与问题

- 用户反馈 `/cmdb/interfaces` 及 CMDB 其他页面在缩放时都出现布局问题，需要检查页面内容宽度、高度、最小宽度和嵌套滚动，不通过 CSS `zoom`/`transform: scale()` 缩放整个页面。
- CMDB 的“立即采集接口”当前会基于在线设备启动任务；需要在服务端明确限定网络设备，避免只靠前端隐藏选项。

## 影响范围

- 前端：CMDB 页面布局。
- 后端：CMDB 人工接口采集任务的目标设备选择和校验。
- 不更改设备配置、数据库结构、采集协议和周期采集策略。

## 文件与分工

- 主 Agent：负责统一计划、walkthrough、集成审查和最终验证。
- 前端 Agent：审查并修复 CMDB 页面缩放/容器布局；负责 `src/pages/CmdbManagementTab.tsx`、`src/pages/CmdbAssetManagementTab.tsx`、`src/pages/CmdbResourceSearchTab.tsx` 及确有必要的 CMDB 专属子组件。不改 ARP 页或后端。
- 后端 Agent：人工接口采集目标范围；负责 `backend/api/cmdb.py`、`backend/services/interface_collection_service.py` 及该接口采集 job 必须修改的专属服务。不改前端、调度器的周期采集范围或设备配置。

## 实施步骤

1. 逐页检查 CMDB 布局约束，统一视口自适应与内部表格滚动，修复硬编码宽度/缺失 `min-w-0` 等导致的溢出或缩放错位。
2. 审查人工接口采集的 API 与 worker 调用链，以项目现有设备分类为准将目标收敛到在线网络设备；服务端负责最终过滤与校验。
3. 保留用户已有未提交修改，仅改本任务归属区域。
4. 做 TypeScript、Python 静态检查及 `git diff --check`；按仓库质量门禁运行前端 lint 和隔离目录构建，不运行测试或真实设备采集。

## 验证计划

- 确认 CMDB 页面容器在缩放/窄视口下不改变根页面比例，超宽数据表在局部水平滚动。
- 确认接口采集 API 和 worker 的目标设备均经过服务端网络设备过滤，且错误/空候选行为明确。
- 运行 `npm run lint`、隔离输出目录的 `vite build`、后端目标文件 `py_compile` 和 `git diff --check`；不执行 pytest/Vitest、不连接设备。

## 风险与回滚

- 不同 CMDB 标签页的布局层级不同，可能存在页面局部滚动差异；以各页面数据操作不被裁切、窄视口内部滚动为验收。
- 设备分类的历史字段可能不一致；复用 CMDB 已有网络设备分类语义，服务端保守排除非网络设备。若不能从字段可靠区分，需记录未分类设备并安全跳过，不能默认当作网络设备。
- 回滚可分别恢复 ARP 表格区域、CMDB 专属布局和接口采集目标过滤；数据与数据库结构不变。
