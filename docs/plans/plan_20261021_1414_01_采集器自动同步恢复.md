# 采集器自动同步恢复

## 目标与问题
数据库 APPLIED 与内容 checksum 相同时，自动同步跳过发布，但没有核验版本产物、current/runtime 或运行版本文件；版本产物遗失也不会重新生成。失败结果顶层仍 SUCCESS。

## 范围与分工
- 主 Agent：monitoring_v1.py、collector_sync_service.py、main.py、相关同步回归测试与本计划/报告。
- Luna backend_worker：仅 collector_artifact_service.py 的只读完整性函数及 test_collector_artifact_service.py。
- 保留现有前端工作树；不部署、不重启服务，不变更真实设备。

## 实施
1. 复用 validate_artifact 校验版本、current/runtime 内容与状态；不得创建目录或输出凭据。
2. unchanged 分支只在产物完整时复用版本，运行副本损坏则要求重新发布；源产物缺失/损坏则重编译新版本。
3. 汇总 FAILED/PARTIAL_FAILURE，启动日志按结果输出；对跳过与真实发布区分日志。
   发布期间标记 RELOAD_PENDING，只有 exporter reload 成功才确认 APPLIED；重复发布不得覆盖真正的上一已知有效版本。
4. 覆盖冷启动/恢复卷、运行目录损坏、完整配置幂等、依赖失败回归。

## 验证
聚焦 PostgreSQL fixture/API/产物/同步 pytest；PostgreSQL-only scanner；API 契约影响时 npm lint。只读现场核验与本地故障注入分开记录。

## 风险与回滚
不以设备抓取成功率判断配置完整性，避免 SNMP 超时触发循环发布。校验失败保留 Last Known Good；不直接编辑运行凭据。回滚仅涉及本次后端代码。
