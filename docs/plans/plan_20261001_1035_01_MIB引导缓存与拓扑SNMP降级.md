## 目标

消除 LibreNMS MIB 在每个新后端进程第一次使用时重新索引/解析的高开销；修正用户演示的拓扑降级行为：同一台设备无论 SNMP/SSH 哪一路失败，画布始终只有一个设备节点；沿用原设备图标，通过角标和详情说明异常，不生成失败伪节点。发现进度按百分比展示，结束后只列异常项。

## 已知证据

- `ensure_rules_available()` 的 `_AUTO_SYNC_DONE` 是进程内布尔值，进程重启/热加载会重置；MIB 导入在首次规则/光模块路径调用时发生。
- `import_mibs_from_directory()` 先建立全量 MIB 符号索引，再逐个核对已入库文件；日志显示 217 个候选、0 新增、161 更新、56 跳过。
- 拓扑先 SNMP LLDP、后 SSH CLI；批次中 SSH 认证失败设备会标记失败。图上多个未知/重复节点提示当前匹配或证据发布仍有问题，不能把这些失败设备旧观测当成无效并丢弃。
- 用户说明 `10.254.0.1/.2/.3/.6` SSH 认证失败是故意制造的；`F1090-10/-9`、`S6850-4/-5` 成功。截图中仍显示多个 `未匹配到 CMDB` 节点。
- 用户确认 HCL 中 `S6850-1/2/3/4` 分别对应 CMDB `10.254.0.1/.2/.3/.4`；LLDP 的 `S6850_1` 是 `S6850-1` 的分隔符变体。
- HCL 参考图显示 `S6850-3/4` 是 `S6850-5/6` 的上游；若 `.3/.4` 本轮采集失败，就不能从它们生成 `.5/.6` 的当前邻居关系。
- 截图复核发现身份字段契约与 CMDB 别名索引都有缺口：标准邻居记录的 `neighbor_management_ip` / `neighbor_chassis_id` 未被旧提取器完整读取；读时未恢复原始 JSON 中的这些别名；CMDB 索引只使用 COALESCE 后的一条 IP/序列号，也漏掉设备 `sys_name`。这些情况都可能让同设备同时以管理 IP 和 LLDP 名称出现。
- 用户明确要求设备图标保持原样；异常用同一节点上的角标和 SNMP/SSH 分项详情呈现。
- 用户进一步要求每次发现不使用历史 LLDP 观测。旧来源观测在 SSH/SNMP 失败后仍处于 active，批次结束的 link rebuild 和孤立邻居投影会把旧边/伪节点继续画成当前拓扑。
- 当前进度卡即使任务已到 100% 仍显示“执行中”，并把成功设备逐项列出；终态状态和进度文案不一致，成功结果也占据异常列表空间。

## 分工与文件边界

- `mib_startup_cache` Agent：负责 MIB 导入的跨进程持久化跳过策略，仅修改 `librenms_rule_service.py` / `librenms_mib_service.py`，不得触碰拓扑文件。
- 主 Agent：负责拓扑失败设备与 SNMP LLDP 证据、CMDB 匹配、旧快照/链接的端到端核查与修复；负责集成与统一记录。
- 并行最多两个执行者；文件归属不重叠。保留工作树已有平台绑定与 SNMP 改动。

## 实施步骤

1. MIB importer：确认源指纹、parser 版本、导入记录和未解析 OID 修复条件；成功且指纹不变时跨进程跳过全量符号构建/解析，必要时采用数据库事务锁防止多个 worker 同时初始化。不得隐藏持续未解析项。
2. 拓扑：追踪 SNMP 失败/部分 MIB 成功但 SSH 认证失败时的 discovery result、snapshot generation、active observations、link rebuild、CMDB matching 与 API/UI；每轮开始清理本轮目标设备的旧 LLDP 观测及对应图投影，再只用本轮证据建图。采集失败的 CMDB 设备仍显示原节点和异常状态，但不能靠旧观测生成邻居或边；本轮有效 SNMP 邻居仍可合并入图。
3. 设备身份归并：管理设备匹配加入物理资产主机名/资产标签、设备 sys_name、设备与资产各自的管理 IP/序列号；确认的 `S6850_1`/`S6850-1` 等分隔符变体按唯一候选归并，碰撞时返回歧义，不猜测；无 chassis 时以 LLDP 系统名合并不同管理地址。提取器兼容统一字段名；读时从旧观测原始 JSON 恢复字段仅用于兼容当前有效行，不再把上轮记录重新当成本轮证据。
4. 异常展示：API 返回持久化拓扑采集状态及 SNMP/SSH 分项结果；画布保留原厂商/设备图标，只叠加角标，悬浮卡和检查面板显示错误详情。
5. 进度展示：运行时按已处理设备数显示百分比并保持 100% 与终态一致；成功项只计入汇总，终态结果区仅显示失败/部分异常/取消项。
6. 验证本轮清理、名称别名、冲突歧义以及错误/部分成功边界；确认单设备失败不阻断其他设备，并且失败设备不会带出旧邻居边。
7. 更新 walkthrough，明确已完成检查与剩余环境限制；不连接真实设备、不部署。

## 验证计划

运行拓扑邻居匹配、本轮观测清理和 discovery-run 并发边界的聚焦 pytest；执行 Python 编译、`git diff --check`、前端 TypeScript 静态检查，并审查身份归并、异常状态 API/渲染、进度终态调用链。记录目标部署数据库、浏览器和真实网络设备的验证限制。

## 风险与回滚

MIB 跳过判据必须以数据库已完成导入、源指纹/parser 兼容及 OID 修复完成为前提；失败/并发时应允许重试。每轮拓扑发现会删除被选设备的旧 LLDP 观测与对应物理投影，这是用户明确要求的当前拓扑语义；失败设备保留 CMDB 资产节点和错误状态。回滚只撤销本次 MIB/拓扑改动，保留工作树中已有的用户改动。
