# 实施计划：CMDB 接口采集改造为 SNMP 优先 (SNMP-First)

## 1. 任务背景与现状
1. **现状与痛点**：
   - 之前在 CMDB 资产管理与接口详情中，接口采集（`interface_collection_service.py`）默认走的是 SSH CLI（执行 `display interface brief` 并通过 TextFSM 解析）。
   - 华三、华为等交换机在二层 Bridge / Trunk 模式下，CLI 输出不显示三层 Protocol 字段，导致老旧解析器误将其标记为 `unknown`；
   - 此外，历史实现中仅采集包含 IP 地址的三层接口，导致二层物理端口被忽略，拓扑发现插入这些物理端口时占位填入了 `admin_status='unknown', oper_status='unknown'`；
   - 虽然时序监控（Prometheus / Grafana）已经使用 SNMP，但 CMDB 接口资产台账未直接以 SNMP 作为第一数据源。
2. **目标**：
   - 将 CMDB 接口采集改造为 **SNMP 优先 (SNMP-First)**：
     - 若设备配置了 SNMP 凭据，优先通过标准 IF-MIB（GetBulk）采集全量端口硬件状态（`ifOperStatus`、`ifSpeed`、`ifAlias`），毫秒级完成且绝无 `unknown`；
     - CLI 仅用于补充 VLAN 放通列表、VRF、三层 IP 地址等逻辑配置属性，不再由 CLI 决定物理状态；
     - 若设备未配置 SNMP 或 SNMP 超时，优雅降级走 CLI 兜底；
     - 拓扑发现（`topology_service.py`）对活跃 LLDP 接口的初始化不再盲目写入 `unknown`，而是赋予真实的 `up` 初始状态。
3. **约束条件**：
   - 严格遵守用户指令：**仅在本地完成验证与 Git 提交，绝对不执行 `git push`**。

## 2. 拟修改文件清单
1. `backend/services/interface_collection_service.py`：
   - 引入 `resolve_collector_credentials` 与 `collect_interface_data`；
   - 在 `collect_interface_status_target` 中增加 SNMP 优先探针；
   - 增加 `_upsert_snmp_interfaces` 函数，将 SNMP 采集到的全量端口（包括二层端口）同步至 `interfaces` 表；
   - 允许无 IP 的二层端口也能在 CMDB 中正确保持其 SNMP 物理状态（UP/DOWN）；
   - 降级支持：SNMP 失败或无凭据时继续走 CLI。
2. `backend/services/topology_service.py`：
   - 优化新发现 LLDP 接口插入默认值，从 `unknown` 改为遵循活跃链路状态（`up`）。
3. `docs/plans/plan_20260919_1626_01_CMDB接口采集改造为SNMP优先.md`：本计划文件。
4. `docs/fixes/fix_20260919_1626_01_CMDB接口采集改造为SNMP优先.md`：修复与改造记录。
5. `docs/walkthrough/walkthrough_20260919_1626_01_CMDB接口采集改造为SNMP优先.md`：验证走查记录。

## 3. 实施步骤
1. **编写异步转同步安全调度工具**：
   - 在 `interface_collection_service.py` 中增加受控的 `_run_async` 辅助函数，兼容独立运行与已存在事件循环的环境。
2. **实现 SNMP 接口采集与入库**：
   - 实现 `_collect_snmp_interfaces(device)` 与 `_upsert_snmp_interfaces(device, snmp_interfaces)`；
   - 确保端口的 `oper_status`、`admin_status`、`speed`、`description` 优先来自 SNMP IF-MIB 原生数据。
3. **将 SNMP 数据与 CLI L3/VLAN 逻辑数据智能合并**：
   - CLI 收集到的三层 IP、前缀掩码、VLAN 信息作为覆写与补充，而不覆盖已被 SNMP 权威判定的物理 `oper_status`。
4. **运行单元测试验证**：
   - 运行现有的接口采集、多厂商规范化及拓扑接口测试；
   - 确保原有测试全部通过。
5. **本地 Git 提交（不 Push）**：
   - 生成 fix/walkthrough 记录并在本地提交。

## 4. 风险与回滚
- **风险**：极低。SNMP 采集带有严格的超时保护与异常捕获，若设备 SNMP 不可达会自动回退到原有 CLI 逻辑，具有完整的双重容灾保障。
- **回滚方式**：可通过 Git 本地回滚。
