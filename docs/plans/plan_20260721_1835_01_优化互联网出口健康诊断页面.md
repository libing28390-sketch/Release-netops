# 优化互联网出口健康诊断页面 实施计划

本实施计划旨在针对用户对“互联网出口健康诊断页面”提出的状态一致性、数据可信度表达、图表可读性以及页面体验方面的 10 点反馈进行全面优化，提升整体产品的质感与监控专业度。

## 目标与改动内容

### 1. 状态一致性与解耦
- **现状**：当公网 IP 不匹配期望白名单时，若仍处于连续 2 次的防抖确认阶段（`public_ip_changed = False`），总体状态和卡片仍显示“正常”，使用户产生疑惑。
- **优化**：
  - 在卡片区和总体区域区分显示：连通性状态、IP 合规状态与综合状态。
  - 当发生 IP 不匹配时，即便处于防抖确认阶段（未降级健康状态），也在 IP 合规状态卡片和警告条中醒目提示 `不匹配（待确认/已确认）`，并列出匹配详细原因，避免矛盾。

### 2. 顶部摘要卡片改版为 6 栏高密度布局
将上方的五张摘要卡片重新规划并压缩高度 20%，重新组合为以下 6 张高密度信息卡片：
1. **综合状态**：正常/降级/出口中断。
2. **连通性状态**：健康/降级/中断，显示 `X / Y 目标可用`。
3. **公网出口 IP**：显示当前 IP，下方标注 `来源: ...` 和可信度级别。
4. **IP 合规状态**：显示 `匹配` / `不匹配` / `未限制`，下方显示 `期望: 202.96.128.8` 等。规则多时支持鼠标悬浮或展开。
5. **平均时延**：显示 `平均时延`，下方以较小字体展示 `P95: X ms · 最大: Y ms`。
6. **最后检测**：展示 `最后检测时间`（如 18:29:00），下方展示任务状态 `运行正常 / 采样中断 X 分钟` 及 `下次检测: X 秒后` 的倒计时。

### 3. 数据可信度与时延计算
- **优化**：
  - 后端 API 在 `get_outbound_status` 中动态计算当前 Run 的 `p95_latency_ms` 与 `max_latency_ms`。
  - 前端图表展示 P95 与最大时延信息。

### 4. 趋势图平滑度与时间轴不连续问题
- **优化**：
  - **平滑度**：可用率曲线从 `monotone`（平滑曲线）改为 `linear`（折线图）或阶梯线，故障点用红色圆点标记，避免可用率过度平滑失真。时延曲线保留轻微平滑。
  - **时间轴不连续**：当后端由于服务重启或中断出现数据断档时，图表不应自动连线，应在断档处**折线断开**，以正确表达数据缺失。
  - **刻度等宽**：X 轴时间刻度按等间隔显示（如每 5 分钟显示一个刻度），避免拥挤，而中间没有数据的区间呈现断空。
  - **图点微调**：默认不显示数据采样点，仅在鼠标悬停时（Hover）高亮显示。
  - **异常标记区间**：可用率低于 100% 的时间区间渲染淡黄色/淡红色背景指示带（`<ReferenceArea>`），明确标识历史故障，不再直接绘制红色圆圈采样点。
  - **降低透明度**：时延面积图的渐变透明度从 30% 调低至 12% 左右，减淡面积底色以避免干扰可用率曲线。
  - **可用率顶端留白**：可用率 Y 轴的最大值设定为 110%（保留 ticks 为 [0, 25, 50, 75, 100]），使 100% 曲线与顶部边框保持 10% 间距的空隙。
  - **图例与 Tooltip 单位与详情**：
    - 图例增加单位：`平均时延(ms)`、`可用率(%)`。
    - 鼠标悬浮 Tooltip 动态解析显示 `成功目标：X / Y`。
  - **黄色降级状态调优**：将 `degraded` 配色细调为黄色系（`text-yellow-600 bg-yellow-50/40 border-yellow-200`），取代偏深的橙色。

### 5. 语言完全汉化
- 翻译后台 API 的默认英文文案，如 `X of Y targets available` → `X / Y 个目标可用`，`No enabled targets` → `没有已启用的探测目标`。
- 将 `.env` 和 `.env.example` 中所有的配置注释全部中文化。
