# 定时作业创建和审批交互实施计划

## 目标
简化定时作业创建与停用审批流程，解决设备选择、目标预览、执行计划预览和审批验证码邮件的可用性问题。

## 现状与问题
- 创建界面有三步，弹层内容高度和宽度较大；设备匹配明细长期占据侧栏空间。
- IP 输入回车查询与选择设备的行为容易让用户误以为会自动全选。
- 调度与最终确认分散在多个步骤，缺少未来 10 次运行时间的预览。
- 邮箱验证码复用了告警邮件模板，呈现告警字段并包含审批清单、哈希、自由说明等过量信息。
- 停用/删除审批窗口视觉层级较重，验证码需要额外点击“验证”。
- 最新浏览器反馈显示第二步内容列过窄；后端 API 与调度器双重拒绝原始命令、脚本和配置变更作业，造成审批后提交失败。用户明确要求放宽该策略。

## 影响范围
- 定时作业创建/编辑页面与停用/删除审批弹窗。
- 定时作业只读 cron 预览 API。
- PAM 审批邮件专用模板与发送调用。

## 实施步骤
1. 前端：收敛为“任务与目标”“调度与审批”两步；使用适中的最大宽度并重排第二步摘要、调度、目标、审批卡片；IP 查询只显示候选，明确由用户逐项选择；把匹配设备列表缩成第二步中的有限高度摘要预览。
2. 后端：新增只读 cron 预览接口，使用与 APScheduler 相同的本地调度时区和 cron 规则，返回最多 10 个未来时间点；前端在第二步显示并处理加载、无效表达式和错误状态。
3. 前端：第二步集成调度设置、目标预览、审批人与验证码，以及创建摘要；去掉单独的最终确认步骤。
4. 邮件：为 PAM 验证码增加独立简短邮件模板，主题为“Nexora 安全审批验证码”，邮件只包含审批事项、申请人、验证码、有效期与勿转发提示，不走告警邮件布局。
5. 停用/删除审批：缩小弹窗内容和视觉层级；验证码输入到 6 位后自动发起一次验证，展示验证中/失败/成功状态，保留键盘可访问性和重试能力，避免重复并发验证。
6. 按用户授权放开定时作业中的命令、脚本和配置变更类型；仍要求 Operator 权限、OTP maker-checker 审批和审批清单精确哈希。命令作业只接受一个执行来源，脚本必须已发布并在运行时保持内容 SHA-256 不变；调度器每次执行重新验证作业所有者、租户、目标范围、执行权限和特权凭据权限。Linux 命令保持 Shell 执行，不误走网络设备配置模式。
7. 前端恢复命令/脚本选择，增加命令输入、配置变更标记与原因输入、命令筛选分类；客户端校验与服务端策略一致。第二步改为横向摘要、左侧调度、右侧目标和审批。
8. 主 Agent 审查整合差异，完成 walkthrough。

## Agent 分工与文件边界
- 前端执行者：负责 `src/pages/ScheduledJobs/components/JobModal.tsx`、`src/pages/ScheduledJobs/components/DeleteApprovalModal.tsx`、`src/pages/ScheduledJobs/index.tsx`、必要时 `src/pages/ScheduledJobs/types.ts`；可调用 `POST /api/scheduled-jobs/cron-preview`，请求 `{cron_expr: string}`，响应 `{success: true, data: {occurrences: string[]}}`；不改后端。
- 后端邮件执行者：仅负责 `backend/services/config_approval_service.py` 和 `backend/services/notification_service.py`，保留已有安全审批和跨租户改动；不改前端、不触发真实邮件。
- 主 Agent：负责 `backend/api/scheduled_jobs.py` 与 `backend/services/scheduler_service.py` 中的计划作业策略及 cron 预览接口、统一计划与 walkthrough、接口及差异整合。
- 两名执行者之间不共享写入文件；执行者不得创建子 Agent；不得覆盖/回滚既有工作树改动。

## 验证计划
- 做针对性代码审查，确认设备查询不会把结果默认为选中、预览严格最多 10 条、cron 错误有可读反馈、验证码验证无并发重复请求。
- 检查邮件主题/正文不再使用告警模板，也不含审批 manifest、哈希或自由说明。
- 运行 `git diff --check`。收到 Vite JSX 解析报错后，运行 `npm run lint` 和写入系统临时目录的 `npx vite build` 复核前端解析及打包。

## 风险与回滚
- 本次不改数据库与调度持久化，仅增加只读预览 API。若 cron 预览或 UI 有问题，可单独回退对应 API/前端调用，保存与执行路径不受影响。
- 邮件使用独立模板后需保持现有 SMTP 安全传输、速率限制、收件人校验和失败撤销审批令牌逻辑；不改变 MFA/飞书验证流程。
- 保留现有未提交修改；不提交、推送、部署，不创建真实作业、不发送真实审批邮件。
