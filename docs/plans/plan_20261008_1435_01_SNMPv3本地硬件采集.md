# SNMPv3 本地硬件采集

## 目标

让 Nexora 本地硬件发现、采样和 SNMP 诊断能够使用凭据中心已保存并绑定到设备的 SNMPv3 profile；继续兼容 v1/v2c，不依赖单独部署 LibreNMS。

## 现状与问题

凭据中心已保存 SNMPv3 用户名、安全级别、认证/隐私算法与密钥、Context Name。当前 `resolve_collector_credentials` 固定返回 v2c/community；本地硬件 poller 用 community 是否为空判断凭据有效，探测器的 GET/WALK transport 也仅支持 v1/v2c。SNMPv3 profile 因此进入 `not_configured`，无法完成硬件发现/采样。

## 影响范围

后端凭据解析、SNMP transport、硬件探测与轮询、只读诊断 API 与其前端版本选择，以及受影响的回归测试；不增加数据库字段，不改变设备配置，不部署或调用 LibreNMS。

## 实施步骤

1. 让 collector credential contract 从绑定的 SNMPv3 profile 返回版本、安全级别、用户名、算法、解密后的 auth/priv 密钥及 context，同时保留旧 community 字段和设备本地 v2c 回退。
2. 在 SNMP transport 中实现 v3 scalar GET/WALK，并将凭据对象贯穿标准 MIB、规则探测、发现与周期采样；校验 noAuthNoPriv/authNoPriv/authPriv 所需字段，并支持凭据入口允许的 MD5、SHA-1、SHA-224/256/384/512、AES-128 与 DES。
3. 更新系统信息、原始 WALK、接口 OID 与本地硬件等待状态，避免端点再次要求 community 或把 v3 报成 1/2c 错误；界面只提交设备 ID 和版本，不提交密钥。
4. 加入凭据合同、算法/安全级别、成功/失败/空字段路径的 mock 单测；运行相关 SNMP 和硬件采集测试及 PostgreSQL-only policy scan。

## 风险与回滚思路

v3 用户密钥只从已绑定凭据读取并仅用于运行时，不写日志或响应。v3 算法需限定为 transport 明确支持的值；不支持/缺失参数以安全、可诊断状态返回。当前数据模型允许的 AES/DES 隐私算法均由 puresnmp crypto 实现支持；SHA-2 认证使用本地 puresnmp plugin，避免因库内置仅有 MD5/SHA-1 而让已保存 profile 静默失效。回滚本次代码和文档即可恢复原 v1/v2c 行为，不涉及 schema 或设备配置。
