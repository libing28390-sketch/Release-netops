# 业务网段 IP 利用率

## 目标与现状
让 `/ipam/utilization` 默认呈现业务网段的 IP 容量与利用率，避免设备互联、Loopback、管理/网络基础设施、未分类网段干扰容量决策；保留切换全部网段的入口。

已证实现状：`GET /api/ipam/analytics` 不接受统计范围，所有卡片/Top 5/站点汇总/趋势复用同一响应。后端仅排除容器状态父网段、`/31` 和 `/32`，按长度判断仍会把常规掩码的 transit/wan 互联段计入。前端Prefix网段用途在 `network_type`，含 transit、p2p、wan、loopback、management、network_service、unclassified 等。

## 业务范围定义
按 IPAM `network_type` 白名单筛业务容量：`server`, `user`, `user_access`, `dmz`, `wireless`, `voice`, `storage`, `container`, `vpn`, `vip`。历史 `user` 和 `user_access` 都计业务；`transit`, `p2p`, `wan`, `loopback`, `management`, `network_service`, `unclassified`, 空值及未知值默认不纳入业务口径，但“全部网段”仍可查全量。容器类型网段仍遵守现有父网段不纳入可分配容量规则。

## 影响范围与文件归属
- `backend/services/ipam_service.py`：范围过滤发生在每项利用率、站点聚合、Top 5、overview及forecast计算前。
- `backend/api/ipam.py`：`/ipam/analytics?network_scope=business|all` 参数与响应范围标记。UI 显式请求 business；无参数维持现有全量 API 口径。
- `src/pages/IPVlan/IPUtilizationTab.tsx`：默认业务范围的切换，所有图表与指标依赖同一响应；业务模式替代全局Pool/VIP卡片显示所选范围空闲IP数。
- `backend/tests/test_ipam_capacity_and_reconciliation.py`、受影响的前端测试（如已有可复用）：验证业务、互联及“全部网段”聚合一致。

## 实施与验证
1. 在后端统一定义业务用途白名单，并在per-prefix构造之前按network_type筛选；对无效scope返回HTTP 422。
2. 保持每个聚合字段使用同一行集；趋势也按网段用途过滤。保留service旧的无参全量调用兼容，前端显式请求business。
3. 浏览器验证默认选中业务、切换全部后Top 5/概览/站点/趋势口径一致；窄屏保留可达的范围控制。
4. 运行最小后端 PostgreSQL IPAM 测试、IPAM前端相关测试、TypeScript检查及隔离输出构建。

## 风险与回滚
- 旧/未分类网段默认不在业务利用率内，业务模式应展示被排除网段数和切换全部入口，避免误认为数据丢失。
- 不依据掩码猜网段用途，不修改prefix的分类或数据库。回滚仅撤销本次代码与文档，不改历史数据。
