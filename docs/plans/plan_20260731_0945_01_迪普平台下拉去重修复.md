# 实施计划 - 资产录入/编辑平台下拉重复项消除与去重修复

## 1. 任务目标
解决资产管理弹窗（`/assets/dashboard`）选择迪普 (DPTech) 厂商后，操作系统/平台下拉框出现 4 个重复选项（`DPTech Conplat (Switch)` 和 `DPTech Conplat FW (Firewall)` 重复展示）的问题。

---

## 2. 根因分析
1. **定义去重缺失**：
   在 `src/pages/AssetManagement/constants.ts` 中，`VENDOR_PLATFORMS` 字典为了兼容大小写，同时注册了 `DPtech` 与 `DPTech` 两个属性。
2. **ALL_PLATFORMS 展开重复**：
   `ALL_PLATFORMS = [...Object.values(VENDOR_PLATFORMS).flat(), ...SERVER_PLATFORMS]` 直接扁平展开了 `VENDOR_PLATFORMS` 的所有数组，导致内部产生了 4 个相同 `value` 的平台对象。
3. **匹配与去重缺乏兜底**：
   `AssetModal.tsx` 中直接使用 `VENDOR_PLATFORMS[form.vendor] || ALL_PLATFORMS`，在降级或匹配回退时直接把带重复项的数组输出到了 `<select>` 节点的 `<option>` 中。

---

## 4. 实施步骤

1. **重构 `constants.ts` 平台字典与全局数组去重**：
   - 保持 `VENDOR_PLATFORMS` 的标准规范 key，统一厂商映射。
   - 实现全局 `getPlatformsForVendor(vendor)` 函数：支持不区分大小写和空格（`DPtech` / `DPTech` / `dptech` / `迪普`）精准匹配厂商平台，若未匹配则降级返回空/去重后的可用列表。
   - 对 `ALL_PLATFORMS` 增加按 `value` 严格去重的计算，确保绝对不会含有重复项。
2. **优化 `AssetModal.tsx` 下拉框渲染与防御去重**：
   - 使用 `getPlatformsForVendor(form.vendor)` 代替简单的硬编码 key 查找。
   - 对渲染到 `<option>` 的数组添加防御性按 `value` 去重处理。
