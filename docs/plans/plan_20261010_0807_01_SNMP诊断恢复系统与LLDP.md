# SNMP 诊断恢复系统信息与 LLDP

## 目标

让 `/monitor/snmp-walk` 首屏恢复清晰的 SNMP 系统信息和 LLDP 邻居视图，降低现有规则诊断界面的信息密度；继续禁止任意 OID 输入，只允许对当前用户有权访问的 CMDB 设备读取固定标准对象。

## 现状与问题

`5145245c` 将原有 SNMP WALK/系统信息视图替换为 LibreNMS 硬件规则探测，并把旧的系统信息与自定义 WALK API 停用。当前“系统识别”页签仍调用硬件规则接口，前端没有 LLDP 表格。当前工作树已有其他用户改动，本任务不触碰这些文件。

## 影响范围与文件边界

- 后端诊断端点：`backend/api/devices.py`；新增受设备 scope 校验的系统信息 + LLDP 诊断端点，使用绑定凭据和固定系统 OID。
- 后端采集：`backend/services/snmp_service.py`、`backend/services/topology_service.py`；诊断和拓扑的 LLDP walk 均传 `max_rows=None`，避免每个 MIB 列的 10,000 行默认值截断邻居。
- 拓扑读取：`backend/api/topology.py`、`backend/services/topology_graph_service.py`、`src/hooks/useTopology.ts`；页面默认不传 limit，links、nodes、edges、groups 和 members 均返回完整结果；显式传 limit 的其他调用继续兼容。
- SNMP 诊断前端：`src/pages/SnmpWalkPage.tsx`、`src/components/SnmpMib/components/LiveWalkInspector.tsx`；默认展示系统信息与 LLDP，现有硬件规则及已采样样本保留为次级视图，中英文文案同时维护。
- 主 Agent：负责接口契约、计划与交接记录、合并审查、构建/类型检查和最终说明。

## 实施步骤

1. 新增 `POST /api/platform-registry/snmp-system-lldp-test`，仅接受 `{device_id}`；校验现有租户/资源 scope，读取服务端绑定的 SNMPv1/v2c/v3 凭据。
2. 只读固定 MIB-2 系统标量，并调用标准 LLDP-MIB collector；诊断与拓扑采集路径均不设置 LLDP 邻居行数上限，超时继续作为 partial/failed 显示，不返回凭据或任意 OID 结果。
3. 前端把系统与 LLDP 设为默认视图，使用易读摘要和邻居表；将硬件规则 provenance 放在次级页签，保留原样本查看能力。
4. `/monitor/topology` 页面不再固定请求 5,000 条；对应后端 links/graph 查询在未指定 limit 时不加 SQL LIMIT，避免采集完整后又在图 API 阶段截断。
5. 审查接口/权限/错误状态和工作树，只运行适用的前端 lint、前端生产构建及后端语法编译，不运行测试套件。

## 验证计划

- `npm run lint`
- `npm run build` (the repository wrapper invokes Vite without forwarding `--outDir`; output is written to `dist/`)
- `python -m py_compile backend/api/devices.py backend/services/snmp_service.py backend/services/topology_service.py backend/api/topology.py backend/services/topology_graph_service.py`
- 检查 API 严格拒绝额外 body 字段，不接收 OID/凭据输入；确认 SNMPv3 继续使用绑定凭据。
- 检查诊断与拓扑 LLDP collector 显式传 `max_rows=None`；页面两个拓扑读取请求不传 limit，未限长的 SQL 路径覆盖 links、nodes、edges、groups 和 group members。
- 浏览器页面无法直接验证：用户给出的 HTTPS 地址当前触发 `ERR_CERT_AUTHORITY_INVALID`，按桌面浏览器策略不绕过证书警告。

## 风险与回滚

- 标准 LLDP MIB 可能被设备访问控制隐藏，或设备未开启 LLDP；此时必须显示“无数据/不支持/部分返回”，不能把空结果报成设备离线。
- 诊断和拓扑 LLDP walk 不设行数上限；慢响应仍可能因单列 walk 或单设备任务超时返回 partial/failed，不能把超时结果误报为完整快照。
- 拓扑页完整读取可能增加大型图的响应体和渲染开销；此行为遵循用户关于不截断 LLDP 数据的要求。
- 回滚时还原本任务涉及的诊断、拓扑服务/API 与前端文件；继续保留原有任意 OID 接口 410 关闭状态。
