# 网络总览设备吞吐单位标注计划

## 任务目标

让 01 网络总览中的“设备总流量 Top10”清楚表达指标是当前接口吞吐速率、采用 bit/s 单位，并确保 Grafana 表格数值带有可读单位。

## 现状与根因

- 面板查询对 `ifInOctets` 与 `ifOutOctets` 使用 5 分钟 `rate()`，求和后乘 8，计算的是每台设备所有接口入向加出向的近 5 分钟平均吞吐速率，单位为 bit/s；不是累计字节数。
- 生成器调用 `table_panel(..., unit="bps")` 时未传 `value_col_name`，因此单位 override 仍匹配默认列名“数值”。整理转换却把 Prometheus `Value` 列重命名为“总流量”，override 匹配失败，Grafana 只显示原始整数。

## 影响范围

- 仅修改 01 网络总览中设备吞吐 Top10 的标题、数值列名、说明与 Grafana 单位绑定。
- 不改变 PromQL、指标采样窗口、统计口径或其他 dashboard。

## 拟修改文件

- `monitoring/grafana/generate_dashboards.py`
- 生成文件 `monitoring/grafana/dashboards/nexora-network-overview.json`
- 本任务计划、walkthrough 与提交 fix 记录。

## 实施步骤

1. 已将面板标题改为“设备总吞吐速率 Top10”，数值列标明“总速率 (bit/s)”，说明入向和出向均为接口 5 分钟 rate 后按设备汇总。
2. 已将 `table_panel` 的 `value_col_name` 与组织转换后的列名设为同一值，确保 bps 格式化覆盖生效。
3. 已运行 dashboard 生成器并检查 Overview JSON；仅目标 Overview JSON 发生差异。

## 风险与回滚

- 数值为吞吐速率而非流量累计值；把入向和出向相加表示接口读数合计，不代表网络去重后的用户有效载荷。
- 当前 Grafana 浏览器会话曾返回 401，无法在线确认实际渲染；通过 Actions 后由用户同步服务器再检查。
- 若格式呈现不符合 Grafana 版本，可恢复该面板旧标题和字段设置并重新生成 JSON；不需要设备侧回滚。
