# 资产列表与导入模板回归修复计划

## 任务目标

修复今天提交后网络设备列表显示为空的问题，并恢复资产导入模板与导入校验之间的一致性，确保昨天成功使用的思科资产工作簿继续可用。

## 现状/问题

- `GET /api/devices` 已受全局鉴权保护，但网络设备页面的请求未发送 `Authorization`，收到 401 后被前端清空为 0 条。
- 新模板的资产示例与管理入口示例不一致，入口含不存在的 `NET-BJ-002`。
- 新模板删除了存量设备直接投产所需的免上收原因及部分凭据字段，且减少了厂商/平台相关校验。
- 英文模板的路径表头没有被导入解析器识别。

## 影响范围

网络设备列表、资产管理列表、资产导入模板下载、Excel 导入解析；不修改数据库数据，不重新导入用户文件。

## 拟修改文件与分工

- 主 Agent：维护本计划和走查记录，审查后端鉴权契约，负责最终集成、质量门禁及必要的后端错误处理；补齐告警维护页的设备查询鉴权。
- 前端执行者：仅修改 `src/hooks/useInventoryPageData.ts`、`src/hooks/useInventory.ts`、`src/pages/AssetManagement/index.tsx`、`src/pages/AssetManagement/importUtils.ts`、`src/pages/AssetManagement/importUtils.test.ts` 与模板生成相关文件；不修改后端或用户数据。
- 共享文件归属：`public/templates/asset_import_template.xlsx` 由主 Agent 根据前端模板定义重新生成并校验，避免与业务代码同时写入。

## 实施步骤

1. 为所有设备列表读取请求补充现有 `authHeaders()`，并让失败响应保留可见错误而不是伪装为空列表。
2. 统一静态模板和浏览器兜底模板的字段语义、示例资产与管理入口；静态下载文件保留昨天成功使用的 41 列格式，兜底模板额外保留可选 SSH 算法策略列；恢复必要的豁免原因、SNMP 凭据、厂商/平台字段和校验说明，补齐英文路径别名及 NETCONF 选项。
3. 增加旧模板和新模板解析/合并回归测试，覆盖成功、找不到资产、缺少豁免原因和英文路径。
4. 重新生成并检查静态 XLSX，确认下拉校验和示例可直接导入。

## 验证计划

- `npm run test:frontend -- --run src/pages/AssetManagement/importUtils.test.ts`
- `npm run lint`
- 相关后端资产导入测试及鉴权边界测试
- 浏览器确认 `/assets/network-devices` 显示设备、资产管理模板下载内容与解析器一致

## 风险与回滚思路

仅改请求头、模板内容和纯前端解析逻辑；不触碰生产数据。若验证失败，可按文件逐项回退本次改动，用户原有未提交文件和数据库记录不受影响。
