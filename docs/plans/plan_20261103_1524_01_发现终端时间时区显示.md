# 发现终端时间时区显示修正计划

## 目标

修正 `/ipam/endpoints` 最近观察时间直接截取 UTC 时间文本、导致页面显示比上海时间早 8 小时的问题。列表、详情和来源证据统一显示 Asia/Shanghai 时间，并让覆盖提示明确表达“范围/覆盖待核实”，避免被误读为同步延迟。

## 现状/问题

- 后端返回带 `+00:00` 的 ISO 时间，例如 `2026-11-03T06:46:31+00:00`。
- 列表格式化函数直接截取日期与小时，没有解析偏移量；详情和来源证据也直接显示源字符串。
- 本机和系统默认业务时区为 Asia/Shanghai，因此页面应显示 `2026-11-03 14:46`，详情可保留秒。
- 页面把 `coverage_status=partial` 显示为“部分来源待确认”。该状态实际由范围或完整采集代次未完全证明触发，不等同于投影延迟；最近一次 ARP 源观测 `06:46:31Z` 于 `06:47:05Z` 完成投影，样本间隔约 34 秒。

## 影响范围

- 仅发现终端页面的观测时间呈现；不修改数据库时间、API 时间、排序、过滤或 CSV 原始 ISO 时间。

## 拟修改文件

- `src/pages/IPVlan/DiscoveredEndpointsTab.tsx`
- `src/pages/IPVlan/ipamDiscoveryPresentation.ts`
- 本计划及对应 `docs/walkthrough/` 记录。

## 实施步骤

1. 将源时间解析为时间点；有时区的值尊重其偏移，无时区的旧值按项目约定的 Asia/Shanghai 解释。
2. 用显式 `Asia/Shanghai` 时区格式化列表、详情和来源证据时间；列表精确到分钟，详情保留秒。
3. 在时间列及详情标签标明北京时间/Asia/Shanghai，避免读者将显示值理解为 UTC。
4. 重写 partial/unavailable 覆盖状态文案；告警中显示待确认范围数量和最近源采集时间，不把覆盖置信度描述成同步延迟。

## 验证计划

- 代码审阅确认 UTC ISO 时间会转换为 Asia/Shanghai，时区缺省的旧值仍按上海时间解释。
- 按项目代码改动要求可运行前端静态检查与构建；不触碰线上实例，不改变源时间数据。

## 风险与回滚

- 只改变显示字符串，不写回数据；若格式不符合预期，回滚页面 formatter 和标签即可。
