# AC 无线看板与终端明细实施计划

## 目标
修复 03 无线专网监控中的 AC 统计和筛选范围，并让看板展示 AC 所辖 AP 的无线终端明细。

## 现状与证据
- 浏览器现场检查：看板显示 AP_12、AP_13；每台 AP 的关联客户端数为 2；SSID/BSS 面板显示暂无采集数据。
- 看板没有 AC 总数卡片；AP 表中的 `hostname` 值为 AC_11，却以“设备名称”展示。
- `make_network_variables()` 从全网 `up{job="network_snmp"}` 生成厂商、角色、设备选项，会带入交换机和防火墙。
- H3C 探针已从 Station Associate 表采集 MAC 索引、IP、SSID 等字段并保存在硬件传感器元数据中，但 Prometheus 输出不含逐终端明细，Grafana 因而无法查询。

## 影响范围与拟修改文件
- `monitoring/grafana/generate_dashboards.py`：无线专用筛选器、AC/AP 统计和终端表查询/展示。
- `backend/services/snmp_hardware_probe_service.py`：采集 Station AP Relation 表，关联终端到 AP。
- `backend/services/snmp_hardware_inventory_service.py`：输出有限字段的当前无线终端信息指标，不输出用户名。
- `backend/tests/monitoring/test_domestic_and_wireless_monitoring.py`、`backend/tests/monitoring/test_grafana_queries.py`、`backend/tests/snmp/test_h3c_wireless_station_probe.py`：回归断言。
- `monitoring/grafana/dashboards/nexora-network-wireless.json`：由生成器更新。
- `docs/plans/`、`docs/walkthrough/`、`docs/fixes/`：本次实施、验证和提交记录。

## 协作边界与接口
- 后端执行者只修改 H3C 探针、OID 目录、硬件指标渲染及 SNMP 回归测试，产出 `nexora_wireless_station_info`；主 Agent 负责 Grafana 生成器、V2 面板目录、监控测试、集成审查与发布。
- 共享指标标签契约为 `site_name,vendor,role,hostname,station_mac,station_ip,ap_name,ssid,radio_id,wlan_id,vlan_id`；每个当前在线终端值为 1，用户名不得成为 Prometheus 标签。
- 文档和 Git 提交由主 Agent 统一维护。执行者不得提交、推送或改写其他文件。

## 实施步骤
1. 为无线看板建立只读取无线控制器目标的站点、厂商、角色和 AC 筛选器；选择 AC 后据其设备标签筛出所辖 AP。
2. 新增纳管 AC 与在线 AC 统计，并让 AC 选择过滤其 AP、Radio、BSS/SSID 和终端明细。
3. 修正 AP 表中的 AC 标签；为 H3C Station Associate 记录补充 AP 关系，再以 MAC、IP、SSID、AP、Radio、WLAN ID 生成可筛选的当前客户端明细，不暴露用户名。
4. 用生成器更新看板 JSON，运行无线查询、采集器和 JSON 相关测试，检查差异仅落在授权范围。
5. 生成 walkthrough 和 fix 记录，提交到 `main` 并推送。

## 验证计划
- H3C 无线 Station 探针和硬件指标渲染测试。
- 无线 Dashboard 变量、AC/AP 过滤、客户端明细查询测试。
- Grafana dashboard 生成、全部 JSON 解析、`git diff --check`。
- 推送前核对工作区状态、提交基线和提交差异，保留已有用户修改及未跟踪目录。

## 风险与回滚
- MAC/IP 属于终端识别信息；新指标仅输出看板所需字段，不输出用户名。若模拟器不提供 Station AP Relation 表，终端仍可列出 MAC/IP/SSID，但 AP 列可能为空；不能伪造归属。
- 回滚通过撤销本次提交并重新运行 dashboard generator；不修改数据库结构、生产 AC 配置或运行中的 Grafana。
