# 配置备份统计口径与对象存储说明计划

## 任务目标
修正配置备份批次、按 Site 展示及 `/configs/backup-stats` 今日统计的设备总数和成功率：服务器不进入网络设备统计分母；核对并列出代码中的厂商备份命令；将 S3 对象存储状态卡片改为清楚说明连接检查、数据范围和各项计数含义。

## 现状/问题
计划执行加载策略范围内的所有在线设备，再把服务器或不支持已验证备份动作的设备记为 `skipped`。`_finish_backup_run`、Site 汇总和前端成功率把所有账本行计入总数；服务器会造成成功率偏低。对象存储卡片使用 `Spool`、`Legacy` 等技术词，未说明待处理项、旧路径及其状态范围；后端连接检查通过 S3 `ListObjectsV2` 实现。

## 影响范围
配置备份批次目标筛选、历史批次/Site 统计接口、今日汇总与 `/config/backup` 对象存储状态卡片。备份连接、对象存储配置和数据迁移不在变更范围。

- `src/pages/ConfigBackupTab.tsx`

- `docs/walkthrough/walkthrough_20260926_1935_01_配置备份统计口径.md`

## 实施步骤
1. 追踪计划备份、账本创建、历史批次详情、Site 汇总和统计展示的完整链路。
2. 在备份账本创建前排除服务器资产，并确保历史批次、详情、Site 汇总和今日统计使用相同的非服务器范围。
3. 核对平台注册表与备份服务实际使用的内置运行/启动配置命令；区分内置默认命令与依赖已发布配置档的动态命令。
4. 在页面说明 S3 桶连通检查的边界、统计覆盖范围，并给各项存储状态数值补上通俗解释。
5. 检查代码差异并完成静态/前端验证，在走查文档记录验证限制与命令清单。

## 验证计划
运行配置备份统计混合资产回归用例与相关平台/命令聚焦测试；检查 Python 语法、PostgreSQL-only 策略和差异；前端修改后运行 `npm run lint` 与隔离输出目录的生产构建。测试只使用命名明确的本地 PostgreSQL 隔离库。

## 风险与回滚思路
服务器筛选依赖资产类型或可识别的网络身份；未关联或分类错误的数据仍可能被误分。历史计数按现有设备资产关联即时重算，资产分类变更会影响旧批次展示。对象状态数字涵盖配置备份与 PAM 录屏，文案会清楚标出范围。回滚时恢复批次筛选/统计查询和页面文案，不触碰已采集配置或 S3 对象。
