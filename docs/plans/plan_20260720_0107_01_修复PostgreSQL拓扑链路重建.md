# 修复 PostgreSQL 拓扑链路重建

## 任务目标

修复 Docker/PostgreSQL 环境中 LLDP/CDP 采集和设备匹配成功，但 `topology_links` 始终为 0 的问题。

## 当前问题

- 设备采集成功，邻居观察记录能够写入 `topology_observations`。
- `topology_service._rebuild_links_from_observations_unlocked` 查询 `interfaces.name_display`。
- 旧版生产数据库的 `interfaces` 表缺少 `name_raw`、`name_display` 等接口模型字段，链路重建异常回滚，前端只能显示设备节点。

## 拟修改文件

- `backend/database/schema.py`：补齐新库和旧库启动时的接口字段。
- `backend/database/migrations/m0023_interface_identity_fields.py`：为现有 PostgreSQL 数据库执行幂等迁移并回填接口显示名称。

## 实施步骤

1. 增加接口身份、显示、三层属性和聚合兼容字段。
2. 将历史 `interface_name` 回填到 `name_raw` 和 `name_display`。
3. 启动服务自动执行迁移，不删除 PostgreSQL 数据卷。
4. 手动触发一次拓扑发现，确认 `managed_links` 大于 0。

## 验证计划

- Python 编译检查。
- Schema migration 测试。
- 拓扑服务回归测试。
- Docker 启动后检查 `/api/topology/generation-status`。

## 风险与回滚

- 迁移只新增可空/带默认值字段并执行幂等回填，不删除用户数据。
- 如需回滚代码，可回退应用版本；新增字段保留不会影响旧代码。
- 不得使用 `docker compose down -v`，避免删除 PostgreSQL 数据卷。
