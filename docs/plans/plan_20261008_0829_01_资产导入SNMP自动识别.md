# 资产导入 SNMP 自动识别实施计划

## 任务目标

资产导入时使用管理 IP 和已绑定的 SNMP 凭据读取设备身份，通过 Nexora 内置的 LibreNMS OS 识别规则解析厂商/平台，并在唯一、兼容且包含可用 CPU/内存指标的 Profile 时自动绑定。支持 SNMPv2c 和 SNMPv3（当前项目存储的 MD5/SHA、AES/DES、无认证/无加密组合）；不支持的 v3 算法或 context 明确回报，不回退到空凭据。探测失败、规则无匹配或存在歧义时保留资产导入结果，不猜测、不覆盖用户显式填写的身份，并返回可见状态。该流程不要求每台设备配置 LibreNMS 实例；外部/可选 LibreNMS 原生采集运行时属于另一条数据采集链路。

## 现状与问题

当前资产导入校验并保存已选择的 SNMP 凭据，然后可尝试向已配置的 LibreNMS 实例纳管设备；导入路径本身没有执行 SNMP 设备身份探测或 SNMP 指标 Profile 自动绑定。已有设备识别入口可调用 LibreNMS 规则，但不在导入流程中；指标 Profile 有唯一候选解析器，但未由导入调用。

## 影响范围

- 资产导入后的网络设备身份识别与指标 Profile 绑定。
- 导入 API 每行识别状态及前端导入结果提示。
- 既有 LibreNMS 纳管、SNMP 主机名同步及凭据脱敏行为。

## 拟修改文件

- `backend/services/snmp_service.py`、`backend/services/snmp_import_identification_service.py`：实现 v2c/v3 只读身份探测、规则解析、唯一候选 Profile 绑定与安全状态返回。
- `backend/api/assets.py`：在事务提交后并发受限地调用识别服务并把每行结果映射到导入响应。
- `src/pages/AssetManagement/index.tsx`：展示自动识别/匹配结果及未匹配、歧义、探测失败等可操作状态。
- `backend/requirements.txt`：声明 SNMPv3 AES/DES privacy plugin。
- `backend/tests/configuration/test_asset_management_method_import.py` 及 SNMP 自动识别 focused tests。
- `docs/walkthrough/walkthrough_20261008_0829_01_资产导入SNMP自动识别.md`：集成后记录变更与验证。

## 实施步骤

1. 复用现有凭据加密、LibreNMS 本地规则 resolver 和指标 Profile resolver；为导入增加 v2c/v3 scalar GET 能力及 AES/DES 插件依赖。
2. 提交资产后并发受限地读取 `sysObjectID/sysDescr/sysName`，不记录明文凭据；只填充空白的识别字段，不覆盖用户显式字段。
3. 仅在厂商身份无冲突、Profile 唯一兼容、Profile 可用且含 CPU/内存定义时自动绑定；无匹配/歧义/未验证/不支持 v3 时不绑定并回传状态。
4. 保留现有 LibreNMS 纳管及 SNMP 主机名同步行为；身份探测故障不影响已成功导入资产。
5. 补充自动绑定、缺少凭据、冲突/歧义、v3 传输及脱敏回归测试，更新前端结果提示。
6. 运行聚焦 pytest、前端 lint 及 diff 检查，创建 walkthrough。

## 验证计划

- 运行资产导入相关配置测试与 SNMP 识别、指标 Profile 匹配测试。
- 使用 mock SNMP 和本地 PostgreSQL fixture；不依赖真实设备或外网。
- 若更新前端，运行 `npm run lint` 和受影响的前端构建/测试。
- 检查 `git diff --check`、凭据日志/响应脱敏和 API 每行状态契约。

## 风险与回滚

错误识别可能激活错误 OID，因此只接受唯一兼容且已验证、同时包含 CPU/内存定义的 Profile；未验证或不完整模板不自动绑定。只填充空白识别字段，探测失败不影响资产保存。回滚时移除导入后识别调用及 UI 状态，保留已经写入的资产数据和用户原始身份；解绑误绑定的 Profile 可清空相应 `snmp_metric_profile_id`。

## Agent 分工

主 Agent 负责方案、所有代码修改、接口契约、测试集成与最终审查。两个 Luna Explorer 只读审计导入/规则调用链与 SNMP 凭据探测能力，不修改文件。
