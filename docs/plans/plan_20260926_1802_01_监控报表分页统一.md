# 计划：统一监控报表分页行为

## 目标

统一 `/monitor/reports/interfaces`、`/devices`、`/outbound` 三个报表的默认每页条数和用户看到的分页选项。

## 现状与问题

三个子路由复用 `MonitoringReportsPage`，数据切片本身正确，但页面状态默认 25 条，顶部选择器提供 10/25/50/100，底部共享分页器提供 10/20/50/100。默认值 25 不在底部分页器选项中，两个选择器也会造成用户看到的条数设置冲突。

## 影响范围

- 监控报表的接口、设备、出口三类表格。
- 仅前端客户端分页控件和对应组件测试；不修改 API 分页契约。

## 拟修改文件

- `src/pages/MonitoringReportsPage.tsx`
- `src/pages/MonitoringReportsPage.test.tsx`
- `docs/plans/plan_20260926_1802_01_监控报表分页统一.md`
- `docs/walkthrough/walkthrough_20260926_1802_01_监控报表分页统一.md`
- 如需提交，增加新的 `docs/fixes/fix_*.md` 修复记录。

## 实施步骤

1. 已将默认每页条数设为 20，与共享分页器选项一致。
2. 已移除表格顶部重复的每页条数选择器，只保留底部分页器控制。
3. 已为三个报表子路由分别构造 21 条记录，验证初次显示 20 条、翻页后显示余下 1 条，且页面大小显示为 20。

## 风险与回滚思路

变更只涉及复用页面的客户端页大小初始值和重复控件；筛选、排序、查询接口及数据集保持不变。若结果不符，可单独回滚该页面和测试文件，无需后端或数据库回滚。
