# GitHub Actions YunShan 测试收集失败修正计划

## 任务目标

修复 `main` 上最新 Actions 运行在 pytest collection 阶段失败的问题，验证受影响的 YunShan 测试文件，并以一个最终修正提交推送到 `main`。

## 现状与问题

- GitHub Actions run `37410521721`（Release Ubuntu / Linux）在全量 pytest collection 时报告两个 `SyntaxError: unexpected character after line continuation character`。
- 失败位置分别是 `backend/tests/database/test_m0275_huawei_yunshan_platform.py:173` 和 `backend/tests/platform_registry/test_huawei_yunshan_platform.py:123`。
- 两个文件末尾多出了两个非换行字符（反斜杠和字母 n）；上一轮空白清理命令误把换行转义写成文本。
- 当前 `main` 与 `origin/main` 同步；用户本地 skill 修改及构建目录仍在工作区，需要保留。

## 影响范围

只修复两个新增加的 YunShan 测试文件 EOF 字节，并添加本次计划、走查与逐提交修复记录。

## 拟修改文件

- `backend/tests/database/test_m0275_huawei_yunshan_platform.py`
- `backend/tests/platform_registry/test_huawei_yunshan_platform.py`
- `docs/plans/plan_20261006_1154_01_CI测试文件收集失败.md`
- 对应 walkthrough 与 `docs/fixes/fix_*.md`

## 实施步骤

1. 检查两个文件的末尾字节并移除字面量反斜杠-n，保留标准单个换行符。
2. 运行语法编译与两个文件的 pytest collection，再按测试依赖安全运行聚焦测试。
3. 检查 diff 和空白差异；记录实际验证结果。
4. 将修复、计划/走查和 fix 记录作为一个修正提交推送到 `main`，不重写已推送历史、不创建分支。
5. 检查本地与远端 `main` 同步状态。

## 验证计划

- Python `py_compile` 检查两个文件。
- pytest 仅对受影响的两个文件执行 collection，确认不再有语法错误。
- 如使用持久化测试，必须经项目隔离 PostgreSQL 源库运行器，不接触应用数据库；同步运行 PostgreSQL-only 策略检查。
- `git diff --check`、暂存区核对、提交后远端指针比对。

## 风险与回滚

- 修复仅改变文件结尾的两个非法字节，不改变测试断言或业务代码。
- 如果测试未通过，保留失败证据并在推送前继续定位。
- 若推送后需要撤销，新增 `git revert` 提交；不 reset、不强推。保留 `.agents/` 用户改动和构建产物。
