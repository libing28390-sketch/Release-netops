# 资产设备数量同步实施计划

## 任务目标

让资产管理、操作工作台和侧栏“运营总览”对网络设备与服务器使用同一总数口径，并在资产变更后及时刷新；工作台保留按当前搜索、类别和树节点筛选的操作设备数。

## 现状与问题

- 资产管理从 `/api/assets/summary` 的 `by_type.network_device + by_type.server` 得到总数。
- 运营总览读取 `inventoryStore.assetsTotal`，但当前只定义了汇总请求，没有调用点，初始值为 0 后回退为 `/api/devices` 的列表长度。
- 工作台统计当前筛选后的 `devices` 数组；旧的无分页请求在后端最多返回 200 行，且不返回实际总数，因此页面显示 200 时无法判断实际设备行数是否更多。未关联 `devices` 行的 `physical_assets` 也不会出现在操作列表中。
- 首轮修复新增了台账总数卡片，但工作台仍使用无分页 `/api/devices` 的 200 行结果，运营总览在线节点仍以 `devices.length` 为分母；用户截图显示台账 221、工作台/总览 199/200，但当时无法区分 200 安全上限与真实关联差异。

## 影响范围与拟修改文件

- `src/store/inventoryStore.ts`、`src/store/inventoryStore.test.ts`：统一设备总数口径、加载/错误状态及过期请求保护。
- `src/components/AppMainContent.tsx`：登录期间加载并定期刷新共享汇总，账号变化或登出时清空旧租户数据。
- `src/pages/AssetManagement/index.tsx`：本页刷新 summary 后同步共享总数，使新增、编辑、导入、删除等现有刷新路径即时更新其他页面。
- `src/pages/DashboardTab.tsx`、`src/pages/AccessCenterTab.tsx`：显示共享设备总数，保留工作台筛选后的当前节点数量并明确两种口径。
- `src/App.tsx`、`src/hooks/useInventory.ts`：操作工作台切换到轻量分页拉取，完整读取设备列表而不触发后端默认 200 行安全上限。
- `src/utils/assetSummary.ts`、`src/store/inventoryStore.ts`、`src/pages/DashboardTab.tsx`：共享台账在线状态汇总，运营总览在线设备分子与总数分母采用同一份资产汇总。
- 若组件回归测试需要，将为受影响页面增加局部测试文件；完成报告写入 `docs/walkthrough/`。

## 风险与回滚思路

- 汇总 API 失败时保留上次成功值；首次失败显示不可用状态，不用截断列表长度伪装全局总数。
- 请求带取消信号与递增请求序号，避免切换用户、卸载或慢请求造成跨租户旧值回写。
- 新建和导入的网络设备/服务器会自动创建关联 `devices` 记录；更新旧资产时若无关联设备，当前同步 helper 会直接跳过。台账从 `physical_assets` 汇总，工作台从 `devices` 列表取数。部署分页实现后，若设备 API 实际总数仍小于台账总数，再按权限范围和关联关系做只读核对；本任务不修改数据库或创建没有凭据的操作设备。
- 回滚仅撤销本计划列出的前端行为与测试，不触碰工作区其他已有改动。
