# CMDB 页面去除手动刷新与接口采集完成态收起计划

> 创建时间：2026-10-13 08:17（Asia/Shanghai）
> 范围：移除 CMDB 侧栏页面的手动刷新按钮；/cmdb/interfaces 采集终态后收起进度卡片

## 1. 目标

移除 CMDB 侧栏下所有页面的手动刷新按钮，涵盖 `/cmdb/credentials`、`/cmdb/racks`、`/cmdb/assets`、`/cmdb/resources`、`/cmdb/devices`、`/cmdb/interfaces`、`/cmdb/sites`、`/cmdb/vrfs`、`/cmdb/vlans`、`/cmdb/vlan-business` 和 `/cmdb/tenants`。接口骨架采集运行时保留任务进度卡片；任务进入成功、部分失败、失败、取消、超时或其他已识别完成状态后，清除进度卡片并显示一条简洁的成功/失败计数摘要。完成后不再轮询已结束任务。保留接口采集、查询/筛选触发加载、提交/导入后的数据刷新、运行中 spinner 和失败重试按钮。

## 2. 现状与影响范围

页面位于 `src/pages/CmdbManagementTab.tsx`、`src/pages/CmdbAssetManagementTab.tsx`、`src/pages/CmdbResourceSearchTab.tsx` 与 `src/pages/RackManagement/index.tsx`。采集结果存入 `interfaceJobStatus`，`useEffect` 每 2 秒轮询；terminal 状态当前停止 loading 并刷新列表，但没有清空 `interfaceJobStatus`，因此进度卡片仍然渲染。CMDB 使用的四个页面组件各有显式手动刷新入口；移除后，其它业务按钮和自动加载机制保持不变。

拟修改文件：上述四个页面组件与配套任务 walkthrough。此项复用前端现有任务与授权契约，不改后端 API、CMDB/接口数据、其他产品模块的刷新控件。

## 3. 实施步骤

1. 检查 terminal 状态识别与 jobId 轮询清理路径，保持 queued/running 时进度卡片继续可见。
2. terminal 状态处理时输出成功/失败计数摘要、清空进度状态、停止轮询并刷新接口目录；已处理的 Job 不重复提示。
3. 移除 CMDB 共用页头、资产目录、资源检索和机柜页的手动刷新控件；不移除运行中状态图标及其它流程里的重试动作。
4. 检查 JSX/依赖与差异，运行 `npm run lint` 做 TypeScript 检查；本次不运行测试，也不运行会覆盖现有 `dist/` 的生产构建。

## 4. 验收与风险

- 采集中显示进度与异常；轮询完成后卡片收起，列表更新，出现简洁终态摘要。
- 失败/部分失败/取消/timeout 等终态也会收起卡片并停止轮询；重新开始新任务后新进度正常出现。
- CMDB 侧栏列出的所有页面无手动刷新按钮；查询/筛选、显式采集和写入后的自动刷新仍工作。
- 接口页无页头 Refresh，立即采集按钮仍可用；其它产品区域刷新不变。
- 本次仅改变展示状态；后端 Job 仍保留于持久化记录中。
- 不新增/运行测试；适用的 frontend lint/build 是静态/集成检查。
- 回滚只需恢复页面组件；没有数据库或后端状态迁移。
