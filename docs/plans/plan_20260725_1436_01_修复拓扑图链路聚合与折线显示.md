# Implementation Plan - 修复拓扑图链路聚合与折线显示

本实施计划旨在解决拓扑图展示中的两个问题：
1. **链路折线（正交路由）混淆**：当节点间以折线连接时，交叉和重叠容易误导用户（如图二中看似有连接的 T 型交叉，但实际上是独立的点对点物理链路）。我们将支持“直连线 (Straight Line)”与“折线 (Orthogonal Line)”两种路由模式切换，并将“直连线”作为默认值。
2. **链路聚合未展示**：H3C (Comware 7) 和 Huawei (VRP) 设备间的链路聚合（LAG/Route-Aggregation/Eth-Trunk）没有在拓扑图上合并。这是因为缺少 TextFSM 兼容平台映射、物理端口/逻辑聚合接口在规范化名称时没有完全对齐导致的。我们将修正 Compatible Platforms 映射、优化接口规范化逻辑以及拓扑前端展示缩写。

## User Review Required

> [!IMPORTANT]
> 1. 本次修改涉及后端平台兼容映射 `_COMPATIBLE_PLATFORMS` 和接口规范化 `INTERFACE_ALIASES`，这些都是只读解析和匹配的通用核心库。所有改变均向后兼容，不影响现有的数据库数据结构。
> 2. 前端将在拓扑图工具栏中新增“路由”选择框（支持 Straight line 和 Orthogonal line），并使用本地 LocalStorage 和后端数据库进行布局同步保存，默认使用 Straight line。

## Proposed Changes

#### [MODIFY] [textfsm.py](file:///d:/netops/netsops-main/backend/core/textfsm.py)
- 在 `_COMPATIBLE_PLATFORMS` 中，添加/更新对 H3C Comware 7 / Comware 5 / Huawei VRP 设备的 TextFSM 兼容映射，使其在获取 `eth_trunk` 类别（如运行 `display link-aggregation verbose` 或 `display eth-trunk`）时能分别回退并复用 `h3c_comware9_display_link_aggregation_verbose.textfsm` 和 `huawei_vrpv8_display_eth_trunk.textfsm`：
  - `'huawei_vrp'` 的兼容列表增加 `'huawei_vrpv8'`
  - `'h3c_comware'` 的兼容列表增加 `'h3c_comware9'`
  - `'hp_comware'` 的兼容列表增加 `'h3c_comware9'`

#### [MODIFY] [interface_utils.py](file:///d:/netops/netsops-main/backend/core/interface_utils.py)
- 在 `INTERFACE_ALIASES` 列表内加入 `("route-aggregation", "ragg")` 的映射，确保类似 `Route-Aggregation34` 或 `Route-Aggregation1` 能统一被规范化为 `ragg34` 或 `ragg1`，从而在拓扑链路重构匹配中与 `RAGG34` / `RAGG1` 完全对齐。

### 前端拓扑渲染层 (Frontend Rendering)

#### [MODIFY] [TopologyGraph.tsx](file:///d:/netops/netsops-main/src/components/TopologyGraph.tsx)
- 在 `PersistedTopologyLayout` 类型定义中，加入可选的 `routingMode?: 'straight' | 'orthogonal'` 字段。
- 在 `TopologyGraph` 组件内，新增 `routingMode` 的 state，默认值为 `'straight'`。
- 支持在 `readPersistedLayout` / `persistCurrentLayout` 以及从后端 API 获取布局的过程中读写 `routingMode`。
- 实现 `getStraightRoute` 辅助函数，它在给定 `source`、`target` 坐标和 `offset` 的情况下直接计算出直连线 `path` 以及标签的中心坐标，功能与 `getOrthogonalRoute` 相当但没有折角。
- 在 `renderGraph` 内部计算 `link`、`linkHitArea` 和 `linkLabelGroup` 时，根据当前的 `routingMode` 动态选择调用 `getStraightRoute` 或 `getOrthogonalRoute`。
- 增强 `abbreviateInterface`，对以 `Bridge-Aggregation` 或 `Route-Aggregation` 开头的接口缩写为 `BAGG` 或 `RAGG` 前缀，使其在拓扑图上展示时更美白紧凑。
- 在工具栏（右上方 select 行）中添加“路由”选择下拉框，绑定 `routingMode` 和切换方法。
