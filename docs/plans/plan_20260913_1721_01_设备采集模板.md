# 设备采集模板实施计划

## 目标

将 NSOT 当前逐项采集开关简化为逐设备采集模板，并确保模板对 NSOT 后台同步的实际采集路径生效。Automation 继续负责触发时间/周期，不成为设备长期采集策略的第二个来源。

## 现状 / 问题

- NSOT 策略当前把每个 collector 都显示为开关，用户需要自行理解 ARP、MAC、LLDP、RIB、动态协议等区别。
- 策略保存在 `devices.collection_policy_json`，但 unified NSOT 流程对 ARP、路由、接口状态、VLAN、Prefix 等存在不同程度的绕过或部分执行。
- 设备角色值存在别名/展示名称与策略判断不一致；角色默认策略不能代替设备真实 L2/L3 职责。
- 工作区已有用户改动，尤其 `src/pages/IPLocatorPage.tsx`，必须保留，仅在现有变更上做局部增量。

## 影响范围

- NSOT 页面：按设备显示/保存简化模板；高级自定义时保留现有 collector overrides。
- NSOT 单设备策略弹窗只提供精确 IP 查询并呈现该设备策略，不加载完整设备清单；批量套用和周期只在 Automation 操作。
- 后端策略 API/service：模板解析、默认值、角色别名规范化、显式设备覆盖优先。
- NSOT unified collection：使 ARP、MAC/终端定位、路由/协议、LLDP/接口/VLAN、Prefix 等路径遵守有效模板；定时作业保存的 device_scope/filter 必须解析为同一目标设备集合并传入每个采集阶段；实时用户发起查询的既有例外须保持明确。
- 不增加数据库列；继续使用 `collection_policy_json`，便于旧记录保持兼容。
- 为精确 IP 查找建立 `devices.ip_address` 普通索引（migration + fresh-install baseline alignment）；不改变存量数据或 IP 唯一性，索引可回滚删除。
- Automation 继续负责 NSOT 作业执行/调度；`device_scope/device_filter` 解析后传入统一 NSOT 采集任务，不在 JobModal 重复实现 collector 规则。
- Automation 增加一个批量套用/恢复模板的轻任务入口：按站点、角色、设备类型、平台的交集筛选；先预览设备数量和样例，再确认应用。服务端还必须叠加当前用户的 tenant/site 资源授权，不能把业务筛选值当作权限边界。实际策略写入复用 `collection_policy_json` 与同一模板 service；不新建/删除设备。
- 执行周期不存进单设备模板：模板说明“采什么”，NSOT 调度作业说明“何时采”。每个设备组建立一个 NSOT 作业即可配置其周期；不同组建不同作业。Automation 只选择范围、Cron 并调用统一 NSOT 任务，不复制采集规则。

## 模板与 API 契约

- 模板 ID：`role_default`、`basic`、`layer2_switch`、`layer3_gateway`、`firewall`、`wireless`、`custom`。
- 存储格式：`{"template":"layer2_switch","collectors":{...device_overrides}}`。
- 有模板时：模板默认值覆盖角色默认值；单设备 `collectors` 显式覆盖优先。切换预设模板清除旧 collector overrides；恢复默认清除模板及覆盖，回到角色默认。
- `custom` 使用角色默认值作为起点，逐项 collector overrides 仍可用。
- 动态路由采用证据驱动：模板不把未配置协议视为必须采集；显式关闭是硬停止。
- L2 模板开启接口/基础监控、LLDP、MAC、VLAN 和终端定位；关闭 ARP、RIB 与动态协议。ARP 应在实际 L3 网关设备采集。
- L3/网关及防火墙模板启用适用的 ARP/RIB；协议按设备证据自动发现。平台不支持的命令不得因模板而强行执行。
- 无线模板 v1 仅承诺现有通用健康、接口和 LLDP 数据，不声称采集尚不存在的无线客户端/射频专用指标。
- 批量写入只接受命名预设模板或“恢复角色默认”；必须提供至少一个目标过滤条件，预览后使用绑定操作和模板的匹配摘要校验目标集未变化再写入；写入原子化、审计，并显式提示会清除设备级 collector overrides。
- Administrator 可按全局目标运行；非管理员必须有 tenant，且业务候选集再与 `asset:update` 的 tenant/site 资源范围取交集。读取的 options 使用 `asset:view` 范围，tenant-less Administrator 仍保持全局管理能力。
- 周期语义为“一个 NSOT 作业 = 一个设备范围 + 一个 Cron + 统一采集任务”；不创建每设备任务，也不在 v1 为每项指标配置独立 Cron。
- 单设备模板查找 API 接受单个 IPv4/IPv6 地址，优先使用参数化等值查询命中 `devices.ip_address` 索引；IPv6 还要校验 PostgreSQL inet 规范化结果，以识别压缩/展开文本不同但地址相同的重复设备。按当前 tenant/site `asset:view` 范围查找并仅返回单台设备摘要与策略；无匹配用可读空态，多个同 IP 匹配提示冲突，不返回或加载全设备列表。按设备 ID 的兼容性读写 API 同样叠加 tenant/site `asset:view` 或 `asset:update` 范围，避免绕过 IP 查找接口越权访问。输入/查询不会改动策略，提交已有模板操作仍由用户主动触发。
- Automation 批量设备组中的站点选项显示 CMDB `site_name`/`site_code`，内部筛选值仍按设备站点键匹配，避免把 site UUID 当用户可读名称。

## 拟修改文件与分工

- 主 Agent：`backend/services/scheduler_service.py`、`backend/services/ip_locator_service.py`、`backend/services/interface_collection_service.py`、NSOT scope 测试和整合复核；保留现有用户改动。
- Backend worker：只负责 `backend/services/collection_plan_service.py`、`backend/api/collection_plans.py` 与批量策略 API 测试；按本计划契约实现服务端 preview/apply，不触碰前端或 scheduler。
- Backend worker（本轮追加）：负责精确 IP 单设备查询 API 与 PostgreSQL 测试；保留现有 bulk options/preview/apply API，并补充批量站点 option 的 CMDB 友好显示标签。
- Frontend worker（本轮追加）：负责 NSOT 模板弹窗的 IP 查询空态/结果/错误交互，删除全量列表依赖，保留原有模板和缓存改动；批量操作仍留在 Automation。
- 主 Agent 维护计划/walkthrough，整合后执行共享质量门禁；两位执行者不继续创建子 Agent。

## 实施步骤

1. 实现兼容旧 JSON 的模板解析和角色别名规范化；增加逐模板和显式覆盖测试。
2. 在 NSOT 策略模态中提供简洁模板下拉框；选 `custom` 时显示现有高级开关；显示每设备当前模板及自定义状态。
3. 将 unified NSOT 的采集阶段统一按有效策略筛选，确保关闭项不再发出该类设备查询；保持 IP 定位中为完成用户请求而执行的实时查询行为清晰隔离。
4. 为纯 L2 交换机与上联网关的组合增加回归测试：L2 设备采 MAC/VLAN/LLDP，不采 ARP/RIB/路由协议；网关负责 ARP/RIB。
5. 将定时作业保存的范围解析到目标设备 ID，并把同一目标集合传给 ARP、终端定位、路由/协议、拓扑、接口状态和 Prefix 阶段；空范围不运行全量回退。复合筛选损坏、空白或含未知字段时也按零目标处理，表单要求至少选一个条件。
6. 对 scoped 终端投影和持久化做范围保护，避免标记范围外事实失效；增加目标范围与 scoped NSOT runner 回归测试。
7. 在 Automation 增加批量模板预览、确认、应用/恢复入口；后端对目标集合做同条件复算与事务写入，避免全量设备前端加载和预览后目标漂移。
8. 使 NSOT Cron 的目标设备解析与 Automation 批量范围共用一致的字段语义；每个范围+Cron 调用同一个 unified NSOT runner，设备模板继续由 NSOT 服务读取。
9. 把 NSOT 单设备模板弹窗改为“输入 IP → 查找策略”的直达流程；结果仅显示匹配设备与策略，不首屏加载设备清单、不提供重复的批量控制。重复 IP/无匹配/无权限/无效输入有明确状态；设备 ID 兼容 API 也必须应用相同 tenant/site 授权。
10. 运行后端窄测试、前端 lint/build 和相关契约检查，使用已登录 UI 会话验证 NSOT 单设备目录、批量模板预览和 NSOT 作业范围/Cron 展示；不连接真实网络设备。

## 暂缓的后续范围

- 不同采集指标的独立周期（如 ARP 5 分钟、LLDP 每日）暂不拆成独立作业；v1 周期以 NSOT 统一任务为单位，避免多套调度重复连接设备。
- 未来新增“命名设备组/动态组”可以避免批量操作和 Cron 作业重复定义筛选条件；v1 使用当前站点/角色/设备类型/平台精确过滤，并允许分别创建多个 NSOT Cron 作业。

## 验证计划

- Run the focused template/runtime/API/topology suite including `backend/tests/vendor_audit/test_collection_plan_bulk_api.py`; use disposable PostgreSQL source and per-test databases for tests that load `backend/tests/conftest.py`.
- Run `backend/tests/scheduled_jobs/test_nsot_scope_execution.py` and the `scheduled_nsot_stores_partial_when_topology_summary_is_incomplete` case with the same isolated PostgreSQL fixture; never let the session bootstrap point at the protected developer `netops` database.
- 增加/运行接口采集与 NSOT collector policy 的窄测试。
- 批量策略 API 测试覆盖：无筛选拒绝、过滤交集、预览/apply 摘要漂移拒绝、清除 overrides、事务失败不部分落库、0 命中无写入。
- 单设备 IP 查询 API 测试覆盖：精确 IPv4/IPv6 匹配、等价 IPv6 文本重复、无匹配、非法 IP、多匹配、tenant/site scope和无权限；按设备 ID 的列表/详情/更新/重置 API 覆盖租户/站点隔离。Automation bulk site option 保持 CMDB 友好标签并测试 filter value 与调度器 site fallback 一致。
- Automation 前端校验：至少一个筛选条件、预览加载/错误/空态、变更确认及服务器总量显示。
- `npm run lint`
- `npm run build`（需保留现有构建产物时使用隔离输出目录）。
- 静态检查改动 diff；不连接真实网络设备，不操作用户生产环境。

## 风险与回滚

- 旧策略 JSON 必须解析为 `role_default`，不得丢弃现有显式 collector overrides。
- 切换模板清除旧设备覆盖，UI需明确提示；选择“自定义”可重新逐项调整。
- 模板只控制未来采集，不删除既有事实数据。
- 若部署后行为异常，可在 NSOT 策略中恢复“按角色默认”并回滚本次代码；JSON 格式向后兼容，不需数据迁移。
