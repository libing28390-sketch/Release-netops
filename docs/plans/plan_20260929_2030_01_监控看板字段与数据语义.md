# 监控看板字段与数据语义

## 目标

逐项完成本次看板调整：移除用户不需要的硬件索引/规则来源字段；明确区分无采集样本与真实数值 `0`；修复会把缺失指标伪装成零值的查询；调整告警持续时长卡片排版，避免数值换行。

## 现状与问题

- 01 网络总览的内存池/温度 Top10 表展示硬件索引等内部字段。
- 02 网络设备详情暴露 `source_id`、`source_type`、`rule_version` 等来源及规则元数据，硬件明细也多处展示索引。
- 默认空值文案“数据暂不可用”没有说明查询无样本；多处 `or vector(0)` 会在整类指标缺失时仍显示零。
- 12 告警处置与通知效果的未恢复时长卡片过窄，`dtdhms` 数值会换行。

## 影响范围

- Grafana dashboard 生成器及其生成的 JSON 看板；告警指标 exporter 的 Outbox 汇总输出及其聚焦测试。
- 只改展示和查询语义；PromQL 身份匹配仍保留必要的内部标签，真实 SNMP 采集与在线 Grafana 不做变更。

## 拟修改文件

- 配套执行记录：`docs/walkthrough/walkthrough_20260929_2030_01_监控看板字段与数据语义.md`

## 实施步骤

1. 清理 01/02 中面向用户的硬件索引、来源 ID/类型和规则/采集版本字段；保留 PromQL 关联所需内部标签。
2. 将空值文案改为明确的“暂无采集数据”；移除无条件零值回退，对确有已采集基线且统计结果为零的计数使用正向样本门控。
3. 修改 Outbox exporter：查询成功但无队列行时为允许状态输出 0；查询失败时仍省略该指标族，并补充对应测试。
4. 将 12 的两张未恢复告警时长卡片扩展为并排宽卡片，并合理下移其余统计和趋势图。
5. 运行看板生成器，检查受影响的 JSON、面板结构、字段隐藏配置、零值语义和布局，并运行语法及 diff 格式检查。

## 风险与回滚思路

- 移除零值回退后，缺少对应指标族时面板会进入明确的无数据状态，这是预期语义；若确认某计数在有基线时应显示零，使用正向样本门控恢复该计数零值，不对缺失数据全局补零。
- 隐藏字段不改变 PromQL 匹配身份；若后续排障需要内部标签，可在生成器 transformation 中恢复其展示。
- 回滚仅撤销本计划产生的生成器和 dashboard JSON 变更，保留工作区既有设备详情改动及其他用户文件。
