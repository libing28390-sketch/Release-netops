## 范围与文件
- 作者源：monitoring/grafana/generate_dashboards.py、dashboard_presentation_v2.json。
- 输出：monitoring/grafana/dashboards/ 中受影响的三份 JSON；完整扫描全部 12 份，保留其他产物。
- 验证：相关 Grafana 合约测试，必要时新增无数据库依赖的查询测试。
- 不涉及数据库或设备配置。生产部署遵循现有授权规则；先完成本地可审核改动。

## 分工
- 主 Agent：方案、作者源修改、生成与 diff 审查、浏览器检查、统一验证和文档。
- grafana_query_audit：只读审查无线汇总查询、SSID 数据契约及回退语义。
- grafana_validation_audit：只读审查现有测试与查询解析工具、12 看板产物及图例选项。
- 两个子 Agent 不修改共享文件，不创建其他子 Agent。

## 步骤
1. 对照截图、远端页面和作者源定位查询语法错误，确认来源优先级与去重口径。
2. 修复共享查询构造，保留缺失为 No data、真实零为零；不双算 controller 与 SSID。
3. 去掉 SSID/BSS 查询中的硬编码厂商限制。SSID 明细优先 controller SSID，按相同设备和 SSID 回退到非空名称的 BSS 汇总，覆盖现有 Huawei/H3C 来源，避免叠加计数。
4. 仅调整设备详情六个硬件趋势面板的图例展示、提示与布局，保留指标、单位、变量和链接。
5. 生成全部 12 个看板，审查允许变化清单并执行聚焦验证。

## 验证

- 使用实际 PromQL/MetricsQL 解析器校验查询，检查 controller/SSID/legacy 同时、零、缺失等边界。

- 浏览器核对远端错误和本地改动的适用方式；未经同步部署不宣称远端已修复。

## 风险与回滚
- 去掉厂商过滤不会让未采集的平台凭空产生数据，SSID 和 BSS 仍按不同粒度展示。
- 密集部件曲线保留全部数据，图例占位控制不改变统计。完整读数仍可从下方明细查看。
- 通过恢复本次作者源及对应生成 JSON 可回滚，不覆盖用户已有变更。
