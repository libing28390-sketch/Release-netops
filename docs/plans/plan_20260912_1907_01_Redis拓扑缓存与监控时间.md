# Redis 拓扑缓存与监控时间格式

## 任务目标

检查 `/monitor/topology` 的 LLDP 采集、PostgreSQL 持久化、页面读缓存与 IP 定位缓存调用链，解释定位时仍执行 LLDP CLI 的原因，并评估可安全投影到 Redis 的观测。修正 Redis 运维日志的时间展示：Docker 容器日志增加可读时间戳，Redis `MONITOR` 输出提供流式时间格式化工具。

## 现状与问题

- 周期拓扑采集把规范化 LLDP 观察持久化到 PostgreSQL；图页 API 使用进程内短 TTL 读缓存，拓扑采集当前没有向 Redis 预热完整设备 LLDP 快照。
- IP 定位默认只接受 10 分钟内的拓扑邻接，而拓扑链路默认证据 TTL 为 48 小时；locator 的 LLDP Redis key 与周期拓扑 PostgreSQL 观察不是同一数据通道。
- `redis-cli MONITOR` 的首列为 Unix epoch 秒（含小数秒），不是 Docker Compose logging driver 的时间格式；设置容器时区不能改变该协议输出。

## 影响范围

- 拓扑与 IP Locator 后端只读审计，不在本次改变数据库事实、缓存 freshness、scope key 或 generation/invalidation 契约。
- 部署日志展示工具与说明文档。

## 拟修改文件

- `scripts/format_redis_monitor.py`：新增只读 stdin 格式化器，支持显式时区并保留微秒与原始命令文本。
- `scripts/deploy-docker.sh`：`redis-logs` 使用 Docker Compose 时间戳选项。
- `docs/deploy/docker.md`：区分容器 stdout/stderr 与 `MONITOR` 流，并记录格式化命令及监控注意事项。
- `backend/tests/release/test_redis_monitor_formatter.py`：覆盖 epoch 转换、微秒、时区及非匹配行透传。
- `docs/walkthrough/walkthrough_20260912_1907_01_Redis拓扑缓存与监控时间.md`：记录审计结论、实现与验证。

## 实施步骤

1. 核对拓扑采集写库、周期调度、图页缓存，以及 IP Locator 的 LLDP freshness / Redis 回源路径。
2. 新增纯流式时间格式化器；不连接 Redis、不写日志、不暴露认证信息。
3. 让 `redis-logs` 展示 Docker 自身的时间戳；文档说明这不会重写 Redis `MONITOR` 自带 epoch 字段。
4. 运行格式化器单测、部署脚本语法检查和差异空白检查。
5. 给出 LLDP 与其他候选 Redis 投影的数据边界、TTL 和失效建议；另行实施前需统一采集 cadence、generation 与负快照语义。

## 验证计划

- `git diff --check` 检查本轮相关文件。

## 风险与回滚

- 本轮不连接 Redis、不授予 `MONITOR` 权限、不执行拓扑/真实设备采集、不部署服务。
- `MONITOR` 是高权限诊断命令且会增加 Redis 开销；格式化器只处理已有 stdout 流，不会自行开启监控。
- 回滚只需撤销 `redis-logs --timestamps` 选项、删除格式化器并还原对应文档/测试；Redis 数据与 PostgreSQL 数据完全不受影响。
