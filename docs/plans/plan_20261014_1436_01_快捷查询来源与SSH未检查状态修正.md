# 批量快捷查询来源与巡检 SSH 状态修正计划

## 任务目标

修复用户指定的第二条问题：
1. 批量快捷查询保留每台设备的解析器、平台版本、模板和采集源信息；混合结果明确显示为 mixed，并能展开查看逐设备来源。
2. 网络设备巡检没有执行 SSH 时，将 ssh_ok 保存为未检查状态，并让页面与导出显示为“未检查”，而不是成功或失败。

不修改历史 Playbook TextFSM 重解析路径。

## 现状与问题

- 快捷查询逐台发起请求并合并记录，但 parser/source/adapter/parse_status 被放入单一变量，遍历后由后一个设备覆盖；最终结构化表和 Excel 元信息无法反映混合来源。
- 网络巡检结果初始值和“无 CLI 项”的分支把 ssh_ok 设置为 1；SNMP-only 巡检未执行 SSH，历史详情仍显示 SSH 成功。
- inspection_results.ssh_ok 是可空整数列，已有导出 stateLabel 能把 null 显示为 —；无需迁移数据库。

## 影响范围

- 快捷查询 hook、结果弹层、类型、Excel 导出。
- 网络设备巡检后端和巡检历史详情 UI。
- 不涉及第一条历史 TextFSM 重解析问题，不涉及数据库迁移、设备配置或 SNMP 轮询。

## 实施步骤

1. 为每台快捷查询目标保留安全的来源摘要（设备、平台、解析器、parser_platform、模板、来源、命令来源、解析状态、记录数和错误）。
2. 仅在所有设备同值时设置单一汇总标签；存在差异时标为 mixed，结果弹层展示逐设备明细，Excel 元信息同步导出逐设备来源。
3. 在网络巡检中用 null 表示未执行 SSH；路由协议 CLI 回退成功仍记 SSH 成功，实际 SSH/回退失败记失败。
4. 巡检详情页将 null 展示为中性“未检查”标记，现有导出继续使用 null 到 — 的语义。
5. 写入 walkthrough，并运行前端 lint、Python 语法编译及 git diff --check；不新增或运行自动化测试。

## 风险与回滚思路

- 只修改快捷查询返回的聚合元数据，不改变命令执行和结构化记录内容。
- 数据库允许 ssh_ok 为 null；旧数据的 0/1 显示维持原语义。
- 如果调用方依赖 ssh_ok 必须为 0/1，回滚对应后端状态值及前端展示改动即可；无需迁移。
