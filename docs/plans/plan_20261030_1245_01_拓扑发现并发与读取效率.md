# 拓扑发现并发与读取效率

## 目标与现状
用户反馈20台设备手动发现偏慢，授权先修改后由用户现场验证。源码显示默认6台固定分批，整批等待最慢节点；LLDP并行10列但使用GETNEXT；聚合和本机身份读取计入同一设备生命周期。保留完整采集、二进制Port ID及失败回退语义。

## 影响范围和分工
- 主Agent：`backend/services/topology_service.py` 的滑动并发队列、分阶段耗时，以及相关调度测试和文档。
- 用户要求默认10台，随后要求删除环境变量项：移除 `.env.example` 与本地 `.env` 的同名配置，使用代码默认10；不触碰其它环境配置，不提交 `.env`，不重启/部署远端。
- SNMP执行Agent：`backend/services/snmp_service.py` 的LLDP GETBULK选择与兼容回退、`backend/tests/snmp/test_snmp_lldp_walk_limits.py` 和必要的LLDP传输测试。不得改拓扑service共享文件。
- 原资产模板任务继续独立收尾；其执行Agent仅负责资产API、模板和资产测试。

## 实施步骤
1. 将固定批次替换成持续补位的worker队列；用户后续明确要求默认从6台改为10台，环境变量仍可覆盖。保持取消、租约和计数汇总语义，SNMP操作全局默认上限30不变。
2. LLDP在SNMPv2c/v3优先GETBULK，保留SNMPv1 GETNEXT及受限fallback；保持行数无上限调用、截断/超时不能成为完整快照、原始OCTET保真。
3. 增加单设备LLDP、聚合、主机名、本机IP、入库及总耗时日志/元数据，支持现场判断瓶颈。
4. 聚焦验证快设备补位、并发上限、取消/租约、二进制Port ID、超过200行、部分失败和fallback。若聚合优化需要扩大协议契约，本轮先保留并用耗时证据决定。

## 验证与风险
使用netops-topology-engine、netops-backend、netops-network-drivers和netops-quality-gate；运行相关pytest及PostgreSQL-only扫描。纯后端无需重跑前端构建。测试不代表真实设备性能，交付提供现场观测日志字段，用户自行验收。未授权部署/推送/真实设备改动。回滚只撤销本轮代码，保留先前LLDP NUL、画布及资产改动。
