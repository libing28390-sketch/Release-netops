# IPAM 全项数据核查

## 目标与范围
逐项核查 IP地址、发现终端、IP定位、利用率、IP对账、网段、地址池、VIP、DHCP；追踪采集源、数据库作用域、API及展示字段，检查地址/掩码、VLAN/VRF/站点、设备/接口、主机名、时间、状态、分类和汇总口径。根据用户追加要求，统一业务接入VLAN终端口径：三层网关ARP提供IP/MAC，接入交换机同作用域、同VLAN的MAC表提供接入口，基础设施自身地址不算终端。

## 现状与约束
近期业务VLAN过滤、接口快照及界面存在未提交修改，全部保留。使用当前本地数据库做只读核查，不修改真实采集结果、人工台账或设备配置。不能由保存快照证明的设备实时准确性标记为未验证。

## 分工与文件边界
- 主Agent：实时库只读核查、跨层结论、确认问题修复、计划与walkthrough。
- Luna frontend_worker：审计并修复利用率失败态、网段树筛选、地址池/VIP状态、DHCP日期。独占这些页面及聚焦测试。
- Luna backend_worker：审计并修复ip_locator_service.py与collection_plan_service.py中的SVI候选遗漏、ARP/MAC跨VLAN和站点拼接及对应测试。
- 主Agent独占ipam_service.py、ipam_discovery_service.py、IPAddressTab.tsx和其展示helper/测试，维护业务范围、自身地址排除、原始/推断证据、状态及层级边界。
- 子Agent不再派生Agent；公共lint/build和最终集成验证由主Agent统一执行。保留原始ARP诊断缓存，IPAM只投影业务VLAN终端，不为界面需要裁剪全局定位数据。

## 实施与验证
1. 建立全部页面/API/数据源/字段核查矩阵。
2. 对当前库逐项比对快照与输出，记录错误、空值、推断、过期和不可证实项。
3. 修复证据明确的代码错误，保留原始证据与人工数据。
4. 执行受影响IPAM测试、前端类型检查及必要构建，输出逐项结论和验证边界。

## 风险与回滚
本次不做数据清洗或重新采集。修改按文件回滚；既有用户变更不回退。未知信息不得默认为在线、业务或真实采集值。
