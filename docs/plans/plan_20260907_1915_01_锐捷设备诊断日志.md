# 锐捷设备诊断日志实施计划

## 任务目标

为锐捷设备的连接、特权模式、命令发送、设备 CLI 错误回显和 TextFSM 解析链路补充可检索的脱敏日志，使 `192.168.96.101` 的失败原因可以区分为连接失败、enable 失败、命令被设备拒绝或模板未匹配。

## 现状/问题

- 设备 `111` 使用 `ruijie_rgos`，绑定 `ruijie_rgos_v12` Profile 和 `ruijie_os` 驱动。
- 历史错误包含 `Failed to enter enable mode`，当前还需要确认命令是否真正发送以及设备返回的原始 CLI 错误。
- 现有日志缺少统一的设备平台、Profile、Netmiko device type、命令摘要、提示符和解析模板上下文。

## 影响范围

- 只增加后端诊断日志，不改变命令、凭据、权限、解析结果或设备配置行为。
- 不记录密码、enable secret、Token、SNMP community 或完整设备输出。

## 拟修改文件

- `backend/drivers/netmiko_driver.py`
- `backend/services/platform_registry_service.py`
- `backend/services/operational_data_service.py`
- 新增/更新后端网络驱动日志测试
- 对应 `docs/walkthrough/` 验证记录

## 实施步骤

1. 在 Netmiko 驱动记录连接参数摘要、secret 是否配置、登录提示符、enable 尝试结果和连接异常。
2. 在命令发送边界记录脱敏命令、命令中的引号特征、输出字节数、CLI 错误行和执行结果。
3. 在平台动作边界记录 action、发布版本、实际命令、驱动结果和进入解析前后的上下文。
4. 在解析边界记录 parser platform、模板、模板来源、解析状态和记录数。
5. 增加 mock/caplog 测试，验证关键诊断字段存在且凭据不会出现在日志中。

## 验证计划

- 运行新增的日志/驱动定向测试。
- 运行锐捷 TextFSM、平台注册表、LLDP 合约、Netmiko 安全测试。
- 运行仓库 PostgreSQL 策略扫描；本次不修改数据库。

## 风险与回滚思路

- 风险：日志过多或误记录敏感内容。通过字段白名单、命令脱敏和不记录原始输出控制。
- 回滚：仅回退本次新增的日志代码和测试/文档文件，不触碰用户已有未提交变更。
