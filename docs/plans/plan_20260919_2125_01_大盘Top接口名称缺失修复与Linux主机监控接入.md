# 实施计划：大盘 Top 接口名称缺失修复与 Linux 主机监控接入

## 任务目标

1. **解决 Top 排序没有接口名称的问题**：
   - 修复 `04 接口流量与健康 (Interface Traffic & Health)` 和 `06 互联网出口与 WAN (Internet Outbound & WAN Traffic)` 中，Top 排序表格（端口带宽利用率、端口错误与丢弃排行）中完全缺失接口名称列、且多端口被错误压缩成每台设备仅 1 行的问题；
   - 在 SNMP 采集端 (`snmp.yml`) 为所有关键接口指标补齐 `ifDescr` (1.3.6.1.2.1.2.2.1.2) 的 MIB 定义与 `lookups`，实现 `ifName` 与 `ifDescr` 双重回退；
   - 在 Grafana PromQL 中将聚合键由硬编码 `by (hostname, instance, ifName)` 升级为 `by (hostname, instance, ifName, ifDescr, ifIndex)`，确保端口独立细粒度展现；
   - 在 Grafana Organize 变换中映射 `ifName` (端口编号)、`ifDescr` (端口名称)、`ifIndex` (端口索引)。

2. **明确 Linux 主机监控接入规范**：
   - 深入解释 `07 Linux 服务器监控 (Linux Server Metrics)` 依赖的 Prometheus 官方标准探针 **`node_exporter`**（端口 9100）；
   - 在 `monitoring/vmagent/scrape.yml` 中配置/预留标准 `linux_nodes` 抓取作业；
   - 为用户提供一条命令安装启动 `node_exporter` 的标准指引。

## 现状与根因分析

### 根因 1：`snmp.yml` 缺少 `ifDescr` 指标定义与 Lookup 映射
- 目前 `generic_ifmib_interface_std` 仅有 `lookup: ifName`，指标列表中根本没有 `ifDescr`。
- 绝大多数网络设备和主机（华为、Cisco、Linux 等）在 RFC 1213 中对 `ifDescr` 拥有 100% 普遍支持，但很多设备对 RFC 2863 的 `ifName` 并不上报或返回为空。
- 结果就是采集入库的 `ifHCInOctets`、`ifInErrors` 等指标上根本没有 `ifName` 标签，只有数字 `ifIndex`。

### 根因 2：PromQL 聚合键硬编码且 Organize 排除了接口索引
- Top 排序表格的 PromQL 查询为：
  `max by (hostname, instance, ifName) (...)`
- 当时序上没有 `ifName` 标签时，Prometheus `by (hostname, instance, ifName)` 会丢弃不存在的 `ifName`，结果只输出 `instance`；
- 更致命的是：没有 `ifName` 作为区分，该设备下的所有端口在 `max by` 时被折叠压缩成整台设备仅有的一行数据；
- 在 Grafana 的表格 Organize 变换中，又显式排除了 `ifIndex: True`，导致最终渲染出来的表格只剩下“管理 IP”和“带宽利用率”，接口名称彻底消失。

3. `monitoring/vmagent/scrape.yml`：
   - 补充 `linux_nodes` 静态/动态文件发现作业配置，打通 Linux 主机采集链路。
