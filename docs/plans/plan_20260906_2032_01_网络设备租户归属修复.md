# 网络设备租户归属修复实施计划

## 任务目标

从根本上解决 Docker 部署后通过资产页面新增或导入网络设备时 `tenant_id` 为空，导致后续管理员绑定平台触发 403 资源范围校验的问题。新设备必须由后端依据当前认证会话写入租户，不能信任前端提交的租户字段。

## 现状/问题

- `POST /api/devices` 创建 SQL 未写入 `devices.tenant_id`，现有数据库列默认值为空字符串。
- `POST /api/devices/import` 批量导入 SQL 同样未写入 `tenant_id`。
- 资产管理的 `POST /api/assets` 和 `POST /api/assets/import` 会通过 `_create_linked_device` 自动创建关联设备，该 helper 也未写入 `tenant_id`。
- 两个写入接口没有强制认证，后端无法安全地确定设备归属租户。
- 数据库初始化中的历史回填只处理启动时已有数据，不能修复后续新增/导入记录。
- 前端新增和导入请求未统一携带认证头；后端增加会话租户归属后需要同步更新。

## 影响范围

- 网络设备创建、批量导入 API 及资产管理页面对应请求。
- `devices.tenant_id` 默认值、历史空租户数据回填及迁移记录。
- 不改变平台绑定接口的租户校验规则；该校验仍作为最后一道隔离保护。
- 不修改工作区中与本问题无关的已有未提交改动。

## 拟修改文件

- `backend/api/devices.py`：为创建/导入接口加入 Operator+ 会话鉴权，使用认证用户租户写入设备，审计主体取会话值。
- `backend/api/assets.py`：资产创建/导入自动生成关联设备时，使用当前会话租户写入 `devices.tenant_id`。
- `backend/database/schema.py`：将新建设备租户列的基线默认值对齐为 `tenant-default`。
- `backend/database/migrations/m0211_device_tenant_scope.py`：为已部署 PostgreSQL 设置默认值，并将历史空租户设备安全回填到默认租户，保证迁移幂等。
- `src/hooks/useDeviceFormActions.ts`：新增设备请求使用统一认证头。
- `src/hooks/useInventoryImportExport.ts`：设备导入请求使用统一认证头。
- `backend/tests/database/test_m0211_device_tenant_scope.py`：覆盖迁移回填、默认值和重复执行。
- `backend/tests/rackvision/test_device_tenant_scope.py`：覆盖设备/资产创建与导入按会话租户落库，以及未认证请求被拒绝。
- `docs/walkthrough/walkthrough_20260906_2032_01_网络设备租户归属修复.md`：记录实际修改与验证结果。

## 实施步骤

1. 保留现有工作树改动，新增本计划文件。
2. 增加认证用户租户提取与非空校验；设备创建/导入及资产自动建联均使用会话租户写入 `devices`。
3. 同步前端新增/导入请求的 `Authorization` 头。
4. 编写 PostgreSQL 迁移，设置默认值、回填空租户并建立必要索引；更新基线 schema 默认值。
5. 添加回归测试，覆盖设备 API、资产 API、未认证、无租户和迁移幂等边界。
6. 运行定向 pytest、Python 编译检查和前端 lint；根据结果修正实现。
7. 更新 walkthrough，列出未执行的验证项和剩余风险。

## 验证计划

- `pytest -q backend/tests/database/test_m0211_device_tenant_scope.py backend/tests/rackvision/test_device_tenant_scope.py`
- `python -m compileall -q backend/api/devices.py backend/database/migrations/m0211_device_tenant_scope.py`
- `npm run lint`
- 若本地 PostgreSQL 测试服务可用，再运行与资产/平台绑定相关的定向测试；不重置 Docker 数据卷。

## 风险与回滚思路

- 新增/导入接口会从匿名写入变为要求有效的 Operator+ 会话；前端同步补齐认证头，其他直接调用方需按同一 API 契约携带 Bearer Token。
- 迁移只将历史空租户归入现有单租户默认值 `tenant-default`，不改写已经有明确租户的设备；迁移不删除数据且可重复执行。
- 若需回滚代码，可回退 API、前端和迁移文件；已完成的租户回填属于数据修复，不建议反向清空，否则会重新引入越权风险。
