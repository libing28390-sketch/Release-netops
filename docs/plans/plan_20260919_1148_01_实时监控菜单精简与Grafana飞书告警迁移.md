## 1. 任务背景与核心诉求

用户针对监控体系与告警机制提出了两项关键指令：
1. **确认采用“方案 1（极致清爽）”进行侧边栏菜单精简**：
   - 侧边栏【实时监控】菜单组中，移除与 Grafana 大盘功能重复的项（`监控中心`、`互联网出口`、`服务器监控`、`采集健康`）；
   - `运营总览`（系统首页门户）、`网络监控`（即时设备诊断）、`监控大盘`（Grafana 观测枢纽）、`监控报表`（一等公民报表中心）、`采集计划/模块/采集器`（控制面编排）以及`网络拓扑`保留；
   - 将被精简页面的核心管控配置（如出口探针管理、服务器进程诊断、采集诊断）通过 Grafana 大盘顶部快捷工具栏形成无缝互通，保证业务能力不遗漏。
2. **确认 Grafana Alert 接入规则通过飞书 API 通知告警的可行性与落地方案**：
   - 确认 Grafana 告警是否支持通过飞书 API / Webhook 发送卡片通知；
   - 核查 `/alerts/rules` 中涉及 SNMP 的告警规则（CPU、内存、接口利用率、端口 DOWN、SNMP 不可达、温度、错包率等）迁移至 Grafana / VictoriaMetrics 的可行性及映射关系。

## 2. 影响范围与拟修改文件

### 2.1 前端导航与页面集成（方案 1 精简）
- `src/components/AppSidebar/navConfig.ts`：精简 `realtime` 子菜单项，移除 `monitoring`、`outbound-monitoring`、`server-monitoring`、`monitoring-health` 4 个菜单项。
- `src/pages/GrafanaDashboardPage.tsx`：在大盘顶部工具条中，根据当前选中的大盘（如 06 出口、07 服务器、05 采集健康），提供直通对应管理操作（如【⚙️ 探针管理】、【📋 进程诊断】、【🔍 采集调试】）的快捷按钮。

### 2.2 后端 Grafana 告警飞书 Webhook 桥接服务
- `backend/api/alerts.py`：新增 `POST /api/alerts/webhook/grafana` 端点，接收 Grafana Alertmanager 标准 Webhook，解析后调用 `notification_service.send_feishu`，并可选入库告警事件。
- `backend/tests/alerts/test_grafana_alert_webhook.py`：为 Grafana 飞书告警 Webhook 桥接编写单元测试。

### 2.3 规则迁移映射表与 Provisioning 规范
- 整理 `/alerts/rules` 中的 12 类核心 SNMP 告警规则至 Grafana PromQL 告警表达式映射标准。
