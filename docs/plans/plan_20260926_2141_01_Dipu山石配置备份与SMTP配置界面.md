# 实施计划：Dipu/山石配置备份命令与 SMTP 配置界面

## 任务目标
- Dipu 交换机与防火墙的运行配置备份使用 `show running-config`。
- Hillstone 运行配置使用 `show configuration`，启动配置使用 `show configuration startup`。
- 在“平台管理”中提供可见的邮件通知入口，配置 SMTP 连接、凭据、发件人和测试邮件。
- 按用户授权提交并推送至 main，确认 CI/Actions 结果。

## 现状与问题
- 用户指出 Dipu 交换机/防火墙和 Hillstone 的配置命令需要修正。
- 项目已有 SMTP API 与初版设置区域，但用户在浏览器确认平台管理侧栏没有邮件设置入口；实际 SMTP 表单被放在“配置管理 → 配置模板”页面中，归属错误且不易发现。
- 工作区有用户未提交的 `handoff.md` 修改，必须保留且不纳入提交。

## 影响范围
- 配置备份的 vendor/platform 命令映射与相关测试。
- SMTP 邮件设置独立页面、平台管理导航与路由；从配置模板中心移除 SMTP 表单。
- 对应计划、完成记录和修复记录。

## 拟修改文件
- 由配置备份命令映射调查确定的后端模块及其聚焦测试。
- `src/pages/NotificationChannelSettingsPage.tsx`
- `src/pages/PlatformSettingsTab.tsx`
- `src/components/AppSidebar/navConfig.ts`
- `src/components/AppMainContent.tsx`
- `src/utils/routeContext.ts`、`src/utils/routeContext.test.ts`、`src/hooks/usePageTitle.ts`
- `docs/plans/`、`docs/walkthrough/`、`docs/fixes/` 对应归档。

## 实施步骤
1. 追踪 Dipu/Hillstone 的 vendor、platform 到配置备份命令的映射与现有测试。
2. 修正两类设备命令并增加聚焦回归用例。
3. 审查 SMTP 前端与已存在 API 契约，补足完整配置流程和错误/权限状态，不传递或记录明文密码。
4. 从配置模板中心移除 SMTP 区域，新增 `/management/notifications` 独立设置页，并将“邮件通知”加入平台管理导航。
5. 执行配置映射测试、路由测试、前端 lint/build；在浏览器确认当前入口缺失及表单原先所在位置。
6. 更新 walkthrough 与新的 fix 记录；仅提交任务相关文件，保留 `handoff.md`。
7. 将提交推送到 origin/main，确认远端提交和 GitHub Actions。

## 验证计划
- 配置备份模块聚焦 pytest：验证 Dipu 运行配置和 Hillstone 运行/启动配置选中正确命令，并确保既有厂商行为不回归。
- `npm run lint` 与 `npm run build`。
- `npm run test:frontend -- --run src/utils/routeContext.test.ts`，确认平台邮件通知路由解析。
- 使用浏览器实际检查平台管理与配置模板导航，确认原入口缺失及修正后的信息架构。
- 运行与受影响发布契约相关的最小检查。
- `git diff --check`、工作区/提交内容检查，确认无 SMTP 密码或 handoff.md。
- 推送后核验 Actions 运行结论。
- 若 Actions 无法启动，区分账号计费/runner 阻断与代码构建失败；记录实际工作流注释，不将未启动误报为代码失败。

## 风险与回滚
- 错误的备份命令会导致对应设备配置无法读取；以新增命令映射测试阻断此风险。无需对真实设备执行命令。
- SMTP 密码只经现有安全 API 提交，前端保存成功后清空密码输入，错误信息不得显示凭据。
- 如 CI 失败则不宣布完成；按失败结果修复后重跑。发布回滚可 revert 本次任务提交。
