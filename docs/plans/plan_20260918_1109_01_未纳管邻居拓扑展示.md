# 任务目标

调整拓扑页面对未纳管邻居的处理：保留严格的设备身份匹配，避免误生成管理链路；同时把已发现但未匹配的邻居作为外部节点和虚线链路展示，并将管理链路与外部链路分开统计，不再把未纳管邻居单独视为拓扑失败。

# 现状/问题

- 后端 `get_unmanaged_neighbors` 已生成 `unmanaged_nodes` 和 `unmanaged_links`，但前端 `useTopology` 只消费 `links` 与图关系边，丢弃未纳管链路。
- `topologyStats.linkCount` 因此只显示管理链路；当所有邻居都未匹配时显示 0，用户无法看到实际 LLDP 证据。
- generation status 将 unmatched observation 放入 warnings，并以“存在任意 warning 即 degraded”计算健康度，导致未纳管设备被当成系统异常。

# 影响范围

- 拓扑 API 响应兼容现有字段，新增/复用外部链路数据不改变设备匹配或数据库写入。
- 拓扑画布增加未纳管节点/链路展示；管理链路统计保持准确，并增加外部链路统计。
- 发现、采集、凭据和设备配置流程不受影响。

# 拟修改文件

- `backend/services/topology_service.py`：将未纳管邻居 warning 标记为 informational，并让健康度不因该类提示降级。
- `src/hooks/useTopology.ts`：接收 `unmanaged_nodes/unmanaged_links`，合并到当前画布节点与链路模型，保留未纳管标志。
- `src/hooks/useTopologyDerivedData.ts`：在派生统计中区分管理链路和外部链路。
- `src/pages/TopologyPage.tsx`：显示管理/外部链路数量与信息提示。
- `src/contexts/TopologyContext.tsx` 或相关类型：补充外部链路统计/节点类型。
- `backend/tests` 与 `src` 测试：覆盖未纳管数据不降低健康状态、外部链路被展示且管理链路统计不混淆。
- `docs/walkthrough/walkthrough_20260918_1109_01_未纳管邻居拓扑展示.md`：记录验证结果。

# 实施步骤

1. 追踪拓扑 API 到 hook、派生统计和图组件的数据形状，定义稳定的 `is_unmanaged` 外部链路标记。
2. 保持 `topology_links` 只代表两端纳管的管理链路；前端将 API 的未纳管 pseudo-node/link 合并到画布专用数据集。
3. 更新健康度语义：未纳管邻居仍显示提示，但不单独把 generation health 标记为 degraded；真实采集/解析/陈旧问题仍保留告警。
4. 增加/更新测试，运行拓扑后端测试、前端 lint/相关测试。

# 风险与回滚思路

- 不把未匹配邻居写入 `topology_links`，因此不会制造虚假管理关系。
- 外部节点使用稳定的 `unmanaged::...` ID，并在前端过滤/布局中保留现有性能边界。
- 回滚前端/后端改动即可恢复原来的管理链路视图，不需要数据回滚。
