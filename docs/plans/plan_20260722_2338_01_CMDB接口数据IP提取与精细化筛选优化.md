# 实施计划 - CMDB 接口数据 IP 提取与精细化筛选优化

## 1. 任务目标
解决用户对 `/cmdb/interfaces` 页面提出的两大核心痛点：
1. **全厂商接口 IP 提取**：覆盖 Cisco、Huawei、H3C、Juniper、Arista、Ruijie、ZTE 等全厂商设备的接口 IP 提取，修复通用与多厂商 CLI 命令下 IP 缺失导致的接口 IP 显示为 `--` 的根因问题。
2. **多余重复无 IP 接口噪音**：针对交换机 24/48 个未配置 IP 的二层端口在列表重复展示导致的噪音，优化视图与 API 筛选机制，默认开启“仅看配置 IP 的接口”视图，并保留可一键切换至全量二层端口的快捷选项。

## 2. 现状与根因分析
1. **多厂商接口 IP 未全量采集**：此前接口采集逻辑中针对不同厂商平台（如 Cisco/Huawei/H3C/锐捷/Arista 等）的命令和解析处理不完备，导致部分厂商缺乏 `show/display ip interface brief` 命令提取或结果解析缺少 `primary_ip` / `ip_address`，从而使写入数据库的接口 IP 为空。
2. **无 IP 接口全量展示重复度极高**：二层接入/汇聚交换机有大量物理端口（GE1/0/0 ~ GE1/0/48），在默认列表中显示数十条除接口名外完全相同的未配 IP 记录。
3. **缺少快捷筛选与概览统计**：CMDB 接口视图缺乏针对“有 IP / 无 IP”、“Up / Down”及“关联拓扑”的统计卡片与快捷 Toggle 筛选。

## 3. 拟修改文件
- `backend/services/scheduler_service.py`：支持全厂商（Cisco, Huawei, H3C, Juniper, Arista, Ruijie, ZTE 等）采集命令 `show/display ip interface brief`，新增 `parse_generic_ip_interface_brief` 通用解析器，解析并回填接口 IP 地址及 L3 接口。
- `backend/services/cmdb_service.py`：`list_cmdb_interfaces` 增加 `has_ip`、`device_id` 和 `search` 参数支持。
- `backend/api/cmdb.py`：接口 `/api/cmdb/interfaces` 补充 `has_ip`、`device_id`、`search` 查询参数。
- `src/pages/CmdbManagementTab.tsx`：CMDB 接口视图增加 4 项顶部统计卡片（接口总数、配置 IP 数、Up 状态数、拓扑关联数），增加“仅看有 IP 接口 / 全部接口”快捷切换 Pill，以及搜索与设备筛选框。

## 4. 实施步骤
1. **后端全厂商数据采集与 API 增强**：
   - 更新 `scheduler_service.py`：增加全厂商通用 CLI 接口 IP 解析逻辑 `parse_generic_ip_interface_brief`，为 Cisco、Huawei、H3C、Juniper、Arista、Ruijie、ZTE 等全厂商提取 `primary_ip`。
   - 更新 `cmdb_service.py` & `api/cmdb.py`：`GET /api/cmdb/interfaces` 支持 `has_ip` 动态筛选与模糊搜索。
2. **前端 CMDB 接口视图优化**：
   - 在 `CmdbManagementTab.tsx` 中为接口 Tab 添加统计卡片。
   - 默认开启“仅看有 IP 接口”视图，一键收容/隐藏 90%+ 的无 IP 二层端口；提供“全部接口”切回按需排查物理端口。
3. **验证与回归**：
   - 运行类型与语法检查 `npx tsc --noEmit`。
   - 运行全厂商接口采集与 CMDB 单元测试。
