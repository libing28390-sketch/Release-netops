# main 代码提交与推送计划

## 任务目标

将当前工作区中已完成、适合公开仓库的代码与配套记录提交到 `main`，并推送到 `origin/main`。

## 现状与问题

- 当前分支为 `main`，执行前已同步 `origin/main`，本地与远端没有提交差异。
- 工作区有三组已完成变更：华为 YunShan 平台链路及 Windows 开发端口、Grafana 查询与图例布局、Grafana/Nginx 加载链路。
- 工作区还包含 `.agents` 下的用户本地 skill 修改和多个构建验证输出目录。这些不属于本次公开代码提交，应原样保留。

## 影响范围

- 后端与前端的 YunShan 平台适配、导入、驱动、TextFSM 模板及测试。
- Grafana 仪表盘查询、展示布局和相关测试。
- Nginx Grafana 代理连接配置及部署契约测试。
- 对应的计划、走查和逐提交修复记录。

## 拟修改/提交文件

不再修改业务实现；按以下三组精确暂存现有改动及其配套文档：

1. YunShan 平台与 Windows 开发启动端口。
2. Grafana 查询与图例布局。
3. Grafana/Nginx 加载链路。

不暂存 `.agents/`、`.codex-build-validation-*`、`dist-*-check-*` 等内部协作或本地构建产物。

## 实施步骤

1. 核对 `main`、远端提交图、工作区变更以及空白差异。
2. 将三组改动分别精确暂存，确认暂存区文件清单不包含本地构建产物或 `.agents/`。
3. 每个提交同时包含一份新的 `docs/fixes/fix_*.md` 记录，保留每组已有的计划与走查文档。
4. 创建三个描述范围的提交；不改写历史、不创建分支。
5. 推送 `main` 至 `origin`，随后确认远端包含本地最新提交，并复核剩余工作区改动。
6. 归档实际提交及推送结果。

## 验证计划

- `git diff --check` 和每次提交前的 `git diff --cached --check`。
- 检查每次暂存文件名和提交统计，确保范围正确。
- 使用 `git status --short --branch`、`git log` 和提交图检查分支状态。
- 推送后确认 `main` 与 `origin/main` 同步。
- 代码回归结果引用对应改动的 walkthrough；本次提交/推送不重复运行已通过的业务测试。

## 风险与回滚

- 提交采用三个逻辑组，方便审阅和按组回滚。
- 若推送被远端状态阻止，先获取并审查远端差异，不强推、不覆盖远端历史。
- 若推送后的变更需要撤销，在 `main` 创建对应的 `git revert` 提交；不使用重置或强推。
- 本次仅推送 Git 代码，不部署服务、不触发版本发布或推送标签。
