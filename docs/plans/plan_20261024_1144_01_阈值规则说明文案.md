# 巡检阈值规则说明文案

## 任务目标

把巡检指标表的“警告阈值 / 状态规则”和“严重阈值 / 状态等级”内容改成网络工程师一眼能判断触发条件的说明，避免仅显示“期望：xxx”“≥ 80%”“无独立严重等级”等缺少动作含义的短语。

## 现状与问题

- 数值阈值只显示比较符和数字，没有明确说明达到条件后会触发告警还是严重告警。
- 状态规则使用简写，普通状态、合规文本和风扇/电源状态的判断方式不够直观。
- 未配置阈值显示为破折号，信息型指标只显示“信息型”，运维人员无法直接判断是否参与告警。

## 影响范围

- 修改 `src/pages/InspectionItemsTab.tsx` 的列表摘要、悬停说明、展开详情和巡检指标表格导出说明。
- 保持阈值计算、状态匹配、告警级别、API、列配置、布局与分页行为不变。
- 中文和英文说明同步维护。

## 实施步骤

1. 将数值阈值改为“达到或超过/低于 X 时触发告警/严重告警”，未配置项明确显示为未配置。
2. 将状态规则摘要明确为“期望状态不匹配时告警”“异常状态只告警、不升级为严重”或组件码对应级别。
3. 重写悬停与展开详情里的长说明，解释正常值、比较方式、缺测/未知值处理和严重等级。
4. 同步调整信息型指标的显示，明确其只采集展示、不触发阈值告警。
5. 浏览器检查普通状态、风扇/电源状态、数值阈值和未配置/信息型行；执行前端类型检查、生产构建与差异格式检查。

## 验证计划

- 浏览器检查 `/automation/metrics` 中状态型、数值型及未配置/信息型阈值展示，并检查展开详情。
- `npm run lint`
- 在临时目录运行 Vite production build。
- `git diff --check` 检查页面、计划和走查记录。

## 风险与回滚

- 只调整界面说明，不变更任何阈值或状态告警计算。
- 若文案造成歧义，可恢复旧 formatter 和规则说明；告警数据与阈值配置不需要回滚。
