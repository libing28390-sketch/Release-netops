# 存量设备免上收投产计划

## 任务目标

在保留标准口令上收投产流程的同时，为存量设备提供显式免上收投产路径，并区分业务投产状态与平台口令托管状态。

## 现状问题

- 标准投产强制修改普通和特权账号口令，不适合暂时不能改密的存量设备。
- `lifecycle_status` 与 `is_managed` 已具备分离基础，但缺少明确豁免模式和原因记录。

## 影响范围与修改文件

- `backend/api/assets.py`
- `backend/database/schema.py`
- `backend/database/migrations/m0006_asset_legacy_takeover_exemption.py`
- `backend/tests/test_asset_production_takeover.py`
- `src/pages/AssetManagement/index.tsx`
- `src/pages/AssetManagement/components/AssetModal.tsx`

## 实施步骤

1. 新增 `credential_governance_mode`、豁免原因和豁免时间字段及迁移。
2. 投产请求增加 `production_mode=takeover|legacy_exempt` 和豁免原因。
3. 免上收模式要求关联设备、普通账号凭据和已完成连通验证。
4. 免上收成功后写入已投产、未托管和 `rotation_status=exempt`，不启动改密线程。
5. 投产确认框增加标准投产和存量免上收投产两个入口。

## 验证计划

- 验证标准上收状态机保持不变。
- 验证免上收不会启动口令轮换，且正确记录治理模式和原因。
- 验证原因不足、普通账号缺失或未验证时拒绝免上收。
- 运行完整后端测试、TypeScript 检查和生产构建。

## 风险与回滚

- 免上收设备只能使用普通账号执行只读任务，不应视为平台已托管。
- 回滚时撤销前端入口和 API 模式，但保留新增字段，避免破坏已记录的豁免审计数据。
# 用户验收补充：设备来源标记

- 新增资产必须选择“新设备”或“存量设备”。
- 所有新增资产后端强制以待投产状态入库，禁止直接创建为已投产。
- 只有录入时标记为存量设备的资产可以使用免上收投产。
- 已有资产在迁移时回填为存量设备，避免升级后丢失免上收能力。
