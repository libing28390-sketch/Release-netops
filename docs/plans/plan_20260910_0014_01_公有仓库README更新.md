# 公有仓库 README 更新计划

## 任务目标

依据当前源码、导航入口与发布同步规则，更新根目录 `README.md`，使公有仓库准确展示 Nexora 当前功能、技术架构、部署方式和使用边界。

## 现状 / 问题

- 现有功能清单缺少终端接入、PAM、告警处置、变更工单、AI 知识引擎、NSOT、服务器监控等已上线模块。
- Roadmap 仍将 AI Copilot 标记为开发中，与当前导航和后端接口不符。
- 数据层仍描述为“PostgreSQL / SQLite 自动切换”，与生产 PostgreSQL 约束不符。
- 发布工作流会剔除 `docs/images` 与 `docs/walkthrough`，现有 README 中对应截图和用户手册链接在公有仓库失效。
- 环境变量表只覆盖旧版少量配置，且存在 PostgreSQL 可回退 SQLite 的错误表述。

## 影响范围

- 公有仓库首页功能说明、快速部署、架构、环境变量、文档导航与 Roadmap。
- 不修改业务代码、数据库、部署脚本或 GitHub Actions 行为。

## 拟修改文件

- `README.md`
- `docs/plans/plan_20260910_0014_01_公有仓库README更新.md`
- `docs/walkthrough/walkthrough_20260910_0014_01_公有仓库README更新.md`

## 分工边界

- 主 Agent：统一梳理范围、编辑 README、验证链接和发布适配性。
- 前端盘点子 Agent：只读核对导航、页面与用户可见模块。
- 后端/发布盘点子 Agent：只读核对 API、服务、部署方式与发布边界。
- 共享文件 `README.md` 仅由主 Agent 修改。

## 实施步骤

1. 对照前端导航、后端路由、部署文件和公有发布工作流整理功能矩阵。
2. 重写 README 的产品定位、当前能力、架构、快速部署、安全配置和文档导航。
3. 移除或替换发布后不存在的链接，并将 AI 从 Roadmap 更新为当前能力。
4. 运行 Markdown 结构、相对链接、发布保留路径和敏感信息检查。

## 验证计划

- 检查 README Markdown 标题、代码块与相对链接。
- 模拟 `release.yml` 的文档保留范围，确保 README 引用的本地路径会进入公有发布树。
- 检查 README 未包含真实密钥、密码、Token、SNMP community 或内部协作材料。
- 核对 README 功能模块与 `src/components/AppSidebar/navConfig.ts`、`backend/main.py` 注册路由一致。

## 风险与回滚思路

- 风险：功能描述过度承诺或遗漏部署限制；通过源码和发布配置交叉核对降低风险。
- 回滚：本次只改文档，可直接恢复 `README.md` 的本次差异，不影响运行数据和业务服务。
