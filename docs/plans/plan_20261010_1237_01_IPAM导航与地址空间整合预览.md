# IPAM 地址空间工作流整合计划

## 任务目标

把 IPAM 中网段、IP 地址、地址池和 VIP 从互相独立的页面整合为共享网段上下文的地址空间工作流。用户进入某个网段后，可以在同一上下文中查看其 IP、地址池和 VIP；切换视图时保留网段选择。侧栏按地址空间、动态地址和 IPAM 工作台组织功能，并支持展开和收起各功能下的页面入口。

## 现状与问题

- IPAM 页面标签应放在侧栏对应功能模块下，避免在内容区顶部重复横向显示。
- 前缀、地址、池和 VIP 当前有各自页面，切换页面时缺少共享的网段范围。
- IP 地址 API 已支持 `prefix_id`；地址池表有 `prefix_id`，但列表 API 未提供该过滤条件；VIP 记录没有前缀外键，查询也未按网段过滤。
- VIP 地址是独立记录，不能依赖 IP 地址记录推导归属；按所选前缀的 CIDR 和租户过滤，并在当前工作流新增/编辑时验证 VIP 地址落在该网段。
- IP 定位目前由 `AppMainContent` 特别分支渲染，需纳入统一的 IPAM 页面外壳才能显示一致的页内导航。
- `src/pages/IPAMManagementTab.tsx` 有用户已有未提交修改（移除了旧工作流面板导入和渲染）；实现必须保留。

## 影响范围

- 调整 IPAM 侧栏层级和共享地址空间上下文；通过可选 `prefix_id` 查询参数扩展地址池/VIP 读取及 VIP 创建/编辑校验，不改数据库表结构。
- 保留原有 IPAM URL 和无 `prefix_id` 时的全局查询行为；旧链接继续可用。
- 地址空间的侧栏子菜单切换保留所选网段；IP 地址页复用已有前缀筛选，地址池和 VIP 列表由后端按相同网段范围过滤。
- 地址池新建默认归属当前网段；选择网段时锁定其前缀归属，避免创建后落在当前筛选范围之外。
- 保留 DHCP 租约、IP 定位、利用率和对账的既有独立业务流程。

## 实施步骤

1. 将地址空间、动态地址和 IPAM 工作台作为 IPAM 功能模块，在每个模块下放置可折叠的页面入口；移除内容区顶部重复页签。
2. 从侧栏在 IP、地址池、VIP 页面间切换时保留 `prefix_id`，进入网段列表时清除范围。
3. 在地址空间页面显示共享网段上下文；IP 页面沿用已有前缀选择，地址池/VIP 页面可切换同一上下文。
4. 为地址池 API/service 增加精确 `prefix_id` 过滤；为 VIP 增加 CIDR 与租户范围过滤及当前上下文新增/编辑校验。
5. 地址池新建表单默认使用当前前缀，并在已有网段上下文时固定归属。
6. 将 IP 定位纳入统一外壳，保留直接访问旧 URL；保留此前添加的 IP 对账标题映射。
7. 运行前端 lint 与生产构建，并在本地浏览器实际检查侧栏折叠、网段选择、视图切换、筛选和表单默认行为。

## 验证计划

- `npm run lint`
- `node node_modules/vite/bin/vite.js build --outDir .codex-ipam-workflow-build-20261010`（隔离输出，保留已有 `dist/`）
- 使用本地开发页面检查所选网段在 IP/地址池/VIP 视图间保留、范围数据按前缀过滤、地址池创建上下文和独立流程入口。

## 风险与回滚

- VIP 表没有 `prefix_id` 外键，工作流范围按 CIDR 与租户推导；重叠网段由不同前缀分别筛选。后续若要支持跨租户/VRF 下同地址的 VIP 精确归属，可再评估持久化关联。
- 可选查询参数不改变旧 API 的默认返回行为；没有数据库迁移，回滚可移除页面上下文及新增参数处理，不触及数据。
