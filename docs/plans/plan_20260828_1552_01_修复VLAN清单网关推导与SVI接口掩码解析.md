# 实施计划 - 修复 VLAN 清单网关推导与 SVI 接口掩码解析

针对 `/cmdb/vlans` 页面中即使 SVI 接口（如 `Vlan-interface100`）存在 IP 也显示“暂无网段 / 未发现网关”的缺陷，修复 SVI 接口 IP 掩码解析、网关与网段推导以及采集入库链路。

## 1. 目标与根因分析

### 根因分析：
1. **推导阶段字符串拼接异常**：在 [cmdb_service.py](file:///d:/nexora/nexora-private/backend/services/cmdb_service.py) 中，当 `interfaces` 表里的 `ip_prefix_length` 为空且 `primary_ip` 不带 `/` 时，代码执行 `ipaddress.ip_interface(f'{raw_ip}/{prefix_length}')` 拼出了类似 `'10.254.100.4/'`，导致 Python 抛出 `ValueError` 并被 `except ValueError: continue` 静默捕获吞掉，导致 `gateways` 和 `prefixes` 列表为空。
2. **采集阶段掩码信息丢失**：在 [interface_collection_service.py](file:///d:/nexora/nexora-private/backend/services/interface_collection_service.py) 中解析 `display ip interface brief`（如 H3C 的 `10.254.100.4/29`）时，只提取了纯 IP，未将 `/29` 保存为 `ip_prefix_length`。
3. **关联阶段未做容错降级**：在 `_link_prefixes_to_svis` 中，如果缺少独立掩码字段就直接 `continue` 跳过，没有尝试从 IP 自带的 CIDR 或降级为单个主机 IP 处理。

### 修复目标：
- 修复 `cmdb_service.py` 中的 `_expand_vlan_rows_by_device` 和网关推导逻辑，兼容“纯 IP”、“带斜杠 CIDR”、“点分十进制掩码”及“无掩码降级”等所有情况，确保只要 SVI 存在 IP，网关 IP 与网关设备必能正确推导。
- 优化 `interface_collection_service.py` 中的接口采集解析，从 `10.254.100.4/29` 等复合 IP 字符串中提取并持久化 `ip_prefix_length`。
- 增强 `vlan_discovery_service.py` 中的 `_link_prefixes_to_svis` 容错。
- 编写完整的单测覆盖 H3C/Huawei/Cisco 等 SVI 网关推导场景。
