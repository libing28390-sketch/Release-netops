## 本地全量测试中止记录

- 用户明确要求停止本地全量测试并直接推送；本地测试执行到约 50% 后停止，没有再跑本地全量套件。
- GitHub Actions 后端发布门禁完整执行 2,921 项，结果为 2,440 passed、2 failed、1 skipped，耗时 438.91 秒。
- `test_alert_list_summary_and_details_are_scoped_to_authenticated_tenant` 在 `GET /api/alerts/{id}` 失败：详情 SQL 将 `{tenant_filter_sql}` 留在普通三引号字符串中，SQL 未拼接租户过滤，但参数仍包含租户 ID，PostgreSQL 抛出 `TypeError: not all arguments converted during string formatting`。已将详情和时间线 SQL 改成 f-string，并共用受控的租户谓词。
- `test_outbound_status_only_returns_authenticated_tenant_targets_and_samples` 在夹具插入出向探测目标时失败：SQL 有 6 个参数占位符，测试只传 5 个值，缺少 `host`，PostgreSQL 抛出 `IndexError: tuple index out of range`。已在测试夹具中补齐两个目标的主机名。
- 定向 PostgreSQL 验证：上述两个失败用例修复后 `2 passed in 93.68s`；使用临时测试数据库并已自动删除。

## 风险与回滚思路

- 覆盖同名版本标签会替换公开 Release 的源码引用和资产，用户已明确授权此操作；只在 `main` 门禁成功后推送新标签。
- m0257–m0259 会触及告警规则/相关数据。发布只更新仓库和构建产物，不在本机或用户生产数据库执行迁移；部署前应遵循项目备份策略。
- 若主线或 tag 发布门禁失败，保留已推送提交并依据失败步骤修复；不把失败门禁的代码宣称为正式完成，也不删除旧 release 资产，除非工作流按既定流程成功替换。
- 公开源仓库与 Release-netops 的任何同步只由用户授权的 `main`/tag workflows 执行，不直接绕过仓库发布检查。
