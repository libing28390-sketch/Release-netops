# 定时作业授权拒绝记录与脚本摘要修复

## 目标

修复定时作业因授权校验拒绝后，执行历史没有记录的问题；确保内置巡检脚本更新后，其内容摘要与当前内容一致。

## 实施范围

- 在 `backend/services/scheduler_service.py` 的授权拒绝路径中，以 `denied` 状态写入统一执行历史，并保留作业创建人、租户、开始/结束时间和拒绝原因；该路径不得连接设备或启动作业内容。
- 在数据库迁移完成后，为标准内置脚本刷新 `content_sha256`，避免启动时脚本内容更新而摘要仍指向旧版本。
- 在执行历史页面将 `denied` 显示为“权限拒绝”，并用于导出标签。
- 增加 PostgreSQL 隔离测试覆盖拒绝路径的状态、历史可见性及脚本摘要刷新。

## 约束

- 不绕过或重置现有作业的审批/授权快照。
- 不操作生产数据库、设备或部署服务。
- 保留工作区现有改动，仅修改本任务所需代码与文档。

## 验收

- 针对性 scheduled_jobs PostgreSQL 测试通过。
- PostgreSQL-only 策略扫描通过。
- 前端 lint 与构建通过。

## 补充范围（按用户最新反馈）

- `script_snapshot` 的摘要校验属于预期的授权冲突；审批接口将其转换为 HTTP 409，避免作为未处理异常打印整段服务器栈。
- 定时作业编辑弹窗去除背景滤镜；列表禁用态不再对页面内容施加模糊，保留模态遮罩和操作隔离。
- 为脚本摘要异常增加 HTTP 409 用例，并覆盖摘要恢复行为。
- 去除定时作业编辑及候选预览遮罩的背景模糊，列表背景只禁用交互，不再施加滤镜。
- 同页的作业详情、删除审批和采集计划弹窗也统一去除遮罩背景模糊。
