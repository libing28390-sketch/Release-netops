# NetOps 自动拓扑图优化建议实施计划

为了对标企业级拓扑展示，本方案拟对现有的网络拓扑进行交互及样式方面的全面升级。

## 待修改文件清单

* `backend/services/topology_service.py`：
  - 更新 `rebuild_links_from_observations_unlocked` 方法，在构建拓扑链路时，从 `interfaces` 表中查出物理接口实际协商的 `speed` 字段，从而准确设置 `aggregation_bandwidth_mbps` 字段，以供前端渲染相应的带宽色彩。
* `src/components/TopologyGraph.tsx`：
  - **P1 画布利用率**：调整 `buildHorizontalRowPositions` 中对 spacing 的计算占比，并去除冗余的左侧留白。
  - **P1 直线与折线**：重构 `getOrthogonalRoute` 方法，针对水平/垂直链路统一使用直线连接，对跨层斜向链路采用 90° 的折线（Z-shape）连接。
  - **P1 接口标签贴近设备**：修改端口标签的位置计算，将其由浮动于链路中间修改为贴近设备端口附近（固定在设备中心 32px 的延长线上），并微调以避免重叠。
  - **P1 设备状态圆点**：增加 `getDeviceStatusColor` 方法，在设备图标右上角绘制表示在线状态的呼吸小圆点（🟢 在线、🟡 预警、🔴 离线、⚫ 未知）。
  - **P2 带宽着色**：使物理链路的带宽能正确映射至 Legend 的各颜色档位。
  - **P2 节点信息显示**：在 Hostname 下方新增 IP 地址与型号展示。
  - **P2 Hover 信息卡**：
    * 扩展设备 Hover 卡：显示 Hostname、IP、厂商/型号、CPU 使用率、内存使用率、Uptime。
    * 新增链路 Hover 卡：悬停链路时展示本端接口、对端接口、带宽、Duplex、VLAN、CRC/错误包。
  - **P2 图标与字体优化**：将设备 icon 尺寸从 `62px` 缩减为 `38px` ；将端口文字字号由 `8px` 提升至 `11px`；将 Hostname 文字字号保持为 `14px`。
  - **P3 站点容器优化**：移除 site background 的虚线框，改用浅灰背景（`#f8fafc`），搭配实线边框（`#e2e8f0`）和柔和的 Drop Shadow 阴影。
  - **P3 推荐布局**：将站点层级（`CORE` / `AGGREGATION` / `ACCESS`）标签重构为跨越站点卡片内部的横向横幅分隔线（`─── ROLE ───`）。
  - **P3 交互能力扩展**：在拓扑工具栏中，增加 **全屏**、**导出 SVG** 与 **导出 PNG** 功能。
  - **P3 纠正历史布局重叠 (新增加)**：若拓扑的数据库持久化布局包含了历史两层网络的数据，当新增 ACCESS 接入层节点时，为防止新设备因未被重规划或 seeded 坐标重合而与 AGGREGATION 设备物理重叠，在 `hierarchy` / `horizontal` / `radial` 结构化布局下，强制以最新的结构计算规则纠正分层轴的 Y (或 X) 轴坐标，保留其另一轴的拖动坐标，彻底解决节点不见或重合的问题。

## 实施步骤

1. **后端修改**：
   - 调整 `topology_service.py` 中 `SELECT` 接口详情的 SQL，查询接口的 `speed` 及 `bandwidth`。
   - 对物理链路，利用接口速度之最小值（或最大值）设定 `aggregation_bandwidth_mbps` 列。

2. **前端修改 (`TopologyGraph.tsx`)**：
   - 添加 svg `<defs>` 及 drop-shadow filter 定义。
   - 调整 `buildHorizontalRowPositions` 布局宽度占比。
   - 修改 `getDeviceStatusColor` 并将状态点绘制在设备右上角。
   - 重新编写 `getOrthogonalRoute` 以生成直线与 Z 字形折线。
   - 更新端口标签的 D3 tick 定位算法和 font-size。
   - 更新设备 hover 卡字段，并实现链路 hover 卡。
   - 站点外框样式优化并绘制贯穿横向分割线。
   - 增加全屏控制状态，并实现 SVG/PNG 的本地文件导出方法。
   - **强制分层约束定位**：在 `nodes` 状态映射中，若处于 hierarchy/horizontal/radial 模式且结构化坐标计算存在，则直接用分层轴坐标覆盖历史坐标/默认坐标，完美实现旧位置兼容与新层自动校准。

## 验证计划

1. 运行 `pytest` 确保后端改动不破坏既有单元测试。
2. 触发一次拓扑链路发现与重建以验证新物理链路在 DB 中的 `aggregation_bandwidth_mbps` 能够从 `interfaces` 表正常提取。
3. 检查前端 `npm run lint` 以确保 TypeScript 类型 and 格式完全正确。
4. 运行 `npm run build` 进行生产构建包校验，确保没有前端编译错误。
5. 模拟导入包含 6 台交换机（2台 CORE、2台 AGGREGATION、2台 ACCESS）的网络，且存在历史两层网络拓扑布局的数据库数据，验证 2 台 ACCESS 交换机不再重叠展示在 AGGREGATION 之下，且完美在第三行分层渲染。
