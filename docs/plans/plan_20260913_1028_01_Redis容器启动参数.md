# Redis 容器启动参数实施计划

## 任务目标

修复 Redis sidecar 多行 shell 命令被拆参导致容器只输出 `0022` 并持续重启的问题，并将 Redis 服务合并进唯一的 `docker-compose.yml`，确保后续继续使用 `bash scripts/deploy-docker.sh update` 更新。

## 现状/问题

原 Redis Compose overlay 使用列表形式的 `/bin/sh -ec` entrypoint，却将多行脚本配置为普通字符串形式的 `command`。服务器上的 Compose 将其拆词，使 shell 实际只执行 `umask`，日志输出 `0022` 后 Redis 进程没有启动。独立 overlay 也造成项目名、脚本和文档需要维护两份 Compose 输入。

## 影响范围

- 主 Docker Compose 中的 Redis 服务、ACL 与持久卷。
- 部署脚本、离线镜像以及 Windows/Docker 部署说明。
- Redis 部署契约测试。
- 不涉及数据库结构、应用接口或生产数据。

## 拟修改文件

- `docker-compose.yml`
- 删除 `docker-compose.redis.yml`
- `scripts/deploy-docker.sh`
- `.env.example`
- `backend/tests/release/test_deploy_docker_redis_contract.py`
- `docs/deploy/docker.md`
- `docs/deploy/docker-release-manual.md`
- `docs/deploy/windows.md`
- `docs/walkthrough/walkthrough_20260913_1028_01_Redis容器启动参数.md`

## 实施步骤

1. 将 Redis 服务和显式命名的数据卷迁入主 Compose，保留现有容器名、卷名、ACL、时区和健康检查。
2. 将 `command` 改为单元素 YAML 列表，保证整段脚本作为 `/bin/sh -ec` 的一个参数传入。
3. 更新脚本，让它只加载主 Compose，同时保留默认启用和 `NETOPS_REDIS_ENABLED=0` 的关闭能力。
4. 更新部署文档和契约测试，并删除已不再需要的 overlay 文件。
5. 运行 YAML/Compose 可用范围内的配置检查和聚焦测试。

## 验证计划

- 解析主 Compose YAML 并检查 Redis 服务、`entrypoint`、单参数 `command`、卷名与健康检查。
- 确认部署脚本和当前部署文档不再依赖独立 overlay。
- 运行 `backend/tests/release/test_deploy_docker_redis_contract.py` 聚焦测试（以工作区可用运行时为准）。
- 检查最终 diff，确认无敏感信息和无关修改。

## 风险与回滚思路

Compose 正常重建沿用 `container_name: nexora-redis` 与 `nexora-redis-data`，无需搬迁 Redis 数据。风险主要是已有部署脚本/手工命令仍引用已删除的 overlay；因此已同步更新当前部署脚本和 Windows/离线指南。回滚时恢复旧 overlay 和脚本，并避免执行 `down -v`，以保留 Redis 数据卷。
