# 资产设备 SNMP 采集开关

## 目标

在资产管理中新建/编辑设备时可以单独控制该设备的 SNMP 采集，默认开启。关闭后，Nexora 自动采集不再向该设备发送 SNMP 请求；在线状态继续使用 ICMP/管理端口探测，已有 SSH/CLI 回退继续工作。资产导入不提供该列，始终按开启处理。开关状态保存在 `devices.snmp_collection_enabled`，可读取并纳入资产修改审计。

## 现状与边界

- 设备级 `collection_policy_json` 当前配置各类采集器；它不能代表 SNMP 传输总开关。
- SNMP 流程分布在 vmagent/exporter 目标生成、原生硬件轮询、IF-MIB/接口 IP、ARP/MAC/路由/邻居等服务；部分服务会回退 CLI。
- 本计划将“全局”落实为每台资产的总开关，针对单台有问题设备停采，不设计关闭全网所有设备的系统级开关。
- SNMP 采集关闭不删除设备、凭据、监控计划、采集历史或当前观测；监控配置同步会从运行目标中移除该设备，恢复开关后按既有周期重新采集。
- 已经在外部 LibreNMS 独立纳管的设备仍由该 LibreNMS 实例按自身配置轮询；本开关控制 Nexora 发起的自动 SNMP 采集以及后续的自动纳管，不修改外部实例已有设备状态。

## 影响范围

- 资产新建/编辑表单；批量导入继续使用默认开启，不增加可关闭的 Excel 字段。
- PostgreSQL 设备字段、资产 API 读写/审计，以及监控目标自动重编译。
- SNMP exporter、硬件轮询、在线探测、接口、IP Locator、拓扑与路由采集边界；CLI fallback 仅在采集器原本支持时保留。

## 实施步骤

1. 以 `devices.snmp_collection_enabled` 为唯一存储字段，新增 PostgreSQL migration，缺省/旧数据均为开启。
2. 统一通过 helper 判定设备开关；exporter 目标编译跳过关闭设备，硬件轮询、探活和 SNMP-first 采集跳过 SNMP，并保留已支持的 CLI 回退。
3. 资产新建/编辑表单提供默认开启的 SNMP 开关；导入写入设备字段默认值；列表和详情 API 将设备值返回给编辑表单。
4. 开关变更写入资产审计，并触发监控目标同步；不删除 credentials、历史观测或计划定义。
5. 用 PostgreSQL 验证建档默认值、导入默认值、编辑启停、exporter 目标剔除/恢复、硬件轮询跳过、在线探测转 ICMP/端口及 CLI 回退。

## 验证与回滚

- 先跑资产导入/编辑、开关策略、SNMP poller、monitoring compiler 和 IP Locator 相关回归，再跑 TypeScript、隔离构建及 PostgreSQL-only scanner。
- 开关缺失或旧数据空值均解释为开启；迁移失败不得将现有设备转为关闭。
- 回滚移除本功能的判断/UI 和监控目标同步字段；新增列可保留为默认开启，不删除既有采集事实、凭据或设备策略。

## 文件边界

主 Agent 负责设备数据契约、统一判定 helper、跨采集路径集成、文档与最终验证；前端执行者只负责资产表单与 UI 类型文件。具体文件以只读审计后收敛，不批量重构采集器。
