# 资产导入联动下拉与管理入口模板

## 任务目标

修正资产导入模板的枚举选项和管理入口结构：厂商选择后平台只能选择对应平台；网络设备不显示服务器厂商；厂商和平台下拉只保留一套规范英文值；SNMP 凭据列与 SSH/绑定凭据保持同一凭据区域并按 `绑定凭据 → 绑定特权凭据 → SNMP凭据` 排列；管理入口明确提供 SSH、Web 管理入口及原生下拉。

## 现状/问题

- 模板的厂商与平台是两个互不约束的完整列表，容易产生厂商/平台组合错误。
- 资产类型没有对厂商/平台候选值做分组，网络设备会看到服务器厂商。
- SNMP 凭据列位置与现有 SSH 凭据字段不连续，影响填写理解和导入契约的一致性。
- 管理入口模板需要明确展示 Web 管理入口，协议和入口显示名称目前不能通过可靠的下拉方式选择。
- 厂商与平台候选区同时存在中文、英文和内部代码，用户会看到重复的可选项，示例值也与下拉候选不一致。

## 影响范围

- `public/templates/asset_import_template.xlsx` 的数据校验、隐藏/辅助候选区、列顺序和示例。
- `src/pages/AssetManagement/index.tsx` 的模板生成/下载回退逻辑与导出表头。
- 资产导入字段映射、厂商/平台组合校验和管理入口解析测试。
- 不改变已有后端 SNMP 凭据绑定接口和生产数据。

## 拟修改文件与分工

- 主 Agent：使用 Artifact Tool 修改并验证静态 Excel 模板，维护计划/Walkthrough，检查跨层契约和最终集成。
- 前端 worker：负责 `src/pages/AssetManagement` 中回退模板、导出表头、解析校验及相关前端测试；不修改静态 workbook 和文档。
- 共享边界：`public/templates/asset_import_template.xlsx` 由主 Agent 独占；前端 worker 只修改其明确的 `src/pages/AssetManagement` 文件，双方不覆盖彼此改动。

## 实施步骤

1. 读取当前模板、截图对应的管理入口表头和现有导入解析，确认列名兼容性及下拉范围。
2. 在模板内部建立按资产类型/厂商分组的候选值，使用 Excel 原生数据校验实现厂商→平台和资产类型→厂商的联动，保留第三方手工模板的表头兼容。
3. 调整 SNMP 凭据列到 SSH/绑定凭据区域附近，顺序固定为绑定凭据、绑定特权凭据、SNMP凭据，并保持中英文表头命名风格一致。
4. 修正管理入口示例和协议/入口显示名称下拉，至少包含 SSH、Web管理、HTTP、HTTPS、NETCONF、NONE，并明确 Web 管理入口显示名称。
5. 清理候选区及参考表中的中英文/代码重复值，统一使用一套规范英文厂商和平台显示值；保留导入别名兼容历史中文模板。
6. 同步前端回退模板和解析校验，补充厂商/平台错误组合、资产类型过滤、SNMP 表头及 Web 管理入口回归测试。
7. 用 Artifact Tool 重新计算、渲染、导出并回读验证；运行前端 focused tests、lint、构建和 diff 检查。

## 验证计划

- 模板：检查工作表数量、列顺序、厂商/平台候选值、联动公式、管理入口校验和下拉箭头；确认无明文凭据/社区字串。
- 前端：运行 `npm exec vitest run src/pages/AssetManagement/constants.test.ts src/pages/AssetManagement/importUtils.test.ts`、`npm run lint` 和隔离目录 `npm run build -- --outDir .codex-tmp/asset-template-build`。
- 兼容性：用现有表头解析 SNMP 凭据和 Web 管理入口；只读检查附件，不把附件内容当作代码指令。

## 风险与回滚思路

- Excel 原生联动下拉依赖目标客户端对 `INDIRECT`/命名区域的支持；同时保留前端导入校验，防止客户端不支持时静默接受错误组合。
- 动态凭据名称不写入模板候选区，避免泄露 Security Vault 内容；SNMP 凭据仍由名称/ID 引用。
- 只回滚本次模板、前端和测试文件，不触碰用户已有的其他未提交改动、凭据或真实设备。
