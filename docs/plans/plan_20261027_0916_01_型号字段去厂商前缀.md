# 型号字段移除厂商前缀计划

## 任务目标

让资产、设备、机柜和同步结果中的型号只保留型号名称；厂商继续单独保存在 `vendor` 字段。对所有厂商，仅移除型号开头与已识别厂商字段完全对应的“厂商名 + 空格”，不改变型号代码或产品系列。

## 现状与问题

- H3C ENTITY-MIB 返回值如 `H3C S6850`、`H3C F1060`，当前被原样写入型号字段和手动同步结果。
- H3C `sysDescr` 解析也构造带 `H3C` 前缀的型号；其他来源可能同样在型号文本前带品牌。
- 旧的已保存型号可能已含前缀，用户手动重试时需一起规范化，避免因旧值优先级而继续显示品牌。

## 影响范围

- 通用厂商前缀规范化：只移除字段开头精确匹配的 canonical vendor label；不改字段中间内容或未匹配前缀。
- H3C `sysDescr` 型号解析，以及 SNMP ENTITY-MIB / operator / existing model 候选的导入优先级。
- 设备、资产、机柜设备类型和手动同步结果中型号文本的一致性。

## 实施步骤

1. 增加基于已识别厂商字段的通用前缀移除 helper，大小写不敏感，只移除精确的开头厂商名和一个分隔空格。
2. 对 H3C `sysDescr` 与 ENTITY-MIB 型号候选、已填写/已存型号应用规范化，并让 `detected_model`、`synced_model` 和机柜型号键使用同一无厂商前缀值。
3. 回归覆盖 H3C ENTITY-MIB / sysDescr、其他厂商带前缀、型号不带前缀、已有旧前缀值和型号代码内部出现类似厂商文字的边界。

## 验证计划

- 运行 SNMP identity / ENTITY 型号选择测试和资产导入/手动同步隔离 PostgreSQL 聚焦测试。
- 运行 `py_compile`、PostgreSQL-only 策略扫描和 `git diff --check`。
- 不操作真实设备或资产记录；用响应夹具验证前端显示字段无需再拼接厂商。

## 风险与回滚

- 仅处理型号字段最前面的精确 canonical vendor 字符串；型号内部的厂商相似字符、产品系列名和型号后缀均保留。
- 已有记录不会自动批量回填；重新导入或手动 SNMP 同步时按新规则规范化。
- 回滚仅恢复型号候选解析逻辑和对应测试，无数据库迁移。
