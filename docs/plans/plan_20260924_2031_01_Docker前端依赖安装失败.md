# Docker 前端依赖安装失败

## 任务目标

修复 `docker compose build` 在前端依赖安装阶段因 `better-sqlite3` 编译失败而中断的问题，并复查今天 Dockerfile 的提交是否引入了构建故障。项目运行时使用 PostgreSQL，不应为了前端镜像构建安装 Promptfoo 的 SQLite 测试适配器。

## 现状与问题

Dockerfile 的 Node 构建阶段执行 `npm ci --include=dev`。开发依赖 `promptfoo` 引入 `better-sqlite3`；其预编译包下载超时后，`node-gyp` 回退本地编译，但 Alpine 构建阶段没有 Python 和编译工具，导致失败。

## 影响范围

仅影响 Dockerfile 的前端构建阶段。PostgreSQL 服务、运行时依赖和现有部署数据不变。

- `docs/walkthrough/walkthrough_20260924_2031_01_Docker前端依赖安装失败.md`

## 实施步骤

1. 对照今天 Dockerfile 的提交记录与用户提供的失败日志，确认失败步骤及其与前后阶段的关系。
2. Docker 前端阶段改为仅安装生产依赖；前端打包器及 Tailwind Vite 插件仍在生产依赖树中。
3. 直接调用 Vite CLI 并保留原有 Node 内存上限，避免依赖仅用于包装命令的 `cross-env`。
4. 检查变更，并执行可用的前端构建及依赖树验证。

## 验证计划

- 在临时目录执行 `npm ci --omit=dev`，确认安装成功且没有安装 `better-sqlite3`，并确认 Vite 构建所需模块可用。
- 运行仓库前端构建，验证 Vite 命令和应用资源可正常打包。
- 检查 Dockerfile 改动和工作树；若当前环境没有 Docker，则说明无法在本机完成容器镜像构建。

## 风险与回滚思路

如果某个前端打包插件实际只存在于 devDependencies，生产依赖安装可能缺少它；通过生产依赖树检查和构建验证及时发现。回滚时恢复 Dockerfile 原有依赖安装与构建命令即可，不涉及数据卷或数据库迁移。
