# Agent 代码规范补充计划

## 任务目标

在 `.agents/AGENTS.md` 中补充可执行的代码规范要求，明确后续 Agent 修改代码时的架构、后端、前端、数据库、网络设备适配、测试和安全标准，提升交付质量一致性。

## 现状/问题

- 当前 `.agents/AGENTS.md` 已包含文档归档、数据库选型、skills 路由、Agent 协作和通用质量安全约束。
- 现有规则偏流程和质量门禁，缺少“代码应该怎么写、怎么分层、怎么验证”的细粒度规范。

## 影响范围

- `.agents/AGENTS.md`
- 后续所有由 Agent 执行的代码修改、测试、评审和交付说明。

## 拟修改文件

- `.agents/AGENTS.md`
- `docs/plans/plan_Agent代码规范补充.md`
- `docs/walkthrough/walkthrough_Agent代码规范补充.md`

## 实施步骤

1. 检查 `.agents/` 目录现有规则、roles 和 skills。
2. 在 `.agents/AGENTS.md` 增加“代码规范与实现标准”章节。
3. 覆盖通用原则、后端、前端、数据库、网络驱动、测试、可观测性和文档要求。
4. 校验 Markdown 内容可读、编号连续、与已有规则不冲突。

## 验证计划

- 人工检查新增章节结构和中文可读性。
- 使用文本检索确认新增章节存在。

## 风险与回滚思路

- 风险：规范过细可能限制合理实现。通过使用“优先/必须/避免”的分层表述降低僵化。
- 回滚：还原 `.agents/AGENTS.md` 新增章节和本次归档文档即可。
