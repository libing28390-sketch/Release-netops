# 多邮件通道与收件人管理

## 目标
将 `/management/notifications` 从单份 SMTP 设置升级为邮件通道列表。每条通道有独立 SMTP 参数、账号凭据、收件人和启停状态；管理员可以新增、编辑、删除、启用/停用，并从列表快捷发送测试邮件。保留原三步 SMTP 向导作为新增/编辑流程。

收件人可由系统用户组及多个系统用户组合。用户组依据现有 `users.group_name` 动态解析；发送时仅解析当前租户内状态为 active 且有邮箱的成员，不复制静态邮箱快照。

## 现状证据
- `notification_smtp_configs` 已有 `id`、`tenant_id`、`name`、`enabled` 和加密凭据，但 API 保存固定 `name='primary'`，读取和发送也只选一个 SMTP 行。
- 告警规则选择的是 `email` 通道类型，不绑定 SMTP 配置 ID；邮件 outbox 原来每个告警只有一条 email 记录。
- 系统用户组当前通过 `users.group_name` 表示，为自由文本分组；没有独立组实体或组成员表。
- 对象存储管理页已有可复用的配置列表、行内测试/编辑/删除、状态展示和表单交互。

## 方案与接口约束
1. 复用 `notification_smtp_configs`，新增用户可见名称和 JSON 收件人目标字段。旧 `primary` 行迁移后作为既有通道保留；空收件人目标的旧通道继续使用原用户个人邮件通知订阅，确保升级兼容。
2. 新增按配置 ID 管理的 API：列出、创建、更新、启停、删除、连接测试和测试邮件；密码仅返回是否配置，不返回密文。另提供同租户 active 用户和 `group_name` 选项。保留原有单通道 API 供旧调用方过渡使用。
3. 若租户有自己的 SMTP 配置，邮件告警只对该租户的启用配置投递；没有租户配置时才按既有规则回退共享默认配置。邮件专属 outbox 按配置 ID 展开为独立任务，配置间失败和重试互不影响。旧 `workspace` 个人偏好通知继续兼容旧 `primary` 通道。
4. 列表行快捷测试邮件只发给当前操作管理员的邮箱，避免一次点击群发给配置的所有收件人；向导继续提供连接测试和可指定测试收件人的投递测试。
5. 删除最后一条租户级配置且存在共享默认配置时，保留空的租户覆盖标记，避免意外重新启用共享默认。删除其他配置按 ID 物理删除。
6. 前端列表展示通道名称、SMTP 发件地址/主机、收件组与人数、状态、更新时间和行操作；按对象存储管理页样式复用公共 `DataTable`，新增/编辑沿用三步向导。
7. 服务商选择器使用“国内邮箱”分类，卡片不重复渲染分类字样，每家使用独立轻量品牌标记；移除世纪互联版独立卡片，保留 Microsoft 365 国际版。

## 追加要求与交付约束
- 邮件通道管理列表采用对象存储管理页的紧凑配置表格布局，保留可读的测试、启停、编辑、删除行操作和行内测试反馈。
- 用户明确要求推送并在浏览器确认 GitHub Actions 成功后才关机。已核实 `.github/workflows/release.yml` 在普通 `main` 推送时会先运行构建门禁，再将清理后的发行树 force-push 到 `libing28390-sketch/Release-netops`；普通分支推送不会运行 tag 发布或百度网盘上传。该自动同步作为已知的推送工作流副作用纳入交付，并会在浏览器核对工作流结果。

## 验收要点
- 租户管理员能创建并独立修改/启停/测试/删除多条 SMTP 通道；SMTP 密码永不返回客户端。
- 同一通道可选择多个系统用户组和多个个人用户；成员变化后下次告警按实时组成员发送，地址去重且隔离租户。
- 通过 `email` 规则通道投递时，每个启用 SMTP 配置形成独立 outbox 目标和重试状态。
- 原 `primary` 配置、已有用户个人邮件偏好、共享默认回退语义保持兼容。
- 前端 lint、Python 语法解析、迁移/接口的静态审查和 `git diff --check` 均通过；不发送真实邮件，不在本地执行测试套件。获得发布副作用授权并推送后，通过浏览器确认对应 GitHub Actions 完成成功，再执行用户指定的关机。

## 风险与回滚
- 系统组是用户资料上的自由文本组名，没有稳定组 ID；重命名用户组会使目标名称不再匹配原组，管理员需在通道中更新所选名称。
- 多条启用配置会各自发送邮件；通道的启停状态和当前收件人选择决定真实告警的投递目标。
- 向 `main` 推送会触发自动发行同步工作流，将清理后的内容 force-push 到独立发行仓库；用户已授权 push 并要求检查 Actions。
- 迁移采用新增字段和旧行回填；回滚代码时保留新列和配置数据，不删除用户设置。若需回退功能，先恢复兼容的单通道 API/发送逻辑，再择期另行处理数据字段。
