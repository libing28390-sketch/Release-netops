# 接口快照回归断言修正计划

## 任务目标

修正 Actions 中两条因接口状态采集契约更新而失效的回归断言，使测试验证当前 SNMP 优先行为和 PostgreSQL 布尔绑定。

## 现状与问题

- `_upsert_interfaces` 在成功的 IP 接口快照中清除缺失接口的 IP/L3 投影，但保留由 SNMP IF-MIB 维护的状态。
- 旧测试仍要求缺失接口状态变成 `unknown`，与当前代码契约冲突。
- SQL 在状态保护逻辑中新增两个占位符，导致布尔兼容测试依赖的固定参数下标失效。
- 最近一次 Actions 的业务全量测试为 2262 passed、2 failed、1 skipped；失败仅为上述测试。

## 影响范围

仅调整 `backend/tests/vendor_audit/test_collection_regressions.py` 中的旧断言，并增加任务计划和验证记录。

## 拟修改文件

- `backend/tests/vendor_audit/test_collection_regressions.py`
- `docs/plans/plan_20260919_1854_01_接口快照回归断言修正.md`
- `docs/walkthrough/walkthrough_20260919_1854_01_接口快照回归断言修正.md`

## 实施步骤

1. 更新缺失接口状态断言，确认 IP 字段被清理且原 SNMP 状态得到保留。
2. 从 SQL 中定位 `is_l3` 和 `ip_enabled` 对应占位符，避免硬编码其他参数位置。
3. 运行接口回归测试与 SNMP 优先采集测试。
4. 检查 PostgreSQL-only policy scanner，并记录验证结果。

## 验证计划

- `.venv/Scripts/python.exe -m pytest backend/tests/vendor_audit/test_collection_regressions.py -q`
- `.venv/Scripts/python.exe -m pytest backend/tests/vendor_audit/test_snmp_first_interface_collection.py -q`
- 仓库 PostgreSQL-only policy scanner（若项目提供）。

## 风险与回滚思路

本次只更新与已实现行为冲突的测试断言，不改运行时代码。若验证显示状态保留不符合产品契约，可还原本测试文件的改动并重新评估采集状态所有权。
