# 拓扑 SNMP 优先与 CLI 回退

## 目标

按用户最新明确要求：本轮 SNMP LLDP 完整成功就直接使用 SNMP，不建立 SSH 会话、不执行 CLI 邻居/聚合命令；SNMP 未配置、失败、数据不完整或记录不可用时才回退 CLI。回退场景继续汇总有效证据，统一进行本轮身份匹配、去重和链路计算。

## 现状与证据

- 用户提供的 16:19 日志包含全部 8 台设备 SNMP 成功后 `collecting CLI observations for protocol reconciliation`；本轮数据库协议状态也均为 SNMP success / SSH success，方法 hybrid。
- run `02e23e93-5d8f-4643-b968-573efd193c9e`：8 成功、34 观测全部匹配。日志 16 links 为全局图数量，当前站点实际 11 条（9 物理、2 聚合）；额外 5 条不在该 8 台设备范围。
- 当前 `_collect_device_observations` 在成功 SNMP 后也继续 CLI。旧成功路径测试未配置 SSH，未能覆盖这个违背要求的行为。
- 本机 IP 身份采集还存在独立的 CLI 回退，需要遵守 SNMP 主路径明确不尝试 SSH 的选择，避免从辅助采集重新开启 SSH。
- 用户进一步指出正常 SNMP 后仍显示 IP。只读确认 `.0.1/.2/.3/.6` 的设备与资产 hostname 均为 IP，而设备 sys_name 已有实际名称；画布仅读取 hostname，LLDP 成功路径未调用导入时的 hostname 同步。常规 SNMP 健康查询只更新 sys_name，不能作为本轮已验证名称自动写回的证据。

## 影响范围与文件边界

- 后端执行 Agent：只修改 `backend/services/topology_service.py` 的 `_collect_device_observations` 与 `backend/tests/topology/test_snmp_lldp_discovery.py`。不得修改本轮身份、快照、历史清理和其他用户已有代码。
- 主 Agent：`backend/services/topology_local_identity_service.py`、`backend/tests/topology/test_topology_local_identity.py`，统一集成、公共验证与配对 walkthrough。
- SNMP 主路径包完成后，后端 Agent 负责新增 `backend/services/topology_hostname_service.py` 和 `backend/tests/topology/test_topology_hostname.py`；主 Agent 负责在已交回的 `topology_service.py` 集成调用。两人不同时编辑同一文件。
- 主 Agent 补充 `backend/tests/topology/test_topology_run_identity.py` 的发现入口集成断言，覆盖本机名同步先于观测写入、可选读取失败不影响邻居和 SNMP-only 不执行聚合 CLI。
- 应用 netops-topology-engine、netops-backend、netops-quality-gate；不改 API 字段、数据库结构或前端。

## 实施步骤

1. SNMP 完整且有效时提前返回 method=snmp；SSH 协议状态为 not_attempted，attempted_methods 只记录 snmp，不检查 SSH 端口。
2. 完整空 LLDP 表作为正常的 no_neighbors 快照，不因无邻居触发 CLI。非空但无可用记录、partial、异常与凭据缺失仍回退。
3. partial SNMP + CLI 的有效结果保持现有合并、去重与协议异常状态；不丢弃部分有效证据。
4. 辅助本机 IP 采集遇 SSH not_attempted 时不执行 CLI；SNMP 失败且实际进入 CLI 回退时仍允许取 CLI 本机 IP。
5. 用 mock 验证有配置 SSH 的 Cisco/Huawei/H3C 成功 SNMP 零 CLI、空快照、失败回退、部分回退、接口身份辅助路径和既有本轮匹配。
6. 本轮 SNMP LLDP 完整时使用相同已解析目标/凭据读取设备自身 `sysName.0`，不从邻居名或旧 sys_name 推断。读取失败不影响有效邻居；仅在当前 generation 有效时将空/IP占位名称同步到资产、设备和本轮观测。已有真实名称冲突不覆盖；IP形式 sysName 不用于命名。复用现有 hostname 原子同步和监控目标同步机制，无 CLI。
7. 新增隔离 PostgreSQL 测试，验证设备/资产同步、名称冲突、无资产、旧 generation、防并发覆盖和 sysName 失败隔离。前端发现结束会刷新设备库存，无需改变名称优先级。

## 验证计划

执行两份采集单测、受影响本轮身份/快照/历史清理/链路证据/发现并发测试，Python 编译与 PostgreSQL-only 扫描。无前端和 API 契约变化，不重复前端构建或无关全量测试。本次不触发真实发现，不重启用户现有后端，以免中断其操作。

## 风险与回滚

SNMP 已完整成功后不再用 CLI 补列，全部字段以本轮 SNMP 与已确认的资产事实为准；无法证明归属的地址继续待确认，不能猜测。CLI 异常不会污染成功 SNMP。回滚仅恢复采集主路径提前返回和辅助路径选择判断，保留用户其他未提交修改。

SNMP 完整快照提前返回、辅助身份采集零 CLI、本轮 sysName 校验和占位名称原子同步均已接入；已有真实名称、管理 IP 修改/清空、资产缺失和旧 generation 受保护。相关 81 个不同测试通过，Python 编译及 diff 检查通过，PostgreSQL-only 扫描 0 violations。使用隔离数据库和模拟设备验证，没有触发新的现场发现或重启用户服务，现场名称需在运行新代码的下一轮发现时更新。
