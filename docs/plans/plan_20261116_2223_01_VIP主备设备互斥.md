# VIP 主备设备互斥

## 目标与现状

新增/编辑 VIP 时，绑定控制设备和备用设备目前可以选为同一台设备；服务层 create/update 也未拒绝该组合。业务规则要求主备设备不同。

## 影响范围

- `src/pages/IPVlan/VIPManagementTab.tsx`：备用设备检索候选排除主设备；主设备变更导致与备用设备相同时清空备用选择；提交前显示校验错误。
- `backend/services/ipam_service.py`：在 VIP 创建和更新路径统一校验有效主备设备 ID 不相同。
- 不修改 API 字段、数据库结构或已存 VIP 数据。

## 实施步骤

1. 前端备用设备搜索结果排除当前主设备；主设备改成当前备用设备时清空备用值，并保留可选空值行为。
2. 表单提交时检查最终有效主备值，重复时阻止提交并显示明确错误。
3. 编辑表单清空可选设备时在数据库中写为 `NULL`，避免空字符串残留。
4. 服务层在创建和更新时复用相同的设备互斥校验，直接 API 调用及历史冲突记录编辑也不能保留冲突组合。

## 验证计划

- 静态检查前端候选过滤、提交校验和后端 create/update 调用位置。
- 本轮不新增或运行测试、不构建、不做浏览器交互；用户未要求验证。

## 风险与回滚

无数据库迁移。已有相同主备设备的历史 VIP 在编辑并保存前需要调整其中一个设备；仅回滚前后端校验代码即可恢复原行为。
