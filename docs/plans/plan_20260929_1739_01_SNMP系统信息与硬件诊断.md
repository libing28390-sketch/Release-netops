# SNMP 系统信息与硬件诊断

## 目标与现状
SNMP 诊断已有 WALK、接口 IF-MIB 与 LLDP。增加独立系统信息和硬件指标入口；系统信息指设备名称、厂商、软件平台、型号和版本。硬件指标复用实际 LibreNMS/标准 MIB 发现服务。

## 影响范围与文件
- backend/api/devices.py：受角色和资产可见性约束的两个只读诊断接口。
- src/components/SnmpMib/components/LiveWalkInspector.tsx：独立页签、请求状态和诊断结果。
- src/pages/SnmpWalkPage.tsx：开启两个页签。
- backend/tests：对应接口的回归检查。

## 实施步骤
1. 复用资产凭据解析和现有采集服务。
2. 系统信息区分实时识别与资产回退字段。
3. 硬件指标展示分类状态、读数、OID、质量及截断提示。
4. 处理请求失败、切换设备和卸载时的请求取消。
5. 保留已有 WALK、接口和 LLDP 行为。
6. 修复上次 Actions 的 4 个失败：看板测试改为校验当前设备详情契约；校准 PEN 24681 的识别来源预期；隔离 LibreNMS 可选 MIB 查询错误，避免 PostgreSQL 事务中止影响后续资产读取。

## 验证计划
用户最初不要求运行验证，随后明确要求完成检查后直接 push，并要求修复上次 Actions 失败。执行 TypeScript 检查、生产构建、SNMP 诊断接口与平台识别回归、两项 Actions 看板契约回归、PostgreSQL-only 扫描及 diff 检查；不访问真实网络设备。只提交本任务改动，保留其他未提交编辑。

## 风险与回滚
探测依赖设备 SNMP 权限和已有 LibreNMS 适配范围。页面展示有界传感器样本并标出总数；本次不修改设备配置或资产记录。回滚本任务提交可移除新入口和接口。
