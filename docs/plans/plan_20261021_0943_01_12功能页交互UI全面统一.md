## 目标与范围

用户指出 Assets 新增资产弹窗仍显得拥挤，并明确要求其余交互式 UI 全部统一修改。本计划因此覆盖 Nexora 首页定义的全部 12 个功能入口及其高频子视图：Operation Workspace、Monitoring、Alerts、Assets、IPAM、CMDB Core、Config、Automation、Tickets、Capacity and Reports、Platform、AI Center。这里的 Dashboard 指这 12 个业务入口，不是 Grafana dashboard。

审查并实际统一所有页面中可见的表单字段、选择器、筛选/重置、分段切换、菜单/弹出层、对话框/抽屉、行操作、批量操作和持久操作栏。统一的内容包括控件高度/字号/标签层级、边框/主题/焦点/禁用/加载状态、操作按钮层级、弹层间距/滚动/关闭方式及窄视口排布。不能仅补 ARIA 名称、错误状态或等待状态就算完成；每个功能页都要有明确的交互 UI 源码复核和结果记录。只修改确有不一致或可读性/可操作性缺陷的界面，不为了改动数量重排没有问题的组件。

保留 API/schema、数据与权限契约、设备操作、凭据与密码保护、危险操作确认、筛选/分页语义、国际化和路由行为。优先复用已有 FormField、FormLayout、ActionButton、ActionIconButton、TableListControls、Pagination 和 `--ui-*` tokens；不增加 UI 框架或依赖。第三方嵌入内容内部（包括 Grafana）不属于此工作。

## 执行步骤

1. 对照 `src/pages/HomePage.tsx`、`AppMainContent.tsx` 和 `page-coverage.md` 确认 12 个入口和实际组件；并行逐页盘点有交互 UI 的实际文件及最明显的视觉/操作差异。
2. 用现有共享控件和 `ui-foundations.md` 建立统一审查尺度；主 Agent先复核共享字段、按钮、弹层和选择控件，避免页面组各自发明新样式。
3. 按上面的文件边界实施真实视觉改进：表单层级和密度、筛选控件排列、按钮主次状态、分段选择态、弹层标题/主体/操作区、窄屏折叠和焦点反馈。对每个入口至少调整一个确认需要改的交互界面；同一入口已有一致且可读的控件时仅记录审查结论。
4. 为会改变行为或状态语义的改动补有价值的组件测试；纯样式更改不新增只断言 CSS 类的测试。保持危险操作和请求状态契约不变。
5. 主 Agent 审查各分支差异与共享调用方影响，运行聚焦测试、TypeScript lint、隔离 Vite build、`git diff --check`；更新逐入口交互 UI 状态和 walkthrough。

## 验收标准

- 12 个入口逐一列出交互组件/子视图、实际修改或审查结论和对应文件；不得把上一批的“已实现”状态直接当作本次 UI 统一完成。
- 表单标签/帮助/错误具备足够字号和对比；字段分组、必填与可选信息清楚；窄视口布局不会挤成不可读的两列。
- 主要/次要/危险按钮和选中/禁用/加载/焦点状态在跨页面同类控件上表现稳定；现有共享控件优先于局部仿制。
- 弹层标题、内容滚动、固定操作区、关闭行为和中英文长度经过源码及测试复核。
- 所有改动保留页面的业务/API/权限契约；共享 CSS/组件修改要覆盖受影响的本计划调用方。
- 默认不调用 browser/computer-use/CUA 工具；用户在后续明确要求后，按该授权进行只读浏览器走查。DOM/辅助功能树和几何数据仅能记为部分浏览器验收，不能替代截图目视与完整键盘走查；未完成这些证据时，不标为 Browser checked/Complete。

## 浏览器走查驱动的第二轮修改

窄屏浏览器 DOM 实测发现：同类交互控件仍存在尺寸差异——表格默认图标动作约 32×32/32×36px、共享小号按钮高 32px、弹窗输入框最小高 38px，而共享 FormField 已使用 40px。页面没有横向溢出，但小图标动作和弹窗字段的实际命中面积仍显局促。

本轮只统一这些跨页面基础尺寸，不改字段顺序、表格密度语义、筛选/分页、设备操作、请求参数或确认流程：

1. 已在现有 `--ui-*` 体系补充共享控件高度与动作目标尺寸：ActionIconButton 小/中号为 36px/40px、超紧凑号为 28px；ActionButton 小/中号为 36px/40px。
2. 已将共享弹窗的输入、选择和文本区域统一到 40px；关闭按钮和主要/次要动作最小高 40px，目标宽度分别 96px/84px，并统一焦点可见状态。AI Provider 新建弹层接入共享对话框 surface、标题栏、操作区与动作按钮。
3. 同一窄视口下 Assets 弹窗实测输入框高 40px、关闭按钮 40×40px、取消/保存按钮分别为 84×40px 和 96×40px，页面保持 530px 宽，无横向溢出。热更新复载后登录态返回登录页，未输入账号或密码；Alerts、Tickets、CMDB 和 AI Provider 的第二轮浏览器尺寸复核未完成。Chrome 截图接口仍超时，故仍不宣称截图目视验收。

共享样式通过同类控件的现有调用方覆盖聚焦测试、TypeScript 与隔离构建。若动作尺寸影响表格可读行数或触发横向页面溢出，回退至原尺寸，仅保留需要放大的弹窗与工具栏目标。

## 表格文字颜色补齐

复核发现共享表格使用了主题主文字/弱化文字 tokens，但部分单元格仍直接用低不透明度黑字或 `text-gray-300/400`、`text-slate-300/400`。这类颜色在浅色主题下对比不足，且不同页面呈现不一致。本轮在共享表格的 `tbody` 中把这些中性弱对比类映射到 `--ui-fg-muted`，永久深色监控表格使用适配暗底的浅色弱化文字；语义状态色、终端输出和业务字段未改。

本轮只补通用视觉基线，不逐页重写单元格业务样式；需要以表格使用页聚焦测试、TypeScript、隔离构建和 `git diff --check` 验证。截图及键盘目视验收仍受既有浏览器限制。

用户随后提供“告警规则”表格截图，显示该页页面级 `#164e63` 规则名称和透明度黑字仍未与共享列表颜色统一。为完成该可见缺口，对 `src/pages/AlertRulesTab.tsx` 的规则名称/普通数据/次要说明、筛选控件、表头、行悬停与选中底色直接接入 `--ui-*` tokens；严重级别、可用性和通知渠道语义色保持现状。最终源码搜索确认不再有固定 `text-[#164e63]`；`npm run lint`、隔离 Vite build（4334 个模块）与 `git diff --check` 均通过。没有新浏览器截图时仍不得称目视验收完成。
