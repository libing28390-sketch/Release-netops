# 实施计划：IPAM 前缀导出与拓扑布局

## 任务目标
为 IPAM 前缀列表增加可用于运维交接的导出，并调整 `/monitor/topology` 的站点概览与设备拓扑画布布局，解决宽屏留白和工具栏遮挡问题。

## 现状与问题
- 前缀页面仅加载当前页（默认 20 条）；后端 `/api/ipam/subnets` 在省略 `page` 时返回当前筛选条件下的完整结果。
- 当前页面无针对该列表的导出入口；旧版 IPAM 页面的导出范围和字段不适用于此列表。
- 站点概览采用固定多列栅格，站点少时卡片只占左侧列。
- 设备拓扑的控制条绝对定位覆盖 SVG 绘图区，图形默认布局也未充分利用宽屏。

## 影响范围
仅改前端 IPAM 前缀列表、拓扑页面/图组件和角色分层布局工具；导出 helper 及其单元测试；同步更新本计划和 walkthrough。保持 API 合约、筛选语义、图模式和节点/链路交互不变。

## 实施步骤
1. 在前缀页增加 XLSX/CSV 导出入口，当前搜索、站点、状态、IP 族筛选保持一致，使用服务端分页每批最多 100 条遍历全部匹配结果；导出单行一条前缀，利用率与地址计数标注为导出时快照。
2. 把分页完整性校验、字段映射、CSV BOM/转义和公式注入防护放入领域 helper，并为跨页读取、失败不生成残缺文件、行映射与危险 CSV 单元格增加单测。
3. 站点总览根据站点数量采用有边界的自适应列数并居中。
4. 将拓扑工具栏移至画布外的正常文档流，单独测量 SVG 视口；同层横向间距按相邻角色层距控制，避免多层图形横向拉长；更新布局 schema 让旧自动布局重新生成，同时保持现有图层与交互。
5. 检查 diff、运行聚焦前端测试、lint 与生产构建，必要时在浏览器检查工具栏和画布的实际边界。

## 验证计划

## 风险与回滚
- 极大前缀库存由现有服务一次返回且服务对每条前缀统计地址数，可能占用较多时间/内存；若实际数据规模证实不足，应另行增加服务端流式导出，不在本次扩展。
- 工具栏改为流式布局后须重新测量实际绘图容器，防止全屏、缩放、悬浮信息卡定位偏移。
- 回滚仅需恢复上述前端文件和测试文件；无需数据迁移或数据库回滚。
