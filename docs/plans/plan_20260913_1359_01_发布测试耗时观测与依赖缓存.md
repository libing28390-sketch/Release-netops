# 发布测试耗时观测与依赖缓存计划

## 目标

在不减少后端测试覆盖、不启用不安全并行的前提下，为 Release workflow 添加慢测试排行，并缓存 Python pip 依赖，降低重复安装耗时。

## 现状与问题

- Release 日志显示后端 pytest 约耗时 8 分钟，但当前 workflow 仅运行裸 `pytest`，没有慢测试排行，尚不能确认主要耗时来自测试调用还是 PostgreSQL fixture setup/teardown。
- Release workflow 的 Python setup 未开启 pip 缓存；截图中的依赖安装步骤约 31 秒。
- PostgreSQL 隔离测试会逐用例创建和删除独立测试数据库；在未确认 worker 级数据库隔离前，不应直接启用 `pytest-xdist`。
- 1 个 Redis 集成测试因需要显式授权才会访问配置的 Redis 而跳过，与 8 分钟测试时长无关，不改变其跳过策略。

## 影响范围与拟修改文件

- `.github/workflows/release.yml`：开启基于 `backend/requirements.txt` 的 pip 缓存；运行全量 `pytest --durations=25`。
- `docs/plans/plan_20260913_1359_01_发布测试耗时观测与依赖缓存.md`
- `docs/walkthrough/walkthrough_20260913_1359_01_发布测试耗时观测与依赖缓存.md`
- `docs/fixes/fix_20260913_1359_01_发布测试耗时观测与依赖缓存.md`

## 实施步骤

1. 检查 release workflow 与 PostgreSQL 测试夹具的隔离行为。
2. 仅增加 pip 缓存与 pytest 慢测试排行；不缩小测试集合，不改变 Redis 授权/跳过策略，不启用 xdist。
3. 验证 YAML 语法、改动范围与 whitespace；确认 Git 暂存只包含本计划列出的发布配置与记录文件。
4. 经用户明确要求后，将本次变更提交并推送到 `main`。

## 分工与文件边界

- 主 Agent：负责方案、`.github/workflows/release.yml` 修改、文档、验证、提交与推送；本计划列出的文件仅由主 Agent 修改。
- `release_pytest_audit` 子 Agent：只读审查 workflow、PostgreSQL fixtures 与并行风险，不修改任何文件。

## 验证计划

- 使用 PyYAML 解析 `.github/workflows/release.yml`，并确认 pytest 命令仅增加 `--durations=25`。
- 运行 `git diff --check`，检查本次工作流差异；不在本地执行 8 分钟全量 pytest，因为本次不改变应用/测试代码或测试选择。
- 推送后由 release workflow 运行完整后端测试，记录实际耗时排行与原有 pass/skip 数。

## 风险与回滚思路

- pip cache miss 或缓存不可用时，setup-python/pip 会按原方式重新下载，不影响依赖正确性。
- `--durations=25` 只增加报告输出，不改变测试集合与断言。
- 如 action setup-python 缓存恢复失败，可移除 `cache` 和 `cache-dependency-path` 两行；如持续集成环境不能接受额外排行输出，可还原 pytest 参数。本次不改测试夹具。
- 推送到 `main` 会触发既有发布同步 workflow；用户已明确要求推送。
