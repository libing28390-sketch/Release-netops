# 拓扑单会话与接口采集契约修复实施计划

## 背景

现场日志显示，六台华为设备的拓扑发现会分别建立 SSH 会话执行 LLDP、接口摘要和 Eth-Trunk 命令。命令本身耗时较短，但每次重复登录带来数秒级连接开销；同时，拓扑链路聚合关系不需要重复刷新 CMDB 接口状态，接口投影也应保持历史的“只采集有 IP 接口”契约。

## 实施范围

1. 在平台注册动作层增加同设备只读会话复用能力。一次会话内按动作顺序发送多条命令，每条回显继续使用自己的动作命令、TextFSM 模板和字段契约解析。
2. 拓扑发现让 LLDP 与 Eth-Trunk 使用同一个 `PlatformActionSession`，并移除重复的接口摘要动作。
3. 将 Huawei SYSTEM 发布动作中的 `get_link_aggregation` 修复为 `display eth-trunk`，通过幂等迁移修复已有发布版本并重算校验和。
4. 恢复 CMDB 接口投影的 IP-bearing 过滤；拓扑只维护必要的物理接口骨架和聚合成员关系。
5. 为前端共享查询补充认证头，避免登录竞态产生匿名 `/api/users` 的 401 请求。
6. 将“单次登录、多条命令、逐条解析、逐条审计”的边界和禁止事项写入代码规范。

## 约束

- 会话只允许绑定同一设备、同一租户范围、同一当前发布版本和同一普通 SSH 凭据角色。
- 会话复用不绕过动作级授权、命令安全校验、发布版本校验、模板范围校验、字段契约校验或审计记录。
- 只读动作不得通过拼接 shell 管道、分号或批量脚本替代逐条命令执行；写操作和配置变更不复用该只读会话。
- 不删除已有接口数据；成功采集时清理过期投影字段，拓扑关系单独维护物理端点信息。

## 验收

- 同一设备的多个平台注册动作只创建一个 Driver/SSH 会话。
- 任一动作解析失败只影响该动作，后续只读动作仍可继续执行。
- Huawei `get_link_aggregation` 不再调用已验证会报错的 `dis eth-trunk`。
- CMDB 默认只返回有 IP 的接口，拓扑仍可使用物理接口骨架关联 LLDP 和聚合关系。
- 注册表测试、厂商采集回归、TypeScript 检查、前端生产构建和差异空白检查全部通过。
