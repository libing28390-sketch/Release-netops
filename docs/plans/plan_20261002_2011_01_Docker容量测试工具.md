# Docker 容量测试工具计划

## 任务目标

提供部署机可运行的完整容量测试工具。复用当前运行容器的本地镜像和实际 CPU/内存/PID 限额，创建独立网络、容器和测试卷；在隔离实例中运行业务 API、数据库、Redis、S3、SNMP、采集写入、时序查询和 Grafana 查询的混合负载，并持续观测容器与宿主机，产出可复核报告。

## 现状与问题

- 原脚本仅为连通性与轻负载预检查，不能回答限额是否合理。
- 本工作区没有 Docker；只能进行 CLI、模拟 HTTP/Docker、协议、数据计算等本地验证，最终镜像启动兼容性需部署机实跑。
- 原部署有 11 个服务，NetOps/Nginx 设置硬限额，其余服务可能无硬限额。不能横向比较不同分母的 MEM %。
- 测试需覆盖数据规模、持续运行和依赖竞争，不能以固定健康 JSON 或 PING 代替业务负载。

部署机 v1.1.3 报告确认 preflight 已通过，但 stage-5 在 5.416 秒时因 `timeout` 失败，`netops` 场景 `scheduled=0`，正式负载调度器尚未启动；`check-final` 容器也在约 6.8 秒后以同一个 `timeout` 退出。只读并行审计定位为 runner 建立 NetOps 会话时的 `POST /api/login` 超时（runner 自身单请求期限 5 秒），不是 `run_job` 的 120 秒 deadline，也不是 OOM、重启或已开始的业务请求超时。报告主机最低可用内存约 63.1%，关键指标完整，容器无 OOM/重启；stage 期间隔离 NetOps 内存约 246 MiB / 2 GiB、CPU 约 50.2%、CPU throttle 为 0%，不能据此认为 limits 触顶。

本轮子 Agent 分工与交接：`verification_worker` 只读核对 report (5) 的阶段、SLO 和资源字段；`complex_worker` 只读追踪 `check-final`/`run_job`/`_make_context()` 调用链。两者均未改文件；结论是当前报告缺少测试 NetOps/DB 仍运行时的日志，且主循环忽略 warmup 的失败摘要。后续修改限定在测试工具 runner、编排、诊断及相应聚焦测试：标明登录超时操作、保存并检查 warmup 摘要、在失败清理前采集自有测试 NetOps 与 DB 的脱敏日志，避免把该次运行误报成真实容量结果。

上述诊断补强已实现为 v1.1.4：`RuntimeContext.login()` 将请求超时分类为 `api_login_timeout`；主流程把 warmup 摘要纳入 `report.json`，warmup 未通过即停止正式档位；失败报告清理前补采本次测试 NetOps、DB、Redis 的日志尾部并应用既有凭据脱敏。README 同步说明 warmup 和登录超时结果。聚焦回归扩展到 51 项通过，Python 编译、Bash 语法、版本命令和 dry-run 均通过。真实 Docker 复测仍须部署机执行，且不得用此次 v1.1.3 结果评估 limits。

## 实施步骤与 Agent 分工

1. 主 Agent 明确接口并维护计划和文档；负责 Bash 入口、主机编排、隔离栈启动、停止保护、数据报告和最终集成。
2. complex_worker 独占 `runner.py`、`snmp_simulator.py` 及负载测试文件；实现数据库/缓存/对象数据准备、HTTP 与协议负载、SNMP 模拟设备。不得修改编排或指标文件。
3. complex_worker 独占 `metrics.py` 及指标测试文件；实现原始累计计数差分、实际限额、CPU 限流、OOM/重启及宿主机采样。不修改负载或编排文件。
4. 镜像与限额从当前部署只读获取；不复用现有持久化卷或真实凭据，生成临时秘密并只通过 stdin/环境传递。所有临时对象附加唯一运行标签，清理先核对所有权。
5. 执行准备、基线、预热、混合阶梯负载和恢复阶段；报告成功延迟、实际吞吐/未发出的请求、数据完整性及资源瓶颈，缺失指标显式标记。

## 验证计划

- Bash 语法、帮助和默认 dry-run，确认 dry-run 不访问 Docker。
- Python 3.11 编译/stdlib unittest，针对 HTTP 成功/失败/超时、禁用代理、TLS/鉴权、SNMP BER、速率调度、指标差分和安全清理。
- 模拟 Docker 命令验证镜像不拉取、限额继承、内部网络、独立卷和失败清理。
- 覆盖 warmup 登录失败时停止升档并保留摘要，以及测试 NetOps/DB 日志脱敏捕获和 runner 登录超时分类。
- 不运行应用全量回归，不连接真实设备，不在本机实跑 Docker。

## 风险与回滚

- 测试实例和原实例共享宿主机，测试会消耗宿主机资源；必须记录主机/生成器压力并在内存余量或容器故障超过保护条件时停止。
- 合成数据和模拟设备不能证明用户所有业务规模均被覆盖；报告明确数据量、成功场景、最高满足阈值的档位和未覆盖项，不自动修改限额。
- 测试写入只在新建容器和独立测试卷发生，网络 internal 禁止外部设备访问。结束清理本次标签对应的临时对象，保留报告。
- 回滚删除新增容量工具与文档，原预检查仍可独立运行。保留用户已有工作树修改，不提交或部署。
