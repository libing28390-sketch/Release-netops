# Linux 巡检报告状态与异常项

## 任务目标

让 Linux 巡检的执行状态、异常明细和各类导出内容与脚本实际输出一致；报告状态使用“正常 / 异常 / 部分采集”等中文表述，导出字段使用中文，并移除健康评分。执行历史行内提供 HTML 与 Excel 直达导出，预览详情不提供下载按钮。

## 现状与证据

- 用户提供的真实输出显示：严重错误 1 项、警告 0 项、未采集 3 项。严重错误是近 24 小时 SSH 认证失败次数达到严重阈值；DNS、NTP 偏差及进程级文件句柄数据存在未采集情况。
- HTML/PDF 模板含有英语状态值和健康评分字段，HTML 报告使用深色背景。
- Playbook 导出映射会按健康分数推导健康状态，并只生成通用失败原因，无法可靠呈现 Linux 脚本输出中的具体异常项。
- Excel/JSON 报告仍包含评分字段或英文机器字段，导致导出内容不一致。
- 后续检查下载的 HTML 报告发现：Playbook 导出直接读取 `phases_json`，但新执行将阶段输出加密存入 `phases_encrypted`，旧字段仅保留 `{}` 占位符，导致报告拿不到真实 Linux 输出并退化成通用失败说明、未采集数为 0。
- 定时执行设备结果写入 `started_at` / `completed_at`，但完成更新没有写入 `duration_ms`；报告又把缺失值默认为 0，显示为“0 毫秒”。
- NTP 同步状态与偏差采集是不同指标：同步状态可为成功，而偏差仍为未采集；报告必须保留该未采集状态。

## 影响范围

- Playbook/Linux 综合巡检执行结果报告下载（HTML、Excel）。
- 执行历史中 Linux 巡检的状态标签。
- 不改动巡检脚本检查阈值、目标设备或调度周期。

## 实施步骤

1. Playbook 导出按现有执行范围权限校验和审计流程读取加密阶段输出，再解析 Linux 巡检原始输出中的异常明细与未采集项，避免只读 `{}` 占位字段；SSH 审计异常需保留失败次数、阈值和来源 IP。
2. 未采集行按具体原因映射检查项；TCP 重传兼容别名与主指标合并，避免把“无 TCP 发送流量”错标为连接状态检查并重复计数。
3. 导出映射根据脚本明细确定异常状态和原因，不再通过评分推导；没有异常时显示“正常”，存在脚本错误时显示“异常”。
4. 对缺少/为 0 的耗时从设备开始与完成时间计算；定时执行保存实际耗时，无法计算时显示缺失标记而非虚假的 0 毫秒。
5. HTML、PDF、Excel、JSON 的用户可见字段与状态值统一中文，删除评分及评分汇总。
6. HTML/PDF 报告改用白底黑字，并在报告中显示脚本给出的错误、警告、未采集数量及对应明细。
7. 执行详情预览不显示下载按钮；执行历史每行直接提供 Excel、HTML 两个导出图标，不再使用下拉菜单。
8. 统一报告文件名为“系统名_报告类型_作业名_开始时间_记录短ID.扩展名”，开始时间使用 `YYYYMMDD_HHmmss`，并清理文件名中的非法字符。
9. 检查工作区已有未提交变更，避免覆盖与本任务无关的修改；完成后记录实际修改和验证情况。

## 验证计划

- 对照用户提供的实际输出确认报告得到 1 项异常、0 项警告、3 项未采集，并展示 SSH 认证失败的具体原因。
- 对 Playbook 加密输出路径确认导出读取真实阶段输出；确认报告不再把占位 `{}` 当作实际输出。
- 确认耗时从开始/完成时间生成，不将数据库默认值 0 当作有效耗时。
- 检查 HTML、PDF、Excel、JSON 输出路径中的用户可见字段和状态映射，确认没有健康评分字段或平均评分。
- 按当前任务允许的范围检查改动；不触发设备连接、脚本重跑或生产部署。

## 风险与回滚思路

- 兼容已有历史执行记录中旧版字段和缺少原始输出的情况：退回使用已存的执行状态与错误原因，不伪造巡检指标。
- 如新报告映射影响非 Linux Playbook 导出，限定解析逻辑只应用于识别出 Linux 综合巡检格式的输出；可回滚报告映射及模板修改，不涉及数据库迁移。
