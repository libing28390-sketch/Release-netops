# IPAM 批量用途与设备自动关联

## 目标

- 选中多个 IPAM 前缀后，可一次性修改网段用途，并沿用单条编辑的人工保护语义。
- 网关设备/接口关联在存在唯一可靠接口证据时自动填入；点对点 `/30` 有两个端点且未指定网关 IP 时不猜测选择。
- 按 Nexora 公共操作栏规范调整页面按钮位置：常驻页面操作与选择后的批量操作分组呈现。
- 明确 `/ipam/reconciliation` 对账数据来源，区分无可比较数据、缓存不可用与有数据但无差异。

## 现状与证据

- `PrefixManagementTab` 仅提供批量删除；单条更新 `network_type` 时会设置 `manual_override=1`、`classification_status='manual'`，阻止后续自动分类覆盖。
- 网段表单的“网关设备”当前为手工下拉；单条自动网关推断仅发生在后台前缀发现流程，且读共享 `interfaces` 表。手工创建表单没有自动匹配；保存 payload 也未使用表单中的 `gateway_interface_id`。
- 用户截图中的 `10.200.24.0/30` 最近成功 CMDB 快照有 R2 的 `.1` 与 R4 的 `.2` 两个物理接口端点。没有填写网关 IP 时，无法安全指定单一网关设备。
- 公共 `PageHero` 适合放导出/创建/接口生成等常驻操作；批量编辑/删除应紧邻表格选择状态呈现，删除使用危险样式。
- `/ipam/ips` 的只读地址投影有 7 条接口采集记录、5 个设备报告 CIDR，7/7 均未匹配到站点 IPAM 前缀；`subnet_prefix` 为空是预期数据边界。设备报告 CIDR 在独立列显示，但未纳管状态目前只表现为 `-`。
- 当前只读数据：已分配 `ip_addresses` 为 0、活动 `network_endpoints` 为 0、成功 CMDB 接口快照 IP 观察为 55。对账查询只使用前两类，不比较 CLI 接口快照；当前空结果不能解释为对账通过。

## 接口约束

- 新增 `POST /api/ipam/subnets/batch-update-network-type`：校验 ID 列表、用途值及每条资源范围后，在一个 PostgreSQL 事务中锁定并更新全部记录；任何条目无效时整体回滚。更新用途时同步人工保护字段，并写一次审计事件。不新增 schema 或 migration。
- 新增只读网关匹配查询，读取设备最新成功代次的 CMDB 接口观察并限定站点/租户。填写网关 IP 且存在唯一精确接口匹配时，可自动填设备；网关 IP 为空时，只对唯一 SVI 候选自动匹配。多个端点或缺少站点/证据时只显示候选/说明，不猜测。快照无共享 `interfaces.id` 时不伪造接口 ID。
- 对账 summary 返回可比较的 IPAM 已分配地址数、15 分钟窗口内活动端点数及不参与本对账的接口快照观察数；未登记/不一致使用当前活动端点，长期未发现使用 `network_endpoints` 历史最后观测。前端说明来源范围与空结果含义，不把接口观察并入 findings。
- 若存在无法安全归属范围的端点，所选明细分类即使为空也须明确提示这些排除项；“无差异”只能描述当前可比较分类，不能掩盖未归属端点。缓存新鲜度应与窗口内活动端点输入一致，避免 inactive 记录让缓存显示为新鲜。
- 选择人工指定的设备后，自动匹配不得覆盖。保存时实际提交表单中的有效 `gateway_device_id` 和 `gateway_interface_id`。
- `/ipam/ips` 将“已纳管 CIDR”与“设备报告网络”合并为一个 `IPAM登记网段 / 设备报告CIDR` 列：有 IPAM 关联显示台账 CIDR；只有接口观察时显示设备报告 CIDR及“IPAM未登记/待 VRF 确认”；两值不同时分行保留。不得复制观察值成已登记值或自动创建前缀。导出仍可保留两个独立字段。
- PageHero 右上保留导出、接口生成、新增网段；选中行后的批量改用途和批量删除移至表格上下文操作栏。

## 文件分工

- 后端 Agent：`backend/api/ipam.py`、`backend/schemas/schemas.py`、`backend/services/ipam_service.py`、相关 PostgreSQL 隔离测试。
- 前端 Agent：`src/pages/IPVlan/PrefixManagementTab.tsx`、`src/pages/IPVlan/IPAddressTab.tsx`、`src/pages/IPVlan/IPReconciliationTab.tsx`、页面域内的轻量请求/匹配 helper 与测试。
- 主 Agent：本计划/走查、统一接口审查、集成验证。

## 验证计划

1. PostgreSQL 隔离测试覆盖批量用途原子性、权限/范围拒绝、人工保护字段，以及唯一/歧义/无网关接口匹配。
2. 前端窄测试覆盖选择批量用途、错误保留选择、自动匹配不会覆盖手动设备、歧义端点不自动绑定。
3. 运行 TypeScript 检查、Vite 构建、PostgreSQL-only 扫描及 `git diff --check`。
4. 浏览器检查常驻操作与表格上下文批量操作的位置、`/ipam/ips` IPAM登记状态、`/ipam/reconciliation` 无数据提示，并核对 `/30` 显示两个端点但不误选网关。

## 风险与回滚

- 批量用途变更按单条编辑语义会人工保护所有所选网段；操作前在模态框显示影响数量与用途。
- 自动绑定只写入唯一的、与选中站点一致的网关设备证据；歧义/缺证据时保留未绑定。回滚可移除新端点/UI；不需数据库结构回滚。
- 不修改监控代码、设备解析模板或当前真实 IPAM 记录。

## 执行结果

- 追加页面文案简化：用“已登记 IP 与网络发现 IP 核对”解释用途，只展示两侧数量；移除缓存窗口、接口快照统计和数据库表名提示，保留简短的数据不足/过期空态。

- PostgreSQL 隔离测试、前端空态测试、TypeScript 检查、Vite 临时目录构建、PostgreSQL-only 扫描和 diff 检查均通过；细节见配对 walkthrough。
- 用户授权的本机服务自动恢复已执行，HTTP 页面与 API 健康检查通过。CUA 通道不可用，未完成浏览器 DOM/交互验收；不能把 HTTP 200 视为完整浏览器通过。
- 空结果边界已进一步明确：未归属端点会阻止“无差异”空态；缓存新鲜度和展示时间戳对齐活动端点输入。
