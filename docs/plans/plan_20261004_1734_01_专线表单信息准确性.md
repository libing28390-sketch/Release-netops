# 专线登记表单模型与可读性优化计划

## 目标

以“登记一条专线”为表单主线，先修复接口候选项和 SNMP 自动读取的准确性，再把线路信息、本端/对端、带宽和监控设置按业务顺序组织，减少内部术语导致的误填。

## 现状与问题

- 浏览器页面中的接口候选项显示 `ifIndex --`，而后端保存逻辑要求接口必须在 CMDB 中具有有效 `if_index`，造成可选项和实际可保存条件不一致。
- 后端 `/api/monitoring/wan-options` 经 `list_wan_link_options_scoped` 调用 `list_wan_link_options`，目前返回设备的全部接口行，未剔除未被 SNMP/IF-MIB 确认的候选接口。
- A 端摘要直接显示站点、设备和接口 UUID，页面中难以识别实际绑定对象。
- 更改 A 端站点会清空设备/接口，但不会按站点选项更新时区；计数器方向和测量范围显示内部英文枚举。

## 影响范围

- 后端：专线/WAN 选项服务中的接口候选过滤与排序。
- 前端：专线表单元信息解析、站点时区同步、无有效接口提示、枚举中文展示。
- 测试：补充接口选项服务和专线表单的针对性回归。
- 不改数据库结构、采集器调度和已有专线数据。

## 拟修改文件

- `backend/services/wan_link_service.py`
- 与 `list_wan_link_options` 对应的 `backend/tests/monitoring/` 定向测试。
- `src/components/ui/FormField.tsx`（公共下拉框和文本框组件）
- `src/components/wan-circuits/WanCircuitForm.tsx`
- `src/pages/WanCircuitsPage.test.tsx` 或专线表单组件测试。
- `docs/walkthrough/walkthrough_20261004_1734_01_专线表单信息准确性.md`

## 实施步骤

1. 按调用链确认 CMDB 接口同步方式与现有选项测试夹具。
2. 让 WAN 选项仅提供有正数 `if_index` 的接口；别名去重时优先保留具备有效 SNMP 索引的记录。
3. 表单过滤未确认接口，展示“先同步接口”的中文空态；摘要改用站点名、设备名、接口名和 ifIndex，不展示 UUID。
4. 选择 A 端站点时更新其时区；将计数方向和测量范围改为中文可读文案，同时保持 API 枚举值不变。
5. 运行后端定向 pytest、前端专线页面测试、`npm run lint`；若改动触及组件构建集成，再运行 `npm run build`。
6. 更新 walkthrough，记录浏览器观察、实际修改、验证证据及未验证范围。

## 验证计划

- 后端：覆盖空 ifIndex 过滤、有效接口保留、跨站点/设备范围继续有效、别名去重稳定性。
- 前端：覆盖中文摘要、按站点时区更新、无有效接口提示以及有效接口仍能提交正确端点契约。
- 质量门禁：`npm run lint`、专线页面/组件定向 Vitest；后端使用 PostgreSQL 隔离 fixture 跑影响测试。
- 通过浏览器刷新检查本地页面交互；不保存真实线路、不改生产设备或部署。

## 风险与回滚

- 过滤未同步接口可能让部分设备暂时没有可选择项；提示将明确要求先执行 IF-MIB/SNMP 接口同步。接口成功同步后会自动回到选项列表。
- 如影响其他 WAN 链路表单，则可回滚服务端候选过滤；前端摘要与中文显示可独立保留。
- 本次不执行提交、推送、发布或真实线路创建。

## 可读性补充范围（2026-10-04）

用户根据更新后的表单截图反馈，接口、流量方向、测量范围及 Z 端仍不易理解。继续在同一专线表单任务内补充：用业务语言解释端口同步、下载方向和共享端口数据限制；把 Z 端说明为线路对端，并区分可采集设备与仅登记信息；未纳管的 Z 端不显示不会生效的流量方向/测量范围设置。保留既有 API 枚举和公共按钮/表单样式。

验证补充：扩展专线表单组件测试，覆盖中文说明、无接口时的操作指引，以及未纳管 Z 端隐藏采集设置、托管 Z 端保留设置；运行定向前端测试与源码 TypeScript 检查。

## 自动同步与默认表单简化（2026-10-04）

截图反馈指出，仅提示用户离开表单手工同步不符合录入流程；选择 A/Z 端设备时应按需执行该设备的只读 SNMP IF-MIB 采集，并将接口名称和有效索引同步到 CMDB 后更新下拉列表。实现专用、设备级、权限受限的刷新 API，不复用当前面向全站设备且走 CLI/TextFSM 的接口状态批任务，也不调用会采集其他设备指标的通用 SNMP 测试接口。修正 SNMP 采集结果 `if_index` 与 CMDB upsert 字段键不一致的问题。

截图中的方向和端口承载范围只属于少数线路的高级修正项；保留现有保守默认及 API 契约，将其收进默认折叠的“高级监控设置”，使基础录入更简洁。

验证补充：后端覆盖字段映射、仅目标设备 SNMP 同步、权限范围拒绝和安全错误响应；前端覆盖选择 A/Z 设备后调用刷新并展示接口、刷新失败状态，以及高级设置默认折叠和按纳管状态显示；运行定向 pytest、Vitest、TypeScript 检查和生产构建。

## 线路对象流程优化（2026-10-04）

对照产品评审意见重新组织登记流程：线路基本信息 → 本端/对端 → 可选监控设置 → 备注。A/Z 只作为数据契约中的端点代号，主要文案使用“本端/对端”；两个端点使用对称卡片和相同的站点、设备、端口选择结构，只有对端额外区分“本系统已纳管”与“外部/未纳管”。

调用链检查已确认 migration `m0263_wan_circuit_model.py` 中已有统一 `wan_link_endpoints` 表，A/Z 使用相同字段，因此无需为本次表单调整创建数据库迁移。流量带宽按本端视角清楚标为“对端→本端”和“本端→对端”，默认只填一个双向对称值，勾选非对称后再显示第二个方向。现有 `link_role` 仅支持主用/备用/负载分担，扩展加入“单线路”值并同步更新两个 WAN 服务的保存、过滤校验及请求模型；底层列为普通文本，无需结构迁移。

线路用途与运营商使用可输入且附常见值建议的公共文本字段；“公网 IP”语义无法从现有 `public_ip` 字段和历史数据保证，故从表单移除输入框并在编辑时原样回传旧值，避免把 NAT 地址误标成专线互联地址。端点 IP 尚无可靠的一等数据契约，不在本次伪造自动采集或新增字段；后续若需展示，应先核实 CMDB 接口 IP 来源，再定义 A/Z 端地址契约。

站点时区默认继承本端站点；仅在展开监控设置并勾选“为这条线路单独设置时区”后展示可编辑项。更改本端站点会恢复到新站点的默认时区。

验证补充：覆盖默认对称带宽双向映射、非对称带宽方向映射、单线路角色保存与筛选，以及已有 A/Z 自动读取流程。运行专线页面定向 Vitest、影响范围内 pytest、源码 TypeScript 检查、生产 Vite 构建和 `git diff --check`；浏览器运行页面未部署本次代码，不能将测试页面截图描述为运行环境已更新。
