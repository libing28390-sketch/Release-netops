# Linux 巡检指标拆分、TCP 重传率与指标计数修复计划

## 任务目标

修复巡检指标管理页的分页计数错误，拆分 Linux 内置服务器指标与共享综合脚本的绑定，并修复 TCP 重传率指标的输出键与计算口径问题。

## 已确认现状

- `/api/inspections/items/all` 在分页请求时只返回当前页，前端却使用当前页 `items` 计算分类和采集方式数量，因此首次显示的“服务器/主机”数量可能为 0，切换分类后才刷新为真实数量。
- Linux 默认 `inspection_items` 的服务器指标全部绑定 `std_linux_integrated`；`_inspect_server_device` 还会优先执行 `insp_linux_full`，导致页面展示的脚本绑定与实际执行脚本不一致。
- `insp_linux_full` 的汇总键为 `tcp_retrans`，而内置指标 `srv_tcp_retrans_pct` 要求 `tcp_retrans_pct`，造成该指标无法从综合输出中关联到值。
- 当前 TCP 重传率使用启动以来累计 `RetransSegs / OutSegs`，不代表当前采样窗口的重传率，且旧脚本使用固定列号，兼容性较弱。

## 实施范围

- `backend/services/inspection_service.py`
  - 让已绑定脚本的 Linux 指标按 `script_id` 分组执行；保留无脚本自定义指标对综合脚本的兼容回退。
- `backend/database/seed.py`
  - 将内置 Linux 指标绑定到各自脚本。
  - 补齐缺失的单指标 Shell 脚本。
  - 为综合脚本和单指标脚本统一输出 `tcp_retrans_pct`，同时保留 `tcp_retrans` 兼容键。
  - TCP 重传率改为短采样窗口的计数器增量比值，并按字段名读取 `/proc/net/snmp`。
- `backend/services/inspection_service.py` / `backend/api/inspections.py`
  - 为分页指标列表增加服务端 facet 计数，避免前端从当前页推断总数。
- `src/pages/InspectionItemsTab.tsx`
  - 使用后端返回的全量分类/方式计数，保留当前页分页展示。
- `backend/tests/` 与 `src/`
  - 增加后端 facet、Linux 指标执行/解析和 TCP 输出契约测试；按项目规范执行前端 lint/build。

## 接口与兼容性约束

- 保留 `/api/inspections/items/all` 现有 `items/total/page/page_size` 字段；仅追加 `facets` 字段。
- 保留 `insp_linux_full`，因为独立遥测服务仍使用它；巡检指标执行不再无条件覆盖已绑定的单指标脚本。
- 保留 `tcp_retrans` 作为遥测兼容别名，同时以 `tcp_retrans_pct` 满足巡检指标定义。
- 不修改真实设备配置，不连接生产主机，不引入 SQLite 或新的数据库结构。

## 验证计划

1. 运行后端新增/相关巡检测试。
2. 运行前端 `npm run lint` 和 `npm run build`。
3. 运行 PostgreSQL-only 策略扫描并区分既有债务。
4. 执行 `git diff --check`，检查未泄露凭据和未改变用户已有变更。

## 风险与回滚

- 单指标绑定会使一个服务器巡检可能执行多个 Shell 脚本，连接次数和总耗时可能增加；通过按 `script_id` 去重执行，避免同一脚本重复运行。
- 旧的自定义指标没有 `script_id` 时继续走综合脚本回退，不影响既有自定义配置。
- 回滚仅需回退本次 seed、巡检服务、指标页和测试/文档变更，不触碰用户已有未提交内容。
