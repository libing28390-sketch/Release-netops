# 实施计划：修复监控采集编译事务与Grafana站点及设备指标同步

- **创建时间**：2026-09-20 09:27
- **任务编号**：`plan_20260920_0927_01_修复监控采集编译事务与Grafana站点设备指标同步`
- **对应领域**：`netops-monitoring-telemetry` & `netops-backend`

---

## 1. 任务背景与问题现象

用户在 Linux 主机 Docker 部署了 Nexora 平台（`https://192.168.18.139`），在系统 CMDB 中维护了两个站点（`WH-DC-01` 与 `WH-DC-02`），设备均为 H3C（管理 IP 包括 `192.168.56.11` 等），无任何 Cisco 设备。但在嵌入的 Grafana 监控大盘中出现以下异常：
1. **站点下拉菜单只有 `WH-DC-01`，无 `WH-DC-02`**；
2. **大盘中出现了 Cisco 相关的历史指标，且全部网络设备面板显示 `No data`**；
3. **用户在 CMDB 中录入的 H3C 设备从未被 vmagent 抓取**。

---

## 2. 根因排查与定位

通过直连用户的远程测试环境 API 及审查后端代码，查明以下连锁根因：

1. **PostgreSQL 事务中毒导致监控编译全面瘫痪**：
   - 在 `backend/api/monitoring_v1.py` 的 `_load_compile_inputs` 中：
     ```sql
     SELECT pa.*, COALESCE(...) FROM physical_assets pa LEFT JOIN sites s ON (s.id = pa.site_id OR s.id = pa.site)
     ```
     `physical_assets` 表根本没有 `site` 列（仅有 `site_id`），且无 `tenant_id` 列。在 PostgreSQL 环境下，该查询报错抛出 `column pa.site does not exist`。
   - 虽然外部存在 `try...except Exception: servers = []`，**但在 PostgreSQL 连接中发生错误后，当前事务立刻转为 ABORTED 状态**；代码未调用 `conn.rollback()`。
   - 随后的 `SELECT * FROM snmp_modules WHERE enabled = 1` 立即触发 `current transaction is aborted, commands ignored until end of transaction block`，导致采集器编译接口 `/api/monitoring/collectors/{id}/compile` 永久报 500 内部异常，无法工作。
   - 同样，`preview_monitoring_plan` 中查询了 `cli_platform, os_version, firmware_version, device_role, device_category, management_address` 等 `devices` 表中不存在的列，同样导致计划预览和监控概览 500 报错。
2. **历史静态 targets 与硬编码测试机残留**：
   - 因为监控编译全面瘫痪，运行时 `snmp_targets.yml` 始终未能刷新，一直保留着代码仓库 defaults 目录下初始化的 14 个虚拟设备配置（包括写死的思科设备 `10.255.0.4 Cisco`）。
   - `monitoring/vmagent/scrape.yml` 和 `linux_targets.yml` 中静态写死了 `192.168.204.128:9100`，标签写死了 `site_name: WH-DC-01`。
   - 这使得 vmagent 持续抓取这些死目标，VictoriaMetrics 中仅留存带有 `WH-DC-01` 和 `Cisco` 的时序数据；用户的真实设备从始至终未被纳入抓取，故 Grafana 读不到 `WH-DC-02`，所有指标均为 `No data`。

---

## 3. 影响范围

- 后端监控采集控制面：`backend/api/monitoring_v1.py`
- vmagent 抓取配置与目标目录：`monitoring/vmagent/scrape.yml`、`monitoring/vmagent/targets/snmp_targets.yml`、`monitoring/vmagent/targets/linux_targets.yml`

---

## 4. 拟修改文件清单

1. `backend/api/monitoring_v1.py`
   - 修正 `_load_compile_inputs` 中的 `server_sql`，改用合法的 `s.id = pa.site_id`，并增加对事务状态的安全回滚保护。
   - 修正 `preview_monitoring_plan` 的 `device_sql`，对齐 `_load_compile_inputs`，剔除未定义的伪列。
2. `monitoring/vmagent/scrape.yml`
   - 移除 `linux_servers` 中静态硬编码的 `192.168.204.128:9100`（含 `site_name: WH-DC-01`），完全走 `file_sd_configs` 动态文件发现。
3. `monitoring/vmagent/targets/linux_targets.yml` & `snmp_targets.yml`
   - 清理硬编码测试 targets，重设为由 CMDB 动态编译的目标模式。
