# pytest 9.2 数据库代理测试隔离修正

## 目标

修复 Actions 使用 pytest 9.2.0 时，测试通过 `database` 动态代理模块替换 `get_db_connection` 后无法恢复原值、导致整套测试级联失败的问题。保持生产采集、监控和解析行为不变。

## 现状与问题

- VLAN CLI 实现提交后的远端 release workflow 中，完整 pytest 出现 29 个 teardown/setup 错误和 111 个失败。
- 首个错误来自 `test_authorization_denies_on_database_error` 清理 `database.get_db_connection` 时，`_DatabaseModule` 没有该实例属性；后续测试因此继承模拟数据库连接或关闭的连接。
- CI 安装 pytest 9.2.0。本地既有虚拟环境 pytest 9.1.1，版本间 monkeypatch 对模块实例属性的处理不同。

## 范围与约束

- 只修正测试对数据库连接工厂的 monkeypatch 目标，直接替换其实际定义模块 `database.core` 中的属性。
- 不改生产数据库代理、接口/VLAN采集逻辑、监控代码、SNMP实现、解析器或 TextFSM 模板。
- 保留工作区中用户已有的未提交文件和生成物。

## 预计修改文件

- `backend/tests/security/test_audit_regressions.py`
- `backend/tests/security/test_collector_snmpv3_profile.py`
- `backend/tests/snmp/test_snmp_hardware_probe_service.py`
- `backend/tests/vendor_audit/test_collection_plan_bulk_api.py`
- `backend/tests/vendor_audit/test_cmdb_list_performance.py`
- 本方案、walkthrough 和 `docs/fixes/fix_*.md`。

## 实施与验证

1. 对照 pytest 9.2.0 的 monkeypatch 实现确认代理模块行为变化。
2. 将所有直接 patch `database.get_db_connection` 的测试改为 patch `database.core.get_db_connection`。
3. 使用 pytest 9.2.0 运行所有受影响测试和当前 VLAN 采集相关测试。
4. 运行 PostgreSQL-only 检查、`git diff --check`，推送 main 并检查最新提交的 Actions。

## 风险与回滚

- 变更仅影响测试替身的安装和清理；生产功能无行为变化。
- 若测试失败，回滚本次测试文件和对应文档提交即可；不影响已推送的 VLAN CLI 实现。
