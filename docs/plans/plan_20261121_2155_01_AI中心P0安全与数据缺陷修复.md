# 实施计划：AI 中心 P0 安全、数据损坏与阻塞性缺陷修复

- **归档编号**：`20261121_2155_01_AI中心P0安全与数据缺陷修复`
- **创建时间**：`2026-11-21 21:55`
- **目标范围**：完成 AI 中心深度审查报告中的 **第一阶段（P0 全部批次）** 修复与 PostgreSQL 回归验证。

## 1. 任务目标

一次性根除 AI 中心已识别的全部 P0 级安全漏洞、数据损坏/丢失风险、并发竞态与核心阻塞性缺陷，并补充对应的自动化回归测试，确保所有变更通过 PostgreSQL 门禁与相关测试套件。

## 2. 现状与问题清单（P0 全部批次）

1. **P0-1：检索测试 SQL 注入漏洞**
   - `backend/ai/services/rag_retriever.py` 中 `_filter_sql` 将 `request.applicability` 字典的 `key` 直接用 f-string 拼入 SQL（`d.metadata_json -> '{key}'`），而 `backend/api/knowledge_contracts.py` 未限制 `key` 字符集（允许单引号 `'` 等字符）。
2. **P0-2：AI 安全网关凭据漏脱敏、IPv6 压缩地址绕过与输出 `html.escape` 污染**
   - `backend/ai/security/sanitizer.py` 多条凭据脱敏正则存在双必填 `\s+`（无修饰符的 `password mysecret` 无法匹配）、缺少华为 VRP `irreversible-cipher` / `level \d+` 修饰符，且私钥脱敏漏掉 PKCS#8 `BEGIN PRIVATE KEY`。
   - `backend/ai/security/classification.py`、`tokenization.py`、`dlp.py` 的 `IPV6_RE` 不支持含 `::` 的压缩 IPv6 地址（如 `2001:db8::1`、`fe80::1`），导致其绕过分类、Token 化与出向 DLP。
   - `backend/ai/security/output.py` 的 `sanitize_output()` 对所有 LLM 输出无条件调用 `html.escape(clean, quote=False)`，把 `<`、`>`、`&` 及 `<REDACTED>` 污染为 `&lt;` / `&gt;` / `&amp;`。
3. **P0-3：安全网关误杀只读配置/差异分析与变更草案生成 + 分析服务 JSON 解析容错**
   - `backend/ai/security/gateway.py` 无条件对包含 `change_command`（`system-view`、`configure terminal`、`save`、“修改配置”）或 `full_config`（`running-config`、`current-configuration`）的请求抛出 `AI_SECURITY_UNSAFE_TOOL` / `AI_SECURITY_SENSITIVE_DATA`，导致配置分析、配置对比、变更配置生成等合法 NetOps 场景被自身网关阻断。
   - `command_analysis.py`、`config_analysis.py`、`diff_analysis.py`、`alarm_analysis.py`、`config_generation.py` 缺少 `scene` 透传、租户/角色透传及对异常 LLM JSON 类型（如 `risk_level: null`、百分制 `confidence`、非字典列表项）的容错。
4. **P0-4：AI 变更治理假持久化与越权审批**
   - `backend/ai/services/change_governance.py` 向 `change_orders` 插入不存在的 `created_by` 列且缺少必填列 `order_number`，且用 `except Exception: pass` 吞掉异常返回假成功；`approve_change` 绕过行锁、状态机、租户校验与审计记录。
5. **P0-5：`ai_usage_daily` 并发更新竞态与单日预算对比逻辑错误**
   - `backend/ai/gateway/llm_gateway.py` 更新 `ai_usage_daily` 采用非原子 `SELECT` + `UPDATE/INSERT`，在已有唯一索引 `ux_ai_usage_daily_scope` 下并发首单触发 `UniqueViolation` 被吞、并发后续单产生丢失更新。
   - `backend/ai/api/usage.py` 将全历史累计费用与单日预算 `AI_DAILY_BUDGET_USD` 对比，且延迟汇总采用无权重的 `AVG(avg_latency)`；`LLMGateway._budget_exceeded` 仅按单模型检查日预算。
6. **P0-6：Provider 更新 `base_url` 导致出向白名单变砖 & `AzureOpenAIProvider.chat_stream` 崩溃**
   - `backend/ai/api/providers.py` 在 `update_provider` 修改 `base_url` 时未同步更新 `approved_endpoint_patterns_json`，导致更新后运行时被 `LLMGateway` 拒绝。
   - `backend/ai/providers/registry.py` 中 `AzureOpenAIProvider` 在 `chat()` 中非线程安全地就地修改 `self.base_url`，且未覆写 `chat_stream()`，导致流式请求直接发送字面量 `{model}` URL。
7. **P0-7：RAG 评测运行时全局 Monkey-Patch 污染与权限过宽**
   - `backend/api/knowledge_evaluation.py` 允许只读权限触发 `/knowledge/evaluation/run`。
   - `scripts/knowledge_baseline_pg.py` 与 `backend/services/knowledge_evaluation_service.py` 在评测时修改 `ai.services.rag_retriever` 模块全局变量，会劫持同进程并发用户的正常 RAG 检索。

## 4. 实施步骤

1. **修复 P0-1（检索 SQL 注入）**：在 `knowledge_contracts.py` 与 `rag_retriever.py` 对 `applicability` 键名施加严格正则 `^[A-Za-z0-9_]{1,64}$` 校验，并改为 PostgreSQL 参数化 `d.metadata_json -> ?`。
2. **修复 P0-2（脱敏/IPv6/输出转义）**：修复 `sanitizer.py` 正则（含无修饰符密码、华为 `irreversible-cipher` / `level` 与通用私钥头）；统一 `IPV6_RE` 支持 `::` 压缩地址并在 `classification.py` / `tokenization.py` / `dlp.py` 复用；移除 `output.py` 中对普通文本的 `html.escape()`（保留 `<script>` 等危险标签与协议剥离及凭据脱敏）。
3. **修复 P0-3（安全网关场景感知 + 分析服务容错）**：在 `AISecurityGateway.protect()` 与 `LLMGateway.chat/chat_stream` 增加 `scene` 参数；对于只读配置/差异/命令/告警分析及配置草案生成场景，放行不含真实凭据的配置语法词（`change_command` / `full_config`），真实凭据（密码/私钥/Token/SNMP 团体字）依然严格拦截；加固 5 个分析/生成服务的 JSON 类型容错、预脱敏与租户透传。
4. **修复 P0-4（变更治理持久化）**：将 `ChangeGovernanceService.create_change_draft` 接入 `services.change_order_service.create_change_order()`，真实写入 `change_orders`（含 `order_number`、`target_devices`、`commands`、`rollback_plan`、`requester_id`、`requester_username`、`tenant_id`）；`approve_change` 改为带 `FOR UPDATE` 行锁、租户隔离、存在性校验、职责分离与审计日志的安全状态更新（同时返回兼容字段）。
5. **修复 P0-5（`ai_usage_daily` 原子化与预算/延迟统计）**：将 `LLMGateway._log_request` 的 `ai_usage_daily` 写入改为 PostgreSQL 原子 `INSERT ... ON CONFLICT (date, provider_id, model_id, scene) DO UPDATE`；修复 `usage.py` 按当日成本对比 `AI_DAILY_BUDGET_USD` 与加权平均延迟；对齐 `_budget_exceeded` 检查当日总消耗。
6. **修复 P0-6（Provider `base_url` 白名单同步 & Azure 流式）**：在 `providers.py` `update_provider` 修改 `base_url` 且未显式提供 `approved_endpoint_patterns` 时自动同步更新白名单；重构 `AzureOpenAIProvider` 移除对 `self.base_url` 的就地修改并同时支持 `chat` 与 `chat_stream`。
7. **修复 P0-7（RAG 评测隔离与权限收紧）**：为 `RAGRetriever` 增加实例级 `connection_factory` 与 `embedding_provider` 注入参数，修改 `scripts/knowledge_baseline_pg.py` 与 `knowledge_evaluation_service.py` 不再篡改模块全局属性；将 `/knowledge/evaluation/run` 权限收紧为 `manage`。
8. **编写回归测试并执行验证**，最后归档 `docs/walkthrough/walkthrough_20261121_2155_01_AI中心P0安全与数据缺陷修复.md`。

## 6. 风险与回滚思路

- **风险 1**：现有某些安全单测可能断言 `sanitize_output` 对 `<script>` 或普通 `<div>` 做了 `html.escape`，需在运行现有安全测试时核对行为，确保 XSS 防护不降级的同时不破坏正常文本与 JSON 输出。
- **风险 2**：现有测试可能调用 `ChangeGovernanceService.create_change_draft` 或 `/knowledge/evaluation/run` 并依赖返回字段，需保持响应字段向后兼容。
- **回滚思路**：所有改动集中在应用层 Python 文件，未破坏任何既有数据库表结构，出现异常可直接通过 `git checkout -- <file>` 回退单模块。
