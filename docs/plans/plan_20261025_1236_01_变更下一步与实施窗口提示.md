# 变更下一步与实施窗口提示

目标：修正审批完成后一律“等待实施”的误导，将下一步及主要动作放到详情右侧。依据同一时间窗口状态展示未开始/窗口内/已结束；窗口结束使用排他边界。用户明确申请人可兼实施人，移除前端多余限制；执行资格与独立审批仍按现有规则。已有协同审核人复用为可选复核人，不增加重复字段。

范围：ChangeOrder/helpers.ts、详情/编辑/责任面板/父页面及测试；后端检查control_sheet复核人必填规则并调整为可选。保留接口和审批快照结构，不修改已有工单。主Agent负责前端与文档；backend_worker负责backend/api/change_orders及对应测试的可选复核人验证，互不修改共享文件。

用户进一步明确可选复核人承接实施后结果审核。本轮增加独立状态 `implementation_review`（指定复核人）和 `implementation_result_review`（原初审人），不能复用实施前 `initial_review`，也不能重新签发执行授权。接口 `POST /change-orders/{id}/result-review`，动作 `submit/pass/fail/accept/reject`、必填summary。指定实施人提交；指定复核人正常关单、异常转原初审人；原初审人接受结果关单或退回实施人处理。未指定复核人保留原验证/关单流程。现有技术/业务验证门禁保留，提交复核前需满足，不伪造通过记录。复核人不限基础角色但须有效且与实施人不同。审核中不能通过旧completed或重执行路径绕过。

新增范围：后端result_review模块、注册、待办SQL/count与读取权限、对应PG闭环测试；前端状态/流程条/下一步/右侧按钮/意见弹窗/详情说明。后端执行者负责后端上述文件，主Agent负责前端与集成。真实设备操作禁止用于验收。

验证：针对helper/父页面/责任面板测试、TypeScript、隔离构建、可选复核人的隔离PostgreSQL测试及policy扫描、桌面浏览器截图。无数据库迁移；回滚只撤销本轮增量。
