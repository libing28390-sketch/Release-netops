# SNMP 全局 ARP 与 FDB 采集实施计划

## 目标

落实用户确认的 V1：对所有已纳管网络设备按 SNMP 能力全局采集 ARP/FDB；保留原始观测；独立分类终端；端口定位需要站点/VLAN/VRF/时间/拓扑证据；采集失败不改写最近发现时间。统一为每小时一轮有界 ARP+FDB 采集，并停用每日重复 ARP 作业。

## 当前证据

- `.env`、当前运行模块的 ARP 周期均为 600 秒，批次上限 500、并发 2。
- 本机 ARP 源观测在 2026-11-03 11:15 至 11:55 间按约 10 分钟产生。
- 当前 PostgreSQL 仍启用 `arp-daily-sweep`（每天 02:00，尚无运行记录）；m0306 会在安装时创建它。
- `ENDPOINT_FACT_INTERVAL_SECONDS=1800` 虽已配置，但 FDB 事实任务没有挂到 APScheduler。
- IPAM 近期窗口默认仍是旧 ARP 周期 600 秒；FDB 近期窗口固定 26 小时，与小时联合作业不一致。
- 页面保留了显式手动 `arp-sweep` 和 `nsot-sweep` 入口，可能在小时任务外额外发起设备采集；它们不是自动周期。
- ARP 候选受角色/SVI 策略限制；周期 ARP/FDB 采集均存在 CLI 回退。
- 用户工作树有大量无关未提交改动，必须保留；不修改 scheduler_service 中既有 NSOT/工单改动。

## 实施范围

- `ip_locator_service.py`：SNMP 候选、SNMP-only 采集、统一 ARP/FDB 周期作业、能力/失败状态、完整快照替换保护。
- `main.py`：单一 3600 秒 ARP+FDB 调度入口；IPAM 60 秒只读投影保持独立。
- `m0307` 迁移：幂等软停用每日 `arp-daily-sweep`，保留审计历史。
- `.env` 与 `.env.example`：ARP、FDB 周期均设 3600 秒；本机当前配置同步调整。
- 终端分类：原始数据留在 ARP/FDB 源表和受保留期管理的发现快照；业务终端视图排除已知虚拟网关；端口仍要求现有唯一、接入端口证据。
- 更新简明指南和实施走查文档。

## 实施步骤

1. 确认 SNMP 凭据启用筛选、采集状态保存方式和 FDB 完整快照替换契约。
2. ARP 按 SNMP 可用性选择在线纳管网络设备，不再以网关角色/SVI 作为硬门槛；全量 ARP 仍按游标批次和并发上限执行。
3. FDB 对 SNMP 启用设备采集 Q-BRIDGE-MIB；SNMP 不支持、凭据缺失和依赖失败分别记录；任何不完整快照都保留上次完整数据。
4. 将 ARP 与 FDB 串行放入一个 3600 秒有界周期任务；禁用每日 ARP 作业，避免重复入口。
5. 将 ARP/FDB 的近期判定窗口与各自周期对齐，默认使用两轮加 2 分钟抖动。
6. 终端视图保留原始事实，将虚拟网关等识别为基础设施；端口缺少唯一接入证据时保持未定位。
7. 增加聚焦测试、迁移检查和质量门验证。

## 验证

- ARP：无 SVI 的 access 设备在 SNMP 启用时可入选；无 SNMP 配置/不支持/读取失败状态区分；SNMP-only 不调用 CLI；失败保留旧记录。
- FDB：SNMP-only、完整快照才替换、失败保留旧表、能力/错误状态可见。
- 终端分类：VRRP MAC 从终端分类排除但原始观测保留；端口仅在站点/VLAN/MAC 匹配且唯一接入端口时确定。
- 调度：单一 3600 秒入口；60 秒 IPAM 投影保持只读；m0307 对已安装及新数据库均幂等。
- 运行相关 pytest、迁移测试、PostgreSQL-only 扫描；不连接真实设备、不迁移本机业务库、不重启服务。

## 风险和回滚

### 2026-11-03 FDB 深度排查补充

- 只读实测 S6850-5 曾返回 1 条 FDB，随后两台接入设备 FDB 均为空，但 VLAN/桥端口映射可读。
- 空表被误分类为 unsupported 并退避 24 小时；改为 no_data，下一轮重试，保留旧快照。补充现有分类测试并聚焦验证。

- 全局 SNMP 覆盖会增加查询量；按设备游标分批、并发 2、每小时运行，超时/失败不堆叠任务。
- 空表与 MIB 不支持在当前 SNMP API 中可能都表现为无行；对无法证明完整性的快照按失败处理，不清除旧事实。
- 回滚代码时每日作业保持停用；需要恢复时由明确配置控制，避免迁移后自动重复执行。
- 手动全量入口仍可额外触发采集；应只在需要立即更新时使用，未来若要求严格限频可将其并入同一共享采集锁。
