# 巡检指标分类筛选修复

## 任务目标

修复选择“合规性检查”后计数显示 6 条、列表却显示空状态的问题。

## 现状与根因

- 服务端分类筛选和分类统计不区分大小写。
- 页面根据服务端结果再执行一次本地筛选；该过滤器使用大小写敏感的全等比较。
- 合规指标返回的 `category` 为 `COMPLIANCE`，筛选值为 `Compliance`，本地二次过滤因此排除了全部结果。

## 影响范围

- 修改 `src/pages/inspectionItemsExport.ts` 中列表和导出共用的分类过滤比较。
- 不调整服务端 API、分类统计、筛选 UI、分页和指标数据。

## 实施步骤

1. 将本地分类比较改为去除首尾空格后大小写不敏感比较，与服务端筛选保持一致。
2. 检查列表和导出路径共用该过滤器时的行为。
3. 执行前端类型检查、生产构建和差异格式检查。

## 验证计划

- 对照截图中的 `COMPLIANCE` 数据与 `Compliance` 筛选值，确认比较规则一致。
- `npm run lint`
- 在临时目录运行 Vite production build。
- `git diff --check`。

## 风险与回滚

- 分类值仅在大小写或首尾空格不同时会由本地过滤器视为相同；不会扩展成模糊匹配。
- 回滚时恢复分类字段的原始全等比较即可。
