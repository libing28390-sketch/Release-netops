# LLDP 采集完整性

## 目标与问题
按用户确认方案修正两个 LLDP OID 映射，拓扑 LLDP 每个 walk 默认预算设为 30 秒、行数上限为 10000；达到上限必须明确视为不完整，保护已存在拓扑链路。当前使用错误的 `.2` 机箱 ID 和 `.4` 端口 fallback，默认 4 秒/200 行且达到上限按成功返回。

## 影响范围与分工
- LLDP 执行者：`backend/services/snmp_service.py`、`backend/tests/topology/test_snmp_lldp_discovery.py`、新增专用 `backend/tests/snmp/test_snmp_lldp_walk_limits.py`，负责 OID、专用预算及兼容 list 的截断元数据。
- 主 Agent：`backend/services/topology_service.py`、新增 `backend/tests/topology/test_snmp_lldp_row_limit_status.py`，处理截断状态说明与降级/旧链路保护；统一计划、走查、验证执行器和最终审查。
- 日志审计执行者：只读分析用户新增的三份日志，统计错误、追踪 MIB SQL/遥测计数列及容器资源证据；仅允许在 `artifacts/` 写统计结果，不修改服务和数据库。各执行者不创建子 Agent。
- 主 Agent 同时维护全容器只读诊断命令及本次日志排查报告；日志分析不扩展为部署、数据库迁移或未授权的运行时变更。
- 通用 SNMP 默认 timeout/max_rows、UDP transport 与其他监控指标不随 LLDP 改动整体放宽；诊断页面现有 5 秒和 10000 行行为本次不改。保留工作区全部已有改动。

## 实施步骤与接口
1. `lldpRemChassisId` 改为 `1.0.8802.1.1.2.1.4.1.1.5`；移除 `.4` 错误端口 fallback，端口仍读取 `.7` 并保留现有 `.8` 描述辅助逻辑。
   走查发现 `.5` 的真实 MAC OctetString 被通用 UTF-8 解码损坏，因此 LLDP 同时正确读取 `.4` chassis subtype。walk 仅在显式启用时保存原始 bytes 元数据；LLDP 按 subtype=4 格式化 MAC，其余保留可打印文本或安全十六进制。通用字符串返回值及其他采集器不变，增加二进制 MAC 和文本 chassis 回归。
2. LLDP collector 默认 `timeout=30.0`、`max_rows=10000`，显式传入 walk。保留历史测试替身/插件的签名兼容。
3. `_snmp_walk` 继续返回 list 兼容对象，增加 `truncated` 标记；达到行数上限即保守标记不完整，不改变现有截取数量。LLDP batch 增加 `truncated_oids`、`max_rows` 属性；只要超时/失败或截断，且仍有邻居，状态为 partial；没有可用邻居且截断/错误时失败，不能被当作完整空表。
4. 拓扑继续使用已有 CLI fallback/partial 保护，截断时 detail 指出 row limit 与 OID，保持已有字段和错误码契约。
5. 回归覆盖正确 OID、30 秒/10000 行传参、13 邻居、超过旧 200 行、空表、行数上限、部分超时、签名兼容、partial 的 CLI 降级和未观察旧链路保留。真实采集全部 mock。

## 验证
按 netops-topology-engine、netops-monitoring-telemetry、netops-quality-gate 运行聚焦测试。用 `.venv/Scripts/python.exe`，先创建测试专用源 PostgreSQL 数据库再 subprocess pytest；所有用例使用共享隔离 fixture，finally 强制清理。验证 SNMP transport、walk API、LLDP/topology 及相关生命周期合同；运行 PostgreSQL-only scanner、py_compile、git diff --check。无前端/API schema 修改，不触发生产构建或全量业务回归。

## 风险与回滚
30 秒允许慢设备等待更久，但仍受每设备 300 秒总预算、并发 limiter、10000 行上限约束。达到上限时即使恰好读完也保守标记 partial，避免缺失链路被错误老化。修正 OID 无法证明其他部署的具体错误根因或替代实际验证。无数据库迁移、真实设备配置修改或部署；回滚仅本任务服务和测试差异，不覆盖既有工作。
