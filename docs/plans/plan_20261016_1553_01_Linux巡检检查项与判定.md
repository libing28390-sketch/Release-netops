# Linux 巡检检查项与判定优化计划

## 目标

优化内置 `insp_linux_full`，让 Linux 综合巡检的采集项、判定边界和日志输出更准确易读。增加 DNS、NTP、默认网关可达性和文件句柄检查；保留白底黑字输出约定，不输出健康分数或综合评级。

## 现状与问题

- 综合脚本当前没有 DNS、NTP、默认网关和文件句柄检查；标准单项脚本虽有 DNS/NTP/文件句柄的粗略实现，但缺少完整证据或容易误判。
- CPU、I/O、只读挂载、TCP、系统服务和 SSH 失败日志检查存在采样口径、阈值覆盖或误报问题。
- `inspection_service` 依赖 `--- METRICS ---` 和错误/警告汇总行；必须保留既有指标键并保持汇总可解析。
- `backend/database/schema.py` 在初始化时会按脚本 ID 更新系统脚本内容，因此无需新增数据库迁移。

## 影响范围

- 修改 `backend/database/seed.py` 中 Linux 综合巡检脚本。
- 修改 `backend/services/inspection_service.py`，让 `METRICS` 中的显式状态和 `NA` 值正确表示未采集，避免字符串被误标为成功。
- 添加对应 `docs/walkthrough/` 完成记录。
- 不修改用户创建的计划、不部署到远端设备，也不处理这次发现的未来计划状态显示问题。

## 实施步骤

1. 记录并保留工作区现有的 `seed.py` 改动，尤其是 Inode `-` 值保护、Snap 只读挂载过滤和移除综合健康评级。
2. 改善 CPU、内存/OOM、文件系统、TCP、I/O、关键服务和 SSH 审计采样及判定；采集不可用时明确输出“未采集”，避免把缺失值写成正常的 0。
3. 加入 DNS 解析与时延、NTP 同步状态/偏差、默认路由/网关邻居可达性、系统及进程文件句柄检查。
4. 保持机器可解析的 `--- METRICS ---` 区块和现有 `tcp_retrans` 兼容别名；结果只提供逐项状态、证据和严重/关注数量，不产生评分。
5. 调整巡检服务读取明确状态值，未采集字段不作为正常数值参与阈值计算；综合脚本状态和数据库巡检项阈值同时生效，较严重结果优先。
6. 按项目验证要求记录未执行的自动化检查及其原因。

## 验证计划

- 检查脚本字符串、指标名和初始化 upsert 的兼容关系。
- 按更高优先级的运行指令，本轮不新增或执行自动化测试；完成后汇报未运行的检查和剩余验证风险。

## 风险与回滚

- 脚本 CPU、负载和 Swap 的默认阈值与内置巡检项默认值对齐；其他阈值仍需按业务服务器角色校准，可通过环境变量覆盖。
- 缺少 `dig`、`chronyc`、`ntpq`、`ip`、`findmnt` 或 `iostat` 时不能直接判为健康或故障，应给出可读的未采集原因。
- DNS 探测目标不采用公共域名默认值；未配置 `NEXORA_DNS_PROBE_NAME` 时会明确显示未采集。`getent` 走系统名称解析路径，可能命中 `/etc/hosts` 或本地缓存。
- 网关检查分别读取 IPv4 和 IPv6 默认路由；无 `via` 的点到点路由不报告为可达，邻居状态只有 `REACHABLE` 或成功 Ping 才作为实时证据。
- 进程句柄扫描会报告可读取和读取失败的进程数；权限缺口不会被当作完整检查通过。
- 若新脚本在兼容性检查中出现问题，只回退本任务新增的 `insp_linux_full` 内容，保留工作区已有的其他改动。
