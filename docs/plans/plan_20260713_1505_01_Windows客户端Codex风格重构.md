# Windows 客户端 Codex 风格重构实施计划

## 1. 文档信息

- **计划编号**：`20260713_1505_01`
- **计划状态**：待实施
- **目标客户端**：Windows NetOps Agent Manager
- **主要入口**：`desktop/desktop_tray.py`
- **UI 技术栈**：Python、PySide6、Qt Widgets、QSS
- **发布目标**：重新生成 `netops.exe`
- **视觉方向**：全面参考 Codex 桌面端的克制、低噪音、内容优先、紧凑工作台设计语言

> 本计划参考 Codex 的视觉原则、信息层级和交互感受，不复制 OpenAI 商标、图标、字体文件或其他专有品牌资源。NetOps 继续使用自身名称、图标和业务语义。

## 2. 任务目标

### 2.1 核心目标

将现有 Windows 客户端从“传统双栏管理面板”重构为接近 Codex 的现代桌面工作台，重点解决以下问题：

1. 降低卡片、边框、双语文字和高字重造成的视觉噪音。
2. 建立统一设计令牌和公共组件，避免深浅主题分别维护大量重复 QSS。
3. 重构应用壳层、导航、标题栏、设置页和弹窗，使所有页面遵循同一视觉体系。
4. 减少固定宽度、嵌套滚动和内容截断，适配不同 Windows 缩放比例与窗口尺寸。
5. 保留现有服务启停、日志、配置、数据库维护、托盘和升级功能，不改变业务行为。
6. 完成 EXE 重新打包，并在明亮、深色主题下进行完整视觉和功能验收。

### 2.2 交付结果

- 一套集中管理的 Codex 风格设计令牌。
- 一组可复用的 Qt Widgets 公共组件。
- 重构后的主窗口壳层和五个页面。
- 统一主题的确认、警告、进度和结果对话框。
- 支持高 DPI、窗口缩放、键盘焦点和中英文切换。
- 新版 Windows `netops.exe`。
- 对应 walkthrough、截图和验证记录。

### 2.3 非目标

- 不修改 Web 管理端 React 页面。
- 不修改 FastAPI 后端接口和数据库结构。
- 不修改 Agent 与控制器通信协议。
- 不在本阶段改用 Electron、Tauri 或 Qt Quick/QML。
- 不复制 Codex 的品牌 Logo、产品名称或专有插画。

## 3. 现状与问题分析

### 3.1 当前技术结构

当前桌面端主要集中在单文件 `desktop/desktop_tray.py` 中，文件同时承担：

- 应用启动和系统托盘管理。
- 主窗口搭建。
- 页面构建。
- 深浅主题 QSS。
- 控件实现。
- 弹窗实现。
- 业务事件处理。
- 设置持久化。

这种结构导致视觉调整容易产生跨页面回归，也使弹窗、按钮、输入框和页面卡片无法稳定复用。

### 3.2 当前视觉问题

#### 3.2.1 应用壳层

- 侧栏固定为 `220px`，在较小窗口中占比过高。
- Windows 原生标题栏与应用内容区割裂。
- 页面缺少统一页头、当前页面标题和简洁操作区域。
- 侧栏品牌区、导航区和内容区之间缺少清晰但克制的层次。

#### 3.2.2 色彩

- 深色主题采用明显的 GitHub 蓝黑色倾向。
- 明亮主题混合暖灰、纯白和高对比黑色，层级不够统一。
- 边框颜色过于明显，多个容器叠加后形成“表格框架感”。
- 选中、悬停、禁用、危险状态之间的语义不完全一致。

#### 3.2.3 字体

- 中文模式仍大量显示英文括号翻译。
- 标题、字段和值大量使用 `font-weight: 650`，缺少普通、中等、强调三个层级。
- 小标题使用全大写英文，与中文界面不协调。
- 字号较多且没有明确的排版比例体系。

#### 3.2.4 布局

- 设置页左右两张大卡片，左侧再嵌套滚动区域。
- 右侧系统信息卡固定 `320px`，CPU 等长文本被迫换行或截断。
- 大窗口中内容仍然拥挤，小窗口中则出现更多滚动。
- 卡片圆角、内边距和行高偏大，视觉更接近移动端管理面板。

#### 3.2.5 控件

- Toggle 开关尺寸较大，关闭和启用状态对比不足。
- 输入框、下拉框、按钮和复制按钮的高度、圆角、字重不统一。
- 危险操作按钮过度依赖红色边框，悬停状态曾出现文字不可见问题。
- 弹窗部分依赖系统 `QMessageBox`，无法完整继承应用主题。

#### 3.2.6 代码架构

- `DARK_STYLE` 与 `LIGHT_STYLE` 重复维护完整 QSS。
- 多处使用内联 `setStyleSheet()`，覆盖全局主题。
- 页面构建和业务处理混合在一个窗口类中。
- 固定宽度和固定高度散落在页面代码中。
- 自绘开关、进度弹窗和数据库确认弹窗拥有各自颜色逻辑。

## 4. Codex 风格设计原则

### 4.1 内容优先

- 内容区优先于装饰。
- 容器只在需要表达分组时出现。
- 同一页面不同时叠加背景色、粗边框、阴影和大圆角。
- 每个区域只保留一个主视觉焦点。

### 4.2 低噪音

- 中文模式只显示中文，英文模式只显示英文。
- 使用留白和文字层级代替大量边框。
- 次要说明采用弱化颜色，不与主标题竞争。
- 系统信息、版本信息和低频操作默认折叠或下沉。

### 4.3 紧凑但不拥挤

- 控件高度收敛到少量标准尺寸。
- 列表行保持足够点击区域，但减少无效上下留白。
- 页面采用统一水平网格。
- 控件与描述文字基线对齐。

### 4.4 中性色优先

- 大面积背景使用中性灰、炭黑和白色。
- 品牌色只用于状态、焦点、链接和主操作。
- 危险色仅用于真正不可逆操作。
- 成功色仅用于明确成功或在线状态。

### 4.5 状态清晰

- 所有按钮必须有默认、悬停、按下、焦点和禁用状态。
- 所有异步操作必须有进行中、成功和失败反馈。
- 危险操作必须显示影响范围、备份路径和不可逆提示。
- 状态不能只依赖颜色，必须搭配文字或图标。

### 5.5 字体与排版

- 字体优先级：`Segoe UI Variable` → `Segoe UI` → `Microsoft YaHei UI`。
- 中文模式不追加英文括号说明。
- 英文模式不混入中文。
- 主页面标题：`18px / 600`。
- 分组标题：`12px / 600`。
- 设置项标题：`12px / 500`。
- 正文：`12px / 400`。
- 描述和元信息：`10–11px / 400`。
- 状态数字：`20–24px / 600`。
- 代码与日志：`Cascadia Mono` → `Consolas`，`11px`。
- 避免使用 Qt 不稳定的 `font-weight: 650`，统一采用 `400/500/600`。

### 5.6 动效令牌

- 页面切换：`120–160ms` 淡入，不使用明显滑动。
- 悬停：`80–120ms`。
- Toggle：`120ms`。
- 弹窗：`140ms` 淡入并轻微缩放。
- Toast：`160ms` 淡入，停留 `2–4s`。
- 尊重 Windows“减少动画”设置；启用时关闭非必要动画。

## 6. 目标信息架构

### 6.1 主窗口骨架

目标结构：

```text
┌───────────────────────────────────────────────────────────┐
│ 自定义标题栏：品牌 / 页面标题 / 窗口控制                   │
├──────────────┬────────────────────────────────────────────┤
│              │ 页面标题、描述、主要操作                   │
│ 紧凑侧栏     ├────────────────────────────────────────────┤
│              │                                            │
│ Dashboard    │ 单一内容画布                               │
│ Service      │                                            │
│ Logs         │                                            │
│ Settings     │                                            │
│ About        │                                            │
│              │                                            │
│ 版本/状态    │                                            │
└──────────────┴────────────────────────────────────────────┘
```

### 6.2 响应式规则

- 默认窗口建议：`1180×760`。
- 最小窗口：`920×640`。
- 侧栏标准宽度：`188px`。
- 窗口宽度小于 `1024px` 时，侧栏缩为 `64px` 图标栏。
- 内容区最大可读宽度：设置页 `880px`，日志页不限宽。
- 页面只允许一个主滚动区域。
- 禁止页面内再套完整高度滚动区域。
- 不再使用固定 `320px` 系统信息卡。

## 7. 公共组件整改计划

### 7.1 `ThemeTokens`

新建统一主题令牌模块，输出：

- 深色、明亮颜色字典。
- 字号、字重、间距、圆角和控件尺寸。
- QSS 变量渲染函数。
- 系统标题栏深浅主题同步函数。
- 主题变化信号。

### 7.2 `AppShell`

- 管理自定义标题栏、侧栏、页面堆栈和全局 Toast。
- 将窗口级布局从业务窗口类中拆出。
- 支持侧栏折叠。
- 支持页面级标题和操作槽位。

### 7.3 `SidebarNavItem`

- 固定 `36px` 高度。
- 使用统一 SVG/Qt 图标，不继续依赖可能缺字的 MDL2 字符。
- 默认状态无背景。
- 悬停使用弱表面色。
- 选中状态使用稍强表面色和主文字色，不使用高饱和色块。
- 折叠状态提供 Tooltip。

### 7.4 `SectionHeader`

- 统一页面分组标题、描述和右侧动作。
- 禁止全大写中文。
- 支持分隔线可选。

### 7.5 `SettingsRow`

- 标题、描述和控件基线统一。
- 描述为空时自动垂直居中。
- 默认仅使用底部分隔线，不再为每行创建小卡片。
- 支持危险样式、禁用样式和加载状态。

### 7.6 `Button`

定义以下变体：

- `primary`：高对比主操作，每个区域最多一个。
- `secondary`：弱背景或细边框。
- `ghost`：无背景图标操作。
- `danger`：危险操作，红色文字，悬停后浅红背景。
- `link`：纯文字链接。

所有按钮必须支持：

- 默认、悬停、按下、禁用、键盘焦点。
- 加载图标和加载文字。
- 固定最小点击面积。
- 明暗主题可读性。

### 7.7 `ToggleSwitch`

- 尺寸调整为 `36×20px`。
- 关闭状态使用中性轨道。
- 开启状态使用主题强调色或成功色。
- 滑块与轨道保持清晰对比。
- 键盘 Space 可切换。
- 提供焦点描边。
- 禁用状态不允许误判为开启。

### 7.8 `TextInput` / `ComboBox`

- 统一高度 `34px`。
- 默认弱背景，焦点后显示单一描边。
- 下拉菜单与主主题一致。
- 选中项不使用系统蓝色突兀高亮。
- 支持错误、只读、禁用和加载状态。

### 7.9 `StatusBadge` / `StatusDot`

- 在线、离线、启动中、警告和失败使用统一语义。
- 状态点尺寸统一为 `6–8px`。
- 颜色旁必须有文字。
- 禁止只使用闪烁动画表达状态。

### 7.10 `Dialog`

替换业务流程中的裸 `QMessageBox`，统一实现：

- 信息对话框。
- 确认对话框。
- 危险确认对话框。
- 进度对话框。
- 成功/失败结果对话框。

要求：

- 明暗主题完全一致。
- 标题、正文、详情区和按钮区层次明确。
- 危险操作默认焦点放在“取消”。
- 数据库清理必须显示数据库地址、数据库名、备份目录和不可逆说明。
- 长路径支持换行和复制。

### 7.11 `Toast`

- 替代非阻塞型成功提示。
- 支持成功、信息、警告、失败四类。
- 位于主窗口右下角或顶部中央。
- 不阻塞后续操作。

### 7.12 `ScrollBar`

- 默认宽度 `8px`。
- 空闲状态降低透明度。
- 悬停时增强可见性。
- 不使用过亮滑块。

## 8. 页面整改计划

## 8.1 仪表盘 Dashboard

### 目标

将当前大卡片仪表盘改为“状态摘要 + 关键动作 + 最近活动”的简洁首页。

### 布局

1. 顶部页头：
   - 标题“NetOps Agent”。
   - 一行版本和授权说明。
   - 右侧放置服务启动/停止主操作。
2. 状态摘要区：
   - 后台服务状态。
   - 控制器连接状态。
   - 当前管理地址。
   - 最近同步时间。
3. 快捷操作区：
   - 启动/停止服务。
   - 打开 Web 管理端。
   - 运行诊断。
   - 打开日志。
4. 最近事件区：
   - 最近 3–5 条服务事件。
   - 无事件时显示克制空态。

### 视觉要求

- 状态摘要不使用四张厚重卡片。
- 优先采用一张主表面中的多列摘要。
- 服务停止只在状态文字和主操作上使用危险色。
- 诊断输出采用代码块样式，可复制。

## 8.2 服务管理 Service

### 目标

突出当前服务状态和主要操作，弱化低频技术信息。

### 布局

1. 服务状态页头。
2. 主操作：启动、停止、重启。
3. 运行信息列表：
   - PID。
   - 端口。
   - 运行时长。
   - 健康状态。
   - 工作目录。
4. 控制器连接信息。
5. 高级操作折叠区。

### 行为要求

- 启停期间按钮进入 loading 状态。
- 禁止重复点击。
- 启动失败展示结构化错误和日志入口。
- 成功操作使用 Toast，不使用阻塞弹窗。

## 8.3 实时日志 Logs

### 目标

采用接近 Codex 终端/任务输出的工作区风格。

### 布局

1. 顶部工具栏：日志源、搜索、暂停、清空视图、导出。
2. 单一日志画布。
3. 底部状态栏：文件路径、行数、跟随状态。

### 视觉要求

- 日志区使用中性深色，不随明亮主题变成纯白代码区。
- 使用 `Cascadia Mono`。
- INFO、WARN、ERROR 仅对级别标签着色，不整行高饱和。
- 搜索命中采用低透明背景。
- 滚动条保持轻量。

### 行为要求

- 暂停自动滚动不停止日志采集。
- 搜索不破坏原始日志缓存。
- 导出前显示目标路径。

## 8.4 偏好设置 Settings

### 目标

彻底取消现有“左侧滚动大卡片 + 右侧固定系统卡”结构，改为 Codex 风格单列设置页。

### 页面结构

1. **常规**
   - 随系统自动启动。
   - 自动运行后台服务。
   - 关闭窗口时最小化。
   - 自动检查更新。
   - 服务启动后打开浏览器。
2. **外观**
   - 界面语言。
   - 主题模式。
   - 后续可预留“跟随系统”。
3. **连接**
   - 控制器 IP。
   - 当前连通状态。
   - 测试连接。
4. **系统信息**
   - 默认折叠。
   - 展开后显示主机名、系统、CPU、内存、磁盘、MAC、Python 和本机 IP。
5. **高级维护**
   - 修改环境配置。
   - 重置代理客户端。
   - 清理数据库。

### 视觉要求

- 页面最大内容宽度约 `820–880px`。
- 每个分组使用标题和若干扁平设置行。
- 分组之间使用 `24–32px` 留白。
- 行之间只使用弱分隔线。
- 危险区域放在页面最底部。
- “清理数据库”不在默认状态下显示高饱和红色填充。

### 行为要求

- 设置变更后在当前行显示短暂“已保存”。
- 连接测试显示 loading、成功和失败。
- IP 输入错误时使用行内校验，不弹系统对话框。
- 主题切换不重建窗口、不闪白。

## 18. 风险与应对

### 18.1 自定义标题栏兼容风险

**风险**：影响 Windows Snap Layout、多屏拖动、DPI 和窗口阴影。

**应对**：标题栏作为独立阶段；验证失败时回退原生标题栏，只同步深浅主题。

### 18.2 单文件拆分风险

**风险**：页面成员变量和事件回调大量依赖主窗口实例。

**应对**：先抽离无状态组件和主题，再通过显式回调迁移页面；不一次性拆完。

### 18.3 QSS 行为差异

**风险**：不同 PySide6/Qt 版本对伪状态和后代选择器支持不一致。

**应对**：关键状态使用明确 objectName/property，并对自绘控件直接应用 palette。

### 18.4 高 DPI 风险

**风险**：固定像素尺寸在 150% 以上缩放失真。

**应对**：减少固定宽度；图标使用 SVG；在多个 DPI 下截图验收。

### 18.5 业务回归风险

**风险**：视觉重构误改服务启停、数据库清理和设置保存逻辑。

**应对**：页面类只调用现有业务函数；业务逻辑不与 UI 重构同时调整。

### 18.6 打包风险

**风险**：新增模块和资源未被 PyInstaller 收集。

**应对**：更新 spec/打包脚本；在干净环境验证资源路径和 hidden imports。

## 19. 回滚方案

1. 每个阶段保持独立、可审查的变更集。
2. 主题系统、组件、页面和标题栏分别提交。
3. 新旧页面迁移期间可保留短期 feature flag，但最终交付前移除无用旧路径。
4. 自定义标题栏可单独回滚。
5. 打包失败时继续保留上一版可用 EXE。
6. 不修改用户现有 `desktop_settings.ini` key；新增 key 必须有默认值。
7. 若新主题出现严重可读性问题，可临时切回旧 QSS，但不回滚业务功能。
