# Implementation Plan: 资产机柜联动与 Excel 导入异常校验拦截 (方案三)

我们计划在资产管理模块实现两项核心优化：
1. **数据中心与机柜输入联动**：在手动录入资产时，推荐并关联已有的机柜数据（级联联想下拉与自动反填）。
2. **Excel 批量导入异常处理**：在用户使用 Excel 批量导入设备时，智能分析并拦截未录入的异常机柜，提供交互式面板让用户选择“自动创建缺失机柜”、“手动纠错映射”或“跳过不合规行”，防止垃圾数据污染数据库。

---

## 1. 拟修改与新增文件

### [MODIFY] [AssetModal.tsx](file:///e:/data/netsops/src/pages/AssetManagement/components/AssetModal.tsx)
- 在组件打开时异步请求 `/api/racks` 获取全量已有机柜数据。
- 提取出不重复的数据中心（DC）列表，在输入数据中心时进行联想推荐（HTML5 `<datalist>`）。
- 根据选中的数据中心，动态级联筛选该 DC 下的机柜，在输入机柜时进行联想推荐。
- 智能反向填充：如果用户直接选择某个机柜且数据中心为空，自动反填对应的真实数据中心。
- 扩展底部的通用 `Field` 组件以支持传入 HTML5 `list` 联想列表 ID 属性。

### [NEW] [AssetImportValidationModal.tsx](file:///e:/data/netsops/src/pages/AssetManagement/components/AssetImportValidationModal.tsx)
- 创建一个新的异常确认弹窗组件。
- 渲染一个异常提示表格，显示不匹配/缺失的机柜信息（行号、填写的机柜名称、数据中心名称）。
- 提供如下交互动作：
  * **自动新建缺失机柜 (Auto-Create)**：勾选后批量调用 `/api/racks/batch` 把缺失的机柜以默认配置（42U等）同步录入 CMDB 数据库，然后再继续导入设备资产。
  * **纠错映射 (Map / Edit)**：为每行异常数据提供已有合法机柜的下拉列表，用户可直接在网页上将填错的机柜名称（例如 `A-O1`）纠正并映射为已有的正确机柜名称（如 `A-01`）。
  * **跳过不合规行 (Skip)**：直接从导入载荷中剔除这部分异常数据，只导入其他合规的资产数据。
  * **取消导入 (Cancel)**：中止本次 Excel 导入。

### [MODIFY] [index.tsx](file:///e:/data/netsops/src/pages/AssetManagement/index.tsx)
- 在 Excel 解析完毕（`handleImport` 函数）后，调取已存机柜列表进行校验。
- 如果存在不匹配的机柜，不直接调用后端导入，而是调起新建的 `AssetImportValidationModal` 确认弹窗。
- 拦截并接管成功解决异常后的最终提交请求，刷新数据统计。

## 2. 验证方案

### 自动化单元测试
- **测试兼容逻辑**：执行现有的全量 352 项 Pytest 测试套件确保没有影响任何原有接口。

### 手动功能走查
1. **单设备录入联动**：
   - 打开“新增资产”弹窗，数据中心和机柜输入框是否有默认联想提示。
   - 选择一个数据中心，检查机柜输入框的选项是否自动过滤只剩下该数据中心所属的机柜。
   - 直接选一个机柜，检查数据中心是否被智能自动填充。
2. **Excel 异常校验拦截**：
   - 准备一个资产 Excel 文件，包含一些**未注册/不存在的机柜**。
   - 点击导入，确认系统弹出了异常校验拦截面板。
   - 验证“自动创建机柜”功能：导入后，检查 CMDB 中是否自动生成了这些缺失的机柜。
   - 验证“纠错映射”功能：在弹窗中选择已有相似机柜，确认导入后该设备被正确挂载在所映射的机柜下。
