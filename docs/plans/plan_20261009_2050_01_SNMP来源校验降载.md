# SNMP 来源校验降载计划

## 目标

降低 LibreNMS 硬件传感器采集期间重复的来源可信校验，避免新规则扩大传感器清单后持续占用后端 CPU；保持来源验证失败关闭语义不变。

## 现状与证据

- 生产 `nexora-netops` 单 worker 持续约 100–140% CPU；停下页面请求后仍然如此。
- `snmp_hardware_loop` 每 10 秒运行，每周期最多 4 台设备并发；每台设备 `_load_active_sensors` 都会逐传感器调用 `is_trusted_hardware_sensor`。
- py-spy 调用栈多次落在 `_load_active_sensors` → LibreNMS 来源验证 → `_entry_is_verified` / `Path.resolve`。
- 当前导出约 3,896 个传感器行；LibreNMS v8 部署记录约 602 个活动传感器。新规则增大清单，放大了逐条重复校验。

## 影响范围

- 后端硬件轮询器的传感器来源验证去重。
- 采样周期未到时，避免读取/解码整批传感器元数据及重复解析凭据。
- 对应的来源策略与 SNMP 硬件轮询单测。

## 拟修改文件

- `backend/services/snmp_hardware_poller_service.py`
- `backend/services/librenms_source_policy.py`
- `backend/tests/monitoring/test_snmp_hardware_poller_service.py`
- `backend/tests/snmp/test_librenms_source_policy.py`（如需覆盖缓存键完整性）

## 实施步骤

1. 在每次设备传感器加载过程中，以完整 provenance cache key 复用来源信任结果。
2. 在 `poll_only` 轮询中先用聚合 SQL 检查是否存在到期记录；未到期时跳过整批传感器 JSON 解码和凭据解析。
3. 保持每种不同 provenance 仍执行原始完整验证；采样值、标签或设备数据不得进入来源信任缓存身份；到期采样时仍加载并逐个保留所有传感器。
4. 增加重复 provenance 校验复用、采样到期边界、未到期跳过凭据/全量加载的回归测试。
5. 运行 SNMP 硬件轮询、来源策略、LibreNMS 无线规则/适配器和 Grafana 指标导出测试，并检查差异和工作区已有修改。
6. 按用户授权部署到 `192.168.204.128`。将本次相关的 Grafana 导出器、来源策略、硬件轮询器源码同步到主机 checkout；主机 checkout 的其他代码落后于运行镜像，因此以运行镜像为基础、仅覆盖硬件轮询器文件构建补丁镜像，并保留原镜像供回滚；不重建数据库或其他服务。

## 验证计划

- `.venv/Scripts/python.exe -m pytest backend/tests/monitoring/test_snmp_hardware_poller_service.py backend/tests/snmp/test_librenms_source_policy.py backend/tests/monitoring/test_librenms_wireless_rule_service.py backend/tests/monitoring/test_librenms_wireless_detail_adapters.py backend/tests/monitoring/test_grafana_metrics_export.py -q`
- 本次不改 SQL、数据库或持久化测试，无需运行 PostgreSQL-only policy scanner。
- 新镜像构建后检查 Python 编译及来源键导入；只重建 `netops` 服务，确认容器健康、采集日志无导入错误、传感器时间戳继续更新。
- 部署后使用多次 `docker stats --no-stream` 观察应用 CPU，并通过已登录 Grafana 检查 15 分钟 CPU 趋势及硬件指标仍在更新。刚重启后的短窗口只作为初步检查，不作为稳态 CPU 结论。

## 风险与回滚

- 风险：缓存键若漏掉任一 provenance 字段会错误复用信任结果。使用现有完整 provenance helper，并测试字段变化导致独立校验。
- 风险：主机 checkout 与运行镜像源码不同，直接 `docker compose build` 会从旧 checkout 构建并覆盖现有镜像行为。部署时必须以当前 `nexora-netops:latest` 运行镜像为基础，仅叠加轮询器文件。
- 回滚：保留部署前的镜像标签；如新容器启动或健康检查失败，恢复旧标签并只重建 `netops` 服务。此次不改变采集周期、采集数据或数据库状态。
