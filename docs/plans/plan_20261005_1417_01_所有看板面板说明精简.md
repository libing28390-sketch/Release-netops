# 实施计划：所有看板面板说明精简

## 任务目标
精简 Grafana 各 Dashboard 的面板说明，让运维人员先看懂指标含义；只在口径容易误解、无数据含义不明显或状态解释重要时保留说明，并改成简短、直白的中文。网络总览无线终端卡片改为在标题中明确数据来自控制器汇总，减少对面板说明图标的依赖。

## 现状与问题
仓库 12 份生成看板中有 83 个面板带说明。部分说明包含 Prometheus 标签、Exporter 实现细节、复杂统计公式和多重限定语，简单面板也重复显示提示图标，增加阅读负担。用户反馈面板旁的“i”说明过多且难懂。

## 影响范围
仅调整面板说明文案、网络总览无线终端卡片标题及其测试契约；不修改 PromQL、指标、面板布局、Dashboard 级说明、采集逻辑或运行中的 Grafana。生成器会重写其管理的 12 份看板 JSON，生成前后核对所有输出，保留与本任务无关的差异。

## 拟修改文件
- `monitoring/grafana/generate_dashboards.py`
- `monitoring/grafana/dashboards/` 下由该生成器管理的 JSON
- `backend/tests/monitoring/test_domestic_and_wireless_monitoring.py` 及其他对面板说明作精确断言的相关测试
- 本任务 `docs/plans/`、`docs/walkthrough/` 与 `docs/fixes/` 记录

## Agent 分工与接口约束
- 主 Agent 负责生成器、全部 12 份 JSON、计划/走查/修复记录和集成审查；指标查询、采集口径、布局和 Dashboard 级说明保持不变。
- 子 Agent `dashboard_help_tests` 只负责 `backend/tests/monitoring/test_domestic_and_wireless_monitoring.py`，为面板说明长度、AP 计数口径和“控制器汇总在线终端数”标题更新契约，并运行该文件的聚焦测试。
- 双方共享同一工作区；不同时编辑相同文件。主 Agent 集成后统一重跑共享验证。

## 实施步骤
1. 复核面板说明现状和所有依赖其文本的测试断言。
2. 删除标题已能说明含义的重复说明，减少不必要的“i”图标；对必须保留的说明改写为一条简短、易懂的中文句子。
3. 保留避免误读所必需的口径，例如无线终端数来自控制器汇总、无数据不等于 0、AP 状态不等于配置总量、接口 Down 的管理状态范围、速率不等于累计流量、采集指标不等于端到端 SLA。
4. 按生成器管理的 12 个输出检查工作区，然后运行生成器，只保留预期的面板说明差异。
5. 更新相关测试，验证关键语义仍清楚且保留说明足够简短；解析全部 JSON，复核 diff 并运行聚焦质量门禁。
6. 更新走查与修复记录，确认 `main`、提交图和远端状态；沿用用户此前“修复完成后直接 push”的授权。

## 验证计划
- `\.venv\Scripts\python.exe -m pytest backend/tests/monitoring/test_domestic_and_wireless_monitoring.py -q`
- `python -m py_compile monitoring/grafana/generate_dashboards.py`
- 解析 `monitoring/grafana/dashboards/` 下全部 JSON，确认生成器 12 个输出的结构均有效。
- 检查修改后的面板说明篇幅与剩余图标数量，并复核指标口径说明。
- `git diff --check` 与完整 diff 审阅。

## 风险与回滚
说明过度精简可能隐藏指标适用范围，因此只对标题已清楚的普通面板移除说明，保留关键数据口径与运维限制。生成结果不改变面板查询和数据。如果测试、审阅或目标 Grafana 预览发现说明造成歧义，可恢复对应生成器文案并重新生成；不触及设备、采集任务、数据库或 Grafana 运行态。
