# 实施计划 - 修复 CI 异步测试用例报错 (pytest-asyncio 缺失)

## 1. 任务目标
修复 GitHub Actions CI 中 `Backend Pytest Check` 工作流执行失败的问题。CI 在执行 `backend/tests/topology/test_snmp_lldp_discovery.py` 时由于缺少 `pytest-asyncio` 插件，导致 4 个使用了 `@pytest.mark.asyncio` 的 `async def` 测试用例直接报错失败（其余 2252 个用例全部通过）。

## 2. 现状与问题分析
- **CI 报错信息**：
  ```
  FAILED backend/tests/topology/test_snmp_lldp_discovery.py::test_collect_snmp_lldp_neighbors_success - Failed: async def functions are not natively supported.
  FAILED backend/tests/topology/test_snmp_lldp_discovery.py::test_collect_snmp_cdp_fallback_when_lldp_empty - Failed: async def functions are not natively supported.
  FAILED backend/tests/topology/test_snmp_lldp_discovery.py::test_topology_service_collects_snmp_first - Failed: async def functions are not natively supported.
  FAILED backend/tests/topology/test_snmp_lldp_discovery.py::test_collect_snmp_lldp_prefers_port_id_over_description - Failed: async def functions are not natively supported.
  PytestUnknownMarkWarning: Unknown pytest.mark.asyncio
  ```
- **根因分析**：
  1. `.github/workflows/backend-pytest-check.yml` 中的依赖安装命令为：
     `pip install -r backend/requirements.txt` 和 `pip install pytest`，环境中未安装 `pytest-asyncio` 插件。
  2. 查阅全项目已有的 2250+ 个测试（分布于 100+ 个测试文件），整个项目从不依赖 `pytest-asyncio`，所有涉及异步协程的测试（如 `test_topology_scheduler_outcome.py`、`test_snmp_walk_api.py`、`test_dia_001_019_diagnostic_orchestrator.py` 等），均统一采用标准同步函数 `def test_*():` + `asyncio.run(...)` 的范式。
  3. `test_snmp_lldp_discovery.py` 是最新增加的文件，直接定义了 `async def test_*` 并加装了 `@pytest.mark.asyncio`，脱离了项目统一的测试约定，导致在 CI 纯净运行环境中直接被 pytest 判定不支持。

## 3. 影响范围
- 仅涉及测试文件：`backend/tests/topology/test_snmp_lldp_discovery.py`
- 不改动任何业务逻辑、接口、数据库或生产代码。

## 4. 拟修改文件
- [MODIFY] `backend/tests/topology/test_snmp_lldp_discovery.py`

## 5. 实施步骤
1. 修改 `backend/tests/topology/test_snmp_lldp_discovery.py`：
   - 移除 4 处 `@pytest.mark.asyncio` 装饰器。
   - 将 `async def test_collect_snmp_lldp_neighbors_success()` 改为 `def test_collect_snmp_lldp_neighbors_success()`，内部调用改为 `neighbors = asyncio.run(collect_snmp_lldp_neighbors('10.10.10.1', 'public'))`。
   - 将 `async def test_collect_snmp_cdp_fallback_when_lldp_empty()` 改为 `def test_collect_snmp_cdp_fallback_when_lldp_empty()`，内部调用改为 `neighbors = asyncio.run(collect_snmp_lldp_neighbors('192.168.100.1', 'cisco-ro'))`。
   - 将 `async def test_topology_service_collects_snmp_first()` 改为 `def test_topology_service_collects_snmp_first()`，内部调用改为 `batch, method = asyncio.run(_collect_device_observations(device))`。
   - 将 `async def test_collect_snmp_lldp_prefers_port_id_over_description()` 改为 `def test_collect_snmp_lldp_prefers_port_id_over_description()`，内部调用改为 `neighbors = asyncio.run(collect_snmp_lldp_neighbors('10.254.0.3', 'public'))`。
2. 确保与现有 2 个同步测试（`test_match_target_device_relaxed_delimiter`、`test_get_unmanaged_neighbors_filters_stale`）保持风格完全一致。

## 6. 验证计划
- 仿真无 `pytest-asyncio` 的 CI 环境：
  运行 `pytest -p no:asyncio backend/tests/topology/test_snmp_lldp_discovery.py -vv`
- 验证预期：
  6 个测试用例全部以 PASSED 通过，无 `PytestUnknownMarkWarning` 告警，退出码为 0。

## 7. 风险与回滚思路
- **风险**：低。仅为测试调用方式从外部 pytest 插件调度转为 Python 内置 `asyncio.run`，被测函数执行路径和断言完全相同。
- **回滚思路**：直接通过 `git checkout backend/tests/topology/test_snmp_lldp_discovery.py` 恢复原测试文件。
