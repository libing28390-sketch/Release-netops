# 前端生产构建进度提示计划

## 任务目标

让 Docker/生产环境中的 Vite 构建在长时间模块转换期间持续输出可见进度，减少将正常构建误认为卡死的情况。

## 现状与问题

- Dockerfile 的前端构建阶段直接执行 `vite build`。
- `vite.config.ts` 只有 React 与 Tailwind 插件，没有构建进度日志。
- 用户截图显示 BuildKit 的 RUN 阶段计时持续增加，但 Vite 停留在 `transforming...`；Vite 当前默认输出主要位于转换开始和阶段完成处。

## 影响范围与拟修改文件

- `vite.config.ts`：添加仅在 build 命令运行的轻量进度插件，按模块数报告状态。
- `scripts/build-frontend.mjs`：启动 Vite 子进程并每 10 秒输出外部心跳，确保 Vite 主事件循环忙碌时仍有日志。
- `package.json`：将 `npm run build` 路由到统一构建包装器。
- `Dockerfile`：Docker 镜像使用 `npm run build`，与本地生产构建共用进度包装器。
- `.github/workflows/release.yml`：把构建包装器纳入发布输入校验与公有源码筛选白名单，避免公有仓库缺少 Dockerfile 所需脚本。
- `docs/plans/plan_20260925_1034_01_前端构建进度提示.md`：本计划。
- `docs/walkthrough/walkthrough_20260925_1034_01_前端构建进度提示.md`：实现与构建输出记录。

## 实施步骤

1. 添加只作用于 `vite build` 的 Vite reporter，按模块数输出转换进度，不引入新依赖、不改 dev server 行为。
2. 添加 Node 构建包装器，在独立进程内每 10 秒输出存活/耗时状态，并正确传递子进程退出码。
3. 本地与 Docker 的生产构建统一通过包装器；发布工作流必须把包装器保留到公有树。
4. 运行本机生产构建，确认日志持续出现且最终构建照常成功；核对发布工作流路径清单。

## 验证计划

- 执行 `npm run build`，核对模块计数、周期性 heartbeat 与 Vite 最终完成行。
- 执行 `git diff --check`。
- 不运行单元测试；改动只影响 build 日志。

## 风险与回滚思路

- 插件只报告 Rollup 转换 hook 观察到的模块数，不提供预估总量百分比；避免误导用户。
- 包装器必须清除 heartbeat timer，并原样传播 Vite 退出码和信号结果。
- 若日志噪声或构建异常，可让 `npm run build` 直接调用 Vite，回到默认行为。
