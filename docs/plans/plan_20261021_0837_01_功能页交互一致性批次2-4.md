## 1. 目标

根据用户要求开始执行功能页第 2–4 批次，并特别统一、优化高频交互 UI。目标不是把 11 个入口套成相同布局，而是在保留各业务工作流的前提下，让共同交互有稳定预期：按钮层级与反馈、筛选/重置、菜单与弹层关闭、危险操作确认、键盘与焦点、加载/空态/错误态以及分页行为。

本任务遵循 Nexora 已有 React、主题 tokens、共享控件和各页数据/API/权限契约。优先复用 `ActionButton`、`ActionIconButton`、`FormField`、`FormLayout`、`Pagination`、`TableListControls`、`useEscapeClose` 等已有能力；对多处重复的弹窗焦点循环，主 Agent 新增栈式 `useFocusTrap`，统一初始焦点、Tab 边界和关闭后焦点返回。

## 3. 交互一致性验收原则

1. 主要、次要、危险操作使用明确且稳定的视觉/禁用/加载反馈；图标按钮有可访问名称，焦点可见。
2. 搜索遵循页面现有的提交或即时查询约定；重置必须同步 UI 条件、请求条件与页码，不能只清空输入框。
3. 对话框、弹层、菜单与抽屉保留现有业务契约；支持项目已有的 Escape/关闭方式、内部滚动和提交中状态，不随意改权限或操作范围。
4. 列表和工作台区分首次加载、筛选加载、无数据、无匹配、错误/重试和权限拒绝，不把缺失数据画成健康零值。
5. 保持中英文和深浅主题语义；使用现有 `--ui-*` tokens，不增加组件库、状态库或 API/schema。
6. 不使用浏览器或 computer-use 工具（遵循用户后续限制）。浏览器视觉和交互实测留为明确的待验收证据，源码/单测不能替代该结论。

## 5. 实施步骤

1. 基于当前工作区读取页面组件、调用链、API 契约和已有测试，按交互清单找出真实不一致或可验证缺陷。
2. 第 2–4 批按页面边界并行实施；主 Agent 审查执行者差异并完成 CMDB、Config、Platform、AI Center。
3. 先运行页面聚焦测试；如需共享组件或语义类型改动，由主 Agent 扩展实际受影响调用方测试。
4. 集成后运行 `npm run lint`、聚焦前端测试与隔离 Vite build，并检查 `git diff --check` 和全局未提交变更。隔离构建使用直接 Vite CLI；`scripts/build-frontend.mjs` 不转发参数。
5. 更新 `.agents/skills/netops-frontend/references/page-coverage.md` 的逐页状态和本 walkthrough，明确实现/源码审查与浏览器实测的差异。
6. 由于用户要求停止调用 computer-use 工具，保留需真实视口、键盘焦点、交互弹层或浏览器请求证据的检查为待验收项，不虚报通过。

## 6. 验证与完成标准

- 按页面现有测试覆盖检查列表/工作台的筛选、重置、分页、详情/弹层、确认和状态反馈；不新增仅测试 CSS 类名的断言。
- `npm run lint` 通过；使用未占用且位于仓库内的隔离目录完成直接 Vite 构建，不覆盖既有用户目录。注意：本轮误用包装脚本的第一次构建未识别 `--outDir`，刷新了 `dist/`；随后直接 Vite CLI 的隔离构建通过。此副作用已记入 walkthrough。
- `git diff --check` 与计划/walkthrough/coverage 文档空白和冲突标记检查通过。
- 11 个入口逐一获得“已实现”“审查通过、无需修改”或“待验收”的有证据结论。未完成的浏览器验收必须保留 In review/Browser checked 等准确状态；不因本计划代码测试通过就标记 UI 全面完成。

## 7. 风险与回滚

- 交互表面相似但 API/权限语义不同：逐页保留查询参数、页码、选择范围和确认范围，不强行统一业务行为。
- 页面组件庞大且状态多：限制为局部、可审查改动；不批量重排代码或整页重写。
- 浏览器证据不可补：如实标记，不用静态测试冒充 UI 验收。
- 保留 `handoff.md`、导航配置、已有验证目录和其他用户未提交变更。`dist/` 因第一次构建副作用已刷新，无法从当前工作区确认原始生成文件内容；未使用不匹配的旧快照覆盖，需在交接时明确说明。回滚仅针对本计划新增的页面差异与对应记录，不执行全工作树恢复。
