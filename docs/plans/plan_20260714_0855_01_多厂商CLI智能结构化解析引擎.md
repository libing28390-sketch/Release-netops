# 多厂商 CLI 智能结构化解析引擎（仅针对华为与华三平台）

本实施计划旨在将现有的 TextFSM 解析 and 生成流程重构成一个健壮、具备平台感知和版本感知能力的结构化解析引擎。系统将优先采用多层级判定策略：本地自定义模板 -> 内置 NTC 模板 -> 兜底解析，并结合解析质量评分（记录匹配覆盖率与置信度）来防止数据在解析时发生无声丢失。

## 严格执行边界约束

* **目标厂商与软件平台**：
  * **华为平台**：`huawei_vrp`（主流交换机/路由器，如 S5700、AR系列）、`huawei_vrpv8`（高端数据中心交换机 CE 系列）、`huawei_smartax`（OLT 设备）、`huawei_ont`（光猫/光网络终端设备）、`huawei_usg`（USG 系列安全防火墙设备）。
  * **华三/HP平台**：`h3c_comware`（华三 Comware v7/v9 交换机/路由器/防火墙）、`hp_comware`（HP/华三 Comware v5/v7 历史设备平台）。
  * 其他非华三、华为厂商（如 Cisco、Juniper 等）模板完全不作变更，排除在本次模板更新范围外。
* **仅补齐缺失模板，不覆盖默认**：
  * 如果内置的 `ntc-templates` 中已经存在对应的华为/华三命令解析模板（如 `display version`、`display arp all` 等），**严禁**重复创建自定义模板或修改它，直接使用内置模板。
  * 我们只针对内置模板中**完全缺失**的华为/华三系统状态与核心监控命令进行补齐（例如：`display cpu-usage` / `display cpu usage`、`display memory` / `display memory-usage`、`display ip routing-table statistics`）。
* **权威官方数据源**：所有的自定义解析正则和测试回显，必须参考**华为官方文档中心（Hedex）**与**新华三（H3C）技术支持文档中心**的 Command Reference 标准回显规范，确保对不同系统版本（如 VRPv5/VRPv8，Comware v5/v7/v9）的回显兼容性。

## 用户审核要点

> [!IMPORTANT]
> **向后兼容性保证**：现有的 `parse_with_textfsm(platform, command, output)` 接口将保留为兼容性包装器，内部直接调用新的智能解析引擎并返回解析后的记录列表。这保证了原有的拓扑采集、数据规格化（normalizers） and 现有巡检逻辑 100% 零修改、零回归。

> [!WARNING]
> **防止内置模板冲突**：解析引擎在匹配时，如果检测到对应命令在默认 NTC 库中已有解析器，将直接路由到内置解析通道，确保系统自带标准模板不受影响。

> [!NOTE]
> **新增智能解析 API**：新增 `/api/textfsm/smart-parse` POST 接口，将详细的解析遥测数据（匹配得分、匹配行数/总候选行数、解析源类型）暴露给前端。

## 拟修改的文件

### 1. 解析引擎核心逻辑

#### [修改] [textfsm.py](file:///e:/data/netsops/backend/core/textfsm.py)
* 新增 `smart_parse_cli` 函数：
  ```python
  def smart_parse_cli(
      output: str,
      command: str,
      platform: str | None = None,
      version: str | None = None,
      model: str | None = None
  ) -> dict[str, Any]
  ```
* 在 `smart_parse_cli` 内部实现以下处理层：
  1. **数据清洗与预处理**：剥离 ANSI 颜色代码、回车符 `\r`、命令回显行、分页符（如 `--More--`）以及设备命令行提示符（如 `[HUAWEI]`、`<H3C>`）。
  2. **平台与命令标准化**：
     * 利用别名映射字典对命令缩写进行标准化归一（例如：把 `dis ip int br` 归一为 `display ip interface brief`，将 `dis cpu` 归一为 `display cpu usage`）。
  3. **优先级路由与平台隔离**：
     * 第一优先级：精确匹配本地 `custom/` 自定义华为/华三模板。
     * 第二优先级：精确匹配内置 `upstream/ntc` 模板。
     * 兼容性降级匹配：如果找不到精确匹配（如传入平台 `huawei_vrpv8` 但没有该平台的某命令模板），则在同一厂商下尝试退级兼容模板（如退级尝试 `huawei_vrp` 下同命令模板；`h3c_comware` 退级尝试 `hp_comware` 模板）。
  4. **TextFSM 执行与解析覆盖率打分**：
     * 执行 TextFSM 状态机解析。
     * 自动统计回显中的**有效候选数据行数**（排除了表头、分隔线、空行、尾部统计信息），并与 TextFSM 匹配出的记录条数（`matched_rows`）进行对比。
     * 计算解析置信度评分 `confidence`（如果有效行数与解析记录数不相等，表明发生了未匹配的数据行丢失，置信度会显著降低并生成警告）。
  5. **字段映射标准化**：统一将提取 of 非标字段名（例如华为/华三在不同命令中使用的 `IPAddr`/`IP_Address`/`Addr`）自动映射映射为系统标准的 CMDB 字段名（如 `IP_ADDRESS`）。
* 将现有的 `parse_with_textfsm` 重构为包装器，直接调用并提取 `smart_parse_cli` 的数据结果返回。

### 2. 接口层扩展

#### [修改] [textfsm_templates.py](file:///e:/data/netsops/backend/api/textfsm_templates.py)
* 新增 `/textfsm/smart-parse` 接口，支持前端执行完自定义命令后，一键获取遥测报告（解析条数、匹配率、警告信息等）。

### 3. 模板自动生成优化

#### [修改] [textfsm_builder_service.py](file:///e:/data/netsops/backend/services/textfsm_builder_service.py)
* 优化 `auto_generate_template` 框架：在通过数据表头自动构建正则和状态机骨架时，优先匹配内置的**标准字段字典**（如根据列头包含 `IP` 自动匹配标准 `IP_ADDRESS` 正则，避免生成不规范 of 正则名），进一步提升针对华三/华为自定义命令回显的自动生成质量。
