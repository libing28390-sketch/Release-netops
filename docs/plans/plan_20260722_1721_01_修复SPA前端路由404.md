# 实施计划：修复 SPA 前端路由 404 错误

解决在 Windows 桌面端或浏览器直接访问/刷新 `/dashboard`、`/devices` 等前端子路径时，FastAPI 返回 `{"detail": "Not Found"}` 404 错误的问题。

## 问题根因

1. 在当前 `backend/main.py` 中，托管生产前端 `dist/` 目录使用的是默认 `fastapi.staticfiles.StaticFiles(directory="dist", html=True)`。
2. 当用户直接在浏览器中访问非根路径（例如 `http://127.0.0.1:5010/dashboard`）或刷新页面时，HTTP 请求会直接发送给 FastAPI 后端。
3. `StaticFiles` 查找磁盘上是否存在 `dist/dashboard` 或 `dist/dashboard.html` 文件，由于不存在，`StaticFiles` 返回 `404 Not Found` JSON 响应，导致用户界面显示 `{"detail": "Not Found"}`。

## 拟修改文件

- `backend/main.py` (修改 `StaticFiles` 挂载逻辑，引入 `SPAStaticFiles` 处理单页应用回退)
- `backend/tests/test_spa_routing.py` (新增回归测试)

## 实施步骤

1. 在 `backend/main.py` 中定义继承自 `StaticFiles` 的 `SPAStaticFiles` 类：
   - 截获 `404 Not Found` 响应。
   - 判断请求路径：排除 `/api/` 接口请求、`/static/` 静态文件请求以及明确带有静态后缀（如 `.js`, `.css`, `.png`, `.ico` 等）的缺失资源。
   - 对于非 API 且无文件扩展名的单页路由请求（如 `/dashboard`、`/devices`、`/topology`），自动回退返回 `dist/index.html`。
2. 将 `app.mount("/", StaticFiles(directory="dist", html=True), name="static")` 替换为 `app.mount("/", SPAStaticFiles(directory="dist", html=True), name="static")`。
3. 编写自动化单元测试 `backend/tests/test_spa_routing.py` 校验：
   - GET `/` 返回 200 index.html。
   - GET `/dashboard` 返回 200 index.html。
   - GET `/api/nonexistent` 返回 404 JSON。
   - GET `/nonexistent.js` 返回 404。
4. 运行 `pytest` 单元测试验证功能正常。

## 验证计划

### 自动化测试
- 运行 `pytest backend/tests/test_spa_routing.py` 验证 SPA 路由回退逻辑。
- 运行现有后端回归测试。

### 手动验证
- 启动服务后，在浏览器直接打开 `http://127.0.0.1:5010/dashboard`，确认能正确加载前端页面而非返回 404。
