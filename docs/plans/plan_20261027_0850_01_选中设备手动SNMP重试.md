# 选中设备手动 SNMP 同步重试计划

## 任务目标

在资产管理列表中，允许用户勾选已导入的网络设备，手动重新读取 SNMP `sysName` 与设备型号；逐台反馈成功、部分成功、跳过或失败，并保留未完成设备的选择以便重试。

## 现状与问题

- 资产导入和手动新建设备会自动触发 SNMP 识别；现有资产列表没有单独的再次同步入口。
- 资产表已有勾选、多选、批量操作和反馈消息模式，可复用现有交互。
- SNMP 型号 Walk 现已限制为单并发、每列最多 2000 行；重试接口应复用该识别服务和机柜同步逻辑。

## 影响范围

- 新增资产批量手动 SNMP 同步 API，校验操作权限、资产访问范围、资产类型及关联设备。
- 资产列表选中操作区增加“重新同步名称/型号”入口和逐台结果面板。
- 不设置选中数量硬上限；身份读取并发受控、型号 Walk 单并发，避免同时压垮 HCL Agent。
- 尊重 `snmp_collection_enabled`：开关关闭时跳过，不发起 SNMP 请求，不修改主机名或型号。
- 重试操作记录资产审计事件；不发送任何设备配置命令。

## 接口约束

- `POST /api/assets/batch-snmp-sync`
- 请求：`{"asset_ids": ["..."]}`，去重、去空，至少 1 个，不设置最大台数。
- 响应包含 `requested/synced/partial/failed/skipped/results`；结果逐台提供资产 ID、主机名、管理 IP、状态、消息、SNMP 主机名状态、检测型号、已同步型号、型号来源及机柜同步状态。
- 后端使用 `Operator` 角色和现有资产 update scope；仅处理 `network_device` 且关联 `devices` 记录的资产。
- 复用 `identify_imported_device`，设备身份 GET 并发受控，ENTITY-MIB 型号 Walk 共享单并发信号量；识别完成后复用现有机柜型号同步。较大批次会等待串行型号 walk 完成后逐台返回结果。
- 前端对成功设备取消选择，保留 partial/failed/skipped 项供用户检查和再次尝试；不将凭据或 Community 放入响应。

## 文件与协作边界

- 后端执行者：`backend/api/assets.py`、`backend/tests/configuration/test_asset_management_method_import.py`。
- 前端执行者：`src/pages/AssetManagement/index.tsx`、`src/pages/AssetManagement/index.test.tsx`。
- 主 Agent：维护本计划和 walkthrough、定义接口、集成审查与公共验证。
- 所有执行者共享同一工作区；保留已有用户修改，不回滚他人文件，不创建子 Agent。

## 实施与验证

1. 后端实现带权限与范围校验的批量同步接口，覆盖无凭据、SNMP 失败、已关闭采集、成功和机柜同步结果。
2. 前端复用选中操作栏，增加有忙碌状态的手动同步按钮和逐台结果反馈；失败项保持选中。
3. 运行聚焦后端隔离 PostgreSQL 用例和资产管理前端测试，再运行 `npm run lint`、`py_compile`、PostgreSQL-only 扫描及 `git diff --check`。
4. 如当前浏览器环境可安全识别目标 URL，再做只读页面核对；不在共享设备数据上触发批量同步。

## 风险与回滚

- 不设设备数量上限；大量设备需要等待串行型号 Walk 完成，前端显示正在同步状态。单设备仍受 3 秒 OID 超时和设备响应影响；未响应设备逐项返回失败/部分完成结果。
- 只读 SNMP GET/WALK；不修改交换机配置。写入范围限于识别服务已有的 CMDB 主机名、型号、平台字段及机柜设备类型同步。
- 回滚只需移除新 API、前端操作和相关测试/文档；无需数据库迁移。
