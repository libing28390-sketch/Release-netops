# 邮件通知列表视觉精简

## 任务目标

精简 `/management/notifications` 的 SMTP 通道列表，改善信息层级、横向布局和小屏适配；并修正向导“仅保存”的成功流向和通道启用状态颜色。

## 现状与问题

- 列表使用固定最小宽度的宽表格，收件人、状态、更新时间和四个操作按钮挤在同一行。
- 页面主体窄于可用视口并居中，少量通道时内容显得漂浮且留白分布不均。
- 页面标题、卡片标题和重复数量徽标表达重复。

## 影响范围

仅调整邮件通知设置页的展示和保存成功后的前端流向，不更改接口、数据模型、权限规则或邮件发送逻辑。通用保存函数继续供连接测试、发送测试复用；只有“仅保存”成功后返回列表。

## 实施步骤

1. 将 SMTP 表格改为响应式通道行，合并冗余字段并突出名称、状态、服务器和收件人。
2. 收敛列表标题和数量说明，调整主体宽度及对齐，让内容与页面标题区域协调。
3. 为启用/停用状态使用绿/红色标记；“仅保存”成功后返回通道列表，失败时留在向导并显示错误。
4. 保留测试连接与发送测试的当前流程，以及空态、加载/错误/权限态、逐通道反馈、权限禁用及删除确认。
5. 检查差异，运行前端 lint 与独立输出目录的生产构建。

## 风险与回滚思路

变更限定在单页 UI 和前端交互，主要风险是窄屏或长收件人名称造成布局溢出，或保存后错误切换页面。仅在保存 API 成功后切换列表；校验/API 失败仍留在向导。使用响应式 CSS 网格、截断和可访问按钮标签控制；如出现回归，可回退本页面改动。
