# 资产凭据校验错误

## 任务目标
- 让资产凭据保存失败时显示后端返回的结构化校验信息，避免只显示笼统提示。
- 不触发新的密码提交；修复并验证前后端错误响应契约。

## 现状/问题
- 用户在 `http://192.168.56.1:5400/assets/dashboard` 编辑服务器资产，浏览器显示“保存校验失败，请检查填写内容”。
- 后端日志记录对同一资产的多次 `PUT /api/assets/{id}` 返回 422。
- `src/api/http.ts` 对稳定 API 将 `payload.error` 结构对象保存为 `ApiError.detail`，其 `message` 字段含校验原因；资产页仅接受字符串 `detail`，将结构化错误回退到通用提示。
- 当前失败响应正文只存于浏览器内存中的已结束请求，日志未保存响应校验正文；不重提含凭据的请求无法从现有日志还原具体字段原因。

## 影响范围与拟修改文件
- `src/pages/AssetManagement/index.tsx`：兼容稳定 API 的结构化错误并继续脱敏密码。
- `src/pages/AssetManagement/index.test.tsx`：覆盖结构化 422 与密码脱敏。
- 本计划与同后缀 walkthrough。

## 实施步骤
1. 将 `error.detail.message` 作为结构化资产校验错误提示，并保留兼容字符串 detail、Request ID 与秘密值脱敏。
2. 增加聚焦回归测试，确保服务器校验信息可读且输入密码不会出现在错误提示。
3. 运行资产页相关前端测试、TypeScript lint 与前端构建；检查本地编辑页状态，不读取密码值。
4. 不代替用户重新提交或保存凭据；通过修复后的提示由用户确认后自行重试，或继续提供新提示让我进一步修复后端校验。

## 验证计划
- `npm run test:frontend -- src/pages/AssetManagement/index.test.tsx`
- `npm run lint`
- 浏览器曾只读确认重新打开的资产编辑页；开发热更新关闭了原弹窗，未保存的表单输入可能丢失，密码字段保持空白。没有重新输入或提交凭据。

## 风险与回滚思路
- 仅调整错误展示，不改变资产请求 payload、凭据绑定或后端状态。
- HMR 可能关闭编辑弹窗并丢失未保存表单状态；发现后只重新打开资产检查已保存信息，不重复输入或提交凭据，并如实告知用户。
- 回滚限于本次错误解析与测试文件。
