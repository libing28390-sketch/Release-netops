# 硬件采集精简与设备看板

## 任务目标

停止周期采集并停止导出电压、电流和未归一化的 LibreNMS 通用传感器读数，减少无业务用途的 SNMP 轮询和时序数据；精简网络设备详情 Grafana 看板，保留日常健康与排障所需的 CPU、内存、温度、风扇转速、风扇/电源状态及光模块功率。

## 现状与证据

- `nexora_hw_voltage_volts`、`nexora_hw_current_amperes` 目前只在设备详情看板展示，截图中面板为空。
- `nexora_hw_sensor_value` 是尚未归一化单位的 LibreNMS 通用读数，目前只供设备详情看板的“其他 LibreNMS 传感器读数”表格查询，没有告警或健康判断依赖。
- 发现能力状态和传感器质量是由已有库存/采样状态生成的诊断数据，不会额外触发 SNMP 读取；能力状态还参与无线看板的 AP 覆盖完整性判断，因此保留后端状态及所需指标，但从设备详情看板隐藏低频使用的诊断表。
- 风扇与电源部件状态被后端设备健康摘要使用，不能与无归一化的通用读数一起停采。

## 影响范围

- 后端周期采样调度、硬件探测轮询及硬件指标导出。
- 网络设备详情 Grafana 看板生成器及对应生成 JSON。
- 不删除硬件发现记录，不清除数据库历史样本，不修改无线能力状态及告警逻辑，不部署到服务器。

## 拟修改文件

- `backend/services/snmp_hardware_poller_service.py`
- `backend/services/snmp_hardware_probe_service.py`
- `backend/services/snmp_hardware_inventory_service.py`
- `monitoring/grafana/generate_dashboards.py`
- `monitoring/grafana/dashboard_presentation_v2.json`
- `monitoring/grafana/dashboards/nexora-network-device.json`
- 本计划与对应 walkthrough。

## 实施步骤

1. 在轮询候选加载、到期预检查和底层采样入口统一排除 `voltage_volts`、`current_amperes`、`sensor_value`，避免无效轮询和凭证检查。
2. 指标渲染时跳过上述类型，阻止旧的最后读数继续作为当前指标暴露；保留其发现记录和数据库样本供按需诊断。
3. 从设备详情看板移除电压/电流面板、通用原始读数表，以及发现状态/采集质量诊断区；保留对无线看板有用的能力状态指标和其他关键硬件指标。
4. 生成目标看板并审阅差异，确认非目标面板 ID、查询与变量保持不变。

## Agent 分工与文件边界

- 后端执行者：只修改三个 `backend/services/snmp_hardware_*` 文件；不修改看板和文档，不新增或运行测试，不回退其他工作区变更。
- 看板执行者：只修改 `monitoring/grafana/generate_dashboards.py`、`monitoring/grafana/dashboard_presentation_v2.json` 和生成的 `monitoring/grafana/dashboards/nexora-network-device.json`；同步删除目标面板对应的样式项；不修改后端和文档，不新增或运行测试，不回退其他工作区变更。
- 主 Agent：维护计划与 walkthrough，协调生成器和集成审查；两个执行者不得修改同一文件或继续创建子 Agent。

## 验证计划

- 运行看板生成器并解析生成的目标 JSON，确认目标面板已移除、剩余面板 ID 唯一且原查询/变量不变。
- 对三个后端文件进行语法级检查，并审阅静态过滤路径是否同时覆盖预检查、轮询和指标渲染。
- 运行 `git diff --check`。
- 按当前任务要求不新增、不运行自动化测试；不写入线上 Grafana 或服务器。

## 风险与回滚

- 若未来需要电源电压/电流或未归一化的设备专有传感器，可移除周期采样过滤并重新显示对应面板；发现记录与历史数据库样本保留。
- 关闭采样后，VictoriaMetrics 中已有的历史序列按现有保留策略自然过期，不主动删除历史数据。
- 无线看板依赖的 `nexora_hw_capability_status` 与 AP 覆盖标记保持不变。
