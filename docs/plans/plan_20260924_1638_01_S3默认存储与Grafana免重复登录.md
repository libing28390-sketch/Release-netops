# S3 默认存储与 Grafana 免重复登录

## 目标

- 让 Docker 部署的 `.env` 默认选择 S3-compatible SeaweedFS，并确保后端与 SeaweedFS 使用相同的非空凭据。
- 用户已通过 Nexora 认证后，访问 Grafana 页面不再出现第二次登录提示；不在浏览器中暴露 Grafana 管理员凭据，不启用匿名访问。

## 现状与问题

- 工作区 `.env` 被 Git 忽略，当前没有 `STORAGE_BACKEND` 和 S3 配置项；`.env.example` 与 Compose 默认都使用 `local`。
- 应用在 `STORAGE_BACKEND=s3` 时要求 endpoint、bucket 和非空访问密钥；部署脚本目前只自动生成数据库、Grafana 管理员及应用密钥。
- SeaweedFS 仅由 `object-storage` Compose profile 启动，部署脚本会按存储配置选择该 profile。
- Grafana 当前使用独立的管理员用户名密码，Nexora 的前端登录态没有传给 Grafana。
- SeaweedFS named volume 没有 Docker 磁盘配额，`weed mini` 命令也没有显式设置 volume 大小；总容量由宿主机 Docker 数据目录的文件系统空间决定。

## 影响范围

- Docker Compose 环境配置、初始化脚本、Grafana 反向代理和认证边界，以及 S3 容量边界文档。
- 本机被忽略的 `.env` 会先备份再编辑；真实密钥不得写入 Git 跟踪文件。
- 不执行部署，不启动/停止容器，不迁移现有本地存储数据。

## 拟修改文件

- `.env`（先建立同目录备份；只补充/更新存储项，不覆盖其他配置）与 `.env.example`
- `scripts/deploy-docker.sh`、`docker-compose.yml`、`backend/core/config.py`、`docs/deploy/docker.md`
- Grafana 的 Nginx/后端认证代理和前端入口文件（以安全架构审查结果为准）

## 实施步骤

1. 备份本机 `.env`，确认 S3 与 Grafana 相关现值只检查是否配置，不输出密钥内容。
2. 将新安装默认设为 S3；部署脚本为缺省/占位的 S3 凭据生成随机值，并让 SeaweedFS 与应用共用这些值。
3. 审查 Nexora 与 Grafana 的认证链路，使用已登录的 Nexora 会话建立服务端信任；拒绝匿名、URL 密码和前端明文凭据方案。
4. 为已有 Nexora 会话补发 Grafana 专用 Cookie，退出时撤销会话并清除 Cookie；更新 Docker 部署说明和 Grafana 入口。
5. 说明 S3 总容量由宿主机文件系统决定、前端无配额配置，并区分 SeaweedFS 单卷上限与 bucket 总容量。
6. 核对变更范围、`.env` 备份、环境变量示例和部署配置，不触发真实部署或存储迁移。

## 验证计划

- 检查 `.env` 解析与部署 profile 选择，保证 S3 配置下启用 SeaweedFS，并保持 LF/CRLF 兼容。
- 检查 Grafana 登录请求必须通过 Nexora 认证代理，且不能由外部请求自行伪造受信身份头。
- 运行 `git diff --check`；不运行构建/测试或部署，除非用户另行要求。

## 风险与回滚

- S3 启用后，既有本地录像/备份不会自动迁移；恢复 `.env` 备份可回到原存储配置，数据卷和本地文件不删除。
- Grafana 单点登录必须保留 Nginx 与后端的认证校验。若服务端认证代理失败，可回滚代理配置并继续使用 Grafana 独立登录。
- `.env` 备份包含现有私密配置，留在工作区且不加入 Git。
