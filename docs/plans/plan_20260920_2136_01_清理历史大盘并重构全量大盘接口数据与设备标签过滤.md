# 实施计划：清理历史大盘并重构全量大盘接口数据与设备标签过滤

## 1. 任务目标与背景
用户反馈：
1. Grafana 大盘列表中多出了一个 `07 服务器与主机监控 (Server & Host Metrics)`；
2. `04 接口流量与健康 (Interface Traffic & Health)` 这里的接口数据全部没有了，虽然设备和站点都有了，但没有接口数据。并且其他网络大盘也有类似丢失现象。

## 2. 根因剖析

### 2.1 为什么多出一个「07 服务器与主机监控」？
- 代码库前期曾使用 `nexora-server-metrics.json`，随后重构拆分为 `07 Linux 服务器监控` 和 `08 Windows 服务器监控`，磁盘上的旧 JSON 文件已被删除。
- 但老用户环境使用的 Docker 数据卷 `nexora-grafana-data` 中持久化了 Grafana 内置 SQLite 数据库。
- `monitoring/grafana/provisioning/dashboards/nexora.yml` 中配置了 `allowUiUpdates: true`，Grafana 官方规范规定：当允许 UI 更新时，磁盘文件被删除后，Grafana 不会自动从 SQLite 数据库中删除旧大盘，从而造成旧大盘与新大盘并存。

### 2.2 为什么接口数据全都没有了？
1. **`DEV_JOIN` 引入了对不存在的 `sysName` 指标的强制乘法过滤**：
   - 现代码使用了 `DEV_JOIN = "* on(instance) group_left(sysName) (last_over_time(sysName{sysName=~\"$device\"}[1d]) * 0 + 1)"`。
   - 经实测 VictoriaMetrics 时序库，`sysName` 指标仅在部分 H3C 设备上存在，全部 Cisco 设备（R1-R4、SW5-SW6 等）根本没有 `sysName` 指标！
   - 与空向量相乘导致所有无 `sysName` 指标的设备时序全部被强制清除（No data），不仅面板 5-8 丢失，连面板 1-4 的全网聚合流量也被乘没了。
2. **设备变量查询绑定了 `sysName`**：
   - 现代码 `$device` 查询为 `label_values({__name__=~"sysName"...}, sysName)`。在 Cisco 站点下查询为空，导致变量无法选取设备。
3. **原生标签体系被忽视**：
   - 所有网络时序原生带有 `hostname`、`instance`、`site_name`、`vendor`、`role`、`ifIndex` 等完整标签。
   - 过滤设备直接使用 PromQL 原生选择器 `hostname=~"$device"` 即可，根本不需要进行任何脆弱的时序 Join 乘法！
4. **`IF_JOIN` 乘法导致无 `ifName` 序列的接口被整体丢弃**：
   - 端口利用率与 Top 流量面板强依赖 `(ifName * 0 + 1)`，一旦匹配不上便丢弃时序。
5. **端口带宽利用率除法缺失兜底**：
   - 仅除以 `ifHighSpeed`，未考虑百兆口或无 `ifHighSpeed` 仅有 `ifSpeed` 的接口。

## 3. 拟修改范围

1. **`monitoring/grafana/generate_dashboards.py`**：
   - 彻底废除脆弱的 `DEV_JOIN` 乘法过滤，改用原生标签过滤 `hostname=~"$device"`。
   - 修改 `make_network_variables`：`device` 变量改从所有核心指标（`ifOperStatus|up`）中提取 `hostname`，支持 100% 覆盖所有厂商（Cisco、H3C、华为等）的全部设备。
   - 重构 `04 接口流量与健康` 的所有 8 个面板：
     - 面板 1/2/3/4：全局与过滤聚合流量、丢包与错包，直接基于 `hostname=~"$device"` 统计，增加 `or vector(0)` 兜底。
     - 面板 5/6：端口入向/出向流量 Top 10，安全关联 `ifName`，若无 `ifName` 优雅回退显示 `ifIndex`。
     - 面板 7：端口利用率 Top 20，`ifHighSpeed` 兼容 `ifSpeed` 回退，安全关联 `ifName`。
     - 面板 8：端口错误/丢弃 Top 20，安全关联 `ifName`。
   - 同步修正 `01 网络总览`、`02 设备详情`、`03 无线专网`、`06 互联网出口` 中所有因 `DEV_JOIN` 导致的数据丢失隐患，统一为 `hostname=~"$device"`。
   - 大盘版本号升级至 `24`。
2. **重新编译并生成 JSON 文件**：
   - 运行 `python monitoring/grafana/generate_dashboards.py`，更新 `monitoring/grafana/dashboards/` 下的全部 JSON 大盘。
3. **清理多余大盘策略**：
   - 提供 UI 勾选删除的明确说明；
   - 增加 API 清理脚本/命令，调用 Grafana API 彻底删除 `nexora-server-metrics`。

## 4. 实施步骤

1. 编辑 `monitoring/grafana/generate_dashboards.py`，完成变量与 PromQL 的重构。
2. 执行脚本重新生成所有大盘 JSON 文件。
3. 本地运行质量门禁：pytest 测试套件确保所有大盘完整性与编译契约通过。
4. 针对实机 VictoriaMetrics 进行真实 PromQL 表达式回归校验，确保全量设备与接口数据正常产生。
5. 记录修复文档 `fix_*.md` 与走查报告 `walkthrough_*.md`，最后提交并推送到 `main`。

## 5. 风险与回滚思路
- 本次改动仅优化 PromQL 表达式和标签匹配，不改动数据库结构，无破坏性风险。
- 如有异常，可通过 Git commit 直接回滚。
