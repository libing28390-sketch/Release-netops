---

## 1. 任务目标

对 Nexora 平台中 **SNMP 型号指标模板管理页面**（`/management/snmp-metric-templates`）进行架构解耦与交互体验升级：
1. **消除多层嵌套弹窗压迫感**：优化全屏路由下编辑视图的展示形态，实现平滑、沉浸且无层级冲突的模板编辑交互。
2. **列表筛选与搜索防抖**：支持厂商过滤（Vendor）、状态过滤（Status）及 300ms 防抖搜索，大幅提升模板定位效率。
3. **SNMP WALK 实时探测体验重构**：
   - 增加“从匹配设备快速选择”下拉框，自动填入 IP 与凭据标识，无需跳转资产页翻查；
   - 突破 30 行截断限制，支持探测结果关键字过滤搜索（如搜 `temp`、`cpu`）；
   - 保留一键反向填充至表单指标的能力。
4. **接口流量模板一键重置**：增加“恢复标准 IF-MIB”按钮，便于一键回退到 RFC 1213 / IF-MIB 17 项标准 OID。
5. **计算公式与常用倍数预设**：为温度、电压等指标提供常用倍数（如 `×1`、`×0.1`、`×0.01`、`×0.001`）快捷选项。
6. **大组件代码拆分与性能优化**：将近 2000 行的 `MetricOidProfilesModal.tsx` 拆分为职责单一、易维护、带 `React.memo` 渲染优化的子组件。

---

## 2. 现状与问题分析

- **单文件臃肿**：`MetricOidProfilesModal.tsx` 达 1891 行，列表、编辑、IF-MIB、WALK 客户端、自动匹配全部混杂，维护成本高且重渲染开销大。
- **操作层级深**：在页面内点击编辑弹出大 Modal，Modal 内再打开 OID 拾取或预置库又弹出第 3 层 Modal，容易产生滚动条冲突。
- **WALK 探测效率低**：用户必须手动输入 IP 按回车查找；探测结果只切片显示前 30 行，无法全局检索。
- **模板保存与验证同步等待**：保存后同步阻塞等待设备在线测试，设备不通时导致前端界面长时间卡顿在“保存中”。

## 5. 实施步骤

1. **后端适配**：在 `get_model_metric_profile_mapping` 服务中，将匹配设备的 `ip_address` 字段暴露在返回列表中。
2. **拆分与构建子组件**：
   - 提取 `MetricRowItem.tsx`：支持常用倍数快捷填入与 `React.memo`。
   - 提取 `InterfaceConfigSection.tsx`：增加“恢复标准 IF-MIB”按钮。
   - 提取 `LiveWalkInspector.tsx`：增加匹配设备下拉直选、全量结果关键字搜索与反向填充。
   - 提取 `MetricProfileList.tsx`：增加厂商筛选、状态筛选、防抖搜索与表格。
   - 提取 `MetricProfileEditor.tsx`：整合指标、接口与 WALK 面板，优化保存交互。
3. **整合与界面协调**：重构 `MetricOidProfilesModal.tsx`，无缝嵌入各子组件，确保独立页面与弹出窗两种形态均获得极致体验。
4. **前端构建与单元测试检查**：执行 TypeScript 检查与测试，确保无类型错误和破坏性回归。

## 6. 验证计划

- **功能验证**：
  1. 访问 `/management/snmp-metric-templates`，验证列表展示正常，厂商筛选与状态筛选有效。
  2. 搜索框输入关键字，验证防抖（debounce）实时触发搜索。
  3. 点击“新建”与“编辑”，验证编辑面板平滑展开，各项指标 OID 正常修改保存。
  4. 在接口模板中测试“恢复标准 IF-MIB”，验证 17 项 OID 一键还原。
  5. 在 WALK 面板中验证：若存在匹配设备，可从下拉框直选设备自动填入 IP；执行 WALK 后可按关键词过滤结果并反向填充到表单。
  6. 打开“MIB 拾取”与“官方预置”，验证多模态工具弹窗交互自然、无重叠滚动条问题。
- **质量门禁**：
  - 运行 `npm run lint` / `npx tsc --noEmit` 校验前端类型。
  - 运行相关 pytest 单元测试验证后端接口契约。

## 7. 风险与回滚思路

- **风险**：子组件拆分可能导致局部状态丢失或属性传递不完整。
- **应对策略**：统一使用严格 TypeScript 接口定义各子组件 Props，并在 `MetricOidProfilesModal` 中完整保持旧有方法与回调。若出现异常，可快速通过 Git 还原至重构前状态。
