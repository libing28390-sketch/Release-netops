# 采集器运维反馈与详情分离

## 目标

修复采集器管理页点击操作后缺少可见反馈的问题，并将只读详情与测试、校验、编译、发布操作分开。

## 现状与问题

- 采集器操作复用通用 `runAction`，成功时只显示“操作已完成”，且忽略接口返回的状态、版本和错误列表。
- 用户在运行页面点击测试后没有看到任何提示；详情弹窗内同时放置只读信息和编译、发布等运维操作。
- 测试 API 目前只返回记录是否启用及最近心跳时间，不检查实际连通性或采集数据，需要在界面明确说明。

## 影响范围

- 前端采集器管理页面及本任务的计划/完成记录。
- 不改后端接口，不对运行环境执行编译、发布、新建或删除操作。

## 拟修改文件

- `src/components/MonitoringManagementPage.tsx`
- `docs/plans/plan_20261018_2205_01_采集器运维反馈与详情分离.md`
- `docs/walkthrough/walkthrough_20261018_2205_01_采集器运维反馈与详情分离.md`

## 实施步骤

1. 增加采集器专用操作请求，保留接口响应供页面展示，并刷新列表状态。
2. 让采集器详情只展示信息；另设运维操作弹窗，显示加载中、成功结果与错误详情。
3. 将状态检查的真实范围写清楚；编译和发布使用明确的操作说明，发布前确认。
4. 运行前端 lint，并检查工作区差异，确认没有覆盖已有用户改动。

## 验证计划

- `npm run lint`
- 浏览器验证仅限本地前端交互；不得在运行环境触发编译、发布、新建或删除。

## 风险与回滚思路

- 变更限制在单个前端页面，不改变服务端配置状态契约。
- 如界面行为异常，可回退本次页面差异；不需要数据库迁移或运行环境回滚。
