# P0-P1 互联网出口监控逐项收口计划

## 任务目标

按上一轮清单逐项完成并验收 `WAN-P0-001~020` 与 `WAN-P1-001~012`，不以“代码存在”代替完成定义。每项必须具备实现、测试和可复核证据；无法访问真实目标环境的浏览器/真实 SNMP 项目单独标记为外部验收风险。

## 现状/问题

- 现有代码已覆盖链路监控、SNMP 失败语义、告警、趋势、分区/聚合、维护窗口、报告和前端页面的大部分实现。
- P0/P1 任务文件仍将所有主任务标记为 `in_progress`，细项复选框没有对应的逐项证据矩阵。
- 既有 walkthrough 记录显示分批回归通过，但真实监控地址不可达，串行全量 pytest 在门限内未完成。
- 需要补齐边界测试和发现的缺口（质量标志过滤、维护窗口时区/输入校验、报告/保留/分区门禁等），再更新清单和验收记录。

## 影响范围

- 后端：`backend/services/wan_link_service.py`、`backend/services/wan_p1_service.py`、`backend/api/monitoring.py`。
- 数据库：`backend/database/migrations/m0064~m0071_wan_*.py` 及数据库初始化/调度入口。
- 前端：`src/pages/OutboundHealthPage.tsx`、`src/components/Wan*.tsx`、相关 API 类型与测试。
- 测试/文档：`backend/tests/monitoring`、`backend/tests/scheduled_jobs`、`docs/plans`、`docs/walkthrough`。

## 实施步骤

1. 审计 P0/P1 清单、服务、API、迁移、调度、页面和现有测试，建立任务—证据矩阵。
2. 按依赖完成 P0-001~004：链路列表/汇总、告警复发、趋势降采样、采集失败语义。
3. 完成 P0-005~012：64 位计数器证据、质量校验、绑定、方向、批处理幂等、快照一致性、接口 Down 和利用率告警。
4. 完成 P0-013~020：API 契约、配置交互、总览/卡片/趋势、独立事件页、原探测回归、权限审计和综合验收。
5. 完成 P1-001~005：PostgreSQL 月分区、5 分钟/小时/日聚合、P95/峰值/高负载时长、保留策略、错包/丢弃。
6. 完成 P1-006~011：热度条、多维筛选、维护窗口/抑制、告警确认关闭审计、线路组、日报周报月报。
7. 完成 P1-012：性能查询、分区/聚合调度、发布门禁、逐项状态更新和 walkthrough 证据。

## 验证计划

- 先运行 `backend/tests/monitoring`、`backend/tests/scheduled_jobs` 和新增的逐项契约测试。
- 运行迁移幂等/升级/新库初始化测试，确认 PostgreSQL SQL 为权威语义；SQLite 仅作为现有测试兼容路径。
- 运行 `npm run lint`、前端相关测试、`npm run build` 和 `git diff --check`。
- 对真实目标环境不可达的页面、登录态、实时 SNMP 和浏览器交互不伪造通过证据，记录为外部验收项。

## 风险与回滚

- 迁移仅新增编号，不修改已执行迁移；分区、聚合和保留任务失败时事务回滚并写入运行记录。
- 采集失败继续保留失败样本和上次有效值，不产生零值覆盖或误报；若新逻辑异常，可通过调度开关停用 P1 rollup/retention，保留 P0 原始采集。
- 前端改动保持现有 API 响应兼容；发生回归时回退对应组件/API client，不删除历史样本或告警审计。
