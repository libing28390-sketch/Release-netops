# 实施计划 - 统一所有容器北京标准时间配置

## 1. 任务目标
排查并修复项目中所有 Docker 容器的时区配置，确保所有服务（PostgreSQL 数据库、NetOps 应用、Nginx 反向代理、Redis 缓存、VictoriaMetrics、vmagent、snmp-exporter、Grafana）均统一运行在**北京标准时间 (Asia/Shanghai, UTC+8)**。

## 2. 现状与审计结论

| 容器服务 | 基础镜像/构建源 | 当前时区现状 | 是否满足北京时间要求 | 缺失项 / 问题 |
| :--- | :--- | :--- | :--- | :--- |
| **netops** | `Dockerfile` (`python:3.11-slim`) | `Dockerfile` 安装了 `tzdata` 并设 `ENV TZ=Asia/Shanghai`；Compose 注入 `TZ=${TZ:-Asia/Shanghai}` | 满足 | 镜像内未建立 `/etc/localtime` 和 `/etc/timezone` 软链接，可补充软链接强化 OS 级命令行一致性 |
| **db** | `docker/postgres/Dockerfile` (`pgvector/pgvector:0.8.6-pg18-bookworm`) | Compose 设置了 `timezone=Asia/Shanghai` 与 `TZ` | 部分满足 | `docker/postgres/Dockerfile` 未安装 `tzdata`，容器 OS 层面缺少 zoneinfo 文件支持 |
| **nginx** | `nginx/Dockerfile` (`nginx:1.27-alpine`) | Compose 注入了 `TZ=${TZ:-Asia/Shanghai}` | **不满足** | **严重缺失**：Alpine Linux (musl libc) 默认不带 `tzdata`，没有 `/usr/share/zoneinfo/Asia/Shanghai` 时 Alpine 会直接忽略 `TZ` 环境变量并回退为 UTC 时间，导致 Nginx 容器系统与访问日志均为 UTC |
| **victoriametrics** | `victoriametrics/victoria-metrics:v1.103.0` | 仅指定了 command 与 volumes | **不满足** | Compose 中无 `environment` 节点，未注入 `TZ` 环境变量，日志输出默认为 UTC |
| **snmp-exporter** | `prom/snmp-exporter:v0.26.0` | 仅指定了 entrypoint、command 与 volumes | **不满足** | Compose 中无 `environment` 节点，未注入 `TZ` 环境变量，默认为 UTC |
| **vmagent** | `victoriametrics/vmagent:v1.103.0` | 仅指定了 command 与 volumes | **不满足** | Compose 中无 `environment` 节点，未注入 `TZ` 环境变量，默认为 UTC |
| **grafana** | `grafana/grafana:12.1.0` | 注入了 GF_SERVER_*、代理变量等 | **不满足** | 未注入 `TZ=${TZ:-Asia/Shanghai}`，未配置 `GF_DATE_FORMATS_DEFAULT_TIMEZONE=Asia/Shanghai`，导致容器进程为 UTC，且仪表盘默认时区未固化为北京时间 |
| **redis** | `redis:7.4.2-alpine` | Compose 注入了 `TZ: ${TZ:-Asia/Shanghai}`，镜像层已含 tzdata | 满足 | 键值格式可规范化为统一的列表格式 `- TZ=${TZ:-Asia/Shanghai}` |

## 3. 拟修改文件与修改内容

### 3.1 [MODIFY] [docker-compose.yml](file:///d:/netops/netsops-main/docker-compose.yml)
- `victoriametrics`：增加 `environment: - TZ=${TZ:-Asia/Shanghai}`
- `snmp-exporter`：增加 `environment: - TZ=${TZ:-Asia/Shanghai}`
- `vmagent`：增加 `environment: - TZ=${TZ:-Asia/Shanghai}`
- `grafana`：在 `environment` 增加：
  - `- TZ=${TZ:-Asia/Shanghai}`
  - `- GF_DATE_FORMATS_DEFAULT_TIMEZONE=${GRAFANA_DEFAULT_TIMEZONE:-Asia/Shanghai}`
- `redis`：将 `TZ: ${TZ:-Asia/Shanghai}` 规范化为列表项 `- TZ=${TZ:-Asia/Shanghai}`

### 3.2 [MODIFY] [nginx/Dockerfile](file:///d:/netops/netsops-main/nginx/Dockerfile)
- 安装 `tzdata` 依赖：`apk add --no-cache openssl tzdata`
- 设置时区环境与文件：
  `ENV TZ=Asia/Shanghai`
  `RUN cp /usr/share/zoneinfo/Asia/Shanghai /etc/localtime && echo "Asia/Shanghai" > /etc/timezone`

### 3.3 [MODIFY] [docker/postgres/Dockerfile](file:///d:/netops/netsops-main/docker/postgres/Dockerfile)
- 安装 `tzdata` 依赖：`apt-get install -y --no-install-recommends postgresql-contrib-18 tzdata`
- 设置时区环境与文件：
  `ENV TZ=Asia/Shanghai`
  `RUN ln -snf /usr/share/zoneinfo/Asia/Shanghai /etc/localtime && echo "Asia/Shanghai" > /etc/timezone`

### 3.4 [MODIFY] [Dockerfile](file:///d:/netops/netsops-main/Dockerfile)
- 补充软链接以确保非 Python 的原生进程也能感知时区：
  `RUN ln -snf /usr/share/zoneinfo/Asia/Shanghai /etc/localtime && echo "Asia/Shanghai" > /etc/timezone`

## 5. 风险与回滚思路
- 时区补齐属于环境参数增强，不影响已有数据卷、数据库数据或端口映射。
- 若需回滚，直接执行 `git checkout docker-compose.yml nginx/Dockerfile docker/postgres/Dockerfile Dockerfile`。
