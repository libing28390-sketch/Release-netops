# 通知 Relay 启动顺序

## 目标

避免 alert-notify-relay 在通知数据库迁移完成之前启动并重复报错；设备尚未导入时仍保持空队列可正常运行。

## 已知证据

- 用户日志报 PostgreSQL `UndefinedColumn: column "alert_id" does not exist`，故障栈在 `recover_expired_alert_delivery_leases`。
- 迁移 m0245 为 alert_delivery_outbox 增加 alert_id。
- FastAPI 启动同步运行 init_db/migrations；数据库迁移完成后才会开放 health/live。
- Compose 中 relay 目前只依赖 PostgreSQL 和 alert Redis 健康，与执行迁移的 netops 主服务没有启动依赖。
- relay 默认周期 0.5 秒，因此启动竞态会造成高频重复错误。

## 修改范围

- 修改 docker-compose.yml：让 alert-notify-relay 等待 netops 通过 service_healthy 后启动。
- 添加本计划和配套走查报告。
- 不改通知任务逻辑、数据库 schema、0.5 秒轮询间隔；不要求导入设备。

## 实施步骤

1. 确认 netops 没有反向依赖 alert-notify-relay，避免 Compose 依赖环。
2. 在 relay 的 depends_on 中添加 netops: condition: service_healthy。
3. 核对 Compose 片段和差异，确认等待只发生在服务启动时。
4. 不启动、重建或部署线上容器。

## 验证计划

- 静态检查 Compose 依赖关系和 YAML 改动。
- 本次不运行测试或 Compose 部署；不访问/修改线上数据库。

## 风险与回滚

启动时 relay 会等 netops 完成同步数据库迁移并健康后再开始派发；运行中 netops 停止不会由此依赖关系自动停止已运行的 relay。若依赖关系不符合预期，可移除新增的 netops depends_on 条目。
