## 1. 任务目标与范围

将现有资产能力提供给 CMDB、ITSM 和受控自动化系统，提供稳定的公开标识、独立机器身份、租户/站点/字段授权、安全单条写入、外部记录映射、可恢复的批量同步与可追踪结果。

一期分成两个有独立验收门槛的里程碑：

| 里程碑 | 必须交付 | 发布边界 |
|---|---|---|
| P0a：单条资产开放 | API Client/凭证管理、租户/站点/字段权限、限流、审计、公开资产与站点标识、字典与只读接口、存量映射管理、创建/PATCH/退役/受控 Upsert、最小管理 UI、独立 OpenAPI 文档 | 只接受已验收的单条操作；Batch 默认关闭，不出现在 P0a 已发布 Schema 中 |
| P0b：可靠批量同步 | Batch/Jobs、dry-run、逐条结果、可靠派发与补投、独立低并发资产 Worker、恢复/重试/保留策略、任务 UI、共存压测 | 完成故障恢复和资源验收后单独开启 |
| P1：增量与外部通知 | 有序 Change Feed、快照/补偿协议、Webhook、签名/重试、OAuth2 Client Credentials | 本次仅保留扩展边界，不计入 P0 完成度 |
| P2：告警及其他业务 | 自定义脚本告警接入、去重/恢复、拓扑/监控/备份元信息等 | 独立立项与专项容量验收 |

P0a 通过不表示 P0 全部完成；P0 完成要求 P0a 与 P0b 均通过。发布说明必须列出实际开放能力、关闭能力和未实施的后续功能。

一期复用现有 FastAPI、PostgreSQL、Nginx、监控链路及安全工具。公开接口前缀为 /api/v1，不新增独立 API 容器，不引入另一套 ORM、连接池、迁移框架或厂商字典。P0b 的资产 Worker 与告警通知 Worker 分开。

### 3.3 Agent 与共享文件归属

主 Agent 负责需求、接口、数据库/权限决策、共享文件、最终集成和统一 plan/walkthrough。明确、独立的工作包按项目规则交给 Luna 6 Max，最多并行两个执行者，执行者不再分派。

- 后端执行者：冻结后的独立 Router/Service/Schema 文件。
- 前端执行者：冻结契约后的页面/组件，避免与主 Agent 同写共享路由/权限文件。
- 验证执行者：指定检查与可复核失败摘要；不重复运行相同代码状态的公共验证。
- backend/main.py、api_security.py、schema.py、迁移编号、celery_app.py、Compose、Nginx 与主文档由主 Agent 协调。
- 每个工作包列出目标、已知证据、允许文件、相关 skill、接口与验收命令；保留用户已有变更。
- 不创建功能分支、不提交/推送/部署；后续如有明确授权，再按项目规则执行。

## 4. 公开契约与安全边界

### 4.1 统一协议

- HTTPS、UTF-8 JSON、snake_case，时间以 RFC 3339 UTC 输出。
- 成功体为 data；列表附 meta.limit/next_cursor/has_more；不要求昂贵 total。
- 应用错误采用 RFC 9457 application/problem+json，固定 code/request_id，敏感细节不外泄。
- 公开 Schema 固定 OpenAPI 3.1.x，经生成、lint、diff 与示例校验确认；不以修改版本字符串代替验证。
- 认证仅接受 X-API-Key；内部 Session 与机器身份各自用于指定路由，不能互相替代。
- X-Request-ID 限制长度和字符；日志不存原始 API Key、Authorization、SNMP community、密码或不受控请求体。
- 所有 POST 写操作要求 Idempotency-Key；PATCH/退役要求强 If-Match。
- 请求摘要包含方法、规范路径、影响语义的 query（包含 dry_run）、规范化 body 与条件参数；相同键变更语义返回 409。
- 202 仅表示已经可靠持久化接收；资产纳管成功与资产入库分别表示。

### 4.2 接口与权限

所有公开路径相对于 /api/v1。S1 固定 operationId、请求/响应模型、错误码和示例。

| 方法/路径 | 权限 | 里程碑与关键语义 |
|---|---|---|
| GET /assets、/assets/{asset_id} | assets:read | P0a；DB 查询内执行租户/站点过滤，详情返回 ETag |
| POST /assets | assets:create | P0a；201、Location、ETag，幂等创建 |
| PATCH /assets/{asset_id} | assets:update | P0a；If-Match、字段权限、原子版本条件更新 |
| POST /assets/{asset_id}:retire | assets:retire | P0a；独立退役，不调用硬删除逻辑；幂等与 If-Match |
| POST /assets:upsert | assets:upsert + 实际分支的 assets:create 或 assets:update | P0a；外部 ID 定位，已映射更新必须带 expected_version |
| GET /asset-types、/device-roles、/vendors、/sites、/tags | assets:read | P0a；复用字典、过滤可见站点；字典不得变相全局创建 |
| POST /assets:batch | assets:batch + 对应写权限 | P0b；202、逐条独立事务、dry_run、配额 |
| GET /jobs/{job_id}、/jobs/{job_id}/items | jobs:read | P0b；只读本 Client 或明确授权 Job |
| 内部 Client/凭证/外部映射管理 | 现有管理员权限体系中的新增显式权限 | P0a；Bearer Session、资源范围、变更审计，不能由第三方 Key 执行 |

固定路由与动作路由优先注册；P0 不提供公开 DELETE、恢复退役资产或凭证写入接口。P1/P2 路由不得提前出现在已发布 Schema 中。

### 4.3 Client、Scope 与字段授权

API Client 绑定现有 tenants.id（TEXT）、固定来源码、功能 scopes、允许站点与可写字段。管理 UI 采用现有内部站点 ID；公开 API 采用站点 public_id，服务端映射后授权。

- 不接收第三方自行声明的 tenant_id/scope_id。
- 空站点白名单表示无站点权限；全站授权需独立明确标志和高权限审计。
- 无/非法站点资产默认不向 Client 暴露，也不允许建立外部映射；管理员先修正归属。
- 有 devices.asset_id 关联时，devices.tenant_id 必须与 sites.tenant_id 推导的资产租户一致。缺失或不一致记录进入管理员修正清单，公开关联读取、绑定与 Upsert 不得绕过该门槛；新建/移动同步维护设备租户。
- 新建需校验站点存在、所属租户与 Client 可创建范围。
- 资产移动需同时校验源/目标站点权限，并禁止公开接口跨租户迁移。
- 查询、更新、映射查找、Job 结果、Worker 逐条处理均再次执行对象范围与字段校验。
- source 必须匹配 Client 绑定来源；同租户同 source_code 的 Client 归属与接管规则由 S1 固定，默认一个 Client 管理一个来源，轮换通过多个 Credential 完成。
- Client 停用/权限变更需在定义的时限内使新请求与 Worker 条目失效；P0a 默认实时检查，不以长缓存延迟撤销。
- 密钥至少 256 bit 安全随机数；只展示一次；存 HMAC 摘要，pepper 独立于数据库；常数时间比较；支持到期、撤销和短期双凭证轮换。
- 新身份依赖纳入 api_security 的显式授权识别；新增路由不能通过宽泛 /api/v1 白名单绕开鉴权。
- API Key 失败、用户 Session 访问机器接口、机器 Key 访问内部 PAM/管理接口都必须有拒绝测试。

## 5. 资产标识、字段、状态与存量接入

### 5.1 稳定标识与字段映射

保留 physical_assets.id、sites.id 与所有既有外键；分别新增不可变 public_id UUID 作为对外 asset_id/site_id。两个表均包含 nullable 引入、并发新增默认生成、分批回填、唯一性验证和非空约束阶段。

| 公开字段 | 内部来源/规则 |
|---|---|
| asset_id | physical_assets.public_id，不使用短内部 ID 冒充 UUID |
| site_id | sites.public_id，经适配层转为 sites.id 后执行 tenant/site 授权 |
| name | 映射现有名称/hostname；S1 明确展示名与 SNMP 观察名的关系 |
| asset_code | 映射 asset_tag 或已确认编号字段，不新增平行身份规则 |
| asset_type/device_role | 映射现有类型与角色字典，不假定两者当前一一对应 |
| vendor/model/serial_number | 区分声明值与观察值；已发现事实默认受保护 |
| platform | P0 不接受任意技术键；外部 vendor 由现有规范化确定平台并同步 devices；如需公开 platform，则 S1 固定只读规范码 |
| management_ip | IPv4/IPv6 格式与规范化；P0 保留现有唯一约束限制，不用 IP 自动合并 |
| lifecycle_status | 公开 active/maintenance/retired 映射到现有状态；S1 列出 staging/production 等全部内部值的双向矩阵 |
| monitoring_enabled | 映射现有管理/采集配置，默认禁止外部修改；单独字段授权后异步执行，不表示实时在线 |
| tags/custom_fields | 去重、数量/长度/深度/类型与可写白名单校验；替换不得删除其他来源拥有的字段 |
| version | physical_assets.row_version；任何公开表示变化递增 |
| created_at/updated_at | 服务端生成与 UTC 转换；客户端不可覆盖 |

公共 DTO 不包含凭证、私钥、SNMP 原始敏感值和实时监控曲线。P0 默认不返回其他来源的 source_refs，避免跨系统 ID 泄漏及调用方差异影响表示版本。

PATCH：未出现字段不改；null 只清空可空字段；tags 提供时整体替换；custom_fields 默认整体替换其明确授权范围，越权删除/修改拒绝；未知/只读字段拒绝 422。相同值不产生新版本或重复后续任务。

### 5.2 存量映射：一期必交付

外部身份业务键采用 (tenant_id, source_code, external_id)，external_id 默认大小写敏感且不可随设备改名改变。

首次接入流程：

1. 管理员为来源创建 Client，明确租户、站点、字段和功能权限。
2. 导出授权资产摘要；导入或录入外部 ID 对账数据，不包含凭证。
3. 基于资产 ID、站点、IP、SN、厂商/型号等生成候选；只生成候选，不自动合并。
4. 管理员确认选定现有 asset_id；校验资产、devices.asset_id、站点/租户和唯一外部身份。
5. 在一个事务中创建映射、记录来源/操作者/原因审计；冲突整体回滚。
6. 联调 Upsert，验证指向原有资产，资产与关联设备数量没有非预期增加。

P0a 必须包含管理员映射列表/创建/撤销或纠错入口。纠错必须显式审计，不能借普通 Upsert 更换既有映射目标。第三方默认没有 assets:link，普通 Key 不能绑定任意旧资产。

未映射 Upsert：完成范围/字段/唯一性检查后创建；疑似冲突返回 409 与安全的可处理原因，转管理员对账。既有映射指向退役资产返回 ASSET_RETIRED，不自动复活。

### 5.3 重叠 IP 与身份约束

P0a/P0b 保留已存在的全局身份约束，向接入方明确：当前不承诺不同站点相同管理 IP 可同时登记。原 v1.1 的同 IP 跨站点成功用例改为受控冲突/人工处理用例。

解除 IP、SN、hostname 等全局约束需要独立 ADR 与迁移：审查设备按 IP 定位、发现、监控目标、IPAM、拓扑邻居/下一跳、自动化连接与前端选择。只移除 m0014 索引不构成支持重叠地址。该跨链路改造不默认纳入 P0。

### 5.4 生命周期与副作用

S1 固定完整状态映射；多个内部状态映射同一公开状态时，禁止普通 PATCH 将其反向改成任意默认内部值。退役走专门命令，保留资产/设备关联、外部映射、备份与历史。

生命周期与 physical_assets.status、devices.status 分开处理。S1 明确后两者现有内部状态/可达性语义及公开 DTO 是否使用；不得把 active/maintenance/retired 直接写回这些状态字段。退役修改经映射确定的生命周期与期望采集配置，可达性仍由现有探测链路计算。

退役必须将停止采集、停止相关定时作业及告警处理策略作为可恢复副作用，并验证退役后不会被发现流程无授权重新纳管。具体内部字段由 S0 调用链确定，不能只给资产写 retired 文本而继续采集。

监控配置写入、IP 变更和退役产生需要协调的副作用时，资产事务保存可靠意图，提交后由已有可恢复机制或独立协调任务执行。状态应区分期望配置与执行失败；不能因异步纳管失败删除已提交资产。

这类单条资产副作用的可靠恢复属于 P0a。S1 固定其持久化意图与执行/扫描入口，S2 引入必要数据，S3/S5 验证提交后崩溃和重启补偿；不能依赖尚未开启的 P0b Batch Worker。可复用现有资产/监控协调能力，但必须证明关停公开 API 或重启应用后未完成意图仍可恢复。

## 6. 共享业务、事务、版本与幂等

### 6.1 渐进抽取

按创建、更新、退役、外部映射四种操作逐步抽取共享服务，先建立回归基线。复用项目现有 PostgreSQL 连接/事务包装，不引入第二套 ORM。

每次抽取保留：平台规范化、资产/设备同步、标签/机柜关系、授权、审计、提交后监控协调。内部响应不随公开 DTO 改造而改变。Router 只处理 HTTP、校验、授权入口、响应与错误。

### 6.2 版本覆盖范围

S0 列出所有改变公开字段的写入口及实际文件；S1 冻结覆盖清单，包括 assets 与 devices 内部路由、发现、导入、hostname、vendor/model/platform 识别、站点移动、生命周期与监控配置变更。已确认 backend/api/devices.py 存在 physical_assets 直接新增/更新/删除，必须纳入版本与 UUID/映射完整性验收。

- 所有公开字段变更统一增加 row_version；不暴露的凭证变更不机械增加版本。
- 首选共享写入方法；无法立即统一的遗留写入口需显式接入版本维护或经 ADR 采用数据库保护，不能静默遗漏。
- 外部 PATCH/退役在同事务中执行授权、版本验证与条件 UPDATE；禁止先读版本后无条件写入。
- 内部写入口也须保护读改写操作，避免反向覆盖外部已提交值。
- 缺少必要条件返回 428；旧版本返回 412；不存在或越权返回安全的 404。
- ETag 使用资产 UUID、版本及固定表示版本生成，不包含实时监控字段；序列化变化纳入契约版本与兼容检查。
- 字段权威优先级在统一服务内执行，不能只保护外部 API 而让发现路径继续覆盖 CMDB 字段。

### 6.3 Upsert 的并发与旧请求

对外 Upsert 增加 expected_version（严格正整数，对应同一个 physical_assets.row_version 与响应 version）：未映射创建不要求；已映射资产更新必须提供。缺失返回 428 EXPECTED_VERSION_REQUIRED；非正整数、字符串或布尔值返回 422 VALIDATION_ERROR；旧版本返回 412 ASSET_VERSION_MISMATCH。Batch 更新条目采用相同规则并记录逐条失败。Client 从已有响应或 GET 获取版本，遇 412 读取最新状态并做业务合并，禁止自动替换版本后重发旧内容。

相同幂等键重试先回放已完成结果，不因资源版本变化重新执行。幂等与串行化只解决重复执行/竞争，不声明可以识别业务内容新旧；源侧应按记录串行发送。基于可信 source_revision 的自动乱序过滤留作后续明确契约，不以服务器收到时间替代业务版本。

事务步骤：

1. 确定服务器 tenant/source、请求身份、字段与站点权限。
2. 原子认领 Client 幂等键；摘要变化拒绝，并发同键不重复执行。
3. 按外部身份获取稳定的事务级串行保护；不得使用进程随机 hash()。
4. 读取映射与目标资产，重新检查权限；映射未存在则受控创建。
5. 已映射更新对资产行执行锁定/版本条件，即使不同外部来源映射同一资产也不能绕开保护。
6. 资产、devices 等关键关联、映射、版本、关键审计、幂等结果与必要副作用意图同事务提交。
7. UNIQUE(tenant_id, source_code, external_id) 为最终防重约束；竞争失败回滚整个事务后有限重试。
8. 返回 created/updated/unchanged、asset_id、version、ETag。

### 6.4 幂等与审计存储

普通请求幂等默认保留 72 小时，可配置；Create 超过期限不承诺历史全局去重，长期同步使用外部身份。保存必要状态码、响应体、资源标识、Location/ETag 等响应头语义，避免重放丢失条件写入信息。

processing 状态需定义租约与恢复；业务提交和幂等完成记录不得出现无法恢复的断窗。业务错误和暂时依赖错误分别定义缓存/重试规则。Item 执行幂等结果至少覆盖整个 Job 可恢复期限，不沿用短期 HTTP 记录清理导致长 Job 失去保护。

访问日志可聚合/异步；关键变更审计与业务事务原子提交。审计支持内部用户/API Client 操作者、request_id、外部身份、版本与改动字段，不存原始秘密。

## 7. 数据库增量迁移与回滚

使用现有 backend/database/migrations/mNNNN_*.py；实际编号在开始编码时查已占用序号后分配。fresh-install schema 与升级迁移保持一致，不修改历史迁移来代替新迁移。

| 阶段 | 数据动作 | 验收 |
|---|---|---|
| Expand（P0a） | physical_assets/sites 增加 nullable public_id 与新写默认生成；资产增加 row_version；新增 Client/Credential、映射、幂等与单条资产副作用可靠意图数据 | 旧应用可启动；新旧写路径兼容；旧 PK/FK 不变；恢复不依赖 P0b |
| Backfill | 按批回填两个公开 UUID；核对站点租户与 devices 归属；孤立资产转管理员修正清单 | UUID 无重复；待修正数据不被公开接口误授权 |
| Enforce | 在回填与并发写入验证后设 NOT NULL/UNIQUE、外部身份唯一约束、合理索引/FK | 0 NULL、完整性检查、迁移可重复部署 |
| Deploy | 先接共享业务与版本维护，再启用测试 Client | 内部资产/发现/导入回归通过 |
| P0b Expand | 持久化 Job/Item/派发意图、租约、重试与结果保留 | 接收、派发、执行各故障窗口可恢复 |

数据模型要求：

- api_clients.tenant_id 使用现有 TEXT tenant FK，不引用新造 scope 表；公开 Client/Job ID 可用 UUID。
- asset_external_mappings 引用 physical_assets.public_id，包含 tenant/source/external_id；服务必须验证资产通过站点推导的租户与映射租户一致。
- Client、站点授权、字段权威、Credential 各自职责明确；一期可采用严格校验 JSONB，复杂查询时改关联表。
- Job、Item 与派发意图保存稳定身份、状态、attempt、lease、next_attempt_at、结果与错误；参数以实际状态机设计为准。
- 复用现有审计能力；若现有 helper 独立提交，先补共事务能力，不能称调用日志已实现原子审计。
- 站点改租户、资产跨租户迁移、内部硬删除与外部映射 FK 影响需加入专项检查；API 关停不能消除这些数据约束。
- 备份、回填批次、锁等待、索引创建与恢复时间纳入迁移报告；在线索引禁止放入不兼容事务。
- 默认回滚为关闭功能/撤销 Client/暂停新任务并向前修复，保留 UUID、映射、结果和审计；不 DROP 新表或恢复旧库全量覆盖。

## 8. P0b Batch、可靠派发与恢复

### 8.1 接收边界

批次 1～200 条、请求体最大 2 MiB、每 Client 最大 2 个活动 Job。配额认领与 Job 创建采用原子机制，防止并发请求绕过限制；还需全局活动 Job/积压上限，S0 容量基线后在 S1 固定。

P0b 的 Batch 仅支持 upsert；退役仍使用单资产独立接口与版本条件，其他批操作不提前开放。

请求结构/大小/顶层权限错误整批拒绝；条目业务错误记录逐条失败，不因嵌套模型验证把所有条目拒绝。含未知或敏感字段的条目标记失败，仅保存安全身份与错误摘要，不保存该条原始 payload；其余条目通过白名单校验后才持久化。

同批重复 external_id 的所有重复条目标记明确错误，不按随机顺序覆盖。每条使用独立事务；dry_run 只保存安全校验任务/结果，不写资产、映射、业务变更审计或监控副作用。预检不承诺后续写入必然成功。

### 8.2 接收与派发原子性

同一事务保存 Job、经过校验的 Items、请求幂等结果和派发意图，提交后返回 202。派发意图可用独立 outbox，或以具备等价认领/租约/补投语义的 Job 行充当持久化派发源；S1 固定一种实现。

Relay 周期性认领可派发记录，向资产专用 Redis queue 发布；发布失败有限退避，发布成功但确认状态前崩溃允许重复发布，由消费端幂等处理。

必须同时恢复：

- Job 入库后、入队前应用崩溃。
- Redis 发布失败与 Redis 重启丢失已发布消息。
- 发布成功但派发状态未更新。
- 已标记派发但未被领取，超过明确时限后补投。
- Worker 认领后崩溃，租约过期重新领取。
- 业务提交后、Item/Job 进度更新前崩溃。

queued/running 的恢复均有扫描入口与时间边界，不能只扫描 stale running。acks_late 或 Redis 持久化不替代数据库恢复机制。

### 8.3 执行与结果

资产队列 openapi_asset_sync；Worker concurrency=1、prefetch=1 为初始值。任务消息尽量仅含 job_id，不在 Broker 复制完整批次 payload。

Job/Item 原子认领并记录 lease/attempt；长任务有受控续租。每条实时复核 Client、字段与资产范围，复用单条 Upsert/版本/外部身份保护。

稳定执行键为 job_id:item_index；业务写入与 Item 完成结果优先同事务提交。若存在必要的分阶段提交，保留可回放的操作结果，不能在恢复时把原 created 错记为 unchanged，或重复生成审计/副作用。

统计满足 processed=created+updated+unchanged+failed；dry-run 使用 valid/invalid，分开统计。可恢复错误有限重试加抖动，权限/字段/版本冲突不无限重试。

HTTP 幂等、执行幂等、Job 结果和租约清理分别设计。默认 Job/Item 结果保留 30 天；审计按既有策略；未终态 Job、未完成派发与可能重投任务不能被普通 TTL 清理。

### 8.4 Worker 资源与 Broker

资产 Worker 不消费现有 alert_notify_critical/alert_notify_normal；资产 Relay 不混用告警 Relay 的业务表。现有 backend/celery_app.py 绑定 ALERT_NOTIFICATION_BROKER_URL，应保留为告警专用 app。

新增 backend/asset_celery_app.py，导出 app 并仅注册资产任务；使用独立 OPENAPI_ASSET_BROKER_URL 配置，缺失时拒绝启动，不能回退到告警 Broker。S0 从现有通用 Redis 选择显式 DB/命名空间并纳入容量预算；该逻辑隔离不等于 Redis 内存/CPU 隔离，不能占用告警专用实例。

Compose 拟新增 openapi-asset-relay 与 openapi-asset-worker（P0b 专属 profile/启用开关）。沿现有镜像 PYTHONPATH=/app/backend，入口分别为 python -m asset_delivery_relay 和 celery -A asset_celery_app:app worker --queues=openapi_asset_sync --concurrency=1 --prefetch-multiplier=1。实际上线前必须验证模块可导入、Broker/队列对应、DB 池和资源限制，不将规划命令当成已运行服务。

初始测试配置：concurrency=1、prefetch=1、DB pool=1、overflow=0；连接超时、任务时间边界、回收与租约需与实测任务耗时一致。

CPU 0.25～0.5、内存 256～512 MiB 只作为测试预算；若导入与运行峰值无法容纳，不按此上限上线。Compose 必须显式映射资源限制，环境变量本身不代表已隔离。

## 9. 管理 UI、文档与可观察性

P0a 管理员能够通过 UI 创建/停用 Client、分配租户/站点/scopes/字段、生成/轮换/撤销 Credential、完成存量外部 ID 对账绑定，并查看脱敏调用与变更摘要。密钥一次性展示，危险授权与映射纠错有确认及审计。

P0b 增加 Job/Item、失败定位/安全导出、dry-run 与恢复信息；概览统计可分阶段补齐，不能以统计面板未完成阻塞已经定义的最小接入操作。

公开 Schema 使用显式标记与路由白名单导出；路径前缀只是辅助条件。P0a 文档不展示未开放 Batch/P1/P2。内部 docs 维持现有访问策略，不能因接入联调而对外解除。

指标复用 VictoriaMetrics/vmagent/Grafana：RPS、429/5xx、p95/p99、inflight、大小、活动 Job、queued/running 年龄、派发失败/重投、Worker RSS/CPU、DB 等待、Redis 内存、既有页面延迟和告警通知延迟。标签不含资产/外部 ID、request_id、原始 URL。

## 10. 容量基线、限制与降级

S0 记录主机 CPU/RAM/可用余量、swap/IO/OOM，主要容器实际 CPU/RSS 与 limit，DB max_connections/活跃/等待与各进程池，Redis 内存/队列，页面与告警延迟。Compose 默认与真实环境覆盖值分别列出，配置存在不表示进程运行。

默认规划值：读 10 RPS/Client、写 3 RPS/Client、列表默认 100/最大 500、批次最大 200、body 2 MiB、活动 Job 最大 2/Client。全局 in-flight、全局积压、等待上限、恢复扫描时间与熔断阈值经 S0 确认，S1 写入配置契约，不能留为无限。

- /api/v1 在 Nginx 与应用两层限制 body；缺失/伪造 Content-Length、流式上传也受限，不先无限读入内存。
- 为公开接口配置边缘 413/503 的可识别错误响应；应用层输出 RFC 9457。
- Redis 限流不可用时写 API 默认 503；读取采用显式有限策略，不无限放行。
- DB 无法持久化时拒绝写请求；不返回虚假 201/202。
- 超配额 429，系统依赖/过载 503，按契约提供 Retry-After。
- 积压或原有告警延迟恶化时，先拒绝新 Batch、降低写并发；已接受 Job 优雅完成或保持可恢复。
- API 关闭、Batch 关闭与 Worker 暂停为不同操作，明确已接收任务的停机/恢复策略。
- 连接预算覆盖 API、现有告警 relay/workers、新资产 relay/worker 与维护余量，不只统计单进程。

发布否决：持续 OOM/swap 风暴、DB 连接耗尽、资产/设备/映射不一致、任务无法恢复、既有告警/页面出现超过批准阈值的退化。阈值由测量结果与业务容忍度固定，不能凭新 API p95 单独判定通过。

## 12. 验证计划

本次计划修订仅验证文档结构、路径、阶段一致性与约束，不执行下列业务检查。后续实施按 netops-quality-gate 选取最近测试；共享鉴权/数据库变更与正式发布候选执行完整后端回归。

### 12.1 必须覆盖的业务用例

| 类别 | 必须检查 |
|---|---|
| 身份与权限 | 缺失/错误/到期/撤销 Key；Session 与 Key 互不替代；全局 guard 认可新身份；跨 tenant/site；无站点资产；字段越权；Job/映射不可枚举 |
| 存量接入 | 旧资产确认绑定后重复同步不增资产/设备；绑定冲突整体回滚；同 source/external_id 并发无孤儿；跨来源不能冒充；同 IP 冲突可处理 |
| 多厂商 | Cisco/Huawei/H3C 的 vendor→platform→driver→查询目录；切换厂商后旧平台不残留；资产与设备同步 |
| 状态与关联 | 全部内部 lifecycle 映射；退役保留历史、停采集、发现不自动复活；设备/标签/机柜/监控协调一致 |
| 版本与权威 | assets/devices 内部路由、发现/导入递增同一版本；外部旧 ETag/expected_version 拒绝；已映射 Upsert 缺失版本 428、非法类型或非正整数 422；Batch 同类错误逐条失败；不同来源同一资产竞争；相同值不增版本；SNMP 不覆盖受保护 CMDB 字段 |
| PATCH | 未传不变、null 精确清空、必填 null 拒绝、数组替换、自定义字段跨权威不误清；未知敏感字段不落库 |
| 幂等 | 同键相同语义回放状态/体/Location/ETag；不同 body/query/dry_run/条件冲突；processing 恢复；超过 HTTP TTL 不破坏 Job 幂等 |
| Batch | 200 条含非法项逐条结果；重复外部 ID；格式错误边界；dry-run 无业务写入；禁用 Client 的进行中条目拒绝 |
| 故障 | P0a：单条退役/IP 变更提交后协调进程崩溃，重启或关闭公开入口后未完成意图仍恢复；P0b：Job 落库前后、入队前后、Redis 消息丢失、Worker 认领/提交/结果落库各断窗；重复派发、租约过期；重放结果统计与审计一致 |
| 限制与文档 | 2 MiB 两层保护、无 Content-Length/流式请求；配额并发；429/503；Schema 只有本里程碑公开路由；标准错误与 SDK 示例一致 |
| 迁移与内部回归 | fresh-install、上一版本升级、重复执行、并发新增 UUID、0 NULL、FK/唯一索引；资产页面、导入、发现、拓扑、IPAM、监控/告警 |

### 12.2 压测与发布验收

- 合成 300/3,000/10,000 台数据，后两档为余量评估，不代表现网规模。
- 单 Client 10 RPS 读取 10 分钟、3 RPS 写入 10 分钟；初始目标 GET p95 ≤250 ms、单条写 p95 ≤500 ms，不含公网 RTT 或异步纳管。
- 300 台/5 Client 混合流量，GET p95 初始目标 ≤300 ms；明确各 Client/全局 RPS、读写比例、warm-up 与采样，拒绝请求和成功延迟分别统计。
- 连续 5×200 Batch，遵守每 Client 最大活动 Job；可使用多个 Client 或等待终态再提交，不能将限流拒绝算作批任务已完成。
- 与页面、SNMP、告警通知共存；分别测改造前/后资源与延迟，固定可接受退化阈值。
- 数据库/Redis/Worker 故障与限流/停止/恢复演练，记录最终数据一致性、恢复时长与任务积压。
- 0.5 CPU/512 MiB 与延迟目标为起始预算，最终以实际环境和共存结果修订。

## 13. 风险与回滚

| 风险 | 控制 | 回滚/恢复 |
|---|---|---|
| 共享资产服务抽取改变内部副作用 | 按操作渐进下沉、逐项回归、保留接口响应 | 关闭公开写入；兼容迁移保留；按操作恢复旧调用路径 |
| 存量身份错误或误绑定 | 候选仅提示、管理员确认、唯一约束、审计 | 撤销错误来源权限；按映射审计定向纠错，不全量覆盖 |
| 无站点/租户不一致导致越权 | 服务器推导 scope、归属修正清单、旧/新站点双检查 | 暂停受影响 Client；恢复归属并复测 |
| 版本漏维护导致覆盖 | 全写入口清单、共享写入/CAS、内部与外部并发测试 | 禁用写 API，保留版本与审计，按受影响资产定向恢复 |
| 退役继续采集或发现复活 | 明确状态映射、可靠停止意图、发现保护 | 停止相关协调任务并定向修正；不删除资产历史 |
| DB→Broker 断窗/Worker 崩溃 | 同事务派发源、queued/running 补投、租约、稳定执行幂等 | 暂停新任务；依持久化记录恢复，禁止清空共享 Redis |
| API/Batch 抢占告警资源 | 小池/低并发/独立队列、全局背压、共存阈值 | 关闭 Batch、降低写入配额，已接受任务优雅暂停/恢复 |
| 文档或日志暴露秘密 | DTO/路由白名单、日志脱敏、未知字段拒绝 | 关闭受影响路由、撤销凭证、定向清理受污染记录 |
| 外部 FK 影响内部删除/租户迁移 | 显式数据保留策略、内部操作回归 | 功能关停后向前修复约束/业务处理，保留外部身份历史 |
