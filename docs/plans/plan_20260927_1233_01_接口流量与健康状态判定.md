# 接口流量与健康状态判定

## 任务目标

修正 04 接口流量与健康仪表盘的接口状态语义：流量指标只统计管理启用且运行 UP 的接口；状态表默认隐藏管理停用接口，并区分管理状态与运行状态；提供选项查看管理员停用接口。

## 现状与问题

04 仪表盘当前流量查询没有要求接口处于运行 UP 状态；“接口运行状态”表只读取 ifOperStatus，无法区分管理员关闭端口和启用后链路掉线的端口。

## 影响范围

- Grafana 04 接口仪表盘生成器及生成 JSON；通过全局 dashboard version 递增确保 provisioning 能读取更新。
- 依赖已有 IF-MIB ifAdminStatus / ifOperStatus 时序，不改变采集契约、告警或实时 Grafana。

## 拟修改文件

- `monitoring/grafana/generate_dashboards.py`
- `monitoring/grafana/dashboards/*.json`（生成器会重写 9 份仪表盘；预期只有目标内容和统一版本号变化）
- 本计划及对应 walkthrough。

## 实施步骤

1. 为流量、利用率、错误/丢弃统计增加 admin-UP 且 oper-UP 限定。
2. 为状态表添加默认隐藏管理员停用接口的筛选项，并增加管理状态和运行状态两列。
3. 保持运行状态颜色填充：UP 绿、DOWN 红；管理停用显示中性状态。
4. 将统一仪表盘版本递增至 30，运行生成器并检查所有输出差异与 JSON 结构。

## 验证计划

- 确认目标 JSON 中状态表含管理/运行两列、默认筛选隐藏 ifAdminStatus=2，并可切换显示。
- 解析全部生成的仪表盘 JSON，并检查查询包含对应 admin/oper 条件。
- 检查 `git diff --check` 和完整差异；不运行测试套件或写入 live Grafana。

## 风险与回滚思路

- 如状态表或流量查询在目标 Grafana 的 PromQL 渲染与预期不符，可将目标面板查询恢复为原始 `ifOperStatus`/未过滤流量查询，再生成 dashboard JSON。
- 生成器重写 9 个 dashboard JSON，执行前检查工作树，并在生成后确认目标外的仪表盘没有变化。
