# Huawei VRP5 命令契约收口实施计划

## 任务目标

根据 2026-08-04 审查后清单 P0-1，统一 Huawei VRP5 `get_link_aggregation` 的标准查询命令，消除平台注册 Resolver、旧兼容目录和厂商回归之间的 `dis eth-trunk` / `display eth-trunk` 分歧。

## 现状/问题

- `platform_registry_service.py` 的正式 SYSTEM Action Mapping 使用 `display eth-trunk`。
- `m0094_repair_huawei_eth_trunk_command` 已将已发布 SYSTEM Release 修复为 `display eth-trunk` 并重算 checksum。
- `operational_data_service.py` 的旧 Huawei VRP5 兼容目录仍返回 `dis eth-trunk`。
- `test_huawei_vrp5_cli_output.py` 仍断言 `_resolve_commands()` 返回 `dis eth-trunk`。
- 当前厂商回归为 284 passed、1 failed；失败即上述契约冲突。

## 影响范围

- 后端旧目录兼容解析与标准动作命令选择。
- Huawei VRP5 厂商回归测试及平台注册专项回归。
- 不新增数据库表、不改变 API 形状、不改变前端页面或中英文文案。

## 拟修改文件

- `backend/services/operational_data_service.py`
- `backend/tests/vendor_audit/test_huawei_vrp5_cli_output.py`
- 如测试暴露迁移契约问题，再评估是否需要补充现有 m0094 测试；不新建重复迁移。

## 实施步骤

1. 将旧兼容目录中 Huawei VRP5 `eth_trunk` 的标准发送命令与平台注册契约统一为 `display eth-trunk`。
2. 更新命令目录注释，明确旧缩写仍可作为历史回显/解析输入，不再作为新运行任务的标准发送命令。
3. 将厂商回归断言改为正式标准命令，并保留已有 `dis eth-trunk` 回显解析用例。
4. 运行 Huawei 单文件回归、平台平台注册专项和全量 vendor audit。
5. 运行 `npm run lint` 与 `git diff --check`；若本步无前端/API 契约变更，不重建生产产物。
6. 将结果写入对应 `docs/walkthrough/`，并更新审查后任务清单 P0-1 状态。
