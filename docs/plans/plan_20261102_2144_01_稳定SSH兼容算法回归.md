# 稳定 SSH 兼容算法回归

## 目标

修正 main 发布 Actions 中 SSH 兼容算法测试对 GitHub runner 本机 OpenSSH DSA 能力的固定假设，保持旧设备算法策略，并让测试覆盖支持与不支持 DSA 的两种环境。

## 现状与问题

- 提交 `18e1592aaa798509e89d365237dd997cc6809ee0` 的 Release Actions 后端 pytest：3759 passed、2 skipped、1 failed。
- 唯一失败是 `test_legacy_algorithm_lists_contain_full_network_device_suites` 断言实际 OpenSSH 命令必须包含 `ssh-dss`。
- 共享 legacy 算法策略仍声明 `ssh-dss`；system OpenSSH 参数构建器会按本机 `ssh -Q key` 能力过滤，runner 未报告 DSA 支持时应省略它。

## 影响范围

- 只修改 `backend/tests/pam/test_ssh_compat_algorithms.py`，用 mock 主机能力测试系统 SSH 命令构建。
- 不改生产协商逻辑、profile、设备配置、数据库或其他业务模块。
- 新增同批计划、走查和修复记录。

## 实施步骤

1. 从失败日志确认唯一回归测试和 runner 的 OpenSSH 能力差异。
2. 保留静态 legacy 列表断言，移除依赖当前 runner 的命令断言。
3. mock OpenSSH 能力，验证支持 DSA 时包含 `ssh-dss`、不支持时过滤该算法。
4. 运行 SSH 算法专项 pytest 与 `git diff --check`。
5. 新提交推送 main，跟踪其 Release Actions 完成并确认成功；若有其他失败继续排查。
