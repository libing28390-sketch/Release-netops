# 快捷操作分页条数选择

## 目标与现状

快捷操作页使用通用 `Pagination`，但仅传入固定 `itemsPerPage`，未传 `onItemsPerPageChange`。通用分页器因此不渲染“每页条数”选择器。用户希望该选择入口恢复，同时明确默认仍为每页10条。

## 影响范围

- 将快捷操作设备页大小从常量值改为可选状态，默认仍使用 `DEVICE_PAGE_SIZE=10`。
- 把页大小贯通到设备列表 API 请求、页数计算、表格填充判断和分页器选择器。
- 选择新条数时回到第1页并重新请求数据；可选值沿用分页器的10/20/50/100。
- 不修改通用 `Pagination` 组件，也不改变其他页面或快捷操作的布局。

## 拟修改文件

- `src/pages/AutomationExecute/index.tsx`
- `src/pages/AutomationExecute/components/DeviceSelectionStep.tsx`
- `src/pages/AutomationExecute/components/DeviceSelectionStep.test.tsx`（更新 props 夹具）

## 实施步骤

1. 在父组件以10初始化设备分页条数状态，并用它生成 API 请求参数和总页数。
2. 将页大小和更新回调传给设备选择组件；分页器显示选择器，修改后重置到第1页。
3. 浏览器选择20条确认列表数量和总页数更新，再恢复为10条，确认默认布局与留白修正仍在。

## 验证计划

- 浏览器在10条和20条模式下验证选择器、当前行数、总页数及切换后页码。
- `npm run lint`
- 在 `%TEMP%` 独立目录运行 Vite production build。
- `git diff --check`

## 风险与回滚

- 页大小选项上限100，与设备列表 API 的分页契约保持一致。
- 回滚时恢复常量请求、页数计算和不带 `onItemsPerPageChange` 的 Pagination 调用即可。
