# 任务目标
一起处理用户反馈的终端来源、登记入口、候选网段批量选择与 Global 确认问题，并收敛前轮发现的重复展示和 VRF 维护缺陷。

## 现状/问题
候选缺少空间时不能勾选，造成必须逐行确认的操作倒置；终端页使用观察来源/ARP观察等冗长文案，缺少清楚的登记操作；IP列表多来源平铺且归属依据不充分；VRF改名/空VRF删除维护不闭合。

## 分工与文件边界
- 前端子Agent：仅 PrefixManagementTab.tsx 与对应 test，允许新增候选交互本地helper/test；实现先选择、批量应用空间/确认无VRF，保留后台验证。
- 后端子Agent：仅 cmdb_service.py、专用VRF测试；修复同事务改名和未引用空VRF删除，保护所有现有引用。
- 主Agent：终端来源文案、IP登记入口/关联、IP多来源展示、统一文档与验证；不与子Agent写同一文件。
- 主Agent 同步更新 backend/tests/ipam/test_ipam_address_spaces.py 的旧“空VRF一律禁删”断言，并统一验证现有 CMDB CRUD；新VRF专用测试由后端子Agent维护。

## 实施步骤
1. 追踪终端 API、登记 API/表单、候选选择与生成契约。
2. 候选选择与空间确认解耦；批量确认Global/VRF后生成时服务端仍校验。
3. 改来源文案并提供实际登记路径；数据不足时指出缺失条件。
4. 收敛同IP多来源展示，保留来源设备/context，不跨未知空间静默合并。
5. 修复VRF维护的一致性与引用保护，执行定向回归。

## 验证计划
定向Vitest、隔离PostgreSQL的VRF测试、TypeScript、独立目录Vite构建；后端修改运行PostgreSQL-only scanner。公共检查仅统一运行一次。浏览器有已授权会话时进行验收，不发起真实设备采集。

## 风险/回滚
Global必须由用户确认或明确采集证据确定，未知不是Global；不同独立默认路由域可用不同Global空间。保留多来源证据，不删除业务数据。保留既有用户改动，不提交/推送/部署，不连设备。回滚仅本任务差异。
