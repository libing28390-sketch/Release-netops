# Docker 默认管理员密码恢复计划

## 目标

将空数据库首次初始化及数据库恢复出厂后的默认管理员凭据恢复为 `admin / admin`，并让后端逻辑、Docker 配置示例、部署说明和回归测试保持一致。

## 现状与问题

近期安全修改取消了内置默认密码，要求配置 `INITIAL_ADMIN_PASSWORD`。Docker 安装流程不会设置该值，导致空数据库初始化失败；部署说明也存在默认密码契约不一致。

## 影响范围

- 后端用户表初始化及数据库重置的初始账号校验。
- 初始管理员相关回归测试。
- `.env.example` 与 Docker/统一部署文档。

## 拟修改文件

- `backend/database/schema.py`
- `backend/database/reset.py`
- `backend/tests/security/test_audit_regressions.py`
- `backend/tests/conftest.py`
- `desktop/desktop_tray.py`
- `.env.example`
- `README.md`
- `docs/deploy/docker.md`
- `DEPLOY.md`
- 对应的 `docs/walkthrough/` 执行记录。

## 实施步骤

1. 移除初始强密码环境变量校验，恢复缺失管理员创建为 bcrypt `admin` 密码。
2. 仅当现有管理员密码为空或无效时修复为默认密码；保留有效 bcrypt 密码，避免每次启动覆盖用户修改。
3. 让数据库重置流程在不配置初始密码变量时仍能按默认凭据完成初始化和验证。
4. 更新测试，覆盖新库默认登录密码、有效已有密码保留、管理员缺失补建及重置流程。
5. 更新 Docker/部署文档与数据库重置界面，明确初始凭据 `admin / admin`，提醒首次登录后立即改密，并删除不再生效的环境变量说明。

## 验证计划

- 在临时 PostgreSQL 测试数据库运行 `pytest backend/tests/security/test_audit_regressions.py -k "bootstrap or database_reset"`。
- 检查相关 Python 文件编译，包括桌面重置提示模块。
- 执行仓库 PostgreSQL-only 策略扫描；若测试运行环境缺少依赖或 PostgreSQL fixture 不可用，记录具体限制。
- 检查改动 diff，确认没有改动无关的用户工作区内容或真实部署配置。

## 风险与回滚

`admin/admin` 是公开弱口令，部署后可被猜测；文档会明确要求首次登录立即修改。已有有效 bcrypt 管理员密码不会自动覆盖。回滚时可恢复后端与文档代码；本次不做数据库迁移或直接修改已部署数据库，因此代码回滚无需数据回滚。
