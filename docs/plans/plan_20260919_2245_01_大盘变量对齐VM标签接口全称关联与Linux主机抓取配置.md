# 实施计划 - 大盘变量对齐VM标签、Top接口全称关联注入与Linux主机抓取配置

## 任务目标
1. **解决站点与设备下拉框只有 All 的问题**：将全部网络大盘（01-06）与服务器大盘（07-08）中的模板变量查询从不存在的 `site_name` 和 `hostname`，对齐为 VictoriaMetrics 真实存储的 `site_id` 和 `sysName` / `instance`，使得下拉框能正常展开并显示全网 14 台设备全称及站点。
2. **解决 01 概览监控站点数 No data 的问题**：PromQL 从 `count(count by (site_name) (ifOperStatus{site_name!=""}))` 改为 `count(count by (site_id) (ifOperStatus{site_id!=""}))`，使大盘正常显示当前 2 个监控站点。
3. **解决接口展示为 3% 且无接口全称的问题**：
   - 将 Top 20 带宽利用率表格 PromQL 加上 `* on(instance, ifIndex) group_left(ifName) (ifName * 0 + 1) * on(instance) group_left(sysName) (last_over_time(sysName{sysName=~"$device"}[1d]) * 0 + 1)`，成功将 `ifName`（如 `Et0/2`、`GigabitEthernet1/0/9`）与 `sysName` 注入结果集；
   - 在 `clean_organize_transformation` 中显式 exclude 掉 `ifIndex`；
   - 修复表格 fieldConfig，全局 unit 设为 `none`，仅在 overrides 中为利用率数值列设置 `unit: "percent"`，彻底解决数字索引 3 被格式化为 `3%` 的 Bug。
4. **解决 Linux 服务器监控接入问题**：
   - 修复 `backend/services/monitoring_compiler.py` 中的 `render_vmagent_config`，在 vmagent 抓取配置中加入 `linux_servers` / `node_exporter`（9100 端口）和 `windows_servers`（9182 端口）的 scrape job；
   - 修复 07 Linux 服务器大盘中的变量定义，改为按 `instance` 检索主机，并兼容 node_exporter 真实指标标签。
5. **远程 Grafana 实机推送与验证**：
   - 编译生成最新的全量 Dashboards JSON；
   - 通过远程 Grafana API（`https://192.168.204.128/grafana/api/dashboards/db`）直接推送到运行中的 Grafana 实例；
   - 调用 Grafana API 验证大盘渲染与变量返回值。
