# 服务器删除遥测外键修复计划

## 任务目标

修复服务器资产删除失败的问题，确保关联设备的服务器遥测明细和汇总数据在删除设备前被安全清理，并让前端显示后端删除失败原因。

## 现状/问题

`DELETE /api/assets/{asset_id}` 会调用资产删除链路删除关联 `devices` 记录。现有清理逻辑遗漏 `device_telemetry_samples` 与 `device_telemetry_hourly`，而现有 PostgreSQL 外键为默认 `NO ACTION`，因此仍有遥测记录时删除被外键拒绝。服务器列表前端仅处理成功响应，失败响应被静默忽略。

## 影响范围

- 后端资产删除事务及关联设备清理。
- PostgreSQL 现有安装的外键行为和迁移兼容性。
- 服务器资产列表删除失败提示。
- 资产删除、遥测数据完整性和相关回归测试。

## 拟修改文件

- `backend/api/assets.py`：删除关联设备前清理两张服务器遥测表。
- `backend/database/schema.py`：使新建数据库的两张遥测表外键与删除语义一致。
- `backend/database/migrations/m0218_*.py`：为已有 PostgreSQL 安装幂等调整外键为 `ON DELETE CASCADE`，必要时先核验/清理约束。
- `backend/tests/...`：增加带遥测数据的资产删除成功路径和失败/回滚覆盖。
- `src/pages/AssetManagement/index.tsx`：使用统一 API 请求处理删除失败并显示安全的错误信息。
- `src/pages/AssetManagement/components/DeleteConfirmModal.tsx`：展示删除失败详情。
- `src/pages/AssetManagement/components/DeleteConfirmModal.test.tsx`：覆盖失败提示渲染。
- `docs/walkthrough/`：记录实现与验证结果。

## 实施步骤

1. 检查迁移执行器、数据库连接封装和现有资产删除测试。
2. 在删除事务中显式清理 `device_telemetry_samples`、`device_telemetry_hourly`，并同步新库 schema。
3. 编写幂等 PostgreSQL 迁移，兼容已有约束和真实数据，不触碰生产数据库。
4. 修复资产管理页单条及批量删除的错误反馈。
5. 运行聚焦后端测试、迁移/新 schema 验证、前端类型检查和必要的构建。

## 验证计划

- 资产删除相关 pytest：含遥测记录、事务回滚和权限/不存在资产路径。
- PostgreSQL 迁移及 schema 约束检查，确认 `delete_rule` 为 `CASCADE` 或清理逻辑可独立完成。
- `npm run lint`；前端输出或部署静态资源受影响时运行隔离目录构建。
- PostgreSQL-only policy scanner。

## 风险与回滚思路

- 遥测样本属于设备历史采集数据，随设备删除符合现有设备拥有数据语义；删除操作仍由同一事务保护。
- 迁移只调整外键删除规则，不删除非孤儿业务数据；失败时事务回滚。
- 如需回滚代码，可恢复删除清理与错误展示改动；数据库约束回滚需在维护窗口内将 `CASCADE` 改回 `NO ACTION`，并先确认无悬挂引用。
