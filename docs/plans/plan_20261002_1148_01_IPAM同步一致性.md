# IPAM 同步一致性

## 目标与现状
修复隔离 PostgreSQL 已复现的四类问题：同 IP 跨 VRF 记录在列表和差异核对中被覆盖；周期任务忽略 prefix_projection 策略；部分采集与未覆盖设备导致错误前缀老化；终端将交换机名称作为站点。

## 范围与分工
- 主 Agent：`backend/services/ipam_service.py`、`backend/services/ipam_inventory_scope.py`、`backend/tests/ipam/test_ipam_inventory_scope.py` 与现有容量/核对测试的局部 PostgreSQL fixture；统一文档、集成审查及公共验证。
- 执行者一：`backend/services/prefix_discovery_service.py` 与专用周期发现回归测试；策略和采集覆盖范围、老化资格。
- 执行者二：`backend/services/ip_locator_service.py` 与专用终端站点写入回归；canonical CMDB site_id 写入。
- 保留工作区已有告警与前端改动，不调整同步周期，不运行真实设备采集。
- 本次修复 IPAM 权威记录的查询与核对身份；现有按 IP 唯一的发现缓存模型另作风险记录，不在此次局部修复中扩大数据库契约。

## 实施步骤
1. 地址列表按记录保留身份，使用租户、VRF、IP 匹配观察；前缀匹配限制作用域，未知/歧义作用域不错误合并。
2. 差异核对保留全部 IPAM 行，端点按作用域匹配；保持现有响应字段契约。
3. 周期发现先检查 prefix_projection 策略；仅完整成功的设备形成老化覆盖集合，多设备拥有的前缀必须全部覆盖，未知拥有者不老化。
4. 终端新观察写入 CMDB site_id；查询旧记录时验证站点目录，站点名称来自 sites.name，无站点时保持空值。
5. 加入四类原始触发场景及失败/空数据/歧义边界的回归。

## 验证
使用 `.venv/Scripts/python.exe` 和共享隔离 PostgreSQL fixture；先创建测试专用源数据库，再在 subprocess 中运行 pytest，finally 强制清理，禁止改动应用库。聚合运行新增测试、IPAM 分配策略、前缀发现、采集计划及接口契约测试。运行 PostgreSQL-only scanner、git diff --check；仅在 API 契约变化时运行 TypeScript 检查。公共验证由主 Agent 统一运行一次。

验证执行器保存在忽略目录 `artifacts/run_ipam_sync_fix_tests_20261002.py`；覆盖 IP locator cache、NSOT 站点范围执行和旧容量核对契约，首轮共 85 项。首次 83 项通过、2 项新增用例因误读 create_address 返回字段失败；修正测试后这两项通过。集成审查追加孤立端点、遗留父前缀缺失、非法站点归属三项边界保护后，最终统一回归 **88 项全部通过**。

## 风险与回滚
无数据库迁移和自动回填，不修改生产数据。未知观察作用域采用保守匹配，可能显示独立发现项；不会污染其他 VRF 的人工记录。历史误失效记录不自动恢复，需重新发现后确认。回滚本任务服务和测试差异即可；不覆盖既有用户改动。
