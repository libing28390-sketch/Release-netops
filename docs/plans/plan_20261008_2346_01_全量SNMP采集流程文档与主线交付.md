# 全量 SNMP 采集流程文档与主线交付计划

## 目标

梳理当前 SNMP 采集的实际实现，编写从设备导入、硬件发现与轮询、数据持久化到 API/Grafana 展示的完整说明；审查并验证当前工作区中代码与资源变更，将应交付的工作区代码提交并推送到 `main`；检查推送触发的 GitHub Actions，对失败原因进行定位和修复，确认相关 Actions 成功后执行用户要求的计算机关机。

## 现状与问题

- 当前分支为 `main`，初始状态与 `origin/main` 同步。
- 工作区存在多个后端、前端、监控配置、测试、数据库迁移及 LibreNMS MIB/YAML 变更，另有内部协作文件和临时构建验证目录。
- 需要以当前调用链和代码为依据描述流程，不能把 MIB 索引解释成设备 SNMP 采集，也不能把 Grafana 查询与硬件发现混为一谈。
- `source-manifest.json` 同时记录资产厂商、OS profile 厂商、逐 OS profile 和 MIB 上游源路径；上游 35 个 MIB 目录归并到 23 个厂商分组目录及 `standard`，不能将 35 当成 Nexora 厂商数。
- 代码审阅还发现：硬件采集走 LibreNMS YAML，而通用接口采集是独立的 snmp_exporter/Monitoring V1 链路；旧手工 OID module 已退役、当前没有有来源证明的替代 module，需在流程文档中明确记录该接口指标缺口。
- 推送后必须以 GitHub Actions 的实际运行状态作为交付门禁；关机放在所有要求完成之后。

## 影响范围

- 新增公开说明：`docs/architecture/SNMP采集全流程与代码索引.md`
- 新增提交记录：`docs/fixes/fix_20261009_0034_01_工作区全量SNMP采集流程与主线交付.md`
- 可能包含当前工作区中已存在的应用代码、测试、迁移、Grafana/Prometheus/SNMP exporter 配置和 LibreNMS YAML/MIB 资源。
- 本计划与配套 walkthrough 存放在 `docs/plans/`、`docs/walkthrough/`。

## 实施步骤

1. 读取项目规则、相关 Skills、当前分支/提交/远端和完整工作区状态；按项目约定排除内部协作材料与临时验证产物，不覆盖用户已有改动。
2. 只读梳理 SNMP 设备导入、识别、身份绑定、LibreNMS 规则解析、硬件发现/轮询、时序/关系数据存储、监控导出、Grafana 查询和页面展示链路。
3. 编写以当前实现为准的流程文档，列出入口、关键文件、数据实体/指标标签、周期与异常路径；为关键步骤标注依据文件。
4. 完成变更审查和按影响范围选择的质量门禁；同步 LibreNMS manifest 的目录数量/范围说明和无线 dashboard 样式 ID；在架构文档中区分 LibreNMS 硬件采集与当前停用的接口 exporter 路径；修正资产导入反馈残留的自定义指标 Profile 文案/计数；让退役迁移测试通过隔离 PostgreSQL 验证；在 `.gitattributes` 禁用上游 YAML/MIB 的换行转换，验证暂存 Git 对象仍逐字节匹配来源哈希；修复由当前工作区变更引起的失败，不以未验证状态提交。
5. 按仓库规则创建新的 `docs/fixes/fix_*.md`，检查暂存清单与忽略文件，提交到 `main`。
6. 推送 `origin/main`，读取新提交触发的 Actions 运行，逐项确认状态；失败时判断根因、修复、重新提交推送并复查。
7. Actions 全部成功后更新 walkthrough，最后执行已授权的计算机关机。

## 验证计划

- SNMP 流程文档与实际路由、服务、数据库表、采集调度、监控导出和前端/Grafana 数据源核对。
- 运行完整后端 pytest、PostgreSQL-only scanner、前端 lint 与全量 Vitest、隔离目录 Vite production build、Grafana dashboard 生成及 manifest 文件来源校验。
- 提交前检查 `git status`、`git diff --cached --stat`、敏感信息扫描及大文件限制；确认暂存范围不包含内部协作材料和临时验证目录。
- 推送后核对 GitHub Actions 对应提交 SHA 的所有必需运行，只有绿色/成功状态才视为通过。

## 风险与回滚

- 这是跨模块全量工作区交付，未提交改动可能包含相互依赖；保留全部明确属于产品代码/资源的现有更改，失败时用新修复提交解决，不重置或清理工作区。
- MIB 资源可能触发 GitHub 单文件或仓库体积限制；推送前核对，若被拒绝则根据真实错误调整资源打包方案，不静默删减上游文件。
- 迁移 `m0279_retire_custom_snmp_metric_profiles` 会清空设备自定义指标 Profile 绑定并删除配置行，且 downgrade 不可恢复；这是移除自定义采集规则的预期数据迁移，必须在交付文档与迁移测试中明确。
- 推送后可通过对交付提交执行 `git revert` 回滚；禁止 force push 改写远端历史。
- `.github/workflows/release.yml` 的 `main` 推送会在质量门禁后自动把清理过的发布树 force-push 到 `libing28390-sketch/Release-netops` 的 `main`；这是当前发布工作流的外部副作用，推送前向用户说明并在 Actions 中核对结果。
- 仅在目标提交的必需 Actions 成功后关机；若推送、Actions 或权限被外部条件阻塞，则保持机器运行并说明具体阻塞，不宣称完成。
