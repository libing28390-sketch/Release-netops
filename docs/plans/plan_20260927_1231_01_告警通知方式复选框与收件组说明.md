# 告警通知方式复选框与收件组说明

## 任务目标

将告警规则的通知方式改为清晰的复选框，并准确说明邮件通道按 SMTP 配置的用户组/用户选择收件人。

## 现状与问题

- 告警规则表单使用胶囊按钮切换通知方式，用户不容易看出可以多选。
- 邮件说明写成“发送给已启用邮件告警的用户”，未反映 SMTP 通道可按用户组或单个用户配置收件目标。
- 用户组由 `users.group_name` 表示，邮件投递时按当前租户内的活动用户动态展开；组名目前不是独立的可管理实体。

## 影响范围

- 前端告警规则编辑页的通知方式交互及中英文说明。
- 不修改通知 API、用户/组数据模型或投递服务。

## 拟修改文件

- `src/pages/AlertRulesTab.tsx`
- `src/pages/alertManagementShared.ts`
- `src/pages/alertManagementShared.test.ts`
- `docs/plans/plan_20260927_1231_01_告警通知方式复选框与收件组说明.md`
- `docs/walkthrough/walkthrough_20260927_1231_01_告警通知方式复选框与收件组说明.md`

## 实施步骤

1. 将现有通知方式按钮换成带原生 checkbox 的可访问选择项，保留 `workspace` 与指定通知方式互斥的后端约束。
2. 修改邮件收件说明，明确收件组/用户来自已启用 SMTP 通道配置。
3. 检查旧数据兼容、通知渠道状态更新逻辑和工作区现有改动。

## 验证计划

- 运行 `npm run lint` 检查 TypeScript。
- 运行 `npm run build` 检查页面构建与集成。
- 检查最终 diff，确认只改变表单展示与说明，没有改变通知渠道 API 契约。

## 风险与回滚思路

- 风险：复选框交互可能与“跟随个人偏好”互斥规则不一致。
- 回滚：恢复 `src/pages/AlertRulesTab.tsx` 的通知渠道选择区；不涉及数据库或运行时配置迁移。
