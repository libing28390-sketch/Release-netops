# Grafana PostgreSQL 性能看板实施计划

## 目标

在现有 Grafana 监控体系中增加 PostgreSQL 性能看板，使用 `pg_stat_statements` 展示 Query ID 的调用速率、耗时、Rows 和采集状态，并展示数据库级共享缓存命中率。只增加 Grafana 看板及其必需的 exporter/vmagent 数据链路，不建设 Nexora 独立页面、API 或告警中心。

## 生产现状

- 生产环境是 PostgreSQL 18.6，镜像带有 `pg_stat_statements` 1.12 扩展文件。
- `shared_preload_libraries` 为空，目标数据库尚未创建扩展，当前没有历史 SQL 聚合统计。
- Docker Compose 暂无 PostgreSQL exporter。
- Nexora 已有只读数据库观测服务，但扩展不可用时回退到 `pg_stat_activity` 的结果会被标记为 PASS；这不能代表历史 SQL 统计正常。
- 启用 preload 需要重启 PostgreSQL；现有数据卷还需要执行一次 `CREATE EXTENSION`。线上重启需单独安排维护窗口，本计划不包含未经确认的线上重启或数据库写操作。

## 方案与阶段

### P0：准备 PostgreSQL 统计来源

1. Compose 为 PostgreSQL 设置 `shared_preload_libraries`，保留可追加其他模块的配置；使用 `compute_query_id=auto`、`track=top`、关闭规划耗时采样，并将统计上限保持在 5000。
2. 新数据卷通过初始化脚本自动创建扩展和受限 `pg_monitor` 账号；部署脚本对现有数据卷幂等创建扩展并同步该账号。启用 preload 会重启 PostgreSQL。
3. 不增加独立 SQL 查询 API；Grafana 通过 exporter 读取聚合计数器。SQL 文本采集保持关闭，避免敏感 SQL 进入标签和时序数据库。

### P1：时序采集与历史趋势

1. 固定为 `postgres_exporter` v0.20.1，启用 `stat_statements` collector，每次只采集最多 100 条语句；不使用 PostgreSQL 超级用户。
2. 在监控编译器中为本地 collector 生成 exporter target；不直接编辑运行时生成的 `scrape.yml`。
3. 用 `rate()` 展示 Query ID 的调用、耗时和 Rows 趋势。statement collector 不暴露每条 SQL 的 shared buffer 命中/读取数，因此 Cache Hit 仅展示 `pg_stat_database` 的数据库级比例，不混称为单条 SQL 命中率。
4. 通过 `monitoring/grafana/generate_dashboards.py` 生成独立 PostgreSQL 性能 dashboard JSON，遵循现有 Grafana V2 视觉规范；展示有限 Query ID，不展示 SQL 文本。

## 本次变更边界

本次实现最小 PostgreSQL exporter 采集接入和 Grafana dashboard 生成。PromQL 必须基于固定版本官方源码核实；若本地无法运行 exporter，必须记录 runtime `/metrics` 尚未核验，不能宣称已线上验证。生产 PostgreSQL 重启、创建扩展和生产部署均不在本次本地代码验证范围内。

## 验收

- exporter 采集目标编译测试覆盖启用/缺失状态和目标契约。
- Grafana dashboard JSON 可解析，并由仓库生成器产出；PromQL 指标名、类型和 labels 与固定 exporter 源码一致。
- Compose YAML 与 PostgreSQL Dockerfile 可解析；初始化 SQL 幂等。
- PostgreSQL-only policy scanner 通过，`git diff --check` 通过。
- 生产验证需在另行确认的维护窗口中完成：数据库健康、preload 配置、扩展存在、exporter 抓取成功，以及 Grafana 面板出现数据。

## 风险与回滚

- `pg_stat_statements` 会占用共享内存；默认使用 5000 个条目、仅跟踪顶层 SQL、关闭 planning 统计。
- Exporter 只采集聚合指标，不启用 SQL text 标签；`queryid` 仍带来有限但需监控的时序基数。
- 历史累计数据在 PostgreSQL 重启时默认保存，但统计重置会影响窗口计算；趋势必须通过 rate/delta 并识别 reset。
- 如需撤回 preload，可移除 Compose 参数并重启 PostgreSQL；扩展本身不自动卸载。初始化 SQL 保留在镜像中只影响新初始化的数据卷。
