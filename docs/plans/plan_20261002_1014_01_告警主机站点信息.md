# 告警主机站点信息实施计划

## 任务目标

在告警中心和告警历史中显示关联主机名、IP 地址及 CMDB 站点名称，使告警记录可以直接定位到具体设备和站点；不得把系统内部站点 ID 显示为名称。

## 现状与问题

两个页面已有主机名、IP 和站点列，但站点列直接显示原始 `devices.site`，所以可能显示内部 ID。CMDB 的 `/api/cmdb/sites` 已返回站点 `id/site_code/site_name`，告警页面尚未复用该目录映射。

## 影响范围

- 告警列表与详情响应增加 `site_id`，供前端目录映射使用。
- 两个告警页面的站点名展示及共享 `AlertRecord` 类型。
- 不修改告警处置、筛选、权限或站点/设备数据。

## 拟修改文件

- `backend/api/alerts.py`
- `src/pages/AlertDeskTab.tsx`
- `src/pages/AlertHistoryTab.tsx`
- `src/types.ts`
- 对应 `docs/walkthrough/walkthrough_20261002_1014_01_告警主机站点信息.md`

## 实施步骤

1. 追踪两个页面从 API、类型到表格/详情/导出的完整数据链，核对设备、资产与站点关联字段。
2. 复用 `listSites()` 获取 CMDB 站点目录，按站点 ID/code 将告警记录映射为 `site_name`。
3. 告警列表和详情只返回所需 `site_id`；页面名称解析失败时显示“未分配站点”，不回显原始值。
4. 检查 diff 与调用契约，运行 TypeScript lint 和 Python 语法检查；不运行测试。
5. 记录实际变更、验证结果和未验证项到 walkthrough。

## 验证计划

- `npm run lint`
- 对 `backend/api/alerts.py` 执行内存 Python 编译检查。
- 静态检查告警中心与告警历史均通过共享解析 helper 显示 `site_name`，并隐藏无法解析的内部 ID。

## 风险与回滚思路

- 风险：历史告警或已删除设备可能没有关联设备/站点；展示会以可读占位处理，不影响告警本身加载。
- 风险：CMDB 目录不可用或告警记录的站点标识无法匹配时，页面显示“未分配站点”。
- 回滚：恢复本次涉及的告警响应/类型/展示文件即可，不涉及数据库迁移或数据回填。

## 调查分工

- `alert_api_trace`：只读追踪后端告警响应和关联字段。
- `alert_ui_trace`：只读追踪前端页面和可复用的设备/站点映射。
- 主 Agent：确定接口与文件边界、实施、集成和统一验证；调查 Agent 不修改文件。
