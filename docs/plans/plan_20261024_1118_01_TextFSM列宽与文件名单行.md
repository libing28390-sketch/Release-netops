# TextFSM 列宽与文件名单行

## 目标与现状

TextFSM 模板列表的“文件名”列会随窗口尺寸/缩放变化而折行，列之间也显得松散。用户希望第一列保持单行；很长的文件名可以通过悬停查看完整内容。

## 影响范围

- 仅调整 `src/pages/TextFSMTemplatesTab.tsx` 的模板列表表格宽度和文件名单元格呈现。
- 重新平衡列宽比例；保留操作列的固定操作空间。
- 表格在可用宽度不足时使用已有的表格横向滚动容器。
- 右侧现有纵向滚动条由表格区域的 `overflow-y-auto` 和固定分页布局产生；保留该滚动区域。
- 不修改分页默认值、列顺序、筛选、排序、导出或 API。

## 实施步骤

1. 为表格设置适合九列阅读的最小宽度，窄视口时在表格容器内横向滚动。
2. 为长文件名启用单行省略，并通过 `title` 属性悬停查看完整名称。
3. 收紧并重分配列宽，减少无效留白，同时确保厂商、平台、命令、来源和操作列可读。
4. 在默认视口及更窄视口检查文件名单行、横向滚动和整页宽度。
5. 运行 TypeScript 检查、隔离 Vite 构建及差异格式检查。

## 验证计划

- 浏览器检查 TextFSM 列表及长文件名悬停提示；覆盖 1920×873、1280×720 和 390×844 视口。
- `npm run lint`
- 在临时目录执行 Vite production build，保留仓库中已有构建产物。
- `git diff --check -- src/pages/TextFSMTemplatesTab.tsx`

## 风险与回滚

- 窄视口或高倍缩放时，用户可能需要在表格内横向滚动；文件名保持单行，完整值可悬停查看。
- 如需回滚，恢复原列宽和 `min-w`，并移除文件名单元格的 `truncate` 类即可。
