# Implementation Plan - Nexora AI Platform 落地实施计划

## 任务目标
构建并全面实施 **Nexora AI Platform / AI Center** 架构，建立统一的 AI 基础设施（Providers、Models、Model Router、LLM Gateway、Prompt Center、Sanitizer、Rate Limit、RBAC、Token 统计、审计与异常处理），并接入命令解释、配置分析、Diff 智能分析、告警分析等只读 AI 业务场景，逐步延伸至受控 Agent 及 RAG 知识库。

---

## 一、架构设计与核心原则

### 1.1 强制架构隔离
- **模型解耦**：业务代码不允许直接实例化特定 SDK（如 `OpenAI(base_url="api.deepseek.com")`），必须通过 `LLM Gateway -> Model Router -> Provider`。
- **数据通道隔离**：AI 不得直接建立 SSH/SNMP 连接设备，仅能调用受控 Nexora Tool Registry 或读取经过 Sanitizer 脱敏的上下文。
- **绝对只读 (V1)**：第一阶段禁止任何自动修改设备配置、shutdown、reboot 等高风险变更操作。
- **算法确定性归属**：Diff 计算、IP 拓扑查找等确定性逻辑由 Nexora 引擎自身计算，AI 仅负责对真实计算结果做语义理解与智能推理总结。

### 1.2 模块目录结构
- 后端：`backend/app/ai/` 及其子目录 (`api/`, `providers/`, `gateway/`, `prompts/`, `context/`, `security/`, `services/`, `schemas/`, `tools/`, `agents/`)
- 前端：`src/pages/ai/` 及其子组件，并在系统菜单添加 `AI 中心` (AI 助手、分析记录、Prompt 中心、模型管理、Provider 管理、Token 统计、AI 审计等)。

## 二、数据库与迁移设计 (`m0103_ai_platform_tables.py`)

支持的的核心数据表：
1. `ai_provider`：存储供应商 (DeepSeek, OpenAI, Qwen, Ollama, OpenAI_Compatible)，API Key 使用 AES-256-GCM 加密存储。
2. `ai_model`：模型规格及能力标示 (thinking, tool_call, context_length, is_default)。
3. `ai_model_route`：场景路由 (chat, command_explain, config_explain, config_diff, alarm_analysis, natural_query, troubleshooting)。
4. `ai_prompt` & `ai_prompt_version`：提示词模版及多版本审计追溯。
5. `ai_request_log`：全量 API 请求日志 (request_id, user_id, provider, model, latency, token, status)。
6. `ai_usage_daily`：每日 Token 消耗及请求统计度量。
7. `ai_tool` & `ai_agent` & `ai_agent_run` & `ai_agent_step`：Tool 注册表与 Agent 追踪表。
8. `ai_knowledge_base` & `ai_document` & `ai_document_chunk`：知识库与 pgvector 语义检索引擎。

## 三、任务拆解与分期推进

### 阶段 1：P0 核心 AI 基础设施 (AI-001 ~ AI-020)
- **AI-001**：创建 `backend/app/ai` 完整的目录结构与包定义。
- **AI-002 & AI-003**：数据库迁移 `m0103_ai_platform_tables.py`，实现 `ai_provider` 数据表及 AES-256-GCM API Key 加密/脱敏机制。
- **AI-004**：实现 `ai_model` 数据表及 CRUD，支持默认模型与状态切换。
- **AI-005 & AI-006**：实现 `DeepSeekProvider` 及通用 `OpenAICompatibleProvider`。
- **AI-007 & AI-008**：构建 `LLM Gateway` 与 `Model Router` 场景模型映射机制，支持 Fallback。
- **AI-009**：Provider & Model 连通性测试 API (POST /api/ai/providers/{id}/test)。
- **AI-010 & AI-011**：提示词中心 `Prompt Center` 与版本历史回滚 `Prompt Version`。
- **AI-012 & AI-013**：全量 AI 请求日志记录与 Token 使用量每日统计聚合。
- **AI-014**：基于 Redis 的 Rate Limit / Quota 管理。
- **AI-015**：`Data Sanitizer` 敏感信息扫描脱敏模块 (密码、SNMP Community、Token 替换为 `<REDACTED>`)。
- **AI-016 & AI-017 & AI-018**：AI RBAC 细粒度权限控制、统一错误捕获映射、指数退避重试降级。
- **AI-019 & AI-020**：前端模型管理 UI 及 Token 统计 UI 页面实现。

### 阶段 2：P1 AI 业务分析功能 (AI-021 ~ AI-030)
- **AI-021**：命令解释 (POST /api/ai/analyze/command) + 前端嵌入。
- **AI-022**：配置分析 (POST /api/ai/analyze/config) + 脱敏与厂商适配。
- **AI-023**：Diff 智能分析 (POST /api/ai/analyze/diff) + 结合 Nexora Diff Engine 风险提示。
- **AI-024**：告警智能分析 (POST /api/ai/analyze/alarm) + 告警指纹关联Incident Root Cause。
- **AI-025 ~ AI-030**：`Context Builder` 构建 (Asset, Alarm, Config, Topology, Monitoring 上下文组装器)。

### 阶段 3：P2 AI Copilot & 知识库 (AI-031 ~ AI-040)
- **AI-031 ~ AI-035**：AI Assistant 交互对话、意图识别、自然语言资产/IP/MAC定位。
- **AI-036 ~ AI-040**：pgvector 语义库、RAG Chunking、Embedding Provider 与 检索器。

### 阶段 4：P3 & P4 Tool Registry / READ_ONLY Agent / 变更管控 (AI-041 ~ AI-054)
- **AI-041 ~ AI-048**：Tool Registry、R0-R4 风险引擎、Troubleshooting Agent 与 执行轨迹 UI。
- **AI-049 ~ AI-054**：配置生成、风险审查、受控审批与回滚。
