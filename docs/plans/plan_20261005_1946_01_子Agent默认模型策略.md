# 子 Agent 默认模型策略实施计划

## 任务目标

统一项目中所有预置子 Agent 角色的模型设置，默认使用 Luna 6 (`gpt-6-luna`) 与 `max` 推理强度。

## 现状与问题

`.codex/config.toml` 已将全局默认设为 `gpt-6-luna` / `max`，但 `.codex/agents/` 中 backend、frontend、verification 角色显式覆盖为 `gpt-5.6-luna` / `high`，complex 角色仍指定旧版 `gpt-5.6-luna` / `max`，导致默认值无法统一生效。

## 影响范围

修改项目协作说明与预置角色配置，不改业务代码、主 Agent 模型配置、并发数或项目授权策略。

## 拟修改文件

- `.codex/agents/backend-worker.toml`
- `.codex/agents/complex-worker.toml`
- `.codex/agents/frontend-worker.toml`
- `.codex/agents/verification-worker.toml`
- `AGENTS.md`

`.codex/config.toml` 的全局默认已经符合目标，本次保留其现值。

## 实施步骤

1. 将每个角色配置中的 model 统一为 `gpt-6-luna`，推理强度统一为 `max`。
2. 更新 `AGENTS.md` 模型分工和直接指定模型时的回退说明，避免普通工作包仍要求 high 或旧模型。
3. 解析全部 TOML 并核对四个角色及全局默认的最终值。
4. 在完成记录中说明配置覆盖关系与验证结果。

## 验证计划

使用 Python 标准库 `tomllib` 解析配置文件，并检查角色模型与推理强度；不运行业务测试、lint 或构建。

## 风险与回滚

配置文件可直接恢复原值回滚。若当前运行时或具体宿主不支持 `gpt-6-luna`，启动子 Agent 时会报模型配置错误；全局默认已采用同一模型名，角色配置统一可消除此处旧模型覆盖。
