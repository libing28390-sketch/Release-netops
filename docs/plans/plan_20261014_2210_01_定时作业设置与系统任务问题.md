# 定时作业设置与系统任务问题实施计划

## 目标
- 消除定时作业第二步设置时的闪烁，减少宽屏下两侧和卡片之间的空白。
- 修复调度器查询不存在的 `devices.is_active` 字段导致作业失败的问题。
- 避免把只读的系统内置作业误当成可编辑用户作业，并在审批人下拉框中只显示用户名。

## 现状与问题
- Cron 预览在表达式每次变化时清空当前结果，再切换空闲、加载和完成状态，导致卡片内容高度变化；父组件加载审批人时还依赖 `form.action_type`，切换动作会重新清空并请求审批人列表。
- 第二步卡片按两行网格摆放，审批卡片落在右下，左下出现大块空白；外层 `max-w-[1440px]` 限制也未充分利用内容区宽度。
- `devices` 表使用 `status`、`lifecycle_status` 和 `onboarding_status` 等字段，不存在 `is_active`。计划作业的 `all`、`composite`、`site`、`role` 范围查询都带有错误过滤条件。
- 系统内置 NSOT 作业以 `authorization_mode='system'` 出现在普通作业列表中，而卡片和详情仍提供编辑/启停/删除入口；后端正确地拒绝这些变更，但错误暴露给用户。
- 创建、停用等审批人下拉选项显示 `username (role · tenant)`，用户只希望看到用户名。

## 影响范围
- 定时作业设置页、Cron 预览与审批人加载逻辑。
- 计划作业调度器设备范围查询。
- 系统内置作业列表卡片与详情操作入口。

## 实施步骤
1. 将审批人、脚本与设备列表加载副作用拆分，避免切换动作时重复清空审批人；设备刷新完成前保留已加载清单。将验证码倒计时的秒级刷新隔离到局部组件，避免每秒触发整页渲染。
2. Cron 预览请求期间保留上次结果，在有效响应到达后一次性替换；固定预览卡片最小高度，避免结果区闪烁和内容跳动。
3. 将作业表单改为居中的限宽、限高对话框，列表留在遮罩背景中；仅对话框正文滚动，标题与操作区固定。收紧页面左右边距，并让第二步在对话框内按可用空间排列调度、目标设备与审批；中小屏纵向堆叠。审批人选项只显示用户名。
4. 移除调度器设备范围查询中所有不存在的 `is_active` 谓词，仅以租户和已配置的范围条件解析目标；保留后续设备租户/授权校验。
5. 对 `authorization_mode='system'` 作业保留查看能力，隐藏编辑/启停/删除入口，并在详情中展示平台托管说明；后端只读保护不变。
6. 主 Agent 审查变更并记录验证与仍需部署/浏览器复核的事项。

## Agent 分工
- `backend_worker` 独立负责 `backend/services/scheduler_service.py` 的设备范围 SQL 修复；不与主 Agent 共改该文件。
- 主 Agent 负责前端页面、审批倒计时组件、系统内置作业只读入口、计划与 walkthrough，并统一审查和验证。

## 验证计划
- 检查变更后的依赖数组，确认审批人和设备不会因表单编辑重复清空/重新加载。
- 运行 `npm run lint`、隔离目录下的 Vite 生产构建、相关 Python 文件 `py_compile` 和 `git diff --check`。
- 使用浏览器只读确认表单页面结构、用户名显示和系统作业只读提示；不创建真实作业或触发设备执行。
- 不运行自动化测试，除非用户另行要求。

## 风险与回滚
- 删除 `is_active` 谓词会让指定范围解析包含租户下的全部设备记录；这符合现有设备表结构且与页面显示的目标预览一致。运行前仍由现有租户与设备级权限检查约束。
- 系统作业保持只读，降低错误入口带来的误操作；如未来需要修改系统作业，应通过独立的系统管理接口和权限模型实现。
- 若三栏布局在窄屏出现拥挤，保留断点堆叠规则并调低断点；不改动审批、作业执行或设备配置。
