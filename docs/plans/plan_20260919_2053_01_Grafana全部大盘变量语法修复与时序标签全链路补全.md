# 实施计划：Grafana 全部大盘变量语法修复与时序标签全链路补全

## 任务目标

解决用户在 Grafana 中反馈的问题：
1. 大盘（如 `04 接口流量与健康`）顶部的“站点”和“设备”下拉框展开只有 `Selected (1)` 和 `All`，无法列出具体站点和设备；
2. 折线图图例显示为断头破折号 `-(10.254.0.1)-`，缺失设备名称 (`hostname`) 与端口名称 (`ifName`)；
3. 表格中只显示了“管理 IP”，缺失“设备名称”和“端口编号”；
4. 深度排查并修复全部 8 个 Grafana Dashboards 的变量查询语法、选择器兼容性、图例渲染和表格变换。

---

## 现状与根因深度剖析

### 根因 1：Grafana 变量查询缺少指标限定，VictoriaMetrics 返回空
- 在 `generate_dashboards.py` 中，站点和设备变量定义为：
  - `label_values(site_name)`
  - `label_values({site_name=~"$site",vendor=~"$vendor"}, hostname)`
- 在 Prometheus/VictoriaMetrics 官方标准规范中，未限定指标的 `label_values(label)` 发起的是全局 `/api/v1/label/label/values` 请求。在时序数据未命中全局标签缓存时，直接返回 `[]`，导致下拉框仅有 `All`。
- 官方与最佳实践要求为：必须指定 metric 表达式，如 `label_values(ifOperStatus or up, site_name)`，Prometheus 才能准确定位该指标的时序标签。

### 根因 2：采集端 `snmp_targets.yml` 基线缺失，入库指标缺少 `hostname`、`site_name`
- `monitoring/vmagent/targets/snmp_targets.yml` 当前在仓库和默认运行时中是空列表 `[]`。
- 缺少静态预置基线和启动自愈逻辑，导致 `vmagent` 抓取时未打上 `nexora_hostname`、`nexora_site_name`、`nexora_vendor`、`nexora_role` 标签，被抓入 VictoriaMetrics 的指标只包含默认的 `instance` (IP)。
- 由于时序上没有 `hostname` 标签，`label_values(..., hostname)` 结果为 0 项，设备下拉框变为空。

### 根因 3：图例硬编码分隔符导致空标签破裂，表格聚合丢弃列
- 图例配置为 `"legendFormat": "{{hostname}} ({{instance}}) - {{ifName}}"`。当 `hostname` 和 `ifName` 为空时，Grafana 渲染结果呈现为极其刺眼的 `-(10.254.0.1)-`。
- 表格查询 `max by (hostname, instance, ifName) (...)` 在原始时序缺少这些标签时，PromQL 聚合会自动剔除缺失标签，仅保留 `instance`，导致 Organize 变换后表格只剩“管理 IP”一列。

## 拟修改文件清单

1. `monitoring/grafana/generate_dashboards.py`：
   - 修复所有 8 个 Dashboards 的变量查询语法，全部改用显式指标限定的 `label_values(...)`；
   - 升级 `device` 变量定义，支持在无 `hostname` 标签时优雅回退到 `instance`；
   - 优化图例模板格式，去除孤立短横线，统一为优雅兼容格式；
   - 优化选择器 `dev_sel`，支持 `hostname=~"$device" or instance=~"$device"` 双向匹配；
   - 优化表格 Organize 变换，保障在列缺失时的安全展示。
2. `monitoring/vmagent/targets/snmp_targets.yml`：
   - 写入当前数据库中全部 14 台纳管网络设备的完整采集目标与元数据标签（`nexora_hostname`, `nexora_site_name`, `nexora_vendor`, `nexora_role`, `nexora_platform` 等）。
3. 执行 `python monitoring/grafana/generate_dashboards.py`：
   - 重新生成全部 8 个 dashboard JSON 文件。

## 实施步骤

1. **修改 `monitoring/grafana/generate_dashboards.py`**：
   - 统一变量查询：
     - `site`: `label_values(ifOperStatus or ifHCInOctets or sysUpTime or up, site_name)`
     - `vendor`: `label_values(ifOperStatus{site_name=~"$site"} or sysUpTime{site_name=~"$site"} or up, vendor)`
     - `role`: `label_values(ifOperStatus{site_name=~"$site",vendor=~"$vendor"} or up, role)`
     - `device`: `label_values(ifOperStatus{site_name=~"$site",vendor=~"$vendor"} or sysUpTime or up, hostname)`
   - 优化单设备详情大盘（Dashboard 02）：
     - `dev_sel` 宏升级为 `(hostname=~"$device" or instance=~"$device")`；
   - 优化图例：
     - 将 `{{hostname}} ({{instance}}) - {{ifName}}` 改为 `{{hostname}} {{instance}} {{ifName}}`；
     - 将设备 CPU/内存/温度图例改为 `{{hostname}} {{instance}} · {{vendor}}`；
2. **运行生成脚本更新 8 个 JSON 文件**：
   - 运行 `.venv\Scripts\python.exe monitoring/grafana/generate_dashboards.py`；
3. **填充 `monitoring/vmagent/targets/snmp_targets.yml` 基线**：
   - 使用从数据库导出的 14 台网络设备全量 targets 与标签更新该文件，确保 Docker 卷和静态运行时能直接获得完整元数据；
4. **验证测试**：
   - 运行针对 monitoring 的单元测试与编译器测试；
   - 验证生成的 JSON 语法合法性；
5. **归档交付**：
   - 编写 `fix_*.md` 与 `walkthrough_*.md`。
