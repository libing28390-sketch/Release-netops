# v1.0.9 完整代码提交与覆盖发布计划

按用户明确要求，将当前 `main` 工作区中本任务以及之前积累的真实代码和相关文档一并提交、推送到 `main`，把已存在的源仓库 `v1.0.9` 标签更新到新提交，并由现有发布工作流重新发布同名 Release。

## 现状与问题

- 当前分支为 `main`，本地和 `origin/main` 同为 `2e7b1f162b33190f27d79eb4fce478e0ef395e5b`。
- 源仓库 `v1.0.9` 是 annotated tag，远端存在并指向当前提交；`package.json` 版本已是 `1.0.9`。
- 用户要求把历史工作区改动一起提交。工作区包含专线中心实现，以及较早的 Docker 容量测试、日常变更文档和构建产物。

- 公开仓库当前已有 `v1.0.9` Latest Release；本次更新会覆盖同一标签对应的发布内容。用户明确要求继续使用该标签。

- 重新指向现有 `v1.0.9` 会改变公开版本标签和该版本 Release 内容；此行为由用户当前指令明确授权。
- 如提交推送成功但正式门禁失败，不声称发布成功；保留失败日志，修复后仍以 `v1.0.9` 触发重跑。

- 不执行 Docker、本机部署、生产迁移或设备路由变更。`.codex-build-validation-*` 与临时 `dist-*` 输出只保留在本机，不进入提交。
