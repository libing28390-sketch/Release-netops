# 路由邻居 SNMP 采集实施计划

## 任务目标
将 `/automation/metrics` 中 OSPF/BGP 邻居类巡检指标和后台 OSPF/BGP 邻居状态变化告警改为 SNMP 优先，SNMP 不可用时保留 CLI 回退；同时盘点后续可纳入 SNMP 的常用监控项，并审查自动化脚本执行链路的优化空间。

## 现状与问题
巡检项已有 BGP Down 数的 CLI 默认配置，SNMP 提取器目前不识别协议邻居表；状态变化告警通过 SSH/CLI 拉取 BGP、OSPF、BFD。仓库已有 `snmp_service.collect_snmp_routing_neighbors` 标准 MIB 采集器，并被路由邻居调度采集任务使用。LibreNMS 导入范围以 OS 识别、硬件和无线定义为主，BGP/OSPF 将复用已有标准 MIB 采集器，不假设硬件 YAML 规则覆盖路由协议。

## 影响范围
- 巡检项默认值与后端设备巡检执行
- 后台 BGP/OSPF 状态变化告警采集及告警数据的采集源展示
- `/automation/metrics` 中 SNMP 邻居指标的编辑提示
- 自动化脚本的 SNMP、CLI、TextFSM 只读审查
- 任务计划与完成记录

## 实施步骤
1. 复用标准路由邻居采集器，建立统一的设备级 SNMP 凭据/版本适配封装，并限制协议邻居查询超时。
2. 让巡检项按 BGP/OSPF 的 check key 识别 SNMP 邻居表，统计 Down 数并记录逐邻居状态变化；SNMP 失败时使用现存命令与解析配置回退。
3. 将默认 BGP 邻居巡检项改为 SNMP 优先，并补充常见平台的 OSPF 邻居 Down 指标。
4. 将后台 BGP/OSPF 状态告警改为 SNMP 优先、完整采集失败时 CLI 回退；BFD 继续使用原 CLI 路径。同步 OSPF `two_way` 等状态归一化与采集源文案。
5. 只读审查自动化脚本的 SNMP、CLI、TextFSM 执行链路，整理有证据的优化建议。
6. 盘点当前已支持与可优先补充的 SNMP 指标，写入 walkthrough。

## 验证计划
静态检查调用链、凭据解析、错误/空数据分支、状态归一化和差异；检查变更差异与 `git diff --check`。不运行测试，除非用户明确要求。

## 风险与回滚思路
BGP4-MIB 当前覆盖 IPv4 peer；某些设备未开放标准 MIB 或 SNMP view 不完整时会回退 CLI。SNMP 超时或不完整快照不得更新 peer state。回滚时恢复巡检种子的 CLI 配置和后台告警采集函数即可，SNMP 服务为只读查询，无数据库迁移。
