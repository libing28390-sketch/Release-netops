# 实施计划 - 锐捷交换机、迪普防火墙、迈普交换机 TextFSM 模板开发与验证

## 1. 任务目标
根据锐捷交换机（Ruijie RGOS）、迪普防火墙（Dptech Firewall）、迈普交换机（Maipu MyPower）三类国产网络设备的 CLI 回显格式，按照 NTC-Templates 命名规范和字段契约编写 TextFSM 模板，并在后端解析引擎（`backend/core/textfsm.py`）、平台映射与测试套件中完成充分验证。

## 2. 现状与问题分析
1. **锐捷 (Ruijie RGOS)**:
   - 现有的 `ruijie_rgos_show_ip_interface_brief.textfsm` 仅支持 `IP-Address(Pri)` / `IP-Address(Sec)` 单一回显，缺少对普通交换机 `Interface IP-Address OK? Method Status Protocol` 标准列格式及 `administratively down` 等状态语法的全面兼容。
   - 缺少 `show interface brief` 接口摘要模板。
2. **迪普防火墙 (Dptech Firewall)**:
   - 现有的平台映射和 TextFSM 自定义模板库中尚未针对 Dptech (`dptech_ios` / `dptech`) 建立标准接口解析模板（包含 `show interface brief` / `show ip interface brief`）。
3. **迈普交换机 (Maipu Switch)**:
   - 现有的平台映射和 TextFSM 模板库中缺少 `maipu_show_ip_interface_brief.textfsm` 与 `maipu_show_interface_brief.textfsm` 模板。

## 4. 实施步骤
1. **编写并增强 TextFSM 模板**：
   - 为锐捷 RGOS 编写多格式兼容的 `show ip interface brief` 和 `show interface brief` 模板。
   - 为迪普防火墙编写 `dptech_ios_show_interface_brief.textfsm` 和 `dptech_ios_show_ip_interface_brief.textfsm`。
   - 为迈普交换机编写 `maipu_show_ip_interface_brief.textfsm` 和 `maipu_show_interface_brief.textfsm`。
2. **扩展后端平台适配层与 Sample 数据**：
   - 在 `backend/core/textfsm.py` 的 `TEXTFSM_PLATFORM_MAP` 和 `_COMPATIBLE_PLATFORMS` 中添加 `dptech` (`dptech_ios`) 与 `maipu` 映射。
   - 在 `TEMPLATE_DEFAULT_SAMPLES` 中添加三厂商典型测试 CLI 样本，方便前端预览与在线解析测试。
3. **单元测试与门禁验证**：
   - 编写 Pytest 测试用例，覆盖各厂商标准输出、无 IP / 默认 VLAN / 物理端口 down 态、多字串状态等边界用例。
   - 运行全量 `pytest` 及质量门禁。

## 5. 验证计划
- 使用 `.venv\Scripts\pytest.exe backend/tests/vendor_audit/test_ruijie_dptech_maipu_textfsm.py` 验证模板解析准确率与字段映射。
- 运行全量测试套件确保无回归问题。

## 6. 风险与回滚思路
- **风险**：平台名称大小写或下划线命名差异可能导致智能解析匹配降级。
- **回滚思路**：TextFSM 模板均保存在 `data/textfsm_templates/` 自定义目录中，若有异常可按版本还原模板文件，且不影响系统底层 NTC 官方内置库。
