## 1. 任务目标与交付定义

将现有 WAN 能力扩展为专线中心，让运维人员能回答：哪条线路异常、影响哪些站点、证据来自哪里、统计是否可信、是否达到配置的服务目标。

首版交付独立专线总览、单线详情、A/Z 端点映射、按线路执行的探针上下文、基础质量/SLA、故障事件与诊断跳转。复用现有线路 ID、WAN 采集、历史样本、告警、维护、主备组及容量能力。

专线中心中的 SLA 表示“根据配置的观测点、目标和策略测得的服务水平”。必须附测量范围、路径证据、覆盖率与策略版本。平台测量不能直接证明运营商责任，未纳管对端不能被解释为故障。

用户配置入口、必填字段、自动读取字段和六步启用流程见第21节；专线信息先在监控页面配置，再由系统生成业务看板和诊断链接。

## 3. 首版范围与后续路线

### 3.1 V1 必交付

1. 专线总览与单线详情，按站点、运营商、状态、类型、主备角色及关键词查询。
2. 基于 wan_links 的 A/Z 端点；A 端须有可管理的独立计量接口，Z 端允许未纳管。
3. 合同上下行带宽、绑定版本和合同历史；业务线路编号与内部 ID 分离。
4. 上下行流量、合同利用率、峰值、平均、窗口 P95、接口状态、错误/丢弃。
5. 复用探针，按线路上下文执行；路径未验证或能力不支持时明确显示原因。
6. ICMP/TCP 可达性、ICMP RTT/丢包/Ping RTT 波动；HTTP/DNS 作为应用证据单独展示。
7. 24h、自然月和已关闭月份的基础 SLA；维护排除、未知时长、覆盖率和统计证据。
8. 复用告警、维护和主备组；增加线路故障/恢复时间线及路径证据。
9. 全链路 tenant/site/resource 授权、审计、分页、缺测和错误态。
10. 修复相关导航链接，提供可授权的设备/接口诊断入口。

### 3.2 V1 后增量交付

- 运营商对比与可导出月报：先统一观测条件和覆盖率，再比较同类线路。
- 健康评分：保留可解释规则；当前中断直接 critical，评分不能覆盖故障。
- 路由/BGP/SD-WAN/IP SLA/NQA 证据、分布式观测点及双向主动探测。
- 经租户隔离验证的逐线路 Grafana 看板、容量预测和 AI 分析。

V1 不提供自动改路由、自动切换主备或自动扩容。多点 MPLS、共享物理口流量拆分及云 API 自动发现进入后续阶段，需对应真实计量来源。

## 4. 固定架构决定

- **业务根对象**：wan_links.id。保留原采样、告警、分组、报告与 API 关联；circuit_number 是运营商业务编号，不充当全局主键。
- **权威业务数据**：PostgreSQL 保存端点、合同/策略版本、WAN 时序、线路探针结果、质量时间槽和 SLA 快照。
- **业务界面**：React 专线中心负责线路身份、总览、详情、SLA 和事件。已有 Grafana 负责平台/接口诊断。
- **采集**：继续现有 WAN 原生 SNMP 路径；同一实际设备/接口/cadence 的采样尽可能复用。按接口识别数据，端点映射负责业务归属。
- **探针**：复用 outbound_probe_service 和调度体系，引入线路执行上下文；同一目标绑定不同线路时按不同路径上下文执行。
- **Grafana 安全**：共享 /metrics 继续只输出低基数汇总。V1 逐线路/租户 SLA 通过鉴权业务 API 读取，不直接加入共享 circuit_id 指标。
- **版本边界**：冻结在当前仓库约定的 Grafana 12.1.0 与 VictoriaMetrics 数据源上，不依赖较新 Grafana 的预览功能。

数据流：

~~~mermaid
flowchart LR
    CMDB["现有设备 / 接口 / 站点"] --> LINE["wan_links + A/Z 端点"]
    LINE --> SNMP["复用 WAN SNMP 采样"]
    LINE --> PROBE["线路探针执行上下文"]
    PROBE --> PATH["执行来源与路径证据"]
    SNMP --> PG["PostgreSQL 时序与版本"]
    PATH --> PG
    PG --> AGG["状态 / 质量时间槽 / SLA"]
    AGG --> API["tenant + resource 鉴权 API"]
    API --> UI["React 专线总览与详情"]
    PG --> GLOBAL["脱敏全局汇总"]
    GLOBAL --> VM["现有 VictoriaMetrics / Grafana"]
~~~

### 5.1 端点与租户

- 老记录的单端接口回填为 A 端，Z 为未纳管；旧字段继续兼容 A 端采集。
- A/Z 的设备、站点、接口和探针必须属于同一允许租户作用域；跨租户端点首版拒绝。
- 根据现有设备租户回填线路 tenant_id。设备/站点归属冲突进入异常清单，管理员修正前不开放新专线接口，不静默选租户。
- 活跃端点在每条线路/side 下唯一。接口仍须属于设备，并通过最新资产同步确认 ifIndex；ifIndex 改变须重新核验，不能继续沿用失效索引。
- V1 保留原独立接口唯一约束。共享物理口没有子接口或专属计数器时，measurement_scope=shared_interface，仅允许展示共享口证据，不启用逐线路流量/SLA 容量结论。

### 5.2 历史与并发

- 端点、合同和 SLA 策略按生效时间追加版本，禁止覆盖已生效历史。
- 老合同回填起点使用最早可信时间，不能声称知道此前真实合同；更早历史标记 legacy_contract_unknown。
- 历史利用率使用采样时生效合同；当前合同只用于当前值。容量建议也必须返回合同/窗口版本。
- 编辑接口使用配置版本与乐观并发检查，过期版本返回 409；有效期重叠的写入在 PostgreSQL 事务内锁定线路并拒绝冲突。
- 新端点样本承载 A/Z 两端；旧 wan_link_samples 的 (link_id,sampled_at) 唯一键不能直接放入双端数据。A 端由同一次实际采样投影给旧查询，新增表不触发第二次设备轮询。
- 时间存 UTC TIMESTAMPTZ；业务窗口按线路策略时区切分，展示转换为当地时间。
- 删除改为归档/停采并保留历史；租户授权同时覆盖历史。旧 destructive DELETE 改动须明确兼容说明，物理清理走管理员保留策略。

## 6. 探针执行与路径验证

### 6.1 独立执行身份

执行身份至少包含 link_id、binding_version、endpoint_id、executor_id、protocol、target_id、source/path_version。幂等键为 context_id + scheduled_at；一次执行重试不能制造第二份有效样本。

普通出口探针继续使用现有 target 结果。线路探针写带上下文的结果；同 target、不同线路不得共用全局 success。可共享结果的条件是完整执行身份完全一致，且调用方有资源权限。

### 6.2 平台适配与证据状态

| path_status | 含义 | SLA 使用 |
| --- | --- | --- |
| unverified | 配置已保存但没有执行路径证明 | 仅展示目标可达性，逐线路 SLA insufficient_data |
| verified | 执行源地址与路由证据有效，且绑定/执行器/路径配置版本一致 | 可进入当前证据有效期内的线路质量统计 |
| invalid | 源地址、出口、目标或绑定证据与配置不一致 | 线路质量 unknown，提示核验 |
| unsupported | 当前协议/执行器无法完成指定来源或路径验证 | 显示具体能力缺口，不退回默认路由冒充线路测量 |

- 适配器报告协议/平台的 source binding 能力；TCP/HTTP/DNS 使用受限 socket/HTTP wrapper，ICMP 使用受控平台参数。不可实现的协议返回 unsupported。
- 验证至少保留实际绑定源、执行器、目标解析结果及与线路对应的主机/网关路由证据。只配置 source_ip、只看 traceroute 或只见探针成功均不足以宣称线路已验证。
- source bind 不等于选路。VRF、策略路由、代理和备用路由可能改变出口，须有可复核证据；目标路径或绑定变化立即失效。
- 证据带 verified_at、expires_at 和版本。默认最多 24h 有效，并按已有路径核验能力续验；续验失败后停止给出新的可信 SLA 结论。未知历史不被后来验证结果追溯改成已验证。
- 每轮检查可获得的执行器源地址与路由指纹，变化立即使证据失效。不能持续核验的适配器只能证明核验当次的测量范围，不用24h有效期替代实际路径观测；上游设备动态选路无法证明时继续标记未验证。
- 初版观测点为平台执行器。远端 A/Z 任意端的主动测量仅在实际部署了对应执行器后启用，页面显示观测点和测量方向。
- 主机/设备路由、VRF 或策略配置由管理员按部署环境完成。平台首版只保存、验证和观测，不自动修改主机或设备路由。

### 6.3 安全与调度

- 复用现有 SSRF 校验、受限端口、DNS/IP 验证、重定向和超时策略；源地址绑定不能绕开这些检查。
- 避免环境代理造成路径误判；HTTP 代理必须显式配置且纳入路径身份。
- SNMP 凭据走现有 resolve_collector_credentials；日志不含真实 community、Token、密码或连接串。
- 采集与页面读取分离。探针轮次、结果写入和 SLA 重算均有执行锁/幂等键，限制并发，处理调度重叠。
- destination timeout/refusal 等测得失败，与 executor 权限不足、DNS 校验拒绝、配置错误、内部异常、任务未执行区分。后者是 unknown，不直接计为线路断线。
- 延迟结果带原始 scheduled_at；槽在最多两个采集周期的等待水位前为 provisional，水位后确定结果，后到有效数据可按版本纠正并留审计。

## 7. 指标语义

| 指标 | 固定口径 |
| --- | --- |
| 速率 | 有效 counter delta / 真实时间差 × 8，优先 HC；reset/wrap/缺测有质量标记 |
| A→Z / Z→A | 正向接口中 A 出/Z 入观察同一方向，A 入/Z 出观察反向；显式方向配置支持 reversed |
| 主曲线 | 默认以 A 端为 canonical 计量来源；Z 端用于对照，不将双端求和；A 缺测时不自动拼接 Z 数据 |
| 合同利用率 | A→Z 对应合同 upload，Z→A 对应 download；分别计算，超过 100%保留真实值 |
| 错误/丢弃 | counter 差值或 packets/s；不是端到端丢包，也不能将通用 ifInErrors 标为 CRC |
| 流量 P95 | 对同方向、同窗口、同计量来源的有效等间隔速率样本按 nearest-rank 计算，并显示覆盖率 |
| RTT | 仅 ICMP 成功测量的 RTT；TCP/HTTP duration 用本协议名称单独展示 |
| 丢包 | ICMP 按窗口 sum(sent-received)/sum(sent)；缺 packet counts 的旧结果不虚构分母 |
| Ping RTT 波动 | 同一探测批次连续有效 RTT 绝对差的均值，保留 pair_count；不声称是单向 IP SLA jitter |
| 主备 | 显示主/备健康和“切换候选”；只有路径/路由及承载流量证据同时支持时才显示“已确认切换” |

- P95 禁止平均小时 P95、取最大小时 P95后标成整月 P95。已有容量建议中的最大小时 P95可继续作为风险证据，但须按真实口径命名。
- 分钟流量 rate 表达该采样间隔的平均速率。跨合同/端点版本分别计算，不能把历史记录全按当前合同归一化。
- 新的月 P95使用保留的分钟有效样本；超出原始样本保留窗口只给有明确口径的汇总，不能还原精确窗口 P95。
- 小样本的丢包率展示 sent/received 和分辨率。当前代码正常每批5个echo，若实际发送5包则loss步长为20%；新结果以实际包数计算，不能显示出不存在的精度。
- 波动和错误/丢弃首版作诊断，不参与默认合同 SLA 判定。未配置的指标为 not_configured，不视为达标。

## 8. SLA 时间槽、覆盖率与判定

### 8.1 默认策略

- 基础时间槽 60s；V1 可信可用率策略要求对应探针 cadence=60s。老线路其他采样周期保留，未满足 SLA 策略采样条件时明确为 insufficient_data。
- 默认窗口：滚动 24h、自然月截至当前、已关闭自然月。时区默认 Asia/Shanghai，按策略固定。
- 目标默认建议值可用率 99.9%、成功 ICMP RTT P95 30ms、ICMP loss 0.5%；全部可配置，创建时须确认测量目标与适用线路，不自动声称运营商合同。
- 默认最低有效覆盖率 99%；最低有效 RTT 样本 100、loss 发包数 1000。数值是产品首版默认门槛，不是统计置信度承诺。
- 维护默认只抑制通知；SLA 是否排除必须在策略显式设置，避免把所有维护自动从合同统计中扣除。

### 8.2 每槽状态

可用性只采用策略选定且路径有效的 ICMP/TCP reachability 上下文；HTTP/DNS 失败属于应用证据，不默认当作专线中断。

默认 availability_rule=any_success，建议两个独立目标：
- 有至少一个有效成功结果：up。
- 所有必选目标均有有效失败结果：down。
- 无成功且有未执行、内部错误、缺失或路径无效结果：unknown。

策略可显式选择 all_success，但策略改变后新增版本，不混用历史。secondary/witness 不替代指定主质量目标的 RTT/loss。单目标服务异常与线路可达性同时保留，不强归因运营商。

接口 oper/admin、设备采集与主动可达性分别统计；接口 DOWN 提供物理证据，不静默替代“端到端可达性”策略。unknown 状态不能从采集失败推成 down。

### 8.3 时间和公式

区间使用 [start,end)。统计截止到已完成槽；当前未完成槽不放入已完成 SLA 分母。维护排除区间先按策略展开、合并去重，再与窗口取交集。

E = 窗口内已完成可统计秒数（扣除显式允许排除的维护）。
U、D、X = eligible 部分的 up、down、unknown 秒数，且 U + D + X = E。

~~~text
coverage_percent       = (U + D) / E * 100
observed_availability  = U / (U + D) * 100
availability_lower     = U / E * 100
availability_upper     = (U + X) / E * 100
~~~

E=0 返回 not_applicable；U+D=0 时 observed_availability=null。不得填成 100%。

判定顺序：
1. 没有有效路径、可用策略或所需测量协议：insufficient_data/not_configured。
2. availability_upper < target：breached；已知故障足以证实失败，即使另有缺测也保留这一结论与低覆盖率标记。
3. coverage≥minimum 且 availability_lower≥target：met。
4. 其他情况：insufficient_data。observed 很高不能覆盖 unknown 的不确定性。

RTT/loss 独立显示 status、覆盖率、样本数和门限；可信的任一指标 breach 则整体 breached；所有已配置指标 met 才整体 met；其余 insufficient_data。可用率达标不代表性能指标达标。

### 8.4 可复核算例与月结

按 1000 个等长 eligible 槽、可用率目标 99.9%、路径有效：
| U | D | X | observed | lower / upper | 结论 |
| --- | --- | --- | --- | --- | --- |
| 999 | 1 | 0 | 99.9% | 99.9% / 99.9% | met |
| 998 | 2 | 0 | 99.8% | 99.8% / 99.8% | breached |
| 998 | 0 | 2 | 100% | 99.8% / 100% | insufficient_data |
| 0 | 0 | 1000 | 无有效测量 | 0% / 100% | insufficient_data |

- 当前月显示 period_state=in_progress；月结在结束后完成迟到数据水位处理，写 closed 快照。
- 中途接入、停采/归档、策略启停时间显式显示。接入前整月覆盖率不冒充完整月份；按已启用测量区间统计，同时返回 requested_period 与 monitored_period。
- 跨端点/合同/策略变化返回分段结果；整月目标不同则标 mixed_policy，展示各段达标结果，不捏造单个统一 SLA。
- 快照带算法、策略、证据和配置版本；迟到纠正形成新 revision，保留旧版。重复计算不生成重复快照或故障事件。

## 9. 状态、事件与告警

保留旧 WanHealthStatus 契约，新页面使用 circuit_status=healthy/warning/critical/unknown/disabled；旧 degraded/unavailable 在兼容层映射。维护为独立 maintenance_active 标记，不覆盖观测状态。

- critical：已确认有效观测路径不可用，或有可信受管接口故障证据；同时展示证据类型和影响范围。
- warning：性能门限超限、合同高利用率、单目标异常或仅有主备切换候选。
- unknown：缺测、路径未验证、能力不支持或数据已过期；没有测量证据时不显示健康。
- healthy：已配置必需检查的证据均有效且正常；可用性正常但性能缺测时显示 unknown/质量不完整。
- disabled：停采/归档，不纳入“正常线路”计数。

告警复用既有规则和事件生命周期。建议默认连续 3 次有效失败触发、连续 2 次有效恢复解除，并配置独立恢复门限。去抖用于通知，不把第一批有效失败从 SLA 槽中删去。

unknown 有持续采集/证据异常事件，不能直接关闭正在发生的中断。维护抑制保留事件和证据但不发通知。事件记录最早失败槽、确认时间、最后失败、恢复槽及计量分辨率；不显示秒级精度的虚构中断时间。

## 13. 计算、存储与性能预算

以下是实施验收目标，需要负载测试证明，不是当前已有性能结论。

- 默认观测 cadence 60s。压测基线100条线路、最多200个受管端点、200个线路探针上下文；更大规模按实际硬件和任务时长测得容量。
- 验收再增加20%负载，要求60s轮次P95≤45s且无重叠/coalesced遗漏；未达到时降低接入规模或明确unknown，不把未运行任务记为成功。
- 默认新增线路探针并发上限16，全局调度预算共同限制普通出口与线路探针；每个目标有timeout、socket/resource上限。SNMP预算独立受控但纳入同一主机资源观测。
- 容量约束：ceil(context_count/concurrency) × measured_p95_execution_time ≤ 0.8 × cadence。超过预算必须降低接入量/调整cadence或增加经过验证的执行能力，不能重叠排队假装按时采集。
- 新线路探针明细、质量槽和分钟有效rate保留至少90天，支持月结和近期重算；原有rollup策略保持兼容。关闭月快照和必要证据索引至少13个月，审计保留遵循项目策略。
- 当前旧WAN原始/5m/1h/daily保留为30/180/730/3650天，旧探针结果为30天。新端点/上下文表独立采用90天保留；旧不足窗口只能回填已存在的真实数据，不能从rollup恢复原始观测。
- 新高量结果按UTC时间分区、以过期分区清理；最低索引为tenant/link/time、context/scheduled_at、快照window/version。避免给所有字段建立索引。
- 两目标/100线路每分钟最多约28.8万执行结果/天，90天约2592万条；实施前实测每行/索引大小并计算磁盘、WAL和备份需求。
- SLA每分钟增量更新，小时/日校验，月结生成快照；页面读预计算摘要，禁止列表逐条查询或GET触发月级重算。
- 总览/分页 API p95目标≤1s，缓存命中的详情≤2s；缓存键包含权限作用域、筛选、窗口与配置版本。图≤1500点、列表≤100条。
- 观测任务耗时/积压/跳过、path证据失效、质量覆盖率、聚合水位、数据库查询耗时及保留清理结果；并发与缓存参数可配置。

## 17. 迁移、灰度与回滚

1. 先备份并记录现有行数/版本/配置；确认测试与生产目标分离。
2. 新表/nullable字段→按设备租户回填A端和当前合同→列出异常→验证完整性→新增必要约束/索引。迁移事务和回填批次避免长时间锁表。
3. 历史没有真实路径证据的探针保留为全局/目标证据，禁止回填成已验证逐线路SLA。
4. 模块开关默认关闭新入口/新调度，先在授权测试站点影子运行，与旧WAN采样对照，再启用业务页面。
5. 旧采样与新聚合不得双重派发通知；只保留一个事件主来源，后台执行锁跨进程有效。
6. 回滚关闭新入口/聚合/线路探针，恢复旧WAN兼容读取；新增表与历史保留，不通过drop或清空数据“回滚”。
7. 作用域过滤是上线前提。回滚不能移除租户隔离或重新开放越权API；必要时停用相关接口并显示维护。
8. 最少验收一个独立计量专线与一个主备场景，核实路径、故障恢复、缺测和合同利用率。
9. 本轮完成S0—S4代码实现及代码级验证；未提交、推送、发布、执行生产迁移或修改真实设备/主机选路。后续这些动作按用户授权和项目规范执行。

## 21. 监控页面的专线信息录入与启用流程

用户补充要求已纳入：必须在Nexora监控页面配置业务线路及采集关系，才能把设备接口数据解释为某条专线的流量、容量和质量。Grafana不负责推断线路身份、合同带宽或探针选路；配置入口统一在专线中心，并复用当前WAN编辑表单。

### 21.1 表单字段和来源

| 表单分组 | 用户填写/选择 | 自动读取/计算与校验 |
| --- | --- | --- |
| 基本信息 | 线路名称、类型、运营商、线路编号、主备角色；名称/类型必填，未知运营商/编号显式留空 | 内部link_id由系统生成；tenant由身份和所选资产确定，普通用户不能指定他人租户 |
| A端 | 从资产选择站点→设备→接口，并声明计量范围（专属接口/共享物理接口） | hostname/接口名称/ifIndex/alias/物理速率自动读取，接口必须属于设备且在授权范围；不手填ifIndex。共享物理接口可登记身份和采集证据，但不归因线路利用率/容量告警；优先选择子接口或专属计量源 |
| Z端 | 选择受管站点/设备/接口，或选择“对端未纳管”并填站点说明 | 未纳管端的设备状态不编造；受管端执行相同授权/身份验证 |
| 合同与方向 | 签约下行Mbps、上行Mbps、合同生效时间、接口方向；合同带宽必填且>0 | 保存为bps；物理口速率不自动充当合同带宽；更新追加历史版本 |
| 探针 | 选择观测执行器、协议、目标、用途、来源/路径配置；可只启用接口监控后再补 | 目标来自同租户探针资产；源IP须是执行器可用地址，不能把远端路由器IP当本机源；协议能力和路径核验独立呈现 |
| SLA | 选择启用与否、时区、目标、采样周期、维护排除规则 | 采用已冻结策略默认值并允许修改；路径、覆盖率不满足时状态为数据不足 |
| 主备/维护 | 选择已有线路组/角色，维护窗口及备注 | 组成员租户一致；主备健康和真实承载证据分别展示 |

健康状态、当前速率、利用率、RTT/loss/P95、SLA结果和最近采样时间由系统产生，不提供人工填写“正常/达标”的输入框。

### 21.2 六步流程和启用门槛

1. **新增专线**：点击“实时监控→专线中心→新增专线”，填写名称与业务属性。
2. **绑定端点**：选择A端，配置Z端；缺ifIndex先进入资产接口同步，不能保存虚构索引。
3. **填写合同**：填签约上下行、方向及生效时间；共享物理口提示粒度不足，引导选择子接口或专属计量源。若仍登记共享口，系统保留接口总流量，但线路利用率与容量告警保持未知/抑制，不把整口流量误归给单条线路。
4. **测试采集并保存**：复用当前test-config，校验SNMP凭据、接口身份和counter能力；服务端保存测试凭据引用/配置签名与有效期，启用检查不能仅相信前端“测试通过”布尔值。台账保存与端点/合同初始版本在同一事务完成。
5. **绑定探针并验证路径**：绑定同租户目标，测试协议执行来源、可达性和路由证据。测试可达只说明目标响应，路径核验另显示verified/unverified/unsupported。
6. **按能力启用**：接口采集成功可启用“接口流量监控”；共享物理口仅呈现端口总流量，不启用线路利用率。未配或未验证探针时显示“线路质量待验证”，不展示专线SLA达标。路径有效后启用线路质量与SLA，覆盖率累积期间显示数据不足。

### 21.3 从配置到看板的自动关联

- 台账配置→后端endpoint/context映射→真实采集/探针→有线路身份的数据与SLA→业务API→React专线看板。
