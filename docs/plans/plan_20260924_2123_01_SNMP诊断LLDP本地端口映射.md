# SNMP 诊断 LLDP 本地端口映射

## 任务目标

修复 SNMP 诊断结果中 H3C LLDP 邻居能显示、但本地端口显示为“未识别端口（索引 N）”的问题。

## 现状与问题

- 用户的 SNMP 探测根 OID 是 `.1.0.8802.1.1.2.1.4`，即 LLDP 远端表父节点。
- 诊断页面仅把 `.4.1` 和 `.4.1.1` 识别为专项 LLDP 查询；对 `.4` 只 WALK 远端表，未追加本地端口 ID/描述和 IF-MIB `ifName` 查询。
- 远端表能够返回 `lldpRemLocalPortNum` 索引、邻居名和对端端口，但要把本地端口索引映射成接口名，还需本地 LLDP 表或 IF-MIB 名称表。
- 当 MIB 节点后缀元数据缺失时，解析器当前先用用户 WALK 父根截断 OID，可能把列编号误当成实例索引；应优先从已知列 OID 精确提取后缀。
- 后台 `collect_snmp_lldp_neighbors` 已读取本地端口表和 `ifName`，日志与拓扑图证明设备 SNMP LLDP 数据正常；故障范围在诊断 UI 的专项查询与解析链。

## 影响范围

只调整 SNMP 诊断弹窗的 LLDP 专项 WALK 根识别、补充列查询和实例后缀解析，不改后台拓扑采集与设备配置。

## 实施步骤

1. 将 LLDP 远端表父 OID `.4` 及其子树纳入专项探测识别。
2. 专项请求同时读取 `lldpRem*`、`lldpLocPortId`、`lldpLocPortDesc` 和 IF-MIB `ifName`。
3. 有 MIB 实例后缀时继续优先使用；缺失时从已知列 OID 根计算实例后缀，再退回用户 WALK 根。
4. 运行前端类型检查、隔离输出目录的生产构建及差异检查；不对真实设备发起探测。

## 风险与回滚思路

专项探测会增加少量只读 SNMP GET/WALK 请求，但仅在 LLDP 远端表根及其子树触发。回滚时恢复本文件原有 OID 根判断和后缀回退顺序即可，不影响拓扑服务端采集。
