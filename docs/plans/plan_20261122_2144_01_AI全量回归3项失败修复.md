# AI 全量回归 3 项失败修复实施计划

- 创建时间：2026-11-22 21:44
- 目标目录：`D:\netops\netsops-main`

## 1. 任务目标

修复 `D:\netops\netsops-main` 后端 AI 全量 PostgreSQL 回归测试（1085 项）中发现的 3 项失败用例，确保全量回归 100% 通过且不削弱既有 P0 安全边界。

## 2. 现状与根因

1. `backend/ai/services/conversation_service.py:242`：`list_conversations(..., search=...)` 直接索引 `row["content_safe"]`，在兼容行对象缺少该字段时抛出 `KeyError`。
2. `backend/core/config.py`：`Settings` 未声明 `AI_KNOWN_HOSTNAME_TTL_SECONDS`，导致 Pydantic v2 拒绝 `.env` 配置映射及测试 `monkeypatch.setattr`。
3. `backend/tests/ai/test_d1_credential_redaction.py:83`：用例在默认 `chat` 场景下传入含 `system-view` 的配置片段，触发 P0 加固后的 `AI_SECURITY_UNSAFE_TOOL` 阻断；配置片段分析应走 `config_explain` 场景，以同时保留 `chat` 场景阻断写命令与 `config_explain` 场景脱敏放行两条安全契约。

## 3. 影响范围与拟修改文件

- `backend/ai/services/conversation_service.py`
- `backend/core/config.py`
- `backend/tests/ai/test_d1_credential_redaction.py`

## 4. 实施步骤

1. 在 `conversation_service.py` 中使用 `_row_has(row, "content_safe")` 防御性读取 `content_safe`。
2. 在 `core/config.py` `Settings` 中新增 `AI_KNOWN_HOSTNAME_TTL_SECONDS: int = 300`。
3. 在 `test_d1_credential_redaction.py` 中为 `system-view` 配置片段用例显式传入 `scene="config_explain"`。

## 5. 验证计划

- 在独立临时 PostgreSQL 测试库运行 `test_d1_credential_redaction.py`、`test_d2_cmdb_hostname_tokens.py`、`test_ai_p0_security_and_data_fixes.py`。
- 运行 `scripts/validate_postgresql_only.py` 确认 0 违规。

## 6. 风险与回滚思路

改动仅涉及 3 处局部防御与配置声明，风险极低；如有异常可通过 `git checkout -- <file>` 精确回滚单文件。
