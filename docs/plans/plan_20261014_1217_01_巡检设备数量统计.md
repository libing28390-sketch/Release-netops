# 巡检设备数量统计实施计划

## 任务目标
修复 /automation/inspections 概览设备数量超过 200 时仍显示 200 的问题。

## 现状与问题
巡检页读取 overview.total_devices，但该 monitorOverview 仅在监控/健康路由加载；巡检路由下回退到 devices.length。自动化页使用普通 ull 设备查询，后端默认结果最多为 200 条，导致回退统计被截断。

## 影响范围
仅影响自动化巡检概览和巡检记录路由所用设备加载模式；不改 API 契约与后端统计逻辑。

## 拟修改文件
- src/App.tsx：为巡检相关路由选择已存在的全量分页轻量加载模式。
- docs/plans/plan_20261014_1217_01_巡检设备数量统计.md
- docs/walkthrough/walkthrough_20261014_1217_01_巡检设备数量统计.md

## 实施步骤
1. 将巡检概览、巡检记录路由切换到 ll-light，复用现有分页加载和完整性校验。
2. 检查差异，确认仅触及巡检路由加载模式与归档文档。

## 验证计划
静态检查页面路由到设备加载模式的映射及 ll-light 分页实现；按当前执行约束不运行测试/构建。

## 风险与回滚思路
巡检页面会分页读取全部设备的轻量字段，设备量大时会增加请求数；若出现性能问题，可后续将总数改由专用统计字段提供。回滚方式是恢复该路由的 ull 模式选择。
