# 分离资产导入模板修复计划

## 任务目标

将资产导入模板按“网络设备”和“服务器”拆分为两个资产工作表，降低填写复杂度；管理入口中的 SSH 只保留单行配置，系统自动提供 SSH 终端和 Web SSH，同时继续兼容旧版统一资产表。

## 现状/问题

- 当前下载模板只有一个统一的“资产信息”工作表，服务器和网络设备字段混在一起。
- SSH 管理不需要额外填写 Web SSH 入口，导入逻辑应把 SSH 主通道视为同时支持终端和 Web SSH。
- 旧版用户工作簿仍使用“资产信息”表，不能因模板改版而失效。

## 影响范围

资产模板下载、Excel 工作表识别、资产类型推断和管理入口示例；不修改设备或资产数据，不改变 API 请求契约。

## 拟修改文件

- `src/pages/AssetManagement/index.tsx`：生成两张分离资产表和简化 SSH 入口示例。
- `src/pages/AssetManagement/importUtils.ts`：导出网络设备/服务器工作表识别规则，保留统一表兼容。
- `src/pages/AssetManagement/importUtils.test.ts`：覆盖分离表类型推断及 SSH 单行合并。
- `public/templates/asset_import_template.xlsx`：同步静态下载模板的工作表结构和校验。
- `docs/walkthrough/`：记录实际变更和验证结果。

## 实施步骤

1. 为网络设备和服务器工作表增加明确的名称识别，按工作表推断资产类型；统一“资产信息”表仍按行内资产类型解析。
2. 生成两个分离资产表，保留各自需要的字段和必要校验；管理入口仅示范一行 SSH，注明自动提供 SSH 终端和 Web SSH。
3. 让静态 XLSX 与兜底生成器保持相同的分离表和入口语义。
4. 增加解析合并回归测试，验证旧统一表、分离表和 SSH 单行路径。

## 验证计划

- `npm run test:frontend -- --run src/pages/AssetManagement/importUtils.test.ts`
- `npm run lint`
- `npm run build`
- 只读检查静态 XLSX 的工作表、表头、下拉校验和示例关联
- 浏览器确认模板下载可用且网络设备列表仍正常显示

## 风险与回滚思路

解析器按表头和工作表名称兼容旧文件，分离模板只影响新下载文件。若验证失败，可回退本次模板与解析器改动，不涉及数据库回滚或设备操作。
