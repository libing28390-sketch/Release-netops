# 实施计划：配置备份支持平台自动转储 TFTP 与启动配置 (Startup-Config) 采集

## 任务目标
1. **启动配置 (Startup Config) 采集与未保存配置检测**：
   - 为各厂商（华为、华三、思科、锐捷、中兴、迈普、瑞斯康达、迪普等）引入官方标准启动配置采集动作 `get_startup_config`；
   - 支持同时采集并归档 `running-config`（运行配置）与 `startup-config`（启动配置/已保存配置）；
   - 支持 **Running vs. Startup 一键 Diff 对比**，自动识别并告警“未保存运行变更（Unsaved Drift）”，杜绝设备断电丢配置故障。
2. **方案 A：配置备份与日志自动转储到外部 TFTP 服务器**：
   - 在平台后端实现轻量可靠的 TFTP 客户端推送服务；
   - 在「备份策略」中提供 TFTP 自动归档配置（支持配置目标 TFTP 服务器 IP、端口、目标子目录与命名规范）；
   - 每次定时/手动备份成功后，平台后台自动将备份配置文件与批次摘要日志同步推送至指定的外部 TFTP 服务器。

---

## 现状与问题分析
1. **当前现状**：
   - 目前仅采集 `running-config`，无法判断网络管理员调试配置后是否执行了 `save / write`；
   - 备份文件仅保存在 Nexora 服务器本地挂载目录与数据库索引中，没有外部 TFTP/SFTP 存储服务器的自动同步与日志转储机制。
2. **影响范围**：
   - 后端动作定义、多厂商技术平台命令映射；
   - 配置快照数据表结构与持久化；
   - 配置备份执行流水线（`run_scheduled_backup`）；
   - 前端备份策略配置与快照列表、Diff 对比视图。

## 实施步骤

### 第一阶段：数据库与多厂商命令注册
1. 编写迁移脚本 `m0105_config_backup_tftp_and_startup.py`，向 `action_definitions` 添加 `get_startup_config`，向 `config_snapshots` 添加 `config_type`（支持 `running` 和 `startup`），向策略表增加 `tftp_config`；
2. 在 `PLATFORM_ACTION_COMMANDS` 中完善各厂商官方命令（Huawei/H3C/DPtech -> `display saved-configuration`，Cisco/Ruijie/ZTE/Maipu/Raisecom -> `show startup-config`，Junos -> `show configuration`）。

### 第二阶段：TFTP 客户端与自动转储服务开发
1. 实现 `tftp_service.py`，提供 `upload_file_to_tftp(server, port, local_file_path, remote_filename)` 与 `batch_sync_to_tftp(...)`；
2. 增加超时、重试与网络不可达异常捕获，确保 TFTP 上传失败时不影响主备份成功状态。

### 第三阶段：配置备份引擎双流采集与转储接入
1. 在 `backend/api/configs.py` 中更新 `_backup_one`：若策略开启采集启动配置，依次采集 running 和 startup，存入两条快照记录；
2. 计算 running 与 startup 文本的归一化差异，若有差异标记未保存告警；
3. 批次完成后触发 TFTP Worker 异步转储所有快照文件及 `backup_summary.log`。

### 第四阶段：前端交互与 Diff 视图呈现
1. 在 `ConfigBackupTab.tsx` 策略弹窗增加 TFTP 表单区域（服务器 IP、端口、路径、开关）及启动配置开关；
2. 在快照表格中添加“配置类型”徽章（`Running` 绿标 / `Startup` 蓝标），提供“未保存差异”醒目标记与一键 Diff。

## 风险与回滚方案
- **风险**：个别设备未开启启动配置权限或 Junos 无独立 startup-config。
- **应对**：Junos 自动映射至当前 committed 配置；对不支持 startup-config 的设备平滑降级，仅保存 running-config，并在日志中友好记录。
- **回滚**：所有新增字段均提供默认值，策略默认保留纯 running 采集与本地存储，可随时在 UI 一键关闭 TFTP 与 startup 采集。
