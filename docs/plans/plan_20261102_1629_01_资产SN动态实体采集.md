# 目标
仅迁移独立脚本的 SN 采集与机框/堆叠归属逻辑到 NetOps，不改主机名、厂商、型号识别、前端、模板、其他遥测或 SSH。
# 现状与范围
目前仅 H3C 固定索引 1/2/3，持久化也限制索引。参考脚本动态 ENTITY-MIB、完整性检查、关系判定、私有SN证据与候选保护。按 HCL 模拟器反馈，允许同一设备多个机框索引返回相同 SN。
# 文件及分工
Luna 后端执行者拥有新增 backend/services/snmp_chassis_serial_reader.py 与 backend/tests/snmp/test_asset_chassis_serial_service.py（更新旧固定GET测试）。主 Agent 拥有 backend/services/asset_chassis_serial_service.py、snmp_import_identification_service.py 的 SN 分支、backend/api/assets.py 的 SN 提示、配置测试和计划/报告。不修改脚本本身。所有既有未提交修改保留。
# 实施步骤
1. 定义动态采集快照契约，使用现有 SNMPv2c/v3 凭据、限流和通信实现。
2. 动态发现实体，校验机框类型、父子关系、有效 SN 和快照变化；同 SN 的多个机框按实体索引分别保留，未知模块与冲突私有映射仍仅作为候选。
3. 持久化放开正整数实体索引；只在完整可信快照清理旧成员或更新自动SN，部分/失败不误删、不覆盖人工SN。
4. SN导入同步开放标准ENTITY多厂商，其余识别保持现状。
# 验证
定向SN reader单测、真实隔离PostgreSQL成员同步及资产导入契约测试、PostgreSQL-only扫描、差异审查；不执行真实设备请求、部署或全量回填。
# 风险与回滚
动态WALK增加只读请求量，设置行数、并发、设备总预算及超时。不猜测OID或私有索引映射。保持现有API结果形状和数据库结构，只撤回本次增量。

- 完整快照中所有机框只有一个不同 SN 值时，将共同值同步到资产主 SN。机框 SN 有多个不同值时仍只保留成员明细，不任意挑选主 SN；人工录入的主 SN 仍受保护。
- 更新现有重复 SN 断言，未运行测试、lint 或 build；先前 77 passed 记录对应本次调整前的代码，不能证明此次后续调整。
- 新资产导入的 SN 采集在 HTTP 响应后的后台任务中运行；资产页原先在响应返回时即停止列表轮询。对 SN pending 的导入增加 1.5、4、10、20、40 秒后的限次自动刷新，并按每 5 台设备一波追加 60 秒刷新，以覆盖单台 60 秒采集预算。
- 本机当前导入批次只读汇总为 15 行：9 行有采集时间、机箱成员和主 SN，6 行无采集观测/成员/标量 SN。列表与详情共用投影为 9 行返回成员 SN、6 行无成员数据；当前资产列表页刷新后第一页有 4/10 行显示 SN。未暴露资产标识或 SN 值。
- 本机 Vite `:5400` 代理到 Python API `127.0.0.1:15310`；API 使用当前仓库工作目录，进程启动晚于 SN 源码变更时间。这支持本次代码已由本机开发后端加载，但没有直接模块 hash 证明，也没有部署容器。
- 导入审计没有保存最终 `serial_sync` 状态，仓库没有本次导入运行日志；6 条空结果无法进一步区分后台任务未启动/未完成与设备未提供可确认的完整 ENTITY-MIB 快照。
- 速度复核发现 SN 阶段误用了容量为 1 的型号探测信号量，导致同批设备逐台采集；现改为使用导入批次容量为 5 的信号量。单台 reader 仍限制 3 个并发 SNMP 操作、60 秒总预算，全局 SNMP limiter 默认 30。15 台设备的 SN 阶段最多约 3 波，每波仍受 60 秒设备预算影响；实际时长需在后续运行中观察。
