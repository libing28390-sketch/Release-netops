## 1. 任务背景与核心诉求

用户针对 `/monitor/topology` 网络拓扑页面提出了两项页面精简与交互优化要求：
1. **默认 LLDP 物理拓扑并下线视图下拉选择器**：
   - 拓扑关系默认锁定为 LLDP 物理连接关系，不再需要“物理视图（LLDP/CDP）”、“二层视图”、“三层视图”、“逻辑视图”等多余下拉切换器；
   - 将工具栏中的关系视图下拉菜单移除，精简操作区；
2. **移除“拓扑自动生成流水线”横幅卡片（图二）**：
   - 顶部占用较大面积的“拓扑自动生成流水线 [证据正常] ... 01-06 步骤”横幅卡片不再展示，避免对核心拓扑大图造成视觉干扰，把屏幕空间全部留给拓扑图与设备筛选。

同时，用户咨询了之前在 `/monitor/reports` 报表中出现的 500 报错原因：
- 该报错系因原 SQL 查询中引用了不匹配底层 PostgreSQL 模式的字段（`s.name` 实际为 `s.site_name`，`d.temperature` 实际为 `d.temp`，`outbound_targets` 实际为 `outbound_probe_targets`）；
- 该问题与宿主机是 Windows 还是 Linux/Docker 无关，如果未经修复在 Docker 生产环境中同样会抛出该 SQL 异常；
- 我们已通过修改底层服务将三处 SQL 彻底修正，并在本地直连真实 PostgreSQL 验证通过（`Interfaces: 58, Devices: 14, Outbound: 7`），彻底排除了该隐患。
