# 实施计划：拓扑图缩放与视口高度优化及采集计划菜单下线

## 1. 任务背景与问题分析
1. **拓扑图缩放到 31% 变得极小**：
   - 用户访问 `/monitor/topology` 发现拓扑图被严重缩小（界面显示 31%），设备图标聚集且极小；
   - **根因**：
     - `TopologyPage.tsx` 画布高度使用 `min-h-[500px]`，在外层滚动容器中发生高度塌陷；
     - `TopologyGraph.tsx` 的 `createDefaultTransform` 计算中，`dy` 较大时 `targetHeight / dy` 算出了 0.31 的极低缩放；
     - 计算出来的 31% 缩放被缓存至 local storage 和后端，导致刷新或点击“适应”依然停留在 31%。
2. **`/monitor/collection-plans` 采集计划下线**：
   - 用户提问该页面是否可以废弃；
   - 当前 Prometheus/SNMP-Exporter 内置 20 大厂商模块，CMDB 接口状态已切换为 SNMP-First 原生采集；该页面业务利用率极低；
   - 建议将其从左侧导航栏下线，精简监控导航。

## 2. 拟修改文件
1. `src/pages/TopologyPage.tsx`：为拓扑画布设置充裕的视口高度 `h-[calc(100vh-270px)] min-h-[660px]`；
2. `src/components/TopologyGraph.tsx`：
   - 优化 `createDefaultTransform` 缩放策略：小规模拓扑（<= 16 节点）保底缩放提高至 `0.75 ~ 1.15`，避开顶部工具栏；
   - 增加旧布局缓存防御：当缓存的 `transform.k <= 0.45` 时自动触发重新自适应；
3. `src/components/AppSidebar/navConfig.ts`：下线 `monitoring-plans` 菜单项；
4. 单元测试与构建验证；
5. 对应计划、修复记录与走查文档归档。
