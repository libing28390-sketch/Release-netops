# 仪表盘平台分布统计修复计划

## 任务目标

修复 `/monitor/overview` 平台分布图使用受限设备列表长度作为纳管总数的问题，使环图总量、平台分类和资产总数卡片采用同一统计口径，并避免把总设备数标成在线数。

## 现状与问题

- 资产卡片通过 `/api/assets/summary` 统计 `network_device + server`。
- 平台图依赖 `/api/devices?mode=light` 的前端数组；后端兼容无分页请求最多返回 200 条。
- 环图中心和副标题直接显示 `devices.length`，副标题使用“台在网”，但这组数据没有在线状态过滤。
- `/api/assets/summary` 已返回同口径的 `by_platform`，可以复用，避免新增接口和重复查询。

## 影响范围

- 资产汇总状态解析与缓存。
- 总览平台图的数据转换、图例、总量和无数据/错误状态。
- 不修改后端 SQL、数据库结构、其他报表所用的设备平台数据。

## 拟修改文件

- `src/utils/assetSummary.ts`：解析并校验平台分布数据，确保平台计数合计与资产 KPI 总量一致。
- `src/store/inventoryStore.ts`：缓存、重置并暴露平台计数及其解析错误状态。
- `src/utils/assetSummary.test.ts`：覆盖有效汇总、非法平台值和计数合计不一致。
- `src/store/inventoryStore.test.ts`：覆盖汇总加载及清理平台计数状态。
- `src/components/AppMainContent.tsx`：从统一汇总构造总览图表 view model，并传入 DashboardTab。
- `src/pages/DashboardTab.tsx`：用实体资产总量和平台计数渲染环图，修正文案和无数据状态。
- `docs/walkthrough/walkthrough_20261017_0737_01_仪表盘平台分布统计.md`：记录完成结果和验证状态。

## 实施步骤

1. 扩展资产汇总解析器，验证 `by_platform` 是非负安全整数映射，且计数总和等于网络设备与服务器总数。
2. 将解析后的平台计数纳入现有资产汇总 store 生命周期，随重置和数字型旧 setter 一并清除。
3. 在 AppMainContent 中把平台 key 转成显示名、稳定颜色、计数和百分比；仅为网络设备平台保留设备列表跳转。
4. 在 DashboardTab 中以 `assetsTotal` 作为中心总量、用原始数量绘制饼图、显示精确台数与比例，并展示加载/错误/空态。
5. 检查最终差异和未提交工作树，运行聚焦测试、lint 和隔离目录构建；不触碰无关用户变更。

## 验证计划

- 运行 `npx vitest run src/utils/assetSummary.test.ts src/store/inventoryStore.test.ts`。
- 运行 `npm run lint`。
- 运行 `npx vite build --outDir .codex-build-validation-platform-distribution-20261017`，使用 Vite 的隔离输出参数，避免构建脚本忽略参数并覆盖已有 `dist` 用户改动。
- 检查改动 diff，确认 store 生命周期、摘要口径、展示字段和错误分支一致。

## 风险与回滚思路

- 若后端 `by_platform` 与 `by_type` 总数不一致，图表将显示摘要不可用而不会呈现错误比例；保留总数卡片数据。
- `by_platform` 覆盖网络设备与服务器，可能比旧图多出服务器操作系统平台；这是为了与 221 总量保持相同实体资产范围。
- 回滚时恢复上述前端文件即可；不涉及迁移、生产数据写入或外部设备操作。
