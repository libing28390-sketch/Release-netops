# 终审窗口有效期校验

## 目标

避免实施窗口已结束的变更单仍进入“审批完成”，同时允许审批完成后在已开始且未结束的窗口内立即实施。

## 现状与问题

`scheduled_start`/`scheduled_end` 作为半开实施窗口 `[start, end)`，目前仅在进入实施阶段校验。最终审批不核验窗口是否已结束，因此可能出现审批成功、随后无法开始实施的断路流程。

## 影响范围

- 后端变更单时间窗口校验与终审状态转移。
- PostgreSQL 隔离测试。
- 不改 SLA 策略、账号权限、用户数据或数据库结构。

## 实施步骤

1. 增加可审批窗口校验：窗口必须完整、有效且尚未结束；不要求当前时间晚于开始时间。
2. 最终审批时调用该校验；开始实施仍使用现有完整窗口校验。
3. 增加回归用例覆盖开始时间已过但窗口仍有效、窗口已结束两种情况。
4. 运行变更单授权测试、PostgreSQL-only scanner 和差异检查。

## SLA 边界

此修复只约束变更实施窗口，不新增审批 SLA。审批处理时限需要独立策略（按优先级/风险、工作日历、提醒和升级配置），在组织目标未确认前不写入默认分钟数。

## 执行状态

已完成窗口有效性检查与回归验证。变更单审批 SLA 仍是独立待建设能力，本次不新增未配置的时限承诺。

## 风险与回滚

已过期窗口的终审将返回可识别的 409，需更新实施窗口并重新审批；窗口仍有效或尚未开始时仍可终审。若流程要求允许过期计划审批，可撤销终审前的窗口有效期检查，实施阶段的窗口校验仍保留。
