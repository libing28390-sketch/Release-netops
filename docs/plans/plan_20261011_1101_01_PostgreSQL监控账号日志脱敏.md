# PostgreSQL 监控账号日志脱敏

## 任务目标

修正 Docker 部署过程中 postgres_exporter 初始化/对齐账号时的日志回显，避免把 `ALTER ROLE ... PASSWORD` 明文写入部署日志，并确认初始化顺序是否影响 exporter 启动。

## 现状与问题

- `scripts/deploy-docker.sh` 在 Compose 启动后对 PostgreSQL 执行 `CREATE EXTENSION`、创建或更新 exporter 角色及授权。
- 两条账号 SQL 路径都用 `SELECT format(...)` 配合 psql `\gexec`。`\gexec` 会显示查询结果后执行生成的 SQL，因此日志会包含 exporter 密码。
- `docker/postgres/21-postgres-exporter-role.sh` 是新数据卷初始化路径，也有相同的密码回显风险。
- 后置对齐用于兼容已有持久化数据卷；新数据卷则在 PostgreSQL 初始化时建立角色。当前 Compose 在后置对齐前会启动 exporter/vmagent；若旧数据卷中的密码与 `.env` 已不一致，存在短暂认证失败窗口。

## 影响范围

只涉及 Docker 部署脚本与 PostgreSQL 初始化脚本的成功输出，不改变账号名、密码来源、SQL 权限、幂等行为或部署服务顺序。已有数据卷发生密码轮换时的短暂启动顺序窗口保留并在交付中说明。

## 拟修改文件

- `scripts/deploy-docker.sh`
- `docker/postgres/21-postgres-exporter-role.sh`
- `docs/plans/plan_20261011_1101_01_PostgreSQL监控账号日志脱敏.md`
- `docs/walkthrough/walkthrough_20261011_1101_01_PostgreSQL监控账号日志脱敏.md`

## 实施步骤

1. 隐藏两条 psql 命令的标准输出，并将 `client_min_messages` 设为 `warning`，避免成功命令标签、生成 SQL、重复扩展/授权 NOTICE 被打印。
2. 删除部署脚本中冗余的账号初始化进度日志。
3. 保留 `ON_ERROR_STOP`、`\gexec` 的安全引用方式和失败时的 stderr/非零退出行为。
4. 复核改动范围和差异，记录未执行的部署验证。

## 验证计划

- 检查两处 psql 调用的 stdout 重定向、NOTICE 级别、错误退出设置，以及部署脚本调用顺序。
- 本任务是日志脱敏排查，按当前请求不运行测试或实际 Docker 部署。

## 风险与回滚思路

- 静默后看不到成功 SQL 的逐条命令标签；部署失败仍保留 stderr 错误并应因 `ON_ERROR_STOP` 返回非零状态。
- 回滚时恢复两处 psql 的 stdout 输出和原进度日志即可；无需迁移数据库或重建数据卷。
