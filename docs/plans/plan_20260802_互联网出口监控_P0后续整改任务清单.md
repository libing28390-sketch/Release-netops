## 1. 目标与执行边界

本清单用于把互联网出口监控整改收敛到可验收的 P0，而不是继续扩展 P1/P2 能力。

P0 收口必须满足：

- 出口链路列表、配置、采集、当前状态和趋势页面可正常使用；
- 64 位接口计数器、上下行速率和签约带宽利用率计算可信；
- SNMP 失败、接口 Down、计数器重置和重复采集不会产生误导数据；
- 70%、85%、95% 持续阈值告警支持恢复、迟滞、去重和再次触发；
- 1 小时、6 小时、24 小时、7 天、30 天趋势完整且点数受控；
- 原有服务可用性探测不受影响；
- PostgreSQL、API、权限、前端和浏览器验收均有可复核证据。

本轮不纳入 P0 完成口径：

- PostgreSQL 原生分区；
- 5 分钟、1 小时和日聚合表；
- P95、峰值和高负载持续时间；
- 错包、丢弃专题图表；
- 维护窗口和告警确认；
- 探测目标与链路关联；
- 主备切换识别和容量扩容建议；
- 日报、周报和月报。

上述能力保留在本文 P1/P2 后续清单中。原整改书“26.1 功能验收”包含部分 P1/P2 项目，实施时应分别使用 P0、P1、P2 门禁，禁止再用一个“全部完成”状态混合表达。

## 2. 当前审查基线

### 2.1 阻断级问题

- [ ] `WAN-P0-001` 修复出口链路列表接口汇总异常。
  - 当前问题：`list_wan_links()` 计算 `max_util_pct` 时引用未定义变量 `item`，接口直接返回 500。
  - 影响：链路卡片、总览和页面首屏均无法加载。
  - 完成定义：
    - 空链路、单链路、多链路均返回 200；
    - 最大利用率同时覆盖上传和下载方向；
    - `summary` 与 `items` 数据一致；
    - 增加空数据和多链路 API/服务测试。

- [ ] `WAN-P0-002` 修复告警恢复后无法再次触发的问题。
  - 当前问题：`wan_alert_events.event_key` 全局唯一；已恢复事件保留后，再次触发会发生唯一约束冲突。
  - 影响：采集事务回滚，后续样本和快照可能无法保存。
  - 完成定义：
    - 仅 `status='firing'` 的活动事件保持唯一；
    - 同一规则支持“触发 → 恢复 → 再次触发”形成两个可追溯事件；
    - 重复采集不会重复创建活动事件；
    - PostgreSQL 与 SQLite 测试路径语义一致。

- [ ] `WAN-P0-003` 重构长时间趋势查询。
  - 当前问题：历史查询固定按升序返回前 600 条原始分钟样本，24 小时、7 天和30 天数据被截断。
  - 影响：趋势窗口与页面选择不一致，验收标准第 4 项失败。
  - 完成定义：
    - 1 小时返回完整分钟数据；
    - 6 小时按 1～5 分钟粒度；
    - 24 小时、7 天、30 天使用服务端时间桶或等价降采样；
    - 返回点数控制在 300～600；
    - 第一条和最后一条数据覆盖请求时间范围边界；
    - API 返回实际 `resolution`、`start_time`、`end_time`。

- [ ] `WAN-P0-004` 统一 SNMP 失败、部分失败和接口不存在语义。
  - 当前问题：底层 SNMP 异常可能被吞掉并返回部分接口或空列表，WAN 服务可能误记为 `success` 或 `interface_not_found`。
  - 影响：采集失败被误报为接口 Down，或者错误更新 `last_success_at`。
  - 完成定义：
    - 明确区分 `success`、`partial`、`timeout`、`auth_failed`、`device_unreachable`、`interface_not_found`；
    - 失败采集必须保存失败状态证据，但不得用 0 覆盖上次有效速率；
    - 失败采集不得推进 `last_success_at`；
    - SNMP 失败不得累计接口 Down 连续次数；
    - 连续失败后的恢复行为有测试覆盖。

## 4. 后端与数据整改明细

### 4.1 API 和输入校验

- [ ] 链路列表接口支持 `page`、`page_size`、`site_id`、`provider`、`health_status` 和 `keyword`。
- [ ] `page_size` 设置后端上限，默认 20。
- [ ] 列表只返回卡片需要的摘要字段，趋势和事件按需加载。
- [ ] 增加单链路详情接口，避免列表携带大字段。
- [ ] 增加接口采集测试 API，只测试所选设备/接口，不触发全部链路采集。
- [ ] 后端校验 `site_id` 存在，并校验设备属于所选站点。
- [ ] 后端校验接口属于所选设备。
- [ ] 后端以库存接口的 `if_index` 为准，不接受前端伪造覆盖。
- [ ] 校验 `link_role`、`direction_mode` 和采集间隔枚举/范围。
- [ ] 唯一约束冲突返回 409，不向客户端泄露数据库异常。
- [ ] 手动采集增加并发锁、频率限制和稳定错误码。

### 4.2 SNMP 与计算

- [ ] 采集结果显式记录计数器来源：`ifHCInOctets/ifHCOutOctets` 或 32 位兼容回退。
- [ ] 高速接口缺少 64 位计数器时标记数据质量，不静默当作正常 64 位样本。
- [ ] 同一设备的多条 WAN 链路共享一次 IF-MIB 批量采集结果。
- [ ] 设备级采集与链路级派生计算分离。
- [ ] 使用真实采样时间差计算 bps。
- [ ] 处理计数器重置、32 位回绕、设备重启和 ifIndex 变化。
- [ ] 对小于 10 秒、超出合理范围的采样间隔标记无效。
- [ ] 对超过物理接口速率合理倍数的尖峰标记无效。
- [ ] `direction_mode=reversed` 时交换上传/下载计数器语义。
- [ ] 签约带宽大于物理带宽时给出配置警告，但保留明确业务决策入口。
- [ ] 采集失败样本的 bps 和利用率保存为 `NULL`，不得写成 0。
- [ ] 首轮基线样本不生成速率，不参与高利用率告警。

### 4.3 PostgreSQL 和事务

- [ ] 增加修复迁移，不直接修改已执行的 64 号迁移语义。
- [ ] 将活动事件唯一约束改为 PostgreSQL 部分唯一索引。
- [ ] 为 SQLite 测试路径提供等价的应用层唯一保证。
- [ ] 为 WAN 链路、样本、快照、规则和事件补齐明确外键或等价完整性校验。
- [ ] 定义链路删除策略：P0 暂按级联删除还是软删除，必须形成产品决策并测试。
- [ ] 样本 UPSERT、告警评估和快照更新在同一事务中保持一致。
- [ ] 数据库写入失败时回滚，不产生半条样本或错误快照。
- [ ] 可重试错误与不可重试错误分类，避免无限重试。
- [ ] 重复调度同一分钟样本时不产生重复记录。
- [ ] 常用查询使用 `(link_id, sampled_at DESC)` 索引。

### 4.4 告警生命周期

- [ ] 接口 Down 仅在 `collection_status=success` 且 `oper_status=down` 时计数。
- [ ] `unknown`、`partial` 和 SNMP 失败不等于接口 Down。
- [ ] 接口连续 3 次 Down 触发，连续 2 次 Up 恢复。
- [ ] 70%：持续 10 分钟触发，低于或等于 60% 持续 5 分钟恢复。
- [ ] 85%：持续 5 分钟触发，低于或等于 70% 持续 5 分钟恢复。
- [ ] 95%：持续 2 分钟触发，恢复阈值按最终产品决定统一为 80% 或85%，不得文档和实现不一致。
- [ ] 上传和下载分别计算，事件中记录实际触发方向。
- [ ] 活动事件重复采集只更新 `last_seen_at` 和当前值。
- [ ] 恢复事件写入 `recovered_at`。
- [ ] 已恢复规则再次超阈值时创建新事件。
- [ ] 告警评估失败不得导致原始样本丢失；应定义隔离或补偿策略。

## 5. 前端整改明细

### 5.1 数据层和请求状态

- [ ] 将 WAN 数据请求从大组件中抽到领域 hook/API client。
- [ ] 列表、详情、趋势、事件分别维护 loading、empty、error 和 retry 状态。
- [ ] 趋势请求使用 `AbortController`；切换链路或时间范围时取消旧请求。
- [ ] 只允许最新请求更新页面，避免旧响应覆盖新范围。
- [ ] 403 显示权限不足；401 进入统一登录处理；500 显示可重试错误。
- [ ] 首屏不默认加载全部设备和全部接口。
- [ ] 选择站点后再加载站点设备，选择设备后再加载接口。
- [ ] 列表超过 500 条时使用服务端搜索、筛选和分页。

### 5.2 链路配置

- [ ] 将站点选择放入同一个配置表单/向导，不放在表单卡片外。
- [ ] 配置顺序固定为“站点 → 设备 → 接口 → 运营商/线路 → 带宽 → 角色 → 方向 → 测试”。
- [ ] 切换站点时清空不属于该站点的设备和接口。
- [ ] 切换设备时清空旧接口。
- [ ] 接口显示名称、ifIndex、描述、物理速率和当前状态。
- [ ] 保存前执行采集测试并展示成功、失败、超时和权限错误。
- [ ] 删除操作保留确认提示，并明确是否删除历史样本。
- [ ] 表单支持窄屏布局和键盘操作。

### 5.3 总览、卡片和趋势

- [ ] 综合总览显示链路正常数/总数、当前上传、当前下载、最高利用率和活动告警。
- [ ] 无有效速率时显示“无数据”，不得显示 0 Mbps 伪装成正常低流量。
- [ ] 采集失败状态显示上次成功时间和失败原因。
- [ ] 链路卡片显示站点、运营商、设备、接口、ifIndex、签约上下行和角色。
- [ ] 卡片颜色区分正常、关注、严重、接口 Down、无数据和采集失败。
- [ ] 趋势图支持“流量 Mbps / 利用率 %”切换。
- [ ] 趋势图同时显示签约带宽或100%基准线。
- [ ] Tooltip 显示时间、上传、下载、双向利用率和采集状态。
- [ ] 1h、6h、24h、7d、30d 按后端返回粒度绘制，不在前端截取原始数组。
- [ ] 图表空数据和部分数据状态可区分。

### 5.4 告警事件页

- [ ] “告警事件”页签使用独立事件列表组件和 API。
- [ ] 支持活动/已恢复状态、严重级别、站点、运营商、链路和时间筛选。
- [ ] 默认分页 20，支持 10/20/50/100。
- [ ] 显示触发值、阈值、开始时间、最后出现时间和恢复时间。
- [ ] 点击事件可进入对应链路和时间范围。
- [ ] 大数据量下不一次加载全部事件。

### 5.5 服务可用性回归

- [ ] 原探测目标标签、单目标详情、可用率、平均时延和 P95 保持可用。
- [ ] 原 Ping、DNS、TCP、HTTP/HTTPS 新增、编辑、删除和立即检测保持可用。
- [ ] “新增指标”全部统一为“新增探测目标”。
- [ ] 综合总览中链路失败不应覆盖单目标探测的原始事实。
- [ ] 切换四个页签不重复发起无关的大数据请求。
