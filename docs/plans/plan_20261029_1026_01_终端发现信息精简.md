# 终端发现信息精简

## 目标与现状
用户指出 IPAM“发现终端”入口缺少直观图标、页面信息堆叠，并补充要求保留观察时间与 VRF 名称，且列表只纳入 VLAN 下已分类的业务网段终端。当前列表展示 6 张摘要卡、来源覆盖/最近成功时间、7 个筛选项和 10 列发现/审计字段；数据接口默认混合所有用途网段和 MAC-only/IP 观察。

业务网段沿用利用率页的分类白名单：`server`、`user`/`user_access`、`dmz`、`wireless`、`voice`、`storage`、`container`、`vpn`、`vip`。运行数据检查发现发现账本有 854 条 ARP 观察，但全部 `vrf_context_status=unknown`、`scope_status=scope_pending`；只有 200 条带观测 VLAN，IPAM 前缀均未关联 VLAN，`vlans` 目录为空。原过滤器强制要求显式 VRF 和前缀 VLAN 关联，因此把全部记录都筛掉。

修正规则：终端 IP 必须落入当前租户/站点下唯一最具体的 active 业务前缀；若源记录带 VLAN，则使用该观测 VLAN 作为 VLAN 证据，若 IPAM 前缀已关联 VLAN 还须精确一致。源 VRF 未知时，仅当该 IP 的唯一命中前缀属于全局/默认 VRF 时允许推断并在返回中标识；多 VRF 歧义、无 VLAN 观测、无业务前缀及互联/管理/网络服务/未分类记录仍排除。MAC-only 记录只有在 VLAN 目录和前缀关联可确认其唯一业务 VLAN 时才显示。

## 影响范围
- `backend/services/ipam_network_scope.py`：共享业务网段分类白名单，供利用率与终端发现复用。
- `backend/services/ipam_service.py`：改为引用共享分类，不改变利用率 API 行为。
- `backend/services/ipam_discovery_service.py`、`backend/api/ipam.py`：增加 `network_scope=business_vlan|all`；兼容默认 `all`，只由发现终端页面显式请求业务 VLAN 范围。
- `backend/tests/ipam/test_ipam_discovery_evidence.py`：覆盖业务、互联、管理、未分类、无 VLAN、VLAN 不匹配和 MAC-only 情况。
- `src/pages/IPVlan/ipamDiscoveryPresentation.ts`、`DiscoveredEndpointsTab.tsx`：页面固定请求业务 VLAN 范围；摘要收为 4 项、低频筛选折叠；列表保留时间、VRF 名称及 VLAN。
- `src/pages/IPVlan/ipamDiscoveryPresentation.test.ts`、`DiscoveredEndpointsTab.test.tsx`：验证查询范围、首屏信息和筛选详情行为。
- `src/components/AppSidebar/navConfig.ts`：发现终端菜单使用终端图标。

## 实施步骤
1. 沿发现 API、投影证据、IPAM 前缀/VLAN 关联追踪范围与可用字段。
2. 复用既有业务前缀白名单，在发现服务按租户/站点和最长前缀匹配；显式 VRF 需精确匹配，未知 VRF 只允许唯一命中全局/默认前缀时推断；API 默认全量保持兼容。
3. 页面默认固定请求业务 VLAN 终端，收起低频筛选，缩减不必要的状态/证据字段，同时显示最近观察时间、VRF、VLAN 和终端接入信息。
4. 更新已有测试并运行后端范围回归、前端聚焦测试、lint 和隔离生产构建；浏览器检查受本地自动化策略限制时如实记录。

## 风险与回滚
业务过滤依赖 IPAM 前缀 `network_type`、站点归属、源 VLAN 证据和 VLAN 关联准确度；源 VLAN 缺失、VRF 歧义、未分类或非业务数据仍按用户要求不显示。API 的默认 `all` 保留既有调用方行为。回滚时恢复上述前后端文件即可，不涉及数据库迁移或数据改写。
