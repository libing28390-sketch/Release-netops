# Grafana Auth Proxy 网络动态分配计划

## 目标

避免 Docker Compose 启动时 Grafana 与 Nginx 争用 `grafana_auth` 网络上的同一固定地址；使用 Docker IPAM 动态分配地址，并让 Grafana Auth Proxy 信任该专用子网。

## 现状与问题

- Compose 将 Nginx 固定为 `172.30.254.2`，但 Grafana 在同一专用网络上动态获得地址。
- 实际部署中 Grafana 已取得 `.2`，导致 Nginx 创建失败。
- `grafana_auth` 是 `internal: true` 网络，Grafana 和 Nginx 同时也通过默认网络维持其余服务通信。

## 影响范围

- 修改 Docker Compose 的 Grafana Auth Proxy 白名单和 Nginx 网络地址配置。
- 更新 `.env.example` 与 Docker 部署说明。
- 不修改运行中的服务器、不修改生产 `.env`、不重启或部署服务。

## 拟修改文件

- `docker-compose.yml`
- `nginx/nginx.conf`
- `.env.example`
- `docs/deploy/docker.md`
- 本计划与对应 walkthrough 文档

## 实施步骤

1. 将 Grafana Auth Proxy 白名单改为与内部网络共用的 `GRAFANA_AUTH_PROXY_SUBNET`。
2. 移除 Nginx 在 `grafana_auth` 上的固定 `ipv4_address`，保留其默认网络与专用网络连接。
3. 从示例环境文件移除不再使用的 `GRAFANA_AUTH_PROXY_NGINX_IP`，说明专用网络只应连接 Grafana 与 Nginx。
4. 更新部署文档，描述动态地址、CIDR 信任范围、网络成员限制及旧变量处理。
5. 同步更新 Nginx 配置注释，避免继续描述已移除的单 IP 白名单。
6. 检查 Compose YAML 语法及差异；若本机没有 Docker Compose，记录未能执行的运行时配置校验。

## 验证计划

- 解析 `docker-compose.yml` 与 `.env.example` 的 YAML/环境变量相关配置。
- 检查 Grafana 白名单和网络子网引用同一变量，Nginx 不再声明固定地址。
- 检查变更 diff、部署文档与示例配置的一致性。

## 风险与回滚

- 白名单从单个 Nginx IP 扩大到整个 `grafana_auth` 子网；该网段必须保持专用，只连接 Grafana 和 Nginx。
- 若该信任范围不可接受，可回滚 Compose 配置并改用精确 IP 白名单，同时确保地址不会与 Grafana 动态地址冲突。
- 本次只修改仓库文件；服务器部署需用户将变更同步至部署目录后自行执行 Compose 更新。
