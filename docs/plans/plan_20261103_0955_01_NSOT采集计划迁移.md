# NSOT 采集计划迁移到定时作业

## 目标

下线系统内置的全量 NSOT 每日定时作业。资产 NSOT 页保留人工触发的事实更新；ARP 使用独立分批定时作业，BGP/OSPF 提供独立只读作业类型，供管理员按目标范围和周期显式创建。关闭 B-Loop 的角色默认协议轮询，减少设备侧 SNMP/CLI 请求和无关阶段的数据库读写。

## 现状 / 问题

- `background_monitor_service.py` 中的 B-Loop 约每 60 秒运行一轮；BGP/OSPF 当前仍由角色轮询配置隐式触发。
- `run_unified_nsot_sync()` 是固定的复合采集流程；系统内置每日 NSOT 作业调用它，因而会周期性触发多个 NSOT 阶段。
- `collection_policy_json` 和 NSOT 模板还被路由、拓扑、终端定位、接口及手工查询路径读取，不能只删页面或 API 后即认为移除完成。
- `monitoring_collection_plans` 是独立的监控 OID/硬件计划，不属于本次移除范围。
- 用户要求 `/assets/nsot` 除 ARP 外采用手动触发；BGP/OSPF 单项作业由用户显式创建，不自动添加默认计划。

## 影响范围 / 拟修改模块

- 后端定时作业 API、调度执行器：删除系统内置 NSOT 作业，仅提供独立 ARP sweep、BGP 邻居和 OSPF 邻居作业路径；BGP/OSPF 采集项、目标范围、周期全部进入审批快照。
- `background_monitor_service.py`：移除 B-Loop 对 BGP/OSPF/BFD 的周期轮询；保留可达性等独立监控。
- NSOT 模板/设备策略 API、`NSOTCollectionOperations`、`BulkCollectionPlanModal` 和 IP Locator 的模板编辑入口：从产品路由下线。只保留 `/api/collection-plans/bulk-options` 只读接口，因为监控管理页用它填充站点/角色筛选项；内部策略读取保留给资产 NSOT 手动复合刷新。
- PostgreSQL migration 对内置 NSOT 作业做软删除并创建独立 ARP system job；不删除其他用户作业记录。
- 定时作业 UI 类型与详情页：移除全量 NSOT 作业，增加 BGP/OSPF 单项作业入口。
- 相关后端/前端验证；同步更新 walkthrough。

## 实施步骤

1. 完成所有 `collection_policy_json`、NSOT template 与 NSOT schedule 的读写调用盘点，确认现有系统任务和用户计划作业的行为。
2. 将内置每日作业替换为独立 ARP sweep；设备目标继续使用有界批次和退避。
3. 增加 BGP 邻居与 OSPF 邻居两种只读定时作业；使用 SNMP 优先、CLI 回退，最短周期 5 分钟，并让审批绑定动作和设备范围。
4. BGP/OSPF 告警使用已采集快照更新；关闭 B-Loop 的隐式协议轮询，避免重复采集。
5. 移除全量 NSOT 定时作业创建及其定时预览入口，保留资产 NSOT 页的手动刷新；不删除用户策略数据或独立监控计划表。
6. 对内置 NSOT 作业做软删除；保留运行历史。其他用户作业数据不删除；旧的用户 NSOT 全量作业在下次触发时先停用并跳过设备采集。
7. 审查差异与 migration 行为；不部署到运行环境。

## 验证计划

- BGP / OSPF 只在独立作业所选的目标设备和周期触发；无此作业时不因设备角色自动采集。
- 系统内置 NSOT 作业被软删除；ARP system job 只运行分批 ARP sweep，不调用全量 NSOT pipeline。
- SNMP 成功、SNMP 缺失/失败后的 CLI 回退，以及被禁用类别不运行。
- 作业只选择 BGP 时不启动 ARP、MAC、LLDP、路由、接口或终端定位阶段；目标范围为空时跳过。
- 采集失败或超时不被记作邻居 Down；超过 freshness 阈值标记为过期而非故障。
- migration 保留现有调度作业、审计记录与可恢复的旧计划数据；PostgreSQL-only 扫描通过。

## 风险与回滚

- 移除角色默认采集后，旧环境如果没有 BGP/OSPF 定时作业，将失去邻居状态更新；上线前需展示缺失的作业覆盖，不得悄悄创建高频全量作业。
- 若告警 freshness 和采集节奏不一致，可能把“没采到”误报为 DOWN；必须区分未知、过期和邻居故障。
- BGP/OSPF 作业仍有设备请求与快照写入成本，因此按目标数、最短周期、授权次数和 max_targets 限制。
- 回滚时可恢复 NSOT API/UI 和旧作业路径；迁移只软删除精确匹配的系统内置 NSOT 作业，其他用户作业与设备策略数据保留。
