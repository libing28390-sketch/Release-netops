# 任务目标

让 Docker 首次部署在尚未发布业务采集计划时，SNMP exporter 和 vmagent 也能自动启动并处于可用待命状态，避免用户误以为部署失败；发布真实采集配置后继续通过现有 reload 流程切换配置。

# 现状/问题

- `monitoring/vmagent/scrape.yml` 已提供空目标可运行的默认抓取配置；SNMP exporter 还要求至少一个 auth 定义，因此 bootstrap 需要一个明确不可用且不含真实秘密的占位认证。
- `docker-compose.yml` 的 `snmp-exporter` 启动命令却等待共享卷中的 `current_version.json`，首次部署无该文件时容器持续等待并被健康检查标记为 unhealthy。
- `vmagent` 依赖 `snmp-exporter` healthy，因此停留在 `Created`，用户必须手动发布配置并再次执行 Compose。

# 影响范围

- Docker Compose 监控服务启动依赖与健康状态。
- 不改变采集凭据、编译产物、发布、回滚或 reload 逻辑。
- 既有已发布 artifact 仍从持久化 runtime 路径加载。

# 拟修改文件

- `docker-compose.yml`：移除首次启动对 `current_version.json` 的阻塞等待，让 exporter 直接加载默认/当前 runtime 配置。
- `monitoring/snmp-exporter/snmp.yml`、`scripts/sync-frontend-dist.sh`：提供并迁移无目标 bootstrap auth，兼容已有未发布 runtime 卷且不覆盖已发布 artifact。
- `backend/tests/monitoring/test_monitoring_v1_deployment_contract.py`：增加无阻塞启动契约。
- `docs/deploy/docker.md`：更新首次部署行为和检查说明。
- `docs/fixes/fix_20260918_1006_01_监控服务自动启动.md`：记录变更、验证和回滚方式。

# 实施步骤

1. 修改 exporter 启动命令，直接执行 v0.26 exporter，保持 runtime 配置路径不变。
2. 为默认配置增加不可用的 bootstrap auth，并在旧未发布 runtime 仍为 `auths: {}` 时刷新该文件。
3. 保留后端发布后的 `/-/reload`，确认新配置仍可热加载。
4. 更新部署契约测试和 Docker 文档，明确无设备/无计划时服务是空目标待命而非失败。
5. 运行监控部署契约、编译器相关测试、Compose 静态配置检查和 `git diff --check`。

# 验证计划

- `python scripts/monitoring_poc_preflight.py`

# 风险与回滚思路

- 默认配置不包含 SNMP 凭据且目标文件为空，启动 exporter 不会主动访问设备；风险低。
- 如运行环境的 runtime 配置损坏，exporter 仍会按原路径报告配置错误，便于发现问题。
- 回滚 `docker-compose.yml` 的启动命令即可恢复原等待行为；不删除任何数据卷。
