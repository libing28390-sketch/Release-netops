# 全站表单与列表体验统一实施计划

## 任务目标

参照用户提供的腾讯云表单与资源列表截图，统一 Nexora 同类管理页面的表单、搜索、筛选和表格体验。列表右上角齿轮打开自定义列设置，支持搜索字段、增删展示列并保存；表头筛选使用复选项及“确定/重置”；表格提供一致的行悬停和已选中状态。

## 现状与问题

- `DataTable` 目前是原生 `<table>` 包装器，缺少列定义、筛选、选择行和列偏好能力；已有列设置散落在设备、资产、服务器、告警工作台等页面。
- 全仓约有 46 个 `DataTable` 消费文件，其中包括顶层资源列表，也包括弹窗、详情和历史记录的嵌套表，不能把列表工具栏机械地加到每张表上。
- 列偏好目前保存在浏览器 `localStorage`，没有用户级服务端偏好接口。
- 公共表单控件仅覆盖字段级输入，没有统一的分区、表单主体和固定操作栏骨架。
- 定时作业列表搜索在当前分页结果上过滤，且前端搜索字段与提示文案存在不一致；服务端端点目前没有通用关键字参数。
- 工作区已有用户改动：`dist/index.html`、`AppMainContent.tsx`、`DashboardTab.tsx`、资产汇总 store/utils 及其测试文件；另有大量本地构建目录、计划、走查和日志。实施中不得覆盖或整理这些改动。

## 影响范围

### 公共能力

- 统一 `DataTable` 默认视觉样式和行状态；`unstyled` 表由显式使用方决定是否采用通用样式。
- 新增通用列表搜索/操作栏、表头多选筛选、齿轮列设置和列偏好持久化辅助能力。
- 新增表单分区、对话框骨架、页面骨架和操作栏等布局级组件；字段校验及业务提交仍由调用页面负责。

### 页面接入

- 先覆盖资源管理和运维主列表：网络设备、资产、服务器、告警工作台、定时作业，并核查其他具有列表搜索/筛选/分页的顶层 `DataTable` 页面。
- 为主要长表单复用表单骨架：定时作业、存储配置、资产新增/编辑、设备编辑；向导和整页表单仅复用分区/操作栏，不强行改成模态框。
- 所有 `DataTable` 消费页统一视觉；嵌套明细表、弹窗候选表和纯历史明细表不增加独立搜索/列设置工具栏。

### 业务边界

- 每个页面继续定义自己的字段、导出、权限、校验和编辑行为；定时作业搜索/类别/启停过滤通过现有分页 API 查询完整结果集。
- 不改数据库；仅给定时作业列表 API 增加可选过滤参数，旧请求保持原语义。列偏好按页面命名空间存储在当前浏览器。
- 数据量较大的列表保持现有服务端分页与筛选边界，不将分页结果上的客户端过滤宣传为全量搜索。

- `src/components` 与 `src/components/ui`：新增列表工具栏、筛选菜单、列设置对话框、列偏好 hook/helper 和表单布局 primitives。
- `src/pages/AssetManagement/index.tsx`、`src/pages/InventoryDevicesTab.tsx`、`src/components/DeviceList/DeviceTable.tsx`、`src/pages/InventoryServersTab.tsx`、`src/pages/AlertDeskTab.tsx`、`src/pages/ScheduledJobs/index.tsx`、`src/pages/CmdbAssetManagementTab.tsx`：主要资源列表接入共享能力；实际文件位置以检索为准。
- `backend/api/scheduled_jobs.py`：为现有分页列表端点增加定时作业关键字、类别和启停状态过滤，权限条件保持不变。
- `src/pages/ScheduledJobs/components/JobModal.tsx`、`src/pages/StorageManagementPage.tsx`、`src/pages/AssetManagement/components/AssetModal.tsx`、`src/components/DeviceFormModal.tsx`：接入表单骨架，保留业务状态与交互。
- 根据顶层列表盘点结果，继续接入其他适合的资源列表页面；不触碰嵌套表和无关页面。
- `docs/walkthrough/walkthrough_20261018_1609_01_全站表单列表体验统一.md`：完成后记录实际文件、行为和验证结果。

## 实施步骤

1. 完成页面清单和共享组件边界确认，逐页标记顶层列表与嵌套表，确认现有列偏好/分页/筛选语义。
2. 新增可复用列表搜索操作栏、筛选菜单、列设置 UI 与命名空间偏好 helper；提供受控 props，避免组件接管查询逻辑。
3. 调整全局 DataTable 视觉并提供显式 `data-selected` 样式契约；保留现有表格的密度、主题和导出能力。
4. 将共享列表控件接入主要资源列表；为定时作业分页 API 增加关键字、类别和启停过滤，并让页面以服务端返回的过滤总数分页。
5. 新增表单布局 primitives，迁移主要长表单的标题、分区、滚动主体和操作栏外观。
6. 对照参考截图检查列表工具栏、筛选弹层、列设置弹窗、表格选中状态和表单结构，更新走查文档。

## 风险与回滚思路

- 原生 children 表格没有结构化列模型，因此列设置必须由页面显式提供稳定列 key 与可见性状态，不能仅在 `DataTable` 内推断列。
- 跨多个页面迁移可能影响自定义密度、导出以及响应式布局；每个页面逐步接入，出现异常可撤销该页面的控件接入，同时保留独立的共享组件。
- `localStorage` 偏好按页面隔离，升级时应校验未知 key、重复 key 和不可隐藏列，读取失败回退到页面默认列。
- 表格选择高亮与 hover 必须区分；只有真实选择/详情上下文才使用持久选中态。
- 不更改后端数据或用户配置；出现视觉/状态问题可回退到各页面现有控件和默认列配置。

## 协作边界

- 两个子 Agent 只完成只读表单/列表盘点，没有修改源文件或运行测试。
- 主 Agent 负责公共组件接口、页面迁移、计划/走查文档、验证范围和最终集成。
- 共享组件及其消费者由主 Agent 串行修改，避免接口尚未稳定时产生并行冲突。
