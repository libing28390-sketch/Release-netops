# 发现终端证据分级

## 目标与现状

`/ipam/endpoints` 默认“已映射业务网段”时为空；切换全部观察有 49 条当前 ARP，但只有 32 个不同 IP。34 条观察精确命中当前三层接口地址；其他记录还包括虚拟网关、已管理设备和只有 ARP 的候选。页面目前将原始观察数量放在“发现终端”摘要，缺少可核查的主机证据分级。

## 影响范围与拟修改文件

- `backend/services/ipam_discovery_service.py`：仅使用当前成功代次的 ARP、FDB、接口和正式设备信息，给每条 IP 观察附加基础设施、接入口主机或待核候选判定及依据；保留原始观察与地址空间待确认状态。
- `src/pages/IPVlan/DiscoveredEndpointsTab.tsx` 与 `src/pages/IPVlan/ipamDiscoveryPresentation.ts`：默认显示全部当前 IP 观察，区分观察数与去重后类别数，展示判定依据与筛选。
- 相关聚焦测试：覆盖三层接口、虚拟网关、管理设备、同设备同 VLAN 接入口和证据不足路径。

## 实施步骤

1. 从当前成功接口快照识别设备自身 IP；从正式设备台账识别管理地址；从 VRRP 虚拟 MAC 识别虚拟网关。
2. ARP 与当前 FDB 仅在设备、MAC、VLAN、原始上下文相同且证据近期、完整、路径唯一时关联；明确 access 物理端口才标为“接入口主机候选”。其余保留待核，不自动登记正式 IP。
3. 按租户、站点、明确空间或原始上下文、IP 去重统计；保留原始 ARP 行数，以免 49 条观察被误解为 49 台终端。
4. 调整页面默认视图、列和详情文案，并复核本地实际页面。

## 验证与回滚

运行聚焦后端和前端回归、TypeScript 检查，并在本机页面核对 49 条观察、分类与样例。发现误判时撤回服务层投影和页面展示变更；不修改采集原始行、正式 IP 台账或设备配置。

## 风险

ARP/FDB 可证明当前连接路径，无法单独确认使用人或资产身份；“接入口主机候选”不得显示为已登记资产。未知 VRF 上下文保持待确认；不能为方便展示推断 Global。
