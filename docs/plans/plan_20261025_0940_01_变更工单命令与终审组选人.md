# 变更工单命令与终审组选人

## 目标

- 将手工回退方案改为可逐条添加、删除的回退命令，同时保持现有 `rollback_plan` 字符串接口，以换行分隔命令。
- 统一机器命令区域的名称，删除重复的“命令/下发内容”标签。
- 将变更控制表作为正式提交的必填内容；草稿仍可不完整保存。
- 初审人与终审人都只能由管理员担任，并分别属于初审组/终审组工单职责；无候选人时给出明确说明。
- 在用户管理中单独展示和编辑工单职责，避免把“管理员/普通用户”账号基础角色与初审/终审职责混为一谈。

## 现状与证据

- `ChangeOrderEditor.tsx` 将执行命令作为数组编辑，回退方案仍是单个 textarea；同一区域重复显示“命令/下发内容”。
- 控制表默认折叠并显示“可选”，但后端已有初审提交完整性校验，要求变更时间、实施人、协同审核人、设备 IP、变更前检查、人工实施步骤、变更后验证、业务验证和回退方案。
- `ChangeOrder/index.tsx` 在没有找到终审组成员时回退显示所有符合基本条件的管理员；后端 `_resolve_assignment_user(..., stage='final')` 明确要求目标用户同时是管理员且 `change_groups_json` 包含 `final_approver`。因此 UI 当前可能提供后端必然拒绝的候选人。
- 初审规则目前允许非 Viewer 用户，且初审人候选在初审组为空时回退到所有普通用户；用户明确要求初审/终审只能由管理员承担。
- `UsersTab.tsx` 和 `useUserManagement` 已有 `change_groups` 字段并在保存请求中传递，但用户表单没有职责组控件，用户无法通过页面为 Alice 配置 `final_approver`；列表也只显示账户基础角色和用户所属分组。
- 本机用户管理页已读到 Alice 的基础角色是管理员，但“工单职责”当前未配置，编辑表单的初审组和终审组均未勾选；这与后端拒绝 Alice 作为终审候选的响应一致。
- 用户确认 Alice 是终审用户；截图中的“所属分组”字段与工单职责组 `change_groups` 是不同概念，不能用前者代替终审组成员证据。

## 影响范围

- 前端：变更工单编辑器、变更工单页的提交校验和初/终审候选过滤、用户管理的工单职责配置、相关 helper/tests。
- 后端：变更控制表初审提交校验及针对职责组候选校验的回归测试。
- 计划、walkthrough 与 handoff 交接记录。

## 实施步骤

1. 增加回退命令的换行解析/序列化 helper，编辑时兼容历史多行回退内容，添加和移除单条命令不改变后端字段类型。
2. 将区域标题改为“机器命令”，字段标签改为“待下发命令”；回退命令采用与执行命令相同的逐条录入和移除交互。
3. 控制表默认展开，移除“可选”提示并标注必填；正式提交前在前端验证当前后端要求的人员及文本字段，草稿路径保持可保存。
4. 后端对进入 `initial_review` 的创建、更新和状态迁移始终执行控制表完整性校验；管理员可配置的附件阶段校验保持原行为。
5. 用户管理新增独立“工单职责”配置；初审/终审职责只允许管理员勾选，普通用户改为管理员以外的基础类型时清除初/终审职责。列表显示账户角色和工单职责，保持两个维度清楚分离。
6. 初审人与终审人候选只保留管理员且分别属于对应职责组的成员，移除回退候选；后端在分配、初审处理和终审处理时都强制管理员角色，并保留职责组/指派关系校验。空候选及英文校验错误给出可操作的中文提示。
7. 增加前后端聚焦回归测试，运行相关测试、lint 和隔离构建；使用本机浏览器验证工单表单、用户职责配置、列表导航/分页、弹窗 Escape 及命令添加/删除，不创建或提交真实工单。

## 接口与行为约束

- `commands` 仍为执行命令数组；`rollback_plan` 继续为字符串，多个回退命令以换行连接，模板回退预览仍按现有方式保存。
- 只有提交审核（`initial_review`）要求完整控制表；草稿可保存不完整内容。
- 账号基础角色仍只有管理员和普通用户；初审/终审是独立工单职责，不新增基础角色。非管理员不能获得初审或终审职责。
- 初审候选必须满足 `role == Administrator` 且 `change_groups` 包含 `initial_reviewer`；终审候选必须满足 `role == Administrator` 且 `change_groups` 包含 `final_approver`，并继续排除申请人、当前处理人和实施人。
- 本次不修改 Alice 或其他账号的权限/职责组，不触发真实设备命令、不提交业务工单、不部署。

## 验证计划

- 前端：回退命令序列化/旧值兼容；控制表缺项阻止正式提交但不阻止草稿；初审/终审候选只包含管理员职责组成员，普通用户不能勾选初/终审职责，列表与表单能分别展示基础角色和工单职责。
- 后端：缺少控制表字段时创建/提交被拒；完整控制表可进入初审；普通用户初审/终审均被拒；管理员缺少对应职责组时不能被分配；有效管理员可完成审批。
- `npm run lint`、变更工单 focused frontend tests、对应 PostgreSQL backend tests、隔离 Vite build、`git diff --check`。
- 本机浏览器读取目标页面和交互；不点击“创建工单”或最终“确定”提交动作。

## 风险与回滚

- 现存草稿提交初审时若缺少控制表字段会被拒绝，用户补全后即可提交；历史已提交工单不受影响。
- 历史回退方案按换行呈现为多条命令；原始持久化字符串及读取契约不变。
- 若职责组页面显示 Alice 已在终审组但后端仍拒绝，需以数据库当前 `change_groups_json` 的持久化值为准排查缓存或保存失败；本次不自动授予权限。
- 给 Alice 勾选终审组会新增审批权限；本轮仅验证了未保存的编辑界面，不保存这项权限变更。
