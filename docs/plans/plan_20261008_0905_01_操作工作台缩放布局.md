# 操作工作台缩放布局修复计划

## 任务目标

修复 `/access/workspace` 在浏览器缩放或可视区域变窄时表格列被压缩、状态文字逐字换行及内容错位的问题，让表格在空间不足时横向滚动并保持列内容可读。

## 现状与问题

截图中操作工作台的设备清单列宽异常收缩，站点、状态和操作入口文字被拆行。页面为不同分类的 `DataTable` 指定了 1320–1640px 的最小宽度，但应用级 `.app-shell :where(table:not(.nx-terminal-table))` 规则也为表格设置 `min-width: 640px`；该选择器优先级更高，覆盖了页面的 Tailwind 最小宽度工具类，导致表格在窄视口内被压缩。

## 影响范围

- 只调整操作工作台的四种设备清单表格宽度约束。
- 不改共享表格样式、应用壳、数据/API 契约或其他页面。

## 拟修改文件

- `src/pages/AccessCenterTab.tsx`：为各分类表格显式设置有效的最小宽度，维持现有横向滚动容器。
- `docs/plans/plan_20261008_0905_01_操作工作台缩放布局.md`
- `docs/walkthrough/walkthrough_20261008_0905_01_操作工作台缩放布局.md`

## 实施步骤

1. 核对 `DataTable` 是否把原生 `style` 属性透传到 `<table>`，并确认当前包裹层能承载横向滚动。
2. 给 ALL、SSH、RDP、WEB 表格添加与现有设计一致的原生 `minWidth`，避免被应用级通用规则覆盖。
3. 执行前端类型检查和生产构建；检查变更范围与 Git 状态，保留既有未提交内容。
4. 记录实际改动与验证结果。

## 验证计划

- `npm run lint`
- 使用隔离输出目录执行生产构建，避免覆盖仓库现有构建产物。
- 检查补丁确认只影响操作工作台表格宽度。

## 风险与回滚思路

风险限于窄窗口中表格出现横向滚动，这是维持列内容可读所需行为。若需要回滚，移除操作工作台四处表格的显式 `minWidth` 即可；不涉及数据和持久化状态。
