# 实施计划：清理 Grafana 旧主机大盘

## 任务目标

从部署中的 Grafana 删除废弃大盘 UID `nexora-server-metrics`（`07 服务器与主机监控`），保留当前由仓库生成的 Linux、Windows 和网络大盘；为 Docker 部署增加可重复运行的定向清理入口。

## 现状与证据

- 当前 `monitoring/grafana/dashboards/` 只生成 8 个正式大盘，不再包含旧 UID。
- Grafana provisioning 文件允许删除旧 dashboard，但部署实例仍显示该历史记录。
- 已通过 `li` SSH 登录并 `sudo -i` 取得部署机 root shell；Grafana health endpoint 返回 200。
- 未认证 dashboard API 以及容器配置凭据、用户提供的 Grafana 凭据均返回 401；线上管理员密码与已尝试凭据不一致。
- 部署脚本从容器内部调用本机 Grafana API；手动清理命令在凭据不匹配时会隐藏提示输入当前管理员账号和密码，不把密码写入命令行或日志。

## 影响范围

- Docker 在线安装/升级与离线启动流程，以及一个手动清理命令。
- Grafana 中仅固定 UID `nexora-server-metrics`；不删除或重建任何现有 JSON 大盘。

## 拟修改文件

- `scripts/deploy-docker.sh`
- `docs/deploy/docker.md`
- 对应的 `docs/walkthrough/` 执行记录

## 实施步骤

1. 在 Docker 部署脚本加入等待 Grafana healthy 后，调用 Grafana Dashboard API 删除旧 UID 的幂等函数；将其接入在线安装/升级、离线启动和单独 `prune-legacy-dashboard` 子命令。手动命令遇到容器凭据失效时，隐藏提示输入当前管理员凭据。
2. 明确处理删除成功、记录已不存在、认证失败和其他 HTTP 错误；失败时报告原因，不宣称清理成功。
3. 更新 Docker 部署文档，给出立即清理的命令和成功判据。
4. 检查 diff 与 Bash 语法；不部署、不触碰目标机其它数据。

## 验证计划

- `bash -n scripts/deploy-docker.sh`
- 静态检查清理目标固定为 `nexora-server-metrics`，且现有 dashboard JSON 与数据卷不在删除范围。
- 目标机 SSH 可用，但当前 Grafana 管理凭据不能认证；部署实例的删除结果须使用有效 Grafana 管理员凭据执行清理后，确认 UID API 返回 404。

## 风险与回滚

- 删除动作仅针对 UID `nexora-server-metrics`；重复执行时，HTTP 404 按“已不存在”处理。
- 若 UID 误复用，删除前应核对其标题。若 Grafana API 鉴权或删除失败，脚本应 fail closed，不影响其它大盘。
- 回滚可撤销部署脚本和文档变更；已删除的历史大盘如需恢复，应从旧 JSON/备份重新导入。
