# 实施计划：MIB 全量 ZIP 自动上传与后台异步同步

## 任务目标
解决用户通过前端“上传 MIB / ZIP”按钮上传大型/多厂商/无后缀 MIB 压缩包时报错（400 / 超时 / 无法自动建目录）的问题。实现：用户直接在前端拖拽/选择任意 MIB ZIP 压缩包，系统自动解压、自适应目录层级、在后台异步执行全量符号索引与 OID 入库，前端实时展示进度条并自动刷新。

## 现状与问题分析
1. **目录层级与无后缀支持**：目前 `parse_and_store_zip` 仅根据后缀 `.mib/.my/.txt/.asn` 进行过滤，无法直接识别 LibreNMS 或官方厂商压缩包中的无后缀文件及 `.smi` 文件。
2. **大包同步阻塞与 HTTP 超时**：全量 MIB 包含数千个文件（如 4830 个文件、88.5 万 OID 节点），单次解析耗时约 5 分钟。现有同步上传接口会导致浏览器/代理产生 `ECONNRESET` 或 `504` 超时。
3. **缺少自动解压落盘与任务串联**：现有流程需要用户手动创建 `backend/data/librenms_repo/mibs/`、手动解压并执行 CLI 脚本。用户期望在 Web 页面一键完成上传+自动解压+自动同步。

## 影响范围与模块
- **后端服务与接口**：
  - `backend/api/devices.py`：升级 `/platform-registry/mibs/upload` 接口，支持大包检测与异步后台任务触发。
  - `backend/services/snmp_mib_service.py`：增强 ZIP 解压安全检查、无后缀 MIB 嗅探和多层目录自适应。
  - `backend/scripts/sync_librenms_mibs.py`：提供解压后直接调用或流式解压调用的标准入口。
  - `backend/core/config.py`：调优 `SNMP_MIB_UPLOAD_MAX_BYTES` 默认值（支持 150MB+ 压缩包）。
- **前端页面与组件**：
  - `src/components/SnmpMib/MibUploadModal.tsx`：支持异步上传响应处理、无缝联动现有的 `syncState` 进度轮询与完成后刷新。

## 详细实施方案

### 1. 后端 ZIP 智能解压与层级适配
- 实现 `safe_extract_mib_zip(zip_bytes, target_dir)`：
  - 路径穿越防护（防止 `../` 恶意解压）。
  - 自动识别并去除多余的最外层包装目录（例如 `librenms-master/mibs/` 或 `mibs/` 或直接根目录 `cisco/`、`huawei/` 等）。
  - 过滤系统垃圾文件（`__MACOSX`, `.DS_Store`, `Thumbs.db`）。
  - 支持无后缀 MIB 文件与 `.smi`、`.mib`、`.my`、`.txt`、`.asn`。

### 2. 上传接口分流：小包同步快速入库，大包自动启动后台任务
- 在 `/api/platform-registry/mibs/upload` 中：
  - 检查 ZIP 成员数量与目录结构。
  - 若为**多厂商目录结构 / 大包（文件数 > 30 或体积 > 2MB）**：
    1. 自动解压并更新到 `backend/data/librenms_repo/mibs/`。
    2. 启动 `BackgroundTasks` 执行 `import_mibs_from_directory`（两阶段符号索引与全量解析）。
    3. 更新 `_librenms_sync_state` 状态。
    4. 立即向前端返回 `200/202`，带 `async: true` 标记及初始状态。
  - 若为**单文件或小型增量 ZIP（< 30 个文件）**：
    - 直接在内存中解析并同步返回入库结果。

### 3. 前端交互与进度条联动
- 在 `MibUploadModal.tsx` 中：
  - 当上传接口返回 `async: true` 时，提示 `MIB 压缩包已接收，已自动启动后台全量解析与索引...`。
  - 立即触发 `checkSyncStatus()` 开启每 3 秒进度轮询。
  - 模态框顶部进度栏显示当前解析文件数和节点数；任务完成后自动刷新左侧 MIB 列表和统计。

## 验证计划
1. **单元与集成测试**：
   - 编写针对 ZIP 包含多层目录（`mibs/cisco/`、`huawei/`）及无后缀 MIB 文件的自动解压与解析测试。
   - 测试恶意路径过滤与异常文件处理。
2. **端到端流程验证**：
   - 模拟前端上传包含多厂商目录的 ZIP 压缩包，验证接口快速返回 `async: true`。
   - 验证后台任务自动解压并完成入库，状态接口能正确报告进度并更新数据库。
3. **回归验证**：
   - 运行现有的 MIB 解析与设备管理测试套件，保证旧有单文件上传与内置 MIB 重载功能不受影响。

## 风险与回滚
- **磁盘与内存占用**：解压大包前检查磁盘与解压比，分批提交数据库事务，避免内存飙升。
- **并发同步保护**：若后台同步任务已在运行，提示已有同步任务进行中，避免多任务同时写库冲突。
