# 实施计划：定时作业 UI 流式架构与视觉深度重塑

## 1. 任务目标与背景

彻底解决当前定时作业创建/编辑界面（`JobModal.tsx`）的四大 UI/UX 硬伤：
1. **彻底消除“左长右空”排版失衡**：将原本堆叠在左侧的层级与右侧零散的卡片重构为 **自上而下 3 大核心逻辑区**。
2. **去除套娃 Header**：消除页面外层与内部卡片的双重标题和关闭按钮冲突。
3. **驱动协议精炼内联化**：将脚本执行模式下的资产大类（网络/主机）与协议通道（CLI/SNMP/Shell）改为精致的内联 Segmented Pills，告别笨重的大色块堆积。
4. **范围选择与实时匹配 1:1 左右联动**：将设备范围过滤与实时匹配看板收敛到同一个第三区块内，左侧调节条件，右侧自适应对齐展示匹配设备，杜绝视线来回跳跃。

## 3. 详细实施步骤

1. **Section 1: 基础配置与调度审计区**：
   - 采用 3 列自适应栅格（作业名称、Cron 表达式与快速预设、安全审批授权人与验证码）。
2. **Section 2: 执行动作与驱动协议区**：
   - 顶部提供 4 态 Segmented Tabs（智能巡检、配置备份、NSOT 事实库、脚本执行）。
   - 脚本模式下内联呈现「目标对象（网络/服务器）」+「驱动通道（CLI/SNMP/Shell）」+「联动脚本下拉」。
3. **Section 3: 目标设备范围与实时匹配联动区**：
   - 左右 1:1 布局，左侧为范围选择器（站点下拉/角色下拉/复合选择/标签选择/IP输入），右侧为实时动态匹配看板（在线离线、平台分布、设备列表、兼容性预警）。
4. **验证与质量门禁**：
   - 执行 `npm run lint` (`tsc --noEmit`) 确保 0 报错；
   - 验证各种作业类型（巡检/备份/NSOT/脚本）及各种范围（站点/角色/标签/IP/复合）的完美切换与响应。
