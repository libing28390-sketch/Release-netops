# 采集器列表工具栏

## 任务目标

确认采集器列表“新建”入口是否对应有效功能；如有意义，复用公共列表工具栏，将新建放在最左侧，搜索框缩小并与筛选、导出靠右排列。

## 现状与问题

- 列表当前使用页面私有工具栏，搜索框靠左，“新建”靠右。
- 后端 `POST /api/monitoring/collectors` 会持久化采集器记录；本地采集器记录可关联分配并参与配置编译/发布。
- 远程/边缘采集器目前只登记元数据，尚无自动安装和心跳接入；保留新建有意义，但界面能力边界需如实说明。
- 公共 `ListToolbar` 支持 `leadingAction`；split 样式将搜索和控件放到右侧，并把搜索宽度限制在 320px。`ListSearchInput` 可复用公共搜索样式。

## 影响范围

仅调整监控采集器列表工具栏的布局和公共组件复用；不改采集器数据接口、表单、筛选与导出行为。

## 拟修改文件

- `src/components/MonitoringManagementPage.tsx`
- 本计划和对应 walkthrough

## 实施步骤

1. 复用 `ListToolbar` 的 `leadingAction` 放置“新建”按钮。
2. 将搜索切换为 `ListSearchInput`，搜索、状态筛选、重置和导出留在右侧控件组。
3. 保留现有按钮行为、响应式布局和中英文文案。
4. 运行 TypeScript lint 与隔离 Vite 构建；按已有授权部署到指定机器并检查页面服务与容器健康状态。

## 验证计划

- 代码检查确认使用公共工具栏与公共搜索组件。
- `npm run lint` 和隔离 Vite build。
- 远端 `/monitor/collectors` 页面 HTTP 200，`netops` 与 VictoriaMetrics 健康；部署前后磁盘保护配置值不变。

## 风险与回滚思路

- 主要风险为窄屏下工具栏换行；沿用公共 split 样式和 flex-wrap 行为。
- 若远端页面异常，可恢复部署前 NetOps 镜像标签并重建 `netops`；不修改数据库或 VictoriaMetrics 数据卷。
