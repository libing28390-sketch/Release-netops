# Promptfoo 评估路径与失败诊断实施计划

## 目标

修复 v1.0.9 标签触发的 Promptfoo RAG 质量门禁，使配置能从仓库正确找到 Python provider，并让失败报告准确、安全地归类 Promptfoo 0.118.0 的错误结果，随后重跑相关 Actions 并核对发布仓库同步。

## 现状与问题

- 资产导入使用已保存 SNMP 凭据完成 LibreNMS 纳管的修复已包含在当前 `main` 提交 `786c0eab`，导入、绑定、客户端和纳管专项测试已复跑通过 72 项。
- v1.0.9 的 Promptfoo workflow 显示 50 个案例全部为 `evaluation_error`，约 2 秒内完成；隔离 PostgreSQL corpus bootstrap 与 AI/RAG release config gate 均通过。
- workflow 从仓库根目录加载 `docs/knowledge-engine/eval/promptfoo-rag-gate.yaml`，但 Promptfoo 0.118.0 将 `python:` provider 路径相对 YAML 文件目录解析。现有 `python:scripts/promptfoo_nexora_provider.py` 因而指向不存在的 `docs/knowledge-engine/eval/scripts/...`；真正的脚本位于仓库根目录 `scripts/`。
- 报告脚本把 `failureReason` 优先于 `error`。Promptfoo 0.118.0 的 `failureReason` 是数值枚举，数字 `2` 会遮住可安全分类的错误文本，导致报告退化为泛化类别。

## 影响范围与拟修改文件

- `docs/knowledge-engine/eval/promptfoo-rag-gate.yaml`：修正相对 provider 路径。
- `scripts/promptfoo_gate_report.py`：优先读取字符串错误，并单独映射数值失败枚举。
- `backend/tests/ai/test_promptfoo_gate_report.py`：覆盖 YAML provider 路径可解析性、Promptfoo 0.118.0 数值枚举与错误文本并存时的安全分类。
- `docs/fixes/fix_20261008_0256_01_Promptfoo评估路径与失败诊断.md`：记录本次缺陷、修复和回滚方式。
- `docs/walkthrough/walkthrough_20261008_0256_01_Promptfoo评估路径与失败诊断.md`：测试和 Actions 完成后填写。

## 实施步骤

1. 更新 Promptfoo provider ID 为相对评估 YAML 可解析到仓库根 `scripts/` 的路径。
2. 调整脱敏报告字段提取，忽略未知数值枚举作为错误正文；对 Promptfoo 0.118.0 已知的 ASSERT/ERROR 枚举给出稳定、安全的类别，并优先对实际字符串 `error` 做分类。
3. 添加回归测试，确保 provider 文件存在且错误正文不会进入持久报告。
4. 运行聚焦 pytest、Promptfoo 50 条完整评估和现有 RAG 配置检查；修复任何与本变更相关的失败。
5. 更新 walkthrough 与 fix 记录，提交到 `main`，按用户已授权的发布要求推送提交并将 `v1.0.9` 指向该提交；核验 GitHub Actions 与 Release-netops 镜像仓库。

## 验证计划

- `.venv\Scripts\python.exe scripts/knowledge_eval_ci_gate_check.py`
- Promptfoo 0.118.0 先执行 workflow 定义的 10 条安全用例 smoke，再执行完整 50 条；都使用隔离 PostgreSQL corpus 和 `AI_GATEWAY_MODE=mock` 配置。
- `git diff --check`，并在提交后查看提交图、tag 指向、main 与公共 Release-netops 的同步以及 Actions 最终结论。

## 风险与回滚

- provider 路径若仍按不同基目录解析，评估会在启动前失败；回归测试和实际 Promptfoo smoke 将验证路径。
- 失败报告只保留错误类别与异常类型，不写入 provider 错误正文、prompt、答案或密钥。
- 回滚时只需回退本计划涉及的 YAML、报告脚本、回归测试和配套文档提交。重新发布前应同步恢复 `main` 和 `v1.0.9` 指向；已更新的公共发布制品需按 release workflow 重建。
