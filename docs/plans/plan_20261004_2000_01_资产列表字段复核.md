# 网络设备列表字段精简与机柜名称计划

## 目标与完成状态
调整 `/assets/network-devices` 默认列，让常见桌面宽度优先显示日常巡检需要的信息；低频诊断字段继续可选；列偏好刷新后保留；机柜列和导出使用机柜名称。实现已完成，聚焦验证通过。

## 现状与根因
网络设备字段原先全部默认开启，表格使用 `min-w-[2200px]`，截图中必须横向拖动。平台适配与版本诊断、重复状态和设备检测元数据挤占空间。列偏好没有持久化。设备 API 的 full/light 查询均已提供 `rack_name`；问题在于 UI/export 优先显示 `rack_code` 或旧 `rack` 字段。

## 实施范围
- `src/components/DeviceList/DeviceTable.tsx`、`deviceColumns.ts`：精简默认列、全宽表格、校验和保存列偏好、机柜名显示。
- `src/pages/InventoryDevicesTab.tsx`：列设置和恢复默认交互；稳定列表查询的分页/过滤反馈。
- `src/components/DeviceList/deviceExport.ts`：导出使用与列表相同的机柜名称字段。
- 相关 DeviceTable、列偏好、导出和 inventoryStore 测试。
- 本计划和对应 walkthrough。

没有修改 `src/types.ts`、后端/API、数据库 schema 或机柜关联数据：已有 `Device.rack_name` 类型和响应字段已满足需求。

## 关键行为
1. 设备名称、资产编号、管理 IP、类别、角色、厂商、型号、站点、机柜、U 位、在线状态、健康状态和操作列默认显示。
2. 连接方式、平台、版本、适配来源/版本/类型、版本差异、标签、生命周期、最近检查信息、CPU 和内存默认隐藏，仍可从列菜单开启。
3. 列偏好写入版本化 localStorage；损坏数据和未知键安全回退；操作列常驻，且不能关闭最后一个业务字段；菜单可恢复默认。
4. UI 和导出仅显示 `rack_name`，名称缺失时显示 `—`；不把机柜代码、旧字段或内部 ID 冒充名称。
5. 移除 2200px 强制最小宽度，保留窄视口下的表格滚动能力。
6. 网络设备列表用请求序号阻止过期查询写回，并在最新请求失败时清空旧列表、显示错误；本地 quick/lifecycle/tag 筛选每次重置到第一页，分页总数保留服务端设备总数，使后续服务端页面仍可翻到。筛选仍在当前已加载页面内计算，未提供服务端筛选总数，可能出现没有命中项的页面。

- 使用 Vite 生产构建验证前端打包。

- 没有浏览器页面的运行时烟测；组件测试验证了默认列、表格全宽类、行点击与机柜名称。构建产物不纳入交付。

## 风险及边界
核心默认列较此前减少，但窄窗口仍可能需要横向滚动。用户开启更多可选字段后也可能横向滚动。没有机柜名称时使用空占位符，因此机柜数据若仅有代码不会在此列显示。quick/lifecycle/tag 条件仍然只过滤当前 API 页，UI 的分页总数为服务端总数而非过滤后的匹配数。

`/assets/dashboard`（CMDB 资产目录）的跨页严重级别筛选、旧请求覆盖和请求失败时旧结果残留，是先前只读复核记录的问题，本次明确实施范围为 `/assets/network-devices`，未改动资产目录。工作区既有 WAN/SNMP 与历史生成目录保持原样；未提交、推送、部署或访问真实设备。
