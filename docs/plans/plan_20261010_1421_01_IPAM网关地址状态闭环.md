# IPAM 网关地址状态闭环计划

## 任务目标

让前缀配置的网关地址在 IPAM 前缀统计、地址列表和地址矩阵中保持一致：网关有明确标识、不会被显示为空闲，且不被误计为手工登记或自动发现记录。

## 现状与问题

- 前缀的 `gateway` 字段是网关配置的权威值。当前矩阵把没有 IPAM 地址记录的网关显示为灰色“系统保留”，没有表达“正在使用的网关”状态。
- `/api/ipam/addresses` 只合并手工 IP 记录和活跃发现端点，没有为已配置但未登记的前缀网关生成展示条目。
- 前缀 `used_ips` 和利用率只统计 `ip_addresses` 表，因此未登记网关既不显示为占用，也不计入使用量。
- 矩阵按整个 CIDR 展示，但地址库存 API 每页最多返回 100 条；前端只读取一页，超过 100 条时可能漏掉已登记/发现地址。

## 影响范围

- 不增加数据库迁移、不自动写入 IPAM 地址表；从前缀配置派生只读网关展示项，并通过显式来源字段与真实记录区分。
- 网关配置与 IP 生命周期状态分开：矩阵呈现网关占用和标识，真实记录的其他状态与来源信息仍保留。
- 更新前缀统计、地址库存响应和前端网格，保持列表记录数、人工登记数、发现数与派生网关数语义清楚。
- 矩阵按服务端分页元数据完整读取选中前缀的数据；常规列表分页行为保持不变。

## 实施步骤

1. 统一校验和派生前缀网关地址；将未登记网关以 `is_prefix_gateway`、`is_virtual_gateway` 等显式字段加入 IPAM 库存与前缀地址列表，并为已存在的对应记录追加网关标记，避免重复地址。
2. 在前缀使用量、利用率和树形统计中把未重复计入的有效网关加入占用数；维持手工记录和自动发现统计的原有含义。
3. 将矩阵中的网关渲染为已使用状态并显示 `GW` 标识；将只读派生行标明为前缀配置，避免出现会调用地址变更 API 的操作按钮。
4. 矩阵进入/切换前缀时重置页码，并按 API 的 `total` / `has_more` 完整读取全部数据页；中止过期请求，失败时明确提示并支持重试。
5. 运行后端编译、前端 lint/生产构建、PostgreSQL SQL 约束检查及差异检查；在已有本地页面条件允许时复核网关标记。

## 风险与回滚

- 派生网关条目不是 `ip_addresses` 数据行；前端必须通过显式虚拟来源字段禁用编辑/释放操作，后端统计也不能把它冒充为实际 IPAM 记录。
- 相同地址可能属于不同 VRF/租户或父子前缀，派生与去重必须限制在对应的前缀身份和作用域内。
- 没有数据库迁移或数据回填；回滚可移除库存派生逻辑、统计调整和前端展示标记，不需要恢复数据。
