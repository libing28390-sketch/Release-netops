# IPAM 分类冲突与统计卡片

## 目标

解释并修正 IPAM 前缀页的跨站点冲突判定、冲突数量口径和顶部分类卡片无响应问题。

## 现状与根因

- IPAM 的人工创建/更新校验以 tenant + VRF + site 为前缀唯一范围；`prefix_discovery_service._upsert_candidate` 却把同租户、同 CIDR 的跨站点记录标成冲突，且不会清除旧标记。当前只读核对有 12 条历史 `cross_site_prefix` 标记，但 12/12 已找不到另一站点的当前同 CIDR 对端；当前跨站点重复组为 0。截图中的条目是 Loopback `/32`，掩码本身不是触发条件。
- 分类汇总接口返回全局统计，未接受页面站点、状态、地址族和搜索筛选条件。
- 前端分类卡片是静态 `div`，没有点击处理函数；冲突数量口径/范围也未说明。

## 范围与接口

- 后端：跨站点相同 CIDR 作为动态 `cross_site_reuse` 信息，不再作为真实冲突；旧 `cross_site_prefix` 标记只在读取时映射，不直接修改现场数据库。列表支持 `conflict`/`reuse` 分类筛选；分类汇总支持当前 `site/status/family/q` 范围。
- 前端：分类卡片改为可访问的按钮；点击后切换分类筛选，列表范围、计数和导出保持一致；显示当前分类筛选状态及清除操作；将“冲突”与“跨站点复用”分开展示，并解释两种计数口径。
- 不修改监控、设备解析模板或无关 IPAM 页面。

## 分工边界

- 后端 Agent：独占 `backend/services/prefix_discovery_service.py`、`backend/services/ipam_service.py`、`backend/api/ipam.py` 与相应后端测试。
- 前端 Agent：独占 `src/pages/IPVlan/PrefixManagementTab.tsx` 与对应前端测试。
- 主 Agent：维护本计划/走查文档、协调接口契约、集成审查和验证。

## 实施与验证

1. 将当前跨站点相同 CIDR 动态展示为地址空间复用；对已失效的历史 `cross_site_prefix` 标记只在 API 投影中清除，不改现场数据库。
2. 为列表及汇总接口添加一致的分类筛选与当前页面筛选范围。
3. 连接统计卡片与列表筛选，确保键盘访问、筛选回显及导出一致。
4. 运行冲突规则/筛选范围的 PostgreSQL 隔离测试、前端交互测试、TypeScript 检查及 Vite 构建；在 `/ipam/prefixes` 核对卡片交互和结果。

## 风险与回滚

- site 是 IPAM 地址空间唯一范围；跨站点相同 CIDR 显示为复用信息，不删除、合并或改写真实前缀数据。
- 若列表或汇总出现范围不一致，可回滚本次前后端过滤参数与冲突计算改动；不对真实前缀执行删除或自动合并。
