# 资产修改冲突提示与校验优化实施计划

为了解决在资产管理页面编辑或新增设备时，若U位被占用未能直接在弹窗内进行显式拦截提示的问题，我们将升级前端资产编辑弹窗的错误处理机制，使所有的U位空间冲突校验错误（HTTP 400）能够直接在弹窗内的红框区域显式呈现，以便用户及时修改，防止静默失败或在机柜图上无端消失。

## 用户审查要求

> [!IMPORTANT]
> 1. 本实施计划遵循工作区归档与中文命名规范，保存在 `docs/plans/` 目录下。
> 2. **弹窗内联错误拦截提示**：当前端资产编辑发送 `PUT /api/assets/{id}` 或 `POST /api/assets` 时，若后端返回 `400`（如 U-position conflict）错误，前端将不再作为外部通知提示，而是将其捕捉并设为 `modalError` 状态。
> 3. **强校验防护**：确保弹窗在校验未通过时保持打开状态，方便管理员即时修正起始U位或高度，且后端事务在校验失败时自动回滚，确保 `physical_assets` 和 `rack_devices` 中的状态完全一致。

## 拟作出的变更

### 1. 资产保存错误捕获机制重构

#### [修改] [index.tsx](file:///e:/data/netsops/src/pages/AssetManagement/index.tsx)
* 在保存保存函数 `doSave`（lines 317-324）中，重构 HTTP 响应状态码的处理：
  * 将 `r.status === 400` 的场景与 `r.status === 422` 合并处理。
  * 当接口返回 `400` 时，关闭确认状态，并将具体的后端错误描述（`err?.detail`）填入 `modalError` 状态，由 `AssetModal.tsx` 在弹窗正下方以红色横条进行提示。
