# 知识引擎 V2 影子运行与灰度切换实施计划 (MIG-010 ~ MIG-013 & ING-020/021)

## 1. 任务目标
推进 Knowledge Engine V2 开发清单（`docs/knowledge-engine/16-development-master-checklist.md`）中的未完成核心任务，聚焦于 **M5 影子运行与灰度切换** 阶段：
1. **核对与收敛已完成项**：确认 `ING-020`（导入任务列表UI）与 `ING-021`（导入前Metadata预览确认）在清单中的验证状态；
2. **`MIG-010` 影子检索观测与差异记录**：核对并固化 `RAGRetriever._shadow_compare` 与 `retrieval_trace_store` 中的双检索观测、延迟比对、候选与 Chunk 差异脱敏记录；
3. **`MIG-011` / `MIG-012` / `MIG-013` V2 功能开关与灰度控制**：
   - 后端实现 `KNOWLEDGE_V2_ENABLED`、`KNOWLEDGE_V2_TARGET_ROLES`、`KNOWLEDGE_V2_ROLLOUT_PERCENT`、`KNOWLEDGE_V2_ENABLED_SITES` 多层灰度控制机制；
   - 保证管理员与内测用户可选择开启 V2，并支持零停机热切换切回 V1（`MIG-013`）；
   - 在 Copilot 与 Assistant 检索路由中无缝消费灰度策略；
   - 前端支持管理员感知和切换 V2 检索状态；
4. **测试框架与 pytest 环境修复**：修正 `pytest.ini` 中 pythonpath，确保全量自动化测试套件可顺利运行。

## 4. 实施步骤

### 阶段一：测试环境与 pytest 配置修复
1. 修改 `pytest.ini`，配置 `pythonpath = backend .`，消除测试导入路径差异。
2. 运行所有现有 `test_mig*.py` 与 `test_captcha_and_login_failures.py`，确认测试发现恢复正常。

### 阶段二：`MIG-011` / `MIG-012` / `MIG-013` 灰度与热切换引擎
1. 在 `backend/core/config.py` 中扩充 V2 灰度控制参数：
   - `KNOWLEDGE_V2_ENABLED: bool = False` (全局开关)
   - `KNOWLEDGE_V2_FORCE_ROLES: list[str] = ["admin"]` (管理员/内测角色直接放行)
   - `KNOWLEDGE_V2_PILOT_USERS: list[str] = []` (指定内测用户名)
   - `KNOWLEDGE_V2_ENABLED_SITES: list[str] = []` (指定试点站点)
   - `KNOWLEDGE_V2_ROLLOUT_PERCENT: int = 0` (0~100 比例灰度)
2. 编写 `backend/ai/services/feature_flag_service.py`：
   - 提供 `should_use_knowledge_v2(user_context: dict) -> bool` 方法，支持按 Role -> Pilot User -> Site -> Hash(user_id) % 100 <= RolloutPercent 判定；
   - 支持动态在会话级或请求级覆盖（当管理员显式切换时）；
   - 保证当全局关闭或出现异常时毫秒级静默降级到 V1。
3. 接入 `rag_retriever.py` 与 `assistant.py`：
   - 依据 `feature_flag_service` 判定为主选 V2 还是 V1；
   - 当主选 V1 且开启 `KNOWLEDGE_V2_SHADOW_READ=True` 时执行 `MIG-010` 影子对比并上报 trace。

### 阶段三：自动化测试与验证
1. 编写 `test_mig011_feature_flag_rollout.py`，覆盖：
   - 全局禁用时一律走 V1；
   - 管理员与白名单用户走 V2；
   - 指定试点 Site 走 V2；
   - 灰度百分比区间哈希命中验证；
   - 运行时配置热切换（无需重启与 DB 回退即可生效）；
2. 运行前端 `npm run lint` 与 `npm run test:frontend`。

### 阶段四：清单更新与文档归档
1. 同步更新 `16-development-master-checklist.md`，记录 `MIG-010`、`MIG-011`、`MIG-012`、`MIG-013` 等项进度。
2. 生成对应的 `docs/walkthrough/walkthrough_20260820_1739_01_知识引擎V2影子运行与灰度切换.md`。

## 6. 风险与回滚思路
- **风险**：灰度服务对未认证/匿名请求的判定异常。
- **应对**：`feature_flag_service` 内部使用严格的安全兜底机制，所有缺失字段或异常均默认返回 `False`（保持 V1），并记录审计日志。
- **回滚**：如发生异常，只需在环境变量或配置中设置 `KNOWLEDGE_V2_ENABLED=False`，系统立即 100% 走 V1。
