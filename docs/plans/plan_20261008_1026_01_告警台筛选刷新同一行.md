# 告警台筛选刷新同一行

## 任务目标

统一调整告警管理下当前告警、告警规则、历史告警和维护窗口列表的工具栏，将搜索与过滤控件排在同一行；手动刷新改为带无障碍名称与提示的小图标按钮。四个列表表格在浏览器缩放时保持内容单行，并在列宽超出可视区域时横向滚动。告警台默认减少展示列，非核心列可由用户勾选恢复；四页搜索框和历史告警的时间范围输入统一控制宽度，避免占满工具栏。

## 现状与问题

告警管理的各列表页把搜索和过滤控件分散到多行，手动刷新按钮放在页面标题区并带文字；规则页还把类别筛选单独放在一行，和资产列表工具栏交互不一致。历史告警表在缩放时列宽被挤压，标题、告警信息、站点等文字换行；其他告警列表也需要统一避免列内容被压缩换行。告警台原本默认展示 13 个业务字段，快速处置时横向浏览负担较大；搜索框使用 flex-1 后又占据大部分工具栏空间。

## 影响范围

- 当前告警、告警规则、历史告警和维护窗口列表的筛选与刷新工具栏。
- 四个列表表格的列宽、单行文本与横向滚动行为。
- 四页统一搜索框宽度。
- 历史告警时间范围输入宽度。
- 告警台默认显示列、自定义列菜单、用户偏好持久化和导出列。
- 不改变自动刷新开关、告警查询、筛选条件、状态计数、批量操作和新建操作逻辑；历史告警的高级时间范围仍按需展开。

## 实施步骤

1. 将每个告警列表的搜索和过滤控件组合到一行；当前告警状态标签、规则类别标签也纳入各自筛选行。
2. 将各页手动刷新按钮移入对应筛选行，使用共享图标按钮样式并保留加载旋转状态、可访问标签和悬停提示。
3. 保留自动刷新开关、规则/维护窗口新建操作和历史告警按需展开的时间范围筛选。
4. 四个表格统一按内容宽度布局并禁止单元格文字换行；空间不足时由表格区域横向滚动。对历史告警标题和长消息使用截断展示并保留悬停全文。
5. 告警台默认展示标题、信息、主机、IP、级别、状态、责任人、发生时间和持续时间；指标、次数、接口、站点可在列设置中选择。选择保存到本地，并让导出列与当前可见列一致。
6. 将四页搜索框宽度统一限制在 240–360px，将历史告警起止时间输入限制在 200–240px；展开后的面板按控件宽度收拢，日期输入、快捷范围保持同一行，窄屏时在面板内横向滚动。

## 验证计划

- 运行 `npm run lint` 与 `npm run build`。
- 运行告警列偏好、告警导出相关测试并执行 `git diff --check`。
- 检查四个告警列表在常见桌面宽度和浏览器缩放时保持单行；窄屏可横向滚动且不挤压控件。

## 风险与回滚思路

主要风险是窄视口中工具栏或表格宽度不足；通过各自的横向滚动保留控件与列内容。历史告警和告警台的长标题及信息以省略号显示，鼠标悬停查看全文。告警台偏好损坏或缺失时恢复精简默认列。
