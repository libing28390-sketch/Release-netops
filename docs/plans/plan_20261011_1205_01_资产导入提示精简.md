# 资产导入提示精简

## 任务目标

精简资产导入成功后的页面提示，并降低导入校验/提交等待：不再逐条展示 SNMP 身份识别、LibreNMS 纳管和本地 SNMP 采集信息；保留新增/跳过数量及真正的跳过原因；复用 SNMP 身份识别已读取的 sysName，避免为新资产重复发起 hostname GET；将机柜存在性检查从逐行扫描列表改为一次建索引。

## 现状与问题

`AssetManagement` 的导入反馈把 SNMP hostname 同步、身份识别、LibreNMS 纳管、本地采集和逐行结果全部拼进同一条成功提示。正常成功导入时会占据很大屏幕空间，用户不需要在导入反馈中查看这些后台工作细节。导入路径还会为新设备分别执行 hostname `sysName.0` 读取和包含相同 OID 的三字段身份探测；机柜预检则对每条导入行遍历全部已加载机柜。

## 影响范围

- 调整资产管理页导入反馈和机柜预检查找方式。
- 新资产 hostname 同步复用 SNMP 身份识别得到的 `sysName.0`；重复导入仍走既有 hostname 探测路径。
- 不改变在线状态判定、SNMP/LibreNMS识别规则或导入响应结构；`hostname_sync` 汇总将包含身份探测阶段复用 sysName 的结果。

## 拟修改文件

- `src/pages/AssetManagement/index.tsx`
- `backend/api/assets.py`
- `backend/services/snmp_import_identification_service.py`
- `backend/tests/configuration/test_asset_management_method_import.py`（更新 SNMPv3 导入结果的既有预期）
- 本计划及对应 walkthrough。

## 实施步骤

1. 成功提示只保留新增和跳过数量；详情仅保留实际未导入的跳过行。
2. 不在导入反馈展示 SNMP、LibreNMS 或本地采集状态。
3. 新导入设备的身份探测复用读到的 sysName 完成 hostname/asset/topology 写回，避免额外网络 GET；重复资产路径保持现有行为。
4. 将机柜预检改为预建索引，保持现有站点别名匹配语义。
5. 人工检查前后端失败路径、中英文文案、类型和数据响应契约。

## 验证计划

- 人工审查成功、跳过及失败分支的提示拼装和既有反馈渲染。
- 人工审查新设备身份识别与 hostname 同步共享 sysName 的调用链，并核对身份未识别时 hostname 仍会写回。
- 人工比较机柜预检索引的匹配语义与旧线性扫描。
- 更新既有 SNMPv3 无响应场景的汇总预期；不新增测试场景。
- 不运行测试或构建：当前执行指令限制在未获用户明确要求时不运行测试；本次通过源码调用链和 diff 做静态审查。

## 风险与回滚思路

- 机柜查找仍以机柜记录中的站点 ID、编码、名称和数据中心别名做完全匹配。
- 身份探测无法读取有效 sysName 或 CMDB 写回失败时，仍保留导入时填写的名称并计入 hostname 同步失败；SNMPv3 Context Name、SHA-2 与 AES-128 继续沿用 SNMP 服务支持的配置。
- 如需回滚提示可恢复 `AssetManagement/index.tsx`；如需回滚合并探测，可恢复 `backend/api/assets.py` 与 `backend/services/snmp_import_identification_service.py`，不会涉及数据库迁移。
