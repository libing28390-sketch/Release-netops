# Grafana 接口描述与 S3 内部代理排查实施计划

## 任务目标

修正 Grafana 中“接口全称/接口描述”的数据来源与展示，恢复接口仪表板查询；排查对象存储检查返回 HTTP 502 的部署路径问题。

## 现状与根因

- 设备 CLI `interface ... / description ...` 对应 IF-MIB `ifAlias`（OID `.1.3.6.1.2.1.31.1.1.1.18`），而非 `ifDescr`。`ifName` 继续用于“接口全称”。
- 用户在部署服务器运行的 SNMP walk 已确认 `ifAlias` 返回人工配置的描述，例如 `TO-F1090_9`、`TO-S6850_3`、`TO-S6850_4`、`TO-S6850-2`、`ROUTER-ID`、`FIREWALL-INSIDE`；端口默认文本（例如 `GigabitEthernet1/0/3 Interface`）也会原样出现。指标尾部数字是 `ifIndex`，可与同索引 `ifName` 对照。
- 线上 Grafana 04 的 panel 10 实际 PromQL 仍直接请求 `ifDescr{...}`，但运行时没有独立 `ifDescr` 时序；`ifDescr` 是部分指标的查找标签。因此 panel 10 与复用同一 helper 的接口面板没有数据。线上 Explore 对 `ifHCInOctets{job="network_snmp"}` 返回 475 条时序；对 `F1090-9` 的接口状态 join 返回 27 条，说明采集时序存在，空结果来自 dashboard 的 `ifDescr{}` 查询。
- `ifAlias` 是单独导出的 DisplayString 指标，包含 `ifIndex` 和 `ifAlias` 标签，但不包含 `ifName`。接口筛选需通过 `ifName` 指标生成选中端口集合，再按 `(instance, ifIndex)` join `ifAlias`；`ifAlias` 右侧 selector 不能带 `ifName=~...`。
- 存储设置页默认 `Environment` profile 指向 `http://seaweedfs:8333` 和 bucket `nexora`，测试返回 502。SeaweedFS 日志显示服务启动，但不能证明后端容器绕过代理直连成功。`netops` Compose 服务继承 `.env`，原先未为 SeaweedFS 服务名设置代理绕过。
- 非默认 `test` profile 另有 `http://seaweedfs:8333/conf` endpoint；它与默认 `Environment` profile 分开，本次不修改线上 profile 或凭据。

## 影响范围

仅修改 Grafana 共用接口 join helper、设备/接口/出向 dashboard 工件与相关契约测试，以及 Docker Compose 后端代理绕过设置和部署文档；不改采集器字段语义、SNMP 设备配置、S3 凭据或线上 profile。

## 实施步骤

1. 将 Grafana“接口描述”从 `ifDescr` 切换到 `ifAlias`，以 `(instance, ifIndex)` 把别名标签关联到接口行；04 和出向仪表板按设备过滤 `ifAlias`、按接口名过滤 `ifName`。
2. 更新接口表格列映射：`ifName` 显示“接口全称”，`ifAlias` 显示“接口描述”，并隐藏无关的 `ifDescr` 列。
3. 重新生成受共享 helper 影响的设备详情、接口详情和出向监控三个 JSON 工件。
4. 加入 Grafana 查询及列映射契约断言，避免重新引入不存在的 `ifDescr{...}` 时序，并确认 `ifAlias` 查询 selector 不要求 `ifName` 标签。
5. 给 `netops` 容器追加大小写两种 `NO_PROXY`/`no_proxy` 中的 SeaweedFS 内网服务名，保留现有代理配置以支持外部 S3 兼容 endpoint；更新部署文档和契约测试。
6. 运行相关监控测试及 Compose YAML、Grafana JSON 生成器一致性检查；在有部署容器 shell 的环境下比较默认代理路径与直连路径。

## 验证计划

- `pytest backend/tests/monitoring/test_domestic_and_wireless_monitoring.py backend/tests/monitoring/test_monitoring_v1_deployment_contract.py`
- 检查受影响 dashboard 查询均以 `ifAlias` join 别名，且没有引用 `ifDescr{...}`；确认生成后的 8 份 JSON 与 generator 一致。
- 使用 Python + PyYAML 解析 `docker-compose.yml`，检查 `netops.environment` 的两种 `NO_PROXY` 都包含 `seaweedfs` 和 `nexora-seaweedfs`。
- Grafana live evidence: panel 10 查询使用独立 `ifDescr{...}`，导致 04 面板为空；原始 `ifHCInOctets` 返回 475 条时序，F1090-9 join 返 27 条；用户服务器 SNMP walk 的 `ifAlias` 行返回配置描述。
- Docker CLI 当前不可用，无法本机执行 `docker compose config --quiet` 或进入部署容器验证代理；修改尚未部署。

## 风险与回滚

- 有些设备的 `ifAlias` 为空，或者返回厂商默认文本；表格将展示设备通过 IF-MIB 上报的原始值。回滚时恢复接口描述列到 `ifDescr` 并重新生成三个 dashboard JSON。
- Compose 仅为 Docker 内部 SeaweedFS 名称增加代理绕过；外部 S3 endpoint 可继续使用既有代理。回滚时移除 `netops` environment 中新增的两条绕过项。
