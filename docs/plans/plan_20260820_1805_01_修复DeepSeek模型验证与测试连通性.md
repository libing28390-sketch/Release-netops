# 修复 DeepSeek 模型验证与连通性测试 (Plan)

## 1. 任务目标
修复在 AI 供应商管理中，DeepSeek 供应商配置官方模型（如 `deepseek-chat` / `deepseek-reasoner`）测试连通性时报 `AI_MODEL_NOT_FOUND`，以及随后触发 `AI_HEALTH_BACKOFF` 熔断冷却的问题。

## 2. 现状与根因分析
1. **根因 1（模型白名单限制过窄）**：
   `backend/ai/providers/deepseek.py` 中 `SUPPORTED_MODELS` 仅定义了 `frozenset({"deepseek-v4-flash", "deepseek-v4-pro"})`。
   在实际环境或数据库默认初始化的模型为 DeepSeek 官方生产模型 `deepseek-chat`（DeepSeek-V3）或 `deepseek-reasoner`（DeepSeek-R1）。
   当执行连通性测试或路由调用时，`DeepSeekProvider._validate_model("deepseek-chat")` 检查不匹配，抛出 `AIModelNotFoundException("DeepSeek V4 model is required")`，对应错误码 `AI_MODEL_NOT_FOUND`。
2. **现象 2（健康探测冷却）**：
   初次测试因上述原因失败后，`ai_provider` 的 `health_status` 变为 `unhealthy`，并记录 `last_health_check_at`。
   用户在 30 秒冷却时间内再次点击测试时，API 命中 `AI_HEALTH_BACKOFF` 策略直接返回冷却提示（0ms 响应）。

## 3. 拟修改文件
1. `backend/ai/providers/deepseek.py`：扩展 `SUPPORTED_MODELS`，支持 `deepseek-chat`, `deepseek-reasoner`, `deepseek-coder`, `deepseek-v4-flash`, `deepseek-v4-pro` 及通用 `deepseek-*` 前缀校验；
2. 数据库：重置当前 `prov_test` 的健康状态与冷却时间，清除历史 `AI_MODEL_NOT_FOUND` 错误状态；
3. 测试用例：在 `backend/tests/ai/test_deepseek_contract.py` 中补充 `deepseek-chat`、`deepseek-reasoner` 的契约测试。

## 4. 验证计划
1. 运行 pytest 单测验证 DeepSeekProvider 支持 `deepseek-chat` 与 `deepseek-reasoner`；
2. 运行全量 AI Provider 测试套件；
3. 验证数据库中 Provider 连通性测试链路。
