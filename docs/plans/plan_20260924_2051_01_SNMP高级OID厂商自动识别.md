# SNMP 高级 OID 厂商与自动识别

## 任务目标

修正 `/monitor/snmp-walk` 高级 OID 查找的厂商选项，使其与资产导入模板的 `Vendor_Network` 完全一致（41 个厂商），并在选择 CMDB 设备时自动识别厂商，优先复用 LibreNMS 识别规则和 SNMP `sysObjectID`。

## 现状与问题

- `public/templates/asset_import_template.xlsx` 中网络设备表的厂商下拉项来自 `Vendor_Network`，范围 `L2:L42`，包含 41 个网络和安全厂商。
- MIB 浏览器的厂商下拉项来自 API 返回的数据库 MIB 厂商集合；服务端又按已注册平台厂商过滤，因此页面只显示少数厂商。
- SNMP Walk 页已选择 CMDB 设备，但没有把设备 ID、资产厂商传给 MIB 浏览器；LibreNMS/sysObjectID 识别结果也没有参与厂商筛选。
- 后端已有 `snmp_vendor_registry` 的完整资产厂商目录，以及 SNMP/LibreNMS 身份识别基础，可在原有架构内接通。

## 影响范围

只改 SNMP Walk 高级 OID 目录、设备只读身份识别 API 及其测试。资产模板、凭据存储和网络设备配置不变。

- `src/pages/SnmpWalkPage.tsx`

## 接口约束

- 新增只读识别请求 `POST /api/platform-registry/snmp-walk-vendor-detect`，请求体为 `{ "device_id": "..." }`。
- 后端在服务端按当前用户租户读取目标与 SNMP 凭据，只读取 `sysObjectID`、`sysDescr` 等系统身份 OID；响应不得包含 community 或其他凭据。
- 成功响应返回规范厂商、资产厂商、识别来源（LibreNMS、sysObjectID 或未识别）、状态和必要的设备身份摘要。资产厂商与探测结果冲突时明确返回冲突并以探测身份作为筛选候选，不静默覆盖资产数据。
- 前端下拉项直接使用资产导入模板同源的 41 个规范厂商名称；MIB 暂无该厂商节点时显示空结果，不删除选项。

## 实施步骤

1. 后端实现租户隔离的只读 SNMP 身份查询，优先使用 LibreNMS 规则，其次使用现有 `sysObjectID` 厂商映射，并覆盖冲突、空身份和凭据缺失路径。
2. MIB 私有节点查询允许资产目录中的完整厂商范围；前端固定呈现与 Excel 完全相同的 41 项。
3. SNMP Walk 页将已选设备和资产厂商传给 MIB 浏览器；加载私有 MIB 时自动识别并筛选，无法识别时回退到规范资产厂商并允许手动选择。
4. 运行前端类型检查和生产构建，以及后端语法检查；确认改动差异无空白错误。

## 分工边界

- 后端执行者：负责 `backend/api/devices.py`、`backend/services/snmp_discovery_service.py`、`backend/services/librenms_rule_service.py` 和 SNMP 后端测试；不得修改前端文件。
- 前端执行者：负责 `src/components/SnmpMib/MibNodeBrowser.tsx`、`src/pages/SnmpWalkPage.tsx` 和前端测试；按上述 API 契约接入，不修改后端。
- 主 Agent：维护本计划和 walkthrough，统一接口、集成差异并运行共享验证。

## 验证计划

- 确认 Excel、前后端厂商目录 41 项及顺序完全一致。
- 前端运行 `npm run lint` 和将输出隔离到临时目录的 `npm run build`。
- 后端运行 `python -m compileall` 检查改动模块，并执行 `git diff --check`。
- 检查识别成功、未知身份、资产冲突和缺失凭据路径；确认响应不包含 SNMP 凭据。

## 风险与回滚思路

- LibreNMS 规则首次初始化可能依赖后端已有规则快照或受控的规则同步；识别规则不可用时仍通过 `sysObjectID` 识别，最终回退资产厂商和手动筛选。
- 资产模板中的厂商可能尚无本地 MIB 节点；仍展示该厂商，搜索结果显示空态。
- 回滚时恢复前端 MIB 浏览器筛选逻辑并移除新增的只读识别 API，不涉及数据库迁移、设备配置或凭据数据。
