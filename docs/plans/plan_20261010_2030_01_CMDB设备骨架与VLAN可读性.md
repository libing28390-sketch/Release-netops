# CMDB 设备骨架与 VLAN 可读性

## 目标

让 `/cmdb/devices` 的“设备骨架”只展示网络设备，并优化 `/cmdb/vlans` 在常见桌面视口下的信息密度和可读性。

## 现状与问题

- `GET /api/cmdb/devices` 当前调用 `cmdb_service.list_cmdb_devices()`，查询 `devices` 时没有按资产类型过滤，服务器资产会进入网络设备骨架。
- VLAN 页面在单屏表格中同时显示大量字段，截图中列宽过窄、文字密集，难以快速阅读。

## 影响范围

- 设备骨架只改变列表返回范围，不删除服务器资产、不改全局资产库，也不影响独立服务器视图或采集任务。
- VLAN 页面只调整显示结构；数据、筛选、树形分组、分页、导出、详情和编辑/删除行为保持可用。
- 使用 CMDB 的 `asset_type` 与共享设备分类语义识别网络设备，避免只靠前端隐藏服务器。

## 拟修改文件

- `backend/services/cmdb_service.py`：过滤网络设备，复用服务器分类器。
- `src/pages/CmdbManagementTab.tsx`：精简 VLAN 主表，使用操作列详情入口展示完整信息。
- 对应计划与 walkthrough。

## 实施步骤

1. 核查物理资产和设备的规范分类字段，令 CMDB 设备骨架只返回网络设备；空资产类型沿用当前 CMDB 约定，但显式识别为服务器的设备仍排除。
2. VLAN 主表保留 8–9 个常用摘要字段；不默认展开行，操作列详情图标打开完整信息视图；确保长文本截断、窄视口可横向浏览。
3. 保留工作区既有改动，只修改以上职责边界内的代码。
4. 做源码审查、静态检查和生产前端构建；按工作区执行规则不新增或运行测试。

## 验证计划

- 确认设备骨架后端按网络设备范围过滤，响应结构保持兼容。
- 确认 VLAN 表格在主列表中突出 VLAN、设备、站点与网关等关键字段，其余信息仍可查看，原有操作入口可用。
- 执行 `git diff --check`、前端 lint、隔离目录 Vite 构建及目标 Python 文件 `py_compile`；不连接生产设备、不部署。

## 风险与回滚

- 历史设备资产类型可能缺失或分类字段不一致；兼容 CMDB 默认网络设备语义，并对明确识别为服务器的条目做保守排除。
- 主表隐藏低频列后需点击详情图标查看完整信息；保留现有详情内容和导出，不修改业务记录。
- 可分别回滚设备查询过滤和 VLAN 表格显示改动，不影响数据库记录。

## 最新界面反馈补充

- 用户指出当前 VLAN 主表和展开区仍然信息过多；本次验收以常用视图能快速识别 VLAN、设备/站点、网段/网关和端口规模为准。
- 默认列表不显示展开区、空的 ARP/MAC 面板或冗余统计卡；低频业务字段与较长终端清单保留在详情入口。
- 改动仅收纳展示信息，不减少后端返回字段、不删除数据或功能。

## 最新交互与字段范围确认

- VLAN 记录不使用行展开；在操作列通过公共图标按钮进入完整详情视图，复用现有详情内容与表格操作样式。
- 主表保留约 8–9 个字段：VLAN ID、名称、设备/站点、网段/网关、端口/设备数，以及描述、VRF、SVI 接口、状态。长描述截断并可查看完整文本。
- 顶部摘要保留 3 项核心计数；默认列表与详情分层，详情视图仍可查完整接口、ARP/MAC 终端和业务属性。
