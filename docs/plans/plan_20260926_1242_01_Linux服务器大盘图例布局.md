# 07 Linux 服务器监控图例布局调整计划

## 任务目标

调整 07 Linux 服务器监控中时间序列面板的图例布局，减少右侧统计表造成的视觉突兀感，并为曲线提供更完整的横向空间。

## 现状与问题

- 用户截图显示 CPU、内存、系统负载和磁盘吞吐等趋势图右侧出现占比过大的图例统计表。
- `timeseries_panel` 当前默认将图例设为右侧表格，并显示 Last、Max、Mean；Linux 大盘使用了该默认配置。
- 当前工作树只有既有的 `handoff.md` 用户改动，实施时需要保留。

## 影响范围

- 仅修改 07 Linux 服务器监控的时间序列图例展示；PromQL、指标、面板网格位置和统计口径保持不变。
- 不改变其它仪表盘调用 `timeseries_panel` 的现有默认表现。

## 拟修改文件

- `monitoring/grafana/generate_dashboards.py`
- 生成文件 `monitoring/grafana/dashboards/nexora-linux-metrics.json`
- 本任务计划与完成记录。

生成器输出清单已检查：9 个 JSON（Network Overview、Device、Wireless、Interface、Interface Detail、Monitoring Health、Outbound、Linux Metrics、Windows Metrics）。预计只有 Linux Metrics JSON 随本次定向配置发生变化。

## 实施步骤

1. 为时间序列面板生成函数增加可选图例模式、位置和统计字段配置，保留所有现有调用的默认值。
2. 为 Linux 大盘时间序列面板指定底部列表图例并移除图例统计列。
3. 运行生成器并检查完整输出差异，只保留预期的 Linux 大盘生成结果。

## 验证计划

- 编译 `generate_dashboards.py`。
- 解析所有生成的仪表盘 JSON。
- 确认 Linux 面板 7、8、9、10、12、14 的 legend 为 bottom/list 且没有汇总统计列。
- 确认其它八个仪表盘 JSON 无差异，运行 `git diff --check`。

## 风险与回滚

- 底部图例会占用少量纵向空间，但系列名称仍可见，趋势图将获得完整宽度。
- 若实际 Grafana 中的展示不符合预期，可撤销本次可选参数与 Linux 大盘参数，重新生成该 JSON；无需修改查询或采集配置。
