# 实施计划：Token 使用率极致优化 5 项全链路落地

- 创建时间：2026-11-26 23:22
- 目标仓库：`D:\netops\netsops-main`

## 1. 任务目标
全面落地 5 项本地化与 Token 优化措施，最大化使用本地 PostgreSQL 与本地向量能力，将不必要的云端 Token 消耗压到最低：
1. **高置信度知识库命中 0 Token 本地直出**：`knowledge` 意图下本地知识库高分命中（如 `score >= 0.85`）且非深度解释/改写类问题时，直接本地渲染原文与出处，不调用外部大模型。
2. **扩展本地零 Token 运维查询与 `/` 显式指令直出**：新增 IPAM 网段利用率、拓扑邻居、接口异常状态、近期配置变更 4 类本地 PostgreSQL 只读查询；并在 MCP 工具注册表与 `local_router` 中补齐 `/ipam`、`/interfaces`、`/changes` 等直出通道。
3. **意图识别与健康探测低成本路由 + 轻量化探测**：无显式场景路由时，`natural_query` 与 `model_health_probe` 自动优先路由至本地/最低成本/Flash 模型；定时健康探测支持轻量 `/models` 连通性检查以减少后台 Token 消耗。
4. **本地语义问答缓存（PostgreSQL + 本地 Embedding）**：对高频重复的通用/知识问答建立 PostgreSQL 语义缓存（支持精确哈希 + 余弦相似度 ≥ 0.94 命中，绑定知识库版本自动失效，严格不缓存实时联网或敏感资产内容），命中即 0 Token 返回。
5. **RAG 上下文紧凑 Markdown 序列化**：替换传给大模型的冗长 `json.dumps(context_facts)`，去除内部元数据键名噪声，以紧凑 Markdown 呈现检索片段与外部网页参考，降低 30%~50% 输入 Token。

## 4. 风险与回滚思路
- 语义缓存仅针对纯知识/通用无敏感数据问答，且自动绑定知识库更新时间与 TTL，防止陈旧或越权复用；
- 高分知识库直出、语义缓存、轻量探测均配有独立开关（默认开启，可经 `.env` 随时关闭），零侵入回滚。
