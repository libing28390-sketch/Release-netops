# 计划作业审批快照对齐

## 任务目标

修复定时作业在审批后因创建摘要和执行摘要口径不一致而被误拒绝的问题；在历史详情中把该类拒绝原因说明清楚，并保留审批对执行内容的完整性保护。

## 现状与问题

- 历史页显示“权限校验拒绝”，原因文案为 `Scheduled job content changed after approval`，容易被理解为普通角色权限不足。
- 创建路径从规范化请求生成授权摘要，执行路径从数据库行重建执行快照；巡检项 `check_items` 会在列表和 `commands` 字符串之间转换，逗号/换行会造成摘要口径差异。
- 该拒绝也可能表示作业确实在审批后被修改；截图对应运行记录没有可核对的 job ID、数据库行或调度日志，不能假定所有拒绝都是误报。

## 影响范围

- 后端：`backend/services/scheduled_job_authorization.py`、`backend/api/scheduled_jobs.py`。
- 前端：`src/pages/ExecutionSchedule/components/ExecutionDetail.tsx`，将摘要不一致提示改为更易读的处理卡片，并链接到定时作业页。
- 保留执行端现有授权摘要比对；不重算或覆盖数据库中已有作业的授权摘要。
- 通过同一执行快照校验创建内容与审批内容完全一致，不涉及数据库结构调整。

## Agent 分工

- 后端执行者：只负责计划作业审批/执行摘要归一化和创建校验，拥有两个后端文件。
- 主 Agent：负责用户文案、计划、walkthrough、handoff、最终集成与复核。
- 共享工作区；双方保留其他工作树改动，不覆盖无关修改。

## 实施步骤

1. 对照审批创建、作业创建、持久化与调度执行快照，定位摘要差异。
2. 将巡检项按执行端实际拆分规则规范化；创建前以拟持久化字段计算执行快照，并要求与已批准内容摘要完全一致。
3. 若执行内容与审批摘要不一致，在消费审批凭据前拒绝创建；不自动授权已有作业。
4. 在历史页对该类拦截只显示“权限校验未通过，作业未执行”；不展开原因和处理步骤。该提示使用紧凑弹窗，正常执行详情及其他权限拒绝保持原布局。
5. 执行 Python 语法解析、TypeScript 检查、隔离 Vite 构建和差异检查；不触碰真实数据库或作业记录。

## 验证计划

- Python `ast.parse` 检查两个后端文件。
- `npm run lint`。
- 在临时目录运行 Vite production build。
- `git diff --check`。
- 不运行自动化测试、不部署、不修改数据库或真实作业。

## 风险与回滚

- 已有摘要失效的作业不会被自动重新授权；检查作业内容后需要走重新审批流程。
- 若现场拒绝实际由用户在审批后修改内容造成，拒绝本身是正确的安全行为。
- 回滚可恢复原创建摘要逻辑和原历史页文案；执行端摘要保护始终不应被绕过。
