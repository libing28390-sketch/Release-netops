# 实施计划 - 网络设备路由重命名与资产投产状态同步

## 1. 任务目标
1. 修复网络设备列表（原路径 `/assets/devices`）资产投产状态始终显示“未投产/待投产”、未与资产管理（`physical_assets`）同步的问题。
2. 将网络设备页面的 URL 路由路径从 `/assets/devices` 修改为更具可读性与语义化的 `/assets/network-devices`，同时保持对旧路由的向下兼容重定向。

---

## 2. 现状与根因分析

### 2.1 资产投产状态未同步根因
1. **Backend 查询投影遗漏**：
   - `backend/api/devices.py` 中的 `read_devices` (`GET /api/devices`) 接口，在 `mode=light`（轻量模式，前端表格轮询默认使用）的 SQL 投影 `select_clause` 中漏掉了 `d.lifecycle_status` 字段。
   - `asset_cols` (物理资产连表列) 亦漏掉了 `pa.lifecycle_status AS asset_lifecycle_status`。
2. **状态规范化缺乏层叠合并**：
   - `_sanitize_device_item` 在序列化设备字典时，没有优先读取物理资产表 `physical_assets.lifecycle_status`。由于未包含物理资产状态且设备表原生状态缺失，后端直接返回了没有 `lifecycle_status` 属性的 JSON。
3. **前端降级兜底**：
   - 前端 `StatusBadge.tsx` 接收到 `lifecycleStatus` 为 `undefined` 时，回退使用了默认状态 `'staging'`（待投产/未投产）。
4. **数据库与数据同步缺乏自动联动**：
   - 资产管理修改 `physical_assets.lifecycle_status` 时，部分路径未同步更新关联的 `devices.lifecycle_status`。

### 2.2 路由路径不清晰
- 当前“网络设备”页面挂载在 `/assets/devices`，不能一眼区分与服务器 (`/assets/servers`) 或 CMDB 设备 (`/cmdb/devices`) 的区别。
- 需要将标准路由切换为 `/assets/network-devices`，并配置重定向逻辑。

## 5. 实施步骤

### 阶段一：后端 API 与资产/设备状态同步修复
1. 修改 `backend/api/devices.py` 中的 `read_devices` 接口：
   - 在 `asset_cols` 中加入 `, pa.lifecycle_status AS asset_lifecycle_status, pa.status AS asset_status`。
   - 在 `mode=light` 的 `select_clause` 中补上 `d.lifecycle_status` 字段。
2. 修改 `_sanitize_device_item`：
   - 增加规范化计算逻辑：`sanitized['lifecycle_status'] = str(sanitized.get('asset_lifecycle_status') or sanitized.get('lifecycle_status') or 'staging').strip() or 'staging'`，实现网络设备实时同步资产管理的投产状态。
3. 校验 `backend/api/assets.py` 资产编辑接口 `PUT /api/assets/{id}`，确保资产更新生命周期状态时实时刷入关联设备的 `devices.lifecycle_status`。

### 阶段二：前端路由重命名与跳转兼容
1. 在 `src/components/AppSidebar/navConfig.ts` 中，将 `id: 'devices'` 的 `path` 从 `/assets/devices` 改为 `/assets/network-devices`。
2. 在 `src/utils/routeContext.ts` 中，`assets` 分支支持匹配 `second === 'network-devices'` 与 `second === 'devices'`。
3. 在 `src/App.tsx` 的 `redirects` 映射表中追加 `/assets/devices: '/assets/network-devices'`，并确保路由判断兼容新旧路径。
4. 全局查找并替换跳转路径：
   - `DashboardTab.tsx`: `/assets/devices` -> `/assets/network-devices`
   - `CmdbManagementTab.tsx`: `/assets/devices` -> `/assets/network-devices`
5. 更新 `src/store/inventoryStore.ts` 中的 `normalizeDeviceRecord`，确保前端从 API 提取并保持 `lifecycle_status` 属性。

## 7. 风险与回滚思路
- **风险**:
  - 部分旧的深层硬编码链接跳转到 `/assets/devices` 可能出现未捕获情况。
- **回滚思路**:
  - 重定向映射表保留旧路由兼容处理，即使遗漏硬编码也可以通过 Router automatic redirect 安全兜底。
  - 若数据查询发生异常，可恢复 SQL 连表投影及 `_sanitize_device_item` 回退到原有实现。
