# 实施计划 - CMDB 凭据修改与设备自动改密指引优化

## 1. 任务目标
澄清与优化用户反映的“在 `/cmdb/credentials` 修改凭据密码后设备本身未自动改密”的疑问：
1. **原理澄清与答疑**：明确 CMDB 凭据中心是 Nexora 系统的凭据保管库（Credential Vault），编辑密码用于更新 Nexora 连接设备时使用的已存凭据。真正的“通过 SSH 特权账号登录交换机下发 CLI 命令修改硬件口令”功能由“密码轮换与上收服务”（`password_rotation_service`）与“改密剧本”完成。
2. **凭据中心交互与指引优化**：在 CMDB 凭据中心页面顶部增加提示 Banner，说明凭据库与硬件设备改密的功能分工，并提供跳转至“密码轮换改密”的快捷操作按钮。

## 2. 现状与根因分析
- 用户在 CMDB 凭据中心点击编辑密码，系统更新了数据库中保存的凭据密文，但未触发底层 SSH 登录物理设备执行改密 CLI。
- 页面缺少针对“凭据保管库记录”与“硬件设备口令轮换”的分工说明，容易让使用者误以为修改 CMDB 数据会自动向网络设备发命令改密。

## 3. 拟修改文件
- `src/pages/CmdbManagementTab.tsx`：当 `tab === 'credentials'` 时，增加明晰的提示 Banner 和跳转“密码轮换”功能的快捷按钮。

## 4. 实施步骤
1. 在 `CmdbManagementTab.tsx` 中加入 `tab === 'credentials'` 的提示 Alert 节点与跳转路由。
2. 运行 `npx tsc --noEmit` 进行前端类型校验。
3. 向用户详细解答 CMDB 凭据存储与自动化设备改密的原理差异及使用指引。

## 5. 验证计划
1. `npx tsc --noEmit` 校验语法与类型。
2. 确认 CMDB 凭据中心提示清晰，操作路径顺畅。
