# 定时作业跨租户审批人

## 任务目标

移除共享配置验证码审批中的“审批人与申请人必须同租户”限制，使符合审批权限及验证码配置条件的其他租户用户也可被选择并完成审批。该服务也被告警规则和执行计划审批复用。

## 现状与问题

- 候选人列表 SQL 只查询当前租户。
- 发起验证码时，审批服务再次比较审批人与申请人的租户。
- 验证验证码和最终消费审批令牌时，还会按申请人租户重新校验审批人，因此只改列表会让跨租户申请在后续阶段失败。

## 影响范围

- 定时作业创建/编辑的配置审批人选择及其验证码发起、验证和令牌消费。
- 同一审批服务被执行计划和告警规则共用；这些选择器也会改为读取合格审批人目录并显示租户标识。
- 不改变申请人必须绑定有效租户、不允许自审批、账号启用、PAM 审批权限、显式 RBAC 范围及 MFA/邮箱/飞书验证要求；显式受限账号仍需具有申请人租户或全局审批范围。
- 列表会返回候选人所属租户，以便选择时辨识。

## 实施步骤

1. 查询所有启用用户，再按 PAM 审批权限、未自审批、可用验证码方式和全局/显式 RBAC 范围筛选候选人。
2. 删除发起、验证和消费阶段的审批人与申请人租户相等判断；资源授权仍按用户显式权限范围执行。
3. API 返回候选人 tenant_id；定时作业、执行计划和告警规则统一读取该合格审批人目录，选择项展示租户。
4. 静态检查完整审批链与差异；不创建真实审批或作业。

## 验证计划

- 检查候选列表、发起、验证码验证、令牌消费四个阶段均不依赖审批人租户等于申请人租户。
- 检查申请人租户绑定、自审批阻止、账号状态、PAM 审批授权、验证码和资源范围校验仍保留。
- 运行与本次改动相符的最小静态检查；不向真实系统发起审批。

## 风险与回滚思路

- 候选范围扩大到其他租户后，用户名会跨租户可见；下拉项显示 tenant_id 以帮助识别。
- 具备显式 tenant-only 资源范围的账号仍只能审批其获授权的租户；跨租户审批需要可作用于申请人租户的授权或全局授权。
- 回滚上述服务、API 和前端文件即可恢复原行为；无数据库变更。
