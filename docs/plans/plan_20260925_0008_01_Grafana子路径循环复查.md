# Grafana 子路径循环复查计划

## 任务目标

修复 Docker 部署后 `/monitor/dashboards` 的 Grafana 地址不断追加 `/grafana`，使公开 `/grafana/` 与 Grafana 内部路由保持一致。

## 现状与证据

- 用户的 Grafana、Nginx、NetOps 容器均健康；`/api/grafana/auth` 返回 204，Grafana 插件 API 可返回 200。
- Nexora iframe 初始地址仅含一段 `/grafana`；Nginx 首次请求 `/grafana/d/...` 返回 200，下一跳 `/grafana/grafana/d/...` 返回 404。浏览器随后继续访问含数十段 `/grafana` 的路径。
- 服务器实际环境为 `GF_SERVER_SERVE_FROM_SUB_PATH=false`、Nginx `proxy_pass http://grafana_backend/;`、`GF_SERVER_ROOT_URL=https://192.168.204.128/grafana/`，与当前仓库一致。此前本地静态契约通过但线上现象未消失。
- 用户确认普通浏览器直接打开 `/grafana/` 和无参数的仪表盘 URL 也会累加路径，因此故障与 Nexora 仪表盘查询参数无关。
- Grafana 12.1.0 官方支持 Grafana 处理子路径并由代理原样转发。首跳 200 后重复路径最初指向浏览器端导航；后续无痕对照和 Cookie 删除实验进一步把触发因素定位到旧 Grafana 会话 Cookie。
- 2026-09-25 00:11 已在服务器启用 `serve_from_sub_path=true` 并由 Nginx 原样转发。普通窗口禁用缓存并强刷后仍循环，无痕正常。
- 用户在普通窗口删除 `grafana_session` 后仪表盘恢复；截图同时显示 `grafana_session`、`grafana_session_expiry` 和独立的 `nexora_grafana_session`。因此已定位为浏览器遗留的 Grafana 原生会话 Cookie 与 Nexora Auth Proxy 身份冲突，Nexora 会话 Cookie 不是应清理对象。

## 影响范围与拟修改文件

- `docker-compose.yml`：与已在服务器验证可供无痕窗口访问的子路径模式同步，并显式保持 Auth Proxy 不签发 Grafana 登录 Cookie。
- `nginx/nginx.conf`：保留 `/grafana/` 前缀转发；Auth Proxy 鉴权子请求只向后端发送 Nexora Bearer，主 Grafana 上游不接收浏览器 Cookie。
- `backend/tests/monitoring/test_monitoring_v1_deployment_contract.py`：同步部署契约期望。
- `docs/deploy/docker.md`：说明子路径转发和双 Cookie 的边界。
- 本计划与对应 `docs/walkthrough/` 记录。

## 实施步骤

1. 保留已在服务器运行的 Grafana 子路径配置：Grafana 处理 `/grafana`，Nginx 原样转发；显式关闭 Auth Proxy 登录令牌 Cookie。
2. 在 Nginx 的两个代理位置均不转发原始浏览器 Cookie；`/_grafana_auth` 仍从原始请求读取 `nexora_grafana_session`，仅将其作为 Bearer 传给后端验证。
3. 更新部署契约和 Docker 部署文档。
4. 服务器备份 Nginx 配置，校验后仅重建 Nginx；用已清除旧 Cookie 的普通窗口确认 Grafana 与 Nexora Auth Proxy 正常。

## 验证计划

- 针对 Compose/Nginx 的部署契约检查。
- Compose YAML 解析；有 CLI 时运行 `docker compose config` 和 `nginx -t`。
- 运行部署契约、解析配置；部署后检查普通窗口仪表盘仍只有一段 `/grafana`，同时确认 Nexora 身份桥接仍正常。

## 风险与回滚

- Grafana 在反向代理后从子路径提供 UI；若部署目录使用了其他代理配置，需先核对实际加载的配置。
- 若新增 Cookie 过滤导致异常，只需恢复本次 Nginx 备份并重建 Nginx；保留 `.env`、Grafana 数据卷、PostgreSQL 数据和凭据。
- 当前服务器已运行子路径试验配置；该配置已在无痕窗口正常提供仪表盘，后续操作只改 Nginx 的 Cookie 转发。
