# 采集磁盘保护设置

## 任务目标

移除采集器表单中没有运行时消费者的“队列磁盘上限（MB）”，并让管理员在前端调整 VictoriaMetrics 的最小剩余空间保护值。保存时同步更新宿主机 `.env` 与持久化运行配置，成功后立即重启 VictoriaMetrics 进程，并在页面明确显示同步/生效状态与短暂中断提醒。

## 现状与问题

- `queue_disk_limit_mb` 目前只在采集器 CRUD 中存取，没有组件读取它来限制队列。
- 真正的 VictoriaMetrics 最小剩余空间保护值由 Compose 命令行参数 `-storage.minFreeDiskSpaceBytes` 控制。
- NetOps 后端没有 Docker 控制权限；将 Docker socket 权限交给 Web 后端会扩大权限边界。
- 用户已将阈值改为 5 GiB，但主机 `.env` 仍是 10 GiB。仅依赖运行时卷会让进程当前阈值正确，却使 Compose 的后续默认配置与 `.env` 认知不一致。

## 影响范围

- 采集器编辑/新建表单不再展示或提交无效队列上限值。
- 使用独立共享运行时卷传递磁盘保护配置；VictoriaMetrics 内的轻量 shell supervisor 检测值变化，优雅停止 VictoriaMetrics 进程后退出，由容器现有 `restart: unless-stopped` 策略重启整个容器，不访问 Docker socket。
- 用宿主机 systemd path/service 监听受限的运行配置请求；独立 root helper 只同步 `VM_MIN_FREE_DISK_SPACE_BYTES` 一项到主 `.env`，先生成权限为 0600 的备份，再以原子替换保留其他参数和 LF/CRLF 行尾。完整 `.env` 不挂载给 NetOps Web 容器，也不增加 Docker 容器。
- 管理 API 仅在宿主机同步服务就绪时接受更新；先等待 `.env` 同步确认，再提交运行配置触发 VictoriaMetrics 重启。API 返回同步状态与请求编号，页面展示成功、失败或待同步。
- 新增管理员专用后端读取/更新 API；页面显示当前值、当前生效值和运行状态。
- 修改后由管理员确认立即应用；页面红色提示说明服务短暂重启及写入中断。
- `.env` 与持久化运行值保持一致；运行值仍保存在运行时卷并供 supervisor 使用，部署脚本为 Linux/systemd Compose 主机安装同步 helper。不移除数据库中的旧队列字段，不改变旧采集器 API。

## 实施步骤

1. 移除前端队列磁盘上限的类型、默认值、编辑回填、提交字段和输入框。
2. 新增共享运行时卷初始化服务，让 NetOps 用户和 VictoriaMetrics supervisor 安全读写小型状态文件。
3. VictoriaMetrics 启动时从配置文件读取保护值；文件更新后优雅停止 VictoriaMetrics 子进程，再让 supervisor 以退出状态触发 Docker restart policy 重启整个容器，并记录状态与当前生效值。
4. 增加角色受限的读写 API，限制数值范围并原子写入配置文件。
5. 在采集器管理页面增加紧凑的保护设置行、红色容器重启提醒、持久化位置说明、保存确认和状态轮询。
6. 将 API 设定写入同步请求，由宿主机 helper 原子备份并只更新 `.env` 目标键；确认同步成功后再提交运行配置。
7. 将同步可用性、请求编号和失败代码返回给 API/页面；部署脚本自动安装 systemd path/service，更新既有阈值使 `.env` 与持久卷对齐。
8. 更新 `.env.example` 与磁盘保护文档，说明同步服务、备份文件和运行机制。

## 风险与回滚思路

- 配置值不正确时，supervisor 保留旧进程并报告受限错误代码；不会接触 Docker socket。
- 修改成功后，VictoriaMetrics 会优雅退出，容器重启期间写入会短暂停止；持久化历史数据仍保留在原数据卷。
- 用户授权同步代码后，远端被覆盖文件先备份，远端 `.env` 不覆盖；部署失败时恢复该备份并重建受影响服务。
- `.env` 同步 helper 只修改一个白名单键；每次实际变更前备份原文件并保留文件权限与行尾。同步 helper 未就绪或失败时 API 明确拒绝或报错，不静默声称 `.env` 已同步。
- 回滚时恢复旧 Compose 命令并移除新卷挂载/路由/systemd path/service；不删除 `nexora-vmdata`，不迁移或清理历史指标。
