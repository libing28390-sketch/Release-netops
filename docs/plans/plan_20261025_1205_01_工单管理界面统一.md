# 工单管理界面统一

## 目标与现状

按 netops-itsm-design、netops-frontend 重新检查工单工作台、变更创建/详情、故障与服务申请及管理弹窗。当前存在重复资料、字段卡片过多、装饰色/字号不统一、弹窗重复实现与信息层级拥挤的问题。保留现有导航、权限流程、接口、默认每页10条及条数选择器。

## 影响范围与文件边界

- 主 Agent：公共工单 UI 组合组件、Tickets/index.tsx、ChangeOrderList.tsx、ChangeOrder/index.tsx 中外围弹窗、覆盖记录及文档、最终集成。
- 前端执行者一：ChangeOrderEditor.tsx、ChangeOrderDetail.tsx、ControlSheetPanel.tsx、ChangeOrderWorkflowPanels.tsx；压缩重复信息，保留操作和校验。
- 前端执行者二：Tickets 下 ServiceRequestComposer/Details、ServiceCatalogManager、TicketSlaSettingsPanel、TicketSlaSummary、TicketSummaryPanel；统一弹窗和字段层级。
- 执行者不改其他人的文件、不创建子 Agent，不维护整套文档。公共组件归主 Agent。

## 实施步骤

1. 浏览器记录当前页面和代表性详情的基线；核对现有公共组件契约。
2. 基于现有 FormDialogShell、ActionButton、FormField、分页和主题 tokens 组合工单公共呈现组件。
3. 并行修改变更与故障/服务申请界面，主 Agent 处理列表、管理弹窗与集成。
4. 运行 Tickets/ChangeOrder 前端测试、TypeScript 检查和隔离生产构建。
5. 同窗口浏览器复核列表、详情、创建、管理弹窗，检查 Escape/焦点、10条分页及窄屏边界。

## 验证与风险

不更改后端、数据库、审批权限或真实设备命令。已有未提交改动原位保留。UI 调整若影响交互，补最小行为回归；全量公共验证由主 Agent 统一执行一次。浏览器不得为演示而审批或下发命令；现场数据不足的状态使用已有前端 fixture 验证。回滚仅撤销本次呈现层增量。
