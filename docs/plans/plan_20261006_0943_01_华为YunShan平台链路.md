# 华为 YunShan 平台链路

## 目标与现状

用户要求先核实华为官方网站，再支持资产导入、`/assets/network-devices` 平台绑定及 TextFSM，并确认 LibreNMS 支持情况。官网产品彩页确认 YunShan OS（云杉）用于部分 CloudEngine 设备，官方命令参考的系统信息可同时包含 VRP Software 标题和 YunShan OS 版本行。现有 UI、规范化、系统 Profile 和解析目录主要支持 VRP V5/V8，缺少独立 YunShan 身份。

## 接口与影响范围

- 规范业务平台及解析键：`huawei_yunshan`；显示名称：Huawei YunShan OS / 华为 YunShan OS（云杉）。接收 `yunshan`、`yunshanos`、`YunShan OS` 等明确别名。
- 保留独立 OS 身份；SSH 复用已有 Huawei transport，只在驱动边界映射，不把 YunShan 持久化为 VRP。
- 不凭型号或 V600/V300 单独推断 OS；明确 YunShan 标识优先于同时出现的 VRP 标题。
- YunShan 有 OS 1.x 与产品软件 VxxxRxxxCxx 两类版本，不套用 VRP V5/V8、Comware V5/V7 的代际命名。版本模板暂为 `common`，表示尚未证实需区分的语法；版本解析分别保留 `VERSION`、`PRODUCT_VERSION`，不承诺所有版本实机兼容。
- 原有设备不自动改绑；新增平台注册及模板只更新系统目录，保护租户自定义记录。

## 文件边界与分工

前端 Luna：只修改 `src/` 中资产导入、设备平台选项、模板目录共享映射和对应测试。后端 Luna：只修改 `backend/core/platform_utils.py`、相关资产/设备规范化服务与系统平台 registry、平台识别及新增 `m0275` 注册迁移和相关测试。主 Agent：`backend/core/textfsm.py`、驱动适配、YunShan 模板和解析测试、官网资料、最终集成及统一记录。具体清单在两位执行者只读调查返回后收敛；共享文件由主 Agent协调。

## 实施步骤

1. 查官方产品/命令参考并记录可复核链接；追踪导入→资产→设备→Profile→驱动→命令→解析。
2. 同步前后端规范键、别名、厂商关系和平台选项；允许独立绑定并同步资产与设备。
3. 注册幂等系统 Profile/动作/识别规则；旧安装通过编号迁移获得新目录。
4. 建立独立 TextFSM 命名空间及已核实输出的基础模板，禁止随意回退 VRP 版本模板。
5. 运行聚焦测试和前端类型检查，汇总缺少真实设备输出等未验证边界。
6. 对比 LibreNMS 上游和内置规则，核实 SNMP 识别、指标范围、平台持久化和本地适配器能力；不能凭图表名称承诺内存采集。
7. 收尾用户先前授权的 Windows `WinError 10013`：本机 excluded range 5256–5355 包含 5310，临时覆盖 15310 已验证健康；将 Windows 开发启动器、等待脚本及 Vite 代理的默认值统一到 15310，Linux 仍 5310、显式环境变量仍优先。主 Agent 负责 `scripts/dev-internal.mjs`、`scripts/dev-backend.mjs`、`package.json` 和 `vite.config.ts`，检查语法和本机启动健康。

## 验证范围

覆盖 Cisco/Huawei/H3C 厂商→平台→驱动→命令契约、YunShan 别名、厂商切换、导入保留身份、手动平台绑定；测试双标题识别优先级；每个新增模板至少两个脱敏代表性样本；迁移幂等及系统/自定义记录保护使用隔离 PostgreSQL fixture。前端 `npm run lint`、相关 Vitest、必要构建；后端聚焦 pytest 和 PostgreSQL-only 策略扫描。公共检查仅运行一次。不连接真实设备。

## 风险与回滚

不同设备/版本命令和输出可能不同；明确支持已核实基础模板，不以泛化正则承诺所有型号。回滚代码不删除已被设备绑定的系统 Profile；不改写历史资产 OS。不推送或发布。
