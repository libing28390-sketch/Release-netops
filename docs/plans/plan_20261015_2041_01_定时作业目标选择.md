# 定时作业目标选择

## 任务目标
- 修正创建/编辑定时作业时，目标 IP 候选窗口被父窗口遮挡的问题。
- 改善任务表单布局，使常用配置和操作按钮在桌面首屏内可见，减少重复滚动。
- 根据用户补充截图压缩执行动作区域：合并基本信息与动作设置，备份说明改为紧凑文案，命令/脚本审批提示按动作展示。
- 使用浏览器检查现有页面与修改后布局。

## 现状与问题
- 路由 `/automation/scheduled-jobs` 由 `ScheduledJobs/index.tsx` 组合创建表单和候选设备窗口。
- 创建窗口层级为 `z-[80]`，候选窗口为 `z-[70]`，候选列表显示在创建窗口后方。
- 第一步把基本信息、动作与目标范围纵向堆叠，选择 IP 后进一步增加高度。
- 工作区已有多份未跟踪构建产物，保持原样。

## 影响范围与拟修改文件
- `src/pages/ScheduledJobs/components/CandidateModal.tsx`：候选窗口层级、紧凑列表、键盘/复选框与窗口高度。
- `src/pages/ScheduledJobs/components/JobModal.tsx`：桌面双栏布局、目标输入和已选设备、固定操作区。
- 必要时调整 `src/pages/ScheduledJobs/index.tsx` 的窗口组合，不修改调度或审批契约。
- 本计划及同后缀 walkthrough。

## 实施步骤与分工
1. 主 Agent 负责浏览器复现、方案、JobModal 布局、集成与归档。
2. 前端 Luna 子 Agent 只负责 CandidateModal，修正弹层与列表交互；不得修改共享文件或继续分派。
3. 集成后检查 diff，使用浏览器核对桌面与窄屏，以及搜索、选择、取消和返回。

## 验证计划
- 按 netops-quality-gate 选择 TypeScript 检查和隔离目录构建。
- 浏览器复现远端现状；先用模拟数据预览，再复用用户已登录的 `http://192.168.56.1:5400/automation/scheduled-jobs` 验证真实查询、勾选、返回、Esc 与窄屏，不提交真实定时作业或触发设备操作。
- 当前任务仅涉及前端布局，不运行无关后端全量回归。

## 风险与回滚
- 保持表单状态、IP 搜索和审批回调契约，避免影响编辑回填与已有选择。
- 不部署或推送；线上地址是否更新取决于后续授权部署。
- 回滚时只撤销本次组件和归档变更，保留已有用户文件。
