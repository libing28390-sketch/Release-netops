# 新部署采集链路审查

## 任务目标
只读核查新部署无法自动编译发布、容器指标缺失、硬件及无线数据缺失的代码链路，形成可复核根因与后续验证清单。

## 现状与证据
用户正在重新部署。旧现场 cAdvisor Docker factory 因容器内缺少 containerd socket 注册失败，仅导出 id=/；宿主机 overlayfs 且 socket 存在。另一现场曾 VictoriaMetrics 存储只读，扩容后恢复。手动编译发布曾使采集器从未知变为部分异常。

## 范围和文件
backend 启动、采集器同步/编译/发布、硬件/无线发现轮询导出；Docker Compose、部署入口、vmagent 与 Grafana 查询；相关现有测试。业务文件只读，不修改部署，不提交推送。

## 分工
主 Agent：部署和 cAdvisor、指标抓取、集成审查、统一文档。
Luna audit_autosync：自动编译发布和初始化/调度/重试，只读。
Luna audit_hardware_wireless：硬件与无线发现/轮询/导出，只读。
执行者不创建子 Agent、不写共享文件。

## 步骤
1. 核对当前代码/近期改动与已有现场证据。
2. 逐条追踪启动、触发、落盘、运行时加载与查询。
3. 运行最小现有测试或静态复核，验证可复现缺陷。
4. 写 walkthrough，区分确定缺陷、推断和新现场待验证项。

## 验证计划
聚焦自动同步恢复、部署契约、编译器、硬件和无线现有测试；不依赖真实设备，不写生产库。记录实际命令/结果。

## 风险和回滚
审查不改变业务代码或运行服务；仅新增计划和审查报告。保留用户已有改动。不将单测或旧机器证据视为新机器部署已验证。
