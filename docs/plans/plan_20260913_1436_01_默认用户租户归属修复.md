# 默认用户租户归属修复计划

## 目标

修复 Docker 全新部署后默认 `admin` 无租户、资产批量导入因此返回 403 的问题；同时确保通过用户管理创建的新账号继承已认证管理员的租户，不能由请求体伪造跨租户归属。

## 现状与问题

- `users.tenant_id` 的基线默认值为空。
- 初始化逻辑先回填已存在的 `admin`，之后才创建缺失的默认管理员；首次初始化会留下空租户的 `admin`。
- 资产导入创建关联设备时依赖认证用户 `tenant_id`，缺失会按安全策略返回 403。
- 用户管理创建用户的 SQL 未写入 `tenant_id`；前端不提供租户选择，因此新用户必须继承认证 actor 的租户，并在 actor 缺租户时拒绝创建。

## 影响范围与拟修改文件

- `backend/database/schema.py`：新建默认管理员时明确写入 `tenant-default` / `role-admin`。
- `backend/database/migrations/m0228_admin_tenant_assignment.py`：幂等修复已有空租户默认管理员，仅处理 `username='admin'`。
- `backend/api/users.py`：将新账号绑定到认证管理员租户；拒绝无租户 actor，不信任请求中的 `tenant_id`。
- `backend/tests/security/test_audit_regressions.py`：覆盖默认管理员租户归属。
- `backend/tests/security/test_user_tenant_assignment.py`：覆盖租户继承、伪造租户拒绝覆盖、无租户拒绝、未认证拒绝。
- `backend/tests/database/test_m0228_admin_tenant_assignment.py`：覆盖 PostgreSQL 升级回填、幂等性及不修改其他用户。
- 对应 `docs/walkthrough/` 完成报告。

## 实施步骤

1. 新建 version 228 PostgreSQL 数据迁移，对已有默认 admin 的空 `tenant_id` / `role_id` 做窄范围回填。
2. 让新建默认 admin 的 INSERT 自身带上默认租户与角色，避免再生成无归属记录。
3. 用户管理创建路径仅继承认证 actor 的租户；若 actor 未分配租户则 fail closed；忽略客户端提交的租户值。
4. 补数据库迁移、默认管理员 bootstrap 和用户 API 的 PostgreSQL 回归测试。
5. 运行定向 PostgreSQL pytest、PostgreSQL-only policy scanner、diff 检查；此项修复将与调度锁/时区修复一同按后续明确授权提交并推送，不操作用户 Docker 主机。

## 分工与文件边界

- 主 Agent 负责所有文件修改、测试、迁移审查与最终集成。
- `user_tenant_contract_audit` 子 Agent 只读审查用户创建契约与测试，不修改文件。
- 主 Agent 独占上述代码/测试/文档文件；保留其他工作区中所有未提交改动。

## 验证计划

- 定向测试：默认管理员 bootstrap、用户 API 租户绑定/拒绝路径、`m0228` PostgreSQL backfill/idempotency。
- 执行 `python scripts/validate_postgresql_only.py`。
- 检查 workflow 外的代码差异和 `git diff --check`；本次不要求全量前端测试。
- 若本地未安装 pytest 或无法连接测试 PostgreSQL，记录具体阻塞并完成静态验证，不连接或修改生产数据库。

## 风险与回滚思路

- 迁移只把默认 `admin` 的空租户归到已有 `tenant-default`，不更改其他空租户用户，也不覆盖非空管理员租户。
- 用户 API 新逻辑会拒绝 tenantless 管理员创建账号，避免错误分配；默认 admin 需先由启动迁移修复。
- 回滚应用代码不应撤销已完成的数据回填；如需回滚迁移代码，可移除该版本迁移，但不将 admin tenant_id 再清空。
