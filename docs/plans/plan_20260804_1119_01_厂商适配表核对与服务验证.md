# 厂商适配表核对与服务验证计划

> 时间：2026-08-04 11:19（Asia/Shanghai）  
> 任务：用用户提供的厂商适配 Excel 做静态契约核对，并在服务恢复后复核 TextFSM 注册表页面。  
> 约束：只读分析，不修改 Excel、不改业务代码、不写入现有租户/设备数据，不执行真实设备命令或 Playbook Apply。

## 目标

1. 核对锐捷、迪普、迈普、中兴四家厂商的 CLI、回显样例、作用说明与平台注册表的 canonical platform/action/template 契约。
2. 识别设备角色的“不支持/未启用”边界、空回显、平台命名别名和型号覆盖缺口。
3. 在服务正常后复核注册表页面的模板加载、厂商筛选、SYSTEM 只读门禁和中英文跟随系统的页面入口。
4. 将静态证据与仍需外部授权/设备证据的事项分开，避免把 Excel fixture 当成在线验收。

## 输入与范围

- Excel：`C:/Users/Administrator/Desktop/中兴锐捷迪普迈普厂商适配模板(1).xlsx`
- 页面：`http://192.168.42.1:5400/automation/textfsm-registry`
- 代码契约：`backend/core/textfsm.py`、`backend/services/operational_data_service.py`、`backend/services/platform_registry_service.py`
- 本轮不执行：模板 Fork/保存/发布、上传样例、真实设备 SSH、Playbook Dry Run/Apply、生产租户写入。

## 执行步骤

1. 使用 artifact-tool 只读导入工作簿，读取每个 sheet 的 used range；不导出、不覆盖原文件。
2. 统计命令行数、回显覆盖、显式能力标记、型号清单及敏感字段关键词；只保留汇总，不把原始回显复制到仓库。
3. 将表格平台标签归一到平台注册表 canonical platform，并对照已发布模板/动作命令。
4. 登录当前服务，等待注册表 API 完成加载，按厂商筛选并切换一个 SYSTEM 模板，检查内容是否随模板更新。
5. 将结果写入对应 walkthrough，并同步更新最终收口任务清单；不修改代码。

## 验收口径

- 表格结构、行数、平台别名、空回显和“不支持/未启用”标记均有可复核统计。
- 规范平台别名不得被误判为新平台：`ruijie_os → ruijie_rgos`、`DPTech → dptech_ios`、`MyPower → maipu`、`中兴 ZXROS → zte_zxros`。
- 页面加载后能看到模板总数，厂商筛选能看到对应 SYSTEM 模板；SYSTEM 显示只读，Fork 可见，Sandbox/上传在当前能力门禁下不可用。
- 不把静态 fixture 结论升级为“真实设备在线识别已完成”。

## 风险、回滚与数据保护

- 工作簿回显可能包含口令/序列号/MAC/地址等敏感或准敏感信息；仓库文档只写数量、命令和状态，不写原文。提交前仍需人工脱敏确认。
- 发现命令名称空格、连字符或别名差异时，先进入契约决策清单，不在本轮擅自改代码或批量重命名。
- 浏览器验证仅读现有 SYSTEM 数据；若服务再次断开，记录具体错误并停止写操作，不使用生产租户替代测试租户。
