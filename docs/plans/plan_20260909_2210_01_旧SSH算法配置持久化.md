# 旧 SSH 算法配置持久化实施计划

## 任务目标

将第一阶段的 SSH 算法 profile 从临时连接上下文扩展为可持久化的设备/资产配置，使需要 `legacy_break_glass` 的跨厂商设备在资产纳管、巡检、备份、拓扑、调度和 PAM 会话中持续使用明确的算法策略。

## 现状/问题

- 第一阶段已在通用传输层实现 `auto`、`modern`、`legacy_compat`、`legacy_break_glass`，默认 `auto` 可覆盖附件中的安全 legacy 交集。
- `ssh_algorithm_profile` 当前仅能通过部分连接请求临时传入，设备和资产 CRUD 未保存该字段；极老设备无法在后台任务中持续选择 break-glass profile。
- 设备与 `physical_assets` 是双向同步关系，必须保证创建、更新、关联同步、读取和导入链路不丢失该配置。

## 影响范围

- PostgreSQL schema/migration：`devices`、`physical_assets` 新增 profile 字段及约束。
- 后端设备/资产 CRUD、同步和连接上下文。
- 前端资产/设备表单、类型、导入/导出及安全提示。
- PAM session 使用持久化 profile。

## 拟修改文件与分工

- 主 Agent：`backend/database/migrations/`、`backend/database/schema.py`（仅必要的 fresh-install 对齐）、`backend/api/devices.py`、`backend/api/assets.py`、`backend/api/pam.py`、同步/查询调用方及后端测试。
- 前端 Agent：`src/pages/AssetManagement/`、`src/pages/InventoryDevicesTab.tsx`（如实际存在）、`src/types.ts`/领域 types、相关 API/导入测试；只修改 SSH profile 字段呈现、校验和提交，不改后端文件。
- 共享契约：字段名 `ssh_algorithm_profile`；允许值 `auto`、`modern`、`legacy_compat`、`legacy_break_glass`，未知值后端归一化为 `auto`；默认 `auto`。

前端 Agent 已完成其边界：资产及独立设备表单的配置下拉、导入/导出映射、列表/详情展示、break-glass 确认和前端测试，未修改后端或数据库。

## 实施步骤

1. 检查现有 migration runner、devices/physical_assets 建表和所有 CRUD/sync 查询。
2. 新增幂等 PostgreSQL migration，在两张表增加非空默认 `auto` 的 profile 字段，并添加允许值 CHECK 约束；不回填为 break-glass。
3. 更新后端创建、更新、读取、关联资产同步、连接测试和 PAM session，使 profile 全链路传递并安全归一化。
4. 更新前端表单/类型/导入映射，默认自动兼容；选择 break-glass 时显示风险提示和确认，不在输入过程中强制重置。
5. 增加 migration、CRUD、vendor-platform、profile 传递和前端 lint/交互回归测试。

当前实际实现：migration 215 已加入两张表；后端设备/资产创建、更新、导入、双向同步、连接测试和 PAM 审计已接入；前端 profile 入口和导入/导出契约已接入。

交付门禁结果：后端 profile/migration/连接相关 focused 回归 24 passed；设备租户与持久化回归 6 passed；前端 lint 通过、相关测试 15 passed、隔离目录生产构建成功。PostgreSQL-only 扫描仍只有仓库既有 m0211 PRAGMA 违规。

## 验证计划

- PostgreSQL fresh schema 与从上一版本升级 migration 测试。
- 后端 profile CRUD、资产/设备双向同步、PAM/连接测试和现有 SSH focused tests。
- Cisco、Huawei、H3C、Ruijie 的 vendor→platform→driver→profile 回归，并验证 vendor 切换不残留旧 profile。
- `npm run lint`，必要时 `npm run build`；运行 PostgreSQL-only scanner。
- 不连接真实设备，不修改设备配置。

## 风险与回滚思路

- migration 采用 `ADD COLUMN IF NOT EXISTS` 和幂等约束；downgrade 保留字段以避免破坏已配置的纳管策略。
- break-glass 仅显式选择，默认不启用；前端提供风险提示，后端再次校验并归一化。
- 若 CRUD 或前端回归失败，可单独回滚 profile 字段读写改动；数据库新增字段保留不影响旧版本读取。
