# 实施计划 - 兼容全量SSH算法与修复Docker配置备份时区

## 1. 任务背景与目标

1. **SSH 算法兼容问题**：
   - 用户在访问 Web 终端 (`/access/workspace`) 登录老旧网络设备时报错：`✗ ssh_connection_failed: No matching MAC algorithm found, sent hmac-sha2-256-etm@openssh.com,hmac-sha2-512-etm@openssh.com,hmac-sha2-256,hmac-sha2-512 and received hmac-md5,hmac-sha1,hmac-sha1-96,hmac-md5-96`。
   - 根因：`backend/api/pam.py` 在调用 `asyncssh.connect` 时，未开启 `PAM_ALLOW_LEGACY_SSH` 时仅显式传入了 4 个 SHA2 系列 MAC 算法；即便开启也遗漏了 `hmac-sha1-96`、`hmac-md5-96` 以及 `ssh-dss` 等；同时 `backend/drivers/ssh_compat.py` 的算法列表中也缺少部分老旧设备算法。
   - 目标：将 AsyncSSH 的 `encryption_algs`、`kex_algs`、`mac_algs`、`server_host_key_algs` 设置为全面兼容全量算法（优先现代安全算法，自动向后兼容 legacy 算法），同步补全 `ssh_compat.py` 算法列表和 Paramiko 驱动连接参数，确保各类老旧设备无缝连接。

2. **Docker 时区与配置备份时间不一致问题**：
   - 现象：Docker 部署后首页（Dashboard/Monitoring 等）时间正常，但配置备份（Config Backup）处的时间偏差 8 小时。
   - 根因：
     1. `Dockerfile` 基于 `python:3.10-slim`，默认未安装 `tzdata` 包，导致容器即使设置环境变量 `TZ=Asia/Shanghai` 也无法生效系统时区；
     2. `backend/api/configs.py` 和 `backend/services/config_backup_policy_service.py` 中使用了 `datetime.now().isoformat()`（朴素 naive datetime），在 UTC 容器环境下生成类似 `2026-08-18T03:52:00` 的无时区标记字符串；而首页/监控等模块使用的是 `datetime.now(timezone.utc).isoformat()`（带 `+00:00` 或 `Z`）；
     3. 浏览器端 JavaScript `new Date("2026-08-18T03:52:00")` 缺少时区信息时会当作本地时间处理，导致比实际时间慢 8 小时。
   - 目标：
     1. `Dockerfile` 中安装 `tzdata` 并设置默认时区，`docker-compose.yml` 注入 `TZ`；
     2. `backend/api/configs.py` 统一采用 `datetime.now(timezone.utc).isoformat()` 写入时间；
     3. 前端 `ConfigBackupTab.tsx` / `ConfigDiffViewTab.tsx` 等时间格式化函数增强对无时区历史数据的容错解析（自动识别 UTC ISO 格式并转换本地时间）。

3. **约束条件**：
   - 今天所有的代码不要 push 到远程仓库（严格遵守）。

---

## 2. 影响范围与拟修改文件

1. **SSH 算法全量兼容**：
   - `backend/api/pam.py`：动态获取并注入 AsyncSSH 全部支持的加密、KEX、MAC 及 HostKey 算法。
   - `backend/drivers/ssh_compat.py`：补全 `LEGACY_MAC_ALGORITHMS`（添加 `hmac-md5`, `hmac-md5-96`, `hmac-sha1-96` 等）、`LEGACY_HOST_KEY_ALGORITHMS`（添加 `ssh-dss`）、`LEGACY_CIPHERS`。
   - `backend/engine/drivers/linux_driver.py`：添加 `disabled_algorithms={}` 保持兼容。
   - `backend/tests/pam/test_ssh_compat_algorithms.py`：增加针对 AsyncSSH 与 SSH 兼容参数的全量算法回归测试。

2. **Docker 与配置备份时区修复**：
   - `Dockerfile`：在 apt-get 安装列表中增加 `tzdata`，并配置 `ENV TZ=Asia/Shanghai`。
   - `docker-compose.yml`：在 `netops`, `db`, `nginx` 服务中增加 `TZ=${TZ:-Asia/Shanghai}` 环境变量及 `/etc/localtime` 挂载兼容。
   - `backend/api/configs.py`：将所有 `datetime.now().isoformat()` 替换为带 UTC 时区的 `datetime.now(timezone.utc).isoformat()`。
   - `backend/services/config_backup_policy_service.py`：将 `_utc_now_iso()` 修正为带 UTC 时区。
   - `src/pages/ConfigBackupTab.tsx` 与 `src/pages/ConfigDiffViewTab.tsx`：完善时间解析函数，支持历史数据与 UTC 格式的高容错展示。

## 3. 实施步骤

1. **步骤 1**：修改 `backend/api/pam.py` 与 `backend/drivers/ssh_compat.py`，实现 SSH 算法全量兼容。
2. **步骤 2**：修改 `Dockerfile` 与 `docker-compose.yml`，解决 Docker 容器内部 `tzdata` 与时区支持。
3. **步骤 3**：修改 `backend/api/configs.py` 与 `backend/services/config_backup_policy_service.py`，统一配置备份的时间戳为标准 UTC ISO 格式。
4. **步骤 4**：优化前端 `src/pages/ConfigBackupTab.tsx`、`src/pages/ConfigDiffViewTab.tsx` 的时间解析和展示逻辑。
5. **步骤 5**：编写并运行自动化测试（pytest），验证 SSH 算法解析与时间格式转换。
6. **步骤 6**：生成验收报告 `docs/walkthrough/walkthrough_20260818_1150_01_兼容SSH算法与修复配置备份时区.md`。

## 4. 验证计划

1. **SSH 算法验证**：
   - 验证 `get_all_asyncssh_algorithms()` 返回的算法列表中包含 `hmac-md5`, `hmac-sha1`, `hmac-sha1-96`, `hmac-md5-96` 以及 `diffie-hellman-group1-sha1`, `ssh-rsa`, `ssh-dss` 等。
   - 模拟连接参数注入，验证不再报 `No matching MAC algorithm found`。
2. **时区与时间戳验证**：
   - 验证 `configs.py` 生成的 snapshot 与 backup run 的时间戳格式均带 `+00:00` 时区。
   - 验证前端在不同时间戳格式（带 `Z`、带 `+00:00`、无时区历史格式）下均能正确按本地浏览器时区格式化显示。
3. **回归测试**：
   - 运行 pytest 单元测试套件。
