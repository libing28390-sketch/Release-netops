## 1. 任务背景与核心诉求

用户对当前监控报表页面（`/monitor/reports`）提出了明确的产品与交互改进意见：
> "这个监控报表做的不咋好看啊，我想要的是表格的方式展示，然后支持高级选项来搜索，这样才更人性化吧"

**现有痛点**：
- 当前页面仅有 3 张静态下载卡片和简单的文本说明，用户无法在页面上直接查看报表数据，缺少数据洞察感；
- 缺乏在线检索和数据筛选能力，无法根据特定站点、厂商、设备角色、接口状态或利用率阈值进行针对性排查；
- 视觉层次单薄，缺少现代网络运维平台应有的 KPI 概览与可视化状态标识。

**本次重构目标**：
1. **在线表格化展示（Table View）**：
   - 将原有的静态下载卡片升级为**全交互式专业数据大表**；
   - 支持 Tab 切换三大核心报表维度：【全网接口流量与利用率】、【网络设备运行与资源】、【互联网出口与 WAN 链路】；
   - 表格支持列点击排序、分页（10/25/50/100条）、斑马纹、利用率动态彩色进度条、状态健康徽标；
2. **人性化高级搜索与多维筛选（Advanced Filters）**：
   - 快速关键词搜索（设备名、管理IP、接口名、描述实时过滤）；
   - 高级筛选抽屉/折叠栏：支持站点（Site）、厂商（Vendor）、设备角色（Role）、运行状态（UP/DOWN/异常）、利用率阈值（全部 / >50% / >70% / >85%）、错包过滤；
   - 筛选标签实时高亮展示，支持一键清空与重置；
3. **KPI 聚合概览卡片（Metrics Summary）**：
   - 顶部提供 4~5 项关键指标概览（总数、UP数、超负荷预警数、错包端口数、平均利用率/负荷），直观展现全网态势；
4. **导出能力无缝协同（Export Integration）**：
   - 表格右上角提供【导出当前筛选数据 (Excel/CSV)】与【导出全量多工作表完整报告 (Excel/CSV)】；
   - 导出保持 UTF-8 BOM，彻底杜绝 Excel 中文乱码。

## 2. 影响范围与拟修改文件

### 2.1 后端服务与 API 扩展
- **`backend/services/monitoring_export_service.py`**：
  - 提炼结构化数据提取函数 `fetch_interfaces_report_data`、`fetch_devices_report_data`、`fetch_outbound_report_data`；
  - 返回带有 summary KPI 统计、items 列表、options 选项（厂商/站点/角色列表）的完整数据结构；
  - 原导出函数复用该数据源，并支持传入筛选参数，实现“按筛选导出”。
- **`backend/api/monitoring_v1.py`**：
  - 新增 `GET /api/monitoring/reports/data` 端点，支持入参 `report_type` 及各类筛选条件，供前端表格与 KPI 实时查询；
  - 增强 `/api/monitoring/export/interfaces`、`devices`、`outbound` 端点，支持接收筛选参数。

### 2.2 前端页面与交互重构
- **`src/pages/MonitoringReportsPage.tsx`**：
  - 全面重构页面：
    - 顶部 PageHero + 快捷操作（直达 Grafana、导出当前筛选、刷新）；
    - 报表类别 Tab 切换（接口流量与利用率 / 设备运行与负荷 / 互联网出口）；
    - 动态 KPI 统计卡片网格；
    - 搜索框 + 展开/折叠高级筛选面板（站点、厂商、角色、状态、阈值）；
    - 交互式数据表格（排序、分页、状态点、进度条、错包高亮、处置建议）；
    - 导出弹窗/按钮无缝调用后端导出。

### 2.3 测试与验证
- **`backend/tests/monitoring/test_monitoring_export_service.py`**：补充对新增数据查询与筛选导出的测试用例。
- 前端测试：`npx vitest run src/utils/routeContext.test.ts`
- 前端生产构建：`npm run build`
