# IPAM 页面布局自适应计划

## 任务目标

修正用户截图中 IP 定位 ARP 表与 IP 地址列表在不同窗口宽度下的拉伸、溢出和窄列文字竖排问题，同时统一 IPAM 页面容器的宽度与高度收缩行为。

## 现状与问题

- IP 定位页 ARP 表使用自定义 grid 表格，但表格高度随记录和页面滚动容器增长，表头和分页不能稳定留在可视区域；列宽在小窗口下可能被压缩。
- IP 地址列表包含 15 列，普通 auto table layout 会在有限宽度中挤压列，状态/用途/角色徽标可能折行甚至逐字竖排；页面缺少明确的最小可读表宽度。
- IPAM 内容承载层未显式设置 `min-w-0`，内部宽表可能把父级 flex 布局撑开。
- 工作区已有未提交 IPAM 改动，本次仅在现有状态上调整页面布局，不覆盖或回滚既有业务逻辑。

## 影响范围

- 前端公共承载层：IPAM root 与内容区域的 flex 收缩、宽度约束。
- IP 定位页：ARP 表工具栏、表格滚动区、列宽与固定分页。
- IP 地址页：筛选工具栏换行、表格最小宽度、列内容不换行与紧凑行高。
- 不改接口、数据、路由、采集行为或数据库。

## 执行分工与文件边界

- 主 Agent：维护本计划/走查，负责 `src/pages/IPAMManagementTab.tsx` 公共容器与最终集成。
- 前端 Agent A：只负责 `src/pages/IPLocatorPage.tsx` 中 ARP 表页的响应式布局。
- 前端 Agent B：只负责 `src/pages/IPVlan/IPAddressTab.tsx` 中筛选区和列表布局。
- 所有执行者共享工作区；不得覆盖其他人或用户的修改，不创建或运行测试/构建。

## 实施步骤

1. 为 IPAM flex 承载层补齐 `min-w-0` 和内部高度约束，避免长表把主内容区撑宽。
2. 将 ARP 表页调整为视口内固定工具栏、可滚动结果区和固定分页；给列设置可读最小宽度，并让窄屏横向滚动而不是挤压文字。
3. 优化 IP 地址筛选区的响应式换行和表格列宽；合并资产编号/序列号为资产信息列，状态、用途、角色等徽标保持单行，低频长字段截断并保留 title 查看。
4. 静态审查差异和 `git diff --check`；不运行测试、lint、构建或浏览器验证。
5. 写入配对 walkthrough，说明修改、验证边界和剩余风险。

## 验收标准

- IP 地址表徽标不再被压成逐字竖排；超出视口时由表格容器横向滚动。
- IP 地址筛选项在窄窗口下能整齐换行，不挤出内容区。
- ARP 表结果区在不同视口高度下独立滚动，过滤工具栏与分页可见。
- IPAM 内部宽内容不扩大主内容视口；页面仍能在横向滚动中查看完整列。
- 不改变任何后端/API/数据行为或既有工作区业务修改。

## 验证计划

- `git diff --check`。
- 静态检查容器 `min-w-0`、表格滚动区、响应式工具栏和单行徽标 class。
- 按本轮协作要求不运行测试、lint、构建或浏览器验收。

## 风险与回滚思路

- 表格最小宽度会在窄窗口产生横向滚动条，换取列内容可读；不会隐藏或丢弃用户数据。
- 若 ARP 固定结果区与低高度视口冲突，可回退该页 wrapper 的 `min-h-0/flex-1/overflow-auto` 调整，而不动采集逻辑。
- 回滚时仅恢复本次触及的三个布局文件与本计划/走查，保留其余工作区已有修改。
