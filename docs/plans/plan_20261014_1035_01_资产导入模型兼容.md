# 资产导入模型兼容修复

## 任务目标

修复 GitHub Actions 中资产批量导入相关测试因 `AssetCreate` 缺少 `remote_desktop_profiles` 属性而失败的问题，同时保留 HTTP 导入请求的 `AssetImportCreate` 契约。

## 现状与问题

- 提交 `43d43459` 为批量资产导入增加了 `AssetImportCreate`，远程桌面配置字段由该模型提供。
- FastAPI 请求校验会把 HTTP 请求解析为 `AssetImportCreate`。
- 现有测试直接调用 `import_assets()`，传入历史 `AssetCreate` 对象，绕过 FastAPI 的请求模型解析。
- 导入行逻辑无条件读取 `body.remote_desktop_profiles`，使原有资产导入路径抛 `AttributeError`；Actions 日志显示 11 个测试失败，根因一致。

## 影响范围

- 修改 `backend/api/assets.py`：在批量导入函数入口兼容旧的 `AssetCreate` 实例，并将其规范化为 `AssetImportCreate` 后再进入导入行逻辑。
- 新增本任务计划、配套 walkthrough 和提交修复记录。
- 不改变 HTTP 请求字段、数据库结构、导入事务或远程桌面配置保存语义。

## 实施步骤

1. 保留 `/assets/import` 使用的 `list[AssetImportCreate]` 请求契约。
2. 在直接调用/内部调用入口将 `AssetCreate` 通过其 `model_dump()` 规范化为 `AssetImportCreate`，以默认空 profile 列表保持旧调用行为。
3. 检查差异并运行空白检查；将修复提交并推送到 `main`，由 Actions 重新验证。

## 验证计划

- 复核日志中 11 个失败是否均由同一缺失属性造成。
- 执行 `git diff --check`。
- 本地不另行运行测试；提交后核对对应 GitHub Actions 结果，使用 Actions 作为此次修复的测试验证。

## 风险与回滚

规范化仅为直接传入的旧 `AssetCreate` 模型补齐 `AssetImportCreate` 默认字段，不改变已有资产字段值。若回归，可通过 `git revert` 回滚本次单独修复提交；HTTP 请求契约仍可保持原提交行为。
