# 首页加载位置稳定

## 目标与现状
用户在前一轮登录页与首页宽度修正后仍观察到卡片轻微上下移动。本轮只处理首页异步数据引起的布局位置变化。

已确认的源码原因：标题下的额外加载提示 `p` 在资产汇总返回后卸载，消除 4px 上边距与 16.5px 行高，导致下方卡片上移约 20.5px。上一轮夹具只断言宽度与 transform，未覆盖真实 DOM 几何 y 变化，本轮补齐该证据。

## 文件与分工
- 主 Agent：`src/pages/HomePage.tsx`，必要时 `src/components/AppMainContent.tsx`，统一浏览器验证与文档。
- Luna frontend_worker：只读审查 VersionBanner、TopHeader、AppLayout 及数据下发链路；不写代码或跑重复检查。
- 保留此前粒子及首页修正和用户已有修改。认证、接口、设备与发布配置不变。

## 实施步骤
1. 保存当前已修改首页作为本轮基线，搭建内部滚动容器下的真实组件验证夹具。
2. 将标题中的加载、成功、错误信息放在稳定的描述区域；检查异步徽标、平台与资源数据对卡片起点的影响。
3. 按实际测量处理内部滚动条造成的横向变化，避免扩大至无关页面。
4. 若发现更新横幅会位移，记录其条件性行为；用户明确本次为卡片上下移动，未出现横幅，不据此擅改升级流程。

## 验证计划
- 在 1440×900、1280×720 的浏览器夹具中，逐帧采集标题、KPI、模块按钮、平台面板、快捷操作的 x/y/width/height，比较慢资产汇总、延迟主机资源、错误/成功切换。
- 显式区分 transform 变化与真实布局回流，不再用 transform=none 代替位置不变。
- 运行现有 HomePage 测试、覆盖应用源码的 TypeScript 检查及隔离 Vite 构建。
- 记录夹具与真实账号验证边界，保留可复查 JSON 与截图。

## 风险与回滚
加载与错误文字可能较长，需检查中英文和窄屏换行。回滚仅撤销本轮局部差异，保留前轮全部修改及用户现有文件。
