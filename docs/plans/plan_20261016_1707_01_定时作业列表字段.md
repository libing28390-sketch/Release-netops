# 定时作业列表字段精简计划

## 目标

将 `/automation/scheduled-jobs` 的用户作业列表改为简洁表格，列为作业名称、任务对象、执行周期（Crontab）、状态、修改人、修改时间和操作。

## 现状与问题

- 用户作业以信息密集卡片展示，名称、状态、凭据、触发次数、最近运行、审批人和创建时间等信息混在一起。
- 作业记录有 `updated_at`，但没有 `updated_by`，因此无法准确展示最近修改人。

## 影响范围

- `src/pages/ScheduledJobs/index.tsx`：用七列表格替换用户作业卡片列表。
- `src/pages/ScheduledJobs/types.ts`：声明 `updated_by` 和 `updated_at` 响应字段。
- `backend/api/scheduled_jobs.py`：创建、编辑和启停作业时写入最近修改人。
- `backend/database/migrations/m0288_scheduled_job_updated_by.py`：为已有 PostgreSQL 安装新增并回填 `updated_by`。
- `docs/walkthrough/`：记录完成摘要与验证结果。

## 实施步骤

1. 新增幂等数据库迁移，添加非空 `updated_by` 字段，并将已有作业回填为创建人或 `system`。
2. 创建作业时记录创建者为修改人；编辑和启停时记录当前操作者及时间。
3. 用户作业列表改为七列表格；执行周期列展示原始 Crontab 表达式，状态按启用状态显示。
4. 修改人显示 `updated_by`，兼容迁移前的 API 响应时回退为 `created_by`；修改时间回退为创建时间。
5. 保留详情、编辑、启停、删除操作及现有审批流程。

## 验证计划

- 运行 `npm run lint` 与前端生产构建。
- 对后端 API 与迁移文件运行 Python 语法检查及 PostgreSQL-only policy 扫描。
- 在浏览器检查七列、Crontab 文本、修改人/时间和行操作；不执行真实作业、不部署。
- 用户明确要求检查操作按钮时，运行定时作业页面的聚焦交互回归测试。

## 本轮跟进：操作列、预览和脚本跳转

- 使用通用 `TableActionHeader` / `TableActionCell` 对齐操作列表头和行内按钮；在浏览器读取实际布局边界确认右对齐基准一致。
- 作业详情只显示执行方式摘要和绑定的脚本名称，不渲染脚本正文，也不叠加脚本源码弹窗。
- 点击蓝色脚本名称跳转至 `/automation/scripts?q=<script_id>`，脚本管理页按脚本 ID 过滤结果。
- 在浏览器打开查看、编辑、启用/停用审批、删除审批入口并逐一取消；不提交编辑或审批。
- 定时作业组件测试覆盖启用和停用状态、详情预览、脚本跳转以及操作入口不发送写请求。

## 风险与回滚

- 迁移仅新增并回填一个文本元数据列，不改变现有作业调度语义。
- 回滚前端可恢复原列表；数据库字段保留以避免丢失修改人记录，旧代码会忽略该字段。
