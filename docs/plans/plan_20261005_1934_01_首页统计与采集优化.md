# 首页统计与采集优化实施计划

## 任务目标

修复首页设备统计被 `/api/devices` 无分页 200 条安全上限截断的问题，减少首页和设备资产列表中的重复重型设备请求；修复 SNMP exporter 配置重载因数字枚举键被 YAML 字符串化而失败的问题。

## 现状与证据

- 首页用 `devices.length` 和当前设备数组计算总量、在线率及平台分布；共享设备列表无分页请求最多返回 200 条，因此 313 台资产可能显示为 200 台。
- 首页和设备资产子页还会触发共享设备列表轮询；设备列表响应需经过 profile、标签和健康信息标注，日志显示 `/api/devices` 平均耗时约 3.9 秒、P95 约 15 秒，15 秒间隔会造成重叠请求风险。
- 监控配置编译时保留 `enum_values` 的 JSON 字符串键，SNMP exporter 的整型枚举映射解析失败并返回 reload 500；每次变体配置重载会重复出现。
- 日志中的 exporter 超时、无效 OID 和调度器跳过记录来自周期性采集失败及任务超时，需保留其实际失败信号，不通过隐藏日志来处理。

## 接口约束

新增 `GET /api/devices/summary?asset_type=network_device`，沿用设备列表路由的资产类型过滤语义，返回：

```json
{
  "total": 0,
  "online": 0,
  "offline": 0,
  "pending": 0,
  "unknown": 0,
  "by_platform": []
}
```

所有计数基于完整筛选集的数据库聚合；不返回单台设备详情，不执行 profile/标签/健康标注。

## 影响范围与文件边界

- 后端执行者：`backend/api/devices.py`，新增轻量汇总 API；不改前端及监控编译器。
- 前端执行者：`src/pages/HomePage.tsx`、`src/components/AppMainContent.tsx`、`src/App.tsx`，改为读取汇总 API，并停止 dashboard 与 inventory devices 子页的共享全量设备轮询。
- 主 Agent：`backend/services/monitoring_compiler.py`，仅在 exporter runtime 配置边界规范化数字 `enum_values` 键；并负责集成审查及本计划/Walkthrough。
- 不改数据库结构、不新增迁移、不改设备采集周期与真实设备配置。

## 实施步骤

1. 新增 `/api/devices/summary`，使用数据库聚合返回完整设备状态和平台统计，并应用 `asset_type` 过滤。
2. 首页增加可取消、无重叠的汇总请求与 30 秒刷新，切换首页时不再请求重型设备列表；设备资产分页页仅保留其页面自身分页请求。
3. SNMP exporter YAML 渲染前，将 metric/index/lookup 中 `enum_values` 的数字字符串键转换为整数键，拒绝无法解析及转换后冲突的键，不改变持久化 JSON 格式。
4. 审查改动和接口调用关系，更新完成记录。

## 验证计划

- 按本轮上级执行约束，不新增或运行测试、lint、构建命令；通过代码差异审查确认 API 契约一致、首页不再触发明细请求、枚举转换仅作用于 exporter 输出。
- 最终记录未执行的自动化验证及原因；不部署、不触碰生产数据或网络设备。

## 风险与回滚

- 首页统计只覆盖 `devices` 中且符合 `network_device` 类型筛选的已接入设备；资产台账中未建 `devices` 记录的资产不会被计入，避免混淆“资产数”和“可监控设备数”。
- 若计数查询与资产连接产生重复，需要按设备 ID 去重；回滚可恢复首页旧数据路径、轮询逻辑和 exporter 原始 YAML 渲染逻辑，无需数据库迁移。
- 错误或冲突的枚举键将使生成配置明确报错，避免输出 exporter 无法解析的配置；配置发布仍遵循现有流程。
