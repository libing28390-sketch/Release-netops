# 推送全部待提交代码到 main

## 目标

将当前工作区中全部产品源码、测试、数据库迁移及产品导入模板提交到 `main` 并推送 `origin/main`，确认该提交触发的 GitHub Actions 成功；如失败，定位并修复后继续推送和验证。

## 现状与问题

- 当前分支为 `main`，本地与 `origin/main` 提交图一致，工作区有尚未提交的多项功能变更。
- 变更涉及 SSH 兼容算法、资产 SN/堆叠成员采集、维护期 UI、IPAM 与拓扑等；另有大量历史构建目录、日志、内部协作文件和截图。
- main 推送会触发 `.github/workflows/release.yml` 的 Linux 发布及同步工作流。

## 影响范围

- 纳入：跟踪中的应用源码与测试、未跟踪的应用源码/测试/数据库迁移、`.env.example` 和资产导入模板，以及本次发布记录。
- 排除：`dist/` 生成输出、`.codex*`/`dist-*` 构建验证目录、日志、历史截图/PDF、内部 `.agents/`/`.codex/`/`handoff.md` 及无关历史计划记录；这些本地内容保留原样。

## 实施步骤

1. 检查分支、提交图、工作区状态和产品文件清单，确认不包含敏感配置或生成输出。
2. 运行后端发布静态门禁、前端类型检查、测试和隔离构建；本机测试数据库不可安全连接时，以隔离的 GitHub Actions 数据库作为后端 pytest 验证依据。
   - 全量前端测试暴露并发超时后，将 jsdom worker 上限设为 4、单项超时设为 10 秒，再复跑完整套件。
3. 在同一提交中加入计划、走查和 `docs/fixes/` 修复记录。
4. 显式暂存产品代码、测试、迁移、资产导入模板和本次记录，复核 staged diff。
5. 提交并推送 `main`，按提交 SHA 跟踪 Actions；失败时排查、修复、补记录、再推送并确认最终成功。

## 验证计划

- 后端：与发布工作流一致的知识测试配置检查、PostgreSQL-only 检查、`pytest --durations=25`。
- 前端：`npm run lint`、`npm run test:frontend -- --run`、`npm run build`（使用隔离输出目录保护现有 `dist/`）。
- 若资产管理旧测试夹具未填写新增必填字段，只更新夹具以满足当前资产录入契约，并重跑相关测试。
- 全量 UI 测试包含大量 jsdom 交互；限制 worker 数并给慢 runner 留出稳定的单项执行窗口。
- Git：`git diff --check`、staged 文件审核、提交 SHA 与远端 `main` 对齐。
- CI：检查该 SHA 对应的 main push 发布工作流所有 job 的最终状态。

## 风险与回滚

- 本次包含 PostgreSQL 迁移；运行迁移前应按项目顺序升级，保留数据库备份和已存在的迁移版本。
- 若 Actions 失败，优先提交最小修复并重新验证；如需撤回已推送代码，使用新的 revert commit，不改写远端历史。
- 自动发布工作流随 main push 执行；本任务仅通过获授权的 main push 触发仓库既定流程。
