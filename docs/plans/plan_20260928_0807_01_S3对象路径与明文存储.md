# S3 配置快照目录与在线文件查看

## 任务目标

将新写入的 S3 配置快照保存为可读的 `.cfg` 文本，并按 `config/年/月/日/厂商/` 分层归档。管理员可在 `/management/storage/files` 在线预览和下载快照，同时保留路径复制与既有录像存储绑定。历史 `.cfg.gz`、`.cfg.enc` 对象继续兼容查看/下载；本地快照加密方式和 S3 凭据加密不变。

## 现状/问题

- 当前新 S3 快照使用 gzip 明文，key 以 `.cfg.gz` 结尾，目录仅按年月组织且没有厂商层级。
- 文件浏览页只展示对象路径，不支持页面内查看和下载。
- PAM 录像独立绑定 `pam_recording` 用途，不应因配置快照目录调整而迁移或改写。

## 影响范围

- 配置快照存储序列化、对象 key 命名与失败重试 spool。
- 管理员对象存储 API：读取配置文本并以安全 `.cfg` 文件名下载。
- 独立文件浏览页：日期/厂商树、快照在线预览和下载。
- 存储说明、任务计划与完成记录。

## 实施步骤

1. S3 快照 key 变为 `config/YYYY/MM/DD/{vendor}/{hostname}_{time}_{trigger}_{snapshot-id}.cfg`，清理路径段中的分隔符和不安全字符；新 S3 对象写入 UTF-8 配置原文。
2. 更新上传失败 spool 与重试 key，使重试对象名与成功上传规则一致；旧快照继续按既有 gzip/Fernet 兼容路径读取。
3. 增加管理员专用对象内容 API，限制可读文件类型、校验 object key、解码历史格式并提供安全的 `.cfg` 下载名。
4. 文件浏览页保留目录懒加载、分页和路径复制，采用类似 VS Code 的双栏目录/文件布局，为配置文件提供醒目的在线预览和下载操作，以及加载与错误状态。
5. PAM 录像 key 与存储绑定保持不变，并更新存储说明和完成记录。

## 验证计划

- 检查快照上传与重试 key 的分层规则、路径段清理和失败处理。
- 检查对象内容 API 的权限、路径/文件类型限制、错误脱敏和旧格式兼容。
- 检查页面在线预览、下载、目录树和错误/加载状态。
- 实施时的初始计划不运行自动化测试；代码集成推送前已追加 lint、前后端回归用例和隔离目录生产构建，结果记录在 `docs/walkthrough/walkthrough_20260928_2338_01_代码校验与推送.md`。

## 风险与回滚思路

- 页面内容读取和下载继续要求管理员身份与后端 S3 凭据；不生成公开或匿名 URL。
- 历史 gzip/Fernet 对象不迁移、不改写；保留 `CREDENTIAL_ENCRYPTION_KEY` 才能读取加密历史配置。
- 无数据库迁移和 PAM 录像改写。回滚代码不影响对象内容，但新路径需要作为已写入对象的有效位置保留。
