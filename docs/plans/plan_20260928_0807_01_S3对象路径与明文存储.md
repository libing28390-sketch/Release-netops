# S3 对象路径展示与新文件明文存储

## 任务目标

将“对象存储”整理为父级菜单，并在其下提供“存储配置”和“文件浏览”两个子菜单。文件浏览独立成页，默认以目录树浏览 S3 对象，按需加载目录、显示对象路径并支持复制 `s3://` URI；不生成预签名 URL。新写入 S3 的配置快照不再做应用层加密；本地存储维持现有加密行为。历史加密对象保持原样并继续兼容读取。S3 访问凭据仍加密保存。

## 现状与问题

- 首版将平铺对象路径列表放在存储配置页底部，配置和文件查看混在一起；通过前缀输入过滤也不利于按目录查找。
- 对象列表 API 把后端 S3 错误统一包装为通用 503，页面只显示“服务暂时不可用”，无法判断配置、权限或服务可达性问题。
- 配置快照当前在 gzip 后使用 Fernet 加密，S3 key 以 `.cfg.enc` 结尾；PAM 录像按原始字节上传。
- S3 provider 的 Access Key 与 Secret 在数据库中加密保存，属于凭据保护，不随对象文件的加密设置改变。

## 影响范围

- 后端 S3 服务与管理员对象列表 API。
- 对象存储侧边栏父子菜单与 `/management/storage/files` 路由。
- 平台管理平铺栏目中的嵌套菜单展开和当前子项精确高亮。
- 模块侧栏叶子路由的匹配规则：仅显式设置 `activeMatch` 的菜单使用前缀匹配。
- 独立文件浏览页的 S3 目录树、按目录懒加载、对象路径复制和安全错误展示。
- 新配置快照的序列化和对象 key 命名，以及存储说明文档。

## 实施步骤

1. 在 S3 存储服务增加带 `Delimiter` 的 continuation-token 分页，返回当前目录下的对象和子目录。
2. 扩展管理员专用 API 和前端类型；错误只暴露服务端已脱敏的 S3 错误码/HTTP 状态，不返回原始 provider 文本。
3. 在导航中将“存储配置”和“文件浏览”整理为“对象存储”下的子菜单，并新增 `/management/storage/files` 路由。
   - 嵌套子项按完整路由精确高亮；对象存储父项不使用会覆盖子路由的宽泛前缀匹配。
4. 从配置页移除平铺列表，在独立文件页实现默认树形浏览、逐层懒加载、分页续读、空态/错误态和路径复制。
5. 仅新 S3 配置快照改为只 gzip、不加密，并用 `.cfg.gz` 命名；本地存储继续 Fernet 加密。S3 失败重试 spool 使用 gzip 明文并匹配目标后端；读取逻辑继续解密历史 `ENCRYPTED:` 对象。PAM 新录像继续按原始字节保存。
6. 更新存储说明，明确历史对象兼容、凭据加密和服务端静态加密的边界。

## 验证计划

- 静态检查对象列表 API 的授权、分页边界、错误脱敏和 API 类型。
- 检查新快照写入只产生 gzip 数据且旧 Fernet 数据仍走兼容解密路径。
- 检查路由与子菜单激活状态、目录树展开/折叠、延迟加载、续页、复制、无对象和请求失败交互。
- 按当前执行约束，不运行测试或构建命令；完成代码差异审阅并在完成记录中注明未执行项。

## 风险与回滚思路

- 列出对象需要所选 S3 凭据拥有 `ListBucket` 权限；权限不足时页面展示脱敏错误码和状态，具体修复仍需依据 S3 配置确认。
- HTTP Endpoint 地址本身不是签名链接，访问仍受网络可达性和 S3 授权控制。
- 历史 `.cfg.enc` 对象保持加密；保留 `CREDENTIAL_ENCRYPTION_KEY` 才能解密历史配置和存储凭据。
- 无数据库迁移和既有对象改写；回滚代码即可恢复原行为，新 S3 `.cfg.gz` 对象仍可被当前解压逻辑读取。
