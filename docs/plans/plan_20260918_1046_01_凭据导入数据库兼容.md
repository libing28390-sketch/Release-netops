# 任务目标

修复本机开发数据库在凭据 Excel 导入时因缺少 SNMPv3 凭据字段而返回 500 的问题，并兼容已经把 `m0232` 标记为已执行但字段未实际落库的历史数据库。

# 现状/问题

- `credential_service.create_credential` 在插入凭据时写入 `snmp_security_level`、`snmp_auth_protocol`、`snmp_auth_password`、`snmp_priv_protocol`、`snmp_priv_password`、`snmp_context_name`。
- 当前本机数据库 `schema_migrations` 最高版本为 239，但 `credentials` 只有旧版 `snmp_community` 与 `snmp_server` 字段。
- 原始 `m0232` 已被记录为已执行，正常重启不会再次运行，因此导入预览成功、确认写入时失败。

# 影响范围

- 仅为 `credentials` 表增加缺失的可空/默认兼容列，不改动现有凭据值、加密内容或绑定关系。
- 新安装和已经完整升级的数据库会通过幂等检查跳过已有列。

# 拟修改文件

- `backend/database/migrations/m0240_repair_credential_snmpv3_columns.py`：新增修复迁移。
- `backend/tests/database/test_m0240_repair_credential_snmpv3_columns.py`：覆盖缺列、已有列和默认值。
- `docs/deploy/windows.md` 或对应开发运维说明：记录重启后自动修复行为。
- `docs/walkthrough/walkthrough_20260918_1046_01_凭据导入数据库兼容.md`：记录验证结果。

# 实施步骤

1. 按现有迁移框架新增版本 240，使用表结构探测后逐列 `ALTER TABLE ... ADD COLUMN`，每列带与当前模型一致的默认值。
2. 不删除或重写现有凭据；让迁移在同一启动事务中完成并由框架记录版本。
3. 增加 PostgreSQL 迁移测试和凭据插入回归检查。
4. 重启本机后端，确认迁移版本和字段存在，再重试 Excel 导入。

# 验证计划

- 运行 `backend/tests/database/test_m0232_monitoring_v1.py` 与新增 m0240 测试。
- 运行凭据服务/导入相关测试（若存在）。
- 运行 PostgreSQL-only policy scanner 和 `git diff --check`。
- 使用当前本机 PostgreSQL 连接验证 migration 240 后列存在；不删除或重置任何数据库数据。

# 风险与回滚思路

- 迁移只做幂等 `ADD COLUMN`，不触碰已有数据；回滚代码不会删除新增列，以避免破坏已写入的 SNMPv3 凭据。
- 如迁移启动失败，保留数据库和日志，修复迁移后重新启动；不采用手工删列或重置数据库的方式回滚。
