# 任务目标
恢复资产 SSH 兼容算法连接和维护期已登录用户认证。
# 现状与范围
追踪导入默认值、历史策略规范化、连接器算法及维护期请求认证。保留工作区已有修改；不推送、不部署、不更改设备配置。
# 拟修改文件
SSH: backend/drivers/ssh_compat.py、backend/api/pam.py、backend/tests/pam/test_ssh_compat_algorithms.py、src/pages/AssetManagement/constants.ts 与 index.tsx 的说明文字。维护期: src/pages/AlertMaintenanceTab.tsx、alertMaintenanceApi.ts 及各自测试。备份: backend/api/configs.py 补齐策略读取、backend/tests/configuration/test_scheduled_backup_driver_dispatch.py 增加 PostgreSQL 查询回归。
# 实施与分工
主 Agent 负责 SSH、集成、记录；Luna 子 Agent 负责维护期认证，禁止编辑 SSH 与共享认证基础设施。共享验证由主 Agent 运行一次。
# 验证计划
针对性 pytest、前端测试、TypeScript、隔离构建、PostgreSQL 策略扫描；尝试浏览器复现和复测，单独报告真实设备验证边界。
# 风险与回滚
保持旧数据可读与权限校验；只回退本任务补丁，不覆盖用户变更。

## 排查结论与决策
- 当前库 17 个资产、17 个设备全部为 auto，无 modern；无策略数据迁移。
- auto/legacy_compat 旧实现仅开放有限旧算法，与资产页面保留兼容模式的预期不一致。兼容档案统一现代优先并开放底层支持的完整旧算法；显式 modern 保留原行为。
- Paramiko 4.0.0 本身不提供 ssh-dss，不降级库、不全局修改底层 Transport。
- 维护期新建漏带认证头，改用已有 apiRequest，不改变后端权限。
- 用户追问备份链路时发现常规备份 SQL 漏读 ssh_algorithm_profile，补齐透传；平台动作路径本已 SELECT d.*。
- 本地服务在浏览器复测前停止，使用既有 dev-internal.mjs 恢复；不执行生产部署。
