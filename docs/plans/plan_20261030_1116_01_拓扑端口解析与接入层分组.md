# 拓扑端口解析与接入层分组

## 目标

修复 SNMP LLDP 将二进制 Port ID 当作接口字符串导致 NUL 写库失败的问题；改进拓扑画布的节点名称可读性，并在接入设备较多时自动按连接关系分行组织。

## 现状与根因

- 用户提供的 SNMP walk 显示同一 LLDP 行 `.6` Port ID subtype 为 3（MAC Address），`.7` Port ID 是六字节 MAC，其中合法 `00` 字节被解码进字符串。`snmp_service` 当前没有读取 subtype，直接把 Port ID 当接口名称。
- 拓扑标签使用 60px 固定初始背景，名称依据同层最近节点间距截断；接入交换机汇聚在一行时名称不可辨认。
- 已有角色分层、LLDP排序与自适应画布，可扩展布局，无需引入新前端框架或数据库结构。

## 影响范围

- `backend/services/snmp_service.py` LLDP OID 收集及 Port ID typed normalization。
- `backend/services/topology_service.py`：将安全的 Port ID 子类型和十六进制证据放入诊断 payload。
- `src/utils/topologyRoleLayout.ts`：密集角色层分行及关系分组。
- `src/components/TopologyGraph.tsx`：完整换行名称、包围框、缩放及导出一致性。
- `docs/walkthrough/walkthrough_20261030_1116_01_拓扑端口解析与接入层分组.md`。

## 实施步骤

1. 同时采集 `lldpRemPortIdSubtype` 和原始 `lldpRemPortId` octets，按 subtype 区分接口文本、MAC、网络地址和本地标识。
2. 对 MAC/网络地址/线路标识 subtype 只作为端口标识证据保留，不作为接口名；优先使用可读远端端口描述。输出字符串不得包含 NUL 或替换字符伪装成接口名。
3. 密集层（优先接入层）按 LLDP 最近上联设备排序，并拆为每行最多6台；完整主机名按可用宽度换行显示，扩大背景框和碰撞障碍区域。
4. 保留人工拖动位置、层级标签、工具提示、全屏适配、SVG/PNG导出行为。
5. 执行聚焦验证和前端 lint/build，记录实测结果及边界。

## 验证计划与执行边界

- 代码修改完成后运行 Python 静态语法检查、前端类型检查和隔离构建；本次不新增或运行测试。

## 风险与回滚

- MAC Port ID 不是远端接口；无法从描述确定接口时保留邻居关系并将端口设为未知，避免伪造错误链路端口。
- 端口变为未知可能减少自动双向链路确认，但仍保存 LLDP 邻居证据。
- 布局改动只作用于生成的层级坐标；保留用户已有手动位置，允许重新选择“自动布局”恢复。
- 无数据库迁移和设备配置操作；回滚对应 service、component、layout utility 与测试改动即可。
