# Nexora 1.0.8 发布计划

## 任务目标

将当前 PostgreSQL 18、Windows 启动器、pgvector、Agent skills 和 Codex 配置变更整理为 `1.0.8`，提交到 `main`，并推送 `v1.0.8` 标签触发 Windows/Linux 发布工作流。

## 现状 / 问题

- 工作树包含 PG18 统一、Windows `psycopg2` 打包、Qt ICU 冲突过滤、启动确认/密码双输入及 Docker PG18 卷路径修复。
- 之前的 Windows 新包因 Poppler ICU 78 DLL 冲突导致 QtCore 导入失败；过滤规则修复后隔离包已通过 `SMOKE_TEST_OK`。
- 版本字段仍为 1.0.7，需要同步到 1.0.8。
- 用户明确要求将 `.agents/skills/**` 和 `.codex/config.toml` 一并提交；日志、临时 artifacts、备份和 Blender 临时文件不属于发布提交。

## 影响范围

- PostgreSQL 18.6 运行与升级契约、Windows 发布包、Docker/CI。
- FastAPI 版本信息、前端版本 fallback、Windows release notes。
- `.agents/skills/**`、`.codex/config.toml` 协作配置。
- Git `main` 提交和 `v1.0.8` 标签；推送已获用户明确授权。

## 实施步骤

1. 更新 package、lock、backend、desktop、文档和前端 fallback 的 1.0.8 版本字段。
2. 审查并纳入 `.agents/skills/**` 与 `.codex/config.toml`；排除 `.codex` 日志、`.codex_kb_refs.txt`、临时构建输出、真实/运行时备份和二进制临时文件。
3. 创建 `docs/fixes/fix_20260915_0013_01_发布1.0.8.md`，记录根因、修改、验证和回滚方式。
4. 运行发布相关定向测试、PostgreSQL-only 扫描、CI 合同检查、前端 lint/build；检查敏感文件和 staged diff。
5. 提交 `main`，确认提交图和工作树，再推送 `main` 与 `v1.0.8`。

## 验证计划

- `desktop`/数据库版本定向 pytest。
- `scripts/knowledge_eval_ci_gate_check.py` 与 `scripts/validate_postgresql_only.py`。
- `npm run lint`、`npm run build`。
- `.github/workflows/release.yml`、Docker Compose 和 `NetOps.spec` 解析/契约检查。
- 已验证隔离 Windows EXE 的 SHA-256、归档无 Poppler ICU、`--smoke-test` 返回 0 且写入 `SMOKE_TEST_OK`。
- commit 前检查 staged 只包含授权路径，且不存在真实凭据。

## 风险与回滚思路

- 推送 tag 会触发远端发布工作流；若 CI 失败，保留 tag 便于诊断，修复后通过新提交重新触发，不回滚用户数据库。
- PG17→18 仍需用户按备份、`pg_upgrade` 或逻辑备份恢复迁移；代码发布不会自动转换数据目录。
- 若发布工作流发现 Windows 干净环境缺少系统 ICU，停止发布并改为随包提供匹配的 Qt ICU 运行库。

## 文件边界

- 纳入：本任务代码、测试、部署文档、`docs/plans`、`docs/walkthrough`、`docs/fixes`、`.agents/skills/**`、`.codex/config.toml`。
- 排除：`.codex` 日志与 agent 运行时 TOML、`.codex_kb_refs.txt`、`artifacts/` 临时构建和诊断输出、`data/backups/`、Blender `.blend1` 临时文件、根目录 PG17 临时 ZIP。
