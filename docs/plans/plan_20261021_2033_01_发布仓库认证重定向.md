# 发布仓库认证重定向

## 目标
修复 Release and Sync workflow 向 Release-netops 推送时 GitHub URL 重定向后交互式读取用户名失败的问题，并验证主分支和版本标签两种推送使用相同的认证方式。

## 现状与证据
main 已推送到 42a20d63；Actions #748 两次均通过后端/前端检查，但发布目录的 `git push` 在 GitHub URL 重定向后失败并尝试提示 Username。无认证 `git ls-remote` 可以读取目标仓库。现有 workflow 把 `RELEASE_REPO_TOKEN` 嵌入 remote URL。

## 拟修改文件
- `.github/workflows/release.yml`
- `backend/tests/release/test_release_repo_push_auth_contract.py`
- 本计划、对应 walkthrough、新增 docs/fixes 记录

## 实施步骤
1. 通过仅对 git push 生效的 GitHub HTTP Authorization header 传递 token，去除 remote URL 中的凭据；遮罩编码后的认证头。
2. 确认 main 和版本 tag push 都使用该 header，缺失 secret 时给出清楚错误。
3. 用纯配置契约测试验证工作流，不访问真实 secrets 或发布仓库。
4. 提交到 main 并观察精确 Actions run。生产发布仓库写入只由受保护的 Actions secret 执行。

## 验证与风险
运行新建 release contract pytest、`git diff --check` 和质量门必要配置检查。Secret 内容只从 GitHub Actions 环境读取，认证不写入 git remote 或版本库。失败时可 revert workflow/test/docs 提交；目标发布仓库是否更新以 Actions 为准。
