# 配置备份页移除文件归档实施计划

> 创建时间：2026-10-13 08:12（Asia/Shanghai）
> 任务范围：移除配置备份中的外部 SFTP/FTP/TFTP 文件归档能力及页面顶部刷新按钮，保留 S3 对象存储能力

## 1. 目标与边界

从配置备份 UI、自动备份策略、后端 API 与运行流程中彻底移除自建/远程文件归档（SFTP、FTP、TFTP）：归档服务器凭据设置、连通测试、单快照上传、批次 ZIP 推送和定时策略推送。移除配置备份页 PageHero 右上角“刷新”按钮。

继续保留：

- 备份中心列表、详情、设备配置采集/恢复/删除、差异和历史数据。
- `config_snapshot_storage.py` 与 `storage_service.py` 中配置快照的 S3 写入、读取、删除、重试/迁移及相关状态。
- `/api/storage/status`、S3 存储健康检查/手动检查、旧对象迁移状态。
- 备份策略的计划任务、范围、运行/启动配置、留存版本和正常备份 Job。
- 备份记录既有的归档执行历史数据；本次不删审计历史或 S3 对象。

页面中“旧版本地文件/本地暂存副本”是 S3 迁移/失败重试状态，不是远端归档功能，因此保留。历史备份详情仍保留自身的刷新动作；只移除页面最上方刷新按钮。

## 2. 现状与证据

- 主页面：`src/pages/ConfigBackupTab.tsx`；File Archive 按钮、FTP-family 设置弹窗、单快照上传、批次归档与 PageHero 刷新集中在此。
- 自动策略：`src/pages/ConfigSchedule/BackupPolicyManager.tsx` 含协议、服务器、账号、密码及自动归档字段；API 位于 `backend/api/config_backup_policies.py`，持久化逻辑位于 `backend/services/config_backup_policy_service.py`。
- `backend/api/configs.py` 含 `/configs/tftp/*` 设置、探测、快照/批次上传 endpoints，并在 scheduled backup 结束后向远端服务器 offload ZIP。
- `backend/services/file_transfer_service.py` 与 `tftp_service.py` 为归档传输支持；实现前核实并清理全部 call sites，确认无其他功能复用。
- `config_backup_policies` 保存加密传输凭据，`global_vars` 可存 `tftp_backup_settings`。升级数据库应清理这些已弃用的目标配置/凭据，禁用策略的外部上传字段；保留旧迁移文件及历史 `config_backup_runs` 审计字段/记录。
- 当前 Compose 默认备份路径为 S3 服务层；此任务不改变 S3 provider、bucket/key contract、既有 S3 对象绑定或存储迁移机制。

## 3. 拟修改文件

### 后端

- `backend/api/configs.py`：删除远程归档专属 schema/helpers/routes、单条/批次传输、定时备份 post-run archive offload；移除写入和 API 响应中的归档配置字段；从 detail API 隐去历史归档字段；不改核心 S3 snapshot lifecycle。
- `backend/api/config_backup_policies.py`：移除 FTP-family 字段与协议验证。
- `backend/services/config_backup_policy_service.py`：停止读取、解密、加密、写入、返回和更新这些配置项，调整 policy SQL 占位符。
- 若确认没有其他调用者：删除 `backend/services/file_transfer_service.py`、`backend/services/tftp_service.py` 及仅验证这些服务的 `backend/tests/configuration/test_tftp_backup_service.py`。
- 新增 `backend/database/migrations/m0284_retire_config_file_archive.py`：幂等停用既有策略的远端上传字段，清除遗留 `tftp_backup_settings` 和策略中的加密目标密码/账号/地址；保留旧列以兼容回滚，不删历史运行结果、对象或既有迁移。
- 删除远端传输专属测试文件，更新 `test_startup_config_backup.py` 中其余策略/备份完成契约，不引入新测试。

### 前端

- `src/pages/ConfigBackupTab.tsx`：删除 FTP-family 类型/状态、settings/test/sync 请求、归档按钮与弹窗、单快照/批次上传操作、归档日志展示；删除 PageHero 顶部 refresh 动作与依赖；保留 storageStatus 和运行中加载图标。
- `src/pages/ConfigSchedule/BackupPolicyManager.tsx`：删除策略中的文件传输类型/密码字段和自动远端归档表单；保留 scheduled backup、设备范围与 running/startup 配置能力。
- 只在 S1 确认某个 import/type/message 唯一用于上述功能后才删；不清理其他模块通用的 archive/S3 状态文案。

### 文档

- 本计划与对应 walkthrough 归档在 `docs/plans/` 与 `docs/walkthrough/`。

## 4. 实施步骤

1. 复核目标模块调用链和 Git 状态，确认 file transfer service 无其他用户。
2. 先删前端归档入口和状态，再移除计划策略 UI/API payload 字段及后端持久化读写；保留策略业务校验与正常 scheduler。
3. 从 scheduled config run 剥离 FTP-family network I/O；从 configs router 移除专用设置、测试、快照/批次同步 endpoints。S3 的配置快照保存仍经现有 storage service。
4. 清理只服务归档的传输模块和专属测试；更新剩余策略、backup run 契约，不能为删除功能而改写历史迁移。
5. 新增 PostgreSQL 编号迁移清理旧配置与凭据；静态核对 migration 保持幂等，保留历史备份运行与 S3 对象引用。
6. 检查 config/backup 页面无归档控件、API 调用/API schema 不再暴露归档 routes/字段，PageHero 无顶部 Refresh。保留 S3 状态面板内健康刷新及历史详情区刷新。
7. 按本次约束不新增或运行测试；运行前端 TypeScript 检查和 Python 语法检查，配合 migration SQL 静态审查、差异空白检查和定向静态检索。由于生产构建会写入现有 `dist/`，本次不覆盖该工作区产物。

## 5. 验收标准

- `/config/backup` 不显示远端文件服务器配置、探测或上传入口，也不在 PageHero 顶部显示手动刷新按钮。
- 单快照、批次、定时策略不能发起 SFTP/FTP/TFTP 网络上传；旧客户端请求无法重新保存旧归档字段。
- 新建/修改策略 API 不响应或处理归档 host/credential/protocol fields。
- 系统启动/策略运行代码不导入 FTP-family transfer helper，不执行远端 archive offload。
- 旧保存的传输凭据在 migration 后清理，archive-enabled policy 变为不执行外部推送。
- 最新/历史备份、备份策略运行、S3 health/card、S3 对象读写、下载/比较流程的既有调用链保持不变；本次不运行回归测试。
- 旧 `config_backup_runs.tftp_*` 历史结果字段与迁移日志不被破坏或外发到新前端模型。
- 无修改其它页面的刷新按钮与独立归档概念（例如模板/PAM 记录 archive）。

## 6. 验证计划

- 不新增或执行 pytest；删除仅覆盖远端传输服务与端点的过期测试文件，并更新既有策略/备份收尾契约用例，不报告测试通过。
- `npm run lint` 做 TypeScript 检查；不运行 `npm run build`，因为脚本会覆盖工作区已有 `dist/` 产物。
- 使用 `python -m py_compile` 检查变更后的后端模块语法。
- `git diff --check` 和 `rg` 检查差异空白及旧 endpoints/字段/上传函数调用；历史迁移与数据库兼容列留档属预期。
- migration SQL 面向 PostgreSQL；未运行 migration/升级验证。不得连接真实设备或对 S3 对象做删除/迁移。

## 7. 风险与回滚

- 删掉 transfer credential 会让旧协议配置不能恢复；这是功能移除的一部分。保留历史执行审计和既有 S3 对象，发布前通过迁移测试核验范围。
- 策略 API 移除传输字段时保持其余运行/启动类型和计划/设备范围契约稳定；前后端同时删除对应字段，避免旧客户端字段被持久化。
- 若后续 S3 读写或历史页面验证失败，回退服务代码。弃用凭据清理迁移不可逆；若需恢复旧协议必须重新配置凭据，不恢复旧明文或密文副本。本次仅静态审查 migration，数据库升级尚未执行。
- 不删备份文件、配置快照、S3 bucket 对象、历史 job/audit；不提交、推送或部署本任务改动。
