## 任务目标

按NetBox对标建议书启动首批整改：

1. 未知VRF不得自动登记成全局网段。
2. 地址推荐/分配只依据IP地址页当前展示的数据：正式登记记录、活动发现端点（`network_endpoints`）、每设备最新成功的CMDB接口采集结果。
3. 不读取跨历史的`ipam_discovery_observations`记录参与当前占用，不处理或清理历史快照。
4. 同租户/站点范围内、页面当前显示且VRF仍不明的具体IP，作为该host的临时保留并显式告警（`pending_discovery_count`），不推断为Global/VRF。
5. IP台账所有者与发现到的接入交换机/端口分开，避免混合列表值被编辑表单保存为正式归属。
6. 网关候选使用的接口快照没有 VRF 上下文时，只作为待确认候选展示，不自动写入 Prefix 的 `gateway_device_id` / `gateway_interface_id`。

### P2b.2 Pool/Range 策略契约

- Pool 必须能解析到明确的 `address_space_id`；首期仍通过父 Prefix 创建和展示，但服务端写入 canonical space ID。迁移只从已明确映射的 Prefix 派生；旧 Prefix 未映射的 Pool 保持待确认，不猜 Global。
- `management_mode` 使用 `local_static`、`reserved`、`external_dhcp`、`external_other`；`allocation_allowed` 决定本地正式分配，`mark_populated` 独立控制是否禁止创建单个 IP，`mark_utilized` 只影响利用率。旧 `status` 是生命周期：只有 `active` 范围可参与分配，`reserved`/`deprecated`/未知状态按 fail-closed 屏障处理。策略之间不得互相代替或从状态字段推导。
- 同一空间中的范围 overlap 按完整地址区间检查，跨父/子 Prefix 也冲突；使用 address-space advisory lock 保护检查与写入。
- 从 Prefix 分配时跳过禁止本地分配或已 populated 的 Pool；指定 `pool_id` 时需校验同空间、父 Prefix 包含、active、`local_static` 且允许分配，候选必须在该区间内。手工登记同样遵守显式 Pool 禁止策略。
- `mark_utilized` 不能阻断分配；Prefix 与 Pool 利用率分别说明其分母。外部 DHCP lease 是观测；外部 DHCP 池范围才是静态分配屏障。所有数据来自当前正式资源/当前成功来源，不读取历史 discovery observations。

### P2b.3 VIP、租约与正式写入一致性

- VIP 是正式虚拟地址资源：新建/更新必须有可验证的 address space 与 Prefix（空间由服务端从 Prefix 派生），跨 Prefix 按同一空间做冲突检查；`prefix_id` 和空间关联必须持久保存。旧 VIP 未明确空间时保持 pending，不能按裸 IP 或 tenant 猜 Global。
- DHCP lease 是外部观测：保留 source/pool/scope/有效时间；只有关联到明确 external DHCP Pool/space 时才能用于该域对账。裸 IP lease 不能成为跨域硬占用，也不因 lease 到期释放静态台账；External DHCP Pool 的范围仍阻止静态分配。
- IP、Pool、VIP、Prefix 的交叉变更在同 address-space lock 下重新校验；同多空间操作按稳定顺序加锁。Update/delete 统一 row-lock 顺序，避免地址行与 Prefix 行互锁。
- 手工登记待确认 observation 继续遵守用户确认的方案 A；观察事实只约束自动推荐/自动分配，正式 Pool policy 的明确阻断规则除外。
- 为可重试写操作补幂等键与 `revision`，将同键不同请求体作为冲突，批量写默认全回滚；正式 assignment 关系使用可验证外键，审计写入与台账事务保持一致。

## 风险与回滚思路

- 不再默认全局会使原来依赖默认推断的批量生成数量下降，这是预期的安全行为；UI必须清楚显示待确认并允许显式global。
- 无scope的旧endpoint不再消耗每个网段的分配池，可能释放此前错误冻结的地址；只对以后请求生效，不批量重分配已有地址。
- VRF未知但tenant/site匹配的页面当前观测只保留具体地址，可能短期减少可分配数；必须给出计数与发现页入口，不能推断成全网/global冻结。
- **手工登记覆盖（F3，用户已确认方案 A）**：操作者可手工登记待确认 IP，临时保留只约束自动推荐/分配；用户确认该手工操作视为明确选择。若未来需强制确认，走方案 B 另批实施。
- **持锁扫描（F4）**：分配在 Prefix 行锁内读取scope catalog、全部活动 endpoint 和当前接口观察后再在 Python 过滤。当前本地活动 endpoint 为 0，最新接口数据有 33 条带 IP；本地规模小但不能代表生产。上线前需在有代表性数据量下观察耗时，后续通过安全的 SQL 下推过滤优化。
- **候选顺序（F5）**：推荐与分配仅在 IPv6 前缀短于 `/127` 时可能因网络地址处理不同而给出不同结果；IPv4 `/31`、`/32` 与 IPv6 `/127`、`/128` 当前候选相同。此为既有问题，列为后续事项。
- **网关候选（G05）**：R1-9 已改为无 VRF 时待确认且不自动绑定；P3 仍需设备本地 context 映射，不能用通用 VRF 名称/别名补足缺失上下文。
- **工作树（F2）**：非本任务变更若被误纳入提交，会带入未审查代码并删除历史计划；所有检查和提交必须按本任务 pathspec 限定。
- 若前端无法取得正式记录或接口失败，必须停在编辑错误态，不可退回混合对象自动提交。
- 回滚代码可恢复旧规则，但会重开错误全局归属/跨域占用/观测覆盖台账的风险；本批不更改已有数据库行，故不需要数据反迁移。

## P3.1 当前 FDB/MAC-only 投影批次

### 数据契约

- `mac_table` 是 legacy 可替换缓存，缺少 VRF/local-context 与 generation；成功空表目前也可能留下旧行。因此不得把它直接作为 IPAM 当前台账来源，也不得回读旧 discovery observations。
- 新增独立 `ipam_current_fdb_observations`，在共享 `ipam_endpoint_collection_states` 中用 `observation_source='fdb'` 保存每设备/来源/context 的 generation、latest attempt/status、last-success、行数和错误码。观察键含 MAC、VLAN、接口、context，允许跨上下文同一 MAC 保留多条事实。
- 仅 latest-success 的 FDB 行展示为当前观察。complete/verified-empty 可原子替换一个上下文；partial/failed/unsupported 只更新状态并保留成功代次；scope_unknown 只替换同一未知上下文，不进入 IP 分配占用。

- 主 Agent：`m0316_ipam_current_fdb_observations.py`、`ipam_current_fdb_observation_service.py`、current endpoint 服务/API/UI 的 FDB 投影和 PostgreSQL 隔离测试、任务文档与集成审查。
