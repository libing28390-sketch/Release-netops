# LLDP 完整快照 Redis 复用

## 任务目标

将拓扑周期采集的每设备 LLDP 完整快照接入 IP Locator 的共享 Redis 缓存，使定位过程优先复用拓扑采集结果，而不是在旧/缺少 per-locator 缓存时重复执行 LLDP CLI。保留 PostgreSQL 为事实源，并在采集开始、失败、成功空快照及并发完成时正确 fencing。

## 现状与问题

- `topology_service` 已把标准化邻居 observation 存入 `topology_observations`；图 API 主要读取 PostgreSQL，周期拓扑采集未预热 locator Redis。
- IP Locator 的 topology freshness 默认 10 分钟，拓扑链路证据 TTL 默认 48 小时；locator 只查询自己的 observation 表，因而图上已有较新 LLDP 时仍可能回设备执行 CLI。
- `device_collection_status` 没有 attempt generation；它只在扫描后记录成功/失败。仅提高 Redis TTL 无法在新采集中、失败或成功空快照时可靠作废旧缓存。
- 完整空快照必须与解析失败区分，不能把 parser miss、命令错误或截断输出写成 `no_neighbors`。

## 影响范围

- 拓扑 LLDP 采集、IP Locator snapshot cache、run dependency manifest/fencing、默认 topology TTL、PostgreSQL 增量迁移。
- 不改变设备命令集、不部署或连接用户设备。用户明确要求验证 Redis 写入后，最多执行一次 `nexora:*` 下唯一临时 key 的短 TTL 写入/读回/删除，不写真实 LLDP facts。

## 实施步骤

1. 建立每设备 PostgreSQL generation marker；每次完整 LLDP attempt 开始递增 generation 并标 `collecting`，只有 token 仍为当前值时才允许完成写入。
2. 让 topology observations 与快照 complete marker 在同一事务提交；失败、过期 worker 或不完整解析不能覆盖上次 observations，也不能发布 complete cache。
3. 快照 payload 只含标准化邻居字段、采集时间、device/site scope、generation、schema/action/parser 指纹和完整性状态，不复制 raw CLI、凭据或 run secrets。
4. topology collection 成功后从 PostgreSQL 已提交事实发布 generation-qualified Redis key；locator 校验 PostgreSQL marker 后读 Redis，miss 时从 PostgreSQL 重建并回填 Redis；generation 不匹配、扫描中/失败、强制刷新时不复用旧 snapshot。若接口已有强终端证据且无已知拓扑邻居，普通定位不再为了排除 LLDP 下游而额外跑 CLI；强制刷新仍遵守用户意图实时查询。
5. 将 locator topology freshness 默认对齐 48 小时；Redis physical retention 大于 logical freshness，过期数据不作为新鲜事实。
6. 验证完整正快照、明确完整空快照、parse failure、CLI failure、Redis miss/failure、并发旧 token、generation 变化及 run finalization fencing。

## 验证计划

- 迁移在隔离 PostgreSQL 上 fresh/upgrade/idempotency/constraints 验证。
- LLDP contract 与 topology service 定向测试。
- IP Locator Redis/PG snapshot reuse、force refresh、dependency fence 测试。
- 使用配置的 Redis adapter 对唯一临时 LLDP snapshot key 做短 TTL `SET`/`GET`/`DEL` round-trip，验证真实 Redis 写权限、publisher payload 序列化和读回；测试结束确认临时 key 已删除，不读取/输出认证信息。
- `pytest backend/tests/ -k "topology or lldp or neighbor"` 与定位器/任务协调相关测试。
- `python scripts/validate_postgresql_only.py` 和限定文件 `git diff --check`。

## 风险与回滚

- Redis 是可重建投影；不可用时定位器从 PostgreSQL snapshot fallback，仍无可信 complete snapshot 才允许 CLI 回源。
- snapshot migration 为加表方式，回滚应用时保留表/数据，不做破坏性 downgrade；旧应用可继续使用原 topology observation 表。
- complete empty 仅在命令执行成功且输出被明确判定为完整时发布；无法判定时状态设为 failed/incomplete，避免误判无邻居。
- generation-qualified Redis key 防止迟到旧 worker 覆盖新 key；终态事务复核 generation，确保运行期间变更不会以 completed 返回。
