# 实施计划：巡检与网络事实库 (NSOT) 架构解耦与整改

## 1. 任务目标与背景

### 1.1 现状与问题
当前系统中存在巡检系统（Inspection）与网络事实库（NSOT / Network Source of Truth）职责混淆的问题：
- [`src/pages/InspectionTab.tsx`](file:///d:/nexora/nexora-private/src/pages/InspectionTab.tsx)（`/automation/records` 与 `/automation/inspections`）页面顶部错误嵌入了名为 **“设备采集计划 (Device Collection Plan)”** 的卡片，其配置项为 `arp`, `mac_table`, `lldp`, `routes`, `bgp`, `ospf`, `endpoint_location` 等。
- 这些采集能力实质属于 **NSOT 网络事实库**（供 IP 定位、拓扑推导、CMDB 事实丰富使用），误放在健康巡检页面造成了概念和交互混淆。

### 1.2 目标架构
1. **纯粹化巡检管理 (`/automation/records` & `/automation/inspections`)**：
   - 彻底移除巡检页面中与事实库采集无关的“设备采集计划”卡片及冗余状态/请求。
   - 巡检模块聚焦：**全网健康打分看板、巡检运行记录与历史趋势、异常风险设备分析、巡检报告（Excel/PDF/HTML）导出与下载**。
2. **完善网络事实库 (`/assets/nsot`)**：
   - 事实库模块聚焦：**终端事实库 (Endpoints)、IP 资产明细 (Inventory)、路由事实库 (Route Table)、路由协议邻居 (Neighbors)、BGP RIB 表 (BGP Routes)**。
   - 将设备采集能力策略（`Collection Capabilities`：ARP/MAC/LLDP/路由/动态协议开关）与全网同步触发（`Sync All Data`）统一收敛在 NSOT 事实库页面中，提供优雅的“采集能力策略配置”模态窗/抽屉。

## 3. 实施步骤

1. **第 1 步：清理 `InspectionTab.tsx`**：
   - 移除 `collectionPlans`, `selectedPlanDeviceId`, `collectionPlansLoading`, `collectionPlanMessage` 等状态。
   - 移除 `fetchCollectionPlans` 与 `updateCollectionPlan` 回调。
   - 移除顶部“设备采集计划”卡片，调整主看板顶部间距，使健康打分与指标卡片更加突出。
2. **第 2 步：在 `IPLocatorPage.tsx` NSOT 事实库中集成采集能力策略管理**：
   - 在 NSOT 页面工具栏增加“采集能力策略”弹窗/抽屉按钮。
   - 复用 `/api/collection-plans/devices` 接口，支持用户按设备查看当前生效的 NSOT 采集能力（有效角色策略 vs 覆盖开关），支持快速勾选启用/禁用特定协议与表项的采集。
3. **第 3 步：质量门禁与端到端验证**：
   - 执行 `npm run lint` (`tsc --noEmit`) 验证前端 0 类型错误。
   - 验证 `/automation/inspections`、`/automation/records` 与 `/assets/nsot` 页面导航与交互逻辑。
