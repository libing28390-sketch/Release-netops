# Docker Compose 项目名兼容实施计划

## 任务目标

修复已有 Docker 容器健康运行、但 `deploy-docker.sh update` 在发布备份阶段报告 `service "db" is not running` 的兼容问题；确保脚本能识别旧版 Compose 创建的项目，并安全完成备份后更新。本次不操作生产主机、不提交、不推送。

## 现状与问题

- 旧版脚本合并 `docker-compose.yml` 与 `docker-compose.redis.yml` 时未显式指定项目名，现有容器可能带有 `com.docker.compose.project=nexora-redis` 等历史标签。
- 新版脚本默认强制 `--project-name nexora`。
- Docker 容器名和健康状态不等于 Compose 项目归属；当标签项目名不一致时，`compose exec -T db pg_dump` 无法找到当前项目的 `db` 服务。
- 更新流程在同步源码前强制备份，因此该不兼容会正确地中止更新，但也导致用户无法升级到后续版本。

## 影响范围

- `scripts/deploy-docker.sh` 的 Compose 项目名解析。
- Redis/Docker 发布契约测试。
- Docker 部署故障排查说明。
- 不修改数据库、容器、数据卷或生产环境。

## 拟修改文件

- `scripts/deploy-docker.sh`
- `backend/tests/release/test_deploy_docker_redis_contract.py`
- `docs/deploy/docker.md`
- `docs/walkthrough/walkthrough_20260913_0034_01_Docker项目名兼容.md`

## 实施步骤

1. 保留显式 shell 环境变量和 `.env` 中 `COMPOSE_PROJECT_NAME` 的最高优先级。
2. 未显式配置时，读取现有 `nexora-db` 容器的 `com.docker.compose.project` 标签并沿用历史项目名。
3. 没有现有容器时继续默认使用稳定项目名 `nexora`。
4. 对解析出的项目名继续执行字符白名单校验。
5. 增加聚焦契约测试和迁移排查说明。

## 验证计划

- 运行发布脚本 Redis/Compose 契约测试和 Redis MONITOR 格式化测试。
- 静态/模拟验证项目名优先级：shell 环境、`.env`、历史容器标签、全新部署默认值。
- 验证 Bash 语法（环境可用时）、YAML 解析和差异空白。
- 检查未触及用户已有无关修改，确认无提交、无推送。

## 风险与回滚思路

- 自动探测仅在用户没有显式指定项目名时发生，且只读取固定容器 `nexora-db` 的 Compose 标签。
- 标签缺失或容器不存在时回退到 `nexora`；非法标签会被现有白名单拒绝。
- 回滚可撤销项目名探测函数及测试/文档，不涉及生产数据。
