# 实施计划 - 迪普平台全链路命令目录与 Netmiko 映射兜底

## 1. 任务目标
解决 `POST /api/devices/{device_id}/operational-data` 接口在对迪普交换机/防火墙（`dptech_conplat` / `dptech_conplat_fw`）执行快捷查询/命令采集时，因 `_PLATFORM_ALIAS` 缺失及 `COMMAND_CATALOG` 缺少 `dptech_ios` 命令字典，引发 Netmiko 校验失败报出 `Error: Unsupported 'device_type'` 的问题。

---

## 2. 根因分析
1. **`_PLATFORM_ALIAS` 漏掉别名**：`operational_data_service.py` 中的 `_PLATFORM_ALIAS` 别名映射表中未包含 `dptech`、`dptech_conplat` 与 `dptech_conplat_fw`。
2. **`COMMAND_CATALOG` 缺少命令目录**：`COMMAND_CATALOG` 未包含 `dptech_ios` 命令集合，导致 `_resolve_commands` 无法找到迪普设备的查询命令。
3. **`_build_connection_params` 缺乏防漏防穿透兜底**：当未成功匹配时，原生平台字符串 `dptech_conplat_fw` 被原样作为 `device_type` 传给 Netmiko，引发 Netmiko 抛出不支持 `device_type` 校验失败。

---

## 3. 拟修改文件列表

- `docs/plans/plan_20260731_1038_01_迪普平台全链路命令目录与Netmiko映射兜底.md` [NEW]

---

## 4. 实施步骤

1. **补全 `_PLATFORM_ALIAS`**：
   在 `operational_data_service.py` 的 `_PLATFORM_ALIAS` 中追加：
   `dptech`, `dptech_conplat`, `dptech_conplat_fw` -> `dptech_ios`
2. **补全 `COMMAND_CATALOG['dptech_ios']` 命令目录**：
   为 `dptech_ios` 提供完整的接口、邻居、ARP、MAC、VLAN、路由、NTP、日志等查询命令集合。
3. **强化 `_build_connection_params` 防漏兜底**：
   无论入参为 `dptech_conplat` 或 `dptech_conplat_fw`，均无死角自动校准转换为 Netmiko 合法的 `dptech_ios`。
