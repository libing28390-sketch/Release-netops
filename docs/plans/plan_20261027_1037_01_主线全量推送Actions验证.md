# 主线全量推送与 Actions 验证计划

## 任务目标

将当前 `main` 工作区中已完成的应用源码、测试、数据库迁移及必要的计划/走查文档提交并推送到 `origin/main`，确认该提交对应的 GitHub Actions 全部结束且通过；失败时根据日志修复并重新验证。

## 现状与范围

- 本地 `main` 与远端 `origin/main` 当前指向同一提交 `1bf5ba0c0d390f973bdafdefff9c9199cde7784c`。
- 工作区累计了资产导入与 SNMP 型号/主机名同步、凭据与权限、变更单及工单 UI 等源码和测试改动。
- `.agents/`、`handoff.md`、`.codex-build-validation-*`、`dist-*`、`logs/`、`backend/artifacts/` 和纯生成的浏览器截图/PDF 属于内部协作或验证产物，本次不放入公开提交。

## 拟提交范围

- 已修改和新增的 `backend/`、`src/` 源码、测试与数据库迁移。
- 与上述实现直接对应的 `docs/plans/`、`docs/walkthrough/` Markdown 文档。
- 本任务新增的 `docs/fixes/fix_*.md` 记录。

## 实施步骤

1. 逐项核对源码差异、未跟踪测试和迁移，排除个人数据、生成文件、密钥及内部协作材料。
2. 按项目质量门运行 PostgreSQL-only 扫描、改动模块的后端聚焦回归、前端类型检查/全量测试/隔离目录构建和差异空白检查。
3. 写入本次提交的修复记录及最终走查结果，检查提交清单与 Git 历史。
4. 在 `main` 创建可追溯提交并推送一次，记录远端 `main` 的最终 SHA。
5. 检查该 SHA 对应的 Actions；如果失败，取 job 日志定位、修复、复测、补充记录并再次推送。

## 验证计划

- `python scripts/validate_postgresql_only.py`
- 改动模块的 pytest 回归（使用一次性 loopback PostgreSQL 数据库并在结束后清理）。曾尝试本地 4,009 项全量 pytest，运行至约 11% 后因本机耗时过长中断；完整全量回归由推送触发的 Release Actions 执行并作为发布门禁。
- `npm run lint`
- `npm run test:frontend -- --run`
- 用 Vite CLI 将构建输出指向唯一临时目录，保护工作区已有 `dist/`；Release Actions 再按正式脚本构建。
- `git diff --check`
- GitHub Actions 中最终推送 SHA 对应的运行结果

## 风险与回滚

- 推送会触发仓库 `main` 的发布工作流；将核对它只处理仓库配置的发布路径，并以实际 Actions 结果确认。
- 不改写远端历史，不使用强推。若发布后的变更需要撤回，使用后续 revert 提交恢复。
