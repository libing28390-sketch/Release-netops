# 实施计划：十二大模块总线实测四项边界缺陷优化

- **创建时间**：2026-11-27 09:28
- **目标仓库**：`D:\netops\netsops-main`
- **背景来源**：42 轮实时浏览器 Copilot 联动测试（36 PASS / 2 PARTIAL / 4 FAIL，41/42 轮 0 Token）

## 1. 任务目标
彻底修复 42 轮线上实测中发现的 4 项 Copilot 边界缺陷，使十二大模块 0-Token 总线、防串台、因果推理升级与危险命令拦截在复杂多轮对话中均稳定准确。

## 2. 现状与问题
1. **IPAM 被 PAM 子串误抢（第 31 轮）**：`local_router.py` 使用 `"pam" in lower` 且顺序早于 IPAM，导致 `"IPAM 网段利用率怎么样"` 被误路由至 `pam_sessions`。
2. **因果/对比分析未能正确升级给大模型（第 16、30 轮）**：`_REASONING_ESCALATION_MARKERS` 缺少 `结合上面 / 潜在风险 / 对比 / 哪台更 / 分析下` 等表达；且返回 `None` 后进入外部 `intent_parser` 不仅多消耗 600+ Token，还被误分类为 `asset_analysis` 吐出全网 17 台设备表。
3. **全局查询后粘滞旧设备焦点（第 22 轮）**：第 17~21 轮全网查询后未清空持久化的 `active_device`，且 `"最近有哪些待审批变更工单"` 触发省略主语继承，串台回 `S6850_1`。
4. **危险命令拦截被历史确认卡绕过（第 40 轮）**：`assistant.py` 在 `pending_clarification` 存在时跳过 `_explicit_device_execution_request`，导致 `"帮我在这台设备上执行 undo ospf 1 并保存"` 混入了第 39 轮的华为 OSPF 确认卡。

## 3. 影响范围与拟修改文件
- `backend/ai/services/local_router.py`：IPAM 优先 + `pam` 词边界正则；扩展推理升级词并确定性直通 `troubleshooting`（带 `reasoning_escalation=True`，跳过外部 `intent_parser`）。
- `backend/ai/services/entity_context.py`：复数列表问法（`有哪些...` 且无单设备代词）归为 `global`；收紧 `_OMITTED_SUBJECT_ATTR_MARKERS`。
- `backend/ai/services/assistant.py`：`_persist_entity_memory` 支持显式清空 `active_device`；全局查询自动释放单设备焦点；`_explicit_device_execution_request` 不再被 `pending_clarification` 跳过；`_merge_history_scope_continuation` 保留 `reasoning_escalation`。
- `backend/tests/ai/test_twelve_module_entity_bus.py`：补充针对上述 4 项缺陷的精准回归单测。

## 4. 实施步骤
1. 修复 `local_router.py`（IPAM/PAM 词边界与顺序 + 推理升级直通大模型）。
2. 修复 `entity_context.py`（复数全局列表判定与省略主语词收敛）。
3. 修复 `assistant.py`（全局查询清空 `active_device` + 危险执行拦截无条件优先 + 保持 `reasoning_escalation`）。
4. 补充回归测试并运行 `py_compile` + `pytest` 回归套件，归档 `docs/walkthrough/`。
