# Nexora NetOps 3D Rack Twin V1 实施计划

## 任务目标
在现有 `RackManagement` 页面中引入基于 Three.js / React Three Fiber 的 **3D 机柜孪生（3D Rack Twin V1）** 增强视图。
遵循单一业务数据源原则（2D 与 3D 共用 `RackViewModel`），2D 负责排布编辑与精准调度，3D 负责沉浸式观察、状态聚焦与排障跳板，具备 WebGL 自动降级与数据质量防护。

## 一、实施前数据与语义校验结果 (Data Readiness Verification)

通过对 ORM、Schema、Service、API 以及 `RackElevation.tsx` 的全链条审计，确认各关键字段语义如下：

| 字段 | 类型/来源 | 业务真实语义 | 3D V1 处理方式 |
| :--- | :--- | :--- | :--- |
| `rack.id` | TEXT / UUID | 机柜全局唯一主键 | 唯一标识与场景绑定 |
| `rack.name` / `rack_name` | TEXT | 机柜展示名称（如 DC01-A01） | 3D 顶部标牌文字 |
| `rack.total_u` | INTEGER (默认 42) | 机柜总 U 位容量（24/42/48U 等） | 决定机架高度与立柱刻度范围 (1 ~ total_u) |
| `rack.width_mm` | INTEGER (默认 600) | 机柜外宽（毫米） | 决定 3D 机架 X 轴比例（默认 600mm） |
| `rack.depth_mm` | INTEGER (默认 1000) | 机柜外深（毫米） | 决定 3D 机架 Z 轴比例（默认 1000mm） |
| `rack_device.id` | TEXT / UUID | 机柜上架设备记录 ID | 3D 设备点击选中、聚焦的唯一键 |
| `rack_device.asset_id` | TEXT | 关联的 `physical_assets.id` | 关联资产档案与网络设备 `devices.id` 的关键中继 |
| `rack_device.start_u` | INTEGER | 设备占用的**最低 U 位**（1-based，即底部起始 U 位） | 3D 中设备底面对应 `(start_u - 1) * U_HEIGHT` |
| `device_type.u_height` | INTEGER | 设备占用 U 高（1, 2, 4 等） | 设备厚度，设备占用区间为 `start_u .. start_u + u_height - 1` |
| `rack_device.position` | TEXT (`front` / `rear`) | 上架朝向 | `front` 朝向 +Z（正面），`rear` 朝向 -Z（背面） |
| `device_type.is_full_depth`| INTEGER (1 / 0) | 全深 / 半深设备 | 1 沿 Z 轴贯穿前后，0 沿 Z 轴只占半深（另一侧留空） |
| `device_type.device_role` | TEXT | 设备角色（switch/server/firewall/router/pdu/patch_panel等） | 驱动程序化面板（Procedural Chassis/Faceplate）外观与布局 |
| `vendor` / `model` | TEXT | 设备厂商与型号 | 决定铭牌文字、局部高光色系（不染整机） |
| `power_watts` | INTEGER | **额定功耗**（瓦特） | 标明为“额定功耗”，不伪造实时功耗 |
| `rd.status` | TEXT (`active`/`offline`/`planned`等) | **资产生命周期状态** | 与 `healthStatus` 区分，决定生命周期标签 |
| `device_health` | API / Service | **实时运维健康状态** (`healthy`/`warning`/`critical`/`unknown`)、CPU、内存、温度、告警数 | 驱动小型状态 LED 指示灯与告警呼吸边框，缺失时显式标为 `unknown` |

### 2D 与 3D 坐标系统一规则
- **Y 轴（高度）**：U1 在最底部（Y_min），U(total_u) 在最顶部（Y_max）。与 2D `RackElevation` 保持 100% 相同方向。
- **X 轴（宽度）**：+X 为机柜宽度方向（从左立柱到右立柱）。
- **Z 轴（深度）**：+Z 为机柜正面（Front），-Z 为机柜背面（Rear）。

## 二、架构设计与模块划分

```text
src/pages/RackManagement/
├── index.tsx                         # 统一入口，增加 [ 2D机柜 | 3D孪生 ] 切换，共用 Drawer 与状态
├── types.ts                          # 补充 RackVM / RackDeviceVM / HealthStatus 定义
├── adapters/
│   └── rackViewModel.ts              # API 数据归一化、数据质量校验、坐标换算
└── Rack3D/                           # 3D 纯查看/聚焦模块
    ├── index.tsx                     # 3D 入口容器、WebGL 能力检测、ErrorBoundary
    ├── RackScene.tsx                 # Three.js Canvas、柔和三点光、轨道控制
    ├── RackFrame.tsx                 # 参数化机架（24/42/48U、立柱、发光U刻度、轻量网孔贴图门）
    ├── RackDeviceItem.tsx            # 单设备装配体（位置计算、选中聚焦、健康LED）
    ├── CameraController.tsx          # 相机视角切换（正面/背面/45°等轴/重置/平滑聚焦）
    ├── models/
    │   ├── ProceduralChassis.tsx     # 基础金属机箱（1U/2U/4U/全深/半深）
    │   ├── SwitchFaceplate.tsx       # 交换机/路由器前面板（端口网格贴图、Logo铭牌、指示灯）
    │   ├── ServerFaceplate.tsx       # 服务器前面板（进风栅格、硬盘托架贴图）
    │   └── GenericFaceplate.tsx      # 通用/其他设备面板
    └── utils/
        ├── webgl.ts                  # WebGL 2.0 / 1.0 检测与性能探测
        └── textures.ts               # 程序化 Canvas 生成轻量蜂窝网孔贴图与端口纹理
```

## 三、6 个分步实施阶段 (P0-1 ~ P0-6)

### P0-1 — RackViewModel 与适配层
- [x] 数据契约审计
- [ ] 创建 `adapters/rackViewModel.ts`，定义 `normalizeRackToVM()`
- [ ] 实现数据质量校验：U 位越界、设备重叠、非法 position、缺失 asset/device
- [ ] 编写 Vitest 单测覆盖异常数据与边界（24U/42U/48U、1U/2U/4U、front/rear、unknown health）

### P0-2 — 2D / 3D 视图切换与 WebGL 降级
- [ ] 在 `RackManagement/index.tsx` 顶部操作栏增加 `[ 2D机柜 | 3D孪生 ]` 切换器
- [ ] 视图切换保持 `selectedRackId`、`selectedDeviceId` 与 Drawer 状态完全一致
- [ ] 集成 `WebGL` 探测与 `ErrorBoundary`，遇到不支持或 Canvas 错误时自动回退 2D 并给以清晰友好提示

### P0-3 — 参数化机柜框架 (RackFrame)
- [ ] 根据 `totalU`（24/42/48U）与 `width_mm`/`depth_mm` 动态构建 3D 冷轧钢机柜框架
- [ ] U1 在底、Max U 在顶，立柱刻度清晰可读
- [ ] 使用轻量透明度纹理实现前网孔门（支持开关门切换），不生成密集蜂窝几何体

### P0-4 — 程序化设备模型 (Procedural Device)
- [ ] 实现 `ProceduralChassis`（1U/2U/4U/全深/半深）
- [ ] 实现 `SwitchFaceplate`、`ServerFaceplate`、`GenericFaceplate`
- [ ] 工业深灰/黑/银金属材质，小型铭牌标识，禁止整机涂抹品牌色

### P0-5 — 设备健康与指示灯联动 (Health)
- [ ] 关联 `device_health` 真实遥测指标（若无则准确显示 `unknown`，绝不伪造 `normal`）
- [ ] 状态视觉映射：
  - `healthy`：原材质 + 小型绿色常亮 LED
  - `warning`：橙色 LED + 轻微边缘提示
  - `critical`：红色 LED + 柔和克制呼吸边框
  - `offline`：低饱和度暗色 + 灰色 LED
  - `unknown`：中性深色 + 灰色 LED
- [ ] 功耗标注为“额定功耗”

### P0-6 — 交互与现有功能联动 (Interaction)
- [ ] 视角预设：正面、背面、45° 等轴、俯视、重置
- [ ] 鼠标点击 3D 设备触发高亮，相机平滑过渡聚焦
- [ ] 联动右侧现有 CMDB 资产详情 Drawer（资产档案、指标、Web SSH 一键跳转），不造重复轮子

## 四、验证计划与质量门禁

1. **单测验证**：运行 `npm run test:frontend` 验证 ViewModel 转换、数据质量校验、U位边界与坐标算法。
2. **类型与构建检查**：运行 `npm run lint` (`tsc --noEmit`) 确保无类型错误，运行 `npm run build` 确保生产打包顺利。
3. **功能回归检查**：确保原有 2D 机柜拖拽、编辑、删除、Excel 导入导出、资产安装 100% 无回归。
