# 全站对话框与个人设置样式统一

## 任务目标
收敛全站表单对话框的文字层级、边框、提示区和主操作色，让资产、设备、CMDB 与个人设置页面使用一致的中性表面与标准蓝强调色；覆盖个人设置中的 Fixed PIN、MFA、通知与终端设置，并覆盖 CMDB 下所有新建/编辑入口。表格操作按钮由公共组件统一保持可见。

## 现状与问题
全局已有语义色变量，但部分表单仍直接使用 `text-black/30`、cyan 色阶和单页自定义底色。资产表单、设备表单、CMDB 基础数据和个人设置在外框、提示卡片、PAM、固定安全码、按钮及文字对比度上各有一套表现，视觉噪点较多；CMDB 通用新建记录弹窗和机柜新建/设备型号表单仍保留模糊遮罩、重阴影或强调色。

## 影响范围
- 共用表单对话框和区块样式，为采用公共表单布局的页面提供统一的语义表面、文字与主按钮规则；全站 cyan 强调映射到标准蓝。
- 资产新增/编辑对话框：基础提示、字段文字、PAM 卡片和保存栏。
- 设备编辑对话框：字段层级、SNMP 说明、PAM 凭据及操作栏。
- 个人设置对话框：外框、导航、基本资料、安全、通知和终端设置；固定安全码保留风险语义，但降低大面积琥珀色。
- CMDB 通用记录新建/编辑弹窗：覆盖凭据、设备、接口、站点、VRF、VLAN 与 VLAN 业务等复用同一表单的页面。
- CMDB 机柜管理：新建/编辑机柜、安装设备与设备型号管理弹窗；让新建入口使用统一标准蓝色并靠左，搜索、导入导出及其他工具靠右排列。
- 公共表格操作组件：操作按钮不再依赖鼠标悬停才显示；`TableActionCell` 扁平化已有的 `ActionIconGroup`，避免重复分组。
- 保留现有表单字段、验证、权限、提交和安全行为。

## 实施步骤
1. 复核全局 UI 语义变量及上述对话框浅色/深色主题实现，区分信息提示、危险提示和普通表单区域。
2. 在共享 CSS 中扩展既有 `FormDialogShell` 的中性文字和表面规则，统一对话框边线、字段层级和标准蓝焦点/主操作样式。
3. 将资产、设备及个人设置的提示区和凭据卡片改为轻量表面，缩小高饱和颜色覆盖面积；固定 PIN 继续保留温和的安全提示标识。
4. 复核个人设置各标签和浅/深色分支，确保控件功能及保存/取消路径未改动。
5. 将 CMDB 通用 CRUD 表单和机柜管理的新建相关弹窗接入同一中性对话框样式，去掉模糊/缩放装饰，使用标准蓝主操作色；新建按钮置左，搜索、导入导出和工具置右；旧数据维护逻辑与表单结构保持不变。
6. 在公共 `ActionIconGroup` 中固定操作按钮可见，并让 `TableActionCell` 复用现有分组而不生成嵌套分组；检查 CMDB 与其他表格页面不再通过 hover 控制显隐。
7. 运行前端 lint、独立目录生产构建和 `git diff --check`，并在可用浏览器里查看资产、CMDB 凭据/基础记录、机柜新建表单及表格操作列。

## 验证计划
- `npm run lint`
- `node .\node_modules\vite\bin\vite.js build --outDir <临时目录> --emptyOutDir`
- `git diff --check`
- 浏览器查看资产表单及个人设置的固定 PIN/MFA 外观；不保存或修改用户设置。
- 浏览器检查 CMDB 代表性新建表单与机柜新建相关弹窗；仅打开和关闭，不提交数据。

## 风险与回滚思路
个人设置含浅色与深色条件样式，需分别保留对比度；安全和错误状态不可被一般蓝色弱化。CMDB 通用表单在不同实体间复用字段布局，样式调整不得影响必填、验证、凭据显隐或提交路径。若视觉调整影响可读性或主题对比，可回退对应对话框样式类与共享语义样式，业务状态和表单行为不涉及更改。
