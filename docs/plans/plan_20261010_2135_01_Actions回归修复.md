# Actions 回归修复计划

## 目标

定位并修复 GitHub Actions 中 `pytest` 的 50 个失败，保留当前工作区里已有的本地资料与构建产物，不通过放宽断言来单纯消除红灯。

## 现状与问题

失败集中在 IPAM 对账与采集器、Grafana 面板基线、SNMP 接口采集、拓扑 LLDP/聚合采集、NSOT 调度契约以及测试 PostgreSQL schema。当前 `main` 已包含最近推送的功能变更，测试中部分 mock/固定预期可能未同步；IPAM 时效与拓扑 SNMP 优先路径还需确认是否为真实行为回归。

## 影响范围

- 后端采集与 IPAM 对账行为。
- 测试 PostgreSQL schema 和测试替身。
- Grafana 面板结构契约测试。
- Actions 使用的后端 pytest 全量门禁。

## 拟修改文件

- `backend/services/ip_locator_service.py`、`backend/services/ipam_service.py`、`backend/services/interface_collection_service.py`、`backend/services/snmp_service.py`、`backend/services/topology_service.py` 及对应调用处（仅在确认实现问题时修改）。
- 对应 `backend/tests/**` 测试、PostgreSQL 测试 schema/fixture 和 Grafana 合同测试。
- `docs/walkthrough/` 验证记录及 `docs/fixes/` 本次提交的修复记录。

## 实施步骤

1. 按失败堆栈归组，检查当前实现、测试夹具、迁移和 Actions 配置。
2. 区分实现回归与预期功能变更造成的过时测试；更新测试契约时保留其原有行为覆盖和断言强度。
3. 修复确认的实现缺陷与 fixture/schema 漂移。
4. 运行失败测试对应的最小模块回归，再按结果扩展验证；检查 PostgreSQL-only 策略。
5. 汇总工作区未提交内容、验证结果、剩余风险，并遵守现有授权边界处理 Git。

## 验证计划

- 先运行 IPAM、SNMP 接口、拓扑、NSOT、Grafana 面板相关的失败测试。
- 仅当测试基础设施与共享代码没有阻塞时，再运行 `pytest` 全量门禁。
- 检查 `git diff --check`、PostgreSQL-only 扫描及工作区状态。

## 风险与回滚思路

- 对账时效、LLDP SNMP/SSH 回退及采集传输方式涉及业务语义，修改前以当前需求和实现证据判定，不为迎合测试改变行为。
- 如修复造成回归，可逐文件回退本次补丁；保留修改前已有的 `.agents/`、`handoff.md`、构建目录和日志，不清理或覆盖。
- 不在未验证测试 PostgreSQL 连接目标前执行持久化测试。

## 执行记录

- 按当前实现更新了测试 mock 和夹具：IPAM 端点时间改为当前 UTC；SNMP 采集 mock 接受 `version` 参数；拓扑凭据明确标记 SNMP 已配置；NSOT、MAC/ARP 快照契约与当前接口保持一致；PostgreSQL 临时表补齐当前查询依赖的列。
- Grafana 合同测试基线按当前目录更新为 13 个 dashboard、271 个面板、57 个分组行和 100 个统计面板；设备详情中已移除的电压/电流面板 ID 30、31 继续断言不存在。
- 静态验证通过：本轮修改的测试文件 `compileall`、Grafana 目录统计脚本、`git diff --check`。
- 在本机 PostgreSQL 18 上创建唯一 `nexora_pytest_actions_*` 测试库后，14 个受影响文件共 `217 passed`；失败用例修复后的针对性复测为 `23 passed`。两轮临时测试库均在命令结束时删除，未连接 `.env` 中的 `netops` 应用库。
- 本机 `.venv` 使用 Python 3.13.14，Actions 使用 Python 3.11；本地 PostgreSQL 为 18。完整 `backend/tests` 未运行，CI 的 Python 3.11 环境仍需在下一次 Actions 中确认。
- 当前分支 `main` 与本地 `origin/main` 对齐；本轮没有提交或推送。
