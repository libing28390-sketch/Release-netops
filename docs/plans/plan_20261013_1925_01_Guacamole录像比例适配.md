# Guacamole RDP/VNC 录像画面比例适配

## 任务目标
改善 RDP 与 VNC 会话录像的回放画面尺寸与比例体验，同时保持远端画面原始宽高比、不裁切内容。

## 现状与问题
用户截图中回放内容约为 4:3，在宽屏播放器内居中显示并留下较宽的左右黑边。播放器按录像源分辨率等比 contain 显示，因此需处理 RDP 的动态尺寸更新，并为无法改分辨率的 VNC/历史录像提供可滚动的宽度缩放。

## 影响范围
Guacamole 前端远程桌面尺寸协商与录像播放器缩放/布局；RDP 动态分辨率参数；RDP 与 VNC 的显示服务端能力可能不同。

## 拟修改文件
- `src/components/access/RemoteDesktopClient.tsx`
- `src/components/access/GuacRecordingPlayer.tsx`
- `backend/services/guacamole_service.py`
- `backend/tests/pam/test_remote_desktop_guacamole_service.py`
- 本任务的 `docs/fixes/` 记录和 `docs/walkthrough/` 结果

## 实施步骤
1. 检查 Guacamole 连接尺寸、录像源分辨率与播放器缩放，区分源分辨率和回放布局。
2. RDP 启用 `display-update`，客户端将目标尺寸限制在 16:9 且不超过 1920×1080；VNC 通过 Guacamole 原有尺寸协商尝试适配。
3. 录像播放器提供完整适配和按宽度等比放大，并显示录像源分辨率/比例；不拉伸、不裁切。
4. 运行前端 lint/build 和后端定向测试，提交推送 `main`；等待 Actions 成功，再按既有授权部署到 Ubuntu 验证。

## 验证计划
- 前端 `npm run lint` 与 `npm run build`。
- 后端 `pytest backend/tests/pam/test_remote_desktop_guacamole_service.py -q`。
- 浏览器检查两种缩放模式和尺寸标签；Actions 成功后运行 `bash scripts/deploy-docker.sh update` 并检查部署状态及 RDP/VNC 录像显示分辨率。

## 风险与回滚
VNC 服务端可能忽略动态尺寸请求，此时保留服务器原始分辨率并让宽度模式以滚动方式查看；历史录像的源分辨率不会被改写。回滚可还原本次 RDP 尺寸协商、播放器和后端参数改动。
