# Guacamole RDP/VNC 录像画面比例适配

## 任务目标
改善 RDP 与 VNC 会话录像的回放画面尺寸与比例体验，同时保持远端画面原始宽高比、不裁切内容。

## 现状与问题
播放器已增加源分辨率标记、完整适配和按宽度放大模式。Ubuntu 实机验证发现：VNC 新录制源为 1920×1080（16:9）；RDP 新会话仍为 1024×768（4:3），说明该 Windows RDP 服务端没有应用连接后的动态尺寸更新。要让 RDP 录像从首帧开始使用宽屏分辨率，需要提供 Guacamole 初始尺寸。

## 影响范围
Guacamole RDP 初始分辨率与动态尺寸协商、RDP/VNC 共用录像播放器、远端 Ubuntu Docker 发布和实机录像验收。VNC 分辨率仍由 VNC Server 能力决定。

## 拟修改文件
- `backend/services/guacamole_service.py`
- `backend/tests/pam/test_remote_desktop_guacamole_service.py`
- `src/components/access/GuacRecordingPlayer.tsx`
- `src/components/access/RemoteDesktopClient.tsx`
- 本任务的 `docs/fixes/` 记录和 `docs/walkthrough/` 结果

## 实施步骤
1. 在 RDP 连接参数中明确请求 1920×1080 初始桌面，并保留 `display-update` 动态调整；VNC 不加固定尺寸。
2. 保持播放器等比显示源画面，完整适配模式用于全屏桌面浏览，宽度模式用于放大旧 4:3 录像并提供纵向滚动。
3. 运行后端定向测试；Actions 成功后更新 Ubuntu。
4. 创建新的 RDP 会话核对录像源宽高；对 VNC 历史录像核对 16:9 源标记和两种适配状态。
5. 更新 walkthrough 与发布验证记录。

## 验证计划
- `pytest backend/tests/pam/test_remote_desktop_guacamole_service.py -q`。
- 已完成前端 `npm run lint`、`npm run build`；本轮前端未再修改。
- GitHub Actions 全量发布门禁成功后，执行 `bash scripts/deploy-docker.sh update`。
- 通过 Nexora 页面确认新 RDP 录像为 16:9，VNC 源分辨率和播放器缩放模式正常，检查部署容器健康状态。

## 风险与回滚
若 RDP 服务端忽略尺寸请求，录像仍保留实际协商分辨率；播放器的宽度模式可放大旧录像但会需要纵向滚动。VNC 服务端可能不支持动态改屏幕大小。回滚可撤销初始尺寸参数和播放器改动并重新部署。
