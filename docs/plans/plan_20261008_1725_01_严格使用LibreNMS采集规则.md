# 任务计划：严格使用 LibreNMS 采集规则

## 目标
让硬件采集只执行固定版本 LibreNMS 上游定义的规则；清除 H3C/Comware 硬件采集路径中的 Nexora 专有探测规则，并让每个保留的 H3C 规则都能追溯到上游文件与固定 commit。

## 现状与问题
- 本地 `backend/vendor/librenms` 打包了 LibreNMS YAML、MIB，但没有打包 Comware 上游 PHP 发现模块。
- 上游 Comware CPU、内存、收发器与传感器规则分布在 `LibreNMS/OS/Comware.php` 和 `includes/discovery/sensors/*/comware.inc.php`。
- Nexora 以 Python 执行器把这些模块的规则映射为本地指标；当前还额外执行 H3C 无线专有扩展，该扩展不是 LibreNMS Comware 规则。
- 用户要求遵循 LibreNMS 规则，不部署 LibreNMS 服务，也不使用 Nexora 自定义 H3C 采集规则。

## 影响范围
- H3C/Comware 本地规则来源清单及上游快照元数据。
- `backend/services/snmp_hardware_probe_service.py` 的 Comware 规则执行边界。
- 对应硬件探测和 LibreNMS 规则服务测试。
- 文档说明中区分 LibreNMS 上游规则与其他独立无线采集能力。

## 拟修改文件
- `backend/services/snmp_hardware_probe_service.py`
- `backend/vendor/librenms/source-manifest.json`

- 与本任务同名的 `docs/walkthrough/` 结果记录

## 实施步骤
1. 对照 vendored commit `6c26b4fe4a40f7b392c19c36a44257212736e38c` 核实 Comware 官方 PHP 模块与现有 Python 执行结果。
2. 将实际依赖的 LibreNMS 上游 PHP 规则源码纳入本地只读 vendor 快照和 SHA-256 manifest，保留原始版权及许可证信息。
3. 让 Comware 执行器仅按这些固定上游模块的规则生成 CPU、内存和硬件传感器；移除 Comware 无线专有扩展在硬件采集中的调用。
4. 增加/调整回归测试，锁定规则来源、OID、索引、有效值过滤、单位/阈值换算及无线扩展不进入 LibreNMS 硬件结果。
5. 更新 vendor README，解释 Python 仅是运行时执行层，采集规则由固定 LibreNMS 上游快照提供。

## 验证计划
- `pytest backend/tests/snmp/test_snmp_hardware_probe_service.py`
- `pytest backend/tests/snmp/test_librenms_rule_service.py backend/tests/monitoring/test_snmp_hardware_poller_service.py`
- 检查新增 vendor 文件 SHA-256 与上游 revision 一致，且 manifest 可解析。
- 若修改仅限硬件采集路径，不运行无关前端构建或全量回归。

## 风险与回滚
- 移除非 LibreNMS 的 Comware 无线硬件扩展会减少硬件库存页面上的 H3C 无线专有条目；这符合“仅使用 LibreNMS 规则”的要求，既有独立无线监控能力不在此次改动范围。
- CPU/内存和传感器需要 Python 执行层承接 LibreNMS PHP 模块；规则内容以 vendor 中的原始上游文件和 commit 为权威，测试防止执行层自行扩展过滤/单位规则。
- 可回滚方式是恢复此次 H3C 采集分发和来源 manifest 相关改动；不会更改数据库结构或真实设备配置。
