# 任务目标

评估并整理外部“模块化交换机 GLB Demo”，使它能够遵循 Nexora RackVision 的资产规范，作为后续 ToR/模块化交换机建模的隔离 draft 资产，不破坏现有已批准生产 GLB。

# 现状/问题

- 外部 Demo 的坐标轴、原点和 Nexora 规范不一致，端口/插槽多为可见几何而非可绑定语义锚点。
- Demo 缺少材质、法线、UV 和可追溯的端口元数据，直接接入会再次出现端口像保护盖、线缆落点不稳定的问题。
- 外部压缩包没有 Blender 源文件或可重现导出脚本，不能直接标记为 approved。

# 影响范围

- `tools/gltf/` 归一化与验证脚本。
- `assets/build/glb/modular_demo/`、`public/assets/3d/modular_demo/` 隔离 draft 输出。
- RackVision 资产工作流文档与验证记录。

# 实施步骤

1. 读取外部 GLB，保留源文件不变并记录 SHA-256。
2. 转换为 Nexora 坐标系和 front/bottom/center 原点，反转三角形绕序并生成法线/UV。
3. 写入统一 PBR 材质名、场景/节点/端口/插槽语义 metadata；把插槽锚点和端口锚点设为不可见语义节点。
4. 以实际转换后的锚点回填 `slot_manifest.json`，避免源 manifest 与烘焙几何错位；记录声明尺寸与实测尺寸差异。
5. 用独立 validator 检查结构、材质、法线/UV、端口前向性、锚点和唯一命名。
6. 保持 draft 状态，不自动写入生产 asset registry；后续需有 Blender 源文件、官方尺寸/端口资料和人工视觉验收后再批准。

# 验证计划

- `python tools/gltf/normalize_modular_demo.py ...`
- `python tools/gltf/validate_modular_demo.py assets/build/glb/modular_demo`
- `python -m py_compile tools/gltf/normalize_modular_demo.py tools/gltf/validate_modular_demo.py`
- 使用 Three.js GLTFLoader 逐个加载输出 GLB，确认 schema、坐标、材质、NORMAL/TEXCOORD_0 和语义节点。

# 风险与回滚思路

- Demo 几何仍是低多边形工程样例，归一化不会凭空提升 OEM 外观精度；保留 `status: draft` 防止误用于生产。
- 输出位于独立 build/public 子目录；删除该目录即可回滚，不触碰原始压缩包和现有生产资产。
