# 实施计划：RAG 推理提速与语义向量全链路优化（P0-P2）

## 1. 任务目标
针对 Copilot 知识问答实测中暴露的 3 个核心痛点（模型顶部健康状态误报「异常」、单次知识问答耗时 15 秒、Token 消耗偏高）以及在线语义向量链路未自动衔接 DB 已配置 Embedding 模型的问题，一次性完成 P0～P2 全部 5 项优化。

## 2. 现状与问题
1. **意图识别冗余调用 LLM（P0-1）**：产品规格类（如“端口规格/交换容量/参数”）和未指定设备的泛化排障咨询未覆盖在 `IntentParser.is_knowledge_query` 确定性快路径中，导致多一次云端 LLM 往返（增加 3～5 秒耗时与一轮 Token）。
2. **RAG 固定注入 Top-5（P0-2）**：`assistant.py` 的 `retrieve_knowledge` 固定使用 `top_k=5`，即使 Top-1 已精确命中用户提问的型号，仍会把其余 4 篇无关型号文档拼进上下文。
3. **安全策略拦截误标模型为 `unhealthy`（P1-3）**：`llm_gateway.py` 中 `health = "healthy" if status == "success" else "unhealthy"` 在本地安全网关拦截（`blocked` / `security_blocked`）时把正常的 Provider 和 Model 标成 `unhealthy`，导致前端顶部长期显示红色「异常」。
4. **在线语义向量未自动衔接 DB Embedding 模型（P1-4）**：`backend/ai/providers/embedding.py` 的 `semantic_embedding_provider()` 仅读取 `AI_SEMANTIC_EMBEDDING_PROVIDER=sidecar` 环境变量，未自动发现 `ai_model` 表中已启用的 `model_type='embedding'` 模型（如 SiliconFlow `BAAI/bge-m3`）。
5. **纯知识问答 System Prompt 冗长（P2）**：`_build_system_prompt` 在纯本地知识库命中场景仍携带 CMDB/IPAM/Telemetry/自我介绍等长段规则，增加无谓输入 Token。

## 3. 影响范围与拟修改文件
- `D:\netops\netsops-main\backend\ai\services\intent_parser.py`：扩展 `is_knowledge_query` 覆盖产品规格参数查询与泛化排障知识查询。
- `D:\netops\netsops-main\backend\ai\services\assistant.py`：
  - `retrieve_knowledge` 实现精确型号命中裁剪（精确命中时收敛至 Top-2，其余默认 Top-3）。
  - `_build_system_prompt` 增加 `knowledge_compact` 精简分支，纯本地知识命中时使用轻量系统提示词。
- `D:\netops\netsops-main\backend\ai\gateway\llm_gateway.py`：本地拦截/取消状态不再污染 `ai_provider` / `ai_model` 的 `health_status`，成功推理同步更新 `last_health_check_at`。
- `D:\netops\netsops-main\backend\ai\providers\embedding.py`：新增 `OpenAICompatibleDBEmbeddingProvider`，在未配置 sidecar 时自动使用数据库中启用的 `embedding` 模型。

## 4. 实施步骤
1. 完善 `intent_parser.py` 确定性知识快路径 + `assistant.py` RAG 动态裁剪（P0）。
2. 修复 `llm_gateway.py` 健康状态写回逻辑 + 在 `embedding.py` 接入 DB Embedding Provider（P1）。
3. 在 `assistant.py` 增加 `knowledge_compact` 精简系统提示词（P2）。
4. 运行相关后端 pytest 与端到端 Python 验证脚本（验证意图快路径、RAG 裁剪、在线 BAAI/bge-m3 语义检索、健康状态修复与精简 Prompt）。
5. 归档 `docs/walkthrough/walkthrough_20261123_0815_01_RAG推理提速与语义向量全链路优化.md`。

## 5. 验证计划
- 单元测试：运行 `pytest` 覆盖 `intent_parser`、`llm_gateway`、`embedding`、`rag_retriever` 相关测试。
- 实测脚本：
  - 验证 `锐捷 RG-S6120-20XS4VS2QXS 的端口规格是什么？` 走 `deterministic` 快路径（0ms，不调 LLM）且 RAG 裁剪后只注入精准匹配文档。
  - 验证 `semantic_embedding_provider()` 自动加载 `BAAI/bge-m3` 并产出 1024 维向量。
  - 验证 `deepseek-v4-flash` 在 `ai_model` 中恢复 `healthy`，且模拟 `blocked` 不再污染健康状态。

## 6. 风险与回滚思路
- **风险**：DB Embedding Provider 在无网络或超时时可能拖慢检索 -> 设定合理超时（8s）并保留异常降级至本地检索；单测环境中若无 DB 或无配置则安全返回 `None`。
- **回滚**：4 个文件均为局部增量修改，可直接 `git checkout -- <file>` 回滚单个优化项。
