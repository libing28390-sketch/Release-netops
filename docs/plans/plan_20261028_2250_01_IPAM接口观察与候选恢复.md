# IPAM接口观察回显与候选恢复

## 目标与现状

v1.0.11 后 IP 地址页显示网段数量但地址列表为0，接口候选弹窗也为0。只读核实本机 PostgreSQL：WH-DC-01 有15个网段；最后成功 CMDB 接口快照有55条带IP观察，按 IPAM 当前站点解析规则，WH-DC-01 地址页范围内有7条；legacy `interfaces`/`ip_inventory` 和正式 `ip_addresses` 台账均为0。IP地址页前端请求强制 `registered_only=true`，网段候选服务只查询 legacy `interfaces`。根因是展示/候选查询源未随 CMDB 快照隔离迁移，不是原始快照数据被删除。15 是网段数，不是已登记IP数。

## 影响范围与接口约束

仅修改IPAM接口观察展示、CMDB快照到IP前缀候选读取、相关API响应契约和测试。监控代码、ARP/MAC采集、设备驱动和TextFSM模板保持不动。IP地址页面恢复显示只读的current CMDB interface observations，并把正式登记数、接口观察数分别标记。前缀候选优先读取各设备最后成功CMDB接口快照；旧shared interfaces仅用于无可用CMDB快照的旧设备。用户明确指定快照缺失 VRF 默认全局/默认；若精确前缀已唯一存在则复用该前缀 VRF，候选可在生成前改选本租户 VRF。

## 拟修改文件与步骤

1. 修正`src/pages/IPVlan/ipAddressQuery.ts`与`IPAddressTab.tsx`，恢复正式地址和只读采集观察混合清单，统计芯片仍明确显示正式登记数量，并显示观察数量/来源；导出使用同一数据范围。
2. 修正`backend/services/ipam_service.py`候选加载，按CMDB成功generation读取IP/前缀长度/设备/站点；复用旧interface表作为兼容来源，避免重复行。快照缺VRF且无唯一现有前缀时，默认全局/默认；操作员可在生成前覆盖成租户内 VRF。
3. 更新前端候选状态呈现，默认全局/默认清晰可见，可调整 VRF；让观察到的数据和未能安全生成的原因可见；不扩大解析模板或采集行为。
4. 添加隔离PostgreSQL与页面查询回归测试，验证IP观察不误计为登记、快照候选来源、legacy兼容、缺VRF默认为全局、显式租户VRF覆盖有效，以及无站点仍不能生成。

## 本次方案收敛

- IP地址页返回登记记录与只读观察记录；计数分别标为“IPAM登记地址”“接口观察”和“终端发现”，避免把接口观察重复计入终端发现。观察行保持只读。快照CIDR展示为观察信息，缺少VRF时不冒充已关联IPAM网段。
- 接口候选读取最后一次成功的 `interface_inventory` generation；仅对没有成功快照的设备回退读取旧 `interfaces`，防止旧表残留与快照重复。
- 本机只读复核：接口候选共55个IP、34个CIDR候选组、0个跳过；本次按用户要求，缺少 VRF 的候选默认全局/默认，并允许改选租户内 VRF。正式IP登记仍为0，接口观察不会自动写入正式台账。

## 验收与回滚

当前只读计数复核：正式地址0、CMDB观察55、WH-DC-01观察33、legacy接口0。修改后同数据库UI/API查询能见观察数据，正式登记仍为0；候选对55行均有明确生成资格或跳过原因，旧源回退可用。运行聚焦PostgreSQL测试、前端测试/TypeScript、构建和PG-only扫描。回滚应用提交可恢复旧只读行为；不迁移/删除用户台账、共享采集数据或CMDB快照。
