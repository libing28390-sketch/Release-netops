# 实施计划 - 迪普 Netmiko device_type 驱动映射全链路修复与 NTP 模版说明

## 1. 任务目标
1. 解决自动化任务/诊断在对 `dptech_conplat` 或 `dptech_conplat_fw` 平台设备执行 CLI 命令时抛出 `Error: Unsupported 'device_type' currently supported platforms are: ...` 的 Netmiko 驱动不支持错误。
2. 在全后端驱动与服务（`netmiko_driver.py`、`inspection_service.py`、`operational_data_service.py`、`diagnose_service.py` 等）中将迪普平台（`dptech_conplat` 与 `dptech_conplat_fw`）全量映射到 Netmiko 官方合法的 `dptech_ios` 驱动。
3. 梳理并解答系统内 NTP 自动化剧本与 TextFSM 模板的分发规则。

---

## 2. 根因分析
- **Netmiko device_type 校验机制**：Netmiko 的 `ConnectHandler` 初始化时会严格检查 `device_type` 参数。
- **别名丢失导致原样传递**：当设备平台为新定义的 `dptech_conplat` 或 `dptech_conplat_fw` 时，`netmiko_driver.py` 的别名映射列表中缺少该属性，且在降级时将 `dptech_conplat_fw` 原样作为 `device_type` 传给 Netmiko，导致 Netmiko 报出找不到平台的错误。

## 4. 实施步骤

1. **更新 `backend/drivers/netmiko_driver.py` 与 `backend/engine/drivers/netmiko_driver.py`**：
   - 在 `aliases` 字典中增加 `'dptech': 'dptech_ios'`, `'dptech_conplat': 'dptech_ios'`, `'dptech_conplat_fw': 'dptech_ios'`。
   - 在 `mapping` 字典中增加 `'dptech_ios': 'dptech_ios'`。
2. **更新服务层 Netmiko 平台映射**：
   - 更新 `inspection_service.py` 中的 `_netmiko_platform_type`。
   - 更新 `operational_data_service.py` 中的 `PLATFORM_DEVICE_TYPE_MAP`。
   - 更新 `diagnose_service.py` 及 `ip_locator_service.py` 中的 Netmiko 驱动类型解析。
3. **解答 NTP 模板定义**：
   - 总结多厂商 NTP 查询命令（Cisco: `show ntp status`, 华为/华三: `display ntp-service status`, 迪普/锐捷/迈普: `show ntp status`）与 TextFSM 结构化解析逻辑。
