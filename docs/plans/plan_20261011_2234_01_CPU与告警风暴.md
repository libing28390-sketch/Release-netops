- 当前有多个历史构建目录。Vite/Tailwind 是否扫描这些目录待源码和实际扫描文件清单确认。

## 验证计划

- 告警状态只读查询、健康检查和 CPU/内存采样。
- 前端仅配置扫描边界变更时检查配置解析、实际候选入口/源文件清单，避免为验证制造全量构建尖峰。

- 不运行全量回归或真实设备配置变更，不删除告警历史或构建产物。

## 风险与回滚

- 缺凭据误报恢复保留历史记录，通知静默；真实配置设备的 SNMP 失败告警继续保留。
- 限制扫描边界必须覆盖实际前端源码和必要的动态类来源，遗漏会导致 CSS 缺失；需要核对文件清单。
- 运行时会有 VMware、浏览器和 Codex 负载，最终报告区分整机值与进程值。重启前端只在端口空闲且完成配置检查后执行。

## 22:38 扫描证据与实施决定

- Vite 6.4.1 默认 `**/*.html` 发现应用入口以外的 4 个非隐藏 `dist-*` HTML。tinyglobby 默认排除隐藏目录，不能说全部 22 个目录都进入 Vite 优化器。
- Tailwind Oxide `Scanner.files` 只读清单实际有 15,070 条，其中历史构建目录占 7,777 条；限定 `src` 后为 590 条。文件清单读取未调用全量 `scan()`。
- 允许修改 `vite.config.ts`：固定 `optimizeDeps.entries=['index.html']`，文件监听排除 `dist-*` 与 `.codex-*`；修改 `src/index.css`：将 Tailwind 自动源目录改为样式文件所在的 `src`。
- 后端 Agent 只在新增 `backend/tests/monitoring/test_background_monitor_snmp_alerts.py` 写回归用例；共享业务文件仍归主 Agent。
- 离线告警存在独立的状态机问题：仅状态翻转时投影告警，因此单独将 FOR 调大可能使 PENDING 无后续样本。本轮不通过修改实时规则来绕过此问题，保留证据并单列后续整改。
- 用户追问 Docker：Dockerfile 前端阶段执行生产构建，运行阶段为 Python 后端加 Nginx 静态文件，不运行 Vite 开发服务器。`.dockerignore` 原来只排除 `dist/`，新增 `dist-*/` 与 `.codex-*/`，避免本地验证产物进入 Docker 构建上下文。共用后端告警改动需重建镜像才应用到容器。
- 开发后端执行 `uvicorn.run(..., reload=True)` 时，Uvicorn 明确报告监听整个仓库根 `D:\\netops\\netsops-main`；Python 自动重载因此涵盖 node_modules、验证构建输出等无关目录。将重载根收窄到 `backend/`，保留 Python 代码的自动重载。运行中的 Uvicorn 父级需要下次完整启动后才会采用新目录。
- 本地日志在 21:40:18 是最后一条逐设备“未配置 SNMP”编译 warning，累计 12,952 条；21:51 工作树已合并为每次编译单条聚合 warning，当前附件中的 455 条逐设备日志属于旧实现。日志保留了 21:55 之后的新聚合记录。本轮不重复改写该既有聚合修复。
- PostgreSQL 只读查询显示当前 221 台设备全部带 `asset_id`，只有 15 台有 `snmp_credential_id` / `snmp_community`；15 条绑定均已同步到 `devices`，未发现只有资产表保存 SNMP 配置的行。通用 SSH `credential_id` 在当前 15 条中均没有关联 SNMP community。
- 本地日志 20:38 有 9 次 CollectorAutoSync 与 36 次状态翻转；20:07 有 8 次同步、约 1,446 条逐设备未配置告警。结合 `asset_id` 对 221 台设备全命中，确认状态波动能触发不必要的全量采集目标编译。已将筛选收窄到显式 SNMP 字段或服务器目标，并增加纯资产关联与 SSH credential 不触发编译的回归用例。
- 每 5 分钟一次的 CollectorAutoSync 是固定周期任务，保留；本次仅阻断无 SNMP 普通设备状态变化触发的额外同步。
