# 凭据轮换页面密度改版计划

## 任务目标

重排凭据轮换页，让设备与凭据状态更容易扫描，减少宽表横向滚动和操作区文字换行，同时保留现有筛选、密码查看/复制、轮换、导出和分页行为。

## 现状与问题

- 当前表格把设备字段和三种账号类型的全部字段并排展开，设置了 2600px 最小宽度。
- 凭据查看和轮换操作挤在账号列内，窄列造成文字换行和过高的表格行。
- 顶部统计卡采用多块高饱和渐变，零值告警也占据强视觉层级。
- 应用栏与页面标题对凭据轮换功能使用了不同名称。

## 影响范围

- 页面呈现层、页面标题文案，以及共享凭据关联设备的只读分页查询；不修改凭据操作逻辑。
- 主要文件：`src/components/PasswordRotationPanel.tsx`、`src/hooks/usePageTitle.ts`、`backend/api/devices.py`、`backend/services/password_rotation_service.py`。

## 实施步骤

1. 将凭据表收敛为凭据组、设备摘要、平台和账号类型摘要列。
2. 增加按需展开的详细状态区，保留各账号的用户名、设备数、状态、最近轮换时间和到期时间。
3. 统一账号操作布局，确保查看、复制和轮换按钮不换行，保留权限限制和确认流程。
4. 将统计卡改为低饱和度摘要样式，只有存在临期或过期凭据时才突出提醒色；压缩说明提示。
5. 统一应用栏和页面主标题为“凭据轮换”。
6. 关联设备摘要最多展示两个设备名称和剩余数量；详情通过独立面板查看，默认每页 20 条。
7. 共享凭据设备面板使用服务端关键词搜索、平台筛选和分页，覆盖加载、失败、空结果及关闭时取消请求；单设备本地凭据沿用本地单条数据。

## 验证计划

- 运行 `npm run lint`、相关静态检查与前端生产构建。
- 在现有浏览器页面确认热更新结果、表格列数与行高、账号筛选、详情展开、设备搜索和分页。
- 检查查看/复制/轮换交互仍连接原处理函数，不触发真实凭据操作。

## 风险与回滚

- 主要风险是压缩后的摘要遗漏旧表格中的状态字段；展开区需保留全部角色状态与日期，导出仍使用完整导出数据。
- 设备分页查询只返回设备标识、名称、管理 IP 和平台，不返回凭据；每页上限 100，关闭或改筛选时取消旧请求。
- 若页面布局或操作行为不符合预期，可通过本次改动的工作区 diff 回滚源文件，保留已有业务数据。
