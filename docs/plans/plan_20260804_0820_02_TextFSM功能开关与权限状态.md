# TextFSM 功能开关与权限状态收口实施计划

## 任务目标

根据 2026-08-04 审查后清单 P0-2，使 TextFSM 注册表页面读取后端能力状态；租户写入、样例持久化和生命周期操作由资源权限与后端生命周期校验控制，同时保留明确的只读 SYSTEM Sandbox。所有新增提示和按钮文案必须中英文随页面 `language` 状态切换。

## 现状/问题

- 后端写 API 已有资源权限与生命周期校验，但 `ParserRegistryTab` 只按角色计算 `canEdit/canReview/canSample`，未读取后端能力状态。
- 页面需要在能力状态加载失败或角色无权限时明确禁用“新建”、Fork、保存草稿、上传样例等入口，避免点击后才收到错误。
- 页面未显式区分能力状态不可用和角色无权限。
- SYSTEM/PUBLISHED Sandbox 本身允许 `persist=false`，应保持只读测试能力。

## 影响范围

- `backend/api/parser_templates.py` 新增只读 capabilities 契约。
- `src/pages/ParserRegistryTab.tsx` 的能力加载、角色/开关组合和中英文提示。
- `backend/tests/platform_registry/test_parser_templates.py` 的 capabilities/默认关闭回归。
- 不改数据库结构，不改变现有写 API 状态码和持久化语义。

## 拟修改文件

- `backend/api/parser_templates.py`
- `backend/tests/platform_registry/test_parser_templates.py`
- `src/pages/ParserRegistryTab.tsx`
- 视需要补充本计划对应 walkthrough；不修改无关页面。

## 实施步骤

1. 增加 `GET /api/parser-templates/capabilities`，使用 `textfsm.view` 鉴权，返回 `write_enabled` 与 `read_only_sandbox_enabled`。
2. 页面加载 capabilities，并将其与现有角色档案组合成 `canWrite/canTest/canReview/canSample`。
3. 开关关闭时隐藏或禁用新建、Fork、草稿保存、样例上传/删除、历史回归和生命周期按钮；SYSTEM Sandbox 保留。
4. 写操作函数增加前端守卫，避免通过其他交互路径提交请求。
5. 增加中文/英文状态提示，复用现有 `zh` 分支，不写入单语硬编码。
6. 运行后端专项、lint、浏览器登录态只读复核；不执行写操作。

## 验证计划

- `pytest backend/tests/platform_registry/test_parser_templates.py -q`
- `pytest backend/tests/platform_registry -q`
- `npm run lint`
- 登录态浏览器在开关关闭时检查按钮和 Sandbox 状态；开关开启的写流程留待独立测试租户验收。

## 风险与回滚思路

- capabilities 读取失败时默认 fail-closed：隐藏写入口，但不阻断模板只读列表和 SYSTEM Sandbox；需要在 UI 显示安全的加载/失败状态。
- 不改变后端 `_enabled()`，因此即使前端绕过也仍由后端 503 保护。
- 若页面角色模型与后端资源权限出现差异，保留后端 401/403 为最终边界，并在测试中记录。
