# 拓扑发现性能修复实施计划

## 问题

一次拓扑发现会对每台平台注册设备分别执行 LLDP、接口摘要和聚合信息采集；任务入口又按设备串行等待，导致设备数量增加时耗时线性叠加。解析失败、认证失败等确定性错误还会被重复执行。

## 实施方案

1. 在拓扑发现任务层增加可配置的设备级有界并发，默认 `TOPOLOGY_DISCOVERY_DEVICE_CONCURRENCY=6`。
2. 保留 `NETWORK_SSH_PER_DEVICE_CONCURRENCY=1`，不允许同一设备的多个 CLI 会话并发。
3. 对同一设备的 LLDP 与 Eth-Trunk 只建立一个只读 `PlatformActionSession`，在会话内逐条发送并分别解析回显。
4. 增加拓扑任务租约心跳，避免并发批次或慢设备运行期间租约过期。
5. 仅对 `ssh_unreachable` 瞬时传输故障重试；认证、凭据、动作/平台不支持及解析失败直接记录设备失败。
6. 用异步 mock driver/采集器覆盖并发上限、重试策略和单会话多动作行为。

## 验收标准

- 多设备任务的峰值并发不超过配置值。
- 同一设备仍由网络访问限制器串行保护。
- 确定性失败不会再次建立 SSH 会话。
- 任务状态、设备明细、租约和最终拓扑重建结果保持可观测。
