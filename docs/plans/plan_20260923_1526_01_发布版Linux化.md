# 任务目标

将 Nexora 从 v1.0.9 起收敛为 Linux/Docker/Ubuntu 发布形态，移除 Windows 桌面发行、Windows 安装包和 Windows 发布流水线，同时保留对 Windows 网络资产的远程管理能力；补齐 v1.0.9 release 说明，完成验证、提交、推送和 tag 更新。

# 现状/问题

仓库仍包含 Windows 桌面启动器、安装脚本、打包产物及发布流水线引用。部分前端和后端仍提供 Windows 本机下载/路径能力，容易让用户误以为 v1.0.9 继续支持 Windows。当前 v1.0.9 tag 需要在最终提交后重新指向本次完整改造。

# 影响范围

- 发布与部署：Dockerfile、Compose、Ubuntu/Docker 脚本、GitHub release workflow。
- 前后端本机能力：系统下载接口、终端 Agent 安装提示、Profile 设置页、Linux 终端路径模型。
- 删除 Windows 桌面发行文件、Windows 安装/打包文件及专属部署文档。
- 保留 Windows 资产管理、WinRM/远程设备能力、面向被管理 Windows 主机的监控内容，以及 Windows 浏览器访问 Linux 服务端所需的本机 Agent/Web PAM 能力。
- 版本与发布说明：v1.0.9 明确为 Linux/Docker/Ubuntu-only，v1.0.8 为最后一个 Windows 桌面版本。

# 拟修改文件

- `.github/workflows/release.yml`、`Dockerfile`、`docker-compose.yml`、`.env.example`、`scripts/deploy-docker.sh`、备份/安装脚本。
- `backend/main.py`、`backend/api/system.py`、`backend/core/api_security.py`、终端 Agent 脚本及相关测试。
- `src/components/ProfileModal.tsx`、`src/utils/localTerminal.ts` 及前端配置/文案；Windows 浏览器访问与本机 Agent 下载保持跨平台工作站能力。
- 删除 `desktop/`、Windows 可执行文件、Windows 安装脚本和 Windows 发布文档。
- 新增 `docs/deploy/release-notes.md`，并补充本任务的 plan、walkthrough、fix 记录。

# Agent 分工边界

- `linux_only_cleanup`：清理 Windows-only 服务端发行文件、前后端本机入口及残留引用；不删除 Windows 资产管理/WinRM/工作站 Agent。
- `linux_release_audit`：审查部署文档、发布流水线和 Linux-only 发布路径；不提交、不推送。
- 主 agent：统一处理共享文件冲突、版本/tag、验证、fix/walkthrough 文档、提交和推送。

# 实施步骤

1. 盘点 Windows 发布相关路径和当前工作树，保留用户已有改动。
2. 合并 agents 的清理结果，修正共享文件和发布 workflow 的残留引用。
3. 添加 v1.0.9 release notes，明确 Linux-only 服务端范围、Windows Workstation Agent 保留方式与迁移提示。
4. 运行静态搜索、PostgreSQL-only 检查、后端相关测试、前端 lint/build 和 YAML/脚本校验。
5. 创建本次提交所需的 fix 记录，提交到 `main`，推送 `origin/main`。
6. 将 `v1.0.9` tag 更新到最终提交并推送远端，核对远端 ref。

# 验证计划

- `rg` 检查 Windows 发布/桌面残留，并确认 Windows 资产管理引用仍在。
- `python scripts/validate_postgresql_only.py`。
- 相关 pytest（系统/终端 Agent、存储、SNMP 及迁移契约）和前端 `npm run lint`、`npm run build`。
- 使用 Python YAML 解析器检查 release workflow；Docker 在当前 Windows 主机不可用时记录未执行原因。
- `git status`、提交图、远端 main 和 `v1.0.9` tag 核对。

# 风险与回滚思路

- 删除 Windows 桌面发行文件会使 v1.0.9 无法生成 Windows 包；v1.0.8 tag 保留作为历史回滚点。
- 保留 Windows 资产管理代码，避免把“发布平台不支持 Windows”误改成“不能管理 Windows 设备”。
- 若 release workflow 校验失败，先修正 workflow/文档并重新验证；若发布后需回滚，可将部署固定到 v1.0.8 或恢复到本次提交前的 main 提交。
