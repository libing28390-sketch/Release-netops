# 实施计划：支持双角色凭据绑定 (Normal/Admin)

当设备启用双角色认证 (PAM) 模式时，设备需分别配置并使用普通用户与特权/管理员用户登录。本项目当前数据库仅设计了单个 `credential_id` 字段，导致用户只能关联其中一个凭据（关联 `test_admin` 时 `test_user` 即显示“未关联”，反之亦然）。

为了彻底解决这一设计限制，我们需要扩展系统以支持双角色凭据分别绑定：
1.  **普通账号凭据** (对应原有 `credential_id` / `normal_username`)
2.  **特权账号凭据** (新增 `admin_credential_id` / `admin_username`)

---

## Proposed Changes

### 1. 数据库结构变更

#### [MODIFY] [schema.py](file:///d:/netops/netsops-main/backend/database/schema.py)
要在 `physical_assets` 和 `devices` 表中，使用 `ensure_column` 分别追加 `admin_credential_id` 字段：
```python
    ensure_column('physical_assets', 'admin_credential_id', "TEXT DEFAULT ''")
    ensure_column('devices', 'admin_credential_id', "TEXT DEFAULT ''")
```

---

### 2. 后端 API 与服务变更

#### [MODIFY] [assets.py](file:///d:/netops/netsops-main/backend/api/assets.py)
*   **Pydantic 校验模型**：
    *   在 `AssetCreate` 与 `AssetUpdate` 模型中添加 `admin_credential_id` 属性。
*   **`_pre_resolve_credential` 预解析逻辑**：
    *   拆分普通凭据和特权凭据的自动回填字段。普通凭据 `credential_id` 仅回填 `normal_username`/`normal_password`，特权凭据 `admin_credential_id` 仅回填 `admin_username`/`admin_password`，避免两者发生覆盖与混淆。
*   **`_create_linked_device` 设备创建逻辑**：
    *   在 `INSERT INTO devices` SQL 语句中包含 `admin_credential_id` 字段，支持双凭据写入。
*   **`_sync_device_from_asset` 设备同步逻辑**：
    *   支持 `admin_credential_id` 变更后对设备行进行同步更新，自动解密并回填特权口令。
    *   升级共享凭据防篡改机制，若修改了特权凭据但在 `credentials` 中其属于共享凭据，则不执行覆盖写入。
*   **API 路由接口**：
    *   在 `POST /assets`、`PUT /assets/{asset_id}` 及 `POST /assets/import` 接口的 SQL 写入参数及更新列表中追加 `admin_credential_id`。

#### [MODIFY] [vault_service.py](file:///d:/netops/netsops-main/backend/services/vault_service.py)
*   在统一凭据解析函数 `resolve_device_credentials` 中，检测到 `admin_credential_id` 时从 `credentials` 表读取对应的行，并用它解密还原出 `admin_username`、`admin_password` 和 `enable_password`。

#### [MODIFY] [credential_service.py](file:///d:/netops/netsops-main/backend/services/credential_service.py)
*   更新 `_list_devices_using_rows`，支持 `credential_id = ? OR admin_credential_id = ?`，确保两个绑定入口关联的设备都能正确反映在凭据关联列表中。
*   更新 `_infer_device_account_role` 推导逻辑。若设备通过 `admin_credential_id` 指向该凭据则直接判定为 `admin` 角色；若通过 `credential_id` 指向该凭据则判定为 `normal` 角色。这彻底解决了基于用户名比对导致 `user` 用户显示为“管理员账号”的推导逻辑问题。

### 3. 前端 UI 界面变更

#### [MODIFY] [constants.ts](file:///d:/netops/netsops-main/src/pages/AssetManagement/constants.ts)
*   在 `COL_MAP` 中增加 `'绑定特权凭据'` -> `'admin_credential_id'` 导入映射。
*   在 `EMPTY_FORM` 模板中，追加 `admin_credential_id: ''` 属性。

#### [MODIFY] [index.tsx](file:///d:/netops/netsops-main/src/pages/AssetManagement/index.tsx)
*   在 Excel 导入模板表头及样例中增加 `绑定特权凭据` / `Admin Credential` 列。
*   在复制 `openCopy` 和编辑 `openEdit` 触发时，同步映射表单状态中的 `admin_credential_id`。

#### [MODIFY] [AssetModal.tsx](file:///d:/netops/netsops-main/src/pages/AssetManagement/components/AssetModal.tsx)
*   在“绑定已有凭据 (推荐)”模式下，提供两个下拉选择框：
    *   **“普通账号凭据”** (对应原有 `credential_id`)
    *   **“特权账号凭据”** (对应新增 `admin_credential_id`)
*   这两个下拉框在界面上分别与普通及管理员账户字段对齐，并在表单保存时同步提交至后台。
