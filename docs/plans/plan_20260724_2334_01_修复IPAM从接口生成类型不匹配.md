# 修复 IPAM 从接口生成时 PostgreSQL 布尔类型不匹配 Bug

此计划旨在修复在 PostgreSQL 环境下，从接口生成 IPAM 网段时，由于 SQL 语句中使用 `COALESCE(boolean, integer) = 1` 导致 PostgreSQL 抛出类型不匹配异常（`DatatypeMismatch: COALESCE 参数类型 boolean 与 integer 不匹配`）的 Bug。

## 问题分析

1. **现象**：在 IPAM 网段页面点击“从接口生成”时，前端弹出提示“服务内部异常，请联系管理员查看后端日志”。
2. **根因**：
   - 在 `backend/services/ipam_service.py` 的第 424 行，SQL 查询语句为：
     ```sql
     WHERE (COALESCE(i.is_l3, 0) = 1 OR COALESCE(i.ip_enabled, 0) = 1)
     ```
   - 在 SQLite 环境中，布尔类型字段（`is_l3` 和 `ip_enabled`）以整数 `0`/`1` 存储，所以该 SQL 运行正常。
   - 在 PostgreSQL 环境中，这两个字段为 `boolean` 类型。PostgreSQL 执行 `COALESCE` 时要求两个参数类型兼容，因此无法在 `COALESCE` 中将 `boolean` 字段与 `0` (integer) 结合；同样也无法执行 `boolean = 1` 比较，从而抛出类型不匹配错误。

## 解决方案

将 `COALESCE(i.is_l3, 0) = 1` 修改为 `COALESCE(i.is_l3, FALSE) = TRUE`（`ip_enabled` 也做同样修改）。
由于 SQLite 会自动将 `FALSE`/`TRUE` 映射为 `0`/`1`，此写法在 PostgreSQL（严格布尔对比）和 SQLite（数值型对比）下均能完美兼容。
