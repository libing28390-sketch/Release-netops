# 支持 CMDB 站点导入/新建使用国内 11 位手机与座机号码

## 1. 任务目标
修复在 `http://192.168.56.1:5400/cmdb/sites` 导入或新建站点时，输入国内 11 位手机号（如 `13111111111`）或座机号（如 `010-88888888`）时被后端校验强行拒绝并提示 `contact_phone must include an international country calling code, for example +8613800000000` 的问题。

## 2. 现状与根因分析
- **问题现象**：前端 UI 与 Excel 模板提示“支持 11 位手机、座机或国际号码”，并且占位符示例为 `13800000000`。但用户在 Excel 批量导入站点时输入 `13111111111`，后端提示 `contact_phone must include an international country calling code, for example +8613800000000` 导致导入失败。
- **技术根因**：
  在 `backend/schemas/schemas.py` 中：
  1. `SiteCreate.validate_contact_phone` 校验时传入了 `international_required=True`，强制所有传入电话必须以 `+` 国际区号开头。
  2. `SiteCreate.validate_phone_for_country` 后置校验强制匹配 `^\+86[1-9]\d{10}$` 正则，拒绝了未加 `+86` 前缀的标准国内 11 位手机号及带区号座机。

## 3. 拟修改文件
1. `backend/schemas/schemas.py` [MODIFY]
   - `SiteCreate.validate_contact_phone`: 将 `international_required=True` 改为 `required=True`（默认允许 11 位手机号、座机及国际格式）。
   - `SiteCreate.validate_phone_for_country`: 放宽国内号码格式校验正则为 `r'^(?:\+86|0)?1[3-9]\d{9}$|^0\d{2,3}-?\d{7,8}$|^\+[1-9]\d{6,14}$'`，兼容 `13111111111`、`+8613111111111`、`010-88888888` 及其他合法国际号码。
2. `backend/tests/configuration/test_cmdb_sites_import_export.py` [MODIFY]
   - 新增针对国内 11 位手机号与座机号导入/新建的单元测试用例。

## 4. 实施步骤
1. 修改 `backend/schemas/schemas.py` 中的 `SiteCreate` 校验器。
2. 在 `backend/tests/configuration/test_cmdb_sites_import_export.py` 增加回归测试。
3. 运行 `pytest` 校验所有相关测试。
4. 重启后端服务端口 5310，确保最新校验规则生效。
5. 创建 `docs/walkthrough/walkthrough_20260806_2239_01_支持站点11位国内手机与座机号码导入.md`。

## 5. 风险与回滚
- **风险**：低。放宽了国内合规手机/座机的格式限制，使后端与前端 UI 承诺提示保持高度一致。
- **回滚思路**：可直接还原 `schemas.py` 和测试文件。
