# 实施计划：大盘接口全称展示、站点与设备下拉列表补全及 Linux 主机采集打通

## 1. 任务目标与背景
用户在基于 Linux 远程 Docker 运行的 Nexora 环境中，通过 Windows 浏览器查看 Grafana 大盘时发现以下三大问题：
1. **接口未展示全称，且出现带 `%` 的索引**：Top 排行表格中只有 `管理 IP` 和 `端口索引`（显示为 `3%`、`4%` 等），没有展示具体的接口全称（如 `GigabitEthernet0/0/1`）；
2. **所有 Dashboard 的「站点」和「设备」下拉菜单只有 `All`**：展开后没有任何具体站点（如 `WH-DC-01`）或具体设备（如 `R1`、`S6850-1`）；
3. **`07 Linux 服务器监控` 没有获取到主机数据**：用户已经在 Linux 宿主机（`192.168.204.128`）上安装并运行了 `node_exporter`（监听 9100），但大盘全部为 No data。

## 2. 深度根因分析
1. **Top 表格未排除索引且缺少数值 override**：
   - 表格之前直接暴露了 `ifIndex`，并且设置了全局 `unit: "percent"`，导致 Grafana 将整型的端口索引号 `3` 错误渲染为 `3%`；
   - PromQL 聚合未聚焦于 `ifDescr`（接口全称）和 `ifName`（接口名称）。
2. **Docker 持久化 Volume 阻断了最新 targets 与 snmp.yml 的同步**：
   - 用户的部署环境在 Linux 宿主机的 Docker 容器内，`vmagent` 和 `snmp-exporter` 挂载的是持久化命名卷 `nexora-monitoring-artifacts`；
   - 启动脚本 `scripts/sync-frontend-dist.sh` 之前仅在 `/etc/nexora-collector/runtime/vmagent/scrape.yml` 不存在时才执行初始化，导致代码库更新的带标签目标（`snmp_targets.yml`）与支持 `ifDescr` 的 `snmp.yml` 从未同步进 runtime volume，vmagent 采集入库的时序中完全缺失 `site_name`、`hostname`、`ifDescr` 标签，Grafana 的 `label_values(..., site_name)` 自然查出空；
3. **vmagent 缺失针对 Linux 宿主机的 `linux_nodes` 抓取作业**：
   - `scrape.yml` 中未配置抓取宿主机 `192.168.204.128:9100`，导致 `node_exporter` 数据无法入库。

## 3. 拟修改文件
- `scripts/sync-frontend-dist.sh`：容器启动时自动刷新默认 targets 和配置到运行时卷；
- `monitoring/vmagent/scrape.yml`：增加 `linux_nodes` 抓取作业（目标 `192.168.204.128:9100`）；
- `monitoring/grafana/generate_dashboards.py`：
  - 彻底排除 `ifIndex` 列，将 `ifDescr` 映射为 `接口全称`，`ifName` 映射为 `接口名称`；
  - 表格 Panel 采用 field override，防止非数值列被附加 `%`；
  - Top 聚合 PromQL 统一按 `by (hostname, instance, ifDescr, ifName)` 分组；
  - 重新编译生成全量 8 个大盘 JSON。

## 4. 验证计划
- 编译并校验 8 个大盘 JSON；
- 检查 Git 差异与工作树整洁度；
- 指导用户在 Linux 宿主机上拉取代码并快速热加载/重启容器验证。
