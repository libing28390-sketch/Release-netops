# 升级环境参数差异提示

## 目标

让 Docker `update` 每次自动比较更新前后的 `.env.example`，在终端醒目报告新增、默认值变更和废弃参数，并保存不含参数值的报告；不要求用户修改 `.env` 才触发。

## 现状与问题

- 更新流程备份 `.env`，随后同步新版代码并初始化环境参数。
- 目前脚本只显示 Git 文件级差异，不解析新旧环境模板中的参数变化。
- `initialize_env` 在同步新版前后都会改写少数缺失/占位参数，比较时必须使用更新前快照，不能只检查更新后的 `.env`。

## 影响范围

- 修改 Docker 更新脚本及采集器页面反馈；按用户授权部署到 `192.168.204.128` 并重启必要容器验证。
- 不自动覆盖目标机 `.env` 值，不输出任何变量值，不修改数据库或数据卷。

## 拟修改文件

- `scripts/deploy-docker.sh`
- `src/components/MonitoringManagementPage.tsx`
- `docs/plans/plan_20261018_2221_01_升级环境参数差异提示.md`
- `docs/walkthrough/walkthrough_20261018_2221_01_升级环境参数差异提示.md`

## 实施步骤

1. 暴露更新前 `.env` 备份路径和更新前配置备份目录路径。
2. 在同步新版后从更新前归档读取旧模板，与新版 `.env.example` 和原 `.env` 对比。
3. 生成只含变量名和变化类别的报告，并在 update 流程显著打印摘要及报告路径。
4. 保留现有 `.env` 初始化逻辑和用户值；检查最终差异与脚本语法。
5. 备份目标机将覆盖的文件，复制更新脚本与前端源码后重建必要镜像并重启服务。
6. 检查容器健康，并在目标页面验证采集器操作反馈。

## 验证计划

- `bash -n scripts/deploy-docker.sh`
- `git diff --check -- scripts/deploy-docker.sh`
- 静态检查报告不包含模板或 `.env` 的值。
- 部署后检查 Compose 容器健康与采集器页面的只读/操作反馈；不触发编译、发布、新建或删除采集器。

## 风险与回滚思路

- 变更只增加只读比较和报告写入；不改变环境变量迁移策略。
- 若报告逻辑异常，可回退脚本中的报告函数和 update 调用。
- 若目标服务重启或构建失败，恢复已备份文件并按部署前容器镜像恢复；不迁移或清理数据卷。
