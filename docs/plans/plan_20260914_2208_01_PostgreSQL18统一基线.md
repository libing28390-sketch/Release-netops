# PostgreSQL 18 统一基线实施计划

## 任务目标

将 Nexora 当前生产、Windows、Docker 和 CI 发布基线统一为 PostgreSQL 18，并确保 Windows 发布包离线携带 `pgvector 0.8.6` 的 PG18 资产；同时修复 Windows 启动器已确认的 `psycopg2` 打包缺失问题，并在已配置的快速启动和数据库密码输入流程中补充用户确认。

## 现状 / 问题

- Docker 与 CI 数据库镜像原先固定 PostgreSQL 17。
- Windows 向导原先默认安装 PostgreSQL 17.6，发布包仅携带 PG17 的 pgvector ZIP。
- 根目录已有经过固定 SHA-256 校验的 PG17/PG18 ZIP，但安装器只读取 `third_party/pgvector/`。
- `NetOps.exe` 在自身运行时执行 PostgreSQL 就绪检查，但当前打包环境没有安装 `psycopg2-binary`。
- 当前部署文档、发布契约和后端启动流程原先未统一强制 PostgreSQL 18。

## 影响范围

- Windows 安装器、PyInstaller 构建依赖和离线 pgvector 资产。
- Docker PostgreSQL 镜像及复用该镜像的 CI 测试环境。
- PostgreSQL 18 官方容器版本化 `PGDATA` 路径和 Docker 持久卷挂载点。
- 发布工作流、发布契约检查、Windows pgvector 单元测试。
- 当前 README、部署指南和公开部署说明。
- 已配置客户端的快速启动确认，以及 PostgreSQL 密码的双输入一致性校验。
- 不改写历史 plan、walkthrough、fix 记录，也不迁移或修改任何真实数据库。

## 实施步骤

1. 将 Windows 默认安装版本更新为 PostgreSQL 18.6，并由 Windows 向导和后端数据库初始化共同拒绝非 18 主版本，错误信息提示执行安全的主版本迁移。
2. 将 PG18 pgvector ZIP 放入发布器实际读取的 `third_party/pgvector/`，更新 SHA-256、工作流下载地址和发布白名单；PG17 根目录临时文件不作为新基线发布。
3. 将 Docker pgvector 镜像与 contrib 包改为 PostgreSQL 18，使复用该 Dockerfile 的 CI 同步升级。
   同时按 PostgreSQL 18 官方容器布局把数据卷挂载至 `/var/lib/postgresql`，并拒绝旧挂载路径。
4. 在 Windows PyInstaller 构建环境中安装并显式收集 `psycopg2`，消除 EXE 与 `.venv` 解释器错位导致的导入失败；排除开发机 Poppler 提供的不兼容 ICU DLL；固定已验证的 PyInstaller、hooks-contrib、PySide6 和 psycopg2 版本，并在 CI 构建后运行 smoke test。
5. 已配置的快速启动显示 PostgreSQL 18 连接目标并要求用户确认；部署表单要求输入并确认两次非空数据库密码，不匹配时不启动部署。
6. 更新静态发布契约、单元测试、CI 证据清单和当前部署文档；历史故障记录保持原样。

## 验证计划

- 校验 PG18 ZIP SHA-256 与代码固定值一致，并运行 `desktop/tests/test_pgvector_windows.py`。
- 运行 Windows/知识引擎发布契约检查。
- 运行 PostgreSQL-only 策略扫描。
- 对 PostgreSQL 18、17、19 和无效版本返回添加单元测试，确认只接受 18。
- 对快速启动连接摘要、密码双输匹配和密码不一致的拒绝路径添加单元测试。
- 校验 workflow YAML、Dockerfile 版本引用和发布白名单，不再保留当前基线中的 PG17 固定值。
- 构建 `NetOps.exe`，检查归档包含 `psycopg2`、不含不兼容 Poppler ICU，并运行本地与 CI smoke test；若无法运行 Docker，明确记录未验证约束。

## 风险与回滚思路

- PostgreSQL 17 到 18 是主版本升级，已有实例不能通过覆盖二进制原地升级；必须使用 `pg_upgrade` 或逻辑备份/恢复。代码和发布包统一版本不自动迁移用户数据库。
- Windows pgvector 二进制必须与 PostgreSQL 主版本严格匹配，SHA-256 校验失败时拒绝安装。
- Docker 已有 PG17 数据卷不能直接挂载给 PG18 容器；升级前必须备份并按主版本升级流程迁移。
- 回滚代码时恢复 PG17 镜像/安装器/发布资产；真实数据库回滚依赖升级前备份，禁止直接删除扩展文件或数据目录。
- 本机 Windows 10 系统 ICU 验收通过；仍需在干净 Windows 10/11 测试机确认系统 ICU 可用，若缺失则需随包提供与 Qt ABI 匹配的 ICU。
