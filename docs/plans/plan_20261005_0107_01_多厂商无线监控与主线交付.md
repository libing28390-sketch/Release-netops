- 子 Agent A（GPT-6 Luna Max）独占 H3C 采集实现文件：`backend/services/snmp_hardware_probe_service.py`、`backend/services/monitoring_oid_catalog.py`、H3C 无线配置迁移和对应 H3C 测试；不得回退其他既有改动，不得继续派生子 Agent。

## 实施步骤

1. 复核所有 tracked/untracked 工作区改动、当前分支/提交图、关联 worktree 和已有计划/走查，确认哪些文件属于用户已有任务。
2. 并行执行 H3C 代码补齐与 Huawei 官方 MIB/LibreNMS 只读核验；禁止两个执行者写同一文件。
3. 主 Agent 按核验结果补齐 Huawei 缺失的 LibreNMS 采集及 catalog/migration；锐捷/信锐不纳入本阶段改动。
4. 检查 SNMP 采集到硬件发现、库存状态、持久化指标、Prometheus/VictoriaMetrics 和 Grafana JSON 的完整数据流；同步 dashboard 生成器与相应 JSON。
5. 运行针对性后端/迁移/前端检查、仪表盘生成与 JSON 验证、全量差异和敏感信息审查；不对真实设备发起操作。
6. 更新本计划对应 walkthrough；提交前按规则新建 `docs/fixes/fix_*.md` 修复记录，并审查提交文件清单，保留全部相关源代码改动。
7. 在 `main` 创建一个可审查提交并推送 `origin/main`；查询该提交触发的 Actions，等待必需工作流全部成功。
8. 只有远端提交、Actions 成功及最终工作区状态都有证据时，执行用户要求的关机。

## 风险与回滚

- 没有真实无线设备时，现场 SNMP 响应和具体固件/型号可用性只能标为未验证；不得将文档存在等同于实机数据成功。
- 若官方 OID 在部分固件缺失，适配应报告部分/不支持，不能把缺失解释为零或成功覆盖。
- 遇到回归只修本任务相关变更，保留其他用户修改；用新提交修正已推送问题，不对主线使用 reset/force-push。
- Actions 失败时保持电脑开机并继续修复/重新验证，不得提前关机。
- 关机是最后一步；在关机命令前再次确认 GitHub Actions 通过且推送提交准确。
