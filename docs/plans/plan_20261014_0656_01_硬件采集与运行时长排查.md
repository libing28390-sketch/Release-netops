# 硬件采集与运行时长排查

## 任务目标

- 解释首次部署后接口先有数据、硬件晚数分钟出现，与用户点击“编译、发布”的关系。
- 解释系统运行时长曾只在无线设备显示的现象，核对设备支持、采集周期和大盘查询。

## 现状与范围

部署主机为 192.168.204.128。用户已授权服务器和浏览器排查。本任务采用只读方式检查本地源码、部署容器源码、日志、数据库、采集配置、时序指标和浏览器显示。

## 拟修改文件

仅保存本计划、配套走查报告和浏览器截图。不修改业务代码、数据库、部署配置或网络设备配置。

## 分工与共享文件

- 主 Agent：服务器证据、浏览器核对、时间线、结论和文档归档。
- Luna 子 Agent repo_monitoring_path：只读追踪编译/发布、硬件初始化、系统模块周期与大盘查询的源码路径，不写文件、不运行测试。
- 本计划、报告和截图均由主 Agent 维护；无需合并业务代码。

## 排查步骤与验证范围

1. 对照实际部署与本地关键源码，追踪编译/发布调用链。
2. 将首次 MIB 导入、硬件发现入库、硬件指标输出与手动编译时间对齐。
3. 核对当前硬件采样频率与重启后的缓存复用。
4. 核对 system 目标的实际 scrape interval、失败信息与 sysUpTime 序列。
5. 对少量设备执行只读 SNMP 标量 GET，对照真实大盘查询和有线设备浏览器显示。
6. 汇总已证实结论与仍未定位的底层超时原因。

## 风险与回滚

只读 SNMP 请求会增加少量查询负载，限制目标数量。文档不保存密码、SNMP community 或令牌。无运行时变更，因此无需业务回滚；不执行提交、推送或部署。

## 归档说明

本任务的只读检查不要求预先生成实施计划；此文件在完成检查时作为排查范围清单归档，与统一跨 Agent 走查报告配对。
