# 计划：看板与设备列表准确性

## 目标

修正 Grafana 03 无线看板把在线 AP 数误显示为离线数的问题；让 Grafana 03 的总量/离线数据在真实总量缺失时诚实显示无数据，并精简 02/03 硬件与无线 AC/AP 面板说明。同步改善 `/assets/network-devices` 主列表的机柜名称来源和过宽的旧列偏好，并保留适配信息在展开详情中。

## 现状与证据

- Grafana 03 当前在线 AP 为 2，与 AC_11 提供的“Total APs: 2 / Connected APs: 2”一致；但总量卡片为空，离线卡片显示 2。
- 看板生成器的 AP 总量查询只查询 `job="network_snmp"` 的总量指标；目前 H3C 采到的 `ap-count` 是“在线 AP 数”，来自 `platform_hardware_inventory`，不能当作总 AP 数或离线数。
- 离线查询在总量缺失时回退到 `ap-count`，所以将在线 2 错报为离线 2。修复后只有总量和在线量均存在时才计算离线量；否则显示无数据。
- Grafana 02 当前有 164 条电源序列，多条不同部件均为 80 mW，且存在未展开的 `ENTITY-MIB::entPhysicalName` 模板名；温度、风扇、光模块面板无数据。原始部件状态显示两台 AP 各有多条 `down/disabled` 射频记录，异常计数为 12。射频状态是否应视为故障尚缺设备配置上下文，因此本轮不擅自改其含义。
- `/assets/network-devices` 使用设备列表 API，旧列选择偏好可保存 26 列并导致主表横向溢出。平台内部代码、适配版本、绑定来源和“版本一致”属于低价值/重复字段，已由展开详情覆盖，因此从主表列选择中移除；升级列偏好键后回到 13 个核心列。设备 API 以前优先取 `racks.rack_name`，而资产机柜读取模型优先取 `racks.name`；需统一优先使用面向用户的名称，并兼容旧字段。
- Grafana 02 硬件和 03 无线面板的工具提示说明包含过多采集/实现细节；应压缩为简短读数说明，仅保留使用所必需的口径提示。

## 影响范围

- Grafana 生成器与其生成的无线看板 JSON。
- `/api/devices` 设备列表响应中的机柜展示名映射及其测试。
- 设备列表列偏好存储版本、低价值诊断列移出主表、导出字段同步及相关前端测试。
- 02/03 看板面板说明文案及生成后的 JSON。
- 计划、走查和按需提交时的修复记录。

## 文件边界与协作

- 主 Agent：`backend/api/devices.py` 及对应后端测试；`src/components/DeviceList/DeviceTable.tsx`、`deviceColumns.ts`、`deviceExport.ts`、`src/pages/InventoryDevicesTab.tsx` 及对应前端测试；维护本计划、最终集成和走查。
- Luna 子 Agent：只负责 `monitoring/grafana/generate_dashboards.py` 及该生成器实际改动的 Grafana JSON 输出；不得改后端、设备列表或创建额外子 Agent。生成前检查所有输出及工作树，保留已有文件。
- 不触碰现有未跟踪的构建验证目录。

## 实施步骤

1. 核验 `/api/devices` 字段来源和 `racks.name` / `racks.rack_name` 语义，优先返回面向用户的 `racks.name`，保留旧记录兼容回退。
2. 版本化设备列表列偏好键，避免旧的“全部列打开”设置在升级后继续造成横向溢出；将低价值的平台/适配诊断列从主表和导出移除，并保留有用的适配信息。
3. 修正无线看板离线 AP 查询，移除把 `ap-count` 作为总量/离线数的回退；缺少总量时保持“暂无采集数据”。
4. 精简 02 硬件和 03 AC/AP 面板说明，保留必要的口径提示。
5. 运行生成器并审阅完整输出差异；核对 AP 总量、在线、离线查询的指标语义及单位。
6. 运行聚焦后端/前端测试、Grafana JSON 解析和 `git diff --check`；复核已有只读浏览器基线。由于本轮不部署，运行中 Grafana 不作为改动后的验收环境。
7. 生成走查与修复记录，审阅暂存文件后提交并推送到 `origin/main`。

## 验证计划

- 运行设备列表 API 机柜名称映射的聚焦 pytest。
- 运行 `npm run lint`、相关 Vitest 测试及 `npm run build`。
- 运行 Grafana generator，确认仅预期 dashboard 文件变化；解析生成后的 JSON。
- 检查 02/03 硬件及 AP 面板说明均已缩短，且离线数缺少总量或在线数据时保持无结果。
- 复核 03 的 AP 总量仍只来源于总量指标，离线 AP 在总量指标缺失时不返回在线 AP 数。
- 只读浏览器检查用于建立运行前基线；不写入 Grafana、不部署、不操作设备。改动后通过生成 JSON、查询语义和自动化检查验证。
- 确认修复记录和走查已纳入提交，推送后 `main` 与 `origin/main` 同步。

## 风险与回滚

- 当前 AC_11 CLI 证据确认 AP 总量和在线量都是 2，但归一化遥测仅确认采到了在线 `ap-count`；总量指标缺失时离线数应为空，而不是假定为 0。
- 电源 80 mW、射频状态和客户端数无法仅凭模拟器看板判断实际设备语义，本轮记录但不冒险重映射。
- 若机柜记录的展示字段存在差异，通过 API 返回字段的兼容回退保持旧数据可见；回滚只需还原本次涉及的源文件/生成文件，不涉及数据库数据变更。
