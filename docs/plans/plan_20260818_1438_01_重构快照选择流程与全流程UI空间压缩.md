# 实施计划：重构快照选择流程与全流程 UI 空间压缩

- **任务目标**: 
  1. 修复选择设备后跳过快照列表直接触发对比的业务逻辑缺陷（改为进入快照选择页并预选 A/B，用户确认后进入对比，并在设备行提供一键直达按钮）；
  2. 对 Step 1（设备选择页）与 Step 2（快照选择页）进行全面的空间压缩与极简扁平化重构，消除大横幅、空旷指标卡与多层边距，大幅提升可用列表高度。
- **创建时间**: 2026-08-18 14:38

---

## 1. 现状与问题分析

1. **业务流程缺陷**:
   - 用户在 Step 1 点击设备时，系统在后台静默执行了 `autoCompare = true`，自动用最新的 2 份快照直接进入了 Step 3（差异对比），导致用户完全看不到 Step 2（快照选择与时间轴）；
   - 必须在 Step 3 点击“重选”才能返回 Step 2 挑选快照（如启动配置 vs 运行配置、历史版本对比），交互流程反直觉。
2. **UI 空间浪费**:
   - **Step 1（设备选择）**：PageHero 大横幅 + 巨幅标题 + 3 个大空白指标卡片（“可审计设备”、“当前页结果”、“对比方式”），吃掉了首屏 260px+ 高度，设备表格只能露出 1~2 行；
   - **Step 2（快照选择）**：同样存在大横幅与过大的容器边距，快照列表垂直视窗狭小。

## 3. 实施步骤

1. **调整 `handleSelectDevice` 与 `loadSnapshots`**：
   - 默认 `autoCompare = false`；
   - 加载快照后，自动将最新一份填入 B，上一份（或基线）填入 A 作为预选，但停留在 Step 2，由用户点击「开始对比」或快捷按钮触发对比；
   - 在 Step 1 设备列表行中增加「⚡ 快速对比最新」快捷按钮，满足一键直达需求。
2. **重构 Step 1（设备选择页）头部**：
   - 彻底隐藏独立 PageHero；
   - 移除 3 个冗余的大指标卡片；
   - 采用紧凑的单行工具栏（设备总数、搜索框、资产分类树折叠开关、标准化/原始模式切换）；
   - 设备表格和资产树直接铺满全屏高度。
3. **重构 Step 2（快照选择页）**：
   - 采用高度 ~40px 紧凑顶栏（返回设备列表、设备元信息、启动vs运行、快速对比最新、开始对比主按钮）；
   - 紧凑化 A / B 槽位卡片；
   - 快照时间轴列表撑满全部高度。
4. **验证与质量门禁**：
   - 运行 `npm run lint` 与 `npm run build`；
   - 运行 pytest 验证配置单测；
