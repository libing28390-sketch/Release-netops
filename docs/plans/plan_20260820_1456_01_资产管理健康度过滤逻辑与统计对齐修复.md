# 资产管理健康度过滤逻辑与统计对齐修复计划

## 1. 任务目标
修复资产管理页面（`/assets/dashboard`）顶部 4 联严重程度 / 健康度状态卡片与表格数据过滤不匹配的问题。

## 2. 根因分析
1. **临期保修日期过滤错误**：
   - 后端 `/assets/summary` 计算 `warranty_expiring_soon` 时，仅统计未来 90 天内到期的设备（`warranty_expiry >= now AND warranty_expiry <= now + 90d`）；
   - 前端 `helpers.ts` 中的 `severityOf(a)` 之前使用了 `new Date(a.warranty_expiry) <= Date.now() + 90d`，未限制 `>= now`，导致历史已过期的资产（如 `2026-06-01`）被全部误判为 `warning`；
   - 结果导致：卡片统计显示 `0 (0%)`，但点击“P3 需要关注”卡片后，由于全部 8 台历史过保资产均满足旧逻辑，表格把 8 台设备全量展示；而点击“运行正常”（统计为 8）时，表格因被判断为 warning 反而显示 0 条。
2. **状态与严重级别映射不一致**：
   - 卡片 1（P1 严重故障）统计了 `inactive`，但 `severityOf` 之前仅将 `decommissioned` 判定为 critical；
   - 工具栏总数在严重级别过滤激活时显示的是后端全量 `total`，而非当前筛选视图下的条数。

## 3. 修复方案
1. **修正 `helpers.ts` 中的 `severityOf`**：
   - 严重故障（`critical`）：`offline` / `inactive` / `decommissioned`；
   - 重要问题（`major`）：`maintenance`；
   - 需要关注（`warning`）：未来 90 天内临期保修（`exp >= now && exp <= now + 90d`）/ `in_storage` / `staging`；
   - 运行正常（`healthy`）：正常在用且健康的资产。
2. **对齐统计卡片数值**：
   - `criticalCount`：`inactive + decommissioned`；
   - `majorCount`：`maintenance`；
   - `warningCount`：`warranty_expiring_soon + in_storage`；
   - `healthyCount`：`active`。
3. **优化前端过滤与空态体验**：
   - 工具栏显示当前激活筛选下的动态数量；
   - 空态下提供便捷的一键“重置所有筛选”按钮。
