# 平台凭据与 Web 入口表单

## 任务目标
- 通用凭据新建表单不显示 Cisco 专用的 Enable 密码；仅已有凭据且绑定设备均为 Cisco 时提供该字段。
- 资产编辑页的 Web 管理入口改为独立弹窗，通过启用复选框开启并配置；停用时保留配置但不让入口生效。
- 投产流程在前端明确检查设备口令上手状态，避免对“待设置凭据/待验证连通性”的设备发送会被后端拒绝的投产保存请求。
- 对尚未完成口令上手的设备提供“仅保存凭据、保持待投产”路径，并清楚区分口令上收投产与免上收投产的实际影响。
- 在口令上手未完成的阻断弹窗中仍展示两种投产路径及锁定原因，避免用户误以为免上收功能不存在；不得绕过连通性验证门禁。
- 修复 Linux 综合巡检脚本遇到不支持 inode 统计的文件系统时，将 `-` 作为整数比较而产生 Bash 警告的问题。
- 修复资产保存失败时前端吞掉服务端详细校验原因、统一显示“保存校验失败”的问题。

## 现状与证据
- `CmdbManagementTab` 的通用 SSH 凭据表单始终渲染 `enable_password`，表单没有平台信息。
- 资产表单本身已有 Cisco 平台专用 Enable Secret 区块；该字段仍应留在具体 Cisco 资产的编辑流程中。
- Web 入口的完整配置卡片当前直接内嵌在资产编辑表单，增加滚动高度。
- `PUT /api/assets/{id}` 在更新前检查设备 `onboarding_status`；只有 `verified/active` 能转入投产。`pending_credentials` 会返回用户提供的 422。检查先于写入，因而同一请求里的凭据变更也会一起失败。

## 影响范围
- `src/pages/CmdbManagementTab.tsx`：按凭据关联设备平台控制 Enable 密码字段。
- `backend/services/credential_service.py`：安全视图补充是否仅绑定 Cisco 的布尔能力字段，不暴露秘密。
- `src/pages/AssetManagement/components/AssetModal.tsx`：Web 管理入口复选框与配置弹窗；显示生命周期前置条件。
- `src/pages/AssetManagement/index.tsx`、`src/pages/AssetManagement/types.ts`、`backend/api/assets.py`：读取设备口令上手状态并在投产请求前给出阻断提示。
- `backend/database/seed.py`：跳过 inode 使用率为非数字值的挂载点；系统模板初始化时会刷新该脚本。
- `backend/tests/vendor_audit/test_linux_inspection_contract.py`：覆盖 inode 数值解析边界。
- `src/api/http.ts`、`src/api/http.test.ts`：保留更具体的响应 detail，不让通用 error 摘要遮盖它。
- `src/pages/AssetManagement/index.tsx`、`src/pages/AssetManagement/index.test.tsx`：格式化后端校验细节并脱敏后显示。
- 本计划与同后缀 walkthrough。

## 实施步骤
1. 让 credential service 只向前端返回关联设备的平台元数据/Enable 密码可用标记；新建凭据和非 Cisco 绑定凭据隐藏 Enable 密码字段。
2. 将 Web 入口配置从主表单移入弹窗，以复选框启用/停用；停用时保留配置草稿并以 `enabled=false` 持久化。
3. 资产响应携带关联设备 `onboarding_status`。用户尝试投产但状态未验证时，显示可读的阻断说明，并提供仅保存表单、保留原生命周期的操作；后端门禁保持不变。
4. 分别解释投产上收（会更改设备账号口令）与存量免上收（保留现口令、不加入托管）的行为与验证前置条件；即使处于阻断状态也显示两种选项和不可用原因。
5. Linux 巡检脚本仅对数字 inode 百分比执行整数比较，并对 `-`/空值跳过。
6. 资产保存错误优先显示具体 `detail`/字段错误；只在服务端确实没有细节时显示状态码和请求编号，校验消息仍执行口令脱敏。
7. 检查差异和调用链；运行适当的静态检查、构建及聚焦验证。

## 验证计划
- `npm run lint`
- 使用独立输出目录执行 Vite production build。
- 浏览器检查：新建凭据不显示 Enable 密码；非 Cisco 关联凭据编辑不显示；Cisco 关联凭据可编辑；Web 管理入口勾选后弹出配置、取消后入口保持禁用；待上手设备的投产操作在客户端明确阻止。
- 用户已明确授权在 `ubuntu-nexora` 上保存普通/特权账号凭据并验证工作台登录；只进行登录验证，不执行设备配置命令，也不发起投产操作。
- 浏览器凭据录入和最终保存仍由用户完成；资产表单只提供安全的“保存凭据并保持待投产”流程。保存后再继续普通与特权登录验证。
- 组件测试确认未验证状态会显示口令上收、免上收两个禁用选项及可用的“保存并保持待投产”操作。
- 验证 Linux inode 脚本在 `df -iP` 返回 `-` 与有效百分比时不产生整数比较警告。

## 风险与回滚
- 保留现有数据库字段和 API 的 Enable Secret 支持，变更仅约束缺少平台上下文的通用凭据 UI。
- Web 入口关闭只停用配置，不删除用户已填写的 Profile。
- 投产前置门禁保留在后端；前端检查只是尽早反馈，不替代服务端校验。
- 若修改出现问题，回退上述前端可见性/弹窗与响应元数据字段即可，不需要数据库迁移。
- 真实设备验证若未完成，记录用户交接状态；不得把未执行的连通性或会话验证标为通过。
- “免上收投产”仍要求凭据已设置并完成连通验证；不得把该选项作为跳过凭据门禁的入口。
