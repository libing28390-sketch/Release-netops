# PostgreSQL 看板采集恢复计划

## 任务目标

修复主机启动时覆盖已发布 vmagent 抓取配置的问题，将 PostgreSQL 性能看板加入 Nexora 监控大盘目录，并在 `192.168.204.128` 恢复采集后验证指标回流。

## 现状与问题

- 服务器于 2026-10-10 06:47（Asia/Shanghai）启动；Docker 监控容器随后一起启动。
- 已应用的 collector-local v93 归档包含 `platform_postgres_exporter`，但启动脚本把共享运行时 `vmagent/scrape.yml` 覆盖成镜像默认文件。
- vmagent 当前没有 PostgreSQL 抓取目标，VictoriaMetrics 中最后样本停在服务器启动时段；exporter 仍能生成 PostgreSQL 指标。
- Grafana 中存在 PostgreSQL 性能看板，Nexora 前端目录未登记第 13 张入口。

## 影响范围

- Docker 启动脚本及其部署契约回归测试。
- Nexora 监控大盘的前端看板注册表。
- 生产服务器 collector-local 运行配置、vmagent 抓取状态及 Grafana 指标回流验证。

## 拟修改文件

- `scripts/sync-frontend-dist.sh`
- `backend/tests/monitoring/test_monitoring_v1_deployment_contract.py`
- `src/pages/GrafanaDashboardPage.tsx`
- 本计划与对应 walkthrough。

## 实施步骤

1. 修改启动同步逻辑，使存在 `current_version.json` 的运行时配置不被镜像默认 `scrape.yml` 覆盖；补充部署契约回归测试。
2. 在 Nexora 看板注册表增加 PostgreSQL 第 13 张入口，链接现有 Grafana UID `nexora-postgres-performance`，沿用现有双语标题/描述模式。
3. 运行 shell/部署契约验证、相关后端测试、前端 lint 与生产构建。
4. 基于服务器当前发布源码构建精简镜像并更新应用；先备份现有运行配置，再从已发布的 v93 归档恢复 scrape 配置，最后只重启 vmagent。
5. 检查 vmagent active targets、VictoriaMetrics 最新样本、Grafana 面板和 Nexora 入口；记录容器健康状态及回滚依据。

## 验证计划

- 回归测试覆盖：无版本时仍以 defaults 初始化；已有版本时保留版本化 scrape 配置。
