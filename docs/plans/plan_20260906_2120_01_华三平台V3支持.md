# 华三 Comware V3 平台支持计划

## 目标

在“平台管理”和资产设备平台绑定链路中增加 H3C Comware V3，保证新部署与已有 Docker 数据库升级后都能看到并使用同一个可用的系统 Profile。V3 复用现有 H3C 的 `hp_comware` 连接驱动和 `h3c_comware` 解析家族，不新增未经验证的独立驱动或解析器。

## 当前缺口

- `SYSTEM_PROFILES` 只注册了 H3C V5、V7、V9 和未知版本，没有 `h3c_comware_v3`。
- H3C 的版本元数据、TextFSM 变体选择、库存版本自动识别只覆盖 5/7/9。
- 前端资产平台目录、平台设置、TextFSM 平台选择、自动化快捷查询及导入别名没有 V3 选项。
- 已有数据库不会重新执行早期平台注册迁移，因此必须新增幂等升级迁移，而不是只修改旧迁移。

## 实施范围

1. 后端平台注册表：增加 `h3c_comware_v3` 系统 Profile、V3 版本元数据和与 H3C 公共命令目录一致的 Profile 动作快照。
2. 版本识别与解析：补充 Comware V3 的版本识别映射、TextFSM 变体/候选路径和平台 API 的展示映射；V3 没有独立、经过验证的语法时，按 V3 → 已验证 V5 → 公共 H3C 模板顺序回退，不创建空的 V3 模板文件。
3. 连接与运行时：确认 Profile 的 `connection_driver=hp_comware` 能贯通 Netmiko、Scrapli/兼容层、运行数据命令解析和拓扑等共享入口；只在存在具体平台白名单的地方加入 V3，避免厂商切换后残留错误平台。
4. 前端：补充资产平台下拉/导入值、平台设置、TextFSM 平台版本选择和快捷查询的 V3 展示与选择逻辑。
5. 数据迁移与回归：新增下一个编号的 PostgreSQL 幂等迁移，为旧安装补齐 Profile、发布版本和动作；增加迁移、绑定、识别、驱动/解析映射及前端目录测试。

## 验证与验收

- 检查迁移顺序、PostgreSQL 兼容性和重复执行幂等性。
- 后端聚焦测试：Profile/动作目录、V3 版本识别、绑定兼容性、`hp_comware` 驱动和 `h3c_comware` TextFSM 候选。
- 前端聚焦测试、`npm run lint`，并在不覆盖用户已有构建产物的前提下评估 `npm run build`。
- `git diff --check`、Python 编译检查；按质量门禁运行可行的后端测试并记录未运行项。
- 回归确认 Cisco/Huawei/Ruijie 等现有平台映射不受影响，V3 绑定仍执行同厂商和租户资源范围校验。

## 风险与回滚

- V3 CLI 语法可能因具体产品型号存在差异；本次只注册可靠的通用 Comware 连接/解析家族，不伪造 V3 专属模板。后续有真实 V3 输出后再单独增加带夹具的 V3 模板迁移。
- 新迁移只新增或更新 `SYSTEM` Profile，不改写用户自定义 Profile，也不改变现有设备绑定；如需回滚，应通过发布版本/数据库备份恢复，不修改已应用的历史迁移。
