# 修复 Windows 下 Uvicorn 热重载导致服务假死

此计划旨在解决 Windows 环境下，开发服务器启动时由于 Python 编译 `.pyc` 文件触发 `watchfiles` 频繁重载，进而导致 `asyncio` 的 `WinError 64` 错误并引起后端服务卡死的问题。

## 问题分析

1. **现象**：前端登录时提示“登录超时，请检查后端状态后重试”，后端 API 服务不响应任何请求（Hanging）。
2. **根因**：
   - 启动 `npm run dev` 时，`uvicorn` 在 Windows 下默认使用 `WindowsProactorEventLoopPolicy`。
   - 启动过程中，Python 解释器在加载模块时会向 `backend/` 的子目录下写入 `.pyc` 字节码文件（`__pycache__`）。
   - Uvicorn 依赖的 `watchfiles` 监听到这些字节码文件的写入，误认为是代码变更，在启动瞬间立即触发了热重载。
   - 在 Windows 环境下，Uvicorn 热重载在重新传递套接字与创建子进程时，极易由于 Proactor 监听套接字竞争或重置，触发 `OSError: [WinError 64] 指定的网络名不再可用。` 错误。
   - 该错误导致 Worker 进程中的监听协程异常终止，而 Uvicorn 主进程仍然占用 `5010` 端口。这使得所有新的 TCP 连接虽然完成了握手，但没有 Worker 去处理，导致请求无限期挂起（超时）。

## 解决方案

在 `backend/main.py` 的最顶部，针对开发环境（或通过程序显式）设置 `sys.dont_write_bytecode = True`，禁止 Python 写入 `.pyc` 字节码文件。
由于开发环境下没有新的 `.pyc` 文件写入，`watchfiles` 将不会在启动时误触发重载，从而彻底消除该死锁/卡死链条。

### [backend](file:///d:/netops/netsops-main/backend)

#### [MODIFY] [main.py](file:///d:/netops/netsops-main/backend/main.py)
* 在文件最顶部（所有其他导入之前），添加对 `sys.dont_write_bytecode = True` 的设置。
