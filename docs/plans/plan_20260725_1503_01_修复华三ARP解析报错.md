# Implementation Plan - 修复华三ARP解析报错与低权限分页超时

本计划旨在解决华三交换机在执行命令/执行 Playbook 时由于分页以及 TextFSM 模板匹配失败导致的超时和采集报错问题。

## 现状/问题
1. **ARP 模板解析 State Error**：当执行 `display arp all` 收集 ARP 表项时，华三设备的某些系统版本输出的 ARP 类型图例（Legend）含有前导空格或换行。这导致自定义的 `h3c_comware_display_arp_all.textfsm` 模板由于包含极其严格的 `^. -> Error` 规则而抛出 `State Error` 崩溃。
2. **低权限 SSH 连接超时（Pattern not detected）**：在近期代码增加了凭证绑定区分（普通只读用户与管理员用户）后，后台命令收集开始使用普通只读用户（如 `user` 登录）。对于华三设备（`hp_comware`），Netmiko 连接初始化时会尝试执行 `screen-length disable` 关闭分页，但该命令在低权限下会返回 `Permission denied.`。这导致分页实际上处于启用状态。随后执行 `display interface brief` 等长命令时，设备输出会在 `---- More ----` 处暂停，而直接调用 Netmiko `BaseConnection.send_command` 却因为等待设备提示符超时而报错 `Pattern not detected`。

## 实施步骤
1. **修复 ARP 模板**：
   - 修改 `h3c_comware_display_arp_all.textfsm`，将匹配图例的行 `^Type:\s+S-Static\s+D-Dynamic` 改为模糊前缀匹配并且允许首尾空格的 `^\s*Type:\s+S-Static`。
   - 将 `^IP\s+Address\s+MAC\s+Address...` 行匹配优化为 `^\s*IP\s+Address\s+MAC\s+Address\s+VID`。
   - 移除末尾的 `^. -> Error` 匹配。
2. **全局解决分页超时**：
   - 在 `backend/drivers/ssh_compat.py` 中，对 Netmiko 的 `BaseConnection.send_command` 实施全局 monkeypatch。
   - 动态劫持默认的 `expect_string`，在寻找常规提示符的同时也匹配分页关键字（如 `---- More ----` 等）。
   - 在命令执行返回后，自动运行 `drain_paged_output`，在底层自动发送空格读取所有后续分页，确保即便普通用户无法关闭分页也能获得完整命令输出。
