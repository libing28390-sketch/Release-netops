# 修复接口采集与同步中 PostgreSQL 布尔类型不匹配 Bug

此计划旨在修复在 PostgreSQL 环境下，执行接口状态采集（以及计划任务同步）时，由于 SQL 语句中对 `is_l3` (boolean) 字段写入/更新了整数值 `1` 或 `0`，导致 PostgreSQL 报错（`DatatypeMismatch: 字段 "is_l3" 的类型为 boolean, 但表达式的类型为 integer`）的 Bug。

## 问题分析

1. **现象**：在接口采集页面点击“立刻采集接口”时，任务进度条下方显示失败原因：“字段 'is_l3' 的类型为 boolean, 但表达式的类型为 integer HINT: 你需要重写或转换表达式”。
2. **根因**：
   - 数据库从 SQLite 迁移到 PostgreSQL 后，`interfaces` 表中的 `is_l3` 字段类型变更为真正的布尔型 `boolean`。
   - `backend/services/interface_collection_service.py` 在 `_upsert_interfaces` 方法中硬编码了数字 `1` 来表示 `is_l3 = 1`：
     - `UPDATE` 语句中包含：`is_l3 = 1`
     - `INSERT` 语句中包含：`VALUES (..., 1, 1)`
   - `backend/services/scheduler_service.py` 在同步物理设备接口时，也将 `is_l3` 值转换成了整数 `1` 或 `0` 传给 DB。
   - 整数传给布尔型列会导致 PostgreSQL 编译报错，导致采集逻辑和调度任务崩溃。

## 解决方案

1. 在 `backend/services/interface_collection_service.py` 中：
   - 将 `UPDATE` 语句中的 `is_l3 = 1` 修改为 `is_l3 = TRUE`。
   - 将 `INSERT` 语句中的 `VALUES (..., 1, 1)` 调整为 `VALUES (..., TRUE, 1)`（注：`ip_enabled` 为 integer 类型，保留数值 `1` 即可）。
2. 在 `backend/services/scheduler_service.py` 中：
   - 将 `is_l3` 传参时的三元表达式由返回 `1` / `0` 修改为返回 `True` / `False`。

此修改由于使用标准 SQL 布尔关键字 `TRUE`/`FALSE` 以及 Python 布尔对象，能够完全兼容 PostgreSQL 和 SQLite 运行环境。
