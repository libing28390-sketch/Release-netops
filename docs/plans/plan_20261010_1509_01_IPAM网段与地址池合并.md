# IPAM 网段与地址池合并计划

## 目标

将地址池作为所属网段下的分配范围管理，取消独立的地址池导航入口；保持网段、地址池和单个 IP 地址职责清楚。

## 现状与决策

- `prefixes` 管理 CIDR 网段及 VRF、VLAN、站点、网关等上下文。
- `ipam_pools` 保存某个前缀中的起止范围，适合作为该网段的子级分配范围，不应与网段本身混为一项。
- 当前 DHCP 租约页只有人工 CRUD，没有从 DHCP 服务器同步的采集器。没有权威 DHCP 数据源时，本次不将租约并入 IP 清单、利用率或自动分配。
- 用户选择隐藏 DHCP 租约入口，保留既有租约数据、后端接口及旧路由，便于将来接入专用 DHCP 服务器。
- 工作区已有用户未提交的改动；本次须在其上增量修改，不回滚或覆盖。

## 影响范围

- 后端：地址池查询可按前缀过滤；创建、更新范围时验证地址族、CIDR 边界及同网段范围重叠。
- 前端：网段行内打开该网段的地址池管理；地址池独立导航移除，旧 URL 保留兼容。
- DHCP：隐藏导航入口但保留记录、接口和路由；本次不新增 DHCP 采集器或租约关联字段。

## 接口约束

- 地址池列表支持可选 `prefix_id` 过滤，已有不带过滤参数的调用保持兼容。
- 地址池必须归属于一个已存在网段；起止 IP 必须同族、有序且都在该网段内；同一网段中的地址池范围不能重叠。
- DHCP 租约数据表、CRUD 接口与旧路由不删除；侧栏隐藏 DHCP 入口，当前 IP 清单与容量算法不使用人工租约记录。
- 不新增数据库迁移或回填数据。

## 实施步骤

1. 为地址池列表增加前缀过滤，并在创建/更新时校验地址池范围。
2. 在网段行内提供地址池管理弹窗，固定当前前缀并显示所属范围。
3. 移除独立地址池与 DHCP 租约侧栏入口，同时保留兼容路由和后端接口。
4. 检查任务改动与工作区已有改动，记录静态检查及未执行项。

## 验收与验证

- 静态确认网段行可打开仅属于该网段的地址池列表，创建时前缀固定。
- 静态确认池范围校验覆盖不存在前缀、跨地址族、起止倒置、越界和重叠。
- 静态确认旧 `/ipam/pools` 与 `/ipam/dhcp` 路由/数据模型仍兼容，但侧栏不展示入口。
- 不运行测试、lint、构建或浏览器验证；仅记录已执行的语法与 diff 检查。

## 风险与回滚

- 地址池记录和租约记录都不删除；恢复导航即可重新显示旧功能。
- 没有 DHCP 数据源时不能判定动态租约真实状态；未来专用服务器集成应提供权威租约同步，再决定是否将租约叠加到 IP 库存。
- 地址池范围校验将拒绝原来可能存在的跨网段或相互重叠的配置；如已有问题配置，更新该池前需先修正冲突范围。
