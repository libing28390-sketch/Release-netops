# 公有发布排除交接文件实施计划

## 任务目标

修正公有仓库同步/发布链路，确保仓库根目录的 `handoff.md` 不再被复制、提交或同步到公有发布仓库；保留本地交接文件供工作区接续使用。

## 现状/问题

- `handoff.md` 位于仓库根目录，属于内部交接材料，不属于公有发布仓库内容。
- 之前的公开仓库同步链路将其带入了公有仓库，用户已手动删除。
- 当前需要确认是发布树清理规则、同步脚本、发布 workflow 还是 allowlist 同时控制公开内容，避免只修一处后再次泄漏。

## 影响范围

- GitHub Actions 公有发布/同步 workflow 及其调用的清理脚本或发布配置。
- 仅调整公开发布内容边界，不修改运行时业务代码、数据库、设备操作逻辑或本地 `handoff.md`。

## 拟修改文件

- 先通过 `rg` 定位所有公开仓库复制、清理、allowlist 和 `handoff.md` 相关配置。
- 修改实际控制公开发布树的 workflow/脚本/配置；若有测试契约，补充 `handoff.md` 排除断言。
- 新增对应 `docs/walkthrough/` 验证记录；不执行 commit、push 或发布。

## 实施步骤

1. 检查当前 Git 状态，保留用户已有未提交内容。
2. 追踪 release workflow 到公开发布树的完整文件流，确认 `handoff.md` 被带入的根因。
3. 在最小范围加入显式排除规则，并确保源码完整性检查仍可检查内部文件但公开树不会复制它。
4. 检查是否存在其他公开同步路径，避免重复入口遗漏。
5. 运行 YAML/脚本配置检查、release 相关测试、`git diff --check`，并按 release/quality gate 要求执行必要的 lint/build 或说明不相关项。
6. 汇总当前后续工作：发布阻断、RackVision 验收项和本次公开同步修复。

## 验证计划

- `rg` 检查所有 release workflow、同步脚本和公开树 allowlist/denylist。
- 解析 `.github/workflows/release.yml` 及相关配置。
- 执行仓库已有的 release 配置门禁脚本和相关测试。
- 使用临时目录做只读/可回收的发布树模拟，确认 `handoff.md` 不存在；不触碰远端仓库。
- `git diff --check`，并检查最终 diff 只覆盖本任务范围。

## 风险与回滚思路

- 风险：若只在一处加排除，另一个同步入口仍可能上传 `handoff.md`；因此必须追踪完整发布链路并做产物扫描。
- 风险：公开树存在必需路径校验，排除规则不能误删运行时需要的公开文档或配置；修改后需运行 release 配置门禁。
- 回滚：保留最小 diff，必要时仅回退本次公开发布排除规则和对应验证文档，不触碰用户现有未提交文件；本次不提交、不推送。
