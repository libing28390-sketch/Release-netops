# IP 与 VIP 页面筛选和操作精简

## 目标与现状

`/ipam/ips` 页面有“包含采集来源”复选框和冗长说明；用户要求移除这些说明，将下载功能移入操作列，并删除 IP、地址池、VIP 共用网段范围的提示。随后用户要求 `/ipam/vips` 移除公共“当前网段”控件、在 VIP 列表中清楚展示每条记录的所属网段，并将新增/编辑表单中的原生下拉选择改为适合大选项集的检索或直接选择方式。

## 影响范围与分工

- 前端 Luna：`src/pages/IPVlan/IPAddressTab.tsx`、`src/pages/IPAMManagementTab.tsx`，以及只为适配控件变化而需更新的 `src/pages/IPVlan/IPAddressTab.sources.test.tsx`。
- 主 Agent：`src/pages/IPVlan/VIPManagementTab.tsx`，明确呈现每条 VIP 的归属网段。
- 主 Agent：维护本计划和统一 walkthrough；负责路由上下文设备搜索。
- 不改 API、台账数据、地址池查询范围或下载内容。VIP 页面不使用公共前缀筛选，仍由单个 VIP 的归属前缀字段管理范围。

## 实施步骤

1. 移除“包含采集来源”控制和相关副标题。
2. 删除 IP/地址池/VIP 共用范围及“使用下方筛选器切换网段”等提示。
3. 将下载/导出入口移到 IP 地址表格的“操作”位置，保留现有数据导出行为。
4. VIP 页面隐藏公共当前网段选择器，并不把共享 prefix_id 传给 VIP 列表；新增/编辑仍要求明确的归属前缀。
5. 将 VIP 表格中的地址空间与网段拆成独立列，保留每条 VIP 的 CIDR/前缀值。
6. 将前缀和设备长列表改为名称/IP检索选择；将少量 VIP 技术模式改为单选项组，保留原字段值和保存契约。
7. 仅同步现有测试与 UI 控件变更有关的断言，不新增用例。

## 验证计划

- 静态检查相关提示已移除，下载按钮位置与操作列一致。
- 不运行测试、构建或浏览器交互；用户未要求验证。

## 风险与回滚

页面交互与文案调整，不更改查询或导出数据契约。按本计划文件范围回滚即可；不触及业务数据。
