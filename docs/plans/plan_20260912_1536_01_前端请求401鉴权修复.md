# 计划：前端请求 401 鉴权修复

## 目标

修复全局通知、主机资源监控、配置备份配置和系统更新检查请求遗漏 Bearer Token，导致后端持续返回 401 的问题。

## 现状与问题

浏览器日志显示 `/api/notifications` 每 15 秒、`/api/health/resources` 每 30 秒等请求持续收到 401。前端 `isAuthenticated` 只决定是否开始请求，原生 `fetch` 不会自动附加认证头；项目后端全局 API 鉴权要求携带 `netops_token`。

## 影响范围

前端后台轮询和配置页面加载/保存。不会改变后端权限策略或认证契约。

## 拟修改文件

- `src/hooks/useNotifications.ts`
- `src/hooks/useMonitoring.ts`
- `src/hooks/useConfigSnapshots.ts`
- `src/pages/ConfigScheduleTab.tsx`
- `src/components/VersionUpdateNotifier.tsx`
- `docs/walkthrough/walkthrough_20260912_1536_01_前端请求401鉴权修复.md`

## 实施步骤

1. 对受保护 API 请求统一使用现有 `authHeaders()`，JSON 请求使用 `authHeaders(true)`。
2. 确保通知读取/已读写入、资源/监控轮询、配置读取和保存、更新检查都带认证头。
3. 运行前端 lint 与生产构建，检查改动 diff。

## 验证计划

- `npm run lint`
- `npm run build`
- 静态核对用户日志涉及的请求已使用 `authHeaders()`；实际服务器运行后的网络请求需由部署环境复测。

## 风险与回滚思路

风险低：仅补充现有 Bearer Token 请求头，不更改权限或 API 响应。若验证失败，可仅回滚本计划列出的前端文件；不覆盖工作区其他未提交修改。
