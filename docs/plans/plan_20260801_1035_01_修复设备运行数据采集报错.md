# 实施计划：修复设备运行数据采集 NameError 与平台未支持报错

**创建时间**：2026-08-01 10:35
**任务名称**：修复设备运行数据采集报错

## 1. 任务目标与现状
在设备运行数据采集接口 `/api/devices/{device_id}/operational-data` 触发时，产生两层严重报错：
1. `NameError: name 'logger' is not defined. Did you mean: '_logger'?` 在 `backend/api/devices.py` 第 1821 行。
2. 导致上述异常捕获的根本原因是 `NeighborCollectionContractError: unsupported_platform:dptech_ios` 来自 `backend/services/neighbor_collection_contract.py`。

## 2. 影响范围
- 后端 API: `backend/api/devices.py`
- 邻居采集契约: `backend/services/neighbor_collection_contract.py`
- 拓扑发现服务: `backend/services/topology_service.py`
- 测试用例: `backend/tests/vendor_audit/test_lldp_collection_contract.py`

## 3. 拟修改文件
- [devices.py](file:///d:/netops/netsops-main/backend/api/devices.py)
- [neighbor_collection_contract.py](file:///d:/netops/netsops-main/backend/services/neighbor_collection_contract.py)
- [topology_service.py](file:///d:/netops/netsops-main/backend/services/topology_service.py)
- [test_lldp_collection_contract.py](file:///d:/netops/netsops-main/backend/tests/vendor_audit/test_lldp_collection_contract.py)

## 4. 实施步骤
1. 修改 `backend/api/devices.py`，定义 `logger = _logger` 统一别名并规范化 `_logger` 使用。
2. 修改 `backend/services/neighbor_collection_contract.py`，在 `_PLATFORM_ALIASES` 与 `LLDP_COMMAND_WHITELIST` 中补齐 `dptech_ios` 和 `maipu` 平台及允许的 LLDP 命令。
3. 修改 `backend/services/topology_service.py`，在 `DISCOVERY_COMMANDS` 和 `normalize_topology_platform` 中补齐 `dptech_ios` 和 `maipu`。
4. 运行 pytest 测试集（`test_lldp_collection_contract.py` 及 `test_dptech_ios_full_textfsm.py`）。
5. 编写归档验证报告 `docs/walkthrough/walkthrough_20260801_1035_01_修复设备运行数据采集报错.md`。

## 5. 验证计划
- 自动化测试：`pytest backend/tests/vendor_audit/`
- 手动验证：对 `dptech_ios` 设备执行 operational-data 接口测试，确认不再报错。
