# 实施计划：服务器自动采集纳管、Linux大盘彻底净化、站点名称展示与思科拓扑域名剥离

## 1. 任务背景与目标

用户在验证监控系统与网络拓扑时提出四个核心痛点与疑问：
1. **内置采集计划缺少服务器**：现有 Monitoring V1 控制平面仅针对网络设备 SNMP（`snmp-exporter`），未打通 CMDB 中纳管的 Linux / Windows 服务器，导致用户纳管主机后无法自动采集；
2. **07 Linux 服务器大盘混入网络设备**：由于此前网卡流量 panel 配置了 `or rate(ifHCInOctets...[5m]) * 8` 等 fallback，在无 node_exporter 数据时回退到了网络交换机流量，且纳管主机数显示为 0，缺乏完整指标；
3. **大盘站点下拉应使用站点名称**：大盘顶部站点下拉框展示的是内部 ID（如 `site-4eb4ad17a9f3`），用户要求切换为直观的站点名称（如 `WH-DC-01`、`WH-DC-02`）；
4. **思科设备 LLDP 邻居与设备名剥离域名后缀**：思科设备配置了 `ip domain name eve.lab`，执行 `show lldp neighbors` 输出的 Device ID 带域名后缀（如 `R3.lab.local`、`R2.lab.local`），系统拓扑发现与设备命名应自动剥离域名后缀，仅保留纯短主机名（如 `R1`、`R2`、`R3`）。

**目标**：
- 实现“CMDB 纳管即监控”：后台自动从 CMDB `physical_assets`（`asset_type='server'`）编译生成 `linux_targets.yml`（9100端口）与 `windows_targets.yml`（9182端口），无需手动编写任何 yml；
- 彻底净化 07 Linux 服务器大盘：坚决剔除任何网络设备 SNMP 回退指标，补齐 CPU/内存/磁盘/网卡/系统全套纯正 Linux 指标；
- 大盘站点下拉统一切换为站点名称（`site_name`），联表查询修复；
- 拓扑发现和设备命名自动剥离域名后缀，保留纯短主机名。

## 2. 影响范围与拟修改文件

1. **后端目标编译与采集控制平面**：
   - `backend/services/monitoring_compiler.py`：新增服务器 targets 编译能力，将 CMDB server 资产自动编译输出为 `vmagent/targets/linux_targets.yml` 与 `vmagent/targets/windows_targets.yml`，并修复联表查询中的 `site_name`；
   - `backend/api/monitoring_v1.py`：`_load_compile_inputs` 同步查询 CMDB 中的活跃服务器资产，并在 `devices` 联表查询中修复 `d.site_id` 与 `sites.id` 的关联；
   - `scripts/sync-frontend-dist.sh`：容器启动时自动同步默认 targets 配置到 runtime volume；
2. **监控采集端与基线配置**：
   - `monitoring/vmagent/scrape.yml`：配置标准 `file_sd_configs`，同时支持动态 targets 目录热加载；
   - `monitoring/vmagent/targets/linux_targets.yml`：写入 CMDB 中纳管 Linux 服务器（如 `192.168.204.128:9100`）基线；
   - `monitoring/vmagent/targets/windows_targets.yml`：写入 Windows 服务器 targets 基线；
3. **Grafana 大盘代码生成器**：
   - `monitoring/grafana/generate_dashboards.py`：
     - `make_network_variables`：站点下拉改为查询 `site_name`；
     - `build_linux_dashboard`：彻底清理所有网络设备 SNMP 指标（`ifHCInOctets`、`host_cpu_util` 等），重构为纯正 `node_*` 指标，站点变量改用 `site_name`；
     - 重新生成所有大盘 JSON 文件并同步至 `monitoring/grafana/dashboards/` 与生产 Grafana 实例；
4. **思科及多厂商拓扑邻居与设备名域名剥离**：
   - `backend/services/normalizers/cisco.py`：在解析 `show lldp neighbors` / `show cdp neighbors` 时增加域名后缀剥离逻辑（保留 IP 地址，截断如 `.lab.local`、`.eve.lab`）；
   - `backend/services/topology_service.py`：在邻居识别、未纳管节点呈现（`get_unmanaged_neighbors`）、观测记录关联中全面剥离域名后缀；
   - `backend/api/devices.py`：`clean_system_hostname` 优化支持短主机名并统一剥离域名后缀；
5. **文档与 Git 记录**：
   - `docs/plans/plan_20260919_2329_01_服务器自动采集纳管与Linux大盘净化及思科拓扑域名剥离.md`
   - `docs/walkthrough/walkthrough_20260919_2329_01_服务器自动采集纳管与Linux大盘净化及思科拓扑域名剥离.md`

## 3. 实施步骤

### 步骤一：拓扑邻居与主机名域名剥离（Cisco LLDP / FQDN）
1. 在 `backend/services/topology_service.py` 和 `backend/services/normalizers/cisco.py` 中实现统一域名剥离函数 `strip_domain_suffix(name: str) -> str`；
2. 确保在提取 Device ID、System Name、显示未纳管节点时，自动剥离 `.lab.local`、`.eve.lab` 等域名后缀，纯保留 `R1`、`R2`、`R3`；
3. 优化 `clean_system_hostname`，允许单字母及短主机名。

### 步骤二：CMDB 服务器 Targets 自动编译与关联修复
1. 修改 `backend/services/monitoring_compiler.py`，支持 `render_server_targets`，生成 `vmagent/targets/linux_targets.yml` 与 `vmagent/targets/windows_targets.yml`；
2. 修改 `backend/api/monitoring_v1.py`：
   - 在 `devices` 联表查询中补充 `LEFT JOIN sites s ON (s.id = d.site_id OR s.id = d.site ...)`；
   - 加载 `physical_assets` 中 `asset_type='server'` 的服务器，传入编译器生成 targets。
3. 在 `monitoring/vmagent/targets/linux_targets.yml` 中写入 `192.168.204.128:9100`（`docker` 主机），更新 `snmp_targets.yml` 与 `scrape.yml`。

### 步骤三：07 Linux 服务器大盘重构与站点名称变量对齐
1. 在 `monitoring/grafana/generate_dashboards.py` 中：
   - 彻底删除 `ifHCInOctets`、`host_cpu_util`、`host_mem_util`、`host_disk_util` 等一切网络设备指标；
   - 将站点下拉从 `site_id` 切换为 `site_name`；
   - 补齐 CPU、负载、内存、磁盘、物理网卡吞吐/包率/错包、TCP 连接数等纯正指标；
2. 运行 `generate_dashboards.py` 重新生成 8 个大盘 JSON；
3. 通过 Grafana API 将更新后的 07 大盘及其他大盘推送至生产实例。

### 步骤四：质量门禁与验证
1. 运行相关单元测试（编译器测试、LLDP 契约测试）；
2. 验证 Grafana 实时 API 查询；
3. 编写 Walkthrough 与 Fix 记录，合入并推送到 `main` 分支。
