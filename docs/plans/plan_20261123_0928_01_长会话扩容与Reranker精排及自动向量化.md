# 实施计划：长会话扩容、BGE Reranker 精排与自动语义向量化

## 1. 任务目标
在现有 P0-P2 优化基础上，完成三项进阶能力落地：
1. 将 Copilot 历史会话窗口扩大到 128K 上下文的安全上限（`public: 30轮/48K`，`network: 60轮/96K`，`complex: 100轮/110K`），支撑超长运维排障会话并最大化 DeepSeek 前缀缓存命中率。
2. 复用数据库中已配置的 SiliconFlow Provider，接入 `BAAI/bge-reranker-v2-m3` 对 RAG 粗排候选切片进行在线精排（超时或不可用时无感降级）。
3. 打通 `KnowledgeService.add_document_and_chunk` 与重索引路径，使新上传文档自动写入 1024 维 `embedding_v2` 语义向量。

## 2. 影响范围与拟修改文件
- `D:\netops\netsops-main\backend\ai\services\assistant.py`：调整 `_HISTORY_POLICIES` 为 30/60/100 轮（48K/96K/110K）。
- `D:\netops\netsops-main\backend\ai\providers\embedding.py`：新增轻量 `rerank_documents(query, documents, top_n)`（自动复用 DB 中已启用的 SiliconFlow/OpenAI-compatible Provider 的 `/rerank` 接口，默认模型 `BAAI/bge-reranker-v2-m3`，超时 5s 降级）。
- `D:\netops\netsops-main\backend\ai\services\rag_retriever.py`：在粗排得到 ≥2 条候选结果时调用 `rerank_documents` 精排并记录 `reranker` 调试信息。
- `D:\netops\netsops-main\backend\ai\services\knowledge_service.py`：`add_document_and_chunk` 写入切片后自动调用 `semantic_embedding_provider()` 回填 `embedding_v2`（失败时仅记日志不阻塞入库）。

## 3. 验证计划
- 实测 `BAAI/bge-reranker-v2-m3` 在线精排接口对口语化排障提问（如「交换机端口老是闪断、丢包严重怎么查」）的精排打分与 Top-1 命中。
- 实测 `add_document_and_chunk` 新增测试文档后自动生成 `embedding_v2`（1024 维），验证后清理测试文档。
- 确认 `_HISTORY_POLICIES` 生效。

## 4. 风险与回滚思路
- Reranker 外网调用设 5s 超时并捕获所有异常自动降级到原有混合排序，不影响可用性。
- 自动 `embedding_v2` 写入失败时仅降级跳过，不影响文档入库和 `v1` 检索。
