# 平台健康看板指标显示修正计划

## 目标
修正 Grafana 平台健康仪表盘中 Docker 容器“最后观测时间”显示为 1970 年，以及无失败时“端点失败数”错误显示“暂无采集数据”的问题。

## 现状与问题
1. 面板使用 cAdvisor 的 `container_last_seen`（Unix 秒）作为时间值，但 Grafana `dateTimeAsIso` 单位按毫秒解释，导致时间落在 1970 年。
2. 端点失败面板使用 `count(up == 0)`；PromQL 默认比较会过滤成功端点，成功时整个表达式没有序列，Grafana 因此显示“暂无采集数据”。

## 影响范围
仅涉及 Grafana 平台健康仪表盘生成器、生成 JSON 和查询回归测试，不改变采集频率、指标定义或容器服务。

## 拟修改文件
- `monitoring/grafana/generate_dashboards.py`
- `monitoring/grafana/dashboards/nexora-platform-health.json`
- `backend/tests/monitoring/test_grafana_queries.py`

## 实施步骤
1. 确认当前指标值为 Unix 秒，并核对生成器及已生成面板的时间单位；检查失败面板查询与同页端点状态表的一致性。
2. 将观测时间转换为 Grafana 所需的 Unix 毫秒；失败数使用布尔比较后求和，让有样本的零失败显示 0，同时保留无样本状态。
3. 运行 dashboard generator 并检查完整输出目录，避免无关仪表盘变化。

## 验证计划
- Python 编译生成器并运行项目 Grafana dashboard 检查。
- 解析全部生成的 dashboard JSON，检查目标 panel 查询、单位和 12 份文件清单。
- 对照实时 `container_last_seen` 值和转换后的时间；确认生产端点全 UP 时失败数为 0，缺少 `up` 样本时仍为空。
- 运行 `git diff --check`。

## 风险与回滚
只修改两个展示查询，不写入采集源数据。若结果不正确，可将观测时间恢复为原查询 `max by (name) (container_last_seen{name!=""})`，并将失败数恢复为 `count(up{...} == 0)` 后重新生成仪表盘。
