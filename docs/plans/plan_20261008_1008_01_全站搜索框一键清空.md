# 全站搜索框一键清空

## 任务目标

在系统各页面具有搜索/过滤语义的文本输入框中，输入内容后显示清空 X；点击后立即清空输入值，并让现有受控状态与筛选逻辑同步更新。

## 现状与问题

搜索框分布在资产、网络、自动化、监控、配置、知识库和管理弹窗等多个页面，当前多数只能手工选中并删除文本。AST 盘点出 109 个带搜索语义提示的输入字段，分布于 82 个文件；纯日期筛选字段会排除。

## 影响范围

- 全站搜索和过滤文本输入字段。
- 全局样式，用于统一原生和页面内清除图标的大小、对比度与交互状态。
- 不涉及一般名称、编号、命令或配置输入框，也不改变搜索的提交、筛选或分页行为。

## 拟修改文件

- `src/**/*.tsx` 中搜索/过滤语义的输入字段。
- 若需要统一控件样式，再修改 `src/index.css`。

## 实施步骤

1. 盘点静态与动态占位提示、无占位提示但带搜索标签的搜索框，排除“命名当前搜索”等普通文本框。
2. 将搜索字段标记为可清空搜索输入，保留现有 `value`、`onChange`、键盘提交和过滤处理。
3. 对已有自定义清空动作的字段保留单一自定义 X；其余字段使用统一样式的原生清空图标，避免同一输入框出现两个 X。
4. 检查浅色/深色页面和弹窗中的 X 清晰度；确认清除动作即时触发原有过滤逻辑。

## 验证计划

- 运行相关前端测试、`npm run lint`、`npm run build` 与 `git diff --check`。
- 浏览器在资产管理、网络设备页和至少一个弹窗搜索框中输入文本，验证只出现一个清晰的小 X；清空后列表恢复。
- 搜索并审查所有命中字段，确认无普通输入框被误标为搜索框。

## 风险与回滚思路

将文本输入类型切为原生 search 时，浏览器提供清除控件并通过标准输入事件更新 React 受控值。若任一页面的浏览器控件或布局表现异常，可只对该页面恢复输入类型并改为显式清除按钮，保留其他已验证页面。
