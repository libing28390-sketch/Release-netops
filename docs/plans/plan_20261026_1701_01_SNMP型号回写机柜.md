# SNMP 型号回写资产与机柜实施计划

## 任务目标

设备导入完成 SNMP 识别后，自动获取可信的硬件型号，同时同步 `devices`、`physical_assets` 与已有机柜设备记录，使机柜设备类型跟随真实型号更新；清理已被真实型号替代的预留机柜设备型号。

## 现状与问题

- 导入身份探测只读取 `sysObjectID`、`sysDescr`、`sysName`；硬件型号仅从少量 `sysDescr` 规则推断。
- 2026-10-27 对 H3C HCL 设备做只读 SNMP walk 后发现，S6850 的 ENTITY-MIB 三列各有 259 行，首行已返回 `H3C S6850`；现有 200 行上限会把完整表误判为超限并丢弃型号。当前 `sysDescr` 型号解析也只覆盖 Cisco 格式，无法兜底提取 H3C 型号。
- 运行时对比显示，逐台 walk 六台 S6850 均能读出型号；沿用导入批次 5 台并发时仅 1/6 成功，说明 HCL Agent 对多设备并发 ENTITY-MIB walk 的承载不足。应单独串行化型号 walk，保留已有并发 sysName 探测。
- 型号解析可能把 LibreNMS OS 显示名当成型号。
- `identify_imported_device` 已将识别结果写回 `devices` 和 `physical_assets`，但未刷新机柜设备关联的 `device_type_id`。
- 资产创建阶段仅在已有型号时同步创建 `device_types`；补全阶段需使用 SNMP 的整机型号更新机柜型号关联。
- 只读盘点当前 PostgreSQL 发现一个未引用的通用占位设备类型 `Generic / Patch Panel 24P`（`rack_devices` 与 `devices` 均无引用）。
- 机柜目录里的 `generic_*` 3D 外观是渲染兜底，用户确认保留；型号识别成功后仅清除机柜关联上显式保存的 generic 占位 key，让真实型号重新参与外观解析。

## 影响范围

- SNMP ENTITY-MIB 型号表读取及机箱型号挑选。
- 导入身份识别结果与 CMDB 写回。
- 机柜 `rack_devices.device_type_id` 和机柜型号字段同步。
- 未引用 `Generic / Patch Panel 24P` 设备类型的幂等清理迁移。

## 实施步骤

1. 盘点导入、机柜设备类型同步链路和实际预留类型引用；仅删除已确认未引用的通用占位类型，保留通用 3D 渲染兜底。
2. 新增有界的 ENTITY-MIB 只读 Walk，按 `entPhysicalClass`、包含关系和非空型号选择机箱；按用户要求将单列上限设为 2000 行，覆盖实测 259 行设备并为更大的实体表留出余量，同时仍对达到上限、截断和歧义结果失败关闭；兼容 SNMPv2c/v3。
3. 导入批次为 ENTITY-MIB 型号读取设置独立的单并发信号量，避免 HCL Agent 被多个设备的三列 walk 同时压垮；现有 sysName 查询并发保持不变。
4. 优先使用实体型号，增加对 H3C 明确产品型号行（如 `H3C S6850`、`H3C SecPath F1090`、`H3C WX5540H-HCL`）的 `sysDescr` 解析兜底；移除 OS 显示名作为型号的兜底。人工填写型号优先保留。
5. 导入时保存规范机柜 ID/站位/安装方式，即使型号暂空也不丢位置；SNMP 后台任务携带尚未落表的放置细节。
6. 将型号回写资产与设备，并为已关联或待安装资产创建/解析精确 `device_types` 后更新/创建机柜关联及型号键。
7. 增加仅删除 `Generic / Patch Panel 24P` 且无机柜/设备引用的数据库迁移；任何已有引用都会让该记录继续保留。
8. 更新或新增回归覆盖，运行受影响的 SNMP 导入和机柜测试及质量策略扫描。

## 验证计划

- 对 SNMPv2c/v3 Walk 结果覆盖空表、机箱加多个模块、模块索引早于机箱索引、非机箱实体和超限/异常结果。
- 覆盖超过旧 200 行上限但低于新 2000 行上限的 H3C 实体表，并用 H3C Comware `sysDescr` 样本验证型号提取和非型号描述不误识别。
- 以导入批次并发模型复测实体 walk；六台 HCL S6850 应在批次单并发型号读取下全部返回型号，同时 hostname/sysName 探测仍保留并发。
- 验证只填充空型号、资产与设备一致、机柜关联改为新型号、人工型号保留、无可信型号时不写 OS 名称。
- 运行 `backend/tests/configuration/test_asset_management_method_import.py` 与相关 `backend/tests/rackvision/` 聚焦文件。
- 执行 `.agents/skills/netops-quality-gate/SKILL.md` 规定的 PostgreSQL-only 策略扫描及 diff 检查。

## 风险与回滚

- 部分设备不支持或不开放 ENTITY-MIB，或未返回机箱型号；此时继续依次尝试可信 `sysDescr` 解析，并保留空型号与可诊断识别结果。
- 多机箱/堆叠设备可能返回多个机箱实体，选择规则需确定性且不能把模块型号写为整机型号。
- 当前型号类型清理目标无引用；迁移用 `NOT EXISTS` 保护后续被引用的记录。机柜布局型号关联通过既有 placement service 更新，保留占位布局和设备，不删除机柜设备。
- 用户后续要求对 HCL 做只读 SNMP walk；仅执行 GET/WALK，不写交换机配置或应用实际资产数据。仍不部署、提交或推送。
