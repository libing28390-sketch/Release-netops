# 告警 Redis 凭据自动初始化

## 目标

修复 Docker 首装/更新时 `ALERT_NOTIFICATION_BROKER_PASSWORD` 为空导致 Compose 配置失败的问题，并让操作者从错误中能看懂自动修复方式。

## 现状与根因

`.env.example` 将该参数留空，而 `scripts/deploy-docker.sh initialize_env` 未为它生成值。部署脚本先从模板创建 `.env`，随后 Compose 因 required interpolation 失败，阻断安装或更新。

## 影响范围

- Docker Compose 部署脚本和环境模板。
- 告警 Redis 的 Compose 校验提示。
- 不触碰数据库、数据卷、TLS 文件或现有非空 `.env` 配置。

## 拟修改文件

- `scripts/deploy-docker.sh`
- `.env.example`
- `docker-compose.yml`
- 对应的 `docs/fixes/`、`docs/walkthrough/` 记录。

## 实施步骤

1. 在 `initialize_env` 中仅当参数缺失或为空时生成 URL-safe 口令，采用 `nexora` 前缀加随机十六进制后缀，并复用现有 `.env` 写入与初始化变更报告逻辑。
2. 保留用户已有的非空值；模板仍保持空值，避免所有部署共用同一个固定口令。
3. 更新模板说明和 Compose 错误提示，指向部署脚本自动初始化方式。
4. 创建修复记录和 walkthrough；检查脚本语法、差异、Actions，并在已授权目标机应用发布树、重启相关容器并验证健康状态。已完成。

## 风险与回滚

- 随机口令只在缺失或空值时生成，既有口令不会覆盖；初始化报告只输出参数名，不输出口令。
- 若更新或容器健康检查失败，恢复部署前保存的 `.env` 备份和旧镜像，再按既有部署脚本回滚。
