# 凭据中心 SNMP 绑定显示

## 目标与现状

凭据中心把 `snmp-ro` 显示为未绑定。只读数据库核对表明该 Profile 已被 15 条 `physical_assets.snmp_credential_id` 和 15 条 `devices.snmp_credential_id` 引用。原因是凭据列表、详情和删除保护只查询 SSH 普通/特权凭据字段，没有纳入 SNMP 凭据字段。

## 影响范围

- `backend/services/credential_service.py`：列表/详情的设备关联、绑定角色和在用计数。
- `src/pages/CmdbManagementTab.tsx`：将 SNMP 关联显示为“采集”，不把 SNMP 凭据错误呈现为普通账号，也不提供 SSH 绑定替换操作。
- 对应 PostgreSQL 与前端聚焦回归测试。

## 实施步骤

1. 已查询设备与资产的凭据字段，将 SNMP 关联纳入凭据列表及详情；资产与设备是同一绑定时按设备显示一次，独立资产引用也能显示。
2. 已对 SNMPv2/v3 凭据显示采集角色，且不进入普通/特权 SSH 绑定替换流程。
3. 已将设备和资产上的 SNMP 绑定纳入删除保护。
4. 已通过 PostgreSQL 服务测试、前端测试、TypeScript 检查及生产构建；数据库先前核验的 `snmp-ro` 15 台设备引用会呈现为 15 台，而不是重复计算成 30 条。

## 完成状态

代码修改与本地验证已完成。当前仅修改凭据关联的读取、展示和删除保护；没有重启或部署正在运行的服务，运行页面需加载包含此修复的应用版本后才会显示更新结果。

## 风险与回滚

本次只修正凭据中心的关联投影与删除校验，不修改资产绑定、凭据值或交换机配置。回滚时恢复原查询和 UI 角色显示；数据库凭据与设备关联不变。
