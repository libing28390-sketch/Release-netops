# Nexora 互联网出口监控 P1 运维能力整改任务清单

> 文档状态：`implemented_pending_external_acceptance`  
> 编制日期：2026-08-02  
> 前置门禁：P0 综合验收 `WAN-P0-020` 必须为 `done`  
> 适用页面：`/monitor/outbound`、告警事件页、容量报告入口  
> 状态口径：`pending`、`in_progress`、`blocked`、`done`

## 1. P1 目标

P1 将 P0 的“基础链路监控”升级为可长期运行的运维能力，重点解决：

- 原始分钟数据长期增长和 PostgreSQL 表膨胀；
- 24 小时至多年趋势、P95 和高负载时长；
- 错包、丢弃、维护窗口和告警确认；
- 多站点、多运营商、多链路的筛选和视图切换；
- 主备、负载均衡和线路组的运维表达；
- 日报、周报、月报及权限审计。

P1 不负责探测与链路根因关联、历史基线异常检测和容量建议，这些属于 P2。

## 3. 数据库与聚合任务

### 3.1 PostgreSQL 原生分区

- [ ] 设计 `wan_link_samples_1m` 按月范围分区方案。
- [ ] 使用新迁移完成非分区表到分区表的安全演进，不修改已执行迁移。
- [ ] 明确主键/唯一约束必须包含分区键的 PostgreSQL 约束。
- [ ] 保持 `(link_id, sampled_at DESC)` 查询索引。
- [ ] 大分区增加合理的 BRIN 时间索引。
- [ ] 每月提前创建下月分区，不依赖未确认安装的 PostgreSQL 扩展。
- [ ] 缺少目标分区时采集任务返回明确错误并告警，不静默丢数据。
- [ ] 分区创建任务支持多实例部署下的互斥。
- [ ] 旧数据迁移支持分批、可重试和进度记录。
- [ ] 迁移失败具备回滚或恢复步骤。

### 3.2 聚合表与补算

- [ ] 建立 `wan_link_rollup_5m`。
- [ ] 建立 `wan_link_rollup_1h`。
- [ ] 建立每日统计表或等价汇总模型。
- [ ] 聚合字段至少包含平均值、最大值、P95、样本数、有效样本数和采集成功数。
- [ ] 分别聚合上传、下载和双向利用率。
- [ ] 聚合错包与丢弃增量。
- [ ] 聚合接口可用率和采集成功率。
- [ ] 聚合高于70%、85%、95%的累计时长。
- [ ] 聚合任务使用 UPSERT，重复执行结果一致。
- [ ] 支持指定链路和时间范围补算。
- [ ] 聚合只使用质量合格样本。
- [ ] 聚合任务失败不影响实时分钟采集。
- [ ] 对迟到样本定义重算窗口。

### 3.3 P95 与统计口径

- [ ] P95 使用 PostgreSQL `percentile_cont(0.95)` 或经验证的等价算法。
- [ ] 上行、下行、上行利用率、下行利用率分别计算 P95。
- [ ] 空样本、单样本和不足样本窗口返回稳定语义。
- [ ] 指标同时提供平均值、最大值、P95 和有效样本数。
- [ ] P95 仅使用 `collection_status=success` 且质量合格样本。
- [ ] 报告中的 P95 可以通过独立 SQL 复核。
- [ ] 签约带宽变更前后的利用率统计不得混淆，需定义历史口径。

### 3.4 数据保留

- [ ] 1分钟原始采样默认保留30天。
- [ ] 5分钟聚合默认保留180天。
- [ ] 1小时聚合默认保留2年。
- [ ] 每日统计长期保留。
- [ ] 告警事件至少保留3年或按平台策略长期保留。
- [ ] 删除旧数据优先删除分区，不对大表执行无界批量 DELETE。
- [ ] 清理前校验聚合数据完整。
- [ ] 清理任务记录审计、删除范围、行数和执行时间。
- [ ] 保留策略可配置，但设置下限受后端限制。

## 4. 错包、丢弃与告警任务

### 4.1 指标计算

- [ ] 采集 IF-MIB 错包和丢弃计数器并记录计数器来源。
- [ ] 处理计数器重置、回绕和接口更名。
- [ ] 计算每分钟增量、每秒速率和相对包量比例。
- [ ] 聚合口与成员口不得重复叠加。
- [ ] 子接口和物理接口的指标语义分别标注。
- [ ] 缺少包计数器时不伪造错误率。

### 4.2 告警规则

- [ ] 错包异常按持续时间触发并支持恢复。
- [ ] 丢弃异常结合持续增长和高利用率触发。
- [ ] 接口 Down 后抑制“流量为0”“丢弃停止”等衍生告警。
- [ ] 设备不可达时按设备聚合采集失败，不为每个接口重复告警。
- [ ] 告警事件记录最大值、持续时长和方向。
- [ ] 阈值修改产生 before/after 审计。

## 5. 维护窗口与告警操作

### 5.1 维护窗口

- [ ] 建立结构化维护窗口模型，不使用不可查询的自由文本作为唯一事实。
- [ ] 支持一次性和周期性窗口。
- [ ] 支持站点、设备、线路组和单链路范围。
- [ ] 使用链路时区正确处理窗口。
- [ ] 维护期继续采集和保存样本。
- [ ] 维护期记录维护事件，但抑制通知和衍生告警。
- [ ] 窗口结束后按当前状态重新评估，不批量补发维护期旧通知。
- [ ] 窗口创建、修改、删除均写审计。

### 5.2 告警确认和关闭

- [ ] 支持 `firing`、`acknowledged`、`resolved`、`closed` 状态。
- [ ] ACK 不等于恢复，指标恢复仍由采集事实驱动。
- [ ] 只有授权用户可以确认或关闭。
- [ ] 记录确认人、确认时间、关闭人、关闭时间和备注。
- [ ] 已恢复事件可关闭归档。
- [ ] 活动告警唯一约束在 ACK 后仍然有效。
- [ ] 告警详情显示完整时间线。

## 6. 线路组、主备与负载均衡

- [ ] 建立线路组模型和成员关系。
- [ ] 成员角色支持 primary、backup、load_balanced。
- [ ] 同一链路只能在允许的组关系中出现，约束明确。
- [ ] 组级状态由成员状态、角色和实际流量共同计算。
- [ ] 主链路 Down 且备用承担流量时显示“已切换”，但 P1 不做根因关联。
- [ ] 备用链路正常待机时不因低流量标记异常。
- [ ] 负载均衡组显示总带宽和成员分布。
- [ ] 聚合接口使用共享接口标准化工具匹配，不按厂商显示名直接比较。
- [ ] 至少覆盖 Cisco、Huawei、H3C 的聚合口与成员口测试夹具。

## 7. 前端任务

- [ ] 超过30条默认表格视图。

- [ ] 筛选支持站点、运营商、状态、角色、线路组和关键字。
- [ ] 切换筛选重置页码并取消旧请求。
- [ ] 图表只加载选中的1～5条线路。
- [ ] 首屏只加载当前状态，不加载所有历史数据。

### 7.2 热度条与图表

- [ ] 最近60次样本按利用率区间显示绿/黄/橙/红。
- [ ] 无数据为灰色，维护窗口为蓝灰色。
- [ ] Tooltip 显示时间、利用率、速率和采集状态。
- [ ] 增加错包/丢弃趋势图。
- [ ] 增加峰值、P95、高负载时长统计卡。
- [ ] 30天及更长时间范围只读取聚合接口。

### 7.3 维护和告警 UI

- [ ] 维护窗口支持创建、编辑、删除和范围预览。
- [ ] 告警事件支持确认、关闭和备注。
- [ ] 操作按钮按权限显示。
- [ ] 告警时间线按需加载，不在列表返回完整详情。
- [ ] 维护中、已确认、已恢复、已关闭使用不同视觉状态。
