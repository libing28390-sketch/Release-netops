# 修复思科拓扑链路未显示

## 任务目标

修复在 Cisco/cisco_ios 设备发现时，尽管设备上 LLDP 邻居存在，但拓扑图上未显示 links（0 links）的问题。

## 当前问题

1. 在 `topology_service.py` 和 `discovery_service.py` 中，针对 `cisco_ios` 平台定义的 LLDP 邻居发现命令是 `show lldp neighbors detail`。
2. 在某些虚拟化/特定 Cisco IOS 版本（如 IOL/IOU）中，`show lldp neighbors detail` 输出的各条目中**不包含**本地接口（`Local Intf:`）信息，而只在简表（`show lldp neighbors`）中展示本地接口。
3. 拓扑发现和设备匹配的核心逻辑依赖于 `local_interface`（本地接口）来建立双向链路；如果没有获取到本地接口，观察记录就会被过滤/丢弃，导致无法生成链路。
4. NTC-templates 本身内置了对 `show lldp neighbors` 简表的 TextFSM 模板支持（`cisco_ios_show_lldp_neighbors.textfsm`），可以直接正确解析出 `NEIGHBOR_NAME`, `INTERFACE` (本地接口), `NEIGHBOR_INTERFACE`。

## 拟修改文件

* `backend/services/topology_service.py`：修改 `cisco_ios` LLDP 邻居发现指令。
* `backend/services/discovery_service.py`：修改 `cisco_ios` 发现任务邻居查询指令。
* `backend/services/normalizers/cisco.py`：修改解析邻居 TextFSM 命令并适配解析出来的简表字段。
* `backend/tests/vendor_audit/test_h3c_cisco_quick_queries.py`：同步测试断言。

## 实施步骤

1. 修改 `topology_service.py` 中 `DISCOVERY_COMMANDS` 字典中 `'cisco_ios'` 对应的 LLDP 发现指令。
2. 修改 `discovery_service.py` 中 `COMMAND_PROFILES` 字典中 `'cisco_ios'` 对应的 `'neighbors'` 发现指令。
3. 更新 `backend/services/normalizers/cisco.py` 的 `parse_neighbors` 方法，使用 `show lldp neighbors` 命令解析，并从解析字典中兼容检索 `interface` 等简表特有字段。
4. 更新 `backend/tests/vendor_audit/test_h3c_cisco_quick_queries.py` 以反映指令变更。
5. 运行 pytest 测试。
6. 重启服务，手动执行发现验证。

## 验证计划

- **单元测试**：运行 `python -m pytest backend/tests`。
- **页面验证**：拓扑页面手动触发“Collect LLDP/CDP”，确认观察记录和 `topology_links` 正常写入数据库，拓扑图正常显示连线。

## 风险与回滚
