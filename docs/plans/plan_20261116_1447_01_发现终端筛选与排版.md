# 发现终端筛选与排版

## 目标与现状
修复 /ipam/endpoints 选中来源设备后其余设备选项消失的问题；精简首屏筛选并改善文字层级。当前后端在构建选项前已按 device_id 限定投影，且设备选项来自完整筛选结果，导致自我收窄。

## 范围与文件归属
- 主 Agent：src/pages/IPVlan/DiscoveredEndpointsTab.tsx 及其 test、统一计划/走查与内部页面覆盖记录。
- 后端 Luna：backend/services/ipam_discovery_service.py、backend/tests/ipam/test_ipam_current_endpoint_api.py；只处理 current endpoint 设备候选来源和对应回归。
- 保持分页、导出、租户/站点权限、采集和登记契约；不访问真实设备、不变更业务数据。

## 步骤
1. 后端设备候选不被当前设备条件收窄，站点及权限继续有效；增加直接切换及空结果回归。
2. 常用筛选保留站点、来源设备、搜索；记录类型和观察范围移至更多筛选，非默认条件计数正确。
3. 缩短说明，摘要分层，统一正文与辅助文字字号、字重；保留完整详情和指标含义。
4. 定向测试、类型检查、隔离生产构建；可用浏览器进行只读/模拟数据交互与排版验证。

## 验证
后端指定隔离 PostgreSQL 回归（仅可丢弃临时库）；前端 DiscoveredEndpointsTab 测试、npm run lint、隔离 vite build；后端变更运行 PostgreSQL-only scanner。公共检查由主 Agent 统一执行一次。

## 风险与回滚
全设备候选查询可能增大投影开销，避免额外重复加载；选项不泄漏权限外来源。折叠筛选保留原值和默认语义。通过本次文件差异回滚，不覆盖用户已有修改，不提交/推送/部署。
