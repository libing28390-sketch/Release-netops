# IPAM 运行页面与 ARP 周期采集实施计划

## 任务目标

让 ARP 表工具栏使用项目公共控件；把现有 ARP 扫描间隔接入真正的 APScheduler 周期采集，并沿用现有采集状态记录；精简 IP 对账重复说明但保留“IPAM 台账为基准、设备发现缓存为对比证据”；重排利用率页面，减少无趋势数据时的大块空白并改善站点卡片布局。

## 现状与问题

- ARP 表搜索框、刷新、立即采集按钮使用页面私有样式，未复用公共表单/操作组件。
- 页面显示 10 分钟采集间隔，但该配置当前仅用于缓存时效；实际自动 ARP 扫描仅随每日 NSOT 同步发生，也可由用户手动触发。
- ARP 扫描状态已有 collector_sweep_state 记录；暂未发现全入口共享的采集互斥。新增周期扫描前必须处理与手动/NSOT 扫描的重叠风险。
- IP 对账页的基准与缓存说明在标题、状态条、统计卡片中重复出现。
- 利用率页无历史样本时仍展示高大的空图表卡，站点少时布局留白不均。
- 工作区在本任务开始前已有多项未提交改动。本轮保留这些改动，只编辑下列文件及对应文档。

## 影响范围

前端仅调整呈现；后端只在现有 APScheduler 生命周期中启用周期 ARP 扫描，使用现有间隔配置和状态表，不新增数据库表、不改对账算法或 ARP 数据格式。

## 拟修改文件

- backend/main.py（ARP 周期任务注册）
- backend/services/ip_locator_service.py（所有 ARP 采集入口共享数据库租约）
- backend/api/ip_locator.py（采集重入时返回明确状态）
- src/components/ui/IconInputField.tsx（为公共输入标签增加可访问的隐藏样式选项）
- src/pages/IPLocatorPage.tsx
- src/pages/IPVlan/IPReconciliationTab.tsx
- src/pages/IPVlan/IPUtilizationTab.tsx
- 本计划、对应 walkthrough 及 handoff 新增段落

## 实施步骤

1. 将 ARP 筛选框改为公共 IconInputField，刷新与采集操作改为公共 ActionButton，保留原筛选、加载禁用及采集结果行为。
2. 核对 APScheduler 启停生命周期、分布式调度锁和 run_arp_sweep 的所有调用入口；把 ARP_SWEEP_INTERVAL_SECONDS 接到周期 job，默认沿用页面现有 10 分钟配置。
3. 在 run_arp_sweep 服务入口用现有 scheduler_locks 数据库租约避免周期任务、手动 API 和 NSOT 同时扫描同一批设备；复用 collector_sweep_state，不新增定时配置表。采集状态和失败结果继续按现有逻辑写入。
4. 对账页只保留简短比较基准和缓存时效状态，删除重复长段说明及统计卡片描述，不改刷新、筛选、导出和计算结果。
5. 优化利用率 KPI 对齐、利用率行信息层级、无趋势时的紧凑空状态和站点卡片响应式宽度。
6. 静态审查共享组件属性、调度保护与现有状态逻辑，更新 walkthrough 和 handoff。

## 验证计划

- 用户未要求运行测试/构建；不新增或运行测试、不运行构建。
- 运行 git diff --check 检查本任务源码和文档。
- 静态确认：周期 job 使用秒级配置且具备单实例/互斥保护；手动与 NSOT 入口不会重复并行扫描；锁冲突时手动 API 有明确反馈；周期运行继续更新现有 collector_sweep_state；ARP 表显示实际生效间隔；对账基准含义保留；有趋势时仍使用原图表渲染。

## 风险与回滚思路

- 多个后端进程可能各自启动 APScheduler；注册时应复用项目现有数据库租约/唯一执行保护。
- run_arp_sweep 也由手动 API 和 NSOT 统一采集调用。仅为 scheduler job 设置 max_instances 不足以防止这些入口互相重叠；应在服务级加共享锁，或使用可覆盖全部入口的现有数据库租约。
- 长时间采集超过间隔时须避免高频跳过告警或堆积；采用单实例、合并错过触发，且不新增容易造成日志刷屏的短周期轮询。
- 修改局限于指定前后端文件和新增文档记录；不改变现有采集数据或部署配置。

## NSOT 的 SNMP 覆盖补充核对

- 当前统一 NSOT 流程是混合协议：ARP 优先 SNMP、失败回退 CLI；LLDP 优先 SNMP、空结果/不完整时回退或合并 SSH；接口先读 IF-MIB 后仍用 CLI 补齐属性。
- MAC/FDB、路由表、动态路由邻居与 BGP 路由目前走平台命令或 CLI 采集；接口/IPAM 前缀投影、记录落库属于服务端处理，本身不是设备协议采集。
- SNMP 可覆盖多类设备事实，但全量替代取决于各型号启用的 MIB、只读视图和字段完整度。BGP/VRF 路由等需要逐厂商验证，不能因标准 MIB 存在就默认可替换现有结果。
- 本轮只评估，不改写其余 NSOT 采集协议；后续若切换，建议按数据域实现 SNMP，并与 CLI 结果影子比对后再决定回退策略。
