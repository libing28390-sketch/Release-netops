# 资产主机名与 CLI 邻居关联

## 任务目标

资产导入必须提供主机名；拓扑发现使用当前 CMDB 资产主机名展示设备，并在 SNMP `sysName` 不可用时保留该名称。CLI LLDP 邻居只按当前 CMDB 的资产 hostname 精确且唯一匹配；未匹配结果只保留诊断，不生成画布伪设备或正式链路。SNMP 仍按管理 IP 优先关联。CLI 命令和现有解析模板不在本次修改范围内。

用户最新确认：导入时尝试读取设备实际主机名并同步至 CMDB，再同步关联设备记录；同步失败保留导入名称并明确提示用户核对。CLI 不增加强制在线验证门槛，只检查当前 CMDB 名称能否唯一匹配。全平台读取 CMDB 名称，SNMP 成功时不再调用 CLI 获取 LLDP。

## 现状与问题

- 资产导入过去允许 hostname 为空，并将管理 IP 或资产编号写成 hostname，导致 CMDB 缺少可用于 CLI LLDP 关联的设备名。
- 当前身份匹配器对 SNMP、CLI 共用 IP/序列号/多种 hostname 别名策略；CLI verbose 即便报告管理 IP，也可能因此绕过资产 hostname 规则。
- CLI 未匹配邻居目前仍可能进入伪节点/链路投影，和“只供诊断、不进正式拓扑”的约束不一致。
- 设备节点和部分链路端点显示直接读取 `devices.hostname`，没有始终投影资产导入名。
- SNMP `sysName` 成功时使用现有的代次校验与安全同步逻辑；失败时不应让 CLI 本机 System Name 覆盖 CMDB 名称。
- SNMP：管理 IP 优先，按现有冲突保护规则匹配。
- CLI：沿用既有 parser 的名称规范化，在匹配阶段仅与当前 `physical_assets.hostname` 做大小写无关精确匹配；必须唯一。忽略 CLI 邻居管理 IP、序列号、`devices.hostname`、资产标签、历史观测，不新增 separator/FQDN 模糊别名匹配。
- SNMP 采集成功时不调用 CLI；CLI 仅作为现有失败/不完整采集路径的兜底。采集命令及 TextFSM 模板沿用当前实现。
- 发现结果 UI 合并重复异常提示，保留异常数量、可展开逐台详情，并提供一条简短建议：检查 SNMP Community；若 CLI 原始输出有邻居但解析结果为空，再检查对应平台解析模板。

## 影响范围

- 批量资产导入主机名校验与错误回报。

- H3C LLDP verbose 命令用于获得邻居管理地址和名称；SNMP 路径与接口聚合逻辑保持不变。

## 实施步骤

1. 在 CLI identity matcher 中基于 `physical_assets.hostname` 建立独立的唯一索引；CLI 记录不使用 IP、序列号、旧观测或宽松别名关联。
2. 将采集来源贯穿 observation 写入、当前 run 重匹配及 graph rebuild；未唯一匹配的 CLI 观测保留在诊断接口，由已有 managed canvas 投影排除这些临时节点和链接，不进入正式画布。
3. SNMP 匹配与现有成功/失败及 fallback 选择保持不变；不修改 CLI 命令、TextFSM 模板和字段解析。
4. 精简拓扑发现状态条和诊断卡片：移除逐台重复异常 chip/长解释，保留汇总、折叠详情及单条 Community/模板排查建议。
5. 补充 CLI hostname 成功、IP 冲突但 hostname 命中、hostname 未命中、重复 hostname 歧义及未匹配 CLI 不进入 graph 的回归验证。
6. 核对资产导入的自动主机名同步、失败提示及资产到关联设备的名称传播；复用现有同步服务，不引入强制 hostname 已验证状态。
7. 修正设备列表仍读取旧 devices.hostname 的缺口：列表/轻量列表、搜索与排序以关联 CMDB hostname 为准。已关联资产的设备编辑读取 CMDB 名称并修正设备镜像，界面名称字段只读、指引至 CMDB 维护。无关联资产的旧设备保留兼容读取，不在本次批量迁移旧资产。

## 分工边界

- 主 Agent：拓扑 identity matcher、拓扑回归、集成验证及本计划/walkthrough。
- 后端执行者：核对导入同步；独占 backend/api/devices.py 与新的设备名称契约测试，不修改共享 topology_service.py。
- 前端执行者：资产导入同步失败提示及 DeviceFormModal 已关联资产名称只读，不修改主 Agent 已整合的拓扑发现页面。

## 验证计划

- pytest 覆盖 topology 的 SNMP/fallback、当前 run 身份关联、hostname 同步，configuration 的资产导入和设备 CMDB 名称契约，以及 platform_registry 的既有平台绑定检查。
- 前端 vitest 覆盖 DeviceFormModal、资产导入工具及 managed canvas/link projection。
- `npm run lint` 与 `npm run build`，验证双语诊断提示和页面构建。
- `git diff --check`，并通过代码检查确认 CLI 解析命令/模板文件没有变化。
- 不连接真实设备；SNMP/CLI 行为由 fixture 和 mock 验证。

## 风险与回滚思路

- 既有 hostname 已被存成管理 IP 的资产无法凭代码还原原始名称；需要在资产管理中补齐名称。重复导入仍按既有规则跳过，不会静默覆盖已有资产。
- CLI 资产 hostname 精确匹配会降低自动建链覆盖率，但可避免连错设备；需在当前 CMDB 补齐准确、唯一 hostname。
- 大小写按 hostname 通常约定忽略；沿用现有 parser/hostname sync 的规范化，不另加名称猜测。
- SNMP 成功同步和设备采集配置不受影响；未匹配 CLI 邻居仍可在诊断中查看，但不会画入正式拓扑。
