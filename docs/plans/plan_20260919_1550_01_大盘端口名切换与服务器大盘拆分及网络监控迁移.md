# 实施计划 - 大盘端口名切换、服务器大盘拆分及网络监控功能迁移

## 任务目标
根据用户提出的三项新需求进行针对性改进与重构：
1. **大盘端口显示优化**：所有的 Grafana Dashboard 端口不再显示 SNMP 内部数字索引 `ifIndex`，统一使用交换机上的完整物理/逻辑端口编号（如 `GigabitEthernet1/0/1`、`XGigabitEthernet0/0/1` 等真实端口名称）。
2. **服务器监控大盘拆分为 Linux / Windows 专属大盘**：
   - 将原「07 服务器与主机监控」拆分为两个专业、美观、直接的大盘：
     - `07 Linux 服务器监控 (Linux Server Metrics)`：基于生产级 `node_exporter` 经典最佳实践设计（CPU 使用率、负载 Load1/5/15、内存/Swap 分布、磁盘 IOPS 及挂载点利用率、网络吞吐、TCP 状态）。
     - `08 Windows 主机监控 (Windows Host Metrics)`：基于生产级 `windows_exporter` 设计（Windows CPU 占比、物理可用内存/Commit 限制、逻辑盘 C:/D: 空间与读写延迟、网络流量、系统运行时间、上下文切换与活跃会话）。
   - 在前端大盘展示列表 [GrafanaDashboardPage.tsx](file:///d:/netops/netsops-main/src/pages/GrafanaDashboardPage.tsx) 中同步呈现。
3. **下线 /monitor/networks 菜单并将 SNMP 批量同步主机名迁移到 /assets/network-devices**：
   - 彻底从侧边导航栏下线 `/monitor/networks`。
   - 在网络设备管理页面 [InventoryDevicesTab.tsx](file:///d:/netops/netsops-main/src/pages/InventoryDevicesTab.tsx) 的顶部工具栏及批量操作浮动胶囊中，新增「SNMP 同步主机名」按钮，一键或批量调用 `/api/devices/batch-sync-hostname` 完成全网/选中设备的主机名探测与更新。
   - 对历史路由 `/monitor/networks` 提供平滑自动重定向至 `/assets/network-devices`。

## 现状与分析
1. **端口号 `ifIndex` vs `ifName`**：
   - 目前在 `generate_dashboards.py` 中，部分图表的 `legendFormat` 编写为 `端口 {{ifIndex}}`，表格聚合使用了 `by (hostname, instance, ifIndex)`。
   - Prometheus SNMP Exporter 的 `snmp.yml` 采集了 `ifName` (1.3.6.1.2.1.31.1.1.1.1)，在配置 `lookups` 后会直接作为 label 附加在 `ifHCInOctets`、`ifHCOutOctets`、`ifOperStatus` 等指标上。
   - 图表与表格需将聚合键与展示标签切换为 `ifName`，并在表格清理规则 `clean_organize_transformation` 中隐藏 `ifIndex`，突出 `ifName`（端口编号）。
2. **服务器监控大盘现状**：
   - 原 `server-metrics.json` 杂糅了 Linux 与 Windows 指标，面板通用性较粗糙。
   - 官方对 Linux（`node_exporter` 1860 大盘）与 Windows（`windows_exporter` 14611 大盘）有成熟的设计标准，拆分后能让系统运维视角更为专业直观。
3. **网络监控菜单精简**：
   - 监控总览及各专业监控大盘已有完善可视化，原 `/monitor/networks` 页面只剩余单设备指标折线与 SNMP 批量同步主机名功能，用户确认可以移除该菜单。
   - 批量同步主机名属于网络设备资产台账的核心运维动作，迁移至 `/assets/network-devices` 完全符合用户操作心智。

## 实施步骤

### 步骤 1：大盘端口编号切换为 `ifName`
1. 修改 `monitoring/snmp-exporter/snmp.yml`：
   - 为接口相关的关键 MIB 指标（`ifOperStatus`, `ifAdminStatus`, `ifInOctets`, `ifOutOctets`, `ifHCInOctets`, `ifHCOutOctets`, `ifInErrors`, `ifOutErrors`, `ifInDiscards`, `ifOutDiscards`, `ifHighSpeed`）配置 `lookups`，绑定 `ifIndex -> ifName` 与 `ifIndex -> ifDescr`。
2. 修改 `monitoring/grafana/generate_dashboards.py`：
   - 更新 `clean_organize_transformation`：将 `ifIndex` 设为 `excludeByName: True`，将 `ifName` 重命名为 `端口编号`，排在首要显示列。
   - 将所有图表（接口入出流量、丢包统计、出口带宽、利用率等）的 `legendFormat` 从 `端口 {{ifIndex}}` 统一更新为 `{{ifName}}` 或 `{{hostname}} - {{ifName}}`。
   - 将 PromQL 中的 `by (hostname, instance, ifIndex)` 切换为 `by (hostname, instance, ifName)`。

### 步骤 2：拆分并生成 Linux 与 Windows 服务器大盘
1. 在 `monitoring/grafana/generate_dashboards.py` 中：
   - 编写 `build_linux_dashboard()`：UID `nexora-linux-metrics`，大盘标题「07 Linux 服务器监控 (Linux Server Metrics)」。集成 CPU 利用率走势、Load1/5/15 负载走势、内存占用及缓存、磁盘利用率 Top 表格、磁盘读写 IOPS、网络流量 bps、TCP 连接状态统计。
   - 编写 `build_windows_dashboard()`：UID `nexora-windows-metrics`，大盘标题「08 Windows 主机监控 (Windows Host Metrics)」。集成 Windows CPU 使用率、物理内存利用率、逻辑驱动器可用空间、磁盘读写延迟/秒、网络进出吞吐、系统运行时间。
   - 运行生成脚本，生成 `linux-metrics.json` 与 `windows-metrics.json`。
2. 更新 [GrafanaDashboardPage.tsx](file:///d:/netops/netsops-main/src/pages/GrafanaDashboardPage.tsx)：
   - 在 `GRAFANA_DASHBOARDS` 中配置 `nexora-linux-metrics` 与 `nexora-windows-metrics` 两张卡片。

### 步骤 3：下线 /monitor/networks 并将 SNMP 批量同步迁移至 /assets/network-devices
1. 在 [src/components/AppSidebar/navConfig.ts](file:///d:/netops/netsops-main/src/components/AppSidebar/navConfig.ts) 中：
   - 移除 `network-monitoring` 菜单项。
2. 在 [src/pages/InventoryDevicesTab.tsx](file:///d:/netops/netsops-main/src/pages/InventoryDevicesTab.tsx) 中：
   - 引入 `handleBatchSyncHostnames` 方法，调用 `/api/devices/batch-sync-hostname`。
   - 在顶部按钮区域添加「SNMP 同步主机名」按钮，支持对全网设备一键探测同步。
   - 在底部多选浮动胶囊中添加「批量同步主机名」按钮，支持对选中的设备执行定向同步。
   - 同步完成后提示更新台数/未变更台数，并自动刷新设备列表。
3. 在 [src/components/AppMainContent.tsx](file:///d:/netops/netsops-main/src/components/AppMainContent.tsx) 与 [src/utils/routeContext.ts](file:///d:/netops/netsops-main/src/utils/routeContext.ts) 中：
   - 将 `/monitor/networks` 路径重定向至 `/assets/network-devices`。

### 步骤 4：验证与交付
1. 运行 `python monitoring/grafana/generate_dashboards.py` 验证所有大盘生成正常。
2. 运行前端单测 `npx vitest run src/utils/routeContext.test.ts`。
3. 运行 `npm run build` 确保前端构建零错误。
4. 创建 `docs/fixes/` 修复记录与 `docs/walkthrough/` 验证记录。
5. 提交并推送到远端仓库。

## 风险与回滚思路
- SNMP lookups 为标准的 MIB 扩展能力，缺失 ifName 时 exporter 会以原指标正常输出，不影响采集连通性。
- 路由重定向保证原有书签或历史链接不会 404，直接导流至网络设备管理页。
- 全量修改可通过 Git 单次提交完整回退。
