# 设备详情筛选与布局

## 任务目标

优化 `02 网络设备详情` 顶部“设备身份与 SNMP 连通性”表格，避免表格行被面板裁切并减少无关技术标签占用；补齐参考 `04 接口流量与健康` 的站点、厂商、角色筛选，同时保留单设备详情语义。

## 现状 / 问题

- 设备身份表高度为 3 个 Grafana 网格单位，截图中首条设备信息显示不完整。
- 表格仅显式重排业务字段，但未隐藏 `site_id`、`tenant_id` 等非必要标签。
- 设备详情看板只有资产设备、CPU 采样窗口、硬件分组、部件和部件类别变量，没有站点、厂商、角色筛选。
- 生成器 `monitoring/grafana/generate_dashboards.py` 是该文件源头；生成器会重写 12 个看板 JSON。

## 影响范围

- 设备详情 Grafana 看板变量、身份表布局及列展示。
- 不改指标采集、查询语义和其他看板的业务逻辑；不写入 Grafana 实例、不部署。

## 拟修改文件

- `monitoring/grafana/generate_dashboards.py`
- `monitoring/grafana/dashboards/nexora-network-device.json`（由生成器生成）
- `backend/tests/monitoring/test_domestic_and_wireless_monitoring.py`：验证设备变量按站点、厂商和角色筛选。
- 对应 `docs/walkthrough/` 完成记录

## 实施步骤

1. 为设备详情增加级联的站点、厂商、角色变量，并让现有单选设备变量按这些条件过滤，继续以 `asset_id` 唯一限定单台设备。
2. 增加身份表高度，隐藏租户/站点内部 ID 等非面向操作员的标签，保留易读设备身份及 SNMP 状态列。
3. 运行看板生成器，检查全部输出文件的差异，确认仅目标看板变化。
4. 运行 Python 编译和 JSON/面板结构检查、`git diff --check`；使用浏览器检查当前 Grafana 展示。实时实例若未加载本地源文件则记录限制，不执行部署。

## 验证计划

- `python -m py_compile monitoring/grafana/generate_dashboards.py`
- `python` 解析生成器输出的全部看板 JSON，并检查目标变量顺序/查询和面板 ID 唯一性。
- `pytest backend/tests/monitoring/test_domestic_and_wireless_monitoring.py -q`
- `git diff --check`
- 浏览器检查 04 参考看板的变量布局，并尝试检查 02 看板渲染；不执行自动化测试或 Grafana 写入。

## 风险与回滚思路

- 新增变量按 `site_name`、`vendor`、`role` 级联过滤；设备变量仍是单选且仍以 `asset_id` 查询所有单设备指标，避免 All 选项让硬件统计跨设备聚合。
- 若 Grafana 变量查询在目标实例无法解析，撤回设备详情看板生成器对应改动并重新生成目标 JSON；不触碰其他未提交文件。
- 生成器输出范围为 12 个 JSON；生成后逐个检查差异，遇到非目标文件漂移时停止并保留证据。
