# 山石配置备份命令计划

## 任务目标
为 Hillstone StoneOS 配置备份加入用户确认的运行配置命令 `show configuration running` 和启动配置命令 `show configuration startup`，保证单设备、批量和定时备份都使用一致映射，并明确执行平台为 Hillstone。

## 现状/问题
平台/资产目录已包含 Hillstone 与 `hillstone_stoneos`，但备份服务没有厂商默认命令，前端默认命令表也没有 Hillstone；部分旧驱动对未映射平台会静默使用 Cisco device type。这样 Hillstone 可能无法备份或错误使用 Cisco 驱动。

## 影响范围
后端备份命令解析与平台注册表、平台规范化、Netmiko 驱动分发、前端单设备备份默认命令。备份数据格式、权限、配置内容处理与其他厂商行为不变。

## 拟修改文件
- `backend/services/platform_registry_service.py`
- `backend/services/config_backup_command_service.py`
- `backend/services/config_vendor_platform_service.py`
- `backend/api/assets.py`
- `backend/core/platform_utils.py`
- `backend/engine/drivers/netmiko_driver.py`
- `backend/drivers/netmiko_driver.py`
- `src/utils/configBackupCommands.ts`
- `backend/tests/configuration/test_startup_config_backup.py` (更新厂商覆盖预期)
- `backend/tests/vendor_audit/test_hillstone_support.py` (验证资产和 StoneOS 别名规范化)
- `docs/plans/` 与 `docs/walkthrough/`

## 实施步骤
1. 将用户提供的 StoneOS running/startup 命令加入后端平台动作目录和前端单设备命令表。
2. 将 Hillstone/山石与 `hillstone_stoneos` 纳入后端 vendor-first 默认命令解析、资产厂商归一化和平台规范化。
3. 明确两个 Netmiko 驱动路径的 Hillstone platform 选择，避免 Cisco 静默回退；确认当前 Netmiko dispatcher 注册 Hillstone 原生类型。
4. 检查差异、Python 语法和 TypeScript 类型，记录最终生效命令文件与行号。

## 验证计划
运行受影响 Python 源码语法检查、`npm run lint` 和配置备份命令/平台识别聚焦 PostgreSQL 测试；不连接真实设备。

## 风险与回滚思路
命令内容由用户明确提供，未在真实 StoneOS 设备上执行验证；不同版本的 CLI 支持情况仍需设备侧只读核对。若命令或驱动选择不符合设备版本，回滚 Hillstone 专属映射，不影响其他厂商。
