# IPAM 网段布局与对账核查计划

## 任务目标

优化 `/ipam/prefixes` 网段管理页在不同窗口宽度和高度下的排版、表格列宽与滚动行为；同时查明 IP 对账功能的用途和当前页面为何看起来没有发挥作用，并向用户说明证据和判断。

## 现状与问题

- 浏览器中的网段管理页当前显示 26 条记录、16 列。表格位于可滚动卡片中，但通用表格最小宽度只有 640px，列数较多时仍可能被压缩，内容和状态标签可读性不稳定。
- 页面根容器没有显式设置 `min-w-0`/`min-h-0`；操作区和筛选区在窄视口中需要可靠换行，表格应在自身区域横向滚动且不撑宽父级。
- IP 对账页当前三个类别均显示 0。服务端把 `ip_addresses` 与 `network_endpoints` 中活跃发现记录作比较；网段页的“活跃发现 IP 数”目前也显示为 0。
- 对账页的“重新对账”按钮调用的是只读 GET 接口重新计算并刷新结果；另有独立的持久化 reconciliation run/finding API，页面本身未调用该持久化接口。

## 影响范围

- 前端网段管理页面的响应式容器、工具栏和表格呈现。
- 对账功能只读核查，不改变其 API、数据或导航入口。

## 拟修改文件

- `src/pages/IPVlan/PrefixManagementTab.tsx`
- 本计划和配对 walkthrough 文档。

## 实施步骤

1. 保留文件中已有的地址池入口、加载错误处理和其他用户未提交改动。
2. 为网段页面补齐 flex 收缩约束，让操作区/筛选区可换行，并让列表表格至少 1900px、树形表格至少 1800px；空间不足时在结果区横向滚动。
3. 保持结果卡内部独立双向滚动、分页留在卡片底部；表头随纵向滚动固定，状态/用途徽标不拆字，过长网段名称截断并可悬停查看。
4. 静态复核差异并记录对账调用链的证据。依当前协作约束不运行测试、lint、构建或代码以外的浏览器验收。
5. 更新 walkthrough，明确对账功能的用途、页面当前的 0 结果以及造成“未用起来”观感的实现边界。

## 验收标准

- `/ipam/prefixes` 页面不会被宽表撑出主内容区；窗口不足时只在结果区横向滚动。
- 列表和树形视图的关键字段、用途/状态徽标保持可读，操作栏与分页不会因表格滚动消失。
- 不改变前缀数据查询、筛选、分页、导出、接口或业务逻辑。
- 明确解释 IP 对账比较的对象、差异类型、可执行操作、数据依赖，以及当前零结果和“重新对账”行为。
- 记录已发现的对账限制：页面刷新仅读取并重算现有数据，不触发 ARP/SNMP 采集；“僵尸 IP”当前没有按失联时长做阈值判断。

## 验证计划

- 静态检查修改后的 JSX 类名与表格结构。
- `git diff --check`。
- 不运行测试、lint、构建或浏览器验收。

## 风险与回滚思路

- 窄视口可能需要横向滚动来查看完整 16 列，这是保留全部字段和标签可读性的预期行为。
- 若最小表宽度不适合目标设备，可仅调整本页表格的 Tailwind 最小宽度和响应式工具栏，不涉及数据/API 回滚。
- 同一页面文件此前已有的地址池和错误状态修改必须保留；回滚时只撤销本轮布局类名与表格宽度变更。
