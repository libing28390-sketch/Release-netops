# 网络总览硬件指标覆盖与热点计划

## 任务目标

让 01 网络总览回答“硬件监控覆盖是否足够、哪些设备当前 CPU/内存使用最高”，避免用跨设备平均趋势造成含义混淆或掩盖热点。

## 现状与问题

- 总览目前有按设备分组的 CPU、内存趋势和多厂商温度趋势，但默认全设备时会形成多条设备序列，且用户截图中三面板均无数据。
- CPU/内存百分比可从现有多厂商指标族统一筛选；温度传感器定义和阈值并未形成统一的厂商/型号策略。
- 工作树已包含此前 Linux 图例布局、近期 Down 链路过滤和 `handoff.md` 改动；全部属于既有工作，实施时必须保留。

## 影响范围

- 仅重排 01 总览的硬件健康面板：显示 CPU、内存、温度的在线指标覆盖数量，并用 CPU / 内存 Top10 当前值表替换设备趋势图。
- 不改采集指标、硬件使用率 PromQL 的归一化口径、设备详情页面或温度告警策略。
- 覆盖数按在线设备计数；无资源指标时显示 0 台覆盖，未在线设备不进入分母。

## 拟修改文件

- `monitoring/grafana/generate_dashboards.py`
- 生成文件 `monitoring/grafana/dashboards/nexora-network-overview.json`
- 本任务计划与完成记录。

生成器输出清单已检查：9 份仪表盘 JSON；预期仅 Overview JSON 新增差异，之前的 Linux Metrics JSON 改动需原样保留。

## 实施步骤

1. 复用 Overview 的多厂商 CPU、内存和温度 PromQL，统计当前在线且确有对应指标的设备数。
2. 将 CPU/内存硬件趋势替换为按当前使用率排序的设备 Top10 表；移除跨厂商总览温度排序，不将传感器读数套用统一告警阈值。
3. 更新面板标题、说明及网格位置；设备级趋势和温度检查继续由设备详情承担。
4. 运行生成器，检查所有 JSON 与完整差异。

## 验证计划

- 编译 `generate_dashboards.py`。
- 解析全部生成的仪表盘 JSON；检查三个覆盖面板有在线设备过滤，CPU/内存 Top10 查询保留现有百分比表达式。
- 确认其它仪表盘无新差异，运行 `git diff --check`。

## 风险与回滚

- 指标覆盖数为 0 表示在线设备当前没有匹配到该资源指标；可能是设备不支持该 OID，也可能是采集未配置，不能直接推断 CPU/内存为 0。
- CPU/内存 Top10 是当前值排行，不是故障判定；需要阈值告警时应另行按厂商/型号策略定义。
- 温度只呈现覆盖情况，避免不同传感器混排造成误导；具体温度和告警在设备详情检查。
- 回滚时恢复 Overview 的三个硬件时间序列面板及原网格位置，再运行生成器。
