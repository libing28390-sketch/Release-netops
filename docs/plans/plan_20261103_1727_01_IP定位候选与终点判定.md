# IP定位SNMP优先与终点判定

## 目标与现状
发现终端已有SNMP ARP/FDB/接入口证据，定位仍按CLI核心角色起点追踪，产生无关设备失败及虚假的MAC能力不足。

## 影响范围及文件
主Agent负责ip_locator_trace_service.py接入和兼容字段；Luna负责新增ip_locator_endpoint_evidence.py及其测试，不修改共享发现服务。前端仅补SNMP定位类型文案。

## 实施步骤
1. 复用发现终端的同设备VLAN/MAC接入口证明，在租户、授权设备、站点及VRF边界内识别唯一可信端点。
2. 普通定位先使用有效SNMP证据；实时刷新按已知目标ARP来源设备执行现有SNMP事实采集，再重新判断。
3. 证据不足保留原追踪兜底，不将未知VRF解释为完整L3路径，不缓存SNMP端点为旧CLI路径。
4. 修正设备角色导致的MAC能力误判文案/策略，覆盖成功与拒绝边界。

## 验证
focused pytest、类型检查、PostgreSQL策略扫描；本机读取/定位验证实际S6850-5端口以及查询设备范围。

## 风险与回滚
不改设备配置、不扩张授权、不迁移数据库；实时采集复用已有租约及并发限制。移除新入口调用即可回退旧追踪；已有源数据保留。
