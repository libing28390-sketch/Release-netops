# 资产导入字段清理与日期格式计划

## 任务目标

按用户最新模板约束清理两张资产工作表：网络设备删除“业务IP”；服务器删除 SNMP 社区/端口、SNMP 凭据和 Enable 密码；两张表的“录入来源”都使用下拉；购买日期和保修到期统一显示为 `YYYY/MM/DD`；管理入口补充 HTTP、HTTPS 及登录路径样例。

## 影响范围

- `public/templates/asset_import_template.xlsx`：静态下载模板的两张资产表和管理入口样例。
- `src/pages/AssetManagement/index.tsx`：浏览器兜底模板的字段投影、日期格式和管理入口样例。
- `docs/walkthrough/`：记录验证证据。

保留填写说明、参数可选值参考、下拉选项和导入解析兼容逻辑；不做数据库或设备变更。

## 实施步骤

1. 读取当前静态模板并按表头定位列，避免继续使用旧统一表的固定列号。
2. 使用表格编辑工具重建两张资产表的保留列：网络设备跳过业务 IP；服务器跳过 SNMP 社区、SNMP 端口、Enable 密码、SNMP 凭据。
3. 在网络设备/服务器各自的“录入来源”列添加“新设备/存量设备”下拉，调整受影响的生命周期、功能、区域、端口和 U 高度校验。
4. 将现有日期单元格格式设置为 `yyyy/mm/dd`，并在管理入口追加 HTTP `/login` 和 HTTPS `/admin/login` 示例；A/B 继续使用资产表公式自动读取。
5. 对静态文件做 XML 级收尾，清除重建过程留下的空白尾列/空行，并保持命名区域和其它工作表不变。

## 验证计划

- 检查两张表的实际表头不再出现用户要求删除的列。
- 检查录入来源校验公式、日期 number format、HTTP/HTTPS 示例和管理入口公式。
- 检查静态模板行数及其它工作表未被重建。
- `npm run test:frontend -- --run src/pages/AssetManagement/importUtils.test.ts`
- `npm run lint`
- `npm run build`

## 风险与回滚

导入解析仍按表头匹配，因此历史完整模板继续兼容。静态模板编辑前保留在 `.codex-tmp` 的临时副本；若验证失败，可恢复当前静态模板，不触碰用户上传原文件。
