# Linux 遥测目标筛选

## 目标

阻止周期遥测任务把 Windows 或操作系统未确认的服务器发送到 Linux SSH 脚本，避免误连 TCP/22。

## 现状与问题

`device_telemetry_sampler` 每分钟调用 `record_device_telemetry_snapshot()`，并执行 `insp_linux_full`。目标选择条件使用“Linux 平台或设备分类含 server”，因此 Windows 服务器也会被选入；SSH 执行器对缺少端口配置的记录回退到 22。

## 影响范围

- 仅调整 Linux 遥测目标筛选；不变更调度周期、脚本、SSH 凭据、Windows WinRM 功能或其他巡检流程。
- 只采集平台字段明确属于当前 Linux allowlist 的在线设备；Windows、ESXi 和未知平台不进入本任务。

## 拟修改文件

- `backend/services/telemetry_service.py`：移除基于通用 `device_category` 的 SSH 采集兜底，按明确 Linux 平台筛选。
- `docs/plans/`、`docs/walkthrough/`、`docs/fixes/`：保存方案、验证和提交记录。

## 实施步骤

1. 保留现有 Linux 平台 allowlist，仅允许平台值命中后进入 `insp_linux_full` SSH 执行。
2. 静态编译目标 Python 文件，检查 diff；不运行测试。
3. 更新走查与修复记录，审查待提交文件，排除构建产物、日志及 `.agents/`、`handoff.md` 等内部协作材料。
4. 在 `main` 提交已授权的代码变更并推送 `origin/main`。

## 验证计划

- `python -m py_compile backend/services/telemetry_service.py`
- `git diff --check`
- 静态确认入选条件只依据 Linux 平台 allowlist，Windows/未知平台不会进入 SSH 执行集合。
- 检查提交范围、远端分支和推送结果；不部署、不连接真实设备。

## 风险与回滚

- 平台字段缺失或使用未列入 allowlist 的 Linux 别名时，该主机将暂停此遥测任务，需先校准其 `platform` 值再恢复采集。
- 回滚只需还原此筛选条件；不影响数据表或其他设备任务。
