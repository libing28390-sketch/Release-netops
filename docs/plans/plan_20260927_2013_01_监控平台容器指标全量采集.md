# 监控平台容器指标全量采集

## 任务目标

- 修复 Grafana `/metrics` 抓取被 HTTP 代理转发并返回 502 的问题。
- 修复 cAdvisor 启动失败，恢复 Docker 容器资源采集。
- 让平台健康大盘展示全部 Docker 服务容器的资源指标与动态采集清单。
- 修复 VictoriaMetrics v1.103.0 不支持 `vm_total_disk_space_bytes` 导致的存储占用面板无数据。

## 现状与证据

- 浏览器中 `up` 即时查询与大盘一致：六个平台抓取端点中四个为 UP，`platform_grafana` 与 `platform_cadvisor` 为 0。
- 用户提供的 vmagent `wget` 输出显示请求 `grafana:3000/metrics` 被送到 `192.168.31.253:10808` 并返回 502。
- 用户提供的 cAdvisor 日志尾部是启动参数帮助文本；Compose 的禁用指标列表包含官方 v0.60.6 参数列表未列出的 `accelerator`。
- 目标 VictoriaMetrics 镜像固定为 v1.103.0；`vm_total_disk_space_bytes` 在 v1.124.0 才加入。
- 现有容器资源查询使用九个容器名的静态白名单，六行目标明细表示 Prometheus 抓取端点，并非 Docker 容器清单。

## 影响范围

- Docker Compose 中 vmagent、cAdvisor 的 HTTP 代理环境和 cAdvisor 参数。
- Grafana 平台健康看板生成器及其生成的 JSON。
- Compose/看板契约测试。

## 文件与分工

- Compose 执行者：`docker-compose.yml`、`backend/tests/monitoring/test_monitoring_v1_deployment_contract.py`。
- 看板执行者：`monitoring/grafana/generate_dashboards.py` 及生成器输出的 dashboard JSON。
- 主 Agent：本计划、完成记录；负责验证和集成审查。

## 实施步骤

1. 为 vmagent 和 cAdvisor 清空大小写 HTTP/HTTPS/ALL proxy 环境变量，并列出 Docker 内网服务别名到 NO_PROXY。
2. 从 cAdvisor `--disable_metrics` 列表移除 v0.60.6 不支持的 `accelerator` 项。
3. 保留六个平台指标端点状态表并明确命名；新增动态 Docker 容器采集计数和采集清单；CPU、内存、磁盘查询覆盖所有非空容器名。
4. 将 VictoriaMetrics 存储占用面板改为 v1.103.0 可用的 `vm_data_size_bytes` 数据量，保留现有文件系统剩余空间面板。
5. 运行 dashboard 生成器并审阅完整输出范围，执行受影响的契约验证和 YAML/JSON 静态解析。

## 验证计划

- 确认 Compose YAML 可解析，vmagent/cAdvisor 代理变量被清空，cAdvisor 参数仅使用 v0.60.6 支持项。
- 确认生成器输出的 dashboard JSON 可解析，动态容器查询不含固定容器名白名单，VictoriaMetrics 查询兼容 v1.103.0。
- 不触碰生产 Docker 主机；目标运行时需用户部署后再从 vmagent/cAdvisor 端点确认。

## 风险与回滚

- cAdvisor 能否取得完整宿主资源仍取决于目标主机的 cgroup 与 Docker API 权限；若启动后仍失败，应先看完整首条错误日志。
- v1.103.0 没有 VictoriaMetrics 数据目录所在文件系统总容量指标，因此本次将百分比改为已用数据量；升级 VictoriaMetrics 后可再恢复容量百分比面板。
- 回滚时还原本次 Compose、生成器和 dashboard JSON 变更即可；不涉及迁移或已有数据写入。

- Compose/YAML 解析及 `pytest -q backend/tests/monitoring/test_monitoring_v1_deployment_contract.py` 通过（7 passed）。生成器 Python 编译通过；12 份 dashboard JSON 均可解析，目标 JSON 与生成器输出一致，20 个 panel ID 唯一。
