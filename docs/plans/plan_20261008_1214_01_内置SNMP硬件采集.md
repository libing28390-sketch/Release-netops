# 内置 SNMP 硬件采集实施计划

## 任务目标
复用 LibreNMS 版本化 OS 与硬件规则的发现、归一化模型，由 Nexora 自己使用已保存的设备 SNMP Profile 做硬件发现与周期采样。结果写入现有硬件库存，提供诊断页和 Grafana/VictoriaMetrics 指标。不得要求部署 LibreNMS Docker/Compose，也不对 Ubuntu 或真实设备执行部署、配置变更或采集操作。

## 现状与问题
- AC_11 的基础 SNMP 与系统指标可用，但 Grafana 尚无对应硬件采样，诊断页把“未配置 LibreNMS 实例”当成阻断条件。
- 硬件库存已有发现、样本、能力状态和指标出口；导出查询只包含 `librenms_native` 来源。
- 无线 Grafana 明细最初还限制 `component_class="wireless_sensor"`，会漏掉本地 H3C 适配器使用的 `wireless_controller`、`wireless_radio`、`wireless_bss` 等类别；角色/设备变量也只从 `role="wireless_controller"` 的 SNMP up 指标取值，无法选择角色字段为通用值的本地 AC。
- 仓库包含本地规则解析和 SNMP 探测实现，可在 Nexora 内执行规则；后台原先没有调用该探测器的独立周期任务。
- 用户明确不部署 LibreNMS，只采用其规则/数据模型思路。已有的可选外部集成继续兼容，不作为本地采集前提。

## 影响范围
新增 Nexora 本地 SNMP 发现/轮询调度；将本地结果写入现有库存并导出；无线 Grafana 明细和变量接收本地与兼容的外部来源以及各类无线组件；无绑定、无外部实例时诊断显示本地等待或凭据状态；资产导入和 SNMP Profile 文案说明由 Nexora 采集。后台采集沿用 vault_service 的凭据契约，默认 SNMPv2c；本轮未新增 SNMPv3 支持。服务器资产不进入网络设备硬件采集器。

## 实际涉及文件
- `backend/services/snmp_hardware_probe_service.py`、`backend/services/snmp_hardware_normalization.py`：恢复并复用规则驱动和标准 MIB 采集/归一化实现。
- `backend/services/snmp_hardware_poller_service.py`：新增按需发现、周期采样、凭据和资产筛选。
- `backend/engine/orchestrator.py`、`backend/services/background_monitor_service.py`：注册本地硬件采集循环；普通连通性/接口监控仍走既有周期。
- `backend/services/snmp_hardware_inventory_service.py`：Grafana 硬件指标读取本地 `legacy_snmp` 库存及兼容的 LibreNMS 原生库存。
- `monitoring/grafana/generate_dashboards.py`、`monitoring/grafana/dashboards/nexora-network-wireless.json`：无线采集明细纳入本地来源和全部无线组件类别；模板变量合并外部控制器目标与本地无线硬件目标。
- `backend/services/librenms_diagnostic_service.py`、`backend/services/librenms_enrollment_service.py`、`backend/api/assets.py`：优先读取本地结果，无外部实例时返回本地采集状态。
- `backend/api/devices.py`、`src/components/SnmpMib/`、`src/pages/AssetManagement/`：同步诊断 API/UI 和 Profile/导入说明。
- 对应 SNMP 采集、调度、诊断、导入、指标导出测试及本计划/完成记录。

## 实施步骤
1. 复用本地版本化规则解析、标准 MIB 与 H3C 等 OS 适配探测；只执行代码中受控的 numeric OID/GET/WALK 映射。
2. 从 Nexora 凭据中心读取设备 SNMP 凭据，由后台并发受限的周期调度执行发现和样本轮询；沿用现有可用版本（默认 v2c，未扩展 v3），Discovery/样本沿用现有事务和库存模型。
3. 将本地 `legacy_snmp` 样本纳入 `nexora_hw_*` 指标导出，保留已有 `librenms_native` 兼容路径，并修正无线面板及变量的来源和组件类别筛选。
4. 诊断优先展示 Nexora 本地库存；无采集记录时显示本地待采集或 SNMP 凭据状态，不再强制管理员配置外部 API 地址和 Token。
5. 更新资产导入、SNMP Profile 和页面文案，并用模拟 SNMP/隔离数据库覆盖主要路径。

## 验证计划
- 后端聚焦 pytest：本地规则探测、采集调度、诊断回退、资产导入无实例分支、Grafana 本地来源指标及现有原生来源兼容。
- 前端聚焦 Vitest，并运行 TypeScript lint 和隔离输出目录的生产构建。
- 校验无线 Dashboard 生成结果和查询契约测试。
- 对后端修改运行 PostgreSQL-only policy scanner、Python 编译和 diff whitespace 检查。
- 不访问生产设备、不连接 Ubuntu、不部署或改变 Compose/容器。

## 风险与回滚
上游定义无法映射为受控数值 OID 时，保留 unsupported/partial 状态，不能猜值或据此清理已有库存。若本地轮询影响设备或应用，可停用其调度入口或回滚代码；库存、现有外部集成和容器配置均不需删除或迁移。
