# 实施计划：网络监控一键批量同步主机名

## 任务背景与目标
用户在网络监控页面提出：在已有单台设备【同步主机名】按钮的基础上，**增加一键批量同步主机名的功能**，并且本次任务**先不要推送（先不要 push）**。

## 方案设计

### 1. 后端接口实现 (`POST /api/devices/batch-sync-hostname`)
- **零模板标准协议保证**：严格遵循用户规范，批量同步与单台同步一样，直接基于通用 RFC 1213 MIB-II `sysName.0` (OID: `1.3.6.1.2.1.1.5.0`)，不绑定、不依赖任何厂商指标采集模板，所有网络设备厂商统一处理。
- **并发与受控调用**：
  - 允许传入 `device_ids` 列表，或在未传时自动选取当前在管网络设备集合。
  - 使用 `asyncio.Semaphore` 控制网络并发，避免瞬间大量 UDP 请求拥塞本地管理链路。
  - 针对每台设备解析 IP、凭据库中的 SNMP Community（或默认配置）。
  - 调用 `clean_system_hostname()` 清洗剥离域名前后缀（例如 `.CCIE`）。
- **原子联动与三表更新**：
  - 批量更新 `devices.hostname`、`devices.sys_name`。
  - 联动更新关联资产 `physical_assets.hostname`。
  - 联动更新拓扑发现记录 `topology_observations.source_hostname`。
- **返回结构**：返回总处理数、更新数、未变更数及失败数，方便前端向用户展示清晰的反馈信息。

### 2. 前端界面实现 (`src/components/NetworkMonitoring.tsx`)
- **UI 布局位置**：在左侧设备列表概览栏（“X 台在管网络设备”）右侧提供【批量同步】操作按钮；
- **状态与交互反馈**：
  - 同步中提供转圈动画及“同步中…”状态，并禁用重复点击；
  - 同步完成后弹出友好 Toast 反馈统计（例如：“批量同步完成：已检测 2 台设备，更新 1 台设备名称”）；
  - 自动触发当前设备列表与选中设备数据的即时刷新，保证 UI 界面与后台数据无缝联动。

### 3. 测试与验证计划
1. 后端单元测试与批量同步模拟接口测试。
2. 实机针对真实网络中的 2 台核心交换机执行批量同步验证。
3. 运行前端构建检查 `npm run build`。
4. 严格遵守用户指示：**本次先不执行 git push**。
