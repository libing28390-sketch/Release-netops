# PAM 审批人列表排除申请人计划

## 任务目标

修复 `/api/config-approval/approvers` 将当前申请人本人列为候选审批人的问题；在列表阶段按当前登录用户 ID 排除本人，并保留审批请求创建时已有的自审批拒绝校验。

## 现状与问题

- API 只把申请人租户传入候选人查询，没有传当前申请人 ID。
- 候选人列表依据启用状态、`pam.approve` 权限、租户/全局范围和验证方式筛选，但不排除本人。
- 实际创建审批时会拒绝申请人审批自己的请求，因此 UI 可能显示一个之后一定会失败的选项。
- 工作区已有跨租户审批人改动；本次只增加申请人身份过滤，不回退该行为。

## 影响范围

- 后端候选人列表服务接收申请人稳定 ID，并从结果中排除匹配账号。
- API 从已认证会话传入用户 ID；前端响应格式不变。
- 不修改任何账号权限、邮件配置、审批请求或数据库数据。

## 拟修改文件

- `backend/api/automation.py`
- `backend/services/config_approval_service.py`
- `docs/plans/plan_20261014_2056_01_PAM审批人排除申请人.md`
- 对应的 `docs/walkthrough/` 完成记录

## 实施步骤

1. 在审批人列表 API 中取得已认证会话用户稳定 ID。
2. 在候选人服务中排除与申请人 ID 相同的账号。
3. 保留 `_get_approver_for_request` 和审批消费阶段的自审批校验。
4. 检查本次 diff，确认已有跨租户审批改动未被覆盖。

## 验证计划

- 静态审查 API 身份传递、服务过滤条件和已有发起阶段拒绝校验。
- 本次不运行自动化测试；最终说明这一限制。

## 风险与回滚思路

- 只影响候选列表展示，不改变其他审批资格规则。
- 如需回滚，可移除申请人 ID 参数及列表过滤；发起阶段自审批校验仍然有效。
