# 旧 SSH 算法跨厂商兼容实施计划

## 任务目标

在不改变厂商/平台/命令映射契约的前提下，为 Nexora 纳管旧版网络设备提供可控的 SSH 算法兼容能力，覆盖 Netmiko/Paramiko、Scrapli system/Paramiko、AsyncSSH 及资产连通性验证等连接路径。

## 现状与问题

- 旧设备可能仅提供 `diffie-hellman-group*-sha1`、`ssh-rsa`/`ssh-dss`、AES-CBC、HMAC-SHA1 或更弱算法。
- 当前共享兼容模块已经列出多类 legacy 算法，但 Netmiko 参数未显式表达算法能力，Scrapli 的 Windows Paramiko 路径也未完全复用该策略。
- system SSH 兼容命令把部分旧算法放在现代算法之前，存在不必要降级风险；硬编码客户端未必支持的算法还可能导致 OpenSSH 参数解析失败。

## 影响范围

- 后端通用 SSH 传输与算法策略：`backend/drivers/ssh_compat.py`
- 网络设备 Netmiko 驱动及连接参数：`backend/drivers/netmiko_driver.py`、`backend/engine/drivers/netmiko_driver.py`
- Scrapli 驱动和资产快速连通性验证：`backend/drivers/scrapli_driver.py`、`backend/api/assets.py`
- PAM AsyncSSH 算法策略：`backend/api/pam.py`
- 算法策略及跨厂商回归测试：`backend/tests/`

## 拟修改文件

- 优先修改共享兼容策略和直接使用该策略的连接入口；避免在各厂商 API/service 中散落算法分支。
- 新增或扩展 SSH 兼容单元测试、连接参数契约测试和 vendor-platform-driver 回归测试。
- 不修改真实设备配置，不修改无关的用户未提交文件。

本次实际未新增数据库字段或前端表单；`ssh_algorithm_profile` 作为连接上下文的可选字段传递，缺省为 `auto`。附件中的设备可直接使用默认档案；极老设备可在连接请求中显式指定 `legacy_break_glass`。

## 实施步骤

1. 将算法能力拆分为现代默认、legacy KEX、legacy Host Key、legacy Cipher、legacy MAC 等可组合档案，保留客户端实际支持算法过滤。
2. 默认现代算法优先；仅在明确的协商失败或设备显式选择 legacy 档案时启用旧算法，并拒绝无必要的全局降级。
3. 统一 Netmiko/Paramiko、Scrapli 两种传输和 AsyncSSH 的参数入口；保留主机密钥校验语义，不用算法兼容绕过指纹校验。
4. 对 `group1-sha1`、`ssh-dss`、MD5、RC4、DES、Blowfish 等高风险算法设置受控 break-glass 入口，默认不启用或仅在显式档案中启用。
5. 覆盖 Cisco、Huawei、H3C、Ruijie，并验证 Juniper/Arista 等现代设备仍优先使用现代算法；验证 vendor/platform/Netmiko device_type/命令目录不被改变。

实际实现还将连接池键纳入算法 profile，避免同一地址在切换 profile 后复用旧会话。

## 验证计划

- 运行 SSH 兼容模块及连接参数 focused pytest。
- 使用 mock/fake transport 验证 KEX、Host Key、Cipher、MAC 不匹配的识别、重试和错误码。
- 验证 Windows/非 Windows Scrapli 配置、PAM AsyncSSH 配置及所有主要 Netmiko 入口。
- 按网络驱动门禁运行 Cisco、Huawei、H3C 映射回归；按质量门禁检查安全、敏感信息和现有测试失败。

## 风险与回滚

- 旧算法本身存在降级风险；通过现代优先、按设备档案、显式审计和高风险算法禁用降低风险。
- 连接库版本对可用算法集合不同；策略生成必须过滤未知算法，避免连接命令因不支持的算法名失效。
- 如兼容改造引入回归，可回滚共享策略改动并恢复原连接参数；不触碰设备侧配置，因此无需设备配置回滚。
