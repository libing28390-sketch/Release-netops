# 定时作业新建流程简化

## 任务目标

简化 `/automation/scheduled-jobs` 的新建与编辑操作，修正设备预览数量被截断的问题，并让审批人不可用时的原因可见。

## 现状与问题

- 新建表单把基本信息、执行动作、目标范围、设备预览、CRON 和安全审批放在同一长页面中。
- `GET /api/devices` 在未传分页参数时最多返回 200 条；页面用这份列表计算实时目标数量。IP 搜索走带过滤的另一个请求，所以一个已成功加入 IP 清单的设备可能不在预览用的前 200 条中，造成计数为 0。
- 审批人 API 只返回同租户启用用户中，具备 PAM 审批权限且配置了至少一种 MFA、邮箱或飞书验证方式的人员。前端把接口失败和真实空结果都静默显示为空选择框。
- 浏览器实测选中 `Linux` 脚本和 `ubuntu` 主机后，兼容性提示错误地把设备判为不兼容；页面用平台字符串互相包含来判断，未识别 Linux 发行版属于同一系统家族。

## 影响范围

- 仅影响定时作业新建/编辑表单及其审批人、设备列表加载状态。
- 不调整后端审批权限、审批验证契约或定时作业执行行为。

## 拟修改文件

- `src/pages/ScheduledJobs/index.tsx`
- `src/pages/ScheduledJobs/components/JobModal.tsx`

## 实施步骤

1. 将设备清单读取改成轻量分页并聚合完整结果，使实时匹配基于完整设备集合；区分加载中、加载失败和已加载后的零匹配。
2. 为审批人列表增加加载状态、失败重试和明确的资格条件说明。
3. 将表单整理成“任务与目标 → 调度时间 → 审批并创建”三步流程，提供步骤进度、回退和按步骤校验。
4. 将 Linux 发行版与通用 Linux 脚本归入同一兼容家族，避免 Ubuntu 等主机收到错误的不兼容提示。
5. 保留现有验证码审批及创建/更新清单校验，检查差异和静态类型/构建可行性。

## 验证计划

- 静态审查分页聚合的响应归一化、终止条件和加载状态。
- 静态审查三步前进/回退、每步校验及审批验证后的最终提交条件。
- 浏览器确认总设备数、指定 IP 匹配数、步骤切换、空审批人说明及 Linux 脚本对 Ubuntu 的兼容提示。
- 不访问或修改真实作业、设备或审批配置。

## 风险与回滚思路

- 清单总量较大时分页请求可能增加加载时间；使用 `mode=light` 和固定分页大小控制单次响应体，并按 API 的总数终止。
- 步骤 UI 调整可能影响原有表单交互；回滚时可仅还原上述两个前端文件，不涉及数据迁移或后端状态。
