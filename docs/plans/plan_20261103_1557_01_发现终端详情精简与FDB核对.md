# 发现终端详情精简与FDB核对

## 目标和现状

用户要求详情仅保留关键信息，列表IP/MAC分列，并继续核对端口缺失原因。当前详情包含投影、源版本、校验、重复历史等诊断内容；定位缺失尚需设备CLI只读MAC表和SNMP结果对照。

## 实施范围与步骤

- DiscoveredEndpointsTab.tsx：IP/MAC独立列，空行colSpan同步；详情只保留IP、MAC、VLAN、来源设备、实际接入设备/端口、上一次时间。移除历史技术明细显示，原始证据保留在后端。
- 更新前端断言，执行聚焦测试、TypeScript检查、隔离构建和浏览器走查。
- 使用已有保管凭据，只读检查S6850-5/6的display mac-address/display arp并对照SNMP；不配置设备、不制造业务流量，不改变证据匹配安全条件。

## 风险与回滚

补充诊断：两台设备实时MAC表为空且老化时间300秒，ARP仍在。对S6850-5下的172.16.5.10发起2次诊断ICMP后立即读取SNMP FDB，验证动态学习；不改配置，不写业务源表。

仅精简展示，不删除历史数据。诊断与实际采集协议分开，正式全量采集仍SNMP-only。恢复页面布局即可回滚。
