# 互联网出口健康检测 V1 生产级实施计划

## 1. 目标与边界

建设一个可用于生产排障的“互联网出口健康检测”模块，而不是只执行定时 `socket.connect()` 的端口测试。

V1 默认检测 **Nexora 后端所在服务器的互联网出口**。界面必须明确标注“平台服务器出口”，不能把服务器出口结果误认为分公司、VLAN 或防火墙 WAN 线路状态。数据模型预留 `probe_node_id`、`probe_node_name`、`source_ip`，为后续 Agent 多探测节点扩展。

V1 覆盖：多目标分组探测、目标级结果、聚合状态、连续失败/恢复判定、国内/国际/DNS/HTTPS 视图、NAT IP 独立识别、目标管理、SSRF 防护、手动检测、历史趋势和审计。ICMP 作为可选探测类型，不作为 V1 核心依赖。

## 2. 必须遵守的业务规则

### 2.1 聚合状态与防抖

状态枚举固定为：`healthy`、`degraded`、`unavailable`、`unknown`。

对于启用的 4 个目标，默认聚合规则为：

| 成功目标 | 聚合状态 |
| --- | --- |
| 4/4 | `healthy` |
| 2/4 或 3/4 | `degraded` |
| 0/4 或所有有效分组均不可用 | `unavailable` |
| 没有目标、没有有效样本或样本过期 | `unknown` |

单次失败不能直接改变出口状态：连续失败 3 次才确认异常，连续恢复 2 次才确认恢复。状态卡同时展示当前连续失败次数、状态原因和样本新鲜度。

### 2.2 目标分组

目标必须支持 `domestic`、`international`、`dns`、`web`、`business` 等分组。默认种子目标至少包含：国内 DNS、国际 DNS、国内 HTTPS、国际 HTTPS；默认目标故障不能被单一站点故障放大为“出口中断”。

前端按分组展示：国内出口、国际出口、DNS 服务、业务站点，并同时给出总状态。

### 2.3 探测类型

目标模型预留并实现以下类型：

- `TCP_CONNECT`：验证 TCP 建连和建连耗时。
- `HTTP_GET` / `HTTPS_GET`：验证响应状态、TLS 和可选关键字。
- `DNS_RESOLVE`：验证 DNS 解析是否成功及解析结果。
- `ICMP_PING`：可选，运行环境支持时启用。

错误类型统一为 `DNS_FAILED`、`CONNECT_TIMEOUT`、`CONNECTION_REFUSED`、`NETWORK_UNREACHABLE`、`TLS_FAILED`、`HTTP_STATUS_ERROR`、`UNKNOWN`，不得只返回布尔值。

### 2.4 公网 NAT IP 独立检测

公网 IP 识别与目标拨测解耦：目标拨测每分钟执行；公网 IP 每 5 分钟执行一次，或出口异常时立即执行。至少使用两个独立来源：两者一致才确认公网 IP；不一致时标记 IP 识别异常，但不影响出口连通状态。

记录 IP 变化事件，包括发生时间、旧 IP、新 IP、来源结果和一致性状态。

## 3. 数据模型与迁移计划

当前简化的 `outbound_probe_targets` / `outbound_probe_samples` 只能保存汇总结果，不能作为最终模型。迁移必须保留已有安装的兼容性：若版本 24 尚未在部署环境执行，则修正 `m0024`；若已经执行，则新增后续迁移，不得修改已执行迁移的语义。

### 3.1 目标配置表

`outbound_probe_targets` 至少包含：

`id`、`target_name`、`group_name`、`probe_type`、`host`、`port`、`url`、`expected_status_code`、`expected_keyword`、`timeout_ms`、`enabled`、`created_at`、`updated_at`。

目标必须有唯一名称、合法端口和受限超时范围；不得通过前端自由拼接 SQL 或未经校验地保存 URL。

### 3.2 探测节点表

新增 `outbound_probe_nodes`，记录节点名称、节点类型、来源 IP、启用状态和最近心跳。V1 自动创建一个 `platform-server` 节点，并在所有状态和历史查询中带出节点信息。

### 3.3 运行汇总与目标级结果

建议拆为：

- `outbound_probe_runs`：一次完整运行的开始/结束时间、节点、状态、状态原因、成功数、目标总数、可用率、平均延迟、连续失败/恢复计数和公网 IP 快照。
- `outbound_probe_results`：每个目标的成功与否、延迟、错误类型、脱敏错误信息、解析 IP、HTTP 状态码、采样时间和运行 ID。
- `outbound_egress_ip_events`：公网 IP 变化和双来源一致性事件。

原有汇总表如需保留，应作为兼容视图或兼容写入，不得继续承担目标级明细职责。索引至少覆盖 `(node_id, sampled_at)`、`(target_id, sampled_at)` 和状态查询使用的时间字段。原始样本按 `TELEMETRY_RAW_RETENTION_HOURS` 清理，默认 48 小时。

## 4. 后端探测引擎

实施文件主要包括：[outbound_probe_service.py](E:/data/netsops/backend/services/outbound_probe_service.py)、[m0024_outbound_probes.py](E:/data/netsops/backend/database/migrations/m0024_outbound_probes.py)、[monitoring.py](E:/data/netsops/backend/api/monitoring.py) 和 [main.py](E:/data/netsops/backend/main.py)。

探测执行器按 `probe_type` 分派，目标之间并发但限制最大并发数；每个目标单独捕获超时、拒绝、不可达、TLS、DNS 和 HTTP 错误。网络调用必须有上限，不能因为单个目标阻塞整个调度任务。

状态聚合、连续失败/恢复计数和分组状态必须放在 service 层，路由只负责参数校验、权限、状态码和响应契约。手动触发不得直接在 async 路由中执行阻塞网络操作，应使用现有线程池/后台任务机制，并通过运行锁防止重复执行。

## 5. SSRF、权限与审计

这是目标 CRUD 上线前的阻断项。

- 默认拒绝 `localhost`、回环地址、链路本地地址、未指定地址、组播地址和解析后落入内网的地址。
- 至少拦截 `127.0.0.0/8`、`169.254.0.0/16`、`0.0.0.0/8`、`224.0.0.0/4`；RFC1918 私网默认拒绝，企业内网探测通过显式配置的允许网段开启。
- DNS 名称解析后必须校验所有 A/AAAA 结果，防止 DNS rebinding；HTTP 重定向也必须重新校验目标地址。
- 限制 URL scheme、主机名长度、端口范围、超时范围、关键字长度和单次目标数量。
- 目标新增/修改/删除以及手动触发要求运维或管理员权限；手动触发增加 5～10 秒限流、运行锁和审计日志。
- 日志和接口响应不得泄露内部解析细节、凭据或完整异常堆栈；对外只返回标准化错误类型和安全摘要。

## 6. API 契约

使用 Pydantic 请求/响应模型，不再使用无类型的 `request.json()` 作为稳定契约。保留现有 API 路径兼容性，但升级返回内容。

- `GET /api/monitoring/outbound-status`：返回当前总状态、各分组状态、状态原因、成功数、可用率、平均延迟、NAT IP、IP 变化标记、连续失败计数、检查时间、样本新鲜度、历史趋势和目标级结果。
- `GET /api/monitoring/outbound-targets`：分页或有限量返回目标配置，不返回不必要的内部解析信息。
- `POST/PATCH/DELETE /api/monitoring/outbound-targets`：完成权限、字段、SSRF、唯一性和启用状态校验，并写审计事件。
- `POST /api/monitoring/outbound-trigger`：执行一次受保护的手动检测，返回同一状态模型；重复触发返回明确的限流或运行中错误。
- 如前端需要单独查看 IP 变化，增加 `GET /api/monitoring/outbound-egress-events`。

核心响应必须符合以下语义：`status`、`status_reason`、`success_count`、`total_count`、`availability_percent`、`average_latency_ms`、`public_ip`、`public_ip_changed`、`consecutive_failure_count`、`checked_at`、`targets[]`。目标项必须带 `name`、`group`、`success`、`latency_ms` 和 `error_type`。

## 7. 调度与数据生命周期

在 [main.py](E:/data/netsops/backend/main.py) 注册目标拨测、NAT IP 检测和过期清理任务：

- 目标拨测：默认每分钟一次；使用现有跨实例调度锁，设置 `max_instances=1`、合理 misfire 行为和超时保护。
- NAT IP：默认每 5 分钟一次；检测到出口异常时允许一次受控的即时补测。
- 清理：删除超过 48 小时的原始运行和目标级结果，并保留必要的 IP 变化事件。
- 任务失败不能让 scheduler 停止；每次运行记录失败原因和耗时，便于诊断调度阻塞。

## 8. 前端实施

在 [MonitoringCenter.tsx](E:/data/netsops/src/components/MonitoringCenter.tsx) 增加入口，但将请求、状态和目标 CRUD 拆到监控域 hook/store，避免继续扩大单文件职责。

状态卡展示：

```text
互联网出口（平台服务器）
正常 / 降级 / 中断 / 未知
可用率、平均时延、公网 IP、最后检测时间
```

详情 Modal 展示：

- 总状态与状态原因。
- 国内、国际、DNS、业务分组状态。
- 每个目标的成功、延迟、错误类型和解析结果摘要。
- 左轴毫秒时延、右轴百分比可用率的 24 小时趋势图。
- 异常时间段背景、IP 变化事件标记和悬停明细。
- 手动检测按钮的加载、限流、运行中、成功和失败状态。
- 目标 CRUD：分组、探测类型、地址、端口/URL、预期状态码、关键字、超时、启用状态。

必须处理加载、空目标、样本过期、接口失败、权限不足、窄屏和中英文文案。

## 9. 分阶段实施顺序

### Phase 0：基线与契约冻结

审查当前未提交的出口拨测代码，只将其作为脚手架；不把现有简化表结构或“每分钟同时查 NAT IP”的逻辑视为完成。先冻结状态枚举、目标类型、错误类型、API JSON 和迁移兼容策略。

### Phase 1：数据库与领域模型

完成节点、目标、运行、目标结果和 IP 事件表；补齐索引、默认目标分组、迁移幂等性和旧版本升级路径。完成 fresh schema 与上一版本升级验证。

### Phase 2：探测引擎与状态机

实现 TCP/HTTP/HTTPS/DNS 探测器、错误分类、并发限制、目标级落库、分组聚合、四态状态机、连续失败/恢复防抖和样本过期判定。独立实现 NAT IP 双来源检测与变化事件。

### Phase 3：API、安全与调度

使用 Pydantic 契约重做查询、目标 CRUD 和手动触发；接入 RBAC、SSRF 防护、限流、运行锁、审计日志；在 APScheduler 中拆分目标拨测与 NAT IP 任务。

### Phase 4：前端闭环

增加出口状态卡、详情 Modal、分组状态、双 Y 轴趋势、目标级错误明细、IP 变化事件、目标 CRUD 和手动检测交互。

### Phase 5：质量门禁与上线

先跑后端单测和迁移测试，再跑完整 `pytest backend/tests`、`npm run lint`、`npm run build`；最后用模拟目标验证超时、拒绝、DNS 失败、TLS 失败、部分失败、全部失败、恢复、SSRF 拦截和重复触发。

## 10. 验收标准

1. 4 个目标全部成功显示 `healthy`；2/4 或 3/4 显示 `degraded`；连续 3 次全失败后才显示 `unavailable`；连续 2 次恢复后才恢复健康。
2. 国内、国际、DNS、HTTPS/业务分组可独立判断，单一目标故障不会误判全局出口。
3. TCP、HTTPS、DNS 的成功和失败均能产生目标级结果与标准错误类型。
4. NAT IP 查询不影响出口连通状态；双来源不一致会产生 IP 识别异常；公网 IP 变化可追溯。
5. 目标 CRUD 能阻断回环、链路本地、组播、未指定和未授权内网地址；DNS rebinding 与 HTTP 重定向也不能绕过校验。
6. 手动触发具备角色校验、5～10 秒限流、运行锁和审计记录。
7. 状态接口返回稳定的四态模型，24 小时图表能同时显示毫秒时延和百分比可用率，样本过期时显示 `unknown` 或明确的 stale 状态。
8. PostgreSQL 迁移可幂等执行，历史数据按 48 小时清理，调度任务不会重复并发运行。
9. 后端、前端和安全测试全部通过，且不依赖真实公网或生产数据库才能完成 CI 验证。

## 11. 不纳入本期的内容

多分支 Agent 探测节点、复杂线路归因、Traceroute 路径分析和完整国际网络质量评分不纳入 V1 实现，但通过节点字段、来源 IP、分组和错误模型保留扩展空间。
