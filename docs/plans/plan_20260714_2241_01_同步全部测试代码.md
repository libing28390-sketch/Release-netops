# 实施计划 - 同步全部测试代码

## 任务目标
移除 `.gitignore` 对 `backend/tests/test_*.py` 的忽略限制，以确保 `backend/tests/` 目录下的所有测试代码都能够被追踪并成功推送到公有仓库。

## 现状/问题
当前 [.gitignore](file:///d:/netops/netsops-main/.gitignore) 中第 44-47 行忽略了绝大多数测试文件：
```git
backend/tests/test_*.py
!backend/tests/test_ssh_compat_paging.py
!backend/tests/test_database_reset.py
!backend/tests/test_asset_production_takeover.py
```
这导致最近新增的 9 个测试文件无法通过 `git push` 推送到远程仓库。

## 拟修改文件
- [.gitignore](file:///d:/netops/netsops-main/.gitignore)

## 实施步骤
1. 修改 [.gitignore](file:///d:/netops/netsops-main/.gitignore)，移除上述第 44-47 行的忽略规则，释放对测试文件的追踪限制。
2. 在 `docs/fixes/` 目录下创建规范要求的提交修复记录文件 `fix_20260714_2241_01_同步全部测试代码.md`。
3. 执行 `git add .` 将 `.gitignore`、所有原本被忽略的测试文件以及修复记录文件加入 Git 追踪暂存区。
4. 执行本地提交 `git commit -m "feat: track and push all test files under backend/tests"`。
5. 推送代码至远程仓库 `git push origin main`。
6. 创建完成验证报告 `docs/walkthrough/walkthrough_20260714_2241_01_同步全部测试代码.md`。

## 验证计划
- 运行 `git status` 确认没有遗留的测试代码在未追踪或已忽略状态。
- 检查远程仓库是否已成功包含这 9 个测试文件。

## 风险与回滚思路
- **风险**：若存在个别敏感的本地临时测试文件（如包含硬编码凭据等）被误提交。
- **回滚**：如果发现有敏感文件被误提交，可以使用 `git rm --cached <path>` 将其从 Git 追踪中剔除，并重新推送到远程。
