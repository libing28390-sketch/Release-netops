# API 请求阻塞与连接复用

## 目标与现状

用户提供的 5 分钟日志显示 Nginx 未出现 CPU/内存限额压力，后端多个接口出现秒级 Handler 延迟，轻量 live 接口也受影响。代码已确认异步调度锁和请求日志鉴权直接执行同步 PostgreSQL 调用；资源接口直接采样、写库及通知，并在告警事务提交前等待外部通知。连接池仅保留 2 个空闲连接，会在并发请求后重复建连。

本次完成工作区的后端改动和定向验证。用户随后授权提交并 push 相关代码、检查 Actions、在 Docker 部署主机自主部署验证；真实网络设备配置仍不在本次范围内。

用户随后明确“先不要改worker数量”。本轮保持 `WORKERS=1`，不实现多进程后台 leader、共享验证码存储或其他架构改动；2-worker 讨论仅作只读检查，不进入本次差异。

## 影响范围与文件边界

- 主 Agent：`backend/main.py`、`backend/database/core.py`、`.env.example`、`docker-compose.yml`，相关新测试，以及统一计划与走查。
- 后端执行者：`backend/api/health.py` 和新建 `backend/tests/monitoring/test_health_resource_execution.py`，负责资源请求与告警事务。
- 调度实现由主 Agent 负责：`backend/core/scheduler_lock.py` 和 `backend/tests/database/test_scheduler_lock_leases.py`。
- 主 Agent 同时负责 `backend/services/notification_service.py` 与通知连接生命周期测试：通知服务自身也在读取配置后的外部发送期间持有连接，需先加载邮件配置再释放连接。
- 保留无线 Grafana、资产首页及诊断脚本等所有既有未提交变更。
- 用户补充数据库扫描与 Nginx 对话后，增加明确阻塞路径修复：后端执行者仅修改 `backend/engine/orchestrator.py` 和新测试 `backend/tests/monitoring/test_telemetry_orchestrator_execution.py`，将 A/B-loop 数据库快照读取和 B-loop 遥测维护移入线程；保留设备协程、轮数、顺序、LLDP 告警共享状态和 SSH 池清理行为。

## 实施步骤

1. 同步调度锁 acquire/release 在异步包装器内转移到线程执行，处理任务取消时租约释放，保留 owner fencing 和 heartbeat。
2. 健康信息的同步数据库和资源操作移出事件循环；HTTP 资源读取不触发外部通知，后台采样保持告警同步；告警事务提交并归还连接后才执行通知。
3. 请求日志中间件的同步会话查询移到线程；不改变鉴权、会话撤销和 RBAC 语义。
   通知服务所有目标与邮件配置在短数据库读取阶段完成，连接归还后执行 webhook/SMTP，保留原通道筛选、语言及返回结果。
4. 使用有界可配置的空闲连接保留量减少重复建连，保持 overflow 与连接获取超时限制；保持 Nginx 配额和 Uvicorn worker 数量。
5. 以可控慢操作验证并发请求仍可前进，验证告警事务及通知顺序、租约取消清理、连接复用与 rollback。
6. 根据只读证据审查补充 A/B 采集循环中的阻塞 I/O 隔离。以线程门控证明慢数据库快照和第 12 轮同步维护期间事件循环仍可推进；不引入增量 rollup 数据模型或 MIB 索引迁移，先获取实际 SQL 耗时与迟到样本规则。

## 验证计划

- 先运行调度锁、资源告警、请求中间件和 PostgreSQL 连接池的针对性 pytest。
- 使用隔离的本地临时 PostgreSQL 数据库，不向部署主机或业务数据库写入。
- 共享数据库/鉴权路径改动后执行 `pytest backend/tests` 全量门禁与 `scripts/validate_postgresql_only.py`。
- 采集循环补充修复另跑最终代码的线程执行测试；现有角色采集周期、接口遥测契约由正在进行的完整回归覆盖，业务函数未改，不重复跑同一契约。在已启动完整回归的快照与后来局部修正之间准确记录验证范围。
- 检查改动差异、Compose/YAML 及 Python 解析，避免敏感数据和跨文件冲突。
- 线上性能改善需部署后用相同 5 分钟采样复核；若 p95 或超时仍存在，保留周期簇证据并继续追踪剩余同步调用/连接池等待，不能仅凭部署成功宣称卡顿已解决。
- 用户强调本机 Windows 无 Docker，提供 `scripts/diagnostics/collect_nexora_container_review.sh` 与实际 Linux 主机执行命令，采集真实配置、数据库增量及请求耗时；不以本地 pytest 或语法检查替代容器确认。

## 风险与回滚

线程执行的同步任务不能被强制取消，调度取消必须等待 acquire 结果并释放所得租约；告警发送后移可能在提交后进程退出时错过即时发送，维持当前通知系统能力，不引入新队列架构。增加保留连接会增加固定数据库连接数，配置受池上限约束，并记录每进程的连接预算。回滚仅撤销本次文件差异，保留用户既有改动；不进行数据库迁移。
