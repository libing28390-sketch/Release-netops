# 任务目标
解决网段列表“地址空间”和图标操作难懂，以及“自动分类”“待确认”统计重叠造成的误导。用户随后补充接口导入弹窗实际逻辑问题，因此本轮同时核对候选来源、真实网段及已存在资源的预览。

## 已核实现状
- 浏览器当前 WH-DC-01 中21条系统分类网段同时属于network_type=unclassified，已确认Global。classification_status=auto是判定方式，unclassified是用途状态，二者可重叠；当前并列卡片/通用“待确认”文案混淆维度。
- 网段行默认显示迁移地址空间、地址池、编辑、删除四个图标，日常“管理IP”和“确认用途”不突出。
- generate_interface_prefixes生成网段同时登记设备接口IP；ARP/ND/FDB终端来源为独立链路，主机登记需显式确认。

## 文件、分工与影响范围
- 前端子Agent：src/pages/IPVlan/PrefixManagementTab.tsx、对应test；必要时新增本地展示helper/test。保留前两轮变更，主Agent不同时写该文件。
- 主Agent：统一方案、流程说明、浏览器验收、验证记录和最终审查；导入只读预览由后端子Agent负责，数据库schema和业务数据不变。
- 新增后端子Agent：仅 backend/services/ipam_service.py、backend/api/ipam.py 与专用pytest；增加不写库的所选候选导入预览，按明确空间/CIDR聚合、查询已有Prefix与IP，保留原candidate_ids作为生成身份。
- 前端子Agent完成主列表后交回文件，主Agent接手导入弹窗，彼此不同时写同一文件。

## 方案与步骤
1. 列表明确分开用途状态、用途判定方式、网络归属；不把不同维度的统计当互斥状态。
2. “待确认”改为“用途未确定”；自动/人工移至独立的判定方式区域，解释可重叠。
3. 网络归属明确显示全局（无VRF）或具体VRF，待确定归属使用不同完整名称。
4. 行内只保留一个“管理”入口；IP 管理、网段编辑、归属确认/迁移、地址池和删除放入可访问的菜单，删除仍需确认。
5. 页面提供简短流程提示：接口采集→导入网段及接口IP→确认用途→管理IP；终端来源按需登记。
6. 导入前用后端只读预览区分“接口来源条目”与“实际网段”；同空间同CIDR两端聚合展示，新建/已存在/待确认由目标空间和当前正式数据确定，不用原始scope_pending计数冒充导入结果。
7. 已登记的接口IP只能在稳定source_ref、设备、接口、IP、CIDR、tenant/site等精确且唯一匹配时，复用该条IP的正式归属用于候选展示；不因此创建或猜测设备路由上下文映射。

## 验证
定向Vitest（统计维度重叠、归属文案、列表/树操作、确认删除仍有效）、TypeScript、独立构建；浏览器只操作筛选和打开/关闭弹窗，不更改业务数据。相关skill：netops-frontend、netops-quality-gate。

## 风险与回滚
不自动填写用途、迁移空间或写设备；新预览接口只读，原生成与权限契约保留。保留当前筛选含义与结果数量。后端持久化相关测试用隔离PostgreSQL，增加scanner。回滚只撤回本轮差异，保留之前已验证的批量归属与登记修复。

## 用户追加要求：终端采集按角色收窄

- 终端 ARP 周期采集仅纳入明确标注的接入交换机和 AP。优先采用 physical_assets.device_role，缺省时才采用 devices.role；只接受 canonical access/AP 及已知精确别名，不从型号、平台、主机名或通用 switch 推断。
- 只改终端采集入口与终端列表投影，不影响 IP 定位实时查找、路由/核心设备 ARP 线索、IPAM 对账证据及 FDB/拓扑上下文。已有非接入观察保留在底层存储供其他链路使用，但终端台账视图不再展示。
- 不清理既有数据，也不触发设备配置变更；回滚删除筛选即可恢复以前终端来源范围。
- 网段候选按接口实际前缀长度/掩码计算网络；环回口只在采集结果缺少前缀时以明确接口名回退到 /32 或 /128。统一环回识别规则，避免把普通 `lo...` 接口名误判成 Loopback。
- 当前 IP 观察的 Global 地址空间：SNMPv2c 使用默认表且设备没有已配置 VRF/未知上下文时标为 Global；只在租户下唯一活动 Global 空间时自动映射。若多个 Global 空间并存，则保持待确认。已映射地址空间时，按同空间、含该 IP、最具体且唯一的 Prefix 自动预选。
- 终端观察去重：同一站点/租户、IP、MAC、VLAN 的跨设备/跨上下文观察按观测时间取最新；时间相同的多个上下文保留待核，不清理底层历史。被较新样本覆盖的旧观察不能再发起 IPAM 登记。
- 终端台账默认排除 `infrastructure` 分类（CMDB管理地址/接口IP/虚拟网关）；保留“全部判定”和“基础设施地址”筛选用于排查。直接登记 API 也拒绝把已命中的设备基础设施地址当作终端 IP。

## 用户追加要求：网关设备关联与行操作收敛

- 新增/编辑网段时，接口快照中的地址只能作为候选；仅当当前前缀地址空间明确，且同一地址空间内只有一个设备接口候选时，才自动关联网关设备/接口。
- 候选归属未映射或存在多个候选时不得猜测；提示要区分“没有候选”“归属未确认”“候选冲突”，并允许从候选设备快速手动选择。
- 网关设备与“默认网关 IP”继续分开：自动关联设备不自动填写可分配地址排除用的网关 IP。
- 行内只保留一个“管理”入口；将 IP 管理、网段编辑、归属确认/迁移、地址池和删除放入菜单。“设置用途”和“完整编辑”合并为同一个“编辑网段”入口，删除操作仍需现有确认。
- 接口候选弹窗在服务端完成关键词过滤，再按筛选结果计算页数；支持 CIDR、IP、设备、接口、站点和路由上下文关键词，不在前端下载全部候选后本地筛选。
- 导入核对弹窗增加分组搜索和分页，只渲染当前页；导入统计仍基于全部已选候选，不受展示筛选影响。
- 本次改动 `src/pages/IPVlan/PrefixManagementTab.tsx`、`src/pages/IPVlan/prefixGatewayBinding.ts`、`src/pages/IPVlan/InterfaceImportReview.tsx`、`backend/api/ipam.py`、`backend/services/ipam_service.py` 及对应既有前端断言；不改变地址空间映射规则、接口快照或数据库数据。
