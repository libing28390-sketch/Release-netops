# Action 测试失败处理计划

## 任务目标

修复 GitHub Actions 中发现的测试失败，推送修复，并在发布门禁通过后将 `v1.0.9` 指向修复后的提交。

## 现状与问题

- 初始附件报告了两个失败：Grafana 看板字段断言，以及 CMDB 接口别名测试的 PostgreSQL 表缺少新字段。
- CMDB 测试夹具已在提交 `1ec434f2` 修正。用户授权推送后，GitHub Actions run `#605`（该提交）显示 CMDB 测试通过，剩余 1 个失败、2308 个通过、1 个跳过。
- 调查确认看板测试不只检查设备清单 panel 8；它还遍历设备、接口和出口看板中使用 `group_left(ifName, ifAlias)` 的表格。接口看板 panel 6、9、12 的生成器定义和 JSON 漏掉 `excludeByName.ifDescr = true`。
- 远端已有 `v1.0.9` 指向旧发布提交。用户明确要求打上该版本，因此发布时需要把此现有 tag 更新到修复后的提交；tag 工作流还会执行正式发布门禁和公开发布步骤。

## 影响范围与拟修改文件

- `monitoring/grafana/generate_dashboards.py`：补齐三个接口表格的隐藏字段配置。
- `monitoring/grafana/dashboards/nexora-network-interface.json`：同步生成器产物。
- 对应的 `docs/plans/`、`docs/walkthrough/` 与 `docs/fixes/` 记录。
- 此前 CMDB 夹具修复已提交，不再改动。

## 实施步骤

1. 核对 Actions `#605` 的准确失败位置，定位所有满足测试条件的接口面板。
2. 在生成器中修正三个漏配面板并重新生成接口看板 JSON。
3. 运行与断言等价的只读 JSON 检查及差异检查，提交并推送修复。
4. 等待 `main` 的 GitHub Actions 门禁结果；通过后将远端 `v1.0.9` 更新到该提交并等待 tag 发布工作流完成。

## 分工与文件边界

- 主 Agent 负责根因分析、生成器和 JSON 集成、文档、验证、提交、推送与版本 tag。
- 不使用并行执行者；生成器与产物由同一执行者协调。

## 验证计划

- 对设备、接口和出口看板中匹配表达式且包含 organize transformation 的每个面板，检查 `renameByName.ifAlias` 和 `excludeByName.ifDescr`。
- 用生成器重建接口看板，并确认差异只包含三处所需字段。
- 运行 `git diff --check`。
- 由已授权推送触发 GitHub Actions 全量 pytest；若 `main` 门禁通过，再验证 `v1.0.9` tag 发布工作流结果。
- 不在本地额外运行 pytest；本地复核采用与失败断言等价的 JSON 静态检查。

## 风险与回滚

修复仅在三张 Grafana 表格中隐藏已由 PromQL 替换掉的 `ifDescr` 字段，不改变指标查询或数据库。回滚代码可还原生成器与接口 JSON 对应的三处字段。更新已有版本 tag 会触发正式发布流程，按用户明确的 `v1.0.9` 指令执行。
