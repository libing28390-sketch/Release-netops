# 实施计划 - 修复左侧栏折叠报表空白、Grafana大盘全量统计及H3C接口状态

## 任务目标
修复用户提出的三个关键问题：
1. **左侧栏子菜单折叠导航消失**：点击监控报表三项子菜单（全网接口流量与利用率、网络设备运行与资源、互联网出口与 WAN 链路）后，整个左侧导航栏消失（ModuleSubNav 返回 null），刷新后依然空白。
2. **Grafana 大盘数据读取不准**：在「01 网络总览」等 Dashboard 中，「监控站点数」和「纳管设备数」未显示全量数据，只显示 1 个，且变量联动下拉过滤导致设备列表缺失。
3. **H3C 接口状态显示 UNKNOWN**：在监控报表表格中，H3C 设备（如 F1090-10、S6850 等）部分/闲置/二层端口状态显示为 `UNKNOWN`，而非 `DOWN`。

## 现状与根因分析
1. **左侧栏空白根因**：
   - `ModuleSubNav.tsx` 中的 `checkChildActive(child, pathname)` 仅判断顶级菜单自身 `path` 与 `activeMatch`，未递归检查 `child.children`。
   - 当用户点击子菜单 `/monitor/reports/devices` 或 `/monitor/reports/outbound` 时，`navConfig.find(group => group.children.some(...))` 全部返回 false，导致 `currentGroup` 为 `undefined`。
   - `ModuleSubNav` 执行 `if (!currentGroup) return null;`，导致整个左侧栏彻底卸载消失。
2. **Grafana 大盘数据不准根因**：
   - 「纳管设备数」使用了 `count(count by (hostname) (ifOperStatus{hostname=~"$device",...}))`，当默认选中单台设备或缺少 label 时只统计被过滤的设备；且依赖于 `ifOperStatus`，若设备仅存活 (`up`) 但未采集到 ifOperStatus 则不计入。
   - 「监控站点数」使用了 `count(count by (site_name) (ifOperStatus))`，受限于单一指标并过滤掉了空或无此指标的站点。
   - 模板变量使用了 `label_values(ifOperStatus, ...)`，导致未采集 ifOperStatus 的设备与站点无法在下拉菜单中出现。
3. **H3C 接口 UNKNOWN 根因**：
   - H3C Comware 设备的 `display interface brief` 中，二层桥接模式端口（Bridge Mode）仅有 `LINK` 字段（`DOWN`/`UP`），无 `PROTOCOL` 字段；三层路由模式闲置端口 `PROTOCOL` 显示为 `--`。
   - `interface_collection_service.py` 将 `PROTOCOL` 解析为 `oper_status`，遇 `--` 或空值归一化为 `unknown`，忽略了物理 `LINK` 状态已为 `DOWN` 的事实。
   - `monitoring_export_service.py` 导出报表直接使用数据库中的 `unknown`，未根据 `admin_status`（DOWN）做兜底推导，也未在有 VictoriaMetrics `ifOperStatus` 遥测时动态兜底。

## 影响范围
- 前端导航组件：`src/components/ModuleSubNav.tsx`, `src/components/AppSidebar/navConfig.ts`
- Grafana 大盘定义与生成脚本：`monitoring/grafana/generate_dashboards.py`, `monitoring/grafana/dashboards/*.json`
- 后端接口状态解析与报表服务：`backend/services/interface_collection_service.py`, `backend/services/normalizers/h3c.py`, `backend/services/monitoring_export_service.py`
- 数据库已有数据：`interfaces` 表中 `unknown` 状态的修复

## 实施步骤
1. **修复前端左侧栏与折叠导航**：
   - 修改 `src/components/ModuleSubNav.tsx` 中的 `checkChildActive`，支持递归扫描 `child.children`。
   - 在 `src/components/AppSidebar/navConfig.ts` 中恢复 `monitoring-reports` 的 `activeMatch: '/monitor/reports'`，子菜单 `reports-interfaces` 配置 `activeMatch: '/monitor/reports/interfaces,/monitor/reports'`。
2. **优化 Grafana 大盘统计与全量变量查询**：
   - 修改 `monitoring/grafana/generate_dashboards.py`：
     - 将网络总览「纳管设备数」指标调整为全网设备统计 `count(count by (instance) (ifOperStatus or up{job="network_snmp"} or {job=~".*snmp.*"}))`。
     - 将网络总览「监控站点数」指标调整为全量站点统计 `count(count by (site_name) (ifOperStatus{site_name!=""} or up{site_name!=""} or {site_name!=""}))`。
     - 将各 Dashboard 的变量查询由限定 `ifOperStatus` 优化为全局 `label_values(site_name)` 与 `label_values(hostname)`。
     - 重新生成全部 7 个 Grafana Dashboard JSON 文件。
3. **修复 H3C 接口状态解析与兜底推导**：
   - 在 `backend/services/interface_collection_service.py` 中：
     - `_normalize_status` 将 `--`、`-`、`*down` 归一化为 `down`。
     - `_status_record` 中增加兜底逻辑：若 `oper_norm == 'unknown'` 且 `admin_norm in ('up', 'down')`，直接使用 `admin_norm`；若 `admin_norm == 'down'` 则 `oper_norm` 必为 `down`。
   - 在 `backend/services/normalizers/h3c.py` 中：
     - 增加对 TextFSM `LINK` 和 `PROTOCOL` 字段的别名支持。
   - 在 `backend/services/monitoring_export_service.py` 中：
     - 当 `oper == 'UNKNOWN'` 时，若 `admin in ('DOWN', 'ADM', 'ADMINISTRATIVELY DOWN')`，推导为 `DOWN`；若 `admin == 'UP'`，推导为 `UP`。
     - 引入 VM `ifOperStatus` 瞬时指标查表兜底。
4. **数据库历史数据修补**：
   - 对数据库 `interfaces` 中残留的 `unknown` 状态记录进行按需纠正。
5. **验证与质量门禁**：
   - 运行前端单元测试与构建 `npm run build`。
   - 运行后端监控报表单测 `pytest`。
   - 编写 `docs/fixes/` 与 `docs/walkthrough/` 交付文档。
   - 执行 `git commit` 并 push 到远端仓库。

## 风险与回滚思路
- 前端递归函数有退出基条件，无无限循环风险。
- Grafana PromQL 采用 `or` 连接，兼容单一 metric 或全量 metric 场景。
- 若有任何异常，可通过 Git 提交历史单点回滚。
