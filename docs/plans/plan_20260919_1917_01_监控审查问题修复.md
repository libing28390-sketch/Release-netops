# 监控审查问题修复计划

## 任务目标

根据《Release-netops 监控代码审查》修复数据可信度、租户权限隔离、告警生命周期和前端一致性问题，在 PostgreSQL 主开发分支验证并推送。

## 现状与问题

审查报告指出 6 项 P1 和 3 项 P2：报表/事件租户过滤不完整、出口报表合成数据、端口指标按不稳定名称错配、无效样本误报正常/推进恢复、计数器回绕识别不足、维护窗口结束后抑制不解除、通知失败无可靠重试、报表请求竞态、健康下钻超过 200 条静默截断。用户另明确要求服务器资产不得进入网络拓扑，需同时过滤新发现设备、遗留链路 read model 和已持久化证据图。

当前工作树在 `main`，基线提交 `88f1e8b8`；有一份本任务前生成的未提交只读审查报告 `docs/walkthrough/walkthrough_20260919_1911_01_监控发布树审查.md`，需保留并随相关修复记录进入本次提交。

## 影响范围

后端监控 API/服务、后台调度、PostgreSQL 迁移/初始化、前端报表与监控中心、相关测试及计划/走查/修复记录。不得连接真实设备或生产数据；迁移验证仅使用隔离 PostgreSQL 测试库。

## 拟修改文件

- API/服务：`backend/api/monitoring.py`、`backend/api/monitoring_v1.py`、`backend/api/topology.py`、`backend/services/monitoring_export_service.py`、`backend/services/background_monitor_service.py`、`backend/services/monitoring_incident_service.py`、`backend/services/alert_maintenance_service.py`、`backend/services/topology_service.py`、`backend/services/topology_graph_service.py`、必要的指标状态辅助模块。
- 通知持久化：`backend/database/schema.py`、新编号 migration、通知 outbox 服务与 `backend/services/notification_service.py`。
- 前端：`src/pages/MonitoringReportsPage.tsx`、`src/hooks/useMonitoring.ts`、`src/components/MonitoringCenter.tsx`，以及对应局部测试。
- 测试：租户隔离、真实/空出口观测、端口稳定关联、no-data/回绕、维护到期、通知重试、请求竞态和下钻分页。
- 归档：本计划、同名 walkthrough、一次性 `docs/fixes/fix_*.md`；保留并纳入此前只读审查报告。

## 实施步骤

1. 盘点数据表 tenant 字段、报告调用方、指标标签、计数器宽度和 APScheduler 启动方式，锁定向后兼容契约。
2. 建立通知 outbox PostgreSQL 表、迁移及可幂等重试的投递服务；将后台告警接入持久化投递。
3. 修复采样质量语义、包/错误计数器 delta、维护到期恢复与审计。
4. 为 overview、reports、incident 列表/详情/写操作及关联导出增加一致的 tenant/site 范围；缓存按授权范围隔离。
5. 用实测出口记录替代报表合成值；以 asset_id + ifIndex 关联接口指标，无有效速率时返回 no-data。
6. 在拓扑发现设备选择、legacy links 查询和 evidence graph 读取三个后端边界排除服务器设备，清除 server 节点关联的边/分组引用。
7. 给报表请求加取消/代次保护，为健康下钻增加服务端 offset/分页并正确展示总数。
8. 运行聚焦 PostgreSQL 与拓扑测试、迁移升级/新库测试、前端 lint/build、PostgreSQL-only 扫描；检查完整 diff 后提交至 `main` 并按用户授权推送。

## 分工与文件边界

- 主 Agent：监控 API/租户范围、报表数据语义、counter/no-data 告警恢复、维护到期调度、集成审查与公共验证；独占 `backend/api/monitoring*.py`、`backend/services/monitoring_export_service.py`、`backend/services/background_monitor_service.py`、`backend/services/alert_maintenance_service.py`、`backend/main.py`。
- 主 Agent 同时独占拓扑服务器排除：`backend/api/topology.py`、`backend/services/topology_service.py`、`backend/services/topology_graph_service.py` 和相关拓扑测试。
- 前端 Agent：报表并发响应和健康下钻分页；独占三个前端文件及其局部前端测试；依照共享接口约定 `/monitoring/health-devices` 使用 `limit/offset` 并处理 `total`。
- 后端 Agent：通知 outbox schema/migration、投递服务及其数据库/单元测试；不得修改主 Agent 所有的 API/后台采集文件。
- 共享契约：outbox 通过 `enqueue_alert_delivery(...)` 写入告警事件的安全 payload；投递调度由主 Agent 在 `backend/main.py` 注册。执行者不得创建子 Agent。

## 验证计划

- 隔离 PostgreSQL：新增迁移升级与新建库测试、租户 A/B 读取/写入拒绝测试、outbox 多次调度幂等和 5xx 退避测试。
- 指标：用固定 counter fixtures 覆盖 Counter32/64 回绕、设备重启、缺样本不恢复、不同 asset/index 两端口映射。
- 告警：维护窗口到期后仍异常恢复为 open 并依据规则通知；通知失败重试成功、无重复发送。
- 前端：`npm run lint`、`npm run build` 和新增竞态/分页组件测试。
- `.venv/Scripts/python.exe scripts/validate_postgresql_only.py`。

## 风险与回滚思路

多租户过滤可能收窄原先误暴露的列表/导出结果；需要覆盖 Administrator 与 tenant-default 兼容。Outbox 迁移须向前兼容、保留原告警记录，回滚仅移除新投递能力并继续按当前状态保留待处理告警；禁止删除历史审计/事件。指标无数据由“看似 0/正常”改为明确 unavailable，前端需在同一提交同步适配。
