# 资产管理及相关功能模块整改意见书与实施计划

## 1. 任务目标
针对 `/assets/dashboard`（资产管理）、`/assets/network-devices`（网络设备）、`/assets/servers`（服务器）及 `/cmdb/assets`（CMDB 资产目录）进行全链路深度排查后的系统性整改，消除权限隔离漏配、多厂商子平台静默回退、前后端站点字段失配、客户端局部过滤导致的分页错乱、资产复制表单状态污染及历史遗留死代码。

## 2. 现状与问题清单

| 编号 | 优先级 | 所属子模块 | 问题定性 | 核心现象与根因 |
| :--- | :---: | :--- | :--- | :--- |
| **整改项 1** | **P1** | `/cmdb/assets` & `/assets/tree` | 权限边界漏洞 & 字段缺失 | `backend/api/cmdb.py` 中 `GET /api/cmdb/assets/tree` 与 `GET /api/cmdb/assets` 未调用 `_asset_scope_clauses`，受限站点/设备组的 Viewer 用户可越权查看全网资产；`backend/api/assets.py` 中 `GET /api/assets/tree` SQL `GROUP BY` 含 `pa.device_role` 但 `SELECT` 漏选该列。 |
| **整改项 2** | **P1** | `/assets/dashboard` & `/api/assets` | 多厂商平台回退缺陷 | `backend/api/assets.py:_VENDOR_PLATFORM_RULES` 的 `allowed` 集合漏掉了前端已支持的 `cisco_iosxr`、`cisco_asa`、`huawei_smartax`、`huawei_usg`、`juniper_srx` 等平台，保存时被静默覆盖回 `cisco_ios` / `huawei_vrp` / `juniper_junos`；且 `_platform_from_vendor` 返回 `cisco_iosxe` 与前端 `VENDOR_PLATFORMS` 键名不一致。 |
| **整改项 3** | **P2** | `/assets/servers` | 前后端契约失配 & 局部过滤 | `src/pages/InventoryServersTab.tsx` 仍使用已废弃的 `datacenter` 字段与查询参数，导致表格“数据中心/站点”列恒为 `—`、筛选器失效；顶部在线/离线/维护计数和 `quickFilter` 仅在当前页（10 条）计算，跨页统计与筛选失真。 |
| **整改项 4** | **P2** | `/assets/network-devices` | 分页与客户端过滤冲突 | `src/pages/InventoryDevicesTab.tsx` 的生命周期（`inventoryLifecycleFilter`）、标签（`tagFilterIds`）和顶部 5 联健康状态卡片（`quickFilter`）未传给后端 `/api/devices`，仅在当前页 10 条数据上过滤，导致第一页无匹配时出现“列表共 N 台但当前页空白”的分页错乱。 |
| **整改项 5** | **P3** | `/assets/dashboard` | 复制表单状态污染 | `src/pages/AssetManagement/index.tsx:openCopy` 复制资产时保留了 `snmp_community_set: true`，但新建资产并未复制后端密文，导致弹窗显示“✓ 已配置（不会回显明文）”假象，保存后实际未配置 SNMP Community；同时 `platform` 未做 `normalizeImportedPlatform` 归一化。 |
| **整改项 6** | **P3** | `/assets/dashboard` & `/cmdb/assets` | 死代码与冗余 DOM | `AssetManagement/index.tsx` 残留无入口且无 WebSocket 连接的 XTerm 弹窗状态与 `TerminalAccessModal`；`InventoryServersTab.tsx` 残留无触发入口的删除弹窗；`CmdbAssetManagementTab.tsx` 残留 `<div className="hidden">` 的旧分页代码。 |
| **整改项 7** | **P2 (性能)** | `/assets/dashboard` | 首屏 JS 体积过大 | 顶层同步静态引入了未使用的 `xterm`/`xterm-addon-fit`/`xterm.css` 与 ~400KB+ 的 `xlsx` 库，以及 1551 行的 `AssetModal`、校验弹窗，显著拖慢页面首次下载与 JS 解析时间。 |
| **整改项 8** | **P2 (性能)** | `/assets/*` | 首屏重复请求 & 无防抖 | `fetchSummary` 成功后调用 `refreshSharedAssetTotal()` 导致 `/api/assets/summary` 每次进页重复请求 2 次；仅导入时用到的 `/api/racks` 在首屏即提前请求；四个列表页搜索输入均无防抖。 |
| **整改项 9** | **P2 (性能)** | `/api/assets/summary` | 后端串行多次全表扫描 | `asset_summary` 单次请求串行执行 9 条 SQL（含 4 条独立 `COUNT(*)` 扫描），合并为 PostgreSQL `COUNT(*) FILTER (WHERE ...)` 可减少 3 次表扫描。 |

## 3. 影响范围与拟修改文件

### 后端文件
- `backend/api/assets.py`：对齐 `_platform_from_vendor` 与 `_VENDOR_PLATFORM_RULES` 多厂商合法子平台集合；在 `/api/assets/tree` 的 `SELECT` 中补齐 `device_role`。
- `backend/core/platform_utils.py`：同步扩展 `explicit_platforms` 与 `_platform_vendor`，防止设备读取时将合法子平台（如 `huawei_usg`、`cisco_asa`、`juniper_srx`）重置。
- `backend/api/cmdb.py`：在 `/api/cmdb/assets/tree` 与 `/api/cmdb/assets` 中接入 `_asset_scope_clauses` 与 `_sanitize_asset_item`。
- `backend/api/devices.py`：在 `GET /api/devices` 中支持 `lifecycle_status`、`tag_ids`、`quick_filter` 服务端过滤参数。

### 前端文件
- `src/store/inventoryStore.ts` & `src/pages/InventoryDevicesTab.tsx`：将生命周期、标签、健康状态快捷筛选接入服务端 `/api/devices` 分页查询。
- `src/pages/InventoryServersTab.tsx` & `src/pages/inventoryServersExport.ts`：迁移 `datacenter` 至 canonical `site_id` / `site_name`，修复跨页状态筛选与统计，清理废弃删除弹窗状态。
- `src/pages/AssetManagement/index.tsx`：修复 `openCopy` 中的 `snmp_community_set` 与 `platform` 归一化，清理废弃的内嵌 XTerm 弹窗状态。
- `src/pages/CmdbAssetManagementTab.tsx`：移除隐藏的旧版分页 DOM。

### 测试文件
- `backend/tests/rackvision/test_asset_scope_contract.py`（或新增专项测试）
- `src/pages/InventoryServersTab.test.tsx`
- `src/pages/AssetManagement/index.test.tsx`

## 4. 实施步骤
1. **阶段一（后端权限、多厂商平台规范化与 Summary SQL 合并）**：修改 `backend/api/assets.py`、`backend/core/platform_utils.py`、`backend/api/cmdb.py`，补齐多厂商平台白名单、CMDB 资产范围隔离、`/api/assets/tree` 字段，并合并 `/api/assets/summary` 串行 `COUNT(*)` 查询。
2. **阶段二（后端设备列表服务端筛选扩展）**：修改 `backend/api/devices.py`，支持 `lifecycle_status`、`tag_ids`、`quick_filter` 参数。
3. **阶段三（前端网络设备与服务器模块修复及搜索防抖）**：修改 `src/store/inventoryStore.ts`、`src/pages/InventoryDevicesTab.tsx`、`src/pages/InventoryServersTab.tsx`、`src/pages/inventoryServersExport.ts`，对齐服务端筛选、站点字段契约与搜索防抖，并新增 `hydrateAssetsSummary` 消除 `summary` 重复请求。
4. **阶段四（前端资产管理首屏瘦身、复制修复与死代码清理）**：修改 `src/pages/AssetManagement/index.tsx` 与 `src/pages/CmdbAssetManagementTab.tsx`，移除同步 `xterm`、`xlsx` 改为按需 `import('xlsx')`、`AssetModal` 改为 `React.lazy`、延迟加载 `/api/racks`、修复 `openCopy`。
5. **阶段五（质量门禁与回归测试）**：补充并运行 `pytest`、`vitest`、`npm run lint` 与 `npm run build`（对比 chunk 体积变化），输出 `docs/walkthrough/walkthrough_20261122_1046_01_资产管理模块整改.md`。

## 6. 风险与回滚思路
- **风险**：无数据库表结构迁移，新增 API 查询参数均为可选且向后兼容。
- **回滚**：可按模块文件独立回退 Git 变更，不影响存量数据库记录。
