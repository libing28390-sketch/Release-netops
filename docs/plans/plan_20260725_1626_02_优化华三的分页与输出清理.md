# Implementation Plan - 优化华三的分页与输出清理

本计划旨在优化设备交互命令行与自动化任务中的 SSH 分页获取机制，将多页输出的整体时延从约 8 秒降低至 0.2 秒以内，并彻底清除输出中残留的清屏空格。

## 现状/问题
1. **多页读取时延高**：当前的 `drain_paged_output` 使用 Netmiko 的 `read_channel_timing` 进行多页数据读取。该方法通过判断“信道静默超时”来确认无更多输出，默认在最后一页或每页读取时会持续等待静默时间（可达数秒），导致读取多页数据耗时长达 6 到 8 秒。
2. **残留清屏空格**：部分厂商设备（如华三 H3C）在换页发送空格后，会发送一系列空格（如 15 个空格）和回车符来抹除终端上的 `---- More ----` 提示。由于 `splitlines()` 会在回车符处切分行，这些用于清屏的空格行最终残留在输出中，导致数据表格前后夹杂无意义的空白，影响用户查看与解析。

## 拟修改文件
- [ssh_compat.py](file:///d:/netops/netsops-main/backend/drivers/ssh_compat.py)

## 实施步骤
1. **采用基于模式的高效读取**：
   - 在 `drain_paged_output` 中，若 `conn` 对象含有 `read_until_prompt_or_pattern` 方法，则使用此方法传入 `paging_pattern`，使得在匹配到提示符或下一页 `More` 时能立即返回，而无须等待静默超时。
2. **清洗输出残留**：
   - 过滤并剔除仅由空格/空白组成但长度非 0 的行（属于清屏擦除字符）。
   - 去除各行中内含的 `\r` 符号。

## 验证计划
1. 运行基准脚本，确认对华三 `display interface brief` 命令的读取时延降低到 0.5 秒以下。
2. 确认输出中无任何未对齐的空白行残留，结构清晰整洁。
