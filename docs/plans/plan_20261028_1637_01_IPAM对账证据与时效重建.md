# IPAM 对账证据与时效重建及发现终端

## 目标

重新定义对账为登记台账与网络观察的人工核查工具；增加 IPAM“发现终端”页面。共用独立 IPAM 发现快照，不重复采集，不修改监控相关代码、既有共享采集/调度/驱动/解析模板，不引入 Redis。

状态：用户已授权实施、提交并推送main，要求跟踪对应提交的Actions到成功。后端与前端Luna并行实施，主Agent负责契约审查、IPAM专用任务注册、集成验证及发布。

## 确认的现状

- 对账读 ip_addresses 与 network_endpoints，固定15分钟近期窗口、7天未发现阈值。
- network_endpoints 以IP全局唯一，跨站点/VRF同IP可覆盖；旧tracker会将计算时间写为last_seen，并把交换机名称写成终端主机名。
- 主端点流程依赖MAC成功且非空，ARP-only记录可能无法投影。
- 当前独立ARP任务10分钟，缓存TTL20分钟；NSOT计划每天02:00，MAC/终端没有独立5分钟任务。目录5m不等于实际调度。
- 最近只读样本：ip_addresses=0、ARP=90、MAC=0、network_endpoints=0、CMDB接口IP快照=55。
- 现有device_collection_status包含每设备collector状态、last_attempt_at/last_success_at、transport、collection_run_id等信息，可只读复用；但不能未经验证将状态行与原始记录认定为同一完整成功代次。

## 功能分工

1. IP地址：正式登记台账，保留既有分配/编辑功能。
2. 发现终端（新增 /ipam/endpoints）：观察清单，包括ARP-only记录，不以登记为前提，不自动写入台账。
3. IP对账：比较台账与有效发现证据，只输出待核查项。

终端清单是发现地址/网卡记录，不等于PC资产总数：一台设备可能多个IP/MAC，服务器/打印机/网络设备也会出现；多个观察源的同一终端不重复计数，IP-MAC冲突则保留所有证据。

## 数据架构及修改边界

- 新增 backend/services/ipam_discovery_service.py：只读 arp_table、mac_table、device_collection_status 及设备/站点/VRF目录，生成IPAM专用快照；禁止依赖network_endpoints.last_seen作为真实观察时间。
- 新增 PostgreSQL 迁移（编号实施时分配）：ipam_discovery_snapshots、ipam_discovery_observations，保存源设备、源类型、原始观察时间、处理时间、采集状态/范围、源代次或可核验指纹、地址空间、IP、MAC、端口及来源依据。历史保留默认90天、可配置；只清理IPAM自有历史。
- 源观察唯一身份保留 source_device + source_context + IP + MAC；对账按明确的tenant/地址空间或VRF/IP匹配，再处理站点归属。站点可复用同IP，不能在证据层按IP全局去重。
- 原始数据没有VRF/地址空间证据时标为范围待确认，禁止静默映射默认VRF；MAC关联限制在有证据的站点/VLAN/地址空间，不能全局只凭MAC挑一端口。
- 仅有ARP也生成发现记录；MAC缺失只影响端口定位。旧MAC不用于断言当前接入位置，可作为有时间标记的历史证据。
- 复用已存在的采集方式，不新增设备SNMP/SSH访问、不改变ARP/MAC与NSOT周期。新增只读IPAM投影任务默认每分钟检查源版本，源未变化不重复写入；也支持刷新时发现新版本后更新投影，更新投影不更新observed_at。
- 仅在能证明同一设备/范围的完整成功快照时推断“本轮未发现”。若现有元数据不能证明完整性，允许导入正向观察，但缺席结论一律标为证据不足；不为实现缺席判断越界修改共享采集。

## 时间与状态规则

- observed_at：原始ARP/MAC记录的真实采集时间；projected_at：IPAM加工时间，二者分开。
- 正向发现新鲜度参考实际源周期与采集超时，ARP当前建议20分钟；可配置，不能沿用全局固定15分钟。该时间代表最近在设备表中观察到，并非PC实时在线。
- MAC有独立时间与定位可信度；每日采集不能包装为实时端口位置。过期定位显示历史/待更新，不增加监控采集频率。
- 源采集失败、未知、超期、范围未覆盖：未知/数据待更新，保留历史证据，不认定终端离线，不累计有效缺席次数。
- 长期未发现默认7天且至少3次独立、覆盖该范围的完整成功采集均未发现，作为可配置起点；仅产生“疑似停用，待核查”，不自动释放。
- 从未观察到过的登记IP单列“登记后尚未发现”；不伪造首次/最后观察时间，不混入历史长期未发现。
- 有任何有效正向观察可打断持续缺席；不完整/失败采集不能延长或证明缺席。

## 对账结果和人工动作

- 发现未登记：明确scope的有效正向观察在台账中无记录。台账0条但发现有记录时，仍能列出未登记项，不能要求两侧计数均大于0才能比较。
- 信息冲突：同scope IP的MAC冲突、台账可用/已释放而网络有观察；并列证据，不自动覆盖。
- 主机名只接受有明确可信来源的数据；当前ARP/MAC链路无法提供PC主机名时不比较、不校准。OUI厂商不等于设备类型/操作系统。
- 长期未发现、登记后尚未发现、归属待确认、采集不可用分别呈现，不统称无差异。
- 登记需明确目标网段/VRF/站点，不默认选第一个网段；提交前预览字段，服务端校验范围/唯一性/权限。
- 校准只允许证据支持的字段，禁止用交换机名替换终端名；MAC变更要求明确人工确认并检查记录版本。
- 对账页撤下直接“释放”动作，改为查看证据/去台账核查；正式IP释放仍走既有IPAM权限与审计。

## 发现终端页面

- 放在IPAM工作台下，与IP地址、IP定位、利用率、IP对账并列。
- 默认列：IP、MAC、登记状态、站点/VRF、VLAN、接入设备/端口、最近采集时间、证据状态。主机名/类型仅在有可信来源时展示，否则未知。
- ARP-only显示已发现IP、端口待定位；MAC-only没有IP，作为可选“仅MAC记录”单独筛选，不伪造IP、不计入发现IP数量。
- 状态：近期观察、历史观察、归属待确认、IP/MAC冲突；避免用在线/离线描述被动观察。
- 服务端分页/筛选，支持站点/VRF/VLAN/IP/MAC/设备/登记状态；详情按需加载来源、每条观察时间和定位依据。
- 只读列表默认不触发采集。刷新结果只同步/读取已有证据；不新增网络扫描按钮。
- 页面只展示简短用途、发现IP数量及采集覆盖摘要。详细技术信息放行详情，不堆积全页提示。

## 实施顺序

1. 固定数据契约与失败语义，先撤下不可信主机名校准/直接释放入口。
2. 建独立观察/快照表与只读适配器，保留真实时间、scope及ARP-only记录。
3. 新增发现终端页，先验证已有90条ARP的可用性与范围，不承诺全部90条均新鲜/唯一/可定位。
4. 切换对账输入，加入覆盖范围、冲突、从未发现、长期未发现规则；保留原结果作只读对照。
5. 覆盖自动化与浏览器验收后再启用新的人工登记/校准操作。部署/推送遵循当前任务授权，不借本计划触发。

## 验收

- 旧ARP重复投影不改变observed_at；源未变化不会制造新发现或新成功采集次数。
- ARP有、MAC无：仍能列出IP；MAC失败不使ARP发现记录消失；过期MAC不能标为当前精确端口。
- 两站点/两VRF相同IP、同IP多MAC均完整保留，未知scope不误配。
- 一设备成功另一失败：失败范围标未知，不得整体显示核对正常。
- IPAM0条、有效发现N条：显示N个可核查未登记IP；无源输入不能显示核对通过。
- 失败/不完整采集不累计缺席；从未发现与历史缺席分开；7天规则满足仍不能自动释放。
- 真实PC主机名未知时不使用交换机名填充或校准；保留权限、审计与版本冲突保护。
- 使用隔离PostgreSQL测试事务、时间、scope与清理；前端契约测试、TypeScript、Vite隔离构建、PG-only扫描；浏览器验证分页/筛选/详情/登记与错误态，不运行真实采集。
- 检查diff确保没有监控、共享采集writer、驱动或模板变更；记录未验证设备/浏览器条件。

## 风险与回滚

- 原始表缺少真实scope/完整代次时无法凭软件推断补齐，保守显示待确认，允许功能降级但不制造证据。
- 历史从上线后累计，旧记录只能按原始时间导入，不能重建过去连续缺席。
- 新表增量上线，不删除共享记录，不重建既有台账。回滚只切回旧只读入口/关闭IPAM投影，保留新证据表；误校准恢复需有旧值审计，不能依赖快照推测。
