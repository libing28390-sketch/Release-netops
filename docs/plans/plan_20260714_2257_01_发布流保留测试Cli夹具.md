# 实施计划 - 优化发布工作流以在发布库中保留测试 CLI 夹具目录

## 任务目标
修改 GitHub Actions 自动构建发布工作流 [.github/workflows/release.yml](file:///d:/netops/netsops-main/.github/workflows/release.yml)，使其在脱敏清理测试文件时保留 `backend/tests/fixtures/` 目录，仅删除测试用例 Python 文件及临时缓存，使客户发布库 `Release-netops` 中能正常包含测试夹具目录。

## 现状/问题
当前 [.github/workflows/release.yml](file:///d:/netops/netsops-main/.github/workflows/release.yml) 中第 39 行（Ubuntu 构建）与第 178 行（Windows 构建）执行了：
```bash
rm -rf backend/tests/
```
这会把整个 `tests` 目录（包含 `fixtures/`）全部删掉。因此，发布库中完全没有 `tests/fixtures/` 目录。

## 拟修改文件
- [.github/workflows/release.yml](file:///d:/netops/netsops-main/.github/workflows/release.yml)

## 实施步骤
1. 修改 [.github/workflows/release.yml](file:///d:/netops/netsops-main/.github/workflows/release.yml)，将第 39 行与第 178 行的清理逻辑修改为仅清理 `backend/tests/` 下除 `fixtures/` 以外的文件和目录：
   ```bash
   find backend/tests -mindepth 1 -maxdepth 1 -not -name "fixtures" -exec rm -rf {} +
   ```
2. 创建对应的 Git 提交修复记录 `docs/fixes/fix_20260714_2257_01_发布流保留测试Cli夹具.md`。
3. 执行 `git add` 和 `git commit -m "ci: preserve backend/tests/fixtures/ in release workflow"`。
4. 推送更改到远程开发库的主分支：`git push origin main`。推送后将自动触发 GitHub Actions 重新构建并推送至发布库。
5. 创建走查验证报告 `docs/walkthrough/walkthrough_20260714_2257_01_发布流保留测试Cli夹具.md`。

## 验证计划
- 检查 GitHub Actions 运行状态，确认构建及同步步骤顺利完成。
- 推送完成后，检查发布库 `Release-netops` 对应分支（`main` 及 `windows`）中 `backend/tests/` 目录下是否成功包含了 `fixtures/`。

## 风险与回滚思路
- **风险**：工作流中的 `find` 命令语法不兼容导致 CI 报错。
- **回滚方式**：如果 Actions 报错，可将删除方式改回特定列出文件删除（如 `rm -rf backend/tests/*.py backend/tests/__pycache__/ conftest.py` 等）。
