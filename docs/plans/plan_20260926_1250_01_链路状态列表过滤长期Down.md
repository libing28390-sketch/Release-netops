# 总览链路状态列表过滤长期 Down 接口计划

## 任务目标

避免 01 网络总览将长期稳定 Down 的接口持续列为待核查项；总览只突出过去 24 小时状态发生变化且当前仍为 Down 的接口。

## 现状与问题

- 当前异常条件仅为 `ifAdminStatus == 1` 且 `ifOperStatus == 2`，描述的是当前状态，不代表近期故障事件。
- 表格使用 `topk(20, ...)`，由于所有匹配行的查询值为相同的 operStatus 值，Top20 不代表按影响或风险排序。
- 已有 Linux 大盘图例布局变更及 `handoff.md` 用户改动，需保留；本任务只更新 Overview 的状态卡片和异常表。

## 影响范围

- 仅影响 Network Overview 中“启用但链路未连通”计数、列表和对应分区说明。
- 以 24 小时状态变化次数作为 Top20 排序值，并要求接口当前 admin-up / oper-down。
- 长期稳定 Down 接口仍可在接口详情的当前状态面板查看。

## 拟修改文件

- `monitoring/grafana/generate_dashboards.py`
- 生成文件 `monitoring/grafana/dashboards/nexora-network-overview.json`
- 本任务计划与完成记录。

生成器输出清单已检查：9 份仪表盘 JSON；预期仅 Network Overview JSON 发生生成差异。

## 实施步骤

1. 基于 `changes(ifOperStatus[24h])` 生成近期状态变化次数，并与当前 admin-up / oper-down 条件关联。
2. 用符合条件的接口数更新总览卡片；状态指标缺失时保留 No data；用变化次数排序近期异常接口表，稳定 Down 接口通过该条件自然排除。
3. 更新卡片、列表和分区名称/说明，明确这是近期变化清单；保持接口详情中的当前状态视图不变。
4. 重新生成仪表盘并检查所有输出差异。

## 验证计划

- 编译 `generate_dashboards.py`。
- 解析所有生成的 dashboard JSON，并断言 Overview 计数和表格包含 24 小时变动筛选及 admin/oper 状态条件。
- 确认其它 8 份仪表盘 JSON 无差异并运行 `git diff --check`。

## 风险与回滚

- 仅有一次采集状态变化的近期 Down 接口会显示；无状态变化的长期 Down 不进入总览列表，但仍可在接口详情查看。
- 24 小时变化次数取决于 VictoriaMetrics 在该窗口内保存的 `ifOperStatus` 样本；采集间隔或样本缺失会限制可见性。
- 回滚时恢复 Overview 原始异常表达式和标题，再运行仪表盘生成器。
