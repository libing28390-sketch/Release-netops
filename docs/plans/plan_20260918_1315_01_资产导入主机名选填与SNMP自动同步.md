# 实施计划：资产导入主机名选填与SNMP自动同步

## 任务背景与目标
用户在资产导入和运维管理中提出：
1. 资产导入表格中手动填写设备名称耗时且容易出错（如误写为 `R1`，实际设备名为 `core-sw-01`，导致拓扑未纳管）。
2. 资产导入模板中**设备名称（主机名）支持留空**，导入后**自动通过 SNMP 采集实际设备主机名（sysName）并同步为设备名称**。
3. 在界面上提供**“校验/同步主机名”**功能按钮，方便随时随地按需一键校准与拓扑联动。

## 方案设计

### 1. 资产导入模板与校验放宽
- **模板更新**：在 `src/pages/AssetManagement/index.tsx` 和 `constants.ts` 中，网络设备工作表中的【主机名】列移除必填星号，增加说明：“选填；留空且配置了 SNMP 凭据时，系统将自动从设备获取实际主机名”。
- **后端导入容错**：在 `backend/api/assets.py` 的 `import_assets` 中，若 `hostname` 和 `asset_tag` 均未填，只要填了 `management_ip`，自动以 `management_ip` 作为初始临时主机名入库，秒级完成导入，不卡顿。

### 2. 导入后异步自发现与自动重命名
- 在资产导入成功后，若设备的主机名是由 IP 临时占位的，且配置了 SNMP 凭据/团体字：
  系统在后台异步发起轻量级 SNMP 探测，获取 `sysName.0`；
  智能清洗（去除 `.CCIE`、`.local`、`.corp` 等域名后缀）；
  自动更新 `devices.hostname`、`devices.sys_name` 和 `physical_assets.hostname`；
  触发拓扑关系重新匹配。

### 3. 主动“校验/同步主机名”API 与界面交互
- **后端 API**：`POST /api/devices/{device_id}/sync-hostname`
  - 联机通过 SNMP（或 CLI）读取设备实际 `sysName`；
  - 清洗并返回探测结果；
  - 自动将 `devices.hostname` 与 `physical_assets.hostname` 同步更新为清洗后的真实主机名；
  - 重新触发拓扑匹配计算。
- **前端网络监控页面（`/monitor/networks`）**：
  - 在右侧设备详情头部卡片中，比对 `selectedDevice.hostname` 与 `selectedDevice.sys_name`；
  - 若存在差异（例如 `R1` vs `core-sw-01`），展示醒目的差异徽标及 **【校验并同步】** 按钮；
  - 点击后发起同步，并即时刷新页面。
- **前端资产编辑弹窗（`AssetModal.tsx`）**：
  - 在主机名输入框右侧提供 **【从设备探测实际主机名】** 按钮。

## 拟修改文件
- `backend/api/devices.py`：新增 `POST /devices/{device_id}/sync-hostname` 端点。
- `backend/api/assets.py`：放宽导入主机名必填校验，以 IP 兜底；导入后异步探测填充。
- `src/pages/AssetManagement/index.tsx`：更新模板导出说明和必填列表。
- `src/pages/AssetManagement/constants.ts`：更新模板映射说明。
- `src/components/NetworkMonitoring.tsx`：设备头部增加系统名差异徽标与【校验并同步】按钮。
- `src/pages/AssetManagement/components/AssetModal.tsx`：主机名输入框右侧增设探测按钮。
- `docs/plans/plan_20260918_1315_01_资产导入主机名选填与SNMP自动同步.md`：计划归档。

## 验证方案
1. 单元测试与接口测试：调用 `sync_device_hostname` 端点验证 R1 和 R2 自动同步为 `core-sw-01` 和 `core-sw-02`。
2. 拓扑验证：验证同步后拓扑图中的 `core-sw-01` 和 `core-sw-02` 是否完全转为纳管链路。
3. 前端检查：运行 `npm run lint` 确保 TypeScript 类型与 React 组件编译通过。
