# 邮件通知设置体验优化

## 任务目标
将 /management/notifications 改为三步式 SMTP 设置向导，按官方 SMTP 指引预置国内外主流邮箱及开源/本地测试服务，分别提供连接测试和测试邮件投递，并在确认收件后启用真实告警。保留现有配置存储和告警投递语义；不在本次增加 OAuth2 认证模式。

## 现状与问题
原页面把 SMTP 参数、发件人、测试和启用开关放在一个长表单中，测试还曾被告警开关拦截，用户难以区分配置、连通、认证和投递状态。已有 service 支持 SSL 直连、STARTTLS、明文三种路径及可选用户名密码认证，但没有只连接不发信的 API。连接超时字段虽可保存，发送流程未使用该字段。

## 影响范围
更新邮件通知前端与 SMTP 后端 service/API；新增连接测试和删除 SMTP 配置接口，测试动作不新增告警记录、不受正式告警开关限制；保留发送测试邮件和正常告警的既有接口语义。增加可选 clear_password 字段，以便切换到无认证的自建测试 SMTP 时清理旧凭据。

## 实施步骤
1. 将单页表单调整为三步向导：服务与连接、认证与发件信息、测试与启用告警；将宽屏内容容器扩展到 1536px 上限，减少过多横向留白。
2. 按官方资料增加 QQ、腾讯企业邮箱、网易 163/126/yeah.net、Sina、139、189、阿里企业邮箱、Gmail/Workspace、Outlook.com、Microsoft 365、iCloud、Yahoo、Zoho、Mailpit、Mailcow、Postfix/Exim/OpenSMTPD 和自定义 SMTP 预设；使用搜索、分类切换和信息卡选择服务商，预设均可编辑并提供服务商说明。
3. 明确区分隐式 SSL/TLS、STARTTLS 和无加密；仅对 Mailpit 等受控测试环境推荐无加密。清楚注明 Gmail/Outlook 的 OAuth2 限制，当前不支持 OAuth。
4. 新增管理员可用的 SMTP 连接测试接口，检查连接、TLS 和已配置的用户名密码认证，不投递邮件；SMTP 邮件测试继续单独发送测试邮件。新增确认后的删除操作，清除密码和当前租户配置，并用空的租户覆盖记录避免意外回退到共享默认 SMTP。
5. SMTP 配置改动时清除本地验证状态；服务主机变更时要求重新输入新账号凭据，切换至无认证方式时支持清除旧密文。连接和发送超时分别使用对应配置。
6. 测试邮件收到确认后才能启用真实告警；连接测试和邮件测试在配置有变更时先保存，降低“未保存配置”导致的误报错。
7. 更新执行记录，运行前端 lint、直接调用 Vite 的独立目录生产构建、后端语法解析和 diff 检查；不连接外部 SMTP 服务器，不执行项目测试套件。

## 风险与限制
各邮件服务会调整服务器策略、端口和登录认证。预设只填充主机、端口和加密方式，管理员仍需核对官方说明及邮箱账号权限。当前 service 只支持 SMTP 用户名密码认证；需要 OAuth2 / Modern Auth 的账号可能连接成功但不能完成认证。Mailpit 预设要求部署中另有可达的 Mailpit 服务。发生问题可回滚前端和 SMTP service/API 相关文件；新增 clear_password 仅影响管理员主动切换邮箱并保存时所选 SMTP 凭据。
