# 实施计划：原生大模型多轮对话与十二模块本地工具调用重构

- **创建时间**：2026-11-27 09:50
- **目标仓库**：`D:\netops\netsops-main`
- **关联背景**：对标 ChatGPT / Claude / Gemini / DeepSeek 原生 `Chat + Tool Calling + Prompt Caching` 模式，解决此前“正则+静态模板截胡导致上下文割裂、无法基于意图推演多种可能性”的架构问题。

---

## 1. 任务目标

将 Nexora AI Copilot 的自然语言对话主链路从 **「前置正则分类截胡 + 孤立静态报表模板」** 重构为 **「LLM 全程主导上下文与多可能性推理 + 本地 12 模块 & 本地厂商知识库按需工具调用（Function Calling）」**：

1. **上下文天然连贯**：所有自然语言提问统一进入连续的 `messages` 对话流，由主模型直接结合历史对话理解代词指代（`它`、`上一台`、`这里面`）、换对象同查（`那 S6850-2 呢？`）、结果下钻（`展开看看那 3 张工单`）与追问。
2. **基于意图推演多种可能性**：模型面对异常或排障提问时，自主规划并并行调用多个本地只读工具（如同时核查告警 + 接口状态 + PAM 登录 + 配置变更 + 本地厂商 SOP），基于实锤证据给出 **“已排除项 + 高概率可能性排序 + 针对本机型号的核查建议”**。
3. **本地数据绝对优先、严控公网搜索**：默认挂接 **本地 12 模块只读工具 + 本地厂商知识库检索工具**；公网搜索工具仅在用户主动点亮「联网搜索」开关或明确查询外部动态信息（最新 CVE / 厂商 EOL）且本地无记录时才启用。
4. **高信噪比省 Token**：砍掉多余的独立 LLM `intent_parser` 预分类调用；本地工具返回高浓缩结构化事实摘要（单工具控制在 150~350 Token，禁止整表刷屏）；固定静态 `System Prompt + Tools Schema` 以稳定命中模型端 Prompt KV Cache。

---

## 2. 现状与根因问题

1. **自然语言被正则硬拦截，丧失“AI 大脑”**：`local_router.py` 将大量自然语言提问直接截胡到固定 Markdown 模板返回，无法理解潜台词、无法承接复杂上文、无法针对现象推理多种可能性。
2. **双重 LLM 调用浪费且易串台**：未被本地正则命中的句子先走 `intent_parser.parse_intent`（额外消耗 ~600 Token），一旦分类器误判为 `asset_analysis`（如第 30 轮对比两台设备），就会直接吐出全网 17 台资产表。
3. **CMDB 与本地知识库割裂**：聚焦某台设备（如 `S6850_1`，已知 `H3C / S6850 / Comware 7.1.070`）后询问配置或排障，未由模型自动将该设备的厂商/型号/平台参数传入本地知识库检索，反而弹出跨平台澄清卡打断对话。
4. **安全网关脱敏与工具参数还原需打通**：`AISecurityGateway.protect()` 会对发往外部模型的 IP/主机名做可逆 Tokenize（如 `[IP_1]`），工具执行器需调用 `resolve_output()` 还原真实标识后再查本地 PostgreSQL。

## 3. 目标架构与核心机制

```mermaid
flowchart TD
    U["用户输入消息"] --> G1{"是否显式高危执行请求？\n(如: 执行 undo ospf 1)"}
    G1 -->|是| R1["0-Token 本地安全拦截\n引导至变更工单治理"]
    G1 -->|否| G2{"是否显式 /斜杠快捷指令？\n(如 /alarms /racks /pam)"}
    G2 -->|是| R2["0-Token 本地直出原始面板"]
    G2 -->|否| LOOP["进入原生 LLM Chat + Tool Loop\n(保持完整多轮 messages + 静态前缀缓存)"]
    LOOP --> TC{"LLM 判断是否需要核实数据？"}
    TC -->|无需查库\n(纯概念/上文已有数据)| STREAM["直接流式生成回答"]
    TC -->|发起 1~N 个并行 Tool Calls| EXEC["本地安全执行器 (最多 2 轮)\n1. 还原安全网关标识符 Token\n2. 校验 RBAC 角色权限 & 零密钥列\n3. 并行查询 12 模块 SQL / 本地知识库\n4. 压缩为高密度事实摘要 + 引用"]
    EXEC -->|回填 role=tool 结果| STREAM2["LLM 交叉印证事实、排除无关项\n推演多种可能性并流式输出最终回答"]
```

### 3.1 本地只读工具集设计（`copilot_tools.py`，严格只读以通过 `_tool_is_unsafe` 审计）

将 12 大功能模块与本地知识库收敛为 **9 个职责清晰、参数语义明确的标准 OpenAI Function Tools**（避免工具过多稀释模型注意力与前缀 Token）：

| 工具名称 | 覆盖的业务模块 | 核心入参与高浓缩返回（≤ 350 Token） |
|---|---|---|
| `get_network_overview` | **0. 总览 / 10. 容量** | 全网在线率、未恢复严重告警数、巡检概况、机柜与 IPAM 容量瓶颈摘要 |
| `query_cmdb_devices` | **4. 资产与机柜 / 6. CMDB 基础** | 按 IP、主机名、厂商、角色、状态、站点查询设备档案、所在机柜 U 位，或列出站点/脱敏凭据元数据 |
| `query_alarms` | **3. 告警管理** | 按设备 ID/主机名/IP、厂商、级别、时间范围查询未恢复告警统计与最新告警明细（含告警内容与时间） |
| `query_monitoring_topology` | **2. 实时监控 / IP·MAC 定位** | 查询指定设备或全网的接口 UP/DOWN 异常统计、LLDP/CDP 拓扑邻居，或追踪指定 IP/MAC 所在交换机端口 |
| `query_pam_sessions` | **1. 操作工作台 (PAM)** | 查询指定设备或全网近期终端登录次数、操作人、活跃会话与风险等级（RBAC 校验） |
| `query_config_and_compliance` | **7. 配置管理** | 查询指定设备或全网近期配置备份变更、配置漂移结果（增删改行数）及合规基线检查结果 |
| `query_tickets_and_automation` | **8. 自动化 / 9. 工单 / 11. 平台** | 查询变更工单（支持按设备或待审批过滤）、近期自动化巡检结果及平台用户概览（平台项带管理员 RBAC） |
| `search_local_knowledge` | **12. 本地厂商知识库 & 模板库** | 按 `query` + 可选 `vendor / product_model / cli_platform / software_release` 检索本地权威配置指南、CLI 命令与排障 SOP |
| `search_public_web` *(条件挂载)* | **公网动态补充（受控）** | **默认不挂载**；仅当用户点亮「联网搜索」或安全策略允许且明确查询外部 CVE/EOL 动态时挂载 |

### 3.2 多可能性推理与诚实边界（System Prompt 约束）

保持一份 **100% 静态、支持前缀 KV 缓存** 的主系统提示词，明确以下行为准则：
1. **事实必查本地工具**：凡涉及本网设备、IP、告警、登录、机柜、配置、工单、网段的问题，必须先调用对应本地工具获取实锤数据，严禁凭空猜测数字或状态。
2. **CMDB 联动本地知识库**：当对话中涉及具体设备的配置方法、CLI 命令或故障排查时，优先调用 `query_cmdb_devices` 确认该设备的真实 `vendor / model / platform / version`，再将其传入 `search_local_knowledge` 获取完全匹配该硬件平台的本地权威手册。
3. **多可能性推演范式**：当用户询问异常原因、故障排查或风险评估时：
   - 先基于本地工具数据列出 **已核实事实与可排除项**（例如：近 7 天无 PAM 登录且无配置漂移 → 先排除人为改配）；
   - 再按概率高低给出 **2~3 种合理可能性及判断依据**；
   - 最后给出 **针对每种可能性的只读核查命令（匹配该设备真实厂商平台）或下一步操作建议**。
4. **按需精炼回答**：用户问简单事实（如“华三设备有告警吗”）时直接简洁回答核心结论与关键明细，不刷无关八股大表；用户追问细节时再展开。

### 3.3 流式体验与安全网关兼容细节

1. **工具调用过程实时可见**：模型在规划与并行执行本地工具期间，通过现有 SSE `_progress_event` 实时推送步骤（如 `正在核查 S6850_1 活动告警与 PAM 登录记录...`），工具执行完毕后无缝切换至 `chat_stream` 流式逐字输出最终回答。
2. **标识符 Token 自动双向解析**：
   - 工具入参先经 `ai_security_gateway.resolve_output(raw_args_json, tenant_id=tenant, task_id=task_id)` 还原真实 IP/主机名后再执行本地 SQL；
   - 工具返回结果经 `minimize_tool_result` 与脱敏处理后作为 `INTERNAL` 级别送入下一轮合成，确保零凭据外泄。
3. **Token 账单精准累计**：将第 1 轮 Tool Planning 与最终流式合成的 `input_tokens`、`output_tokens`、`cached_tokens` 累加回写至消息记录与 `/ai/usage` 审计表，前端气泡与后台账单 100% 对齐。
4. **模型能力兼容兜底**：若当前选定模型在数据库中 `supports_tools` 未开启但属于主流支持 Function Calling 的供应商（OpenAI / Gemini / DeepSeek / Anthropic / Qwen），自动放行工具调用；若底层模型确实不支持 `tools`（返回 400），自动降级为无工具单轮对话并附带会话实体摘要，确保永不报错中断。

## 7. 风险与回滚思路

- **工具循环失控风险**：硬限制单次提问最多执行 `AI_COPILOT_MAX_TOOL_ROUNDS = 2` 轮工具调用，单工具结果硬截断 ≤ 1,500 字符，杜绝死循环或撑爆上下文窗口。
- **供应商兼容性风险**：部分自定义 OpenAI 兼容代理或本地小模型可能不支持 `tools` 字段；捕获 `AIInvalidRequestException` 后自动降级为普通对话模式重试，保证可用性。
- **一键回滚路径**：在 `.env` 中设置 `AI_COPILOT_AGENTIC_CHAT_ENABLED=false` 即可立即切回原有的本地确定性路由模式，无需回滚数据库或前端构建产物。
