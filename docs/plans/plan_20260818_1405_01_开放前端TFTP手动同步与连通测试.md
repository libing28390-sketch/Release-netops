## 1. 现状与问题分析

1. **现状**:
   - 后端已具备纯 Python RFC 1350 TFTP 客户端能力，并在定时备份策略调度执行时可自动向 TFTP 推送；
   - 但在前端「备份中心」界面上，缺少直观的 TFTP 入口：用户无法直接在界面上测试 TFTP 服务器的连通性，也无法对已完成的单台快照或历史批次进行手动「立即转储至 TFTP」。
2. **目标**:
   - 提供全链路的前端 TFTP 交互：
     1. **TFTP 连通性测试**：实时探测目标 TFTP 服务器可用性；
     2. **全局 TFTP 默认设置管理**：支持保存默认 TFTP 服务器 IP、端口与路径前缀；
     3. **单快照/整批次手动同步**：在快照行操作与批次详情中均可一键推送至 TFTP 服务器；
     4. **备份中心顶部「TFTP 归档转储」控制面板**。

## 3. 实施步骤

1. **后端 API 开发**:
   - 在 `backend/api/configs.py` 增设:
     - `POST /api/configs/tftp/test`: 发送 0 字节探针文件 `_probe_test.tmp` 探测服务器 ACK/WRQ 响应；
     - `GET /api/configs/tftp/settings` / `PUT /api/configs/tftp/settings`: 基于 `global_vars` 持久化全局 TFTP 缺省设置；
     - `POST /api/configs/tftp/sync-snapshot`: 将指定快照解密并上传至 TFTP；
     - `POST /api/configs/tftp/sync-batch`: 将指定批次的所有快照及汇总日志批量上传至 TFTP。
2. **前端 UI 开发**:
   - 在 `src/pages/ConfigBackupTab.tsx` 顶部操作栏增加「TFTP 归档转储」按钮；
   - 实现 **TFTP 管理与同步弹窗**：
     - 配置 TFTP 服务器 IP、端口、子目录前缀；
     - 提供「连通性测试」按钮，实时展示测试结果；
     - 提供「保存为默认配置」按钮；
     - 提供「立即同步最新批次」操作；
   - 在设备快照表格的操作列增设「上传至 TFTP」快捷按钮；
   - 在批次详情弹窗中增设「重新转储本批次至 TFTP」按钮。
3. **自动化测试与质量门禁**:
   - 运行 pytest 验证新增接口正确性；
   - 运行 `npm run lint` 和 `npm run build` 确保前端零类型错误。
4. **归档走查记录**:
   - 产出 `walkthrough_20260818_1405_01_开放前端TFTP手动同步与连通测试.md`。
