# 资产管理直接绑定凭据中心已有凭据

在资产录入（手动录入、Excel 导入）以及编辑页面，支持直接绑定凭据中心（Credential Vault）中已有的凭据。这不仅避免了用户重复录入凭据、多次轮换等繁琐操作，还能提升凭据复用性，同时确保与已有的凭据自动轮换机制兼容互通。

## User Review Required

> [!IMPORTANT]
> 1. **数据库模型**：在物理资产表 `physical_assets` 中补充新增列 `credential_id`。
> 2. **后端同步**：资产编辑或导入绑定 `credential_id` 时，系统自动读取相应凭据数据，对关联的 `devices` 进行同步更新与绑定，同时保障全局 SSH 登录、连通性验证以及 Playbook 正常工作。
> 3. **共享凭据保护**：如果是绑定的已有共享凭据，编辑资产的其他非凭据属性时不会对全局凭据的账号密码进行覆盖修改。

## Proposed Changes

### [Component: Database Schema]

#### [MODIFY] [schema.py](file:///d:/netops/netsops-main/backend/database/schema.py)
在初始化 `physical_assets` 表字段的逻辑中，使用 `ensure_column` 追加 `credential_id` 列：
```python
    ensure_column('physical_assets', 'credential_id', "TEXT DEFAULT ''")
```

---

### [Component: Backend API]

#### [MODIFY] [assets.py](file:///d:/netops/netsops-main/backend/api/assets.py)
1. **Pydantic Model**：
   * 在 `AssetCreate` 与 `AssetUpdate` 模型中添加 `credential_id: Optional[str] = ''` / `Optional[str] = None`。
2. **`_create_linked_device` 关联设备创建逻辑**：
   * 检测 `body.credential_id`。如果传入了且在数据库中存在，则直接使用它作为设备的 `credential_id`。
   * 当使用已有凭据时，跳过往 `credentials` 表插入重复账号记录的步骤。并且从已有凭据中自动读取普通账号、特权账号、Enable 及 SNMP 口令，自动同步到 `physical_assets` 与 `devices` 相关列中，标记 `onboarding = 'verified'`。
3. **`_sync_device_from_asset` 设备同步逻辑**：
   * 如果传入的 `credential_id` 有所更改，将其同步写入 `devices.credential_id` 和 `physical_assets.credential_id`，并解密同步相应账号属性。
   * **共享凭据防篡改**：更新设备关联凭据行时，若发现当前凭据的名称不属于本设备专属（即不是以 `cred-{hostname}-` 起步的自动生成凭据），则**跳过**对 `credentials` 数据表记录的主动改写，避免破坏其他共享资产的认证。
4. **`POST /assets` 与 `POST /api/assets/import`**：
   * 在物理资产数据写入语句（`INSERT INTO physical_assets`）中，支持 `credential_id` 写入。
   * 导入逻辑从数据库反查填入的 `credential_id` 或 `credential_name`，实现以名字做导入绑定。
