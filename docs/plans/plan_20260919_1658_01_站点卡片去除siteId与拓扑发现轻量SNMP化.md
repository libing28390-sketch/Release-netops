# 实施计划：站点卡片去除 site-id 与拓扑发现轻量 SNMP 优先改造

- **时间戳**: 2026-09-19 16:58
- **序号**: 01
- **任务名称**: 站点卡片去除 site-id 与拓扑发现轻量 SNMP 优先改造

---

## 1. 任务背景与核心问题

1. **站点总览卡片展示冗余 site-id**：
   - 界面上站点卡片（例如 `WH-DC-02` / `WH-DC-01`）下方副标题直接展示了系统内部生成的 UUID/哈希主键（如 `SITE-E7966B242326`、`SITE-F287CF1C61EC`）；
   - 用户反馈该内部 ID 对运维人员没有任何业务价值，影响视觉清爽度，应予以去除或替换为友好属性。
2. **拓扑发现（“刷新发现”）过度依赖多条复杂命令，需强化 SNMP 优先直查 LLDP 邻居**：
   - 用户反馈：“右上角的刷新发现是作为CLI兜底的吧，我们是否可以再优化下呢，如果完全可以通过SNMP来解决，就没必要引入那么多条命令啊，就直接查询lldp邻居就好了，其他的命令都不需要”；
   - 现状排查：
     1. 入口门禁问题：`discover_device_neighbors` 强制校验了 `device.username` 和 `device.password`，导致纯 SNMP 设备被无辜阻断；
     2. 发现流程应全面强化 **SNMP LLDP 优先**：直接基于标准工业 IEEE 802.1AB LLDP-MIB（`lldpRemTable` / `lldpLocPortTable`）查询邻居，毫秒级完成，零登录零提权；
     3. 仅当 SNMP 不可用时，才走 CLI 单条 LLDP 邻居命令兜底；其他多余的杂项命令全面剔除或旁路。

---

## 2. 拟修改文件

1. `src/pages/TopologyPage.tsx`：
   - 去除站点卡片中的 `{site.id}` 内部 ID 渲染，保持卡片大标题、状态小圆点与指标的纯粹美观。
2. `backend/services/topology_service.py`：
   - 放宽 `discover_device_neighbors` 入口凭据检查：只要具备管理 IP 且有 SNMP 凭据或 SSH 凭据即可开始；
   - 强化 SNMP LLDP 发现链路：SNMP 采集成功即直接完成，不依赖复杂多命令；
   - 拓扑物理链路入库状态保障：由活跃邻居发现生成的物理链路初始化/更新状态为 `up`，并同步保障端点端口在 `interfaces` 表中为 `up`，彻底杜绝历史残留导致的“中断”。
3. 自动化测试与验证构建；
4. 归档修复记录 `docs/fixes/` 与走查报告 `docs/walkthrough/`。
