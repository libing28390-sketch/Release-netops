# 网络采集与设备会话复用规范

## 目的

同一台设备的一次只读采集任务，必须优先采用“一次登录、多条命令、逐条解析”的执行模型。SSH 登录、VTY 分配、终端初始化和退出的成本通常高于单条查询命令；按动作重复建连会把动作数量直接放大成网络延迟，也会增加设备侧登录压力。

## 统一执行模型

1. 先解析设备当前发布版本、动作命令、参数、解析模板和字段契约。
2. 解析并锁定本次任务使用的凭据、租户范围、资源权限和连接驱动。
3. 对同一设备、同一发布版本、同一凭据上下文建立一个只读会话。
4. 在会话内按确定顺序逐条发送命令；每条命令保留独立的动作码、原始回显、解析结果、错误码、耗时和审计记录。
5. 每条回显必须使用该动作绑定的 TextFSM/解析模板和字段契约独立解析，不能使用上一条命令的模板或字段映射。
6. 任意一条命令解析失败时，只标记该动作失败；是否继续后续只读动作由采集任务策略决定，默认继续，以最大化有效数据覆盖。
7. 无论成功、失败、取消还是超时，都必须在 `finally` 中关闭会话并释放网络并发租约。

## 会话边界

- 会话只允许在同一设备、同一租户范围、同一当前发布版本和同一凭据角色内复用。
- 网络采集和拓扑默认通过 `resolve_collector_credentials(device, ssh_role="normal")` 解析普通 SSH 凭据；凭据中心绑定时以绑定凭据为权威，资产录入的账号密码只按既有兼容回退规则使用，不从 Playbook 参数或页面临时输入密码。
- 不允许跨设备、跨租户、跨发布版本或跨普通/管理员凭据角色复用连接。
- 只读采集可以批量复用会话；配置变更、回滚和其他写操作必须使用明确的变更事务，不得因为复用会话而绕过动作级授权或审批。
- 会话复用不能绕过平台注册表。每个动作仍须执行发布版本校验、命令安全校验、参数校验、模板范围校验、字段契约校验和审计。
- 不得把多条命令拼成带有 `;`、管道或其他 shell 链接符的单条字符串来“复用会话”；命令仍然必须逐条发送。

## 拓扑与CMDB约定

- LLDP 邻居采集负责发现物理邻接。
- Eth-Trunk/链路聚合采集负责得到父接口与成员接口关系；接口状态采集不能替代该关系数据。
- CMDB 接口状态采集遵循当前产品契约，只将有 IP 的接口写入 IP-bearing 接口投影；拓扑可以为物理链路端点维护必要的接口骨架行。
- 拓扑在同一设备上需要多个平台注册表只读动作时，必须传入共享的 `PlatformActionSession`，不得循环调用独立登录的单动作入口。

## 性能与可观测性要求

- 对一台设备的一组只读动作，目标 SSH 登录次数为 1；异常重试才允许重新建立会话。
- 日志必须能够区分登录耗时、命令耗时、解析耗时和数据库写入耗时，不记录明文密码或完整敏感回显。
- 每个动作仍写入独立的 `platform_action_runs` 审计记录；会话复用只改变连接生命周期，不改变审计粒度。
- 回归测试至少覆盖：多动作只创建一个 Driver、每个动作使用自己的命令/模板、单动作失败不污染后续动作、会话最终释放，以及跨发布版本复用被拒绝。
