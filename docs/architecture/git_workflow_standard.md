# Git 工作流规范

## 适用范围

本规范适用于 Nexora NetOps 的代码、数据库迁移、评测数据、CI 配置、前端资源和发布准备工作。

## 单一主线

- `main` 是仓库唯一长期开发、集成和发布准备分支。
- 修改直接在 `main` 工作区完成；不创建、切换或推送 `feature/*`、`fix/*`、`codex/*` 等功能分支。
- 外部工作树或补丁只能用于临时审查、恢复或传输，完成后必须把全部改动合入 `main`，并清理临时分支引用。
- 不把临时分支、未合入的工作树或远端分支作为后续任务的开发基线。

## 修改与合入

1. 修改前检查 `git status`、当前 `main` 提交和用户已有未提交文件。
2. 涉及代码、迁移、评测、部署或批量数据时，先在 `docs/plans/` 建立计划，记录范围、验证和回滚思路。
3. 合入前审查完整差异，禁止用 `git reset --hard`、`git clean` 或覆盖式复制清理冲突；用户已有改动必须保留并可追溯。
4. 数据库迁移必须在 PostgreSQL 上验证幂等性、事务边界和已有历史兼容性，不得删除或重置 `schema_migrations` 历史。
5. 完成后在 `docs/walkthrough/` 记录实际修改、验证结果、未验证项和剩余风险。

## 提交与远端操作

- 每次 `git commit` 前在 `docs/fixes/` 新建对应的 `fix_YYYYMMDD_HHMM_NN_问题名.md`，并与本次代码、配置或文档修改放在同一提交中。
- 提交信息应说明实际变更范围，不把未审查的生成物或个人笔记混入提交；项目明确纳入的知识包和评测证据除外。
- 不向远端推送、不触发 GitHub Actions、不创建 Release，除非用户在当前任务中明确授权。
- 交付前确认当前分支为 `main`，工作树状态、提交 SHA 和验证结果已写入交接/完成文档。
