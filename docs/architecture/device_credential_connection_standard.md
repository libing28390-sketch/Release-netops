# 设备凭据与连接边界代码规范

## 适用范围

本规范适用于拓扑发现、运行数据采集、巡检、诊断、调度、自动化 Playbook、平台注册动作以及其他通过 SSH/CLI 连接网络设备的代码路径。

## 强制规则

1. **统一凭据入口**

   在创建 driver、`ConnectHandler` 或其他网络连接对象之前，必须调用：

   - `services.vault_service.resolve_device_credentials`：需要完整凭据对象的业务；
   - `services.vault_service.resolve_collector_credentials`：网络采集、拓扑和只读 CLI 业务。

   禁止直接把 `devices` 或 `physical_assets` 查询结果中的原始 `username`、`password`、`normal_password`、`admin_password` 等字段传给驱动。

2. **凭据权威顺序**

   设备绑定了凭据中心且凭据声明了账号角色时，`credentials` 表对应角色是权威来源。资产字段仅允许作为未绑定角色的兼容回退。账号和密码必须来自同一角色、同一解析结果，禁止跨来源拼接。

   `enable_password` 是独立的特权提权凭据，只有明确配置时才允许传给驱动；不得用普通账号密码、管理员账号密码或页面临时输入自动填充 Enable Secret。

3. **账号角色隔离**

   拓扑、巡检和只读采集默认使用 `ssh_role="normal"`。配置备份、密码轮换、配置变更和明确授权的特权操作，才可以使用管理员凭据或 Enable 密码。

4. **平台注册与 Playbook 不得绕过**

   平台注册服务可以查询 `devices.*` 获取租户、平台和审计信息，但在调用 `DriverFactory` 前仍必须重新通过统一凭据解析器填充连接参数。Playbook 的 `action_code` 路径与普通命令路径必须遵循同一凭据边界。

5. **测试要求**

   新增或修改连接边界时，必须使用 mock driver 覆盖共享凭据中心、资产回退、认证失败和空凭据分支。测试代码、日志、响应和文档不得包含真实密码、密钥或 Token。

6. **交互认证回显禁止落日志**

   `read_channel()`、认证提示、Enable 交互和密码提交后的终端缓冲区可能包含明文密码或设备回显。禁止将这些完整回显写入日志、审计记录、异常消息或 API 响应；如需排障，只允许记录字符数、行数、是否出现密码提示/认证失败等聚合元数据。异常消息写入日志前必须按当前登录密码、Enable Secret 和管理员密码做二次脱敏。

## 回归约束

平台绑定设备不得因为 `devices.password` 为空而跳过凭据中心解析，也不得把空密码直接交给 Netmiko。任何连接路径都应在驱动层之前完成凭据解析，并保留结构化错误和脱敏日志。

## 拓扑发现性能约束

拓扑发现按设备划分独立任务，允许使用有界的设备级并发；同一设备的 SSH/CLI 操作仍必须遵守 `NETWORK_SSH_PER_DEVICE_CONCURRENCY=1`，不得通过提高同设备并发规避慢速问题。拓扑任务必须持续续租，避免长批次因租约过期被重复执行。

拓扑发现只允许对明确的瞬时传输故障（SSH 不可达、连接超时等）重试。认证失败、凭据不完整、平台/动作不支持、命令错误、解析模板不匹配等确定性错误不得重试，以免重复建立 SSH 会话并放大设备侧负载。
