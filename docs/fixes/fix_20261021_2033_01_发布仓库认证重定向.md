# 发布仓库 GitHub 认证重定向

## 症状
源仓库 main push 已成功，但 Actions 在同步至 Release-netops 时遇到 GitHub 重定向，随后因无交互终端无法读取 Username，最终发布 job 失败。

## 原因
Workflow 将 `RELEASE_REPO_TOKEN` 填入 remote URL 的用户名位置。目标仓库返回同站点 URL 重定向时，Git 没有继续使用原 URL 内的认证信息，转为交互提示。

## 修正
将 Secret 限定在发布 step 的环境变量内，构造并遮罩 Basic Authorization header；remote URL 使用公开不含凭据的地址。主分支推送和版本 tag 推送分别通过 Git `http.https://github.com/.extraheader` 参数附带认证头。

## 验证
- 发布认证契约 pytest：1 passed。
- 提取的 GitHub Actions Bash 步骤经 Git for Windows bash `-n`，exit 0。
- `git diff --check` 在本次修改文件范围内通过。
- Actions 精确 SHA 的目标仓库写入验证尚待本次 workflow 执行；不以匿名 ls-remote 或源仓库 CI 代替。

## 风险与回滚
Secret 缺失、过期或目标仓库无写权限仍会使发布失败。Header 在 step 内显式遮罩且不写入 Git remote、仓库文件或日志。回滚方式是 revert 本次 workflow/test/docs 提交。
