# Git 提交修复记录：待推送改动安全修正

## 问题现象

- m0253 原先会用目录默认值无条件覆盖内置 IF-MIB 模块的 `oid_config_json`，可能丢失运维人员编辑的 OID 或 metrics。
- 配置快照内容和下载 API 通过 snapshot ID 直接读取，没有限制到当前用户可查看的资产租户/站点范围。
- 接口 PPS 时序图缺少独立入向和出向系列。
- 接口状态标签应显示 `Up`/`down`，而不是原始数值；文案大小写应与用户要求一致。

## 根因

- 迁移把初始化默认目录与已配置模块的增量升级合并成整体替换。
- 快照内容/下载端点只确认 snapshot ID 存在，没有复用 asset view scope。
- PPS 查询只按包类型聚合，未保留方向系列。

## 解决方案

- m0253 对空配置仍 seed 完整默认目录；对非空配置只追加缺少的 `ifLastChange`，保留已有配置并按合并后的 JSON 重算 hash。
- 快照内容和下载 API 增加 viewer 身份依赖，按 asset tenant/site scope 读取；非管理员缺 tenant、设备 tenant 与 site tenant 不一致、重复 site name 无法唯一解析时均拒绝；越权和不存在的 ID 都返回 404。
- 04 接口看板和 09 接口详情页 PPS 图增加入向、出向、单播、组播、广播五类曲线与语义颜色。
- 接口状态 `1/2` 显示为绿色 `Up` / 红色 `down`，未知值仍映射为灰色 `UNKNOWN`。

## 风险与回滚方式

- m0253 仅对缺失项做追加；应用前仍应备份数据库。代码提交可通过 `git revert` 回滚；若迁移已经运行，不建议移除 `ifLastChange` 目录项，以免与生成配置不一致。
