# 修复记录：CMDB 接口采集改造为 SNMP 优先与消除 unknown 状态

## 1. 问题现象
1. 在 CMDB 资产管理与接口详情中，交换机（尤其是华三、华为等）的部分物理二层端口或互联端口状态显示为 `unknown`。
2. 拓扑发现（LLDP/CDP）中已建立链路的端口，在新发现写入库时被占位赋予了 `admin_status = 'unknown', oper_status = 'unknown'`。
3. 接口状态采集过分依赖 SSH CLI (`display interface brief` / `show ip interface brief`)，对于不包含三层 IP 的二层端口，历史代码在同步时直接执行 `UPDATE interfaces SET admin_status = 'unknown', oper_status = 'unknown'`，误将物理二层端口洗成 `unknown`。

## 2. 根因分析
1. **根因一 (`interface_collection_service.py`)**：
   - 历史实现仅关注带 IP 的三层接口，二层 Bridge / Trunk 端口因没有直接配置 IP，在构建快照时被排除；
   - 在后续 `_upsert_interfaces` 清理过期 IP 接口映射时，错误地对所有未出现在三层列表中的端口重置了 `admin_status = 'unknown', oper_status = 'unknown'`；
   - 缺少直接利用网络设备标准 IF-MIB (RFC 1213 / RFC 2863) 进行全量端口硬件状态采集的机制。
2. **根因二 (`topology_service.py`)**：
   - 拓扑发现通过 LLDP 推导出新端口入库时，初始占位值盲目填入了 `'unknown', 'unknown'`；但既然 LLDP 能互通，证明该链路物理与协议 100% 为 UP。
   - 聚合口成员端口在推导入库时也仅更新了 `oper_status`，遗留了 `admin_status = 'unknown'`。
3. **根因三 (`snmp_service.py`)**：
   - 原先的 `collect_interface_data` 仅收集了 `ifOperStatus`，未并行拉取 `ifAdminStatus`（OID `1.3.6.1.2.1.2.2.1.7`），导致端口管理状态缺失。

## 3. 解决方案与修改内容
1. **SNMP IF-MIB 采集完善 (`backend/services/snmp_service.py`)**：
   - 在默认接口采集配置与 OID 别名中增加 `if_admin_status_oid = 1.3.6.1.2.1.2.2.1.7`；
   - 在 `collect_interface_data` 中通过 `asyncio.gather` 并行采集 `admin_status_rows`，为每个接口产出标准的 `admin_status` 与 `oper_status`。
2. **CMDB 接口采集 SNMP-First 架构 (`backend/services/interface_collection_service.py`)**：
   - 引入安全异步调用工具 `_run_async`；
   - 扩充 `_INTERFACE_PREFIXES` 厂商接口前缀兼容性；
   - 实现 `_collect_snmp_interfaces(device)` 与 `_upsert_snmp_interfaces(device, snmp_interfaces)`：
     - 若设备配置了 SNMP 凭据，优先通过标准 IF-MIB 一次性毫秒级拉取设备全部二层与三层端口物理状态（Up/Down）、速率（speed）和端口描述（ifAlias）；
     - 入库更新时确保物理二层口状态稳定生效；
   - 修复 `_upsert_interfaces`：移除对缺少 IP 的端口重置 `admin_status/oper_status` 为 `unknown` 的逻辑，并在更新时增加保护（若 CLI 解析为 unknown 则不覆盖已有明确状态）；
   - 在 `collect_interface_status_target` 中打通 SNMP-First 流程，并支持当 CLI 异常时优雅降级仅保留 SNMP 接口台账。
3. **拓扑链路接口状态保真 (`backend/services/topology_service.py`)**：
   - 将 LLDP 活跃邻居推导出的新端口插入初始值由 `'unknown', 'unknown'` 改为真实的 `'up', 'up'`；
   - 聚合口成员端口状态推导时同步更新 `admin_status = 'up'`。
4. **历史数据清理**：
   - 编写迁移脚本将数据库中遗留的 16 条活跃端口历史残留 `unknown` 管理状态修正为 `up`，库内 unknown 计数归零。
