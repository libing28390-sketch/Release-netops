# 修复记录：单组织模式租户边界下线与 Actions 失败修复

## 问题

用户希望移除 Nexora 的多租户管理及租户访问限制，但保留历史数据。先前 GitHub Actions 的发布门禁也因无线 Grafana 面板 10 的中文字段名断言失败：面板已使用“终端数”，测试仍期望“客户端数”。

## 处理

- 以 `backend/core/tenant_policy.py` 统一单组织行为：tenant 不再作为用户访问边界或默认查询过滤；新记录写入 `tenant-default`。
- 关闭租户管理页面入口和租户 CRUD API，同时保留历史租户行、tenant 字段、审计与业务分区键。
- 更新资源授权和跨域服务查询，保留角色/动作、站点/设备组、对象所有权、审批回避、MFA 等限制。
- 新增和更新 PostgreSQL 回归用例，覆盖跨历史 tenant 可见性以及显式站点/设备组仍拒绝越权。
- 修复单组织下无过滤条件时配置快照与告警规则目录拼接的 SQL 语法错误。
- 将 Grafana presentation 测试期望值改为实际中文“终端数”。
- 修复产品解析对重复已审查候选的 OS 家族补全，以及官方来源等价重定向测试在历史 tenant 合并后的重复 URL 夹具。
- 恢复知识生命周期服务所需的 `_CONTROL_RE`，避免 ING015/KUI014/ING019 路径运行时 `NameError`。

## 验证状态

- 上次 Actions release gate 记录为 `1 failed, 3247 passed, 1 skipped`，唯一失败是上述 Grafana 标签断言。
- 对应 Grafana 测试通过；多个受影响 PostgreSQL 定向测试集均通过，`validate_postgresql_only.py` 报告 0 violations。
- 完整后端套件按用户加快进度要求在约 21% 时中止，中止前未观察到新失败；该套件不计为通过。前端 lint/build、PostgreSQL-only policy scan、`git diff --check` 与记录的定向测试已完成。提交推送后以对应 GitHub Actions Release 结果作为全量门禁。
