# 修复拓扑发现参数数量不匹配 修复记录

## 问题现象

本地拓扑发现任务中，可正常连通的路由器 R1 和 R4 状态被标记为 `topology_discovery_failed`，而后端日志显示：
```
TypeError: not all arguments converted during string formatting
IndexError: tuple index out of range
```
导致拓扑收集结果无法入库。

## 根因

1. **INSERT 语句参数冗余**：`backend/services/topology_service.py` 中向 `topology_observations` 执行 `INSERT` 时，SQL VALUES 列表已硬编码了 `0, 1`，但传入的 Python 参数元组末尾同样带上了这两个值，导致参数比占位符多出两个，引发 `TypeError`。
2. **UPDATE 语句参数不对齐**：在 `UPDATE` 分支中，试图解包复用一个只有 15 个值的 `values` 元组，但 `UPDATE` 语句的占位符却有 18 个。导致 unpacked tuple 长度（17个）小于 SQL 占位符个数，引发 `IndexError: tuple index out of range`。

## 解决方案

1. 移除 `INSERT` 元组中多余的尾部 `0` 和 `1` 参数。
2. 彻底废弃旧的 `values` 元组定义，在 `UPDATE` 语句中以内联（inline）的形式明确且完整地传入 18 个参数，对齐所有占位符。
