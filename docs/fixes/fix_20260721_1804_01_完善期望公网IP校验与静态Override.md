# 完善企业级公网IP校验与静态Override 提交记录

## 问题现象

前一版本实现存在以下生产级不足：
1. 静态 Override 配置的 IP 被直接写入历史快照，与真实在线检测结果混淆，影响审计和故障分析
2. 单次检测到非预期 IP 即触发降级告警，外网查询源偶发异常时存在误报风险
3. 互联网连通性状态与公网 IP 合规性状态强绑定，用户无法独立判断是丢包还是出口切换
4. 环境变量格式错误（如 `abc`、`/33`）时静默忽略，用户以为配置生效但实际未执行校验
5. 缺乏 IPv6 双栈匹配支持

## 根因

初版实现作为快速原型未考虑企业级部署中的多来源标识、防抖状态机、配置校验和状态解耦需求。

## 解决方案

1. 数据模型扩展：新建 m0027 迁移，增加 `public_ip_source` 和 `public_ip_verified` 字段
2. 多来源可信度识别：`detect_egress_ip()` 返回完整的来源元数据
3. 启动时严格校验：`validate_expected_egress_ip_config()` 在模块加载时解析并校验配置
4. 连续 2 次确认防抖：基于历史事件表的状态机防止偶发误报
5. 状态解耦：`connectivity_status` 与 `overall_status` 独立输出，通过环境变量控制是否影响健康度
6. IPv6 支持：使用 `ipaddress` 标准库的 `version` 属性隔离匹配
8. 前端默认展示时间调整：将默认范围从 24 小时改为 1 小时
9. 后端兜底检测：冷启动时，如数据库无缓存事件则立即进行一次在线 IP 探测，避免公网 IP 显示为空 `--`
10. 全面中文化：将 `.env`/`.env.example` 中的注释翻译为中文，并将系统监测状态描述 "X of Y targets available" 汉化为 "{X} / {Y} 个目标可用"
