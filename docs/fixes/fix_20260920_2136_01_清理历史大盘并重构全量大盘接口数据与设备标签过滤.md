# 修复记录：清理历史大盘并重构全量大盘接口数据与设备标签过滤

## 1. 问题现象
1. Grafana 大盘列表中存在两个 07，多出了一个历史的 `07 服务器与主机监控 (Server & Host Metrics)`；
2. `04 接口流量与健康 (Interface Traffic & Health)` 这里的接口数据全部没有了，设备和站点虽然能选择，但所有接口图表（包括入/出聚合流量、错误包、丢包率、Top 10 端口流量、Top 20 端口利用率、Top 20 错误丢弃）全部 No Data，其他网络大盘也受到波及。

## 2. 根因剖析
1. **多余大盘来源**：
   - 系统前期曾使用统一的 `07 服务器与主机监控`（UID: `nexora-server-metrics`），后拆分为 Linux 与 Windows 独立大盘。
   - 老用户环境持久化卷 `nexora-grafana-data` 中保留了内置 SQLite DB 记录。
   - `monitoring/grafana/provisioning/dashboards/nexora.yml` 配置了 `allowUiUpdates: true`，Grafana 官方机制在此模式下即使文件被删除也不会自动 purge 数据库中的旧大盘，导致列表并存。
2. **接口数据全部消失的五大核心根因**：
   - **核心根因 1（乘空向量）**：代码中引入了 `DEV_JOIN = "* on(instance) group_left(sysName) (last_over_time(sysName{sysName=~\"$device\"}[1d]) * 0 + 1)"`。经实测 VictoriaMetrics 时序库，`sysName` 指标仅存在于少量 H3C 交换机上，全量 Cisco 设备（R1-R4、SW5-SW6 等）在 VM 中根本没有 `sysName` 指标！当右侧查询为空向量时，相乘结果全量变为空（No data）！
   - **核心根因 2（变量断流）**：设备变量 `$device` 之前从 `sysName` 查设备，在 Cisco 站点下查出为空，传递给图表后导致全盘断流；
   - **核心根因 3（反模式 Join）**：底层 SNMP 采集的全部网络时序（`ifOperStatus`、`ifHCInOctets`、`ifHCOutOctets`、`ifInErrors` 等）原生带有完整的 `hostname`、`instance`、`site_name`、`vendor`、`role`、`ifIndex` 标签，直接使用标签选择器 `hostname=~"$device"` 即可实现 100% 确定性过滤，根本不需要外部乘法 Join；
   - **核心根因 4（IF_JOIN 强绑定）**：端口利用率与 Top 排行强乘 `(ifName * 0 + 1)`，一旦接口缺少独立的 `ifName` 时序直接将整个接口丢弃；
   - **核心根因 5（除法精度与缺失）**：端口利用率除法强依赖 `ifHighSpeed`，未考虑百兆口或无 `ifHighSpeed` 的接口。

## 3. 解决方案与修改
1. **`monitoring/grafana/generate_dashboards.py`**：
   - 彻底废除 `DEV_JOIN` 乘法过滤，网络指标统一使用原生 PromQL 标签过滤 `hostname=~"$device"`；
   - 升级设备模板变量 `$device`：改从核心且必定存在的指标（`ifOperStatus|up`）中提取 `hostname`，全面覆盖 Cisco、H3C、Huawei 等所有厂商全量设备；
   - 构造安全 `IF_JOIN`：增加 `or on(instance, ifIndex) (ifOperStatus * 0 + 1)` 兜底，确保有 `ifName` 显 `ifName`，无 `ifName` 也绝不丢弃任何接口；
   - 端口利用率增加速度回退：`(((ifHighSpeed > 0) * 1000000) or (ifSpeed > 0))`；
   - 同步重构 `01 网络总览`、`02 设备详情`、`03 无线专网`、`04 接口流量`、`06 互联网出口` 大盘的 PromQL 与图例；
   - 大盘版本升级至 `24`。
2. **重新编译生成全部 8 个 JSON 大盘**：
   - 运行 `python monitoring/grafana/generate_dashboards.py` 更新全量大盘 JSON。
3. **多余大盘清理指引**：
   - 用户在 UI 勾选多余的 `07 服务器与主机监控 (Server & Host Metrics)` 并点击右上角删除；或通过 API 命令删除旧 UID。
