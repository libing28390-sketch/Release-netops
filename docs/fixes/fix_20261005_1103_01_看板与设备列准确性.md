# 看板与设备列准确性修复记录

## 问题现象

- Grafana 03 在线 AP 为 2、总 AP 无数据时，离线 AP 错显示为 2；02 硬件和 03 无线 AC/AP 面板的说明冗长。
- `/assets/network-devices` 用户启用旧设置中的全部列后需要横向滚动，部分平台/适配诊断字段对日常巡检帮助有限；机柜列可能展示系统标识而非可读名称。

## 根因

- 离线 AP 查询在总量缺失时回退到了在线 AP 计数。
- 旧列偏好可保存整套内部诊断字段，列选择和导出还保留部分低价值字段。
- 设备列表 API 优先读取 `rack_name` 旧字段，没有优先采用资产模型面向用户的机柜 `name`。
- 面板说明暴露过多采集和实现细节。

## 解决方案

- 总 AP 卡片仅查询总量指标；离线数按设备标签对齐总量和在线量，并在输入缺失时不显示结果。
- 缩短 02/03 现有面板说明，保留用户理解读数所需的语义。
- 升级设备列偏好版本，默认启用 13 个核心列，并从主表/导出移除低价值内部字段。
- 机柜显示名优先使用 `racks.name`，保留旧字段兼容回退，并添加 API 回归测试。
- 模拟器经 SNMP 返回的硬件值不因数值异常而重写。

## 风险与回滚方式

- 总量采集缺失时离线数保持无数据，避免错误地把在线数当成离线数。补齐可靠总量指标后，离线值才可计算。
- 列偏好键升版会让已有的全列设置回到紧凑默认列，用户可重新选择允许的列。
- 若发现问题，可回滚本次提交，恢复此前查询、列偏好和机柜名映射；不涉及数据库 schema 或设备配置变更。
