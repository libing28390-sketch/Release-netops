# 资产导入与工作台统计修复记录

## 问题现象

- 资产表格导入遇到 SNMP 超时或识别缓慢时，接口要等整批主机名同步、设备识别和 LibreNMS 纳管完成后才响应；详细模式下单行导入失败也可能影响其他行的结果。
- 工作台设备读取受 /api/devices 默认最多 200 条限制，超过上限时全量统计不准确；总资产数与在线节点数还可能取自不同数据范围。

## 根因

- 导入接口在请求流程中同步执行提交后的网络补全，且页面未请求逐行详细结果。
- 工作台使用单页列表长度代表完整设备数；运营总览使用该列表计算在线数，而资产台账的规范统计来自 /api/assets/summary。

## 解决方案

- 资产导入逐行保存有效记录，失败行隔离回滚；atomic=true 继续维持整批回滚语义。SNMP、主机名识别和 LibreNMS 补全在 HTTP 响应后由 FastAPI 后台任务继续执行，响应标注待补全状态。
- 工作台用轻量分页完整读取设备列表，并校验分页期间总数稳定、无缺页及重复记录；运营总览从共享资产汇总读取总设备数和在线数。
