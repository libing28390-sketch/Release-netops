# 监控平台容器采集端点与数据空白

时间：2026-09-27 20:35（Asia/Shanghai）

## 问题现象

- Grafana 平台健康看板六个指标端点中，Grafana 与 cAdvisor 为 DOWN；容器 CPU、内存、磁盘面板无数据。
- 用户现场 vmagent 请求 `grafana:3000/metrics` 时连接到 `192.168.31.253:10808` 并收到 HTTP 502；cAdvisor 容器反复以退出码 2 重启。
- VictoriaMetrics 存储占用率卡无数据；资源查询使用固定容器名白名单，且六行端点状态不能表达 Docker 容器全量采集情况。

## 根因

- 已确认 vmagent 的 HTTP 请求被代理环境转发到宿主代理，造成 Grafana `/metrics` 抓取失败。
- cAdvisor 命令的 `--disable_metrics` 含 v0.60.6 文档不支持的 `accelerator` 项，和启动退出码 2 相符；现场日志尾部未包含完整首条错误，因此仍需部署后验证。
- 容器资源看板的 PromQL 只匹配九个指定容器名，名单以外容器被漏掉；cAdvisor 当前 DOWN 又使采集数据源不可用。
- VictoriaMetrics v1.103.0 未提供 v1.124.0 才引入的 `vm_total_disk_space_bytes`。

## 解决方案

- 对 vmagent 和 cAdvisor 显式清空大小写 HTTP/HTTPS/ALL proxy 变量，并按内部目标配置 `NO_PROXY`。
- 从 cAdvisor 禁用指标参数中移除不支持的 `accelerator`。
- 资源查询改为按所有非空容器名聚合，并新增动态 `container_last_seen` 观测计数与清单；保留六个 Prometheus 端点的独立状态表。
- VictoriaMetrics 存储面板改为 `sum(vm_data_size_bytes)` 已用数据量，保留独立的磁盘可用空间面板。
