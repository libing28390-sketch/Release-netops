# 修复记录：Dipu/山石配置备份命令与 SMTP 配置界面

## 问题现象
- Dipu 交换机/防火墙配置备份的运行配置命令与设备实际命令不符。
- Hillstone 运行配置命令错误；启动配置需要继续使用厂商指定命令。
- SMTP 配置区加载失败时会完全隐藏，且字段和高级项拥挤；未保存的修改仍可能发起测试，而测试接口读取的是服务端已保存配置。

## 根因
- 平台动作表中的 DPtech 和 Hillstone 命令映射没有按用户提供的设备命令设置。
- 前端没有持久显示 SMTP 配置加载失败状态，也没有区分常用参数与高级参数；测试调用没有阻断未保存的配置修改。

## 解决方案
- DPtech 运行配置映射改为 `show running-config`，startup 保持原有命令。
- Hillstone 运行配置设为 `show configuration`，启动配置设为 `show configuration startup`。
- 更新命令映射测试，覆盖 DPtech ConPlat 交换机/防火墙平台码及 Hillstone 的运行/启动配置。
- 完善 SMTP 配置界面的加载、错误重试、权限状态、字段校验、配置分组和高级项折叠。
- 仅在测试配置已保存、有效且启用时允许发起测试；不返回或展示 SMTP 密码，成功保存后清空密码输入框。
