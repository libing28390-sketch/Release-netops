# 修复记录：双凭据绑定完善与测试回归修复

## 问题现象

1. **资产管理绑定凭据覆盖问题**：绑定 admin 凭据后，之前绑定的 user 凭据显示"未绑定"，两个角色凭据互相覆盖。
2. **凭据管理页面不显示密码**：无法确认设备真实绑定的密码是什么。
3. **多项单元测试失败**：
   - `test_cmdb_phase3_crud.py`：`create_site` 函数已改为自动生成 `SITE-` 前缀代码，测试仍断言传入的 `BJ-DC1`。
   - `test_cmdb_phase4.py`：拓扑观测记录缺少 `match_status = 'matched'`，导致 `rebuild_links_from_observations` 过滤掉测试数据。
   - `test_playbook_platform_aliases.py`：`huawei_vrpv8` 在 scenarios.py 中保持为独立平台键（不再折叠为 `huawei_vrp`），测试期望值过时。
   - `test_templates_and_tag_statistics.py`：模板缓存在测试间泄漏导致 fallback 测试断言 `connection.closed` 失败。
   - `test_outbound_expected_ip.py`：使用 PostgreSQL `%s` 占位符的 SQL 在 SQLite 测试库中报语法错误；且缺少 `isolated_db` fixture 导致表不存在。
   - `outbound_probe_service.py`：整个服务文件使用 PostgreSQL `%s` 占位符，在生产 PgCursor 适配层会自动将 `?` 转为 `%s`，但直接使用 `%s` 在 SQLite 下崩溃。

## 根因

1. **单字段凭据绑定**：`physical_assets` 和 `devices` 表仅有 `credential_id` 一列，无法区分普通凭据和特权凭据。
2. **服务层 SQL 占位符不一致**：`outbound_probe_service.py` 直接使用了 PostgreSQL 的 `%s` 占位符，而系统的 `_PgCursor._adapt()` 方法是将 `?` 转换为 `%s`，即服务层应统一使用 `?`。
3. **测试用例与生产代码演进脱节**：站点代码自动生成、平台别名保留精确键、缓存机制引入等产品变更后，对应测试用例未同步更新。

## 解决方案

### 双凭据独立绑定
- `physical_assets` 和 `devices` 表新增 `admin_credential_id` 列。
- `AssetCreate`/`AssetUpdate` 模型新增 `admin_credential_id` 属性。
- 前端 `AssetModal.tsx` 在双账户模式下渲染"普通账号凭据"与"特权账号凭据"两个独立下拉框。
- `vault_service.resolve_device_credentials` 支持从 `admin_credential_id` 解密特权凭据。
- `credential_service._list_devices_using_rows` 查询改为 `WHERE credential_id = ? OR admin_credential_id = ?`。
- Excel 导入模板新增"绑定特权凭据"列。

### outbound_probe_service.py 占位符统一
- 全文件 `%s` → `?`，保留 `logger.error` 中的 Python 格式化 `%s`。

### 测试修复
- `test_cmdb_phase3_crud.py`：断言 `site_code.startswith("SITE-")`，唯一性约束改为通过 `update_site` 验证。
- `test_cmdb_phase4.py`：插入观测记录时显式设置 `match_status = 'matched'`。
- `test_playbook_platform_aliases.py`：`huawei_vrpv8` 期望值改为 `huawei_vrpv8`。
- `test_templates_and_tag_statistics.py`：新增 `autouse` fixture 在每个测试前调用 `_invalidate_templates_cache()`。
- `test_outbound_expected_ip.py`：`%s` → `?`；两个需要数据库的测试添加 `isolated_db` fixture。

### SQLite 迁移兼容
- `m0024`：动态 `{placeholder}` 替代硬编码 `%s`。
- `m0025`：SQLite 分支使用 `PRAGMA table_info` 替代 `information_schema`；跳过 `ALTER COLUMN TYPE`。
- `m0026`：SQLite 环境直接跳过。

- `test_asset_production_takeover.py`：站点不存在的测试 seed 问题，与本次变更无关。

## 风险与回滚方式

- 本次变更向后兼容：`admin_credential_id` 列默认 NULL，未绑定特权凭据的资产行为不变。
- 回滚：`git revert HEAD` 即可撤销全部修改。
