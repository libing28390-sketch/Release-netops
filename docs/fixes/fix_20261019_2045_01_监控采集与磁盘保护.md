# 监控采集与磁盘保护提交记录

## 问题现象与提交目的

汇总本轮已完成的监控管理改进：采集器状态探测与界面信息精简、启停配置同步、VictoriaMetrics 磁盘阈值持久化及 `.env` 安全同步，以及 cAdvisor 启动时可能早于 Docker API 就绪而丢失容器指标的问题。将相应源代码、测试和项目文档提交到长期分支 `main`。

## 根因与解决方案

- 采集器启用字段在 API 中需按 PostgreSQL 整数列规范化；停用本地采集器时，运行配置应同步为空目标配置。
- VictoriaMetrics 阈值需要在 UI、持久运行配置和主机 `.env` 之间安全同步，并对容器重启和配置失败提供状态。
- Compose 过去只等待 Docker Socket Proxy 启动，未等待 Docker API `/info` 就绪；cAdvisor 启动过早会导致 Docker factory 初始化失败。现在通过健康检查和 `service_healthy` 依赖约束启动顺序。

## 实际修改范围

- 采集器 API、自动同步、前端管理页面及相关测试。
- VictoriaMetrics 存储阈值 API、运行配置 supervisor、主机 `.env` 同步 helper、部署脚本、Compose、参数文档和测试。
- Docker Socket Proxy/cAdvisor 启动依赖和部署契约测试。
- 对应的 `docs/plans/`、`docs/walkthrough/` 和本提交记录。

不纳入提交：`.codex-*`、`dist-*` 构建/部署校验目录、`logs/` 运行日志和生成的 `dist/index.html`。后者引用的 bundle 未作为源文件入库，发布应从源码重新构建。

## 风险与回滚方式

- 存储保护阈值变更会重启 VictoriaMetrics，期间指标写入短暂中断；已有存储卷保留。
- 停用本地采集器会应用空目标配置；重新启用会触发配置同步。
- 启动健康检查失败时 cAdvisor 会等待 Docker API 可用；不影响既有 VictoriaMetrics 数据卷。
- Git 回滚可 revert 本提交；目标机回滚可使用 `/var/backups/nexora/collector-enable-20261019T122318Z` 中的代码/Compose/dist 备份及旧镜像标签，并只重建相关服务。
