# Git 变更记录: 优化 TextFSM 自动骨架生成与智能验证指标

## 1. 问题与优化背景
之前的自动 TextFSM 生成逻辑虽然能识别简单表格，但在复杂的真实多厂商 CLI 回显（如含有前导空格、包含特殊符号的分隔线、包含空格的描述字段、列与列之间仅单空格分隔、重复列名）时，自动匹配的准确度不够，且用户无法直观看到当前生成的解析模板究竟能成功匹配多少行。

## 2. 解决方案与实施步骤
我们全面重构并强化了 [textfsm_builder_service.py](file:///d:/netops/netsops-main/backend/services/textfsm_builder_service.py)：
1. **保留行首/行尾空格**：改为使用 `rstrip()` 保留每一行的前导空格，保证依赖列对齐的复杂 CLI 回显数据判定不失真；
2. **表头概率打分模型**：实现了基于评分机制的表头检测器，打分项涵盖：下一行是否为分隔线（+10）、是否存在多列分割（+3）、包含关键字的个数加分、包含特定格式数据（如 IP 地址、MAC、up/down 关键字）扣分，防止数据行误判为表头；
3. **分隔线正则拓宽**：采用更通用的正则来解析包含加号、空格、等号或管道符的分隔线，如 `----+----+----` 等形式；
4. **智能列拆分与去重**：表头列首选以双空格及以上进行切割，并且若发现重复列名（如多个 `Status`），将自动附加序号后缀（`STATUS`, `STATUS_2` 等）防止丢失字段；
5. **智能变量正则推断**：自动分析列名：IP 相关采用 IP 正则，MAC 采用 MAC 正则，VLAN/ID/Priority/Metric 自动采用数字正则 `(\d+)`，Description/Name/Message 采用非贪婪 `(.+?)` 匹配，最后一列也默认采用 `(.+?)` 以完全捕获该行末尾的带空格参数；
6. **自动添加表头跳过规则**：模板中自动排除并精确跳过表头和分割线，避免解析结果的第一行混入表头名称，且在行尾统一生成 TextFSM 标准要求的双 `$$`；
7. **实时自验证解析**：生成模板字符串后，内联使用 `textfsm` 库直接试解析样本，统计：成功匹配的结构化记录、候选数据行数、精确匹配率并记录在返回字典中。

同时，我们升级了前端 **[TextFSMDebugger.tsx](file:///d:/netops/netsops-main/src/pages/AutomationExecute/components/TextFSMDebugger.tsx)** 的交互：
*   当调试器开启或自动生成时，立即回显匹配结果网格预览，免去手动点击测试；
*   在顶部展示匹配率、匹配行数及可能存在的分析警告，交互体验极致流畅。
