# 知识引擎 V2 灰度切换、DeepSeek 适配与 Copilot 体验优化

## 问题现象

1. **知识引擎 V2 缺少细粒度灰度与热切换控制**：
   - MIG-010 ~ MIG-013 阶段需要按角色、内测用户、站点和百分比进行多维灰度控制，并在出现异常时支持毫秒级无损降级回 V1。
2. **DeepSeek 模型连通性测试误报模型不存在**：
   - 供应商管理配置官方模型 `deepseek-chat` / `deepseek-reasoner` 时，因驱动内白名单限制过窄报 `AI_MODEL_NOT_FOUND`，并触发 `AI_HEALTH_BACKOFF` 熔断冷却。
3. **Copilot 通用问答拒答与 Trace 数据缺失**：
   - 用户提问通用问题（如系统时间、常识）被机械式拒答，且误展示网络设备诊断卡片；
   - 开发者 Trace 面板中路由模型、Token 开销及耗时未完全传递导致显示“未上报”。
4. **知识库管理页面排版受限**：
   - 左侧 25% 占位的遗留物理目录树挤压文档列表表格，不符合当前基于 Front Matter 元数据驱动的检索设计。
5. **前端部分组件与测试环境兼容性**：
   - `pytest.ini` 顶层缺少 root pythonpath 支持；部分组件图标类型在 React 19 / TS 严格检查下需提升兼容性。

## 根因

1. 缺少集中的 `feature_flag_service` 判定引擎与运行时配置热切换能力。
2. `DeepSeekProvider` 仅静态限制了 `deepseek-v4-flash` / `deepseek-v4-pro`，未兼容官方主模型名称。
3. System Prompt 过于严苛限制且未注入当前系统时间；`build_copilot_contract` 无差别生成网络设备 missing 字段；前端 SSE 消息处理未完整保存 `route_meta`。
4. 知识库页面仍保留两栏布局，未完全迁移至全宽元数据表格。

## 解决方案

1. **灰度与影子运行**：
   - 新增 `backend/ai/services/feature_flag_service.py`，支持角色、用户、站点、百分比灰度及热切换；
   - 完善 `rag_retriever.py` 与 `assistant.py` 中的灰度路由与影子比对 trace 记录；
   - 补充 `test_mig011_feature_flag_rollout.py` 自动化测试，更新清单 `16-development-master-checklist.md`。
2. **DeepSeek 模型扩展**：
   - `backend/ai/providers/deepseek.py` 扩展模型白名单，支持 `deepseek-chat`、`deepseek-reasoner`、`deepseek-coder`、`deepseek-v4-*` 及通用前缀校验；
   - 补充 `test_deepseek_contract.py` 单测。
3. **Copilot 通用问答与 Trace 优化**：
   - `assistant.py` 注入真实系统时间，优化 System Prompt 区分常识问答与设备事实；
   - `copilot_contract.py` 仅在网络诊断意图下生成设备缺失字段与排障建议；
   - `AssistantTab.tsx` 与 `CopilotInspectorDrawer.tsx` 完整记录并展示 Route Model、Token 开销与耗时。
4. **知识库界面全宽升级**：
   - `KnowledgeManagementTab.tsx` 移除左侧物理目录树，全宽展示多维元数据过滤与文档管理表格。
5. **类型与测试环境修整**：
   - 修正 `pytest.ini`，优化前端组件图标类型，确保全量测试与 lint 畅通。

## 未验证项

- 暂未在真实硬件设备集群上直接运行高并发 LLM 压力测试；
- 生产环境真实多租户 PostgreSQL 灰度写入需在发布后结合监控观察。

## 风险与回滚方式

- 灰度判定服务具备异常捕获保底（Fail-Safe），一旦判定出错自动降级为 V1 检索路径，不影响主流程；
- 若需完全关闭 V2，只需在环境变量中设置 `KNOWLEDGE_V2_ENABLED=false` 即可秒级全局停用 V2。
