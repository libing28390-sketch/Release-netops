# 前端构建进度与公有发布同步

## 问题现象

- Docker BuildKit 中 Vite 模块转换期间长时间只有 `transforming...`，不易判断构建是否仍在运行。
- `package.json` 的 build 命令改为依赖 `scripts/build-frontend.mjs` 后，发布工作流的公有树清理白名单若未保留此文件，公有仓库的 Docker build 会因脚本缺失失败。

## 根因

- Vite 默认不会在模块转换过程中周期性输出进度；BuildKit 只能显示 RUN 步骤持续时间。
- `.github/workflows/release.yml` 对 `scripts/` 使用显式保留清单。公有仓库已有其他运行脚本，但新增构建包装器必须单独加入清单及必需发布输入校验。

## 解决方案

- 用 Node 包装器运行 Vite 并每 10 秒输出存活时间；Vite build 插件每处理 250 个模块报告一次进度。
- 让 Dockerfile 调用 `npm run build`，统一本地与镜像构建入口。
- 在 `.github/workflows/release.yml` 的源输入检查、公有树保留清单和清理后必需文件校验中纳入 `scripts/build-frontend.mjs`。公有仓库仍仅由 `release.yml` 同步，不直接推送公有仓库。

## 风险与回滚方式

- 若包装器在目标容器 Node 版本出现兼容问题，可回滚 `package.json` 与 `Dockerfile` 的入口、移除对应进度插件与包装器，并从发布工作流三处清单移除该文件。
- 若发布工作流失败，公有仓库不会自动达到目标状态；修正失败步骤后重推同一 tag 触发重试。按用户授权，`v1.0.9` 可强制更新；回滚时将 tag 恢复到发布前指向的代码提交 `0a8a96d3e5a14abf289503cc3510b0a54db7b653` 并推送。
