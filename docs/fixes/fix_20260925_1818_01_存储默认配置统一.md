# 存储默认配置统一

## 问题现象 / 本次目的

对象存储设置仍暴露用途级 provider、Bucket 覆盖和前缀等日常配置，并让用户填写 Region；产品现已收敛为一个全局默认 S3 配置和固定用途前缀。

## 根因

存储 UI 沿用了用途路由管理模型，配置备份和 PAM 录像可以独立选择 provider 与 Bucket，与当前简化后的全局默认契约不一致。

## 解决方案

- 移除前端用途路由设置，只保留存储配置管理；Region 不再要求用户填写。
- 新增迁移将现有用途绑定统一为全局默认，清理用途级 provider/Bucket 覆盖并保留既有 key 前缀。
- 更新 Docker 部署文档，说明 SeaweedFS 本地默认配置和共用默认存储行为。

## 风险与回滚方式

- `m0251` 的 downgrade 是 no-op；一旦部署环境应用该迁移，旧用途级 provider 与 Bucket 覆盖不能通过迁移自动恢复。应用迁移前可回滚代码；应用后如需恢复旧设置，应先从部署备份中恢复绑定数据，再部署兼容代码。
- 已写入对象的 provider、Bucket 和 key 不因本迁移移动；变更只影响后续写入。
