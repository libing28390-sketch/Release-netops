# 修复 PostgreSQL 拓扑链路重建

## 问题现象

Docker 环境显示 5 台设备但 0 条链路。拓扑状态显示设备采集成功、邻居匹配成功，但手动发现任务状态为 `failed`，`total_links` 为 0。

## 根因

拓扑重建读取 `interfaces.name_display`，而旧生产基线表只包含 `interface_name` 等早期字段，导致 PostgreSQL 查询异常。异常发生在发布 `topology_links` 前，因此所有已匹配邻居都无法生成链路。

## 解决方案

- 新增迁移 `m0023_interface_identity_fields`，幂等添加 `name_raw`、`name_display`、`primary_ip`、`ip_address`、`ip_prefix_length`、`ip_version`、`is_l3`、`last_change`、`last_seen`、`lag_id`、`vlan_mode`。
- 将历史记录的 `interface_name` 回填到 `name_raw` 和 `name_display`。
- 同步更新新数据库基线，避免新部署再次缺字段。

## 验证

- Python 编译检查通过。
- Schema migration 相关测试通过。
- 拓扑服务测试除一个既有的自动刷新间隔断言外通过；该断言与本次迁移无关。

## 部署与回滚

```bash
docker compose down --rmi local
docker compose build --no-cache
docker compose up -d
```

不要使用 `docker compose down -v`。新增字段和回填均可重复执行，不删除已有设备、凭据或拓扑观察数据。
