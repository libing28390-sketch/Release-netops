# 修复记录 - 修复 CI 异步测试报错与统一全量容器北京时间

## 1. 问题现象
1. **GitHub Actions CI 报错**：CI 在运行 `Backend Pytest Check` 时，`backend/tests/topology/test_snmp_lldp_discovery.py` 中 4 个测试用例失败，报错 `Failed: async def functions are not natively supported. You need to install a suitable plugin for your async framework`，且伴随 `PytestUnknownMarkWarning: Unknown pytest.mark.asyncio` 警告。
2. **容器时区不一致**：排查 Docker 生产部署发现，Nginx Alpine 基础镜像未安装 `tzdata`，导致设置的 `TZ=Asia/Shanghai` 失效并回退为 UTC 时间；监控栈各服务（VictoriaMetrics、vmagent、snmp-exporter、Grafana）未声明 `TZ` 环境变量，导致相关容器进程与日志均按 UTC 时间记录。

## 2. 根因分析
1. **CI 异步测试**：CI 环境依赖安装为 `pip install -r backend/requirements.txt` 和 `pip install pytest`，未包含 `pytest-asyncio`。全仓其余 2,252 个测试均统一使用标准同步函数 `def test_*():` + `asyncio.run(...)` 调用，只有该新测试文件使用了 `@pytest.mark.asyncio` 与 `async def test_*`。
2. **容器时区**：
   - Alpine Linux (musl libc) 必须安装 `tzdata` 包才能解析并加载 `/usr/share/zoneinfo/Asia/Shanghai`，否则强制回退为 UTC。
   - `docker-compose.yml` 中新增的监控组件（`victoriametrics`, `snmp-exporter`, `vmagent`, `grafana`）未注入 `TZ` 环境变量与 Grafana 仪表盘默认时区配置。
   - `docker/postgres/Dockerfile` 未在系统层安装 `tzdata`。

## 3. 解决方案
1. **重构测试用例**：
   - 在 `backend/tests/topology/test_snmp_lldp_discovery.py` 中移除 4 处 `@pytest.mark.asyncio`，改为普通 `def` 函数，内部使用 `asyncio.run(...)` 调用协程，与全仓既有规范保持一致。
2. **统一容器北京时间**：
   - `docker-compose.yml`：为 `victoriametrics`、`snmp-exporter`、`vmagent` 注入 `TZ=${TZ:-Asia/Shanghai}`；为 `grafana` 注入 `TZ=${TZ:-Asia/Shanghai}` 和 `GF_DATE_FORMATS_DEFAULT_TIMEZONE=${GRAFANA_DEFAULT_TIMEZONE:-Asia/Shanghai}`。
   - `nginx/Dockerfile`：安装 `tzdata`，配置 `/etc/localtime` 与 `/etc/timezone`，声明 `ENV TZ=Asia/Shanghai`。
   - `docker/postgres/Dockerfile`：安装 `tzdata`，配置 `/etc/localtime` 与 `/etc/timezone`，声明 `ENV TZ=Asia/Shanghai`。
   - `Dockerfile`：补充 `/etc/localtime` 与 `/etc/timezone` 软链接。
