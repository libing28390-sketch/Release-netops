# SNMP 优先拓扑采集与未匹配邻居识别

## 问题现象

拓扑发现可能使用 SNMP 成功采集邻居，但状态仍记录为 SSH；SNMP 无邻居时回退 CLI 的原因不易从日志判断，瞬时失败重试日志缺少参数；关联资产上维护的管理 IP/序列号没有参与邻居匹配，未匹配节点也容易被误解成 CMDB 中不存在。

## 根因

采集状态的传输类型写死为 SSH，SNMP 回退路径缺少可诊断日志，重试日志格式参数不完整，身份比对只查 `devices` 字段。

## 解决方案

- 按实际采集方法记录 SNMP/SSH 传输状态，并记录无 SNMP 凭据、无有效邻居和回退原因；失败元数据包含已尝试的方法。
- 补齐重试日志 `run_id` 参数。
- 邻居匹配联合关联 `physical_assets.management_ip` 和 `serial_number`。
- 以灰阶设备图标和明确提示展示已发现但未匹配 CMDB 的交换机邻居，不按编号相似度自动合并设备。
