# 合并 AI 迁移与配套修改

## 问题现象

`netsops-main` 启动时严格迁移历史检查报 `unknown=(204, 205, 206, 207, 208)`。数据库已经记录这些版本，但主工作区缺少对应迁移模块；隔离工作区还包含与这些模板配套的 AI/RAG、评测、CI、前端和发布修改。

## 根因

主工作区停留在来源提交 `3b6eb0ff`，而隔离工作区已在其后完成连续 12 个 AI/RAG 与发布修复提交，并产生了未提交的官方模板迁移、四厂商知识包、评测脚本/证据及相关测试。代码发现范围与 PostgreSQL `schema_migrations` 历史不一致，严格模式按设计拒绝启动。

## 解决方案

- 将来源工作区从 `main` 之后的全部已提交修复及本轮全部可追踪后续修改纳入 `main`。
- 纳入 `m0204`–`m0208` 五个 PostgreSQL 幂等官方模板迁移、官方模板投影和检索配套实现、评测与知识包、CI/发布配置、Windows pgvector 支持、前端契约和测试。
- 在 `.agents/AGENTS.md` 与 `docs/architecture/git_workflow_standard.md` 固化单一 `main` 工作流：不创建或切换功能分支，临时工作树只作传输，合入后清理临时分支引用。
- 合并过程中保留 `netsops-main` 原有用户未提交文件和生成资源，不重置数据库历史，不执行远端推送。

## 实际修改文件

- 数据库迁移：`backend/database/migrations/m0204_*` 至 `m0208_*`。
- AI/RAG、安全、评测、官方模板投影服务及对应 `backend/tests/ai/` 回归测试。
- `data/kb_import/` 四厂商来源包、评测数据/脚本、CI 工作流和发布/Windows 配置。
- 前端 AI API、Copilot、知识库评测面板及测试，`desktop/` pgvector 支持。
- `.agents/AGENTS.md`、`docs/architecture/git_workflow_standard.md`、本次计划和交接/验证文档。

## 验证命令与结果

来源工作区合入前的 PostgreSQL 聚焦回归已通过：

- `pytest --confcutdir=backend/tests/ai backend/tests/ai/test_official_anchor_management_templates.py backend/tests/ai/test_official_cisco_hsrp_template.py backend/tests/ai/test_official_template_projection.py -q`：`12 passed`。

主工作区合入后还需复核迁移计划/严格历史检查（目标为 `unknown=()`、`pending=()`、`name_drift=()`、`safe=True`）、AI/RAG 聚焦回归、Python 编译、前端 lint/测试/构建、`git diff --check` 及开发初始化路径。

## 未验证项

- 未获得用户授权前不推送远端、不触发 GitHub Actions；真实生产迁移、回滚和外部 Sidecar/Provider 仍按交接阻塞项处理。

## 风险与回滚方式

- 迁移只做幂等官方模板 upsert；失败时依赖 PostgreSQL 事务回滚，不删除既有迁移记录。
- 主工作区原有改动通过 Git stash/恢复保护；若合入验证失败，可将 `main` 回退到合并前 SHA 并恢复保存的工作区状态。
