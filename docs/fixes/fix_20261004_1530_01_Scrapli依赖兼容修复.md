# 修复 v1.0.9 发布门禁中的 Scrapli 依赖漂移

## 问题现象

提交 `f60c00f6bd8fde28fd40691349d396379d91f97f` 的 GitHub Actions 后端门禁在 pytest collection 阶段失败，22 个模块无法导入。Promptfoo 初始化同一后端应用时，50 条用例全部报 `evaluation_error`。

## 根因

`backend/requirements.txt` 仅设置了 `scrapli>=2024.1.30`。CI 在 2026-10-04 安装到 Scrapli `2026.10.3`，该版本没有导出代码当前使用的 `from scrapli import Scrapli`。此前本机安装的 `2026.2.20` 保留该 API，因此本机定向验证未复现。

## 解决方案

将 Scrapli 固定到已在本机验证、兼容现有驱动和 API 导入路径的 `2026.2.20`，保持 `scrapli-community` 现有约束。

## 验证命令与结果

- `.venv/Scripts/python.exe -m pytest --collect-only -q backend/tests`：3,189 tests collected，exit 0。
- 本机 Scrapli 版本：`2026.2.20`；`from scrapli import Scrapli` 可导入。
- `PYTHONPATH=backend .venv/Scripts/python.exe -m pytest -q backend/tests/vendor_audit/test_raisecom_ros_support.py`：3 passed。
- 远端完整后端测试、Promptfoo 评测及 Docker 发布构建需随修复后的 tag Actions 重跑。

## 未验证项

完整后端测试执行结果、Promptfoo 评测结果、Linux/Docker 与 Windows Agent 构建尚待 GitHub Actions 确认。本机没有 Docker。

## 风险与回滚

新 Scrapli API 暂不兼容现有工厂导入路径；升级时应先迁移并测试两个当前导入点，再调整版本约束。
