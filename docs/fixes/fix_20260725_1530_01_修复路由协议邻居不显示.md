# Fix Record - 修复路由协议邻居不显示

## 问题现象
在自动化诊断/即时设备查询页面，当点击“BGP邻居”与“OSPF邻居”标签时，由于查询结果被后台策略过滤，响应始终为空，且终端或日志中包含 TextFSM 模板解析华三设备时抛出的 `State Error`。

## 根因
1. 背景轮询采集计划默认对 BGP/OSPF 等耗资源的动态路由协议处于关闭状态，而手动触发即时操作数据的 API endpoint 未传递重写参数以允许跳过默认过滤规则。
2. `h3c_comware_display_ospf_peer.textfsm` 模板存在匹配前导空格失配、字段名映射顺序颠倒、无法匹配含空格的 `Full/ -` 状态，以及包含 `^. -> Error` 兜底导致崩溃的缺陷。
3. `hp_comware_display_bgp_peer_ipv4.textfsm` 官方模板未支持新 comware 版本的 link-local 提示行，导致其崩溃报警。

## 解决方案
1. 在 `backend/api/devices.py` 的 `/devices/{device_id}/operational-data` 路由中，调用 `collect_operational_data` 时添加传递参数 `policy_override_categories=set(categories)`。
2. 重写 `h3c_comware_display_ospf_peer.textfsm` 模板正则、匹配顺序并使用安全匹配行。
3. 新增 `hp_comware_display_bgp_peer_ipv4.textfsm` 自定义覆盖模板以消除 builtin 模板报错警告。
