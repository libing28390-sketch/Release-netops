# 修复记录：大盘接口全称展示、站点与设备下拉列表补全及 Linux 主机采集打通

## 1. 问题现象
1. **接口未展示全称且误显百分比索引**：Top 20 表格中只有 `管理 IP` 和 `端口索引`，且数值为 `3%`、`4%` 等，未展示接口全称（如 `GigabitEthernet0/0/1`）；
2. **所有 Dashboard 的「站点」和「设备」下拉菜单展开后只有 `All`**，无法选择具体的站点和设备；
3. **`07 Linux 服务器监控` 无法获取到数据**：用户在部署 Linux 宿主机（`192.168.204.128`）上已成功运行 `node_exporter`（9100），但 Grafana 显示 No data。

## 2. 根因分析
1. **表格字段格式化与列排除缺陷**：
   - 表格原本未排除 `ifIndex`，且 `fieldConfig.defaults.unit = "percent"` 导致数字 `3` 被 Grafana 格式化为 `3%`；
   - PromQL 聚合未聚焦于 `ifDescr` 与 `ifName`；
2. **Docker 持久卷阻断配置同步导致时序指标缺少业务标签**：
   - Linux 宿主机上 Docker 容器挂载的 volume `nexora-monitoring-artifacts` 中，之前存放的是未包含 `hostname`、`site_name` 的旧配置；
   - 启动脚本 `sync-frontend-dist.sh` 之前仅在文件不存在时复制 defaults，导致代码更新后持久卷未同步，入库数据缺少 `site_name` 和 `hostname`，Grafana 的 `label_values(..., site_name)` 查不出选项；
3. **vmagent 缺少对宿主机 `node_exporter` 的采集 Job**：
   - `scrape.yml` 之前未配置 `192.168.204.128:9100`，vmagent 未发起抓取。

## 3. 解决方案与实施
1. **大盘展示与格式化修复 (`generate_dashboards.py`)**：
   - 彻底在表格中排除 `ifIndex`，将 `ifDescr` 映射为 `接口全称`，`ifName` 映射为 `接口名称`；
   - 采用 `fieldConfig.overrides` 专门为指定数值列赋予单位（`unit`），默认设置为 `none`，彻底消除 `3%` 的格式化错误；
   - Top 表格 PromQL 聚合维度调整为 `by (hostname, instance, ifDescr, ifName)`；
   - 重新生成全量 8 个大盘 JSON；
2. **容器启动自动同步运行时卷 (`sync-frontend-dist.sh`)**：
   - 改进同步逻辑：当未发布独立版本时，容器启动时自动将 defaults 下的最新的 targets 和 snmp.yml 刷新进运行时卷，确保业务元数据标签生效；
3. **打通 Linux 主机监控 (`scrape.yml`)**：
   - 新增 `linux_nodes` 作业，抓取 `192.168.204.128:9100` 并自动注入 `hostname: "devops"`, `site_name: "本地开发机"`, `role: "server"`。
