# 迁移 MIB 同步服务至 Service 层并保留发布脚本修复记录

## 1. 问题现象
用户在服务器（基于 `Release-netops` 部署目录）运行或上传 MIB 时抛出异常：
`RuntimeError: Cannot locate backend/scripts/sync_librenms_mibs.py module`

## 2. 根因分析
1. **发布工作流清理脚本**：在 `.github/workflows/release.yml` 构建发布至客户发布仓库 `Release-netops` 的过程中，存在历史清理规则 `rm -rf backend/scripts/`，导致构建发布分支时 `backend/scripts/` 目录被整个删除。
2. **核心业务逻辑未归入 Service 层**：`sync_librenms_mibs.py` 原本包含完整的 LibreNMS 符号索引构建、Sparse-checkout 获取与 MIB 递归解析入库核心逻辑，应作为平台核心服务下沉在 `backend/services/` 层，而不是单纯作为开发脚本存在。

## 3. 解决方案
1. **创建核心服务 `librenms_mib_service.py`**：
   - 新建 `backend/services/librenms_mib_service.py`，完整实现 `import_mibs_from_directory`、`fetch_librenms_mibs`、`build_symbol_index` 等所有业务逻辑。
   - `backend/services/` 属于核心服务层，在发布流程中始终完整保留，永不被排除。
2. **API 模块直接引用服务**：
   - 将 `backend/api/devices.py` 中的 MIB 导入逻辑直接改为 `from services.librenms_mib_service import import_mibs_from_directory, fetch_librenms_mibs, MIBS_DIR, TARGET_DIR`。
3. **CLI 包装脚本与发布工作流对齐**：
   - `backend/scripts/sync_librenms_mibs.py` 精简为对 `services.librenms_mib_service` 的 CLI 调用包装。
   - 更新 `.github/workflows/release.yml`，移除 `rm -rf backend/scripts/` 清理指令，使发布包同样保留所有运维管理脚本。
