# 修复 H3C Comware 链路聚合动作映射与数据库迁移

## 问题现象
部分 H3C 设备在资产导入或厂商/平台同步时，默认回退映射到了旧版的 `hp_comware` (Comware V5) Profile，导致平台动作集中缺失规范化的 `h3c_comware` (Comware V7) 链路聚合采集动作 `get_link_aggregation`。采集器在执行拓扑采集时提示 `unsupported_by_platform`，造成 H3C 设备拓扑链路聚合数据无法正常展示。

## 根因分析
1. `backend/api/assets.py` 中的 `_platform_from_vendor` 函数对仅指定 `H3C` 或 `Comware` 的厂商映射默认返回了 `hp_comware`，未对齐当前的 `h3c_comware` 规范。
2. 前端 `src/pages/AssetManagement/constants.ts` 的 `IMPORT_VALUE_MAP` 将无版本号的 `'H3C Comware'` 映射为了 `hp_comware`。
3. `backend/database/migrations/m0115_topology_graph_completion.py` 中的 `_seed_protocol_actions` 未包含 `get_link_aggregation` 动作。
4. 历史版本升级后，存量数据库中已发布 SYSTEM 版本的 `h3c_comware` Profile 缺少 `get_link_aggregation` 动作记录。

## 解决方案
1. **API 默认映射修正**：修改 `backend/api/assets.py` 的 `_platform_from_vendor`，将 `h3c` / `comware` 默认映射至 `h3c_comware`；保留显式声明 V5 的 legacy 映射。
2. **前端导入模板映射修正**：修改 `src/pages/AssetManagement/constants.ts` 中的 `IMPORT_VALUE_MAP`，将 `'H3C Comware'` 默认映射至 `h3c_comware`。
3. **拓扑迁移补充**：更新 `m0115_topology_graph_completion.py`，在 `_seed_protocol_actions` 中补齐 `get_link_aggregation` 动作的初始化。
4. **新增修复迁移脚本**：创建增量及幂等迁移 `backend/database/migrations/m0128_repair_h3c_aggregation_actions.py`，修补存量数据库中 SYSTEM 发布的 `h3c_comware` 缺失动作及 checksum。
5. **单元测试与回归**：新增 `backend/tests/database/test_m0128_repair_h3c_aggregation_actions.py` 验证迁移修复逻辑。
