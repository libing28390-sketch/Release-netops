# 修复记录：拓扑全厂商聚合口适配与右侧面板下线

## 1. 问题现象
1. **拓扑全厂商聚合口 (LAG) 识别不完整**：
   - 华三采用 `Link-Aggregation` / `Bridge-Aggregation` / `BAGG`，华为采用 `Eth-Trunk` / `Trunk`，思科采用 `Port-channel` / `Bundle-Ether` / `Po` / `BE`，锐捷采用 `AggregatePort` / `Ag`，瞻博采用 `Aggregated-Ethernet` / `ae`，通用系统采用 `bond` / `team` / `aggr`。
   - 原代码中识别聚合口的正则和映射仅覆盖了思科 `Port-channel` 和华三部分 `BAGG`，缺少华为 `Eth-Trunk`、锐捷 `AggregatePort`、思科 IOS-XR `Bundle-Ether`、华三 `Link-Aggregation` 以及瞻博 `ae` 等，导致多厂商混合拓扑中聚合链路无法被正确归类、折叠与格式化展示。
2. **拓扑页面右侧抽屉占用大面积画布空间**：
   - 拓扑图右侧的详情抽屉（`TopologyInspectorPanel`）挤占了拓扑图的显示空间，信息存在冗余，用户明确要求将其删除，实现画布全屏展示。
3. **采集模块定位疑问**：
   - 用户咨询 `/monitor/modules` 是否还有意义，或者是否缺少全部厂商支持。

## 2. 根因分析
1. **聚合口前缀规范未涵盖全厂商**：
   - `backend/core/interface_utils.py` 的接口别名映射中缺少 `link-aggregation`、`aggregateport`、`ethtrunk`、`bundleether` 等键值。
   - `backend/services/topology_service.py` 的聚合口正则判定 `_is_logical_aggregation_interface` 与家族提取 `_aggregation_family_key` 原本仅支持 `(po|port-channel|bagg|bridge-aggregation|lag|agg)`，漏掉了华为 `eth-trunk`、锐捷 `aggregateport`、思科 XR `bundle-ether`、瞻博 `ae`、华三 `route-aggregation` 以及 Linux `bond/team`。
   - 前端 `topologyFormatters.ts`、`topologyCore.ts` 与 `TopologyGraph.tsx` 中的端口缩写与正则同样缺失对应前缀，导致画布连线标签上无法紧凑呈现这些厂商的聚合口。
2. **拓扑页面布局与抽屉组件绑定**：
   - `TopologyPage.tsx` 使用响应式两列网格布局，并在节点或链路选中时自动展开 `TopologyInspectorPanel`，造成画布宽度收缩。

## 3. 解决方案
1. **后端全厂商聚合口扩展与规范化**：
   - 在 `backend/core/interface_utils.py` 中补充全厂商别名；
   - 在 `backend/services/topology_service.py` 中更新逻辑聚合口正则与家族匹配，全面支持华三、华为、思科、锐捷、瞻博、迪普、山石和 Linux/服务器聚合口；
   - 编写并执行 Python 单元测试，确保各厂商聚合口全量命中且家族提取准确。
2. **前端聚合口紧凑格式化与连线气泡适配**：
   - 在 `src/utils/topologyFormatters.ts` 中增强 `formatTopologyPort`，将全厂商长名称规范缩写为 `BAGG`、`RAGG`、`Eth-Trunk`、`Po`、`BE`、`Ag`、`ae` 等；
   - 在 `src/utils/topologyCore.ts` 与 `src/components/TopologyGraph.tsx` 中更新端口归一化与连线标签显示。
3. **彻底下线拓扑图右侧抽屉面板**：
   - 修改 `src/pages/TopologyPage.tsx`，移除 `TopologyInspectorPanel` 引入与渲染；
   - 移除 `inspectorOpen` 状态与切换按钮；
   - 画布容器调整为全宽单列弹性布局，画布面积提升 100%。
