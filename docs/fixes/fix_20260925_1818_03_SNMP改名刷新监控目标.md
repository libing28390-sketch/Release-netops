# SNMP 改名刷新监控目标

## 问题现象

资产名称通过 SNMP sysName 同步并写入数据库后，Grafana 设备筛选仍可能读取旧的 `hostname` 指标标签。

## 根因

SNMP 单台/批量同步、发现持久化、后台监控和运行数据采集会更新数据库 hostname，但部分路径没有在事务提交后安排监控采集目标重新编译和发布。

## 解决方案

- 新增 hostname 变化判断与防抖调度 helper。
- 覆盖所有已找到的 SNMP hostname 更新路径，只在名称改变且事务提交后触发。
- 批量同步在整批完成后最多调度一次；未变更时不触发。

- `backend/services/snmp_discovery_service.py`

## 验证命令与结果

- `rg -n "sync_device_hostname_metadata|sync-hostname|batch-sync-hostname" backend`：识别并复核 SNMP 发现、后台监控、运行数据采集及单台/批量 API 路径。
- 审阅对应代码 diff：调度发生在提交之后，批量同步只从已变更结果中调度一次。
- 未运行 pytest 或其他测试命令；本次未请求测试验证。

## 风险与回滚方式

- 异步目标编译或发布失败时，现有采集配置继续运行并记录调度告警；可手动触发目标同步或回滚后端代码。
- VictoriaMetrics 中历史 hostname 序列可能在保留期或查询范围内继续显示。
