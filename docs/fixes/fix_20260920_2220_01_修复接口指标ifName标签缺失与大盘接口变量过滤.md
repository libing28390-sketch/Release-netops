# 修复接口指标 ifName 标签缺失与大盘接口变量过滤修复记录

## 1. 问题现象
在 Grafana `04 接口流量与健康 (Interface Traffic & Health)` 大盘中：
1. 用户在表格中点击 `Et0/0` 接口右侧的 `Filter for value`；
2. Grafana 顶部生成了 Ad-hoc Filter：`Filters [ ifName = Et0/0 ]`；
3. 开启该条件后，大盘中所有面板（包括全网聚合流量、错误与丢弃统计、Top 10 趋势折线图、Top 20 排行表格）接口数据全部丢失（变成 0 或 No Data）。

## 2. 根因分析
1. **Ad-hoc Filter 机制**：Grafana 会无差别向所有面板的 PromQL 查询中注入 `{ifName="Et0/0"}` 选择器（如 `ifHCInOctets{hostname=~"$device",ifName="Et0/0"}`）。
2. **底层指标缺失 `ifName` 标签**：底层存储的时序指标（`ifHCInOctets`、`ifHCOutOctets`、`ifOperStatus` 等）身上**仅有 `ifIndex` 标签，根本不存在 `ifName` 标签**（`ifName` 仅作为单独的一个 metric 存在）。查询注入 `ifName="Et0/0"` 时，底层时序匹配不到任何结果，直接返回空集合（Empty Result）。
3. **采集编译器遗漏 `lookups`**：`monitoring_oid_catalog.py` 的 `STANDARD_INTERFACE_METRICS` 中没有配置 snmp_exporter 原生的 `lookups`，且 `monitoring_compiler.py` 之前只校验 `labelname` 而未兼容标准 `lookup` 键名，导致采集器没有在抓取时将 `ifIndex` 自动映射为 `ifName` 标签注入到数据指标上。
4. **04 大盘缺少原生「接口 ($interface)」模板变量**：用户无法在顶部下拉框中直接筛选接口，才被迫使用表格的 `Filter for value`。

## 3. 解决方案
1. **OID Catalog 与编译器增加 `lookups`**：
   - 在 `monitoring_oid_catalog.py` 中定义 `_INTERFACE_LOOKUPS`，为核心接口指标全面添加 `lookups` 配置；
   - 在 `monitoring_compiler.py` 中放宽键名校验兼容 `lookup` 和 `labelname`，并在 `_fallback_exporter_modules` 中补齐 `lookups`。
2. **04 大盘增加原生「接口 ($interface)」模板变量**：
   - 增加 `make_interface_variables()`，提供按站点、厂商、角色、设备联动的级联接口多选下拉框；
3. **面板 PromQL 稳健安全过滤**：
   - 在 Stat 聚合面板、Top 10 折线图和 Top 20 表格中，统一通过 `(ifName{ifName=~"$interface"} * 0 + 1)` 精准过滤接口，无论底层历史时序是否带有 `ifName` 标签，都能 100% 精准过滤接口，绝不丢失数据。
4. **重新编译生成全套大盘**：版本升级至 `25`。

## 7. 风险与回滚方式
- **风险**：极小，大盘 PromQL 采用向后兼容的向量连接，未带 `ifName` 标签的历史数据与带有 `ifName` 标签的新数据均可正常过滤。
- **回滚方式**：`git revert HEAD` 即可撤销本次提交。
