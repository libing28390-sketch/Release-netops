# 同步命令目录与TextFSM模板及前端预设

## 问题现象
用户反馈前端展示的命令、后端 `COMMAND_CATALOG` 映射以及实际的 TextFSM 模板三者存在不一致。例如用户手动往 `COMMAND_CATALOG` 中添加了部分命令（如锐捷的 BGP、OSPF、BFD，迪普的 NTP，中兴的 BGP 等），但由于没有配套的 TextFSM 模板，导致无法匹配解析，且前端预设的指令与之存在单复数或具体命令字不一致的问题。

## 根因分析
1. **指令不一致**：前端快捷查询预设的命令（`index.tsx` 中的 `cmds`）与后端 `COMMAND_CATALOG` 配置的命令有微小出入。例如前端使用的是复数 `show interfaces status`，而后端改成了单数 `show interface status`。
2. **缺少对应模板**：后端字典新增了诸多国产平台的分析大类（例如锐捷的 `bgp`、`ospf`、`ntp`、`bfd`），但本地 `data/textfsm_templates/` 中却缺少对应的 `.textfsm` 解析模板，导致无法实现解析。
3. **不支持的分类关键字**：后端加入了 `'clock'`，但之前未声明在 `SUPPORTED_CATEGORIES` 中。

## 解决方案
1. **支持 'clock'**：在 `SUPPORTED_CATEGORIES` 中追加了 `'clock'` 类型。
2. **对齐前端预设命令**：修改 `src/pages/AutomationExecute/index.tsx`，确保迪普、迈普、中兴、锐捷等国产设备在前端按键上显示的命令与后端的字典完全对齐。
3. **补充/对齐 TextFSM 模板**：
   - 复制 `ruijie_rgos_show_interfaces_status.textfsm` 重新生成一份 `ruijie_rgos_show_interface_status.textfsm` 模板，保证单复数均能匹配。
   - 分别利用 Cisco/华为 的标准输出模版，为中兴、迪普、锐捷创建或对齐了相应的 `.textfsm` 模板：
     - `zte_zxros_show_ntp_status.textfsm`
     - `dptech_ios_show_ntp_status.textfsm`
     - `zte_zxros_show_ip_bgp_neighbors.textfsm`
     - `ruijie_rgos_show_ip_bgp_neighbors.textfsm`
     - `ruijie_rgos_show_ip_ospf_neighbor.textfsm`
     - `dptech_ios_show_bfd_session.textfsm`
     - `ruijie_rgos_show_bfd_neighbors.textfsm`
     - `ruijie_rgos_show_logging.textfsm`
