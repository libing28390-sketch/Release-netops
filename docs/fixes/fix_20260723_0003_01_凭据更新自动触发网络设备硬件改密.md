# Git 提交修复记录 - 凭据更新自动触发关联网络设备 SSH 硬件改密

## 1. 问题现象与需求
用户在凭据管理（/api/credentials 或 /cmdb/credentials）中修改凭据的密码时，系统此前仅更新了数据库密文，未联动连接物理网络设备下发 CLI 命令修改设备本身的口令，导致凭据变更后交换机口令未同步改密。

## 2. 根因分析
1. `PUT /api/credentials/{cred_id}` 在更新数据库凭据记录后，缺失了联动设备硬件改密的触发器。
2. `password_rotation_service.rotate_password` 之前只支持生成随机 20 位密码，缺少接收指定目标密码（`target_password`）下发到硬件交换机的能力。

## 3. 解决方案
1. 扩展 `password_rotation_service.rotate_password`：增加 `target_password` 参数支持，当下发指定新密码时跳过随机生成，使用用户提交的新密码。
2. 新增 `sync_hardware_device_password_for_credential` 函数：查找所有关联绑定该凭据的网络设备，利用特权账号连接 SSH，下发 CLI（如 Cisco `username secret`、华为/H3C `local-user password cipher`），并执行 `write memory` / `save` 保存配置。
3. 在 `PUT /api/credentials/{cred_id}` 接口中增加 `background_tasks.add_task`：只要用户在凭据管理中更新密码，自动在后台并发对所有关联交换机下发改密 CLI 并记录审计日志。
