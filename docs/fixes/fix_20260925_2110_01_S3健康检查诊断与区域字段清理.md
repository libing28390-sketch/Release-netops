# S3 健康检查诊断与区域字段清理

## 问题现象
对象存储管理页的 Environment 连接测试失败，只显示通用的 `ClientError`，无法判断服务端拒绝原因。项目此前还保留了单独的 `S3_REGION` 环境变量配置。

## 根因
S3 健康检查捕获异常后只返回异常类型；存储 Provider 测试 API 又将失败原因替换成通用提示，丢失了 Botocore 响应中的错误码和 HTTP 状态。S3 SigV4 仍需签名区域，但本项目兼容端点可使用内部默认值 `us-east-1`，不需要把它作为部署变量。

## 解决方案
- 健康检查仅展示字符白名单校验后的 S3 错误码和有效 HTTP 状态，不返回原始异常正文或凭据。
- Provider 测试 API 保留上述脱敏诊断文本。
- 移除设置模型、Compose 显式映射和 `.env.example` 中的 `S3_REGION`；内部继续使用 `us-east-1`。
- 增加测试覆盖错误信息脱敏、API 错误消息保留及部署配置不再声明该变量。

## 风险与回滚方式
- 对外新增信息仅为受限格式的错误码与 HTTP 状态；不暴露原始服务端文本、密钥或凭据。
- 移除变量后 SDK 仍采用 `us-east-1`。部署主机 `.env` 中的旧行需由运维人员删除，更新 Compose 与代码后重建 `netops` 容器使环境生效；此清理本身不保证修复 S3 连接失败。
- 回滚时还原本提交涉及的后端、Compose、示例配置及测试文件，或使用 `git revert` 撤销该提交。
