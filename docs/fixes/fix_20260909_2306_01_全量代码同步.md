# 问题现象

工作区累积了 RackVision 3D、模块化 GLB、LLDP/线缆、Windows 管理入口、SSH 兼容性、数据库迁移、CI/发布配置及相关测试的未提交代码，需要按用户明确授权同步到远端 `origin/main`。

# 根因

多项本地任务在同一个 `main` 工作区完成，尚未形成统一提交；同时工作区还包含本地诊断结果、数据库备份和 Codex 内部状态，不能混入代码提交。

# 解决方案

- 将当前代码、测试、迁移、前端资源、公开文档和 draft GLB 产物集中提交。
- 清理历史 `m0211_device_tenant_scope` 中不再可达的 SQLite `PRAGMA` 分支，使 PostgreSQL-only 扫描可通过。
- 保留并排除本地凭据/诊断上下文、数据库 dump、Codex 内部状态、Blender 自动备份等非代码文件。
- 提交前执行前端 lint/build/测试、后端定向回归、GLB 校验、敏感文件检查和 `git diff --check`。
- 仅推送当前 `main` 到已跟踪的 GitHub `origin` 远端，不推送分叉的 `gitee` 远端，不创建 tag 或触发部署。

# 实际修改范围

包括现有工作区中已修改的应用代码、数据库迁移、网络驱动、前端页面、RackVision 资产/测试、CI/部署配置，以及 `public/assets/3d/modular_demo` 和对应脚本/文档。
