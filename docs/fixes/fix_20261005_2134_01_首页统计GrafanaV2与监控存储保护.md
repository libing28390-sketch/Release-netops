# 首页统计、Grafana V2 与监控存储保护

## 问题现象与根因

首页直接对默认只返回 200 行的设备列表计数，并周期执行昂贵的设备明细标注，导致大于 200 台时计数被截断和额外负载。SNMP exporter runtime YAML 的 enum_values 数字键被保留为 JSON 字符串，影响 reload。平台识别更新 schema 不存在的 physical_assets.version，旧 devices 表也可能缺 version 列。

V2 ZIP 的个别面板包含冲突的状态背景色、无法匹配实际字段名的 override、缺失的真实状态枚举和覆盖 CMDB 阈值的固定警戒颜色。默认 90 天指标保留与 10GB vmagent 缓存缺少足够的低磁盘空间保护。

## 解决方案与文件

新增轻量完整设备摘要 API 和前端请求生命周期处理；修正 runtime enum 键，设备版本仅持久化到有效列并新增 PostgreSQL 幂等 migration 274。按当前 V2 skill 修正展示源并生成 12 JSON，保留查询/统计口径，修复 3 处失效链接字段占位。默认保留 30 天、VM 剩余 10GiB 停写，队列限制 1GB，补充服务器 `.env` 更新与重建指导。

文件覆盖 `backend/api/devices.py`、两个相关 service、migration 274、首页及共享类型/入口、Grafana 生成器/展示源/12 JSON、Compose/.env.example、3 个新回归测试、公开监控存储指南和本轮计划/完成记录。完整文件和设计说明见 [walkthrough](../walkthrough/walkthrough_20261005_2112_01_GrafanaV2复核与工作区推送.md)。内部 agent 配置、skill 与临时构建文件保留本地。

## 未验证项与回滚

标准 npm lint 受历史构建 JS 纳入导致 Node OOM，不能记为通过；等价源码范围检查通过。用户确认 Docker 运行于另一虚机，本机仅检查配置源码；未在线部署/视觉渲染/操作设备，未跑全仓回归。无线离线查询、Windows 重复表头、scheduler 超时跳过记录为既有问题。

以新提交恢复业务文件与配置可回滚；新增可空 version 列可保留。服务器 `.env` 需要同步调整，且应 `docker compose up -d --no-deps victoriametrics vmagent` 重建；只 restart 不更新启动参数。缩短保留期与队列限额造成的清理/丢弃无法回滚恢复。VM 保护不限制其他容器的宿主机写入。
