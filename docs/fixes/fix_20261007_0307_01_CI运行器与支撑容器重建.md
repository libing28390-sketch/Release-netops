# CI 异步测试兼容与资源支撑容器重建

## 问题现象

首次发布验证 Actions run #677（`37515055183`）的后端测试中，2940 项通过、1 项失败、1 项跳过。失败项是新并发健康检查测试；此外，部署脚本通过显式服务选择执行 Compose 更新，资源受限的 cAdvisor 与 Docker socket proxy 未出现在该选择列表中。

## 根因

Actions runner 没有安装 `pytest-asyncio`，但测试使用 `@pytest.mark.asyncio`，因此 pytest 无法执行 async 测试函数。cAdvisor 与 socket proxy 虽由 Compose 依赖关系带起，但服务选择函数没有明确包含它们，无法保证本次服务更新明确覆盖全部受资源限制的容器。

## 解决方案

- 将异步测试改为普通 pytest 测试函数，在内部以 `asyncio.run` 运行场景，避免增加测试依赖并保留原有的并发/阻塞断言。
- 将 `docker-socket-proxy` 和 `cadvisor` 加入部署服务选择，并新增服务选择契约测试。
