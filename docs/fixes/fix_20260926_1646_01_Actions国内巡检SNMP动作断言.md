# 修正全量 Actions 中的国内巡检 SNMP 动作断言

## 问题与证据

提交 `bb36d690` 推送后，GitHub Actions `Build and Sync to Release Repo` 的后端 pytest 门禁失败。全量统计为 2335 passed、1 skipped、1 failed；失败用例是 `backend/tests/vendor_audit/test_domestic_playbook_catalog.py::test_domestic_inspection_is_read_only_and_never_uses_cisco_phases`，错误为 `AttributeError: 'dict' object has no attribute 'lower'`。

本次已经将锐捷、ZTE、迈普通用巡检剧本中的光模块 CLI 查询改成 typed `get_transceivers` SNMP action。被测的巡检阶段因此可以合法地包含只读 SNMP action 字典，旧测试却无条件把每个阶段项都当成 CLI 字符串。生产调用链行为有 optical SNMP 路径测试覆盖；失败原因是测试断言未随着数据结构调整。

Actions 记录：[bb36d690 首轮门禁](https://github.com/libing28390-sketch/netsops/actions/runs/36230072568)。该次失败导致后续前端门禁和发布树同步步骤跳过。

## 修复

更新测试断言：允许以 `show ` 开头的只读 CLI 字符串，或恰好为 `{"action_code":"get_transceivers"}` 的只读 SNMP typed action；其余形式仍失败。未改变生产执行路径。
