# 工单、调度与SNMP/IPAM定位变更发布

## 问题现象与范围
本机积累的工单责任人校验、工单页面交互、定时作业/NSOT退役、SNMP ARP/FDB和端点定位、IPAM字段/时区及公共导出变更尚未提交。用户要求把全部已修改产品代码push至main并确认Actions成功。

## 根因和方案
- 终端发现与旧CLI路径定位的数据链分离，且设备角色默认值被用于判断MAC能力。接入授权范围内唯一有效SNMP ARP/FDB/物理接入口证据，实时刷新优先相关授权设备SNMP；不足时保留有界CLI兜底。后台任务发布前重验源证据。
- 合并ARP/FDB小时采集和投影更新，支持Q-BRIDGE不含PVID的非VLAN桥端口；接口属性失败不丢成功FDB，缺证据不猜端口。
- 用户要求NSOT内置全量作业及采集计划下线：撤销对应路由/入口，迁移只退役精确内置任务，历史记录及用户数据保留。BGP/OSPF使用显式授权的定时动作，后台不再持续轮询协议；BFD自动邻居采集也不再持续更新，未在本轮恢复。
- 定时BGP/OSPF混合成功失败必须标记partial，不能作为全部成功通知。
- UI按已确认要求拆列、缺值留空、统一时区/字体/布局，公共表格导出采用Blob与原生download链接。
- 更新退役接口和入口的旧测试；保留bulk-options的授权范围覆盖、退役404与不改数据验证；导出用例改校验下载契约，保留过滤/分页/列及敏感字段断言。
