# Redis 时区与 Docker 项目名兼容修复记录

## 问题现象

1. Redis sidecar 未显式继承部署 `TZ`，与 PostgreSQL、Nexora 和 Nginx 的默认 `Asia/Shanghai` 时区契约不一致。
2. 已有 `nexora-db` 容器健康运行时，`bash scripts/deploy-docker.sh update` 仍报告 `service "db" is not running`，导致发布前 `pg_dump` 失败并中止更新。

## 根因

- `docker-compose.redis.yml` 缺少 `TZ` 环境变量。
- 历史脚本合并多个 Compose 文件时没有固定项目名，现有容器可能采用最后一个 overlay 的项目标签；新版脚本直接默认 `--project-name nexora`，没有兼容已有容器标签。Compose 按项目标签查找服务，因此容器名存在且健康并不代表当前项目能识别服务 `db`。

## 解决方案

- Redis 注入 `TZ=${TZ:-Asia/Shanghai}`，复用现有 `.env` 配置。
- 新增 Compose 项目名解析：显式 shell/`.env` 配置优先；未配置时读取现有 `nexora-db` 的 `com.docker.compose.project` 标签；全新部署回退到 `nexora`。
- 保持发布前 PostgreSQL 备份为强制门禁，不删除容器、不跳过备份。
- 增加发布契约测试、部署排查说明、实施计划和走查记录。

- 自动探测只读取固定 `nexora-db` 容器标签，并仅在用户未显式配置项目名时启用；非法标签仍会被拒绝。
