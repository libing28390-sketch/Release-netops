# Grafana 会话冲突与监控断点排查记录

## 问题现象与提交目的

普通 Chrome 曾在 Grafana 页面重复追加 `/grafana`；此外，流量面板出现多条接口曲线同步断点。本次提交目的为同步已确认的 Grafana Cookie 隔离修复、部署契约和操作文档，并记录监控断点的诊断边界。

## 根因

- Grafana 重复子路径由普通浏览器遗留的 Grafana 原生 `grafana_session` Cookie 与 Auth Proxy 请求身份冲突触发。禁用缓存未改变现象；删除该 Cookie 后页面恢复。Nexora 专用 `nexora_grafana_session` 仍用于内部鉴权。
- SNMP 图表断点来自采集端间歇性缺样：vmagent 记录过 R3/R4 的 SNMP exporter HTTP 500 和请求超时。VictoriaMetrics 中实际面板 PromQL 与去掉 `topk` 的表达式产生完全相同的缺样时间，多个接口和两个方向同步中断，因此排除了 `topk` 筛选。

## 解决方案与实际修改文件

- Compose 启用 Grafana 子路径服务，并关闭 Auth Proxy 登录令牌 Cookie。
- Nginx 保留 `/grafana/` 路径，鉴权子请求只校验 Nexora 会话；Grafana 上游不接收浏览器 Cookie，避免旧原生会话覆盖 Auth Proxy 身份。
- 更新部署契约断言、Docker 部署说明、任务计划/走查和 `handoff.md`。
- 涉及代码文件：`docker-compose.yml`、`nginx/nginx.conf`、`backend/tests/monitoring/test_monitoring_v1_deployment_contract.py`、`docs/deploy/docker.md`。
- 监控 SNMP 超时目前只有诊断结论，没有修改采集超时或设备配置；不得把本提交描述为已修复 SNMP 断点。

## 验证命令与结果

- 用户在服务器对前一轮子路径配置运行 `docker compose config -q` 与 `nginx -t`，均通过；该结果发生在本次 Cookie 隔离代码部署之前，不能代替对最终 Nginx 配置的服务器验证。
- 普通窗口清理单个 `grafana_session` 后恢复，用户报告无痕窗口原本正常。
- vmagent target API 曾显示 R3/R4 SNMP 模块超时；后续直接探测均有 HTTP 200 响应，证明超时是间歇性的。
- 最近 30 分钟面板表达式和去掉 `topk` 的 range 查询结果在 R3/R4、所有接口及入/出方向有相同断点；最大间隔分别为 90 秒和 150 秒。
- 本次提交准备过程中未运行测试套件；最新 Cookie 隔离配置仍需在服务器重建 Nginx 后验证。

## 风险与回滚方式

- 服务器尚未部署本地新增的 Cookie 隔离配置；如部署后 Grafana 认证异常，可恢复部署时备份的 `nginx.conf` 和 `docker-compose.yml`，再重建对应容器。不要删除 Grafana/PostgreSQL 数据卷或 Nexora 会话 Cookie。
- SNMP timeout 根因细分和修复未完成；后续应比对 vmagent/exporter 的失败时间与设备 SNMP 响应，不宜先盲目提高全局 timeout。
