# 跨平台环境配置解析修复记录

## 问题现象

部分 Docker 部署机执行 `bash scripts/deploy-docker.sh backup-release` 时，PostgreSQL 报角色不存在；同机手工使用 `-U postgres -d netops` 执行 `pg_dump` 正常。

## 根因

Windows 编辑或生成的 `.env` 使用 CRLF 换行。旧版 `env_value()` 通过 `grep | cut` 读取值时保留了行尾 `\r`，导致 `pg_dump` 收到带隐藏字符的用户或数据库名。Docker Compose 的解析正常，不代表主机侧 Shell 脚本的手工解析正常。

## 解决方案

- 在 `env_value()` 中清理返回值末尾的 `\r`，兼容 LF 和 CRLF。
- 保留不直接 `source .env` 的安全解析方式。
- 将 LF/CRLF、安全 dotenv 解析、命令参数引用和回归验证要求写入项目代码规范与发布 skill。
