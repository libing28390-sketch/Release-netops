# RDP 证书指纹固定配置

## 问题现象

Ubuntu guacd 已能建立 RDP 会话，但 Windows 目标使用的自签名 TLS 证书未受系统信任。默认安全行为是证书无效时拒绝连接。用户选择为 LEERBON 固定证书指纹，并保留验证。

## 指纹核对

- Windows 证书存储中的 `CN=leerbon` RDP 证书 SHA-1 Thumbprint：`A990AA8B8BDB086EB59B59E4E9302B27937EE22E`。
- `Win32_TSGeneralSetting` 报告的 RDP-Tcp `SSLCertificateSHA1Hash` 与该 Thumbprint 一致。
- 对证书 DER 字节计算的 SHA-256：`4CE56BB09B6F1B96A521AE58EFCEA743ECBB632A9C8D29F999D01CE47F9FF80E`。

## 解决方案

- 为 RDP asset profile 增加可选 `rdp_cert_fingerprint` 字段，数据库迁移为 m0286。旧记录默认空值，表示继续使用系统证书链校验。
- 后端只接受 64 位十六进制 SHA-256；配置时按 FreeRDP 2.11.7 的要求，将其转换成冒号分隔的十六进制字节并传给 Guacamole，同时保持 `ignore-cert=false`。
- 在资产管理 RDP 表单提供字段与说明，支持按资产固定服务器证书。
- Guacamole 录像名同时修正为 `.guac` 后缀，确保 guacd 输出路径与 PAM spool 一致。

## 验证

- 定向后端和迁移测试：14 passed（初版格式）。
- 前端 TypeScript 检查：通过。
- Windows RDP TLS 握手直接读取到的证书 SHA-256 与资产保存的 pin 一致。
- 第一次 pin 实机连接仍失败。检查 Guacamole 1.6.0 镜像内 FreeRDP 2.11.7 源码后确认，其比较器只接受冒号分隔的 fingerprint；无分隔的输入会导致校验失败。后端已转换为冒号格式，定向服务测试 9 passed。
- Ubuntu 实机复测未再出现证书校验错误；guacd 记录 `RDPDR user logged on`，Windows 事件日志也记录 RDP 会话重新连接成功，证明证书 pin 和目标凭据均通过初始验证。
- Windows 随后以事件 40 reason code 5（`exDiscReasonReplacedByOtherConnection`）结束远程会话；本机仍有活动的 `tete` 控制台会话。录像已写入 `.guac` 文件并成功归档到配置为 S3 的 PAM 存储（`storage_status=READY`）。完整图形桌面尚未稳定显示。

## 风险与回滚

指纹固定只允许当前 profile 配置的证书。Windows RDP 证书更新后，旧 pin 会拒绝新证书，管理员需经可信渠道重新核对并更新指纹。空值继续严格校验系统受信任的证书链，不会退化为忽略证书。
