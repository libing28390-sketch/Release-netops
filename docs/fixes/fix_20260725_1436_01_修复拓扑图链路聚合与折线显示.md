# Fix Record - 修复拓扑图链路聚合与折线显示

## 问题现象
1. 拓扑图画的有问题，对角线相连的设备连线被绘制成 90 度折角（正交路由），导致在网格布线时产生大量假交叉（如 T 型重叠），用户难以准确判断究竟是两根独立的物理连线，还是互相相交。
2. 配置了链路聚合（LAG/Route-Aggregation/Eth-Trunk）的 H3C 和 Huawei 交换机之间，在拓扑图上依然被展示为多条绿色的物理连线，没有正常合并并折叠展示为一根逻辑聚合连线。

## 根因
1. 前端拓扑 `TopologyGraph.tsx` 只有 `getOrthogonalRoute`（正交路由）画线逻辑，没有提供直连线绘图算法。
2. 在后端，H3C 设备的 platform 为 `h3c_comware`（映射到 `hp_comware`），而 Huawei 设备为 `huawei_vrp`。虽然 `data/textfsm_templates/` 中有用于解析 link-aggregation 详细信息的 `h3c_comware9_display_link_aggregation_verbose.textfsm` 和 `huawei_vrpv8_display_eth_trunk.textfsm` 模板，但 `textfsm.py` 内部兼容映射 `_COMPATIBLE_PLATFORMS` 没有针对 `h3c_comware` / `hp_comware` / `huawei_vrp` 建立对高版本模板的降级解析通道。导致在重建链路聚合关系时，由于解析库返回空值使得聚合口没有被录入 `interfaces` 数据库，无法在 rebuild 时 collapsed 为 logical LAG edge。
3. H3C 的三层聚合接口常命名为 `Route-Aggregation`（缩写 `RAGG`），但 `INTERFACE_ALIASES` 遗漏了 route-aggregation 规范化映射，导致聚合口无法正常与 `RAGG` 等小写别名匹配。

## 解决方案
1. **直连线/折线模式切换**：前端重构拓扑组件，引入直连线坐标点计算函数 `getStraightRoute`，默认采用 Straight line，并保存用户选择的 routingMode。
2. **多厂商 TextFSM 平台兼容**：在 `_COMPATIBLE_PLATFORMS` 映射中增加 `huawei_vrp` -> `['huawei_vrpv8']`、`h3c_comware` -> `['hp_comware', 'h3c_comware9']` 等兼容链条。
3. **聚合口规范化支持**：在 `INTERFACE_ALIASES` 中加入 `("route-aggregation", "ragg")`。
4. **前端缩写格式优化**：在 `abbreviateInterface` 中支持将 `Bridge-Aggregation` 和 `Route-Aggregation` 规范缩写为 `BAGG` / `RAGG` 简名。
