# 监控部署与 Grafana 修复

## 目的与问题

- 修复 Grafana 通过 Nginx `/grafana/` 子路径访问时的 localhost 重定向和循环重定向。
- 修复 Grafana 查询 Docker 内部 VictoriaMetrics 时被主机代理转发为 502 的问题。
- 修复 SNMP Exporter v0.26 严格 YAML schema 拒绝 Nexora `unit`/`source_name` 指标元数据的问题。
- 让旧版持久化 monitoring runtime artifact 在后端启动时自动兼容，不要求升级后手动重新应用基线计划。
- 修复 Docker 更新在缺少新环境变量时先执行 Compose 备份、导致初始化逻辑无法运行的问题。

## 根因

1. Nginx `proxy_pass .../` 已剥离 `/grafana/`，Grafana 同时启用
   `serve_from_sub_path=true` 会重复处理前缀并产生重定向循环。
2. Grafana datasource 请求使用 Docker 内部服务名；容器内继承的 HTTP 代理会把
   `victoriametrics:8428` 转发到外部代理并返回 502。
3. OID 配置规范化在移除 `unit` 后再次解析时无条件补回空 `unit`，而
   `snmp-exporter:v0.26.0` 拒绝该字段。
4. 已发布 artifact 位于持久化 volume，镜像升级不会自动重写旧 runtime 副本。

## 方案与文件

- `docker-compose.yml`：Grafana 使用内部根路径模式，探针使用镜像内的 `curl`，
  只挂载 release-owned provisioning 子目录，并清空 Grafana 的代理变量。
- `scripts/deploy-docker.sh`：先初始化 `.env` 再做发布备份，自动生成局域网 Grafana
  URL，并在 exporter 恢复后启动延迟的 vmagent。
- `scripts/sync-frontend-dist.sh` 与
  `backend/services/monitoring_runtime_normalizer.py`：后端启动时原子修复旧 runtime
  副本中的 exporter 不兼容元数据，不输出凭据内容。
- `backend/services/monitoring_compiler.py`：区分 UI 元数据校验与 exporter YAML 渲染，
  不再把 `unit` 写入 exporter 配置。
- `.env.example`、`docs/deploy/docker.md`：明确局域网 HTTPS URL、证书和代理约定。

## 远端更新与恢复

在部署目录执行：

```bash
bash scripts/deploy-docker.sh update --force
```

确认 `.env` 中的 `GRAFANA_ROOT_URL` 使用用户实际访问的域名或服务器 IP，格式为
`https://<host>/grafana/`。升级兼容修复不要求重新应用基线计划；只有新增或修改
SNMP 凭据/采集计划时，才需要发布一次业务配置。

## 回滚

- 使用部署脚本生成的 release backup 和原 Git 版本回退代码。
- 不删除 `nexora-monitoring-artifacts`、`nexora-grafana-data` 或 PostgreSQL volume。
- Grafana/Nginx 配置修改前保留 `.env`、Compose 和 TLS 文件备份。
