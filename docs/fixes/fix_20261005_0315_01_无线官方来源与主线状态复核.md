# 无线官方来源与主线状态复核

## 复核原因

多厂商无线监控的 walkthrough 仍记录为等待修正提交的 GitHub Actions 结果，也将锐捷/信锐资料统一描述为未找到。提交 `496484c48d08147fe73f92ffbeb59bedaf0e7335` 的 run #656 已通过，且信锐官网确有可下载的 NAC OID 汇总表，需要同步准确状态和证据边界。

## 核对结果

- H3C 与 Huawei 无线 AC 的采集、库存、指标和 Grafana 代码已在 `main`。Huawei 无线发现流程对齐固定 LibreNMS VRP 实现；H3C 无线对象采集是基于厂商 MIB 的 Nexora 扩展，因为固定 LibreNMS Comware 实现没有无线发现 handler。没有真实设备，不能据此声称实机或固件兼容已验证。
- 信锐官方 OID 汇总表公开控制器 CPU `1.3.6.1.4.1.45577.1.3`、内存占用率 `1.3.6.1.4.1.45577.1.15`、在线/离线/托管/总 AP 数 `1.3.6.1.4.1.45577.2.12.1.1` 至 `.4`、在线终端数 `1.3.6.1.4.1.45577.2.12.2.1`，以及 AP、Radio、终端、SSID 等表根。该表没有给出各列的完整数值 OID、索引、类型和缩放。
- 信锐官方 SNMP 指南说明完整 MIB 可从控制器下载；当前没有可访问的 NAC 设备，因此不推测表列索引，也不提交未验证的信锐明细采集规则。
- 锐捷官网确认其自有 RG-WS 无线控制器/AP 产品线；本次官方资料检索未找到该 WLAN 产品线的完整 MIB/OID 表。信锐官方介绍其为深信服集团旗下的独立品牌；“锐捷无线”与信锐不是同一个品牌。
- 固定 LibreNMS 源码快照没有信锐 wireless handler。若后续实现信锐，需先获取完整官方 MIB 和设备 walk，再明确其与 LibreNMS 通用采集/库存流程的对应关系。
