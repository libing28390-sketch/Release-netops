# 修复与特性提交记录：IP定位Redis协同与资产导入优化

## 问题现象 / 提交目的

本次提交整合以下核心增强与修复：
1. **IP 定位 V2 协同与 Redis 缓存支持**：
   - 原 IP 定位依赖全量扫描且缺乏多节点协同状态管理，CLI 四阶段采集（路由、ARP、MAC、接口链路）高并发下缺少精细化缓存与作用域隔离机制。
   - 现引入 Redis 7.4.2 Alpine sidecar 支持定位结果与中间表项分级缓存（路由/ARP 300s/1800s、MAC/结果 120s/900s、网段 900s/86400s、拓扑 600s/86400s、正向未命中 15s）；Redis 仅作可重建缓存，PostgreSQL 始终为事实真相；Redis 不可用时平滑降级。
   - 完善数据库迁移 `m0219_locator_v2_coordination` 与 `m0220_locator_run_deployment_scope`。
2. **资产导入模板与管理交互优化**：
   - 简化资产导入交互与模板结构，移除冗余 sheet，支持单行 SSH 自动映射 SSH 终端与 Web SSH 两种登录方式。
   - 网络设备与服务器导入模板支持必填字段动态公式带出与格式化，规范化日期格式（YYYY-MM-DD）。
   - 网络设备列表增加鉴权头及错误提示，避免加载失败静默或未捕获异常。
3. **部署文档与公有仓库更新**：
   - 更新 Docker、Windows、离线部署与 README 文档，明确 Redis sidecar 与 IP 定位配置契约。
   - 归档今日全部计划与走查文档。

## 根因

1. IP 定位在多设备并发排查时容易导致网络设备 CLI 会话压力过大，且缺乏细粒度 TTL 缓存，导致重复采集。
2. 资产导入流程中旧模板表头复杂、多工作表逻辑割裂，用户难以直观理解管理入口映射关系。
3. 设备列表接口在偶发网络或权限异常时未显式传递鉴权头和友好的错误提示。

## 解决方案

1. **后端与数据层**：
   - 新增 `backend/database/migrations/m0219_locator_v2_coordination.py` 与 `m0220_locator_run_deployment_scope.py`。
   - 实现 `ip_locator_cache_service.py`、`ip_locator_task_service.py`、`ip_locator_trace_service.py`。
   - 在 `backend/schemas/schemas.py` 增加 `IPLocatorRunRequest` 契约校验与范围规范化。
   - 新增 `docker-compose.redis.yml` 并更新 `scripts/deploy-docker.sh` 支持 Redis sidecar 生命周期管理。
2. **前端与模板**：
   - 重构 `src/pages/AssetManagement/index.tsx`、`importUtils.ts` 及单元测试，精简单 SSH 管理入口映射与动态公式。
   - 优化 `src/store/inventoryStore.ts`、`src/pages/InventoryDevicesTab.tsx`，加入 `authHeaders()` 与明确错误展示。
   - 更新 `public/templates/asset_import_template.xlsx`。
3. **文档与归档**：
   - 更新 `docs/deploy/README.md`、`docs/deploy/docker.md`、`docs/deploy/docker-release-manual.md`、`docs/deploy/windows.md`。
   - 同步 `docs/plans/` 和 `docs/walkthrough/` 相关计划与走查报告。

## 风险与回滚方式

- **风险**：若部署环境未启用 Redis，IP 定位自动降级为无缓存模式，不影响既有业务。
- **回滚方式**：可通过 `git revert HEAD` 恢复本次提交，由于 migration 具备向下兼容性，回滚不影响历史定位事实数据。
