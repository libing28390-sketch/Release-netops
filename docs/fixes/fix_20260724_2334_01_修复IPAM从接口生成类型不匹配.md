# 修复 IPAM 从接口生成类型不匹配 修复记录

## 问题现象

本地 IPAM 网段页面点击“从接口生成”报错，后端日志显示：
```
psycopg2.errors.DatatypeMismatch: 错误:  COALESCE 参数类型 boolean 与 integer 不匹配
LINE 7:            WHERE (COALESCE(i.is_l3, 0) = 1 OR COALESCE(i.ip_...
```

## 根因

在 `backend/services/ipam_service.py` 内部查询 L3 接口作为 IPAM 备选网段时，SQL 查询条件执行了：
`WHERE (COALESCE(i.is_l3, 0) = 1 OR COALESCE(i.ip_enabled, 0) = 1)`
然而在 PostgreSQL 库中，`is_l3` 为布尔类型 (`boolean`)，而 `ip_enabled` 为整型 (`integer`)。
PostgreSQL 不允许在 `COALESCE` 中混合使用 `boolean` 与 `integer`，也不支持直接进行 `boolean = 1` 的比较运算。

## 解决方案

将 `is_l3` 的过滤条件调整为符合布尔对比规范的 `COALESCE(i.is_l3, FALSE) = TRUE`；保留 `ip_enabled` 的 `COALESCE(i.ip_enabled, 0) = 1` 数值对比。
该方案同时兼顾了与 SQLite 数据库单元测试运行时的类型映射。
