# 存量设备录入直接投产

## 问题现象

录入资产时即使选择“存量设备”，投产状态仍被禁用，只能保存为待投产，无法表达设备已经在生产环境运行的事实。

## 根因

上一轮为了阻止新设备绕过投产流程，将所有新增资产的生命周期控件统一禁用，并在后端统一强制为 `staging`，没有对已明确标记的存量设备放开例外。

## 解决方案

- 新设备录入仍固定为待投产。
- 存量设备录入时允许选择已投产。
- 存量设备直接投产必须填写至少 5 个字符的免上收原因，并配置普通账号用户名和密码。
- 后端保存为已投产、未托管、`rotation_status=exempt`，不执行密码修改。
- 新设备即使伪造 `production` 请求，后端仍保存为待投产。

## 风险与回滚方式

- 免上收资产仍为 `is_managed=0`，后续高权限操作必须继续检查托管状态。
- 如需回滚，可恢复前端控件限制并移除创建接口的 `legacy_production` 分支；数据库字段和历史豁免记录应保留。
