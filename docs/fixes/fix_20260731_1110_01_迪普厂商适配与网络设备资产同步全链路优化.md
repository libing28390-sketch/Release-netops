# Git 提交修复记录 - 迪普厂商适配与网络设备资产同步全链路优化

## 1. 问题现象
1. 网络设备路由原 URI `/assets/devices` 不易识别网络设备属性，且资产管理状态未与网元设备同步。
2. 资产录入选择“迪普”时缺少对 `dptech_conplat`（交换机）与 `dptech_conplat_fw`（防火墙）平台的精准区分，且平台下拉项存在重复。
3. 静态与动态 Excel 导入模版未隔离服务器与网络设备厂商及平台下拉列表，且服务器模版保留了冗余的 Enable 密码与 SNMP 采集项。
4. 标签管理 (`/assets/tags`) 缺少迪普 (DPtech) 厂商标签及平台内建标签。
5. 在 `/automation/tasks` 对迪普设备执行 CLI 命令时，因第三方依赖包 Netmiko 未原生内置 `dptech_ios` 键而抛出 `Error: Unsupported 'device_type'` 报错。

---

## 2. 根因分析
1. 资产状态与 URL 未关联同步；`dptech` 平台的细分映射未收敛。
2. Excel 导入模版的 DataValidation 没有按资产类型维度彻底隔离，服务器模版混入了网络设备属性。
3. `tag_service.py` 的内建标签列表未全量覆盖迪普及服务器/网络多厂商标签。
4. Netmiko 4.x 的 `ConnectHandler` 校验逻辑使用 `ssh_dispatcher.__globals__['platforms']` 列表进行拦截；由于未进行全局闭包注入，导致动态注册未能生效。
