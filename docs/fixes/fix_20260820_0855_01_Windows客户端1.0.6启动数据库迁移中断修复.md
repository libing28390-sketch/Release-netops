# Windows 客户端 1.0.6 启动数据库迁移中断修复方案

## 一、 问题现象

在 Windows 环境下部署或升级运行 Nexora / NetOps 1.0.6 版本时，客户端/后端启动失败并退出，终端报错日志如下：

```text
File "D:\Program Files\netops\backend\main.py", line 139, in lifespan
  init_db()
File "D:\Program Files\netops\backend\database\schema.py", line 82, in init_db
  raise e
File "D:\Program Files\netops\backend\database\schema.py", line 67, in init_db
  raise RuntimeError(
RuntimeError: Database migrations are incomplete; pending versions: (104, 105, 106, 107, 108, 109, 110, 111, 112, 113, 114, 115, 116, 117, 118, 119, 120, 121, 122, 123, 124, 125, 126, 127, 128, 129, 130, 131, 132, 133, 134, 135, 136)

ERROR: Application startup failed. Exiting.
```

---

## 二、 根本原因分析

1. **版本变更与扩展依赖**：
   - 1.0.6 版本引入了 AI 知识库与 RAG 向量引擎功能；
   - 第 104 号数据库迁移（`backend/database/migrations/m0104_ai_pgvector_rag.py`）强依赖 PostgreSQL 的 **`vector` (pgvector)** 与 **`pg_trgm`** 扩展，启动时会调用 `ensure_required_extensions` 进行自检与创建。
2. **Windows 官方 PostgreSQL 缺少 `pgvector` 二进制**：
   - Windows 官方的 PostgreSQL 安装包（EnterpriseDB）默认**只包含 `pg_trgm`，不包含 `pgvector`**；
   - 本地数据库中无法加载 `vector` 扩展，导致第 104 号迁移抛出 `MissingPostgreSQLExtension: PostgreSQL extension 'vector' is unavailable`。
3. **迁移框架严格保护机制**：
   - 系统迁移执行器（`run_migrations`）采用严格的版本连续性保护。当 104 号迁移失败并回滚后，立即安全终止了后续迁移（105~136）的执行；
   - 启动守卫（`schema.py:67`）检测到仍有 33 个迁移处于待处理状态（`pending_versions`），主动拦截启动并报错。

---

## 三、 完整修复与操作方案

### 步骤 1：下载 Windows 版本的 pgvector 预编译二进制包
访问 GitHub 社区预编译包仓库：
- **下载地址**：[https://github.com/andreiramani/pgvector_pgsql_windows/releases](https://github.com/andreiramani/pgvector_pgsql_windows/releases)
- **选择版本**：根据本地安装的 PostgreSQL 版本下载对应的 x64 压缩包：
  - 如果是 PostgreSQL 17，下载：`pgvector_v0.8.6_pg17_x64.zip`（推荐）
  - 如果是 PostgreSQL 18，下载：`pgvector_v0.8.6_pg18_x64.zip`

### 步骤 2：复制扩展文件至 PostgreSQL 安装目录
解压下载的 zip 压缩包，将文件复制到 PostgreSQL 对应目录（需要 Windows 管理员权限）：

> 💡 *以 PostgreSQL 17 默认安装路径 `C:\Program Files\PostgreSQL\17\` 为例（若安装在其他盘符请替换路径）：*

| 提取的文件 | 目标放置路径 |
| :--- | :--- |
| **`vector.dll`** | `C:\Program Files\PostgreSQL\17\lib\` |
| **`vector.control`** | `C:\Program Files\PostgreSQL\17\share\extension\` |
| **`vector--*.sql`**（所有 SQL 脚本） | `C:\Program Files\PostgreSQL\17\share\extension\` |

### 步骤 3：重启 PostgreSQL Windows 服务
以管理员身份打开 CMD 或 PowerShell，执行服务重启命令：

```cmd
net stop postgresql-x64-17 && net start postgresql-x64-17
```

*(或者按 `Win + R` 输入 `services.msc`，在服务列表中找到 `postgresql-x64-17`，右键选择“重新启动”)*

### 步骤 4：确认数据库账号与扩展就绪（可选检查）
使用 `psql` 或 pgAdmin 连接业务数据库（如 `netops`），执行以下 SQL：

```sql
-- 检查 vector 扩展是否可用
SELECT name, default_version, installed_version 
FROM pg_available_extensions 
WHERE name IN ('vector', 'pg_trgm');
```

若查询结果中 `default_version` 显示版本号（如 `0.8.6`），说明扩展已就绪。

### 步骤 5：重新启动 Windows 客户端
双击运行桌面客户端启动程序（`NetOps.exe` 或 `start.bat`），系统将自动无缝跑通 104~136 的所有迁移并成功启动服务。

## 五、 验证方法与验收标准

1. **验收 SQL**：
   ```sql
   SELECT MIN(version), MAX(version), COUNT(*) FROM schema_migrations;
   ```
   **预期结果**：`MAX(version)` 达到当前版本的最新迁移序号（1.0.6 为 136），无任何 pending 报错。
2. **系统运行状态**：
   - 访问 `http://127.0.0.1:5010`（或当前配置端口），登录正常，AI 知识库与 CMDB/拓扑各模块功能正常。

## 六、 风险与回滚方式

- **风险评估**：极低。拷贝 pgvector 文件仅向 PostgreSQL 的 `lib` 和 `share/extension` 添加官方扩展动态链接库与 SQL 模板，不修改数据库现有业务数据和表结构。
- **回滚方式**：若需撤销，只需删除 PostgreSQL `lib/vector.dll` 及 `share/extension/vector*` 文件并重启 PG 服务即可。
