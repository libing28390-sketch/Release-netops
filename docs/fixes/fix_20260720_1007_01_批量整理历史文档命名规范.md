# Git 提交修复记录：批量整理历史文档命名规范

## 问题现象
项目 `docs/plans/` 与 `docs/walkthrough/` 目录中，新旧设计计划与验证报告命名格式并存（旧格式如 `plan_口令上收.md`），在文件夹中乱序杂存，无法进行时间线排序，十分混乱。
同时docs根目录下散落着未跟踪的知乎文章草稿 `zhihu1.md` 等临时文件。

## 根因
1. 2026-07-13 实施“Agent 归档命名规范”后，虽然为以后的文档确立了 `plan_YYYYMMDD_HHMM_NN_[任务名].md` 的带时间戳前缀的格式，但历史旧格式文件没有进行强制批量重命名归档，导致两者并存。
2. 开发者在日常记录中在 docs 根目录下生成了临时笔记草稿，但未予清理或排除。

## 解决方案
1. 编写并执行 Python 自动化重命名脚本，从 Git 提交历史中提取每个旧文件的初次提交时间，作为分配的时间戳；
2. 对于同一个“任务名”，统一将 plan 和 walkthrough 进行规范重命名（如重命名为 `plan_20260713_1402_01_口令上收.md` 和 `walkthrough_20260713_1402_01_口令上收.md`），确保相同的任务名分配完全一致的时间戳和 `NN` 序号，保持计划和走查的完美配对；
3. 调用 `git mv` 执行重命名，从而使 Git 保留其完整的修改历史记录；
4. 彻底物理删除 docs 根目录下的未跟踪草稿（`zhihu1.md` 等）。

## 实际修改文件
*   **重命名**：
    *   `docs/plans/` 和 `docs/walkthrough/` 下的几十个历史旧设计文档（批量利用 `git mv` 执行规范化重命名）。
*   **删除**：
    *   `docs/zhihu1.md`
    *   `docs/video-presentation-script.md`
    *   `docs/refactor-phase4-notes.md`

## 验证命令与结果
1. 运行 `git status` 确认重命名的旧文件状态为 `renamed`，表明 Git 已经记录并保留了其历史痕迹。
2. 检查 `docs/plans/` 和 `docs/walkthrough/` 目录下的文件，确认目前全部文件均以规范格式对齐，列表可以按时间线整齐自然排序。

## 未验证项
无。

## 风险与回滚方式
* **风险**：由于是利用 `git mv` 自动重命名，因此历史版本和作者提交信息均不会丢失。
* **回滚方式**：
  若想回撤此整理，可通过回撤该 commit：
  ```bash
  git reset --hard HEAD~1
  ```
