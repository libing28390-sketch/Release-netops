# 终端代理双客户端一键启动

## 问题

Docker 页面提示用户手动安装 Python/PowerShell，且 Windows 与 Ubuntu 下载入口共用一个脚本，普通用户容易下载错误平台文件。

## 原因

Linux Docker 镜像无法直接运行浏览器所在 Windows 工作站的进程；Windows 客户端需要单独的可执行发布物，Ubuntu 则适合使用 systemd 脚本。

## 修复

- 在 Windows release job 中构建 `NexoraTerminalAgent.exe`。
- 下载接口按 `platform=windows|ubuntu` 分流，并支持 Docker 通过 `TERMINAL_AGENT_WINDOWS_URL` 代理下载 Windows 发布物为附件。
- Docker 镜像保留 Ubuntu 安装脚本，前端同时显示两个明确入口。
- 在 Windows 工作站本地生成并验证 `NexoraTerminalAgent.exe`，作为发布树中的可下载附件。
- Docker 镜像复制该 EXE 但不执行，下载接口优先返回容器内文件，旧镜像才使用远程附件代理。
- 文档增加双击启动与 Ubuntu 安装说明。

## 验证

- `python -m py_compile backend/api/system.py`
- `git diff --check`
- `npm run lint`
- `npm run build`
- GitHub Actions Windows job 负责最终生成并发布 `NexoraTerminalAgent.exe`；本地未安装 PyInstaller 时不重复构建二进制。

## 风险与回滚

Windows EXE 发布失败时，可暂时使用现有 `install-terminal-agent.ps1`；Ubuntu 路径不受 Windows 构建影响。将 `TERMINAL_AGENT_WINDOWS_URL` 改为企业内部地址即可切换发布源。
