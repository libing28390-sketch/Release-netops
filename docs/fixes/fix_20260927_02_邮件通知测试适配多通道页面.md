# 邮件通知测试适配多通道页面

## 问题现象

GitHub Actions 中 `NotificationChannelSettingsPage` 前端测试仍查找旧单通道标题“SMTP 邮件通道”，并使用旧的 SMTP 配置接口 mock，导致测试无法找到页面标题且加载出的通道列表为空。

## 根因

邮件通知页面已切换为多 SMTP 通道列表和向导，页面标题为“邮件通知”，加载接口为 profiles 与 recipients 两个端点，单通道测试仍保留历史断言和响应结构。

## 解决方案

- 将测试标题断言更新为当前页面标题“邮件通知”。
- 将 mock 响应更新为多通道 profiles 与收件人目录契约，并提供可测试的 SMTP 通道 ID。
- 将测试动作更新为列表中的通道测试按钮，并断言按 profile ID 调用当前测试接口。

## 实际修改文件

- `src/pages/NotificationChannelSettingsPage.test.tsx`
- `docs/fixes/fix_20260927_02_邮件通知测试适配多通道页面.md`

## 验证命令与结果

- `npx vitest run src/pages/NotificationChannelSettingsPage.test.tsx --reporter=verbose`：修复后通过。

## 未验证项

- 未运行公共 `npm run lint` 或 `npm run build`，由父 Agent 统一执行。

## 风险与回滚方式

- 仅调整测试夹具和断言，不改变生产页面行为。
- 回滚测试文件与本修复记录即可恢复原测试内容。
