# 修复 Windows 下 Uvicorn 热重载导致服务假死 修复记录

## 问题现象

本地开发执行 `npm run dev` 后，前端登录页面不断提示“登录超时，请检查后端状态后重试”，且后端接口 `http://127.0.0.1:5010/api/docs` 完全挂起（Hanging）不返回，无法进行登录和任何 API 交互。

## 根因

1. **Uvicorn 热重载触发机制**：Uvicorn 在开发模式下使用 `watchfiles` 监测文件变化。启动阶段 Python 导入依赖包会编译并在 `backend/` 的子目录下写入 `.pyc` 字节码文件，这被误判为代码变更并瞬间触发热重载。
2. **Windows asyncio Socket 传递缺陷**：Windows 上使用 `WindowsProactorEventLoopPolicy`，当重载引发重新传递套接字与重启子进程时，极易报错 `OSError: [WinError 64] 指定的网络名不再可用。`。
3. **假死死锁**：报错导致 Worker 协程的 accept loop 直接崩溃死亡，而 Uvicorn 主进程仍然占用 `5010` 端口。这使得所有新的客户端 HTTP 请求在 TCP 握手后无法被处理，处于永久卡死超时状态。

## 解决方案

在 `backend/main.py` 的最顶部导入后，判断 `NODE_ENV == 'development'` 时，将 `sys.dont_write_bytecode` 设为 `True`，阻止开发环境下写入任何 `.pyc` 字节码文件。这规避了启动时的误触发重载，进而防止了 WinError 64 卡死。

## 验证命令与结果

1. 杀掉僵尸进程：`taskkill /F /PID 2824 /PID 6548 /PID 1592`
2. 运行开发后端：`npm run dev:backend`
3. 检查启动日志：无 `watchfiles.main: 5 changes detected` 重载，无 `WinError 64` 报错。
4. 使用 urllib 验证请求：`.venv\Scripts\python.exe -c "import urllib.request; resp = urllib.request.urlopen('http://127.0.0.1:5010/api/docs', timeout=5); print('Response Code:', resp.getcode())"` 极速返回 `Response Code: 200`。

## 风险与回滚方式

- 风险极低。该修改仅在 `NODE_ENV == 'development'` 且为开发环境生效。
- 回滚方式：直接删除 `backend/main.py` 最顶部的 `sys.dont_write_bytecode = True` 代码行即可。
