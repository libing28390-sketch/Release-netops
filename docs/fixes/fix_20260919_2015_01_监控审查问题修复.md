# 监控审查问题修复

## 问题现象

监控发布树审查发现报表会以固定值或零值表示未采样数据，接口指标存在端口串用风险；多租户报表和事件接口缺少完整对象范围；告警在缺失样本、维护窗口结束和通知失败时存在错误恢复、永久抑制或通知丢失；服务器资产还可能进入网络拓扑。

## 根因

监控报表绕过统一指标契约直接回退默认值，告警状态机没有区分 no-data 与 healthy；部分 SQL 只做角色校验而未按 tenant 过滤；通知是进程内异步发送且发送前更新节流状态；拓扑各读模型没有共享服务器分类边界。

## 解决方案

- 使用真实 VictoriaMetrics/出口探测样本、稳定资产/ifIndex 关联和显式 `NO_DATA/STALE` 状态。
- 为报表、overview、incident、collection status、outbound target 和拓扑入口增加 tenant/site 范围。
- 新增 PostgreSQL `alert_delivery_outbox` 及 m0241 迁移，支持幂等入队、`FOR UPDATE SKIP LOCKED`、租约恢复和指数退避；维护窗口恢复自动入队通知。
- 让无效计数器 delta 不推进恢复；服务器分类在拓扑发现、图持久化、读模型和前端绘图层统一执行。

## 风险与回滚方式

本次 outbox 为至少一次投递语义，部分渠道成功后重试可能重复；可通过后续按渠道拆分投递记录优化。代码回滚使用新的 revert 提交，数据库迁移 downgrade 保留 outbox 历史和待投递记录，不删除告警审计数据。
