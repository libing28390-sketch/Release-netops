# 问题现象

Quick Ops 的 H3C Comware V7 接口查询虽然实际经过 TextFSM 解析，却显示为 `NTC Templates（旧目录）`；同时 RackVision 资产解析在干净 CI 检出中可能只检查被忽略的构建目录，误判公开 GLB 不可用。

# 根因

- 未绑定平台 Profile 的 legacy operational collector 丢弃了统一解析器返回的版本模板元数据，并硬编码了旧 parser 标签。
- RackVision resolver 的可用性检查依赖 `assets/build/glb`，而该目录不进入干净检出；实际运行时使用的是 `public/assets/3d`。

# 解决方案

- legacy collector 复用版本感知的 `parse_device_cli_output()`，回传 `parser_platform`、`template`、`template_source` 和模板列表；无模板时明确标记 `platform-parser`。
- Quick Ops 前端移除旧目录文案，显示具体 `h3c_comware_v7_*.textfsm`，历史未回传值显示为“TextFSM 解析（模板未回传）”。
- RackVision resolver 以公开静态资源路径作为运行时可用性依据，并保留仓库根目录边界和非法路径回归测试。
