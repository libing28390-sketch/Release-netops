# SMTP 邮件通知向导与服务商预设

## 问题现象

SMTP 设置集中在简单表单里，服务商参数、认证凭据、连通测试和邮件投递结果混在同一流程中。用户不易区分 465 隐式 TLS、587 STARTTLS、授权码与邮箱登录密码，也无法在不发送邮件的情况下单独检查连接。原测试邮件路径还会把测试信息作为告警内容构造。

## 根因

- 页面没有引导用户逐步配置，也没有内置常见邮箱服务的 SMTP 参数。
- 宽屏容器上限偏小，表单在大视口中显得狭窄、左右空白过多。
- 连接状态和邮件送达被同一个测试动作表达，排查时无法定位到网络/TLS/认证还是投递环节。
- 后端缺少只做 SMTP 连接和认证的接口；测试邮件使用正常告警格式。
- 连接超时参数未用于 SMTP 连接，发送超时参数也未设置到发送 socket。

## 解决方案

- 新增三步 SMTP 配置向导，并预设国内、国际邮箱及常用自建/开源 SMTP 服务。
- 服务商选择采用搜索、分类和信息卡片，卡片展示主机、端口和加密方式。
- 个人中心示例姓名改为“韩梅梅”，邮箱示例同步改为 `han.meimei@example.com`；姓名、手机、邮箱占位提示提高对比度。
- 将内容区最大宽度扩展为 1536px，维持响应式内边距以改善宽屏表单比例。
- 已保存的配置可以在同一表单中继续修改并保存；增加删除入口，二次确认后清除配置和凭据并关闭邮件告警。
- 删除 API 通过空的租户 SMTP 覆盖记录阻止回退到共享默认配置，不会删除共享配置、告警历史或其他通知通道。
- 将 SSL/TLS（隐式 TLS）、STARTTLS 和无加密列为不同模式；无加密提示仅适用于受控测试网络。
- 增加单独的连接测试接口；测试邮件独立发送、使用 SMTP TEST 内容，不创建告警事件且不受告警启用状态阻止。
- 测试前自动保存改动；只有在用户确认收到测试邮件后，才允许从关闭状态打开正式邮件告警。
- 邮件主机变化时要求重新填写账号信息；切换到无需认证的 SMTP 时允许清除已保存密文。
- 使用连接和发送两项独立超时参数，并标注 Gmail/Outlook/Microsoft 365 当前未支持 OAuth2。
- 开源服务选项列出 Postfix、Exim 和 OpenSMTPD；Mailpit 提示 SMTP 1025 与 Web UI 8025。

服务商的 SMTP 主机、端口、可用认证和租户策略可能随时间变化，页面预设是常用起点，管理员仍需检查当前官方资料。需要回滚时恢复三个代码文件即可；本次没有数据库迁移。若只回滚连接测试，需同时移除 API 路由、service 函数和前端调用。
