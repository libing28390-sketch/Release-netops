# IPAM来源证据测试批次选择

## 问题现象与根因

v1.0.11首次正式标签Actions后端3643通过、2跳过、1失败。test_completed_run_context_and_failed_metadata_are_distinguished通过列表第一条断言failed-run状态；原成功来源与失败来源记录有相同observed_at，UUID排序会使首条落到原成功来源，形成时钟相关的偶发失败。main同SHA全量通过，不能据此忽略标签失败。

## 解决方案与文件

backend/tests/ipam/test_ipam_discovery_evidence.py固定测试时钟，按source_run_id明确选择失败批次，验证恰好一条、归属待确认、覆盖不完整，并新增原成功证据保留及汇总不能complete的断言。不修改业务逻辑或排序，不改监控/驱动/解析模板。更新本次发布plan/walkthrough记录失败和候选tag处理。

## 验证

隔离PostgreSQL完整发现证据测试复测，命令和最终结果由本次walkthrough记录；git diff --check检查。修正后的同SHA继续执行main/tag完整Actions，不能以重新提交或开始运行视为成功。

## 风险与回滚

仅测试及交付文档变更。公有v1.0.11尚未生成；修复后将未公开发行的源候选tag更新到修复commit，使用原tag对象的force-with-lease避免覆盖并发修改。历史公开tag不变，测试修改可revert，但会恢复随机失败。

验证调度：同SHA的main与tag发布工作流重复；正式标签是完整检查超集且会同步公有main，因此仅取消重复main流程，正式tag全部检查仍执行。

本地复测结果：12 passed in 163.56s，隔离源数据库已删除；git diff --check通过。
