# Git 变更记录: 修复解析失败时未展示调试器入口的问题

## 1. 变更背景与原因
当用户执行自定义 CLI 命令查询时，如果该命令在 ntc-templates 中**没有匹配模板**（如 `display ip interface brief` 对华三/ hp_comware 平台），后端解析会发生 `TemplateNotFoundError` 异常。
后端的异常处理会捕获该异常，并将该类别的 `parse_status` 设为 `'failed'`，表示解析失败。
然而前端 `QuickQueryResultOverlay.tsx` 的调试器引导 Banner 只检查了 `parse_status === 'unmatched'`，导致当解析状态为 `'failed'` 时，引导 Banner 无法被展示，用户就无法点击进入 TextFSM 调试器。

## 2. 解决方案与实施步骤
我们修改了 [QuickQueryResultOverlay.tsx](file:///d:/netops/netsops-main/src/pages/AutomationExecute/components/QuickQueryResultOverlay.tsx) 组件：
1. **拓宽展示条件**：将调试器 Banner 的渲染判断条件修改为 `parse_status === 'unmatched' || parse_status === 'failed'`；
2. **测试与回归**：通过以上更改，无论是完全无对应命令模版（unmatched）还是发生模板解析错误（failed），只要未产出有效的结构化表格记录，均会智能提示“该命令当前无匹配的结构化解析模板，前端仅展示原始回显。”并展现 `[在线调试与创建解析模板]` 按钮，打通完整的调试闭环。
