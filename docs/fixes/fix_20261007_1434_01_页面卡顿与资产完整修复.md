# 页面卡顿、监控错误与资产操作修复记录

## 问题现象

监控看板打开/刷新会卡顿并偶发报错；模板页有重复请求和较慢列表；资产列表、添加/修改表单及保存操作可能慢或报错；Grafana 冷加载较慢。此前监控 overview 已记录 500，数据库日志出现字面三引号 SQL 拼接文本。资产保存的具体线上错误未能从历史证据复现。

## 根因与范围

- Overview 子查询将租户条件通过三引号文本错误地拼入 SQL，导致语法错误；search 查询也有类似拼接问题与租户列歧义。Overview cache key 还可能让名为 `administrator` 的租户与管理员范围冲突。
- 模板列表逐行查版本和当前用户收藏；共享 lookup 回调依赖模板选择状态，首次选择会重跑请求/轮询生命周期。并发旧账号请求也需要按会话隔离。
- 资产和监控前端对若干请求错误采取静默或零数据展示，资产表单缺少选项加载/错误状态和重复提交保护。
- Hardware exporter 读取并解析 renderer 未使用的 JSON 阈值和审计字段，缺少 DB、解码、分组、渲染等阶段时长记录。此前证据没有证明 SNMP 扫描是当前卡顿的单一根因。

## 解决方案

- 修正监控 SQL 拼接、明确 search 的设备别名和租户条件，并用命名空间 cache key 分离管理员与租户数据。
- 对模板版本与当前用户收藏做分页批量读取。前端移除选择状态闭包依赖、合并同会话并发 lookup；登出、会话切换和卸载时取消旧请求并忽略迟到结果，保留路由刷新和120秒poll。
- 在监控与资产 UI 显示加载、错误、401/403权限、空数据和重试；资产保存防重复，失败保留输入，错误信息不暴露敏感凭据或堆栈。
- 缩窄硬件 exporter 查询列、停止解析未用 JSON 字段，并记录分阶段耗时与响应体大小。没有加入短 TTL 缓存。
- 隔离 PostgreSQL PUT 合同测试覆盖 staging 数据同步、hostname冲突409、坏rack400回滚、跨租户403和 Cisco→Huawei→H3C 平台归一化。现有后端保存服务通过合同，没有改写 `assets.py`/`rack_service.py`。
