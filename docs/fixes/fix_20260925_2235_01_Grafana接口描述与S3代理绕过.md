# Grafana 接口描述字段与 SeaweedFS 代理绕过修正

## 问题现象

- Grafana 将设备接口描述显示为接口全称，部分接口面板在旧查询下没有数据。
- 管理页测试内部 SeaweedFS S3 存储返回 `HTTP 502`。

## 根因

- H3C 设备 CLI 的 `description` 映射到 IF-MIB `ifAlias`（OID `.1.3.6.1.2.1.31.1.1.1.18`）；`ifName` 是接口全称。旧 Dashboard 查询错误地请求独立 `ifDescr{...}` 时序，运行时无该时序。
- `netops` 容器继承 `.env` 的代理环境变量，访问内部 `seaweedfs` 服务时原先没有明确的 `NO_PROXY` 规则。此为 S3 502 的可能原因，但未在部署容器中通过代理/直连对照定案。

## 解决方案

- Dashboard 生成器改用 `ifName` 与 `ifAlias` 按 `(instance, ifIndex)` 关联，描述列读取 `ifAlias`，并保留缺少 alias 时的接口行回退；重新生成设备、接口和出向三个 Dashboard JSON。
- 给 `netops` 的大小写 `NO_PROXY` 分别加入 `seaweedfs` 与 `nexora-seaweedfs`，更新部署说明和配置契约测试。
- S3 运行时根因仍待部署端核验。`Environment` profile 使用固定签名区 `us-east-1`；另一个 profile 配置的 `/conf` endpoint 路径需单独检查。
