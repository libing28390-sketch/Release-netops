# 本次工作区改动与 Actions 失败

## 问题现象

- SNMP 诊断无法分别主动验证设备系统信息与 LibreNMS 硬件指标。
- 上次 GitHub Actions 有 4 项失败：两项看板测试仍依赖旧面板编号和旧变量；平台识别测试遇到 PostgreSQL 中止事务；一个 Hillstone 用例把 QNAP 的企业号当成 Hillstone。
- 凭据轮换页需要降低宽表密度，并让共享凭据设备清单支持服务端检索和分页。
- 资产目录需要固定显示默认列，同时导出完整字段集合。

## 根因

- 硬件采集看板已改为按唯一 `asset_id` 选设备并调整面板布局，测试仍按旧 `id=8` 与 `site/vendor/role/device` 变量检查。
- LibreNMS 运行时 MIB OID 解析吞掉查询异常，但没有恢复 PostgreSQL 事务，后续资产查询因此失败。
- IANA 将 PEN 24681 分配给 QNAP；该用例中的 StoneOS 厂商信息来自 `sysDescr`，不是 `sysObjectID`。

## 解决方案

- 新增只读系统信息和硬件发现诊断接口；页面分开展示设备身份字段和传感器读数，标注资产回退字段与采集状态。
- 对可选 LibreNMS MIB 查询增加 PostgreSQL 保存点恢复。
- 将看板断言改为检查当前设备详情契约，并按实际厂商证据校准 `vendor_source` 预期。
- 凭据轮换页改为摘要表格与按需详情抽屉；共享凭据关联设备由管理员只读接口分页查询。
- 资产目录只使用默认可见列，导出固定使用全部字段定义。
- SNMP WALK、IF-MIB 与 LLDP 原有流程保持原样。
