# CI 数据库游标与 Promptfoo 原生依赖修复

## 目的

修复 1.0.8 发布工作流在 Linux Release 和 Knowledge Engine Promptfoo Gate 中暴露的两个独立问题，使后续 Windows 发布 job 能在其依赖条件满足后执行。

## 问题与根因

1. Linux 后端全量测试已经越过模块收集阶段，但数据库连接包装器 `_PgCursor` 没有实现 psycopg2 游标的上下文管理器协议。代码和测试使用 `with connection.cursor() as cursor` 时触发 `TypeError`，导致 2199 项测试错误。
2. Promptfoo 工作流用 `--ignore-scripts` 安装本地及全局 Node 依赖，跳过了 `better-sqlite3` 的原生绑定安装脚本。Node 22 运行 Promptfoo 时找不到 `better_sqlite3.node`，后续步骤被跳过，报告步骤再因缺少原始 JSON 失败。

## 修复

- 在 `backend/database/core.py` 的 `_PgCursor` 转发 `__enter__`/`__exit__`，保持包装器与 psycopg2 cursor 的兼容行为。
- 增加 `backend/tests/database/test_core_cursor_contract.py`，锁定上下文管理器契约。
- Promptfoo workflow 保留锁文件和包完整性检查，安装开发依赖后只对锁定的 `better-sqlite3` 执行安装脚本，并使用本地锁定版本的 Promptfoo，避免全局二次安装。版本校验直接读取包元数据，不启动 Promptfoo 自己的内部元数据存储；Nexora 的评测数据库仍是 PostgreSQL。

## 验证

- 运行游标契约测试与 Python 编译检查。
- 在 GitHub Actions 中确认 Linux Release 的 pytest 步骤及 Promptfoo 的依赖安装、Bootstrap、评测步骤继续执行。

## 风险与恢复

改动只涉及数据库适配器协议转发和 CI 依赖安装；如需恢复，可回退本次提交，不涉及业务数据或数据库迁移。
