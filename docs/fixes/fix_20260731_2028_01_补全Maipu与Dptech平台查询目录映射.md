# 补全 Maipu 与 Dptech 平台查询目录映射

## 问题现象
在前端下发 Maipu 或 Dptech 设备的快捷查询（如 `show lldp neighbors`）时，后端报错 `No command catalog found for category lldp on platform maipu`。

## 根因分析
1. 后端 `backend/services/operational_data_service.py` 中的 `COMMAND_CATALOG` 字典虽然为各平台定义了分类对应的具体命令（如 `interfaces`, `neighbors`, `arp` 等），但 `maipu` 平台是一个空字典，导致所有分类都找不到对应的命令目录映射。
2. 在 `_PLATFORM_ALIAS` 中缺少 `maipu_mypower` 到 `maipu` 的别名映射，如果入参是 `maipu_mypower`，将无法规范化为 `maipu`。
3. `dptech_ios` 平台存在映射，但命令拼写（如 `arp`, `mac_table` 等）并没有按照 TextFSM 解析库实际支持的命令格式编写。

## 解决方案
1. 在 `backend/services/operational_data_service.py` 中为 `maipu` 补充完整的 `COMMAND_CATALOG`（根据已有的 `maipu_show_*.textfsm` 模板补充了对应的指令，如 `show lldp neighbors`, `show arp`, `show vlan` 等）。
2. 在 `_PLATFORM_ALIAS` 中补充了 `maipu_mypower` 的别名。
3. 修正了 `dptech_ios` 在 `COMMAND_CATALOG` 中的命令，例如把 `show arp` 改为 `show arp all`，`show mac address-table` 改为 `show mac-address-table`。

## 实际修改文件
- `[MODIFY] backend/services/operational_data_service.py`

## 验证命令与结果
- 执行了 `npm run lint` 进行前端相关修改的类型校验（针对之前），校验通过。
- 执行了 `pytest backend/tests/ -k catalog`，测试全部通过，证明字典结构正确且不影响现有系统。

## 未验证项
- 由于没有实际的物理设备，目前只能依据现存的 TextFSM 模板名进行匹配验证。

## 风险与回滚方式
- **风险**: 极低。仅增加和修正了特定平台（Maipu、Dptech）的命令字典映射，不影响主流厂商（如 Cisco, Huawei, H3C）的核心执行逻辑。
- **回滚方式**: 撤销对 `backend/services/operational_data_service.py` 的修改，恢复原始字典结构。
