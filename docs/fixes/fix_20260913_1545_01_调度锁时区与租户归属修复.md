# 修复记录：调度锁时区与默认租户归属

## 问题现象

- PostgreSQL 每两秒记录 `scheduler_locks_pkey` duplicate-key ERROR，日志中 lock 的插入时间显示 UTC，PostgreSQL 日志前缀显示 CST。
- scheduler lock claim 使用过期行 DELETE 后直接 INSERT；失败路径被当作竞争吞掉但 PG 仍记录 ERROR，作业结束未释放锁、长作业无 heartbeat。
- `scheduler_locks.locked_at` 同时保存 UTC 文本时间和 Reindex/Import opaque owner token，字段类型/语义冲突。
- 同次全新 Docker 部署的默认 `admin` 无 tenant_id，资产导入返回 403。

## 根因

- PostgreSQL 错误日志使用 +08 本地时区；锁服务将 UTC ISO-8601 字符串写进 TEXT 字段。`14:54 CST` 与 `06:54+00:00` 是同一 instant，文本列不会由 PostgreSQL 自动格式化。
- 竞争使用非原子 delete + insert；scheduler decorator 及动态任务结束时没有释放；Reindex/Import 将 token 复用作 locked_at。
- 首次管理员创建发生在租户回填之后，用户租户列的初始默认值为空。

## 解决方案

- m0229 为 `scheduler_locks` 增加独立 `owner_token`，把 `locked_at` / `expires_at` 迁成 `TIMESTAMPTZ`，保留旧 ISO 时刻和非时间型 owner token；包含回滚转换。
- 核心调度、动态任务、Reindex、Import 使用过期条件原子 UPSERT，按 owner token heartbeat/release；正常完成即释放，长任务定期续租，TTL 保留为进程异常保护。
- Docker PostgreSQL 默认 `TimeZone` 与 `log_timezone` 设为 `${TZ:-Asia/Shanghai}`，不改变或删除现有 pgdata 卷。
- 同一 release 包含 m0228 默认 admin 租户回填与新用户从认证管理员继承租户的修复。
- DB-022 / ING-017 / OBS-007 契约和 DOC-004 Reindex 运维手册同步更新。

## 风险与回滚方式

- m0229 会重建小型 `scheduler_locks` 表的时间列；会保留 `lock_name`、owner token 和 expiry instant，不改其他业务数据。必须使用新应用版本与迁移同时更新，不要在旧 Reindex/Import worker 运行时手动执行 migration。
- Compose 命令变化会触发 PostgreSQL 容器重建；`nexora-pgdata` 命名卷保留。不要执行 `docker compose down -v`。
- `TIMESTAMPTZ` 存绝对时刻；Asia/Shanghai 是默认读入/显示时区，不改变已存时间点。回滚时协调停止应用并先执行 m0229 downgrade，再运行旧应用。
- 默认租户修复仅自动处理系统 bootstrap `admin`，不会擅自把其他 tenantless 用户指派到默认租户。
