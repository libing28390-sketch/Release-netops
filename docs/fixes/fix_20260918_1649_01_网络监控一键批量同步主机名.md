# 修复与功能记录：网络监控一键批量同步主机名

## 1. 问题现象与提交目的
- **问题现象**：在支持单台网络设备主机名 SNMP 同步后，当用户纳管数十台甚至数百台交换机时，如果需要逐台点击同步按钮，操作成本极高且容易遗漏。
- **提交目的**：
  1. 在【网络监控】页面左侧设备列表概览行增加【批量同步】按钮，提供一键批量校准在管设备主机名的入口。
  2. 后端提供 `POST /api/devices/batch-sync-hostname` 批量处理接口，支持并发受控探测（Semaphore 控制并发为 10），避免 UDP 报文瞬时突发拥塞网络。
  3. 严格遵循零模板标准：批量探测同样直接基于通用 RFC 1213 MIB-II `sysName.0` (OID: `1.3.6.1.2.1.1.5.0`)，完全不依赖任何特定厂商 SNMP 模板，适用于所有厂商设备。
  4. 保持数据原子联动：同步更新 `devices.hostname`、`devices.sys_name`、`physical_assets.hostname` 以及 `topology_observations.source_hostname`。

---

## 2. 根因与设计分析
- **批量并发与网络保护**：针对网络设备执行 SNMP Get 时，若直接启动上百个协程，容易引起网络丢包或古董设备 CPU 瞬时升高；因此引入 `asyncio.Semaphore(10)` 对并发数进行上限截断，平衡速度与稳定性。
- **UI 无感知与即时反馈**：同步执行期间按钮显示旋转 loading 状态并防重复触发，完成后弹出清晰的统计划 Toast（更新数、未变更数、失败数），并即时刷新前端列表和当前选中的监控视图。

## 3. 解决方案与实现说明
1. **后端接口**：
   - 在 [backend/api/devices.py](file:///d:/nexora/nexora-private/backend/api/devices.py) 中增加 `BatchSyncHostnamePayload` 与 `POST /api/devices/batch-sync-hostname` 端点。
   - 读取凭据库中的 SNMP Community，通过通用 OID `1.3.6.1.2.1.1.5.0` 并发读取 `sysName`。
   - 调用 `clean_system_hostname()` 清洗域名前后缀（例如 `.CCIE`）。
   - 自动回写 `devices`、`physical_assets` 和 `topology_observations` 表。
2. **前端交互**：

   - 绑定 `handleBatchSyncHostnames` 回调，完成前后状态切换、Toast 提示与数据驱动更新。
3. **测试验证**：
