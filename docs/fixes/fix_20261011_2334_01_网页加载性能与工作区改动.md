# 网页加载性能与工作区改动

## 问题现象与本次目的

性能建议涉及多个层次，代码中确有入口静态依赖、路由 lookup 重取、overview 遥测读取和拓扑首次加载等可确认的工作量。本次按用户授权实现有证据支撑的改进，并将其余工作区代码改动纳入同一主分支提交；不把未测量的 Redis、SQL 索引或虚拟化方案作为卡顿根因。

## 根因

- Vite 手工 3D vendor 分组使动态页面的 WebGL chunk 进入入口静态 preload；拓扑导出库在 app shell hook 中静态导入。
- shared lookup 只合并在途请求，没有按路由消费者限定请求且缺少完成后会话复用。
- monitoring overview 对设备遥测逐个读取；资源状态 GET 会耦合采样/持久化工作。
- 默认拓扑页和 Grafana 时间范围存在可以避免的初次加载工作。

## 解决方案

- 按操作动态导入登录背景、导入导出依赖与拓扑 PNG 导出；修正 Vite 3D 手工分包，并用生产 manifest 验证入口依赖闭包。
- shared lookups 按页面消费者和身份范围复用，Dashboard 热任务只在 Dashboard 请求。
- overview 遥测批量上限 250，按访问范围对同一在途计算 single-flight；health/resource GET 读取既有调度采样结果。
- 默认拓扑只加载站点/link 概览，进入站点或切换关系视图后取设备图；Grafana 尊重 dashboard 默认时段；普通 Nginx `/api/` 上游允许连接复用。
- 其余已存在于工作区的代码修改一并纳入审查和提交；内部 `.agents/` 与 `handoff.md` 不进入公有提交。
