# 严格使用 LibreNMS 采集规则

## 问题与目标

硬件采集逻辑中存在 Nexora 自定义的 H3C 无线硬件发现分支，且 Comware 的若干规则由 Python 适配层自行表达，可能与 LibreNMS 上游规则产生偏差。目标是以固定版本的 LibreNMS 规则为硬件发现依据，并保留 Nexora 现有采集架构，不部署 LibreNMS 服务。

## 解决方案

- 固定 LibreNMS 上游 commit `6c26b4fe4a40f7b392c19c36a44257212736e38c`，随代码携带所需 Comware OS、传感器发现、内存及数值换算源文件和许可证。
- 更新 Python 执行适配层，使 Comware CPU、内存、温度和光模块指标遵循对应上游规则，并移除 LibreNMS 硬件发现路径里的 Nexora 专有 H3C DOT11 扩展。
- 更新来源 manifest、覆盖上游文件哈希与关键采集行为的测试、计划和 walkthrough 文档。
