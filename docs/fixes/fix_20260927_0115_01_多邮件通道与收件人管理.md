# 多邮件通道与收件人管理

## 问题现象

邮件通知只有一套 SMTP 配置，不能逐通道测试、停用、编辑或删除；无法为不同 SMTP 服务指定不同收件人。简单表单也未能清晰表达从服务商配置到验证和启用的操作顺序。

## 根因

后端保存与读取固定的 `primary` SMTP 行，邮件 outbox 每条告警只有一个 email 目标。前端没有多通道管理表格或收件人组/用户选择模型。

## 解决方案

- 增加 m0256 SMTP 显示元数据和收件人目标字段，并保留旧配置。
- 新增按 profile ID 操作的 SMTP 管理与测试 API；敏感凭据只保存加密密文，不返回客户端。
- 支持多个独立 SMTP 通道；启用的 profile 在告警 outbox 中独立投递与重试。
- 收件人选择支持现有用户组和多个用户，发信时动态解析同租户 active 成员并去重。
- 将通知页面改为公共 `DataTable` 管理列表和三步向导，支持快速测试、启停、编辑、删除和权限降级。
- 保留旧 `primary` 的个人通知偏好语义，并按需求调整服务商类别、品牌标记与世纪互联卡片。

## 风险与回滚方式

- 组目标依赖用户资料上的自由文本组名；重命名后应更新所选目标。
- 多条启用通道会分别发信；每条通道的 SMTP 服务和收件目标决定投递路径。
- 回滚时恢复本次代码提交并保留 m0256 列和配置数据；迁移 downgrade 不删除用户数据。
