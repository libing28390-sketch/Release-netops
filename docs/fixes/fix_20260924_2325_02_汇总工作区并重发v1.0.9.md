# 汇总工作区并重发 v1.0.9

## 问题现象与本次目的

工作区累积了尚未提交的 Docker、Grafana、SNMP 后端与前端改动，当前私有源仓库仍停留在旧提交。虽然公有仓库已有 `v1.0.9` 标签，但上次发布 job 在百度网盘上传阶段失败，GitHub Release 创建步骤被跳过。本次按用户明确授权汇总推送所有经审阅的工作区变更，并将现有 `v1.0.9` 标签更新到新发布提交。

## 根因

- `release.yml` 将可选百度网盘镜像上传放在公有 GitHub Release 创建之前；网盘令牌刷新或第三方服务失败会使步骤失败并阻断同一 job 的后续步骤。
- 本地 `v1.0.9` 标签仍指向旧提交 `ee1a368e`，与当前 `main` HEAD `c70d65ed` 不同。
- 当日已完成的 Docker、Grafana、SNMP、MIB UI 代码与其计划/走查记录尚未在工作树之外形成一个包含完整改动的发布提交。

## 解决方案

- 对百度网盘上传步骤设置 `continue-on-error: true`，使其失败不阻断 GitHub Release 和 Windows Agent 发布。
- 扩充 v1.0.9 Release Note，补充 SNMP 厂商识别、LLDP 本地端口映射、Grafana Auth Proxy 网络/路由、Docker 前端构建内容。
- 将工作区里审阅过的代码、配置、发布说明、计划与走查文档一并提交到 `main`，并将 `v1.0.9` 标签更新至新提交；发布 workflow 会再执行正式门禁。
- `.env`、部署备份、密钥、运行数据和 ignored 文件不纳入版本控制。

- `v1.0.9` 是已存在的发布标签，本次将其从旧目标移动到新发布提交。若发布门禁失败，可按用户决定恢复旧标签提交 `ee1a368e`；保留代码提交并报告发布失败原因。
