# 告警、配置备份统计与 Hillstone 平台修正

## 问题现象

- 用户资料里的通知测试请求因读取错误的 localStorage 键而返回 `401 Authentication required`；告警规则页把飞书渠道显示成具体产品名，渠道控件也偏繁复。
- 配置备份历史及今日统计可能把服务器、主机资产计入网络设备成功率和备份统计。
- Hillstone / StoneOS 的 SNMP 识别、资产平台归一化和备份驱动路径缺少一致的 canonical platform 处理，个别路径可能落到 Cisco 或拒绝 StoneOS 别名。

## 根因

- 应用会话令牌存放在 `localStorage.netops_token`，通知测试却读取 `sessionToken`。
- 备份台账仅保存设备结果；部分历史查询直接按台账计数，没有关联当前资产类型排除非网络资产。
- Hillstone 平台代码已在备份命令和识别服务中增加，但资产 vendor/platform 校验仍缺对应映射和别名优先级。

## 解决方案

- 通知测试统一读取 `netops_token`；告警规则渠道选择器改用紧凑布局，界面显示 `Webhook`，仍保存内部 `feishu` 值。
- 批次列表、详情、Site 与今日统计统一按当前资产关系排除 `server`、`host`、`physical_server`；增加混合资产回归测试。
- 完成 Hillstone/StoneOS vendor、platform、资产 API、驱动、配置命令和识别候选映射；发生平台冲突时不静默沿用 Cisco，并将 StoneOS / 山石别名归一到 `hillstone_stoneos`。
- 保留幂等 migration `m0255_hillstone_stoneos_platform.py`，由应用迁移流程新增 profile。

- 历史备份分类依赖当前 `devices.asset_id → physical_assets.asset_type` 关系；删除或改分类会改变历史统计。
