# 全站列表样式与采集器运行状态

## 问题现象

- 多个 URL 的列表工具栏、表格行选中态、操作按钮、搜索提交和列设置入口不一致；自动化与 CMDB 页面仍保留不统一的按钮颜色、位置或换行表现。
- 资产标签页的分配数不准确或列对齐不稳；标签页新建入口和搜索/工具图标布局不统一。
- 采集器详情把本地采集器显示为“心跳未上报”，状态检查仅凭启用标记返回通过，发布配置还会把运行状态写成在线。
- Docker 更新仅备份 `.env`，没有显著说明新版 `.env.example` 与旧版相比有哪些参数变化。

## 根因

- 页面局部样式与交互各自实现，公共表格和列表工具栏规范没有覆盖所有同类页面。
- 资源计数依赖不完整的设备列表或错误的关联口径。
- 仓库没有远程采集器的心跳写入端点/上报进程；配置发布状态被误当作运行状态，本地 Docker 服务也不应套用 agent 心跳语义。
- 更新脚本没有对比升级前后环境模板中的变量名与变化类别。

## 解决方案

- 统一常见列表工具栏、表格动作列、列选择和表单布局；将新建入口置左、搜索与其他图标置右，统一蓝色操作、可辨识的选中行、操作按钮常显及回车搜索。
- 修正自动化、CMDB、资产、标签、巡检及其他受影响页面，减少窄列换行；修正资产统计/标签关联计数和标签分配数对齐。
- 本地采集器使用固定内部的 vmagent 与 SNMP Exporter 健康接口；远程/边缘采集器无心跳显示未知；状态检查报告运行探测结果，不声称已验证真实设备采集；发布配置只更新配置应用状态。
- Docker update 比较升级前模板与新版 `.env.example`，醒目显示新增、默认值变化和废弃参数，并保存不含参数值的报告；不会覆盖用户 `.env`。
- 补齐三处搜索框的 Enter 提交行为，并按界面语言本地化采集器提示关闭按钮的无障碍标签。

## 风险与回滚方式

- 如果本地健康探测地址在目标部署中不可达，应检查 Compose 服务名、容器网络和健康接口；回滚时可恢复前端镜像与后端文件备份，不涉及数据库迁移。
- 如果 `.env.example` 比较报告异常，可回退更新脚本中的比较函数；报告不包含任何变量值，原 `.env` 仍以目标机备份为准。
- 表格公共样式变化影响多个页面；如目标页面回归，可定位受影响共享组件并按已备份应用镜像回滚。
