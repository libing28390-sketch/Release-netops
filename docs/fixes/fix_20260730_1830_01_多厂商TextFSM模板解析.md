# 修复/变更记录 - 锐捷交换机、迪普防火墙、迈普交换机 TextFSM 模板开发与验证

## 1. 提交目的 / 问题现象
根据用户提供的锐捷交换机、迪普防火墙、迈普交换机 CLI 回显结果，按照 NTC-Templates 规约开发对应的 TextFSM 解析模板，补齐国产多厂商网络设备的结构化 CLI 解析能力，并完成充分验证。

## 2. 根因与分析
- **锐捷 RGOS**：原 `ruijie_rgos_show_ip_interface_brief.textfsm` 仅能匹配部分带有 Pri/Sec 表头的路由器回显，无法匹配带有 `OK? Method` 列的交换机表格，且缺少 `show interface brief` 接口摘要解析。
- **迪普防火墙 (Dptech)**：系统尚未提供针对 `dptech_ios` 平台的 `show interface brief` 及 `show ip interface brief` 结构化解析模板。
- **迈普交换机 (Maipu)**：系统尚未提供针对 `maipu` 平台的 `show ip interface brief` 及 `show interface brief` 结构化解析模板。

## 3. 解决方案与实际修改文件
1. **新建与升级 TextFSM 模板**：
   - `data/textfsm_templates/ruijie_rgos_show_ip_interface_brief.textfsm`
   - `data/textfsm_templates/ruijie_rgos_show_interface_brief.textfsm`
   - `data/textfsm_templates/dptech_ios_show_interface_brief.textfsm`
   - `data/textfsm_templates/dptech_ios_show_ip_interface_brief.textfsm`
   - `data/textfsm_templates/maipu_show_ip_interface_brief.textfsm`
   - `data/textfsm_templates/maipu_show_interface_brief.textfsm`
2. **后端引擎与规范化配置**：
   - `backend/core/textfsm.py` (注册 `dptech_ios` 与 `maipu` 映射及测试 Samples)
   - `backend/core/platform_utils.py` (完善 `dptech` 归一化为 `dptech_ios` 逻辑)
3. **单元测试**：
   - `backend/tests/vendor_audit/test_ruijie_dptech_maipu_textfsm.py`
