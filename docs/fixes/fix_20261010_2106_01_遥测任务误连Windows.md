# 遥测任务误连 Windows 主机

## 问题现象

日志显示 `device_telemetry_sampler` 尝试通过 SSH/22 连接 Windows 服务器 `web-srv-02`。

## 根因

`record_device_telemetry_snapshot()` 执行 Bash/Linux 脚本 `insp_linux_full`，原目标条件允许“平台为 Linux 或设备分类包含 server”。Windows 服务器会因通用分类命中；SSH 执行器在端口字段缺失时回退到 22。

## 解决方案

移除通用 `server` 分类兜底，只对显式平台值 `linux`、`ubuntu`、`centos`、`debian`、`redhat` 的在线设备执行 Linux 遥测。Windows、ESXi 和未知平台均跳过，不改变其他巡检任务或 WinRM 功能。

## 实际修改文件

- `backend/services/telemetry_service.py`
- 此提交按用户“push 全部代码到 main”的明确要求，同时包含工作区中此前积累的 IPAM、SNMP/NSOT、IP 定位、CMDB 和导航界面源码改动；未包含 `.agents/`、`handoff.md`、运行日志和构建产物。
- 对应计划与走查：`docs/plans/plan_20261010_2106_01_Linux遥测目标筛选.md`、`docs/walkthrough/walkthrough_20261010_2106_01_Linux遥测目标筛选.md`。

## 验证命令与结果

- `python -m py_compile backend/services/telemetry_service.py`：通过。
- `git diff --check`：通过。
- 目标筛选代码静态核对：只接受 Linux allowlist。
- 测试与真实设备连接验证未执行；本次仅调整采集目标筛选，不部署。

## 风险与回滚

- 未登记的 Linux 平台别名会被跳过。确认其 Bash 脚本兼容后，将别名加入 allowlist 即可恢复。
- 回滚方式为恢复 `device_category` 兜底条件；无需数据库迁移。
