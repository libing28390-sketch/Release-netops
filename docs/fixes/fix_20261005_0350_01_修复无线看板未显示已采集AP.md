# 修复无线看板未显示已采集 AP

## 问题现象

用户在 Docker 中部署后，Grafana 无线看板仍未显示 H3C AC 下的 AP。

## 根因

SNMP 设备探测正常，AC_11 的 `up{job="network_snmp"}` 为 1，VictoriaMetrics 也已有 AP_12/AP_13 的硬件状态与无线传感器序列。但硬件库存采集结果标记为 `job="platform_hardware_inventory"`，无线 dashboard 将这些指标错误限定为 `job="network_snmp"`，因此查询为空。AP 总数及客户端摘要的向量匹配还将 `job` 当作设备身份的一部分，不能合并两个采集 job 的结果。

## 解决方案

- 将 AP、Radio、BSS、SSID 等归一化无线硬件指标改为匹配 `platform_hardware_inventory`。
- AP 总数及客户端摘要在按设备维度归并后，以站点、厂商、角色和主机名跨 job 合并，避免同一设备来自 SNMP exporter 和硬件库存采集的重复结果。
- 加入生成器回归测试，并重新生成 Wireless dashboard JSON。

## 实际修改文件

- `monitoring/grafana/generate_dashboards.py`
- `monitoring/grafana/dashboards/nexora-network-wireless.json`
- `backend/tests/monitoring/test_domestic_and_wireless_monitoring.py`
- 对应计划与 walkthrough 文档。

## 验证命令与结果

- `.venv\Scripts\python.exe -m pytest backend/tests/monitoring/test_domestic_and_wireless_monitoring.py -q`：7 passed。
- `python monitoring/grafana/generate_dashboards.py`：成功生成 12 个 dashboard JSON。
- 12 个 JSON 文件均成功解析；`git diff --check` 通过。
- 浏览器现场查询确认 AP_12/AP_13 指标存在且属于 `platform_hardware_inventory`；AC_11 的 SNMP `up` 为 1。Grafana Explore 对修正后的跨 job AP 汇总 PromQL 返回 AC_11 = 2。
