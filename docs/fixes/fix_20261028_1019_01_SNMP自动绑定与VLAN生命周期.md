# SNMP 自动绑定设备平台与 VLAN 生命周期

## 问题现象

- 资产导入能通过 SNMP 识别厂商、型号和软件版本，但没有把匹配的平台注册 Profile 自动绑定到网络设备。
- 已有 `devices.version` 非空时，导入流程可能保留旧版本，导致版本 Profile 匹配依据过期。
- VLAN 目录会保留已失去采集来源的自动发现记录；设备删除后，CLI VLAN 快照可能成为孤儿；自动 VLAN 因 prefix 外键关系而无法删除。

## 根因

- SNMP 导入 enrichment 没有调用平台注册绑定服务；原版本写回逻辑优先使用数据库已有值。
- VLAN 来源只做 upsert，没有在来源消失后重算；设备快照表缺少设备删除级联；服务层把所有 prefix 引用一律当作永久删除阻塞。

## 解决方案

- 复用资产导入已有的 `sysObjectID/sysDescr/sysName` SNMP 结果。每次识别到新版本时先同步 `devices.version`，然后以该轮厂商、平台、版本匹配 Profile 并调用现有绑定器；标记 `platform_source=SNMP_AUTO` 并写审计事件。不增加 SNMP 请求、不覆盖已有绑定、不改 `snmp_metric_profile_id`。
- 用户提供的 H3C 样本解析为版本 `7.1.064`，归入 `h3c_comware_v7`。企业根 OID 本身不匹配带子节点边界的前缀规则，该样本通过 `sysDescr` 的 H3C 文本回退识别。
- m0300 为 CMDB collection snapshots 与 VLAN observations 增加设备删除级联，并清理设备不存在的派生快照。设备删除后按站点重算接口、ARP、MAC 和成功 CLI VLAN 快照来源；最后来源消失时仅清理自动 VLAN 行，保留 prefix、手工覆盖和业务绑定。
- 自动 VLAN 可在无实时来源且无手工关系时删除；解除自动 prefix 关联时保留 prefix 记录。VLAN 页面提供显式刷新，不启用周期刷新。

## 风险与回滚方式

- `devices.version` 也用于现有 SNMP 指标 Profile 兼容性匹配；版本更新可能改变兼容性判断。本次没有修改监控代码或指标 Profile 绑定。
- 首次自动 Profile 绑定沿用现有锁定语义；如需纠错，使用现有管理员更正流程。
- 回滚应用代码不会删除 prefix 或监控指标 Profile 绑定。m0300 downgrade 保留设备级级联约束；已清理的孤儿快照是可重新采集的派生状态，不能由迁移自动恢复。
