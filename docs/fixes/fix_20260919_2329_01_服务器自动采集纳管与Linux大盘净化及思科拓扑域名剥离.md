# Git 提交修复记录：服务器自动采集纳管与Linux大盘净化及思科拓扑域名剥离

## 1. 问题现象与本次提交目的
1. **思科拓扑邻居设备名携带多余域名**：思科设备配置了 `ip domain name eve.lab`，LLDP 邻居中输出形如 `R3.lab.local`、`R2.lab.local`，导致拓扑图节点名称带有多余的 `.lab.local`，无法与 CMDB 录入的纯短名 `R2`、`R3` 匹配；
2. **服务器资产缺乏内置自动采集**：系统内置采集计划仅针对网络设备 SNMP，CMDB 中录入的 Linux/Windows 服务器资产未自动生成 exporter 抓取目标文件；
3. **07 Linux 服务器大盘混入网络设备指标且面板单薄**：模板变量未限定服务器作用域导致网络设备混入，PromQL 包含 `or ifHCInOctets` 等网络指标回退，且缺少运行时间、吞吐、丢包、连接数、进程阻塞等关键性能监控；
4. **Grafana 全网大盘站点下拉为 ID**：模板变量绑定 `site_id`，下拉框展示为 UUID（如 `site-4eb4ad17a9f3`），不直观且无法按站点名称过滤。

---

## 2. 根因分析
1. **拓扑解析未做域名剥离**：`CiscoNormalizer` 及拓扑服务直接使用 TextFSM 匹配到的完整 `remote_device` 字符串，未去除 FQDN 域名后缀；
2. **监控编译器未打通 Server 资产**：`monitoring_compiler.py` 和 `monitoring_v1.py` 在加载采集输入时仅查询 `devices` 表，未查询 CMDB `physical_assets` 中 `asset_type='server'` 的服务器，且缺少 `linux_targets.yml` 和 `windows_targets.yml` 自动编译逻辑；
3. **大盘变量未隔离且 PromQL 回退失当**：Linux 大盘模板变量查询条件为 `{__name__=~"node_.*|up"}`，导致带 `up` 指标的网络设备被拉入；部分面板为了兜底错误地增加了网络设备 SNMP 指标；
4. **大盘站点变量绑定错误标签**：大盘生成器在 `make_network_variables` 中使用了 `site_id`，未映射到 `site_name`。

---

## 3. 解决方案
1. 在 `topology_service.py`、`cisco.py` 和 `devices.py` 中引入 `strip_domain_suffix`，保留 IP 地址的同时智能剥离 `.lab.local` 等域名后缀；
2. 在 `monitoring_compiler.py` 增加 `render_server_targets` 函数，并在编译产物中自动输出 `linux_targets.yml` 与 `windows_targets.yml`，打通 CMDB 服务器纳管与运行时同步；
3. 重构 `build_linux_dashboard`，限定变量至 `job="linux_servers"` 与 `node_*`，彻底删除网络设备 SNMP 指标，全面扩充至 14 个纯正主机指标面板；净化 Windows 大盘；
4. 将所有大盘生成模板中的站点变量从 `site_id` 替换为 `site_name`，选择器统一调整为 `site_name=~"$site"`，重新编译生成全部大盘 JSON。
