# NSOT 采集模板、操作目录与定位/刷新优化

## 问题现象与根因

1. **NSOT 采集策略分散**：设备采集策略分散在 NSOT 页面，批量模板和周期缺少统一入口；作业详情仅展示固定说明，看不到设备模板、采集项和版本命令。已绑定 Profile 缺少单项 Action 时，操作类别没有利用对应 TextFSM 模板。
2. **知识源定时刷新冗余**：此前知识源存在后台定时刷新探测机制，带来不必要的网络负载与维护成本，需要将定时刷新移除并将契约改为手动/按需触发。
3. **IP 定位缓存摘要与耗时追踪**：IP 定位页面在不同阶段的缓存命中展示不够清晰，缺少独立于 UI 渲染的耗时与缓存摘要计算逻辑。

## 解决方案

1. **NSOT 采集模板与操作目录**：
   - 增加角色默认/预设/自定义模板、按 IP 查询策略、Automation 批量应用和范围调度；
   - 增加操作目录和只读作业预览；
   - 已发布 Registry Action 优先，缺失的 Quick Ops Action 通过精确平台/版本 TextFSM 回退；
   - 每条命令展示独立来源，设备软件版本与 Registry 发布号分开，数据库投影无需 CLI。
2. **移除知识源定时刷新**：
   - 移除 `source_freshness_service.py` 及其在 `main.py` 和 `scheduler_service.py` 中的定时注册；
   - 更新契约文档与相关测试用例，统一为手动/变更触发。
3. **IP 定位缓存摘要与索引优化**：
   - 新增 `m0230_devices_ip_lookup_index.py` 优化 IP 查询索引；
   - 新增前端 `ipLocatorCacheSummary.ts` 及独立单测，优化定位耗时展示。

## 未验证项、风险与回滚

- **未验证项**：未在真实物理网络设备环境中下发大规模采集指令；真实设备采集依赖网络可达性与凭据正确性。
- **风险**：采集预览基于数据库当前记录的平台与版本，如果设备操作系统版本发生手工变更但未同步，预览命令可能与实际执行命令存在差异。
- **回滚方式**：可直接使用 `git revert` 回滚本次提交；数据库索引迁移 `m0230_devices_ip_lookup_index.py` 支持标准 downgrade 回滚。
