# 修复记录 - 修复左侧栏折叠报表空白与Grafana大盘全量统计及H3C接口状态

## 问题现象
1. **左侧栏子菜单空白**：点击监控报表的三项子菜单（全网接口流量与利用率、网络设备运行与资源、互联网出口与 WAN 链路）后，整个左侧导航栏消失（ModuleSubNav 卸载返回 null），页面刷新后左侧栏依然无法展示。
2. **Grafana 大盘数据统计不准**：在 Grafana「01 网络总览」等 Dashboard 中，「纳管设备数」只显示 1 台，且「监控站点数」读取不准（应该全量展示），同时顶部下拉变量联动过滤时设备范围被过分收窄。
3. **H3C 交换机接口状态显示 UNKNOWN**：在监控报表表格中，H3C Comware 设备（如 F1090-10 等）大量闲置/二层端口的运行状态显示为 `UNKNOWN` 徽章，未正常显示为 `DOWN`。

## 根因分析
1. **左侧栏空白根因**：
   - `src/components/ModuleSubNav.tsx` 的 `checkChildActive(child, path)` 仅核对顶级导航项自身 `path` 及 `activeMatch`，未递归遍历其 `child.children`。
   - 用户访问 `/monitor/reports/devices` 或 `/monitor/reports/outbound` 时，所有模块分组均判定为 false，`currentGroup` 计算结果为 `undefined`。
   - `ModuleSubNav` 执行了保护逻辑 `if (!currentGroup) return null;`，导致侧边栏组件被完全卸载。
2. **Grafana 大盘数据不准根因**：
   - 「纳管设备数」PromQL 表达式包含 `hostname=~"$device"` 等级联过滤，导致选中特定设备时大盘总数被压至 1；且仅统计了 `ifOperStatus` 指标，未采集或离线的探针设备被遗漏。
   - 「监控站点数」仅查询 `count(count by (site_name) (ifOperStatus))`，受限于单一指标并忽略了空值与其它指标共存情况。
   - 模板变量的 `query` 均绑定了 `label_values(ifOperStatus, ...)`，导致未上报 `ifOperStatus` 的站点和设备在下拉框中无法选中。
3. **H3C 接口状态 UNKNOWN 根因**：
   - H3C Comware 设备的 `display interface brief` 命令中，二层桥接接口（Bridge Mode）仅输出 `LINK` 列（`UP`/`DOWN`/`ADM`），无 `PROTOCOL` 列；三层路由模式闲置端口的 `PROTOCOL` 显示为 `--`。
   - `interface_collection_service.py` 将 `PROTOCOL` 作为 `oper_status` 来源，遇到 `--` 或空值被 `_normalize_status` 判定为 `unknown`，忽略了物理 `LINK` 状态已明确为 `DOWN`。
   - `monitoring_export_service.py` 导出报表时直接透传数据库中的 `unknown`，未根据 `admin_status` 与实时 VictoriaMetrics `ifOperStatus` 进行级联兜底。

## 解决方案与修改说明
1. **前端导航与折叠修复**：
   - `src/components/ModuleSubNav.tsx`：改进 `checkChildActive`，支持对 `child.children` 递归检索；当访问任何子路由时均可正确命中 `realtime` 分组并自动展开 `monitoring-reports`。
   - `src/components/AppSidebar/navConfig.ts`：为 `monitoring-reports` 配置 `activeMatch: '/monitor/reports'`，子菜单 `reports-interfaces` 配置 `activeMatch: '/monitor/reports/interfaces,/monitor/reports'`。
2. **Grafana 大盘全量统计与全局变量优化**：
   - `monitoring/grafana/generate_dashboards.py`：
     - 将「纳管设备数」调整为 `count(count by (instance) (ifOperStatus or up{job="network_snmp"} or {job=~".*snmp.*"}))`，确保全量纳管节点统一纳入统计。
     - 将「监控站点数」调整为 `count(count by (site_name) (ifOperStatus{site_name!=""} or up{site_name!=""} or {site_name!=""}))`，统计全网所有非空监控站点。
     - 将各 Dashboard 模板变量的 `label_values` 查询由限定 `ifOperStatus` 调整为全局 `label_values(site_name)` 与 `label_values({site_name=~"$site",vendor=~"$vendor"}, hostname)`。
     - 重新生成全套 7 个 Grafana Dashboard JSON 文件。
3. **多厂商与 H3C 接口状态归一化**：
   - `backend/services/interface_collection_service.py`：
     - `_normalize_status` 支持 `--`、`-`、`*down`、`none` 映射为 `down`。
     - `_status_record` 增加状态继承机制：当 `oper_norm == 'unknown'` 且物理 `admin_norm in ('up', 'down')` 时，直接继承 `admin_norm`；若 `admin_norm == 'down'` 则 `oper_norm` 强制归一为 `down`。
   - `backend/services/normalizers/h3c.py`：
     - `record_value` 支持 TextFSM 中的 `link` 与 `protocol` 键。
     - `_merge_interface` 支持根据 `admin_status` 兜底补全 `oper_status`。
   - `backend/services/monitoring_export_service.py`：
     - 增加对 VictoriaMetrics `ifOperStatus` 的瞬时查询映射 `if_oper_map`。
     - 当数据库记录为 `UNKNOWN` 时，依次通过 VM 遥测（1=UP, 2=DOWN）、`admin_status`（DOWN/UP）进行兜底，彻底杜绝表格中出现脏 `UNKNOWN`。
4. **数据库历史数据纠偏**：
   - 纠正了数据库中历史存量的 38 条 `unknown` 状态接口记录，全部校准为 `down`。
