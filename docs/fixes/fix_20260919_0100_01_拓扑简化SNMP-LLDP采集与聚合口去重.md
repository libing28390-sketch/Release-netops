# fix_20260919_0100_01 拓扑简化 SNMP-LLDP 采集与聚合口去重

## 问题现象

1. **链路重复**：接口有描述时，拓扑图中出现重复 links（每条物理链路被渲染两次）。
2. **采集命令冗余**：刷新发现时执行了大量 CLI 命令（OSPF、ISIS、BGP、STP 邻居等），引入不必要的复杂度与耗时。
3. **聚合口重复**：拓扑图中聚合链路以双线形式呈现——数据库存储的聚合记录与运行时动态综合的聚合记录同时渲染。

## 根因

1. `_rebuild_links_from_observations_unlocked` 在合并链路时未充分去重，接口描述作为标识导致同一物理链路生成两条记录。
2. `run_topology_discovery` 中保留了 BGP/OSPF/ISIS/STP 等协议的 SSH CLI 采集分支，这些分支与 SNMP LLDP 功能重叠且维护成本高。
3. `_synthesise_runtime_aggregation_links`（读取时动态综合）未感知数据库中已存在的 `link_kind='aggregation'` 记录，导致对同一设备对同时输出 DB 聚合 + 运行时合成聚合。

## 解决方案

1. **去重链路**：修正链路 key 生成逻辑，确保接口描述不影响唯一性判断，存储前统一规范化端点标识。
2. **精简采集**：删除 BGP/OSPF/ISIS/STP 协议相关的 SSH 命令采集分支，发现流程只保留 SNMP LLDP + 必要 SSH LLDP 回退。
3. **聚合去重**：在 `_synthesise_runtime_aggregation_links` 中预先查询已有 `link_kind='aggregation'` 记录，对于 DB 中已有聚合的设备对，跳过运行时综合并压制其下属物理成员链路，避免双重渲染。
