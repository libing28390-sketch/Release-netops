# Git 提交修复记录 - 监控报表子菜单迁移至左侧侧边栏（可折叠）与公共分页组件替换

**创建时间**：2026-09-19 13:00 (UTC+8)  
**提交类型**：功能与体验优化 (`feat(monitor)`)

## 1. 问题现象与提交目的

1. **/monitor/reports 分页交互不统一**：
   - 原监控报表页面采用局部简单的向前/向后翻页按钮，缺少系统公共标准分页组件具备的每页条数切换（10/20/50/100 条）、直接页码输入跳转、第一页/最后一页导航以及双语国际化能力。
2. **页面内部 Tab 占用视野且与左侧主导航割裂**：
   - 报表类型（全网接口流量与利用率、网络设备运行与资源、互联网出口与 WAN 链路）原作为页面内容区顶部横向标签页，无法通过侧边栏一目了然定位，也无法分享特定子报表的独立 URL；
   - 用户希望将这三个子菜单迁移至左侧侧边栏【实时监控】->【监控报表】下，并要求具备**访问时自动展开、离开时自动折叠、支持手动折叠**的交互效果。

---

## 2. 根因分析

1. 原报表页面在早期开发时独立实现了内联的分页展示逻辑，未接入系统全局通用组件 `src/components/Pagination.tsx`；
2. 原系统侧边栏仅针对一级手风琴分组做了状态管理，缺乏二级条目（带 `children` 的 NavChild）的嵌套路由监听与折叠/展开动画状态机支持。

---

## 3. 解决方案

1. **统一接入公共分页组件**：
   - 在 `src/pages/MonitoringReportsPage.tsx` 中移除原生手写的分页元素与未使用的分页辅助计算；
   - 引入 `<Pagination ... />`，传入当前页码、总数据量、每页条数及变更回调，完全复用系统的标准交互规范。
2. **左侧侧边栏支持二级可折叠子菜单并联动路由**：
   - 在 `src/components/AppSidebar/navConfig.ts` 中为 `monitoring-reports` 配置 3 个下级菜单（`/monitor/reports/interfaces`、`/monitor/reports/devices`、`/monitor/reports/outbound`）；
   - 在 `src/components/AppSidebar/NavItem.tsx` 中增加折叠小箭头展示与点击事件阻止冒泡支持；
   - 在 `src/components/AppSidebar/index.tsx` 中增加 `openChildIds` 响应式状态：
     - 当访问 `/monitor/reports` 或其子路由时，自动计算命中并展开；
     - 当导航至无关菜单时，自动将其收起折叠；
     - 点击小箭头或条目时支持实时手动切换展开/折叠。
3. **报表页面 URL 深度双向联动**：
   - 通过 `useLocation` 解析路由后缀（`interfaces`/`devices`/`outbound`），与页面内的查询数据及导出工具深度绑定；
   - 将页面顶部的横向 Tab 按钮替换为权威且简洁的当前活动报表标识条。
