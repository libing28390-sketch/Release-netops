# 修复记录：今日工作区改动合并

## 问题现象
- IPAM 前缀列表缺少覆盖全部筛选结果的导出。
- 拓扑画布工具栏遮挡 SVG；宽屏节点横向间距与角色层距失衡，站点摘要分页割裂卡片总览。
- Linux Docker 首次启动会因后端暂时 unhealthy 留下 Created 容器；SNMP Exporter 0.26 拒绝持久化配置里的旧 lookup 字段；S3 sidecar profile 可能未被启用。

## 根因
- 前缀页仅加载当前分页且没有导出映射。
- 拓扑组件用外层尺寸布局并将工具栏覆盖在画布上；保存的旧坐标延续了过宽比例。
- Docker 本地 healthcheck 受代理环境影响且首次启动宽限较短，部署脚本在首次 Compose 失败后未等待恢复重试。
- 默认 SNMP 配置、编译器和持久化 volume 使用与 snmp_exporter v0.26 不兼容的 `source_indexes` / `lookup` 字段。
- SeaweedFS 位于 `object-storage` profile；部署脚本对带空白、引号或 CRLF 的 dotenv 存储模式识别不足。

## 解决方案
- 添加 XLSX/CSV 全分页前缀导出、公式注入处理和导出快照列。
- 将拓扑工具栏移出绘图区，按真实 SVG viewport 布局，并按相邻角色层距设置节点行距；布局 schema/key 升至 v8。站点摘要卡片去掉分页并按站点数量自适应排列。
- 将 Docker probe 固定到 loopback、禁用代理并增加冷启动宽限；部署脚本等待 netops healthy 后自动补启动容器，不重建、不拉取镜像。
- 默认 SNMP 模板和编译器输出 v0.26 lookup schema；启动时原子、幂等迁移旧 monitoring volume。
- 部署脚本规范化 S3 dotenv 值；S3 模式自动启用 SeaweedFS profile，默认配置使用 Compose 内部 DNS endpoint。
