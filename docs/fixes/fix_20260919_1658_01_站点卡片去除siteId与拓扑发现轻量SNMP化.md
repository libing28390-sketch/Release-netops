## 1. 问题现象与用户诉求

1. **站点卡片显示无业务意义的 site-id**：
   - 拓扑页面 Site 视轨中的卡片大标题为站点名称（如 `WH-DC-02` / `WH-DC-01`），但下方副标题展示了系统内部哈希 ID（如 `SITE-E7966B242326`），用户反馈该 ID 对日常运维毫无意义，造成界面视觉噪音。
2. **拓扑刷新发现应全面以轻量 SNMP 查 LLDP 邻居为主，避免复杂的冗余 CLI 命令**：
   - 用户反馈：“右上角的刷新发现是作为CLI兜底的吧，我们是否可以再优化下呢，如果完全可以通过SNMP来解决，就没必要引入那么多条命令啊，就直接查询lldp邻居就好了，其他的命令都不需要”；
   - 现状问题：
     1. 发现入口 `discover_device_neighbors` 强制校验了 `username` 和 `password`，导致纯 SNMP 凭据的设备直接报错拦截；
     2. 在 SNMP 成功拉取到 LLDP 邻居后，系统仍试图去连接 SSH 跑 `_sync_aggregation_inventory`（`eth_trunk` 等命令），违背轻量化设计初衷；
     3. 物理链路在入库时初始 `status` 被默认填为 `unknown`，并在缺少遥测时被误当做 down。

---

## 2. 解决方案与修改内容

1. **站点卡片移除冗余内部 ID** (`src/pages/TopologyPage.tsx`)：
   - 从站点卡片中移除 `{site.id}` 的副标题渲染，保持站点名称主标题清晰对齐，消除视觉杂音。
2. **拓扑发现全面强化轻量 SNMP 优先与旁路冗余 CLI** (`backend/services/topology_service.py`)：
   - 放宽凭据校验：只要设备具备 IP，且拥有 SNMP（`snmp_community` / `snmp_credential_id`）或 SSH 凭据即可启动发现，支持纯 SNMP 设备接入；
   - 彻底轻量化：当 `method == 'snmp'` 成功获取 LLDP 邻居后，直接完成并返回，不再执行任何多余的 SSH/CLI 探测命令；
   - CLI 保持最简兜底：仅当未配置 SNMP 或 SNMP 查询无结果且具备 SSH 时，才使用纯粹的单条 LLDP 邻居命令兜底；
   - 物理链路状态自愈保障：当活跃 LLDP 证据发现物理链路时，链路 `status` 直接标记为 `up`，并确保两端端点端口在 `interfaces` 表中的运行与管理状态确认为 `up`，彻底消除由于历史残留把正常链路标为中断的现象。
