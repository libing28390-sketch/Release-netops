# Windows 客户端与多厂商命令联动

## 问题现象

- Windows 客户端界面层级、主题和弹窗风格不统一，部分明亮/深色状态可读性不足。
- 启动器在脚本或打包上下文中可能出现 `No module named 'ui'`，系统信息中的处理器文本可能被裁切。
- 数据库恢复出厂操作需要更明确地展示实际 `.env` 配置来源、目标数据库和备份路径。
- 客户端部署升级后没有简洁的版本更新说明，用户无法快速确认本次修复内容。
- 资产切换厂商时可能保留旧平台，导致 Huawei/H3C 自动化任务错误使用 Cisco 命令。

## 根因

- 桌面端样式散落在单文件中，缺少统一设计令牌和主题反馈组件。
- 启动器导入路径未同时覆盖包运行、脚本运行和 PyInstaller 场景，系统信息布局未为长文本提供足够高度。
- 资产表单和后端同步只更新厂商字段，未强制校验厂商与平台组合。
- 客户端缺少版本化更新说明及已读版本持久化机制。

## 解决方案

- 建立桌面端统一设计令牌、主题、启动器主题和反馈弹窗，重构主要页面与交互。
- 修复启动器导入兼容和处理器信息自适应布局，完善数据库重置安全确认与备份信息展示。
- 新增 `v1.0.2` 一次性更新说明：首次启动显示，确认后记录已读版本。
- 在前端表单、提交处理和后端资产创建/更新/同步中规范化厂商平台组合，并补充 Huawei 厂商修复旧 Cisco 平台的回归测试。
- 将“厂商 → 平台 → 驱动 → 命令集”写入项目 Agent、网络驱动 Skill 和网络工程师角色规范。

## 风险与回滚方式

- 更新说明只新增一个设置键，不改变现有业务配置；删除 `last_seen_release_notes_version` 可重新显示。
- 若新版 EXE 启动异常，可回退上一版本 `NetOps.exe`，源代码和数据库结构不需要回滚迁移。
- 厂商平台规范化仅修正已知不兼容组合；可回滚对应前后端文件恢复旧行为，但不建议恢复静默 Cisco 回退。
