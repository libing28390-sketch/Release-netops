# 1.0.8 发布修复记录

## 问题现象

- Windows 新构建的 `NetOps.exe` 启动时在 `desktop/ui/feedback.py` 导入 `PySide6.QtCore` 失败，弹出 `ImportError: DLL load failed while importing QtCore`。
- Windows 发布链路仍使用未固定的 PyInstaller/PySide6 依赖，且 EXE 构建没有 post-build smoke gate。
- 平台、Windows 客户端和发布文档版本仍显示 1.0.7；PG18 统一和 Windows 依赖修复尚未形成 1.0.8 发布提交。

## 根因

构建机的 Codex/Poppler runtime 位于 PATH。PyInstaller 将其中的 ICU 78 `icuuc.dll`/`icudt78.dll` 收入 EXE 根目录；Qt6Core 加载时优先找到这份同名 DLL，但它缺少 Qt 所需的 20 个未版本化 ICU 导出，Windows 返回 WinError 127。旧 EXE 不包含这份冲突 DLL，因此可以启动。

## 解决方案

- 在 `NetOps.spec` 的 `Analysis` 完成后、`PYZ/EXE` 创建前过滤 Poppler 路径下的 ICU DLL。
- 固定 Windows 打包依赖：PyInstaller 6.22.1、hooks-contrib 2026.6、PySide6 6.11.1、psycopg2-binary 2.9.13。
- 在 Windows release workflow 中增加 30 秒 `--smoke-test` 和 `SMOKE_TEST_OK` 日志门禁。
- 统一 PG18.6、PG18 pgvector、Docker PG18 数据卷和后端版本门禁；加入启动确认、密码双输入以及自动 `.env` 生成行为。
- 将平台、客户端、前端 fallback 和公开说明升级到 1.0.8。
- 按用户要求纳入 `.agents/skills/**` 与 `.codex/config.toml`；发布 workflow 会在构建公有 Release-netops 树前删除 `.agents/` 与 `.codex/`。
