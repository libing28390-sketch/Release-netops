## 1. 问题现象与用户诉求
1. **拓扑图异常缩放到 31% 且视觉重心靠顶**：
   - 用户访问 `http://192.168.56.1:5400/monitor/topology` 反馈拓扑图缩放仅显示 31%，节点极小且大量画布留白，顶部核心交换机节点紧贴顶部甚至被控制栏局部遮盖。
2. **采集计划菜单项 `/monitor/collection-plans` 废弃与下线**：
   - 用户询问该采集计划页面是否也可以废弃。

---

## 2. 根因分析
1. **拓扑画布高度塌缩与比例畸变**：
   - 页面容器采用 `overflow-auto` 和 `flex-1`，在视口计算时子级图表包裹层高度塌缩为约 250px ~ 300px；
   - 8 个拓扑节点按分层布局计算的总高度跨度 `dy = 638px`；
   - `createDefaultTransform` 计算垂直自适应比例 `scale = (containerHeight * 0.78) / dy` 仅为 `195 / 638 ≈ 0.305`（界面取整为 31%）；
   - 该微缩状态被直接写入浏览器 `localStorage` 及后端 `topology_layouts`，导致用户再次进入或刷新页面依然锁定在病态的 31% 微缩状态；
   - 缺少顶部悬浮操作栏避让高度，导致顶部首层节点紧贴或部分被浮动控制条覆盖。
2. **监控采集体系已全面标准化升级**：
   - 时序指标采集已由 Prometheus + SNMP Exporter（内置 20 厂商工业级 OID 模板体系）原生接管；
   - CMDB 接口与设备状态采集已全面改造为高并发 SNMP IF-MIB 协议直采；
   - 早期以手工/弱规则为主的 `/monitor/collection-plans` 页面已失去核心业务场景，且对运维人员造成心智负担。

---

## 3. 解决方案与修改内容
1. **拓扑画布高度提升与响应式充盈** (`src/pages/TopologyPage.tsx`)：
   - 将拓扑画布固定容器高度从 `min-h-[500px]` 升级为沉浸式大视口 `h-[calc(100vh-270px)] min-h-[660px]`；
   - 给图表父容器与包裹层增加 `min-h-0`，确保 Flex 布局下高度不被外层内容塌陷。
2. **拓扑智能缩放与顶部避让算法优化** (`src/components/TopologyGraph.tsx`)：
   - 在 `createDefaultTransform` 中增加顶部工具栏避让安全高度（`topToolbarMargin = 60`），使网络拓扑视觉重心自然下移 30px，彻底避开浮动工具栏；
   - 将视口可用利用率由 78% 提高到 85%（`paddingPercent = 0.15`）；
   - 增加规模智能保底缩放：<= 12 个节点保底缩放 `0.78`，<= 25 个节点保底缩放 `0.62`；
   - 在 `fitViewport` 中补齐 `setZoomPercent` 状态同步，保证缩放百分比数字即时准确；
   - 增加旧布局缓存防御：当读取到的本地或远程缓存中 `k <= 0.5` 且当前节点 <= 25 时，判定为病态微缩，自动重置并重新触发自适应计算。
3. **下线采集计划侧边栏导航** (`src/components/AppSidebar/navConfig.ts`)：
   - 移除 `monitoring-plans` 侧边栏入口，使“实时监控”导航精炼聚焦为：运营总览、监控大盘、监控报表、采集器管理、网络拓扑；
   - 保留底层 API 与 routeContext 兼容性，确保旧 URL 或内部引用平滑安全。
