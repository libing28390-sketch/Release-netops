# 优化互联网出口健康诊断页面 修复记录

## 问题现象

1. 总体状态与卡片状态一致性不足：期望 IP 不匹配时，若处于连续 2 次防抖阶段，页面总体显示“正常”而卡片显示白名单，产生认知冲突。
2. IP 来源展示单一，缺乏可信度说明。
3. IP 期望白名单无匹配状态，多条规则展示拥挤。
4. 时延曲线没有提供 P95 和最大时延。
5. 趋势图时间轴在服务断档时不连续（直接连成直线，没有断线）。
6. 可用率曲线过度平滑，未标出故障红点。
7. 缺少图例且 Tooltip 信息单一。
8. 页面摘要卡片留白偏大，高度偏高。
9. 副标题存在英文文案 "10 of 10 targets available"。
10. 缺少倒计时、运行状态与故障中断持续时间的呈现。

## 根因

前端 UI 数据仅进行了最简单的绘制，未在 Recharts 图表中使用插值断点处理、自定义 Dot 标识与图例，也未利用后端最新计算的指标进行高密度多状态解耦渲染。

## 解决方案

1. **高密度 6 栏卡片重构**：重新规划为综合状态、连通状态、出口 IP、合规状态、时延指标和检测状态 6 栏紧凑布局。
2. **倒计时与看门狗集成**：在“检测状态”卡片中实现实时秒级倒计时，检测中断时自动显示红色闪烁的 `数据中断 Xm`。
3. **白名单规则弹窗**：合规状态卡片支持点击弹出遮罩层以渲染完整的期望白名单规则及当前连接匹配详情。
4. **图表断点与平滑度修正**：
   - 编写插值填充算法，在相邻采样点间隔超过 3 分钟时插入 `null` 点，使 Recharts 折线图在中断处自动断线。
   - 可用率折线改为 linear。
   - 增加 `<FailureDot />` 以在可用率/结果 < 100% 时高亮渲染红圈。
5. **后端指标补充**：`get_outbound_status` 计算 P95 时延、最大时延和状态维持时间并输出。
6. **完全中文化**：汉化后端提示文本。
