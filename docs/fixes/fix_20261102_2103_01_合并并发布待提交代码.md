# 合并并发布待提交代码

## 问题现象 / 本次提交目的

用户要求将工作区全部待提交代码推送到 `main`，并确保 GitHub Actions 成功。

## 根因

多轮功能开发后的产品源码、测试、迁移和产品模板仍停留在工作区，尚未提交；工作区同时包含不应发布的生成产物和内部协作材料。

## 解决方案

审核差异后显式暂存产品代码、测试、迁移、资产模板与发布记录；完成后端及前端发布验证，提交并推送 `main`，跟踪目标提交对应的 Actions。若失败，修复后以新提交继续。

## 实际修改文件

显式暂存 88 个文件：后端源码、服务、4 个数据库迁移和后端测试；前端页面、组件、测试及 `vitest.config.ts`；`.env.example`、资产导入模板；本次 `docs/plans/`、`docs/walkthrough/` 与本修复记录。资产管理 UI 测试夹具已补齐必填资产编号和管理 IP。

## 验证命令与结果

- 前端全量：193 个测试文件、831 项通过；测试 runner 上限 4 workers、单项超时 10 秒。
- `npm run lint`：通过。
- 隔离前端生产构建：通过。
- 后端配置校验、PostgreSQL-only 扫描、Python 编译、RackVision 目录校验、AI/RAG 发布配置校验及暂存差异/敏感模式检查通过。
- 后端 `pytest --durations=25` 未在本机运行：隔离测试库认证不通；将在 GitHub Actions 隔离 PostgreSQL 上验证。
- `Build and Sync to Release Repo` main push 工作流将在推送后核对。

## 未验证项

本机 PostgreSQL 的 `postgres:postgres` 只读探测未能建立数据库会话（驱动错误解码异常）；OS 身份连接明确要求密码。没有读取 `.env`、启动/重置数据库或写入测试库。

## 风险与回滚方式

涉及数据库迁移和仓库配置的改动按项目发布顺序部署。如需回滚已推送代码，追加 revert commit，不重写远端历史。
