# 网络总吞吐单位与监控报表分页修正

## 问题现象

- 01 网络总览的设备总速率表没有单位，裸数值容易被误解为累计流量。
- 监控报表的接口、设备、出口页面默认按 25 条切片，但共用页脚分页器不提供 25 条选项，页头和页脚控件也不一致。

## 根因

- Grafana 组织转换将 `Value` 重命名，字段 unit override 却匹配另一个默认列名，导致 bps 格式器没有命中。
- 报表页有两个独立的页大小选择器，默认值和可选值不一致；实际数据切片沿用 25 条默认值。

## 解决方案

- 将网络总览面板改称“设备总吞吐速率 Top10”，列名显示 `总速率 (bit/s)`，让 unit override 与重命名后字段完全一致，并说明这是近 5 分钟平均入/出速率合计；Grafana 自动按数量级格式化。
- 三个报表路由统一默认每页 20 条，与通用分页器选项一致，并删除重复的顶部页大小选择器。
- 增加三个报表路由各自的 21 行回归，验证 20+1 条分页结果和一致的页大小控件。

## 风险与回滚

- 网络速率列表示 bit/s，Grafana 按 SI 数量级显示 kb/s、Mb/s 等；它不是累计字节数。在线 UI 仍需用户部署后确认实际格式。
- 报表保持客户端分页，没有修改后端数据分页。
- 如果需要回滚，可单独恢复面板字段变更和报表页/测试变更；没有数据迁移或生产数据写入。
