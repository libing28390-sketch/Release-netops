# 修复记录：Docker 部署启动恢复与 SNMP 配置兼容

## 问题现象
- Linux Compose 首次启动时 `nexora-netops` 短暂 unhealthy，Compose 退出后 Nginx、SNMP Exporter、vmagent 留在 Created，需要手动启动。
- SNMP Exporter v0.26.0 反复重启，日志报 `source_indexes`、`lookup` 是未知字段。
- 默认 Compose 不会启动挂在 `object-storage` profile 的 SeaweedFS；带引号/空白的 `STORAGE_BACKEND=s3` 也可能未触发部署脚本 profile。

## 根因
- liveness probe 会继承代理环境，首次启动宽限过短；部署脚本第一次 `compose up` 失败后没有等待依赖健康再补启动。
- `snmp.yml` 默认模板、编译器及现存 named volume 使用旧 lookup schema，与当前 v0.26.0 Exporter 不兼容。
- SeaweedFS 是显式 Compose profile；直接运行 `docker compose up` 会跳过 profile，部署脚本对 dotenv 格式解析不完整。

## 解决方案
- liveness probe 改为不使用代理的 `127.0.0.1`，首次启动宽限设为 120 秒。
- 部署脚本识别空白、引号、CRLF 和大小写变体；临时启动失败后等待 netops healthy，再以不构建、不拉取的方式自动补启动。
- S3 模式启用 SeaweedFS profile，示例 endpoint 使用 Compose 内部 DNS。
- 默认模板与 compiler 输出 v0.26 lookup 字段；应用启动时原子、幂等迁移持久化 volume 的 legacy lookup。
