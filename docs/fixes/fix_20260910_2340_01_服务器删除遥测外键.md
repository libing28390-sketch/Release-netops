# 服务器删除遥测外键修复

## 问题现象

服务器资产 `nexora` 删除请求返回失败，PostgreSQL 报告 `device_telemetry_samples_device_id_fkey` 外键仍被遥测样本引用，前端未显示失败原因。

## 根因

资产删除链路删除关联 `devices` 记录前没有清理 `device_telemetry_samples` 和 `device_telemetry_hourly`。两张表在已有 PostgreSQL 安装上使用默认 `NO ACTION` 外键，阻止了设备删除；服务器资产页仅在成功响应时刷新，非 2xx 响应被静默忽略。

## 解决方案

- 在 `_delete_linked_device` 同一事务中删除两张遥测表的设备记录。
- 同步新建数据库 schema 的外键定义为 `ON DELETE CASCADE`。
- 新增 PostgreSQL 迁移 218，幂等替换已有遥测外键。
- 使用统一 API 请求错误契约，让单条删除弹窗和批量删除反馈显示安全错误。

## 风险与回滚方式

遥测数据属于设备历史数据，随设备删除；删除和关联清理在同一事务中执行。代码可通过回滚本次提交恢复；数据库级联约束回滚需在维护窗口内执行并先确认无悬挂引用。未执行推送以外的生产数据删除或部署操作。
