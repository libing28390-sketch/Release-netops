# 修复记录：定时作业全宽双栏沉浸式工作台重构与NSOT解耦

## 1. 问题现象与提交目的

1. **巡检概览与记录耦合及高风险操作**：
   - 巡检概览（`/automation/inspections`）与巡检记录（`/automation/records`）此前内容重复且指标卡片打开缓慢；
   - 记录页面存在全局高风险的“立即巡检全部”按钮。
2. **NSOT 事实库与定时作业范围锁定**：
   - 定时作业创建模态窗中，NSOT 事实库被强制置灰锁定为“全部在线设备”，无法按站点、角色或复合条件实现多数据中心分批错峰采集。
3. **定时作业对象筛选体验与 UI 失衡**：
   - 过滤条件依赖手动文本输入，缺少与 CMDB 的智能联动；
   - 脚本执行模式缺乏网络设备（CLI/SNMP）与服务器主机（Shell）的协议通道分层；
   - 在 1080P/2K 宽屏显示器下，定宽居中卡片导致屏幕两侧出现大面积空白。

---

## 2. 根因分析

1. 巡检页面原先同时承载健康大盘与全网批量触发逻辑，导致职责混淆与高并发风险；
2. 早期的 NSOT 后端调用直接绑定了全局刷新函数，前端相应将 `device_scope` 锁定为 `all`；
3. 定时作业表单原本采用定宽卡片居中布局（`max-w-5xl`），在宽屏下空间利用率低，左右两侧被动留白。

---

## 3. 解决方案

1. **巡检与事实库深度解耦与风险管控**：
   - 彻底移除巡检记录页的“立即巡检全部”按钮；
   - 巡检概览专职负责健康评分、趋势图表与风险设备雷达；巡检记录专职负责执行历史、审计与报告导出。
2. **全面放开 NSOT 设备范围与错峰调度**：
   - 移除前端置灰与后端锁定，支持全部设备、CMDB 站点、角色、复合条件、标签及 IP 列表的自由组合采集。
3. **CMDB 智能联动与协议通道分层**：
   - 站点与角色过滤改由 CMDB 数据动态生成带设备计数的下拉菜单；
   - 脚本执行拆分为「网络设备 (SSH-CLI / SNMP)」与「服务器主机 (Shell)」，并联动过滤可用脚本库。
4. **全宽双栏沉浸式工作台 (方案 A)**：
   - 移除定宽限制，采用 `w-full` 左右 56%:44% 黄金比例布局；
   - 左栏负责策略配置与范围设定，右栏实时呈现匹配设备大盘、Cron 调度预测与安全审批，消除大面积留白。
