# 修复记录：拓扑角色分层识别与坐标重叠修复

## 1. 问题现象
在拓扑图视图中，对于使用规范拓扑角色（如 `core`、`distribution`、`access`）定义的设备，当系统进行层级布局计算或恢复已保存的节点坐标时，可能出现：
1. 节点层级判断优先退回到 evidence 关系分层，未优先按规范角色分级（Core / Distribution / Access）展示。
2. 恢复已保存的拖拽坐标时，若历史保存坐标存在折叠或多个节点在 X 轴上严重叠在一起，图形渲染出现文字重叠。
3. `AssetManagement` 与 `PlatformRegistryTab` 相关前端类型和界面渲染细节需要保证与角色/平台规范对齐。

## 2. 根因
1. `topologyRoleLayout.ts` 中 `selectTopologyLayoutLayers` 优先判断了 `evidenceLayers`，导致只要关联关系存在多层，就直接使用了关系层级而非 `topologyRoleVisualTier` 角色分级。
2. 在修复已保存坐标时，缺乏判断节点横向标签宽度与最小中心距离的防碰撞重构函数（`repairTopologyRoleLayeredPositions`）。
3. 拓扑角色解析缺乏对规范化角色字符串（`canonicalTopologyRole`）的兼容提取。

## 3. 解决方案
1. 调整 `selectTopologyLayoutLayers` 逻辑，优先选用已识别的 `roleLayers`（角色层级），当且仅当角色层级无区分时才降级回 `evidenceLayers`。
2. 在 `topologyRoleLayout.ts` 中增加 `repairTopologyRoleLayeredPositions`，结合节点主机名估算标签宽度和节点间距，在检测到 X 坐标碰撞时自动按行重构横向均匀布局。
3. 补充完善 `topologyRoleLayout.test.ts` 单元测试，覆盖折叠坐标恢复与角色分层判断。
