# 修复记录：大盘 Top 接口名称缺失修复、Grafana 变量语法合规化与主机监控接入

## 1. 问题现象
1. **Top 排序表格缺失接口名称与多端口压缩**：在 Grafana `04 接口流量与健康 (Interface Traffic & Health)` 和 `06 互联网出口与 WAN (Internet Outbound & WAN Traffic)` 中，带宽利用率 Top 20/Top 10、错误丢弃 Top 20/Top 10 等表格中，没有显示具体的“接口名称/端口编号”，且同一设备下多个端口被 PromQL 聚合压缩为仅一行；
2. **Grafana 大盘变量语法报错**：在打开 `08 Windows 主机监控` 或 `07 Linux 服务器监控` 等大盘时，右上角出现黄色/红色 Validation 警告弹窗：`Validation failed: cannot parse matches[...]: expecting metricSelector; got '((windows_cpu_time_total or windows_os_info) or hrProcessorLoad) or up'`；
3. **Linux / Windows 服务器监控无数据**：用户在服务器监控大盘中看到全部指标为 0 或 No data，询问 Linux 和 Windows 服务器需要安装什么插件。

## 2. 根因分析
1. **接口指标缺乏 ifDescr 关联与 PromQL 维度丢失**：
   - `monitoring/snmp-exporter/snmp.yml` 的 `generic_ifmib_interface_std` 模块中仅定义了 `ifName` (OID `1.3.6.1.2.1.31.1.1.1.1`)，但未定义 `ifDescr` (OID `1.3.6.1.2.1.2.2.1.2`)，且所有指标的 `lookups` 仅关联了 `ifName`。大量交换机/路由器仅支持或上报 `ifDescr`，导致指标入库时没有 `ifName` 标签；
   - 原大盘表格 PromQL 使用 `by (hostname, instance, ifName)` 聚合，当指标没有 `ifName` 标签时，Prometheus 丢弃该维度并将全设备多端口合并为单一最大值；
   - Grafana 的 `organize` 变换中将 `ifIndex` 排除，导致前端表格完全无端口列。
2. **Prometheus / VictoriaMetrics 系列选择器语法不合法**：
   - 变量查询中使用 `label_values(a or b or c, label)`，Prometheus API `/api/v1/series?match[]=` 只接受合法的单一指标选择器，遇到包含 `or` 的布尔运算表达式时直接报 `expecting metricSelector` 校验错误；
   - 必须使用标准正则表达式选择器语法 `{__name__=~"a|b|c"}`。
3. **vmagent 缺少主机采集作业与 Agent 插件指引**：
   - `monitoring/vmagent/scrape.yml` 之前仅配置了 `network_snmp` 抓取任务，没有配置 Linux (node_exporter: 9100) 和 Windows (windows_exporter: 9182) 的采集通道；
   - 目标服务器未安装相应的 exporter 插件。

## 3. 解决方案与实施
1. **SNMP 模板扩展 (`monitoring/snmp-exporter/snmp.yml`)**：
   - 在 `generic_ifmib_interface_std` 中新增 `ifDescr` (OID `1.3.6.1.2.1.2.2.1.2`) 指标；
   - 为 `ifAdminStatus`, `ifOperStatus`, `ifInErrors`, `ifOutErrors`, `ifInDiscards`, `ifOutDiscards`, `ifInOctets`, `ifOutOctets`, `ifHighSpeed`, `ifHCInOctets`, `ifHCOutOctets` 等关键指标的 `lookups` 均添加 `- source_indexes: [ifIndex], lookup: ifDescr`。
2. **Grafana 大盘代码优化 (`monitoring/grafana/generate_dashboards.py`)**：
   - 在 Dashboard 04 与 Dashboard 06 的 Top 表格中将聚合维度统一扩展为 `by (hostname, instance, ifName, ifDescr, ifIndex)`；
   - 在 `clean_organize_transformation` 中显式映射 `ifName: "端口编号"`, `ifDescr: "端口名称"`, `ifIndex: "端口索引"`；
   - 将全部 8 个大盘的变量查询语句从 `label_values(a or b, label)` 重构为合法的 `{__name__=~"a|b|..."}` 格式。
3. **重新编译全量 8 个大盘 JSON**：
   - 执行编译脚本，重新生成 `nexora-network-overview.json`、`network-device.json`、`network-wireless.json`、`network-interface.json`、`monitoring-health.json`、`network-outbound.json`、`linux-metrics.json`、`windows-metrics.json`。
4. **扩展 vmagent 采集配置与初始化 target 文件**：
   - 在 `monitoring/vmagent/scrape.yml` 中新增 `linux_nodes` (9100) 和 `windows_nodes` (9182) 两个 `file_sd` 作业；
   - 初始化 `monitoring/vmagent/targets/linux_targets.yml` 和 `windows_targets.yml`。
