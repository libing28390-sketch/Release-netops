# IPAM 与 CMDB 累计变更发布准备

## 现象与目的

用户要求将工作区中待提交代码推送到 `main`，并确认 GitHub Actions 成功。工作区同时包含近期 IPAM/CMDB 功能代码、导航默认页与登录粒子交互，以及本机生成的构建、运行和现场审核材料。

## 根因

产品变更与内部协作文件、`dist/`、性能/验证工件、日志和现场数据混在同一工作区；若用 `git add -A` 会把本地或敏感材料带进提交。提交前门禁也发现前端旧断言仍沿用导入核对改版前的直接生成流程和旧字段文案。

## 解决方案

显式暂存后端和前端 IPAM/CMDB 应用代码、对应测试，以及这些代码对应的计划和 walkthrough。排除 `.agents/`、`handoff.md`、`dist/`、`.codex*`、`dist-*`、`backend/artifacts/`、`logs/`、`output/`、现场 CSV 与截图/PDF/JSON。同步测试新的接口导入预览确认步骤，并将终端详情中的“观察来源”统一为“来源”。

## 修改范围

- 后端：CMDB VRF 维护与引用保护、IPAM 接口候选/生成预览、终端观察去重与分类、IPAM 地址空间与网关候选。
- 前端：IPAM 前缀与 IP 地址管理、接口导入复核、终端筛选/登记、CMDB 接口采集提示、IPAM 默认入口与展开状态、登录页粒子指针响应。
- 测试与文档：上述功能的单元/组件/服务测试、任务计划和 walkthrough、本记录。

## 验证

- `python scripts/validate_postgresql_only.py`：通过，0 项违规。
- 本机 pytest 未运行：`DATABASE_URL` 未配置，且 pytest fixture 会先初始化 source DB；无法证明本机 PostgreSQL 目标库可丢弃。完整后端 pytest 由 Actions 的隔离 PostgreSQL 服务验证。
- 前端 focused Vitest：10 个文件、96 项测试通过。
- `npm run lint`：通过（TypeScript 无诊断）。
- `npm run build`：通过，Vite 转换 4364 个模块，耗时 15.96 秒。
- 提交前还需通过暂存差异检查、文件范围检查和敏感信息扫描；推送后以最终 SHA 的 GitHub Actions 结果为准。

## 风险与回滚

推送 `main` 会触发仓库现有 `release.yml`，其中含发布仓库同步。此次推送已获用户明确授权。若 CI 发现代码问题，修正后再推送并跟踪新 SHA；应用代码需要回退时使用 `git revert <commit>`，不重写历史、不清理本机工件。
