# 开发端口冲突与提交记录规范

## 问题现象

- 执行 `npm run dev` 时，后端报 `WinError 10013`，无法绑定 `127.0.0.1:5010`。
- 仓库缺少每次 Git 提交对应的独立 Markdown 修复记录目录和强制规范。

## 根因

- 此前验证资产投产接口时启动的 Uvicorn 后台进程仍监听 5010，开发服务器再次启动时发生端口冲突。
- Agent 规则只要求 plan 和 walkthrough，没有规定提交级修复记录。

## 解决方案

- 核对监听进程命令行为当前工作区的 `uvicorn backend.main:app` 后，安全停止该进程。
- 使用临时 socket 绑定验证 5010 已释放。
- 新增 `docs/fixes/` 目录，并在 `.agents/AGENTS.md` 中规定每次 Git 提交必须创建新的 `fix_*.md`。
- 更新 `.gitignore`，确保修复记录可以进入版本控制。

## 实际修改文件

- `.agents/AGENTS.md`
- `.gitignore`
- `docs/fixes/README.md`
- `docs/fixes/fix_20260713_1107_01_开发端口冲突与提交记录规范.md`

## 验证命令与结果

- 查询 5010 监听进程：确认占用者为工作区 Uvicorn，PID 20428。
- 停止进程后使用 Python socket 绑定 `127.0.0.1:5010`：输出 `PORT_5010_AVAILABLE`。
- 执行 `npm run dev:backend`：Uvicorn 成功监听 `http://127.0.0.1:5010`，应用启动完成后通过 Ctrl+C 正常关闭。

## 未验证项

- 未持续运行完整前后端联合开发进程；后端开发启动已单独验证通过。

## 风险与回滚方式

- 停止后台验证进程不会修改业务数据；重新执行 `npm run dev` 即可恢复开发服务。
- 如不再需要提交级记录，可回滚 Agent 规则和 `.gitignore` 例外，但建议保留历史 `docs/fixes/` 文件。
