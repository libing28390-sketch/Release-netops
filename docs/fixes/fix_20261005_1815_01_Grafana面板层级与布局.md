# Grafana 面板层级与布局

## 问题现象

- 第一轮展示的独立 HTML 视觉稿不是 Grafana Dashboard 面板，未能代表实际配置改版。
- 12 份 Dashboard 的首排摘要卡高度不一；即时 Stat 仍配置面积 sparkline；若干看板缺少可扫描的分区标题。
- WAN 连续 Down 指标和 Windows 非运行关键服务表位于较后位置，部分窄趋势图的右侧图例挤占绘图区。

## 根因

- 第一轮交付展示把视觉概念稿与仓库 dashboard JSON 混为一谈。
- 生成器的首排 KPI 高度、Row 分组和图例位置没有统一策略；Stat helper 默认显示 area graph。
- 部分故障定位面板按内容顺序排列在页面下部，没有优先呈现当前异常。

## 解决方案

- 只修改 Grafana Dashboard 生成器及其 12 份 JSON 输出，不将独立网页当作面板结果。
- 首排 Stat/Gauge 摘要统一为 4 个网格单位高；即时数值 Stat 默认关闭 sparkline。
- 为 12 个 Dashboard 补齐可见 Row 分组；Row ID 分配避开当前看板已用 ID。
- 将连续 WAN Down 摘要前移，将 Windows 非运行关键服务表与 WAN 网卡趋势并列显示；告警效率摘要卡等宽。
- 低序列趋势图例移至底部；平台可达状态用阶梯线呈现。
- 统一 AP KPI 缺数文案，并标明设备详情中的渲染错误计数属于全局指标。
- 保留既有入/出/错误/丢弃和健康/严重度语义色，不通过 Dashboard JSON 更改 Grafana 全局主题。
