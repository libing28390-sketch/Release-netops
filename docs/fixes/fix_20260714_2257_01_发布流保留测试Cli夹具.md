# Git 修复与提交记录 - 发布流保留测试 Cli 夹具

## 问题现象 / 本次提交目的
远程对外发布库 `Release-netops` 中完全缺失了 `backend/tests/fixtures/` 目录下的 CLI 格式化解析夹具数据，导致某些功能无法获得预期的原始数据做测试校验。

## 根因
在自动打包发布工作流 [.github/workflows/release.yml](file:///d:/netops/netsops-main/.github/workflows/release.yml) 中，清理测试资产时直接执行了 `rm -rf backend/tests/`，导致整个 `tests` 目录（包含其中的 `fixtures`）均被彻底清除。

## 解决方案
1. 修改 [.github/workflows/release.yml](file:///d:/netops/netsops-main/.github/workflows/release.yml)，将 `ubuntu` 与 `windows` 打包步骤中的测试清除逻辑由 `rm -rf backend/tests/` 优化为：
   ```bash
   find backend/tests -mindepth 1 -maxdepth 1 -not -name "fixtures" -exec rm -rf {} +
   ```
   这可使工作流仅删除 `tests/` 目录下的 Python 测试文件与缓存文件夹，但完整保留其下的 `fixtures` 目录。
2. 提交并推送修改到开发库主分支，重新触发 GitHub Actions 打包发布流程。

## 风险与回滚方式
- **风险**：工作流中的 `find` 命令运行异常。
- **回滚方式**：若报错，可将清理动作调整为单独罗列删除具体的文件，如 `rm -rf backend/tests/*.py backend/tests/__pycache__` 等。
