# CMDB 快照测试夹具适配设备外键

## 问题现象

提交 `d3304e91108983a6b4c0d95a54aa3129d95748fa` 的 GitHub Actions #759 在全量后端 pytest 中失败：3612 项通过、2 项跳过、3 项 `test_cmdb_snapshot_service.py` 用例因 `cmdb_collection_snapshots_device_id_fkey` 外键拒绝不存在的设备 ID。

## 根因

m0300 为 `cmdb_collection_snapshots.device_id` 增加了正确的 `devices(id) ON DELETE CASCADE` 外键。三个已有快照服务测试使用了任意字符串作为设备 ID，却未创建对应父设备；新约束因此在数据库写入时拒绝这些测试夹具。

## 解决方案

为每个隔离 PostgreSQL 用例先插入对应的最小 `devices` 记录，再运行快照 generation、成功/失败状态和 VLAN observation 替换断言。未修改运行时服务、迁移或监控代码。

## 实际修改文件

- `backend/tests/vendor_audit/test_cmdb_snapshot_service.py`
- `docs/walkthrough/walkthrough_20261028_0925_01_SNMP平台自动绑定与VLAN生命周期.md`

## 验证命令与结果

```powershell
.venv/Scripts/python.exe backend/artifacts/cmdb_validation/run_isolated_pytest.py -q backend/tests/vendor_audit/test_cmdb_snapshot_service.py
```

结果：`3 passed in 152.19s`。测试运行于一次性 PostgreSQL 数据库，运行器结束时已删除临时库。
