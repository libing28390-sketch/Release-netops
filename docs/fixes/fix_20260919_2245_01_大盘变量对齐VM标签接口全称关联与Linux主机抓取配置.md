# 修复记录 - 大盘变量对齐VM标签接口全称关联与Linux主机抓取配置

## 问题现象
1. Grafana 全部大盘中「站点」和「设备」下拉菜单展开只有 `All`，无法选择具体站点或具体设备。
2. 01 网络总览中「监控站点数」卡片显示为 `No data`。
3. 04 接口流量与 06 互联网出口大盘中，Top 20 排行表格没有展示接口全称，接口索引号被错误渲染成了带有 `%` 的百分比（如 `3%`）。
4. 07 Linux 服务器监控中没有展示任何宿主机或节点监控数据。

## 根因分析
1. **下拉菜单只有 All**：VictoriaMetrics 真实存储的时序指标中只包含 `site_id` 和 `sysName`，并不存在 `site_name` 和 `hostname`。旧大盘模板变量查询 `label_values(..., site_name)` 与 `label_values(..., hostname)` 返回 0 条记录，导致下拉菜单始终只有默认的 `All`。
2. **监控站点数 No data**：指标查询使用了不存在的 `site_name` 标签过滤与聚合，导致结果集为空。
3. **接口名称缺失与 3% 渲染 Bug**：
   - 流量指标（如 `ifHCInOctets`）仅带有 `instance` 和 `ifIndex`，真实接口全称存储在 `ifName` 指标中，缺少 PromQL 多对一 Join 语法；
   - 旧代码在表格控件上配置了全局 `unit: "percent"`，Grafana 将未经覆盖的数字列（如 ifIndex 为 3）错误格式化为 `3%`。
4. **Linux 监控无数据**：
   - 远程宿主机虽启动了 node_exporter（9100 端口），但后端 `render_vmagent_config` 中只配置了 `network_snmp` 抓取任务，未包含 node_exporter 抓取 Job；
   - 07 大盘模板变量绑定的是不存在的 `site_name` 与 `hostname`。

## 解决方案
1. **大盘模板变量全面对齐 VM 存储结构**：
   - 站点变量统一改为：`label_values({__name__=~"sysName|ifOperStatus|up"}, site_id)`；
   - 设备变量统一改为：`label_values({__name__=~"sysName",site_id=~"$site",vendor=~"$vendor",role=~"$role"}, sysName)`；
   - 实现站点 -> 厂商 -> 角色 -> 设备的四级无缝级联。
2. **监控站点数与在线数修复**：
   - 监控站点数：`count(count by (site_id) (ifOperStatus{site_id!=""}))`，实测返回当前 2 个监控站点；
   - 纳管设备数与在线数分别通过 `instance` 进行聚合计算。
3. **Top 20 接口全称 Join 注入与表格单元格重构**：
   - 引入 PromQL 双重 Join：`* on(instance, ifIndex) group_left(ifName) (ifName * 0 + 1) * on(instance) group_left(sysName) (last_over_time(sysName{sysName=~"$device"}[1d]) * 0 + 1)`，直接将 `ifName`（如 `Et0/2`）与 `sysName` 注入结果集；
   - 在 organize 转换中显式隐藏 `ifIndex`，并将 `ifName` 重命名为「接口全称」；
   - 表格全局 unit 改为 `none`，仅针对利用率数值列增加 fieldConfig override，彻底根除 `3%` 错误格式化。
4. **Linux 服务器采集链路打通**：
   - 在 `monitoring_compiler.py` 的 `render_vmagent_config` 中增加 `linux_servers`（9100 端口）和 `windows_servers`（9182 端口）的采集配置；
   - 07 Linux 服务器大盘变量与查询调整为基于 `instance`。
5. **双版本大盘编译与热重载**：
   - 编译生成 `nexora-*.json` 与 `*.json` 双套大盘文件，确保 Docker 挂载无缝兼容。
