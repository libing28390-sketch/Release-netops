# 修复记录：修复容器启动覆盖监控目标与启动自同步

## 1. 问题现象
- 用户在宿主机执行 `cat /app/artifacts/monitoring/runtime/vmagent/targets/linux_targets.yml`，发现内容为空列表 `[]`。
- vmagent 未去抓取宿主机 `192.168.18.139:9100`，导致 Grafana Linux 服务器监控仪表盘数据全为 0。

## 2. 根因分析
- 在容器启动入口脚本 `scripts/sync-frontend-dist.sh` 中，`else` 分支无条件执行了 `cp -f "$MONITORING_DEFAULTS/vmagent/targets/linux_targets.yml" "$MONITORING_RUNTIME/vmagent/targets/linux_targets.yml"`，导致容器每次重启都会把代码库预置的空 target 文件覆盖实际运行时的 target 文件。
- 后台采集器自动同步 `monitoring_collector_auto_sync` 仅作为 5 分钟定时任务注册，容器刚启动的 5 分钟窗口期内未主动生成 targets。

## 3. 解决方案
- 修改 `scripts/sync-frontend-dist.sh`：仅在 target 文件不存在时才从 defaults 复制初始化，禁止无条件覆盖已生成的 target 文件。
- 修改 `backend/main.py`：在启动完成注册定时器后，立即调用 `trigger_async_monitoring_sync(delay_seconds=3.0)`，开机即刻对齐 targets。

## 4. 实际修改文件
- `scripts/sync-frontend-dist.sh`
- `backend/main.py`

## 5. 验证命令与结果
- `& "d:\nexora\nexora-private\.venv\Scripts\python.exe" -m pytest backend/tests/monitoring/test_domestic_and_wireless_monitoring.py`
  - 结果：`5 passed in 45.20s`。

## 6. 风险与回滚方式
- 风险：极低，仅影响 target 文件初始化防护与启动同步时机。
- 回滚：`git revert HEAD`。
