# Nexora v1.0.11

发布日期：2026-10-28。服务端发行形态为 Linux / Ubuntu / Docker，Windows 工作站 Agent 随同版本单独提供。

## 本版主要更新

### CMDB 采集与资产识别

- CMDB 接口、接口 IP、VLAN、VRF、BGP 等资料使用独立 CLI 采集快照，页面读取已保存结果；接口采集联动 VLAN，减少重复操作。CLI 仍沿用平台绑定、命令目录和已有解析模板。
- CMDB 采用专用 SSH 容量池，避免与操作工作台、自动化共用同一应用并发配额。设备本身的 VTY 会话总容量仍然适用。
- 修正 VLAN 来源与设备生命周期清理、关联前缀时的删除提示，以及资产导入后的 SNMP 识别与平台同步。使用系统标识及匹配规则识别设备，识别不确定时保留待确认，不凭型号猜测。
- 以上 CMDB 采集调整不改变监控遥测和 ARP/MAC 的现有采集方式或周期。

### IPAM 台账、发现终端与对账

- 新增“发现终端”，从现有 ARP/MAC 数据生成独立观察历史，展示 IP、MAC、来源设备、站点/VRF、VLAN、端口及真实采集时间；只有 ARP 时仍能展示 IP，只有 MAC 的记录可单独筛选。
- “IP 地址”只展示正式登记台账，采集观察不自动变成地址分配。站点网段数与登记地址数分别统计，优化关键信息列宽、时间及导出。
- 对账分为发现未登记、信息冲突、长期未发现、登记后尚未发现、归属待确认、采集不可用六类；失败、过期或范围不明不会显示为核对通过。
- 已有观察重复同步不刷新真实采集时间。长期未发现默认需超过7天且至少3次独立完整采集覆盖责任来源，只提示核查，不自动释放 IP。历史从本版上线后累计，不补造过去的缺席记录。
- 登记必须确认目标网段与归属，MAC 校准检查观察和台账版本；ARP/MAC 不提供可信 PC 主机名时不自动补写。发现与对账支持筛选、分页、来源详情及完整筛选结果导出。
- 优化网段用途去重、批量修改、设备候选、分类冲突和统计卡片交互，以及 IPAM 导航与接口采集进度显示。

### 工单、变更、巡检与自动化

- 完善故障工单、服务申请、SLA 和关联变更流程，改进责任分派、审批、实施和结果复核，以及附件和控制单展示。
- 修正敏感操作授权、MFA/审批状态及自动化执行上下文校验，完善定时作业授权与紧急操作复核。
- 改进巡检指标、阈值方向、解析结果与报告，统一列表、筛选、时间、操作栏和详情交互。

### 监控、平台与运行维护

- 更新安全设备的 LibreNMS 硬件规则与 MIB 依赖，改进 SNMP 身份识别及部分指标/无线状态处理。规则覆盖取决于型号与系统版本，包含 MIB 文件不等于支持其全部采集项。
- 完善采集配置自动同步、运行状态与版本展示，修正报表导出路由和部分存储行为。
- 当前为单组织部署模式：历史租户字段保留用于兼容和审计，不再作为用户访问隔离边界；角色权限与资源授权继续生效。
- 修正发布同步认证，并更新项目首页和部署文档以反映当前功能与部署组件。

## 升级说明

1. 更新前备份 PostgreSQL、部署配置及配置备份/录像/附件对象；保留现有密钥、存储后端与数据卷，不用示例配置覆盖现有 `.env`。
2. 本版累计包含 v1.0.10 之后的数据库迁移，直到 m0301。后端启动时应用待执行迁移；新增 CMDB 快照及 IPAM 证据表不删除共享采集数据。数据库主版本升级另按 PostgreSQL 迁移流程处理。
3. 发现终端与对账持久化在 PostgreSQL，IPAM 投影每60秒处理已有数据库数据，不新增设备扫描，不要求单独部署 Redis。Docker 中 Redis 用于既有平台组件，仍按部署方案配置。
4. 新历史保留默认90天；ARP 近期观察窗口可按原有周期推导，MAC 有独立窗口。它们表示被动观察新鲜度，不能作为 PC 实时在线证明。
5. 未知 VRF、缺失采集范围或无法验证完整代次时，先查看来源并人工确认归属；没有对账结果不代表网络没有终端。
6. 服务端继续支持 Linux/Docker；Windows 用户使用同版本 Release 的工作站 Agent，不提供 Windows 原生服务端安装包。

## 验证范围

发布由 GitHub Actions 执行后端、前端、构建及正式标签门禁。功能在不同设备上的可用性仍取决于凭据、平台绑定、命令和解析覆盖；本次没有把自动化测试结果当作全部真实设备验收。IPAM 新页面尚缺实际浏览器交互验收，已有组件、隔离 PostgreSQL 和本地数据库投影验证。
